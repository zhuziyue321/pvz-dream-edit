# 地图（草坪 / 泳池 / 屋顶）实现

> **状态：数据驱动。** 地图几何的唯一真相源是三份 `ResourceMapData` 资源
> （[resources/map_resource/](../resources/map_resource/)），植物格子网格与僵尸行都在**运行时按它生成**。
> 主游戏场景只负责美术（背景图、泳池、房子、屋顶斜面）与 UI（管理器、相机、各 CanvasLayer）。
>
> 历史做法是「在 `.tscn` 里逐格手摆 `PlantCell`、逐行手摆僵尸行」，**已经移除**。
> 如果你在 `scenes/main/main_game_*.tscn` 里看到成片的格子 / 僵尸行节点，说明那不是本实现。

---

## 一、一张图由什么决定

```
关卡资源 resources/level_date_resource/**/*.tres   (ResourceLevelData)
  ├ game_sences : MainSceneRegistry.MainScenes   ← 选主游戏场景（= 选美术，也选默认地图）
  ├ map_data    : ResourceMapData                ← 可选覆盖；留空则按 game_sences 取默认图
  └ 玩法参数：出怪、卡槽、罐子、我是僵尸、预种植 …
        │
        │  ResourceLevelData.resolve_map_data()              (level_data.gd:253)
        ▼
  MainSceneRegistry.DEFAULT_MAP_PATHS[game_sences]             (main_scene_registry.gd:44)
        │  延迟 load（map_data.gd 反向引用了 MainScenes 枚举，preload 会循环依赖）
        ▼
  resources/map_resource/map_front.tres  →  scenes/main/main_game_01_front.tscn   5 行 × 9 列  草地
  resources/map_resource/map_pool.tres   →  scenes/main/main_game_02_back.tscn    6 行 × 9 列  泳池 / 浓雾
  resources/map_resource/map_roof.tres   →  scenes/main/main_game_03_roof.tscn    5 行 × 9 列  屋顶（带斜面）
        │  都继承
        ▼
  scenes/main/main_game_00_base.tscn   管理器、UI、相机、背景层、空的 PlantCellsRoot / ZombiesRoot
```

三个主场景现在都只有 **1~2KB**：只覆盖 `game_para`、背景贴图、家的门 / 遮罩、`Pool` 实例、
`RoofSlope`，**不含任何格子或僵尸行**。`scenes/main/main_game_00_base.tscn` 里的
`PlantCellsRoot` / `ZombiesRoot`（两处都在场景原点）是空 `Node2D`。

## 二、数据格式

### 2.1 `ResourceMapData` —— 一张图

[resources/map_resource/script/map_data.gd](../resources/map_resource/script/map_data.gd)

| 字段 | 类型 | 含义 |
|---|---|---|
| `game_sences` | `MainSceneRegistry.MainScenes` | 配套主游戏场景（关卡没覆盖 `map_data` 时用于反查默认图） |
| `display_name` | `String` | 备注名，只用于日志 |
| `col_x` | `PackedFloat32Array` | 每列左边缘 x（长度 = 列数） |
| `col_width` | `PackedFloat32Array` | 每列格子宽（长度 = 列数） |
| `rows` | `Array[ResourceMapRowData]` | 每行定义（长度 = 行数） |

方法：

- `get_row_num()` / `get_col_num()`
- `get_cell_rect(row, col)` —— 格子矩形，公式见下
- `get_default_zombie_row_type()` —— 全行同类型则返回该类型，水陆混合返回 `Both`
- `is_valid()` —— 校验：行数、列数 > 0；`col_x` 与 `col_width` 等长；行非空；`row_height > 0`。失败写 `Log.error`

```gdscript
# 第 row 行第 col 列的格子矩形（坐标相对 PlantCellsRoot，后者在场景原点）
x = col_x[col] + row_data.get_col_dx(col)
y = row_data.row_y + row_data.get_col_dy(col)
w = col_width[col]
h = row_data.row_height
```

### 2.2 `ResourceMapRowData` —— 一行

[resources/map_resource/script/map_row_data.gd](../resources/map_resource/script/map_row_data.gd)

| 字段 | 默认 | 含义 |
|---|---|---|
| `plant_cell_type` | `Grass` | 该行格子地形（Grass / Pool / Roof），逐格复制 |
| `zombie_row_type` | `Land` | 该行僵尸行类型（Land / Pool / Both） |
| `row_y` | 0 | **行节点的平地基准 y**（不是第 0 列格子的绝对 y，见第七节） |
| `row_height` | 96 | 该行格子高 |
| `col_dx` | — | 逐列额外 x 偏移；缺省 / 越界当 0 |
| `col_dy` | — | 逐列额外 y 偏移（屋顶阶梯）；缺省 / 越界当 0 |
| `zombie_create_global_pos` | (950, 0) | 该行僵尸生成点，全局坐标（僵尸原点在脚部） |
| `lawn_mover_type` | 0 | 该行小推车类型（`GIM_LawnMover.E_LawnMoverType`：0 草坪 / 1 泳池 / 2 屋顶） |
| `have_rake` | false | 该行是否有钉耙 |

`get_col_dx(col)` / `get_col_dy(col)` 对负数和越界都返回 0，所以数组可以只写前几列。

### 2.3 现有三份资源

- [map_front.tres](../resources/map_resource/map_front.tres) —— 草地；`zombie_row_type` 全默认 Land
- [map_pool.tres](../resources/map_resource/map_pool.tres) —— 泳池；第 3、4 行 `plant_cell_type = Pool`、`zombie_row_type = Pool`、`lawn_mover_type = 1`；第 5、6 行有岸线微偏移 `col_dx = [0,1,2,4,5,6,7,9,11]`
- [map_roof.tres](../resources/map_resource/map_roof.tres) —— 屋顶；5 行都 `plant_cell_type = Roof`、`lawn_mover_type = 2`、`col_dy = [99,84,63,45,17,0,0,0,0]`

## 三、关卡如何拿到地图

`ResourceLevelData` 上有两个相关字段（[level_data.gd:25-32](../resources/level_date_resource/script/level_data.gd#L25-L32)）：

```gdscript
@export var game_sences: MainSceneRegistry.MainScenes = MainSceneRegistry.MainScenes.MainGameFront
## 留空时按 game_sences 取场景默认地图
@export var map_data: ResourceMapData
```

`resolve_map_data()` 的优先级（[level_data.gd:253](../resources/level_date_resource/script/level_data.gd#L253)）：

1. `map_data` 已经非空 → 原样保留（**关卡覆盖优先**）；
2. 否则按 `game_sences` 查 `MainSceneRegistry.DEFAULT_MAP_PATHS`，`load()` 后缓存；
3. 都没拿到 → `Log.error("关卡 %s 没有可用的地图数据…")`。

**调用时机**：主游戏 `MainGameManager._enter_tree()` → `set_game_para()` → `game_para.resolve_map_data()`
（[main_game_manager.gd:142-156](../scripts/manager/main_game_manager.gd#L142-L156)），
在 `_ready()` 调 `init_manager()` 之前完成。各子管理器（格子 / 僵尸行 / 小推车）在 `_ready` /
`init_manager` 里才读 `map_data`，所以顺序没问题。`ResourceLevelData.init_para()` 也会再调一次
（幂等），用于出怪白名单。

> **现状**：`resources/level_date_resource` 下全部 60 个关卡 `.tres` **都没有覆盖 `map_data`**（`level_game_para/` 的自定义参数也没有），地图完全由 `game_sences` 决定。
> 夜晚草坪 / 浓雾泳池 / 生存和自定义关卡都复用这三张图。
> 如果以后要做「同一套美术、不同尺寸的场地」，就在关卡 `.tres` 里直接指定 `map_data`。

`MainSceneRegistry` 的登记表（[main_scene_registry.gd:24-48](../scripts/autoload/global/main_scene_registry.gd#L24-L48)）：

```gdscript
const DEFAULT_MAP_PATHS: Dictionary[MainScenes, String] = {
    MainScenes.MainGameFront: "res://resources/map_resource/map_front.tres",
    MainScenes.MainGameBack:  "res://resources/map_resource/map_pool.tres",
    MainScenes.MainGameRoof:  "res://resources/map_resource/map_roof.tres",
}
```

## 四、运行时生成

```
MainGameManager.init_manager()                         (main_game_manager.gd:241)
  ├ card_manager
  ├ plant_cell_manager   ← 按 map_data 建 all_plant_cells 二维表、赋 row_col；罐子 / 预种植 / 我是僵尸
  ├ game_item_manager    ← 小推车（类型逐行取 row_data.lawn_mover_type）
  ├ hand_manager
  ├ zombie_manager       ← 按 map_data 建 all_zombie_rows / all_zombies_2d / all_ice_roads（都按行索引）
  ├ background_manager   ← 背景图、泳池、雾、雨（由关卡参数 game_BG / is_fog / is_rain 决定）
  ├ drop_item_manager
  └ day_suns_manager
validate_map_consistency()                             (main_game_manager.gd:258)
```

### 4.1 植物格子 —— `PlantCellManager`

[plant_cell_manager.gd:37-99](../scripts/manager/plant_cell_manager/plant_cell_manager.gd#L37-L99)

- `_ready()` 调 `create_plant_cells_from_map_data()` + `build_all_plant_cells()`。
- 逐行建容器 `Node2D`，命名 `PlantCellsRow{行号+1}`，位置留在原点，`z_index = row * 50 + 10`。
- 逐列 `instantiate()` 一份 [scenes/ui/plant_cell.tscn](../scenes/ui/plant_cell.tscn)，设好
  `name = PlantCell{列号+1}`、`plant_cell_type`、`position`、`size`、`slope_step_y = col_dy`，
  **然后才 `add_child`** —— `PlantCell._ready` 会记录各容器节点的初始位置，顺序反了会错位。
- `build_all_plant_cells()` 收成 `all_plant_cells[row][col]`：
  - **`row_col` 只在这里赋值一次**（`Vector2i(row, col)`，col = 该行数组下标，0 = 最左列）；
    不要给 `PlantCell.row_col` 加 `@export`，也不要在别处再写。
  - 连接 `signal_plant_create` / `signal_plant_free`。
  - 每行格子数必须一致；不一致直接 `Log.error("…地图行列必须构成矩形")`。
  - 最后 `row_col = Vector2i(行数, 列数)`。

### 4.2 僵尸行 —— `ZombieManager`

[zombie_manager.gd:75-111](../scripts/manager/zombie_manager/zombie_manager.gd#L75-L111)

- `_ready()` 调 `create_zombie_rows_from_map_data()`。
- 逐行建 `Node2D`，命名 `Zombies_row{行号+1}`，`set_script(zombies_row.gd)` 变成 `ZombieRow`
  （[scripts/item/zombies_row.gd](../scripts/item/zombies_row.gd)），写入
  `zombie_row_type` / `have_rake`，挂一个 `Marker2D` 子节点 `ZombieCreatePosition`，
  局部坐标 = `zombie_create_global_pos`（行节点在原点，所以局部 == 全局）。
- 之后 `_ready` 的循环给每行 `z_index = row * 50 + 30`，并建立
  `all_zombie_rows` / `all_ice_roads` / `all_zombies_2d`（全部按行索引）。
- 没有地图数据时 `Log.error("没有地图数据，无法生成僵尸行")`，直接返回。

> 行节点类型必须是 `Node2D`。`ZombieRow` 只 `extends CanvasItem`；曾经有地图把某行写成
> `Panel + clip_children`，那一行的僵尸会被裁剪在面板矩形里。

### 4.3 小推车 —— `GIM_LawnMover`

[gim_lawn_mover.gd:42-66](../scripts/manager/game_item_manager/gim_lawn_mover.gd#L42-L66)

- 逐行取 `map_data.rows[lane].lawn_mover_type`（`clampi(…, 0, 2)`）。
- 位置固定 x = `GlobalXLawnMover`（默认 20），y = 该行僵尸生成点 y。
- `assert(僵尸行数 == 小推车类型数)`，所以**行数对不上会立刻断言失败**。
- 旧的 `AllLawnMoverTypeFromGameScenes` 场景查表已经删除。

### 4.4 生成结果自检 —— `validate_map_consistency()`

[main_game_manager.gd:258-304](../scripts/manager/main_game_manager.gd#L258-L304)
在 `init_manager()` 末尾执行，把「生成出来的东西」和「数据」逐项对齐：

- `all_plant_cells` 行数 == `map_data.get_row_num()`
- `all_zombie_rows` 行数 == `map_data.get_row_num()`
- 每行格子数 == `map_data.get_col_num()`
- 每格 `plant_cell_type` == 该行数据的 `plant_cell_type`
- 每格 `plant_cell.get_rect()` ≈ `map_data.get_cell_rect(row, col)`
- 每行 `ZombieRow.zombie_row_type` == 该行数据的 `zombie_row_type`

任何一条不符就 `Log.error`。**改完地图先看这条日志。**

## 五、坐标与索引约定（**改地图前必读**）

1. **行号 = 一切的行索引**：`PlantCell.row_col.x`、`Zombie000Base.lane`、`all_zombie_rows`、
   `all_zombies_2d`、`all_ice_roads`、小推车 `lane`、子弹 `lane` 全部同一套（0 = 最上一行）。
2. **列号 0 = 最左列**：等于 `all_plant_cells[row]` 的下标。关卡数据里的 `plant_cell_pos` 是
   **1 基、从左到右**（`plant_cell_pos.y - 1` 才是列下标）。
3. **不再依赖 RTL 镜像**：格子与行节点都在原点，每个格子的 `position` / `size` 是显式正坐标，
   所以 `get_rect()` 的局部坐标 == 地图数据坐标。历史上那套
   「行节点 `layout_direction = 3` + 负 `offset_*` + 靠 RTL 落到屏幕内」的做法已随手摆地图一起废弃。
4. **屏幕坐标 ≠ `get_global_rect()`**：关卡有 `Camera2D`（位置 120,0，入场时还会移动）。
   实测 `canvas_origin = (-120, 0)`，即 `screen_x ≈ rect.x - 120`。
   要点格子 / 判断鼠标压住哪个控件，一律用 `get_global_transform_with_canvas()`
   （见 [项目规范.md](项目规范.md) 的 S-03，以及 [AI调试通道.md](AI调试通道.md) 第五节）。
5. **渲染层次**（`main_game_00_base.tscn`）：

   | 层 | 节点 | 内容 |
   |---|---|---|
   | -10 | `CanvasLayerBG` | 背景图、房子、展示僵尸面板 |
   | 0（默认画布） | `PlantCellsRoot` / `ZombiesRoot` / `LawnMovers` / `Bullets` / `Bombs` / `BrainOnZombieMode` | 格子、僵尸行、小推车、子弹、炸弹、阳光 |
   | 5 | `CanvasLayerFG` | 雾、雨 |
   | 6 | `CanvasLayerDropItem` | 金币等掉落、`CoinBankLabel` |
   | 10 | `CanvasLayerCardSlotFront` | 战斗卡槽 |
   | 20 | `CanvasLayerTemp` | 手持物、`RealShovel` |
   | 30 | `CanvasLayerEffect` | 全屏特效（冰、毁灭菇） |
   | 50 | `CanvasLayerUI` | UI |
   | 60 | `CanvasLayerAlmanac` / `CanvasLayerConsole`（`CanvasLayerUI` 子层） | 图鉴 / 控制台 |

6. **同一层内按 `z_index = 行号 * 50 + 槽位` 排序**（全部由代码在运行时赋值，场景里写的会被覆盖）：

   | 槽位 | 内容 | 赋值处 |
   |---|---|---|
   | `+10` | 植物格子行 | `plant_cell_manager.gd:53` |
   | `+30` | 僵尸行 | `zombie_manager.gd:80` |
   | `+40` | 小推车 / 辣椒火 / 脑子 | `gim_lawn_mover.gd:84`、`gim_brain.gd:41`、`plant_cell_manager.gd:524` |
   | `+45` | 普通直线子弹 | `bullet_000_norm_base.gd:90` |
   | `4000` | 抛物线 / 玉米炮 / 追踪子弹（始终最上） | `bullet_000_parabola_base.gd:114` 等 |

## 六、行类型（Land / Pool / Both）

「这行是不是水」的事实现在只有**两份**数据（旧实现里还有第三份场景表
`MainSceneRegistry.ZombieRowTypewithMainScenesMap`，已随迁移删除）：

| # | 数据 | 位置 |
|---|---|---|
| 1 | 每行 `plant_cell_type`（Grass / Pool / Roof），生成时复制到每个格子 | `ResourceMapRowData.plant_cell_type` |
| 2 | 每行 `zombie_row_type`（Land / Pool / Both） | `ResourceMapRowData.zombie_row_type` |

**默认行类型**由 `map_data.get_default_zombie_row_type()` 算出：全行同类型就返回该类型，
水陆混合返回 `Both`。它决定自然刷怪白名单
（[level_data.gd:247](../resources/level_date_resource/script/level_data.gd#L247)），
白名单本身在 [global_read_data.gd:52-72](../scripts/autoload/global/global_read_data.gd#L52-L72)：
`Both` 取全部，Land / Pool 只取该僵尸自身行类型匹配的 + 本身是 `Both` 的僵尸。

每行 `zombie_row_type` 的运行时消费点：

- 出怪选行权重（[zm_zombie_choose_row_system.gd:43](../scripts/manager/zombie_manager/zm_zombie_choose_row_system.gd#L43)）
- 罐子按行类型分组（[plant_cell_manager.gd:264](../scripts/manager/plant_cell_manager/plant_cell_manager.gd#L264)）、
  罐子开出的僵尸（[scary_pot.gd:169](../scripts/item/scary_pot.gd#L169)）
- 陆生 / 水生僵尸身体、气球僵尸（[zombie_000_base.gd:221](../scripts/character/zombie/zombie_000_base.gd#L221)、`zombie_017_balloon.gd`）
- 蹦极 / 舞王跨行判断（`zombie_jackson_manager.gd`）
- 手持僵尸放置虚影的行合法性（[hand_component_character.gd:237](../scripts/manager/hand_manager/component/hand_component_character.gd#L237)）

> `validate_map_consistency()` 只保证「数据 ↔ 生成结果」一致，**不会检查 `plant_cell_type`
> 和 `zombie_row_type` 语义上是否匹配**。约定是 `Grass / Roof → Land`、`Pool → Pool`，
> 水陆混合的图（如 02_back）整体算 `Both`。改图时这一条要自己保证。

## 七、屋顶特化

- **格子是阶梯摆放的**：`col_dy = [99,84,63,45,17,0,0,0,0]`（5 行相同），第 6 列起贴平。
  `row_y`（88/173/259/343/430）是**行节点的平地基准 y**，第 0 列格子的绝对 y 是 `row_y + col_dy[0]`。
- 斜面本身仍在场景里：[main_game_03_roof.tscn](../scenes/main/main_game_03_roof.tscn) 的
  `CanvasLayerBG/Background/RoofSlope` + [scenes/main_game_bg/slope.tscn](../scenes/main_game_bg/slope.tscn)，
  `SegmentShape2D a=(0,122) b=(460,0)`（约 14.9°），5 个 `Area2DReal` 对应 5 行。
- `MainGameSlope.get_all_slope_y(x)`（[main_game_slope.gd:14](../scripts/main_game_bg/main_game_slope.gd#L14)）
  按 x 取相对 y：僵尸入场落位（`zombie_000_base.gd:204`）、僵尸放置虚影
  （`hand_component_character.gd:260`）、抛物线子弹影子、玉米加农炮都查它。
- `GlobalUtils.update_plant_cell_slope_y()` / `…_array()`（[global_utils.gd:8-25](../scripts/autoload/util/global_utils.gd#L8-L25)）
  用 `plant_cell.slope_step_y`（由 `PlantCellManager` 按 `get_col_dy` 赋值）把检测面
  **从阶梯位置反向补偿回 `row_y` 水平基准**。非屋顶地图 `slope_step_y` 恒为 0，等于空操作。
- ⚠️ **不要用 `plant_cell.position.y` 代替 `slope_step_y`**：数据驱动之后 `position.y` 是格子的
  **绝对 y**（含 `row_y`），拿它当阶梯偏移会把整行高度减到检测框的本地坐标上，受击框被抬走，
  僵尸会直接穿过植物不啃。消费点在 [plant_000_base.gd:119](../scripts/character/plant/plant_000_base.gd#L119)、
  `scary_pot.gd:74`、`ladder.gd:14`、`brain_on_zombie_mode.gd:27`。

## 八、新增 / 改造一张地图的步骤

1. **做数据**：复制最接近的 `map_*.tres`，在编辑器里改成目标几何；
   或者复制旧的手摆场景后用一次性工具导出（见第九节）。
2. **保证矩形**：每行列数一致，`col_x` / `col_width` 长度 = 列数，`rows` 长度 = 行数。
3. **逐行填**：`plant_cell_type`、`zombie_row_type`、`row_y`、`row_height`、
   `zombie_create_global_pos`（y 对准该行脚部）、`lawn_mover_type`、`have_rake`。
4. **屋顶**：逐行填 `col_dy`；`row_y` 写**行节点 y**，不要写第 0 列格子的绝对 y。
5. **注册**：新场景才需要在 `MainSceneRegistry.MainScenesMap` 与 `DEFAULT_MAP_PATHS` 各补一条；
   复用现有场景则只改 `map_data`（放到关卡 `.tres` 里覆盖，或直接改对应 `map_*.tres`）。
6. **关卡指向**：关卡资源的 `game_sences` 指到主场景；要特殊地图就直接在关卡里指定 `map_data`。
7. **进关卡看日志**：`validate_map_consistency()` 无 error 即通过。
8. **跑探针**：见第九节。

> 小推车类型不用单独维护：它跟着 `map_data.rows[].lawn_mover_type`，行数也由数据决定。

## 十、已知坑

- **屋顶 `row_y` 必须是「行节点的 y」而不是第 0 列格子的 y**：`slope_step_y` 按 `col_dy`
  把检测面反向补偿回 `row_y`。写错会让整行错约 99px，植物 / 僵尸检测框不重叠 → **互相不索敌**
  （平地地图 `col_dy[0] = 0`，所以只有屋顶会犯）。
- **不要写死行数**：行数取自 `zombie_manager.all_zombie_rows.size()`（出怪选行系统曾写死 6 行，
  5 行地图的兜底分支会返回越界行号）。
- **僵尸行节点统一用 `Node2D`**：`Panel + clip_children` 会把该行僵尸裁剪在面板矩形内。
- **关卡 `.tres` 里不要写 `属性 = null`**：nil 赋值对带类型的脚本属性等于没写（回落默认值），
  看起来像「关掉了小推车 / 选卡」，实际是默认值；要显式写值。
- **存档按 `row_col` 作数组下标**（[plant_cell_manager.gd:604-613](../scripts/manager/plant_cell_manager/plant_cell_manager.gd#L604-L613)），
  所以列号方向与行列顺序属于**存档格式的一部分**：改 `row_col` 语义、改列数或调整列顺序会让老存档整体错位 / 镜像。
- **`plant_cell.size` 必须在 `add_child` 之前设**：`PlantCell._ready` 会按当时的尺寸记录各容器节点
  初始位置，之后再改尺寸不会重算这些基准。
