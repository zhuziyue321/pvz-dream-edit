# 验证流程

本文件定义改完代码后**必须走一遍**的验证流程。
背景：本项目是游戏，没有单元测试框架，且大量逻辑依赖场景树与 autoload，
因此验证分成「可自动化的静态检查」与「只能人工跑游戏」两部分 —— 两边都不能省。

> ⚠️ **本次踩过的坑**：logger.gd 曾经在 `_write()` 里误用 `Log.debug()`，
> 导致 `_write → debug() → _write` 无限递归爆栈。编辑器全量扫描 **PROBLEMS=0**，
> 资源自检 **通过** —— 静态检查完全抓不到，只有真正执行才暴露。
> 这就是第 4、5 步存在的原因。

---

## 一键运行

```powershell
powershell -ExecutionPolicy Bypass -File test/verify.ps1
```

自定义 Godot 路径 / 跳过慢步骤：

```powershell
powershell -ExecutionPolicy Bypass -File test/verify.ps1 -Godot "D:\Godot\godot.exe"
powershell -ExecutionPolicy Bypass -File test/verify.ps1 -SkipSlow   # 只跑 1/2/3/6
```

退出码：全部通过 `0`，有失败 `1`。

## 六个步骤

> 编号里的 1b / 1c 是第 1 步的补充关卡，不是额外的大步骤 —— 所以仍然是「六步」。

| # | 步骤 | 抓什么 | 为什么不能省 |
|---|------|--------|--------------|
| 1 | **编辑器全量扫描**<br>`godot --headless --editor --quit` | 脚本解析/编译错误、失效的 `ext_resource` | 唯一能**编译**全部脚本的检查（`--script` 模式下没有 autoload，`Global` 之类的引用会误报） |
| 1b | **脚本编译自检**<br>`res://test/script_check.tscn` | 显式 `load()` 每一个 `.gd`，输出 `[SCRIPTCHECK]` | 编辑器扫描**不编译**只被字符串引用的脚本（`load("res://x.gd")` 的语法错误会静默漏过） |
| 1c | **规范静态检查**<br>`--script res://test/standard_check.gd` | 《[项目规范.md](项目规范.md)》的红线：裸 `print`、角色子类重写 `_ready()`、组件命名，输出 `[STDCHECK]` | 让规范不再只靠人记：违规直接判 FAIL 挡住交付（[WARN] 级项只提示、不影响结果） |
| 2 | **资源自检**<br>`--script res://test/project_checker.gd` | 逐个 load 所有 `.tres/.tscn/.gdshader`，报告加载失败与缺失的 `.uid` | 能定位到具体哪个资源坏掉，比第 1 步的聚合报错更细 |
| 3 | **引用完整性** | 全文抓取 `res://` 路径，逐个 `Test-Path` | 改名/移动资源后最容易漏的就是路径字符串（uid 能救回打开，但导出会炸） |
| 4 | **运行期冒烟**<br>`--script res://test/runtime_smoke.gd` | **真正执行** Logger / GlobalUtils / RandomPicker | 抓「编译得过、一跑就炸」的问题，例如递归爆栈 |
| 5 | **autoload 冒烟**<br>`res://test/autoload_smoke.tscn` | 8 个单例全部注册、日志可用、关键属性存在 | 唯一能验证 autoload 初始化顺序的检查；用**隔离的 user 目录**跑，不会碰你的存档 |
| 6 | **卫生检查** | `*.tmp`、孤儿 `.uid`、`*__casetmp*` | 这些残留会污染 Godot 文件系统视图 |

### 关于存档隔离

跑游戏就会写 `user://`（日志、编辑器设置、存档）。
`verify.ps1` 的**每一步**都把 `%APPDATA%` 重定向到一个临时目录，跑完即删，
**不会影响你的真实存档**，也不会去动真实的编辑器设置。

> 为什么是「每一步」：早先只有第 5 步隔离，其余步骤去写真实 `%APPDATA%\Roaming\Godot`；
> 在受限环境（沙箱/只读 AppData）里这会让 Godot **直接崩**（`user://logs/...` 打不开 → signal 11），
> 表现成「1b/2/4 三步神秘失败而 5 却通过」。

### 关于 autopilot 注入

`DebugChannel` 只要看到 `test/inject/scenario.gd` 存在，就会把 autopilot 注入**每一个**启动的场景。
第 1b 步（`script_check.tscn`）和第 5 步（`autoload_smoke.tscn`）启动的不是游戏，
被注入会互相打架（`script_check` 会崩，exit `0xC0000005`），
所以这两步都带 `-- --no-autopilot`。

### 机器可读标记

三个 Godot 侧测试各自输出一行纯 ASCII 汇总，供 `verify.ps1` 解析：

```
[SCRIPTCHECK]   checked=<n> failed=<n> result=PASS|FAIL
[STDCHECK]      scripts=<n> checks=<n> failed=<n> warned=<n> result=PASS|FAIL
[SELFCHECK]     checked=<n> loadFailures=<n> missingUid=<n> result=PASS|FAIL
[RUNTIME-SMOKE] passed=<n> failed=<n> result=PASS|FAIL
[AUTOLOAD-SMOKE] failed=<n> result=PASS|FAIL
```

**为什么必须纯 ASCII**：PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 ANSI 读取，
脚本里写中文正则会变成乱码、永远匹配不上（第一次跑就踩了这个坑）。
所以 `verify.ps1` 全文不含中文，只匹配上面这几行标记。

> Godot 侧脚本的**明细**可以写中文（例如 `standard_check.gd` 的违规定位行），
> 只有 `verify.ps1` 里参与匹配的内容必须 ASCII。

## 人工回归清单（自动化覆盖不到）

自动化只能证明「编译通过、资源引用完好、工具类能执行」。
**游戏行为必须进游戏实测**。改动相关模块后至少覆盖：

| 模块 | 检查点 |
|------|--------|
| 日志 | 进游戏、切场景、开菜单，控制台不刷错；发布版默认只出 `INFO` 及以上 |
| 卡片 | 选卡→种植→冷却→阳光不足置灰；多轮关卡二次选卡不重复扣费 |
| 手持物 | 持卡有虚影、能种/不能种的反馈、铲子铲除、右键取消；**轮次切换与游戏结束不残留手持物**；关卡没有铲子时卡槽不出现铲子（组件化说明见 [手持物实现.md](手持物实现.md)，自动回归 `-Scenario probe_hand`） |
| 角色初始化 | 改过角色 `_ready` / `ready_norm` 链路、组件挂载后跑：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_init`（普僵随机外观、窝瓜掩码组件、睡莲初始化，输出 `[INIT] result=`） |
| 临界值组件 | 默认临界值=自身死亡临界值、低于临界值/已死亡的僵尸不触发小推车、自定义临界值下的自动掉血与事件、死亡后禁用：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_critical_value`（输出 `[CRIT] result=`） |
| 泳池 | 僵尸进/出泳池状态正确，**快速进出**不会卡在「陆地游泳」 |
| 花园 | 手套抓起发芽植物、植物成长为新植物后格子状态正确 |
| 小游戏 | 锤子：未启用时不挥锤、点到 UI 不挥锤、砸僵尸正常 |
| 「我是僵尸」 | 多轮模式下打光脑子能拿到奖杯（旧脑子不会把计数减成负数） |
| 僵尸特化 | 小僵尸跳跃距离不衰减；冰车压植物时受击框生效；大蒜换行正常 |
| 万寿菊 | 正常掉金币（曾经调用了不存在的 `Global.create_coin()`，永远不掉） |
| 存档 | 读档植物位置正确；损坏存档不覆盖旧档 |

## 维护这些工具时注意

1. **改 `verify.ps1` 不要写中文**（除非你确认用带 BOM 的编码保存）。用 ASCII 标记行通信。
2. **新增运行期测试**时，同样输出一行 `[XXX] ... result=PASS|FAIL`，并在 `verify.ps1` 加对应步骤。
3. **批量重命名文件/目录前先关 Godot 编辑器**：编辑器会把瞬时消失的 `.uid` 当孤儿文件删除
   （本项目曾一次性被删掉 17 个 `.uid`，靠备份恢复）。
4. 往项目里加 `print()` 之前先看 [项目规范.md](项目规范.md) 的日志一节 —— 一律走 `Log`。
   第 1c 步会直接判 FAIL；只有 `logger.gd` 整体与 `debug_channel.gd::_line()` 是登记例外。
5. **改规范红线时同步改检查器**：`test/standard_check.gd` 的 `_build_checks()` 里一个条目就是一条检查，
   豁免文件/函数写在文件顶部常量里（`PRINT_EXCEPTIONS` / `CLASS_NAME_EXCEPTIONS`），
   加豁免**必须**同时在 [项目规范.md](项目规范.md) 对应卡片里登记。
5. **不要用 `Start-Process` 起 Godot**：部分受限环境直接 `Access is denied`，
   而 Godot 在 Windows 是 **GUI 子系统程序**，不重定向就完全抓不到 stdout。
   统一用 `cmd.exe /c '"<godot>" <args> > out.txt 2> err.txt'`（`verify.ps1` / `run_autopilot.ps1` 已改）。
6. 新增的启动步骤，若是「启动场景但不是玩游戏」，记得带 `-- --no-autopilot`。
7. **写探针断言时不要依赖随机结果**：本项目大量逻辑用 `randi_range` / `pick_random`
   （僵尸随机外观就是逐项 `pick_random`，全 false 的概率 1/8）。
   断言只写**确定性**判定，随机值放到 detail 里打印 —— 否则探针会随机翻车，
   让人误以为是代码坏了。`test/scenarios/probe_init.gd` 里有正反面示例。

## 调试通道（运行期取证）

静态检查与冒烟测试都只能覆盖「已知的检查点」。
当遇到**只有在真实对局里才复现**的问题时，用调试通道把现场录下来。

### 设计原则

**默认完全静默** —— 不带参数启动时，它只在启动时做一次判定就什么都不做，
不影响正常游戏、不写任何文件。只有满足以下任一条件才激活：

1. 命令行带用户参数：`-- --debug-channel` 或 `-- --debug-channel-level`
2. 存在开关文件 `user://debug_channel.on`

### 用法一：正常游玩时录制（推荐给我排查用）

双击 `test/debug_channel.bat`：

1. 游戏正常启动，**你自己玩**
2. 想记录现场时按 **F10**，会把当前状态快照追加进报告
3. 玩完关掉游戏
4. 把生成的 **`debug_channel_log.txt`** 发我

日志里同时包含：Godot 自身所有 `print`/错误输出 + 调试通道的结构化报告。

### 用法二：全自动跑一关（无需操作）

双击 `test/debug_channel_auto.bat`：

- 无窗口（`--headless`）启动
- 自动载入 `adventure_01_01.tres` 并切到主游戏场景
- **自动跳过选卡**（调用 `main_game_start()`，否则游戏会永远停在选卡阶段，僵尸不刷）
- 跑 45 游戏秒，期间每 120 帧采样一次
- 出报告后自动退出

自定义时长：`set SECONDS=90` 后再运行。

**这个流程不会碰你的存档** —— `.bat` 里把 `%APPDATA%` 重定向到了 `%TEMP%\pvz_debug_userdir`。

### 报告里有什么

| 区块 | 内容 |
|------|------|
| 环境 | 引擎版本、平台、渲染方式、视口、时间缩放、main_scene |
| 自动加载 | 8 个核心单例是否都注册（缺哪个直接列出） |
| 日志自检 | 四级日志各调一次 —— **曾经这里会无限递归爆栈**，看到「正常」即为通过 |
| 注册表 | 角色（植物/僵尸条数）、子弹、AllCards 卡牌数、SceneRegistry 抽检 |
| 运行时状态 | 当前场景、`Global.main_game` 是否有效、植物格子行列数与**失效引用数**、场上僵尸数与**失效引用数** |
| 采样 | 每 120 帧：frame / fps / 节点数 / **孤儿节点数** / 静态内存 / 场景 / 场上僵尸数 |

「失效引用数」和「孤儿节点数」是排查**对象泄漏与悬空引用**最直接的两个指标，
正常情况下应始终为 **0**。

### 已知的正常现象

- 无头模式下 `视口尺寸` 显示 `(0, 0)`、`fps` 会跑到 140+（无垂直同步），都不是问题。
- 自动关卡模式强制退出时可能打印 `ObjectDB instances leaked at exit` ——
  这是**中途掐断对局**造成的，手工正常退出不会出现，属预期。
- stderr 里必然有一行 `[调试通道] error 级自检` —— 那是故意触发的，用来验证 error 级能正确走 stderr。
- 本机还会固定出现 `Failed to read the root certificate store`（没有可读的根证书库），
  `verify.ps1` 已把它当环境噪声过滤，不是项目问题。

### 不要它了怎么移除

1. 删掉 `project.godot` 里 `[autoload]` 下的 `DebugChannel=...` 一行
2. 删掉 `scripts/autoload/debug_channel.gd`（含 `.uid`）
3. 删掉 `test/debug_channel*.bat`
