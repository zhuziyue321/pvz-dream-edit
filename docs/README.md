# docs/ 文档地图（面向 AI Agent）

> **[给 AI Agent] 本目录下的每一份文档都面向 Agent 编写**，开头带统一的「面向 AI Agent」元信息头。

## 1. 三层结构：什么东西放在哪一层

> 记这一条就够：**规则与方法论在 `docs/` 顶层；项目相关的参考文档在 [参考存档/](参考存档/README.md)；一次任务的流程记录在 [工作记录/](工作记录/README.md)。**

| 层级                                    | 放什么                                  | 举例                                              | 强制级别             |
| ------------------------------------- | ------------------------------------ | ----------------------------------------------- | ---------------- |
| **`docs/` 顶层**（本层）                     | **规则 / 方法论 / 管理类**：怎么写、怎么验、怎么协作      | `项目规范.md`、`验证流程.md`、`AI调试通道.md`、`Agent协作协议.md` | **必须** / 按需      |
| **[`docs/参考存档/`](参考存档/README.md)**    | **项目相关**的机制 / 内容说明：某块玩法怎么实现、数据从哪来   | `地图实现.md`、`子弹说明.md`、`关卡数据与出怪表.md`              | **参考**（不做也不打回）   |
| **[`docs/工作记录/`](工作记录/README.md)**    | **逐次任务**的流程记录：步骤 / 决策 / 踩坑 / 最简路径    | `2026-10-01_机制类文档降级到工作记录.md`（历史任务，已标注后续变动）     | **应该**（收尾时建一条）   |

> 层级判定：一句话描述得了「该怎么做」→ `docs/` 顶层；描述的是一个具体模块 / 数据 → `参考存档/`；描述的是「这次任务干了什么」→ `工作记录/`。

## 4. 阅读顺序

- **首次进仓库**：`AGENTS.md` → 本文件 §1（先认三层）→ [项目规范.md](项目规范.md) §1 宏观硬约束（细则按 §2 目录去 [参考存档/](参考存档/README.md) 查）。
- **身处某个代码目录**（`src/` `data/` `animation/` …）：先看该目录的 `AGENTS.md`（一眼版指针，见 §3），再回到本文取正文，不要全读。
- **开工前**：[工作记录/README.md](工作记录/README.md) §2 索引找同类任务的最简路径（有就照抄，没有就收尾时补一条）。
- **只做一件事**：按 §2.1「什么时候必须读」那一列取**对应的一份**；改具体模块时再按 [参考存档/](参考存档/README.md) §1 取机制文档，不要全读（上下文宝贵）。
- **交付前**：[验证流程.md](验证流程.md) —— 先判「要不要验证」，要验证就打开游戏。

## 5. 「面向 AI Agent」元信息头模板

新增文档时**必须**遵守：文件第一行放 `AGENT-DOC` 标记（便于 `grep` 发现），正文开头放元信息块。

```markdown
<!-- AGENT-DOC: index / pointer / archive / record -->

# <标题>

> **[面向 AI Agent]** ｜ **触发条件**：<什么情况下必须读这份>
> **读完你能**：<可判定的产出，一条一句>
> **强制级别**：**必须** / 应该 / 参考 ｜ **不读的风险**：<会坏成什么样>
> **关联**：<上下游文档的相对链接>

<正文>
```

字段要求：

- **首行标记**：`<!-- AGENT-DOC: <类型> -->`，类型取 `index`（目录 / 索引）/ `pointer`（指针）/ `archive`（参考存档）/ `record`（任务记录）/ `spec`（规范与方法论）/ `human`（面向人的说明，Agent 不必读）。
  `grep -l "AGENT-DOC" -r .` 能捞出全部带标记文档；检查某份是否漏标记就用同一条命令反查。
- **触发条件**：写具体动作（如「改地图 / 新增子弹」），不写「需要了解时」这类空话。
- **读完你能**：可判定，最好能对应到一个具体产出（如「知道该继承哪个基类、要登记哪张表」）。
- **强制级别**：只用「必须 / 应该 / 参考」，与 [项目规范.md](项目规范.md) §1.1 一致。

## 6. 维护约定

- 新增文档 → 先按 §1 判定层级：规则 / 方法论放本层，项目相关的机制说明放 [参考存档/](参考存档/README.md)，本次任务的流程记录放 [工作记录/](工作记录/README.md)；加元信息头，并在对应目录的索引表登记一行。
- 新增一级目录 → **建议**在该目录放 `AGENTS.md` + `README.md` 各一份（只做指针、不复制规范正文），并在 §3 登记一行；目录用途变了同步改这两份。
- 改名 / 移动 → 必须全局替换引用：其他 md、`test/`、`src/` `data/` 注释里的 `docs/xxx.md`，以及 `.gd` / `.tres` 注释里的同一种路径写法。
- 规范类内容只进 [项目规范.md](项目规范.md)（按 E-01 编号）；机制说明只进 [参考存档/](参考存档/README.md) 下对应主题文档 —— 同一件事**只在一处**写。
- 代码行为变了 → 同步改对应文档。**文档与代码漂移等同 bug。**
- **踩坑 / 经验即时沉淀**（[项目规范.md](项目规范.md) E-04）：本次任务内写进文档 —— 约束进 [项目规范.md](项目规范.md)，机制进 [参考存档/](参考存档/README.md) 的专题文档，一次性排查过程进 [工作记录/](工作记录/README.md) 里本次的记录文件；**只写在回复里等于没写**。
- **收尾归档流程**（[项目规范.md](项目规范.md) E-05）：每次任务结束在 [工作记录/](工作记录/README.md) 新建 `<YYYY-MM-DD>_<主题>.md`，并在该目录 README §2 索引补一行；**禁止**另建散落流程文件。
- **规则强制级别**（[项目规范.md](项目规范.md) §3）：细则写进 [参考存档/规范细则存档.md](参考存档/规范细则存档.md)（措辞改「建议 / 不建议」），
  规范里只留目录行 + 链接，**并同步摘掉 §1 硬约束表 / AGENTS.md 里的强制字样** —— 否则只是又多了一处必须遵守的副本。
