# 2026-10-11 · 其它 · 模组开关与设置统一存进 `user://<用户名>/mod_config.ini`

> **任务类型**：其它
> **推荐度**：**推荐**（「开关要能持久化」= 找一份**用户目录下**的存档文件，别再指望 `data/` 里的资源）
> **耗时与成本**：约 1 轮，未开游戏（无头 `probe_mod_page` PASS ×2 + 门禁 PASS，已给人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（改动集中在模组层，页面是纯 Control 界面，无头探针跑得完）
> **补充自**：[2026-10-11_模组页面左右分栏.md](2026-10-11_模组页面左右分栏.md)（那条留下「开关只改本次运行」的缺口，本次补上）

## 目标

模组页面的开关点了要**真的持久化**（下次启动照旧），并且**模组自己的设置**（手套冷却、联机目标 / 快照频率）
与开关在同一份文件里 —— 一个模组一段，`enabled` 是开关，其余键是它的设置。

## 步骤

1. 先确认旧落点：开关在 `data/mods/mod_config.tres`（工程资源），设置落在 `ConfigService.console_values`
   （`config.ini` 的 `[console]` 段）。**两份、且工程资源导出后写不回去** —— 这就是"点了不持久"的根因。
2. `ModManager` 加存档区：`_save_path()`（=`user://<用户名>/mod_config.ini`）/ `_load_save()` / `save_mods()`
   / `_schedule_save()`（帧末合并写一次）/ `get_mod_value()` / `set_mod_value()` / `reload_for_current_user()`。
3. 装载顺序改成 `_load_config()`（工程默认）→ `_load_save()`（存档覆盖）→ `_install_enabled_mods()`；
   存档文件不存在时**照工程默认播种一份**并落盘，之后一律以存档文件为准。
4. `set_mod_enabled()` 拆成「改内存 + 补装 / 卸载」的 `_apply_enabled_state()` + 落盘 —— 换用户重读时也复用它。
5. 换用户不用改 `Global`：`ModManager._ready()` 自己连 `UserManager.signal_users_update` 重读。
6. 两个模组的设置改走 `ModManager`（手套冷却两件套、联机的 `target` / `send_rate`），
   `ConsoleEntry` 从 `bind_config()` 改成 `bind(getter, setter)`。
7. 探针 `probe_mod_page` 加第 5 节：写 → 读回（`reload_for_current_user()`）→ 断言开关与设置都在。
8. 文档同步：`模组机制.md`（新增 §2.1）/ `控制台.md` / `联机模组.md` / `关卡格式V2.md` / `架构总览.md` / 两个目录指针。

## 关键决策与理由

- **放在用户目录下（一人一份），不放在 `user://` 根目录** —— 与 `config.ini` 同款口径，切用户存档就换一份；
  代价是要处理换用户，`ModManager` 自己盯信号解决，没去动 `Global.reload_session_for_current_user()`（autoload 顺序上更省心）。
- **`data/mods/mod_config.tres` 不删，降级成"播种用的工程默认"** —— 删了就没有「新用户默认开哪些模组」这一层，
  而且现有开发态（联机开着）会丢；播种后存档文件就是唯一事实来源。
- **设置与开关同段（一个模组一个 section），不搞两个 section** —— 玩家打开 ini 一眼看懂"这一块全是这个模组的"，
  段名就是模组 id，也不用维护键名前缀（`glove.cooldown_time` → `[glove] cooldown_time`）。
- **落盘用帧末合并（`call_deferred`），不在 setter 里直接写** —— 滑条拖动时 `value_changed` 每帧都来，
  一帧内的多次改动合并成一次写盘；真要立刻落盘就调 `save_mods()`。
- **不碰 `ConsoleEntry.bind_config()`**（那是控制台的通用键值区）—— 模组的设置走 `ModManager`，
  以免又出现「同一件事两份落点」。

## 踩坑

1. **探针之间会互相污染**：开关持久化之后，`probe_glove_unlock`（自己打开手套模组）跑完不关回去，
   会写进共享的临时用户目录，下一个 `probe_hand` / `probe_mod_page` 就拿到"手套开着"的状态。
   → **正解**：开模组的探针**收尾必须还原并 `save_mods()`**（照 `probe_custom_level_mod` 已有的写法），
   被影响那一端也加一道"先归零再验"（`probe_mod_page` §2 开头先把手套关回去）。
   ⚠️ 以后谁再写一个"临时打开模组"的探针，这是必做项。
2. **换用户的入口没写在 `Global` 里**：`signal_users_update` 在 `set_current_user()` 里发（那时存档还没重载），
   但 `curr_user_name` **已经改好了** —— 模组只要用户名，所以在这个信号里重读是对的；
   别挂到 `Global.reload_session_for_current_user()` 上（`ModManager` 是排在 `Global` 之后的 autoload，启动那次会被提前调用）。
3. `probe_glove_unlock` 原先 3 条 NG（`is_enabling` / 卡槽显示 / 空手图标）+ stderr 报
   `Invalid call. Nonexistent function '_build_dave_dialog'` —— **与本次改动无关的两处失修**（见下条），本次一并修好：
   - **第 2 节**：4-6 已是关卡脚本，对话资源挂在常量 `DAVE_GLOVE`（`res://data/dave/dialog/adventure_04_06_glove.tres`）
     上，不再有 `_build_dave_dialog()` 这个函数 —— 探针改成直接加载那份 tres。
   - **第 3 节（真凶，值得记住）**：**连续两次进主游戏时必须排除上一局**。
     `GlobalUtils.change_scene()` 是 `call_deferred` 到帧末才切，探针切完立刻 `_wait_main_game()`
     第一眼看到的还是**上一局**的 `curr_main_game`（已在 MAIN_GAME 阶段）→ 直接返回 →
     断言的是上一局的手套组件（它在上一局的进度 34 下判成了禁用），
     表现就是"进度明明 35 却没启用"，很容易误判成模组坏了。
     → 正解：记住旧局实例，等到 `GameContext.curr_main_game != old_mg` 为止。
     ⚠️ 以后写"跑两遍关卡"的探针，这是必做项（`probe_hand` 里那种手动 `change_is_enabling()` 补一次的做法
     只能盖住症状：真正该验的是"进新局时自己判对"，不是"探针帮它补一刀"）。

## 给后来者的最简路径

1. 要持久化一个开关 / 设置 → 确认落点在 **user:// 下**（`data/` 里的 `.tres` 导出后写不回去）。
2. 模组类的值一律 `ModManager.get/set_mod_value(ModIds.XXX, "键", 默认)`，不用给 `ConfigService` 加字段。
3. 面板上的条目用 `ConsoleEntry.bind(读, 写)`，**不要**用 `bind_config()`。
4. 写探针时开了模组 → 收尾 `set_mod_enabled(false)` + `save_mods()`；被影响那一端开头先归零。
5. 跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_mod_page`（无头即可）。
6. **探针连着进两次主游戏**：记住旧局，等 `curr_main_game` 换成新实例再断言（见「踩坑」3）。
