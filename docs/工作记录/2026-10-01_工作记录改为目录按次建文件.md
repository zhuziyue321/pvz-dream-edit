# 2026-10-01 · 文档规范 · 工作记录改为「docs/工作记录/ 目录 + 一次任务一个文件」

> **任务类型**：文档规范
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，纯文档改动
> **验证方式**：免验证（只改 `docs/` 与 `AGENTS.md`，不触达玩法行为，符合 [V-01](../参考存档/规范细则存档.md#v-01-改动较小可免验证)）

## 目标

工作记录不再堆在单一文件里按天追加，改为落在 `docs/工作记录/` 目录：每次任务收尾新建一个记录文件，目录 README 做索引 + 模板 + 命名规则。

## 步骤

1. 新建 `docs/工作记录/README.md`（目录索引 §2、记录模板 §3、命名规则 §4、"必要信息"表）。
2. 把原 `docs/工作流程存档.md` 里的两条记录拆成两个文件迁进该目录：`2026-10-01_新增踩坑沉淀与流程归档规则.md`、`2026-10-01_细枝末节规则降级为参考意见.md`（内部链接改为 `../` 上跳）。
3. 删除 `docs/工作流程存档.md`。
4. 改 [E-05](../参考存档/规范细则存档.md#e-05-工作流程归档每次任务结束必做) 卡片：落点从"追加一条"改为"新建 `<YYYY-MM-DD>_<主题>.md` + 索引补行"，补上"为什么一次任务一个文件"。
5. 全仓替换引用：`项目规范.md` 7 处（关联表 / §0.1 / V-02 / 红线 15 / §9 任务表 / E-04 卡片 / E-05 卡片正文）、`docs/README.md` 4 处、`AGENTS.md` 4 处。

## 关键决策与理由

- **一次任务一个文件**，而不是单文件追加 —— 单文件会无限变长（检索靠锚点、多人并行追加易冲突），且"某条已过时"无法单独标注；拆文件后索引表一行即可定位。
- 索引 + 模板 + 命名规则全放在目录 README —— 后来者进目录就能知道怎么写、写在哪，不用再回规范里翻 E-05。
- 目录名用中文 `工作记录/` —— 与 `docs/` 下现有中文文档（`项目规范.md` 等）保持一致，对 Agent 语义更直白。

## 踩坑

1. 迁移后记录文件里的相对链接全部失效（原文件在 `docs/` 下，新位置在 `docs/工作记录/`）→ 场景/脚本链接会指向不存在的路径 → **正解**：迁移时把 `[项目规范.md](项目规范.md)` 这类链接统一改成 `../` 上跳（`[项目规范.md](../项目规范.md)`）。
2. 只改规范本体就以为改完了 → grep 才发现 `工作流程存档` 在 3 个文件里共 15 处 → **正解**：落点类改动收尾前 `grep "工作流程存档"` 全仓复核（与上一轮降级改动的 grep 复核同套路）。
3. 写完 README 后编辑器自动格式化，把首行 `<!-- AGENT-DOC -->` 标记删掉了（模板里的也删了）→ 该标记是 `grep -l "AGENT-DOC"` 发现文档的唯一依据 → **正解**：新增/改动 md 后检查首行标记仍在（本轮已补回）。

## 给后来者的最简路径

1. 收尾要记流程 → 复制 [README §3 模板](README.md) 新建 `docs/工作记录/<YYYY-MM-DD>_<主题>.md`。
2. 在 [README §2 索引](README.md) 补一行（日期 / 任务类型 / 目标 / 推荐度 / 耗时 / 文件链接）。
3. 记录内的文档链接用 `../` 上跳到 `docs/`。
4. 改落点类规则后：全仓 grep 旧路径名，逐处替换。
