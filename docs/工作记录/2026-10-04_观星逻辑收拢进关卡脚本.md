# 2026-10-04 · 其它 · 观星的特殊逻辑全部收拢进关卡脚本（不再散在关卡数据 / GIM_Other / 轮廓节点里）

> **任务类型**：其它
> **推荐度**：**推荐**（下次「特殊玩法要在进关时摆自己的场 / 打格子限制」照这个走）
> **耗时与成本**：约 1 轮对话，带窗口跑探针 `probe_seeing_stars`（19 断言全过）
> **验证方式**：打开游戏实测（带窗口探针，`[SEESTARS] result=PASS failed=0`）
> **补充自**：[2026-10-04\_实现观星SeeingStars.md](2026-10-04_实现观星SeeingStars.md)（那次把逻辑铺在了 5 个文件里，这次收拢）

## 目标

观星的特殊逻辑全部集中在 `src/levels/mode_minigame/minigame_07_seeing_stars.gd` 一个文件：
`ResourceLevelData` 上没有观星开关，`GIM_Other` 里没有观星分支，轮廓节点里没有观星规则。

## 步骤

1. 认清约束：**关卡脚本是 Resource，不能 `add_child`** —— 绘制必须有 Node，所以
   「把逻辑搬进脚本」不等于「删掉节点」，而是把节点降级成不含规则的通用组件。
2. `LevelScriptBase` 加通用钩子 `init_level_items(mg, item_root)`；`GIM_Other.init_other_item()`
   只调这个钩子，不再认识任何具体玩法。
   时机：排在 `plant_cell_manager.init_manager()` 之后（格子已建好）、玩家能动手之前。
3. 旧的 `SeeingStarsOutline`（含坐标表 + 限种 + 判定）→ 拆成两半：
   规则进关卡脚本；绘制层改名 `CellStarOverlay`（`src/items/mini_game/cell_star_overlay.gd`），
   只收「格子列表 + 达标判定 Callable」，玩法规则一行不留。
4. 删掉 `ResourceLevelData` 的「观星」子组三个字段（`is_seeing_stars` / `seeing_stars_cells` /
   `seeing_stars_max_flag`）；换成脚本自己的 `STAR_CELLS` / `MAX_FLAG`。
5. 探针 `probe_seeing_stars.gd` 改从关卡脚本取 `star_cells` / `star_overlay` /
   `is_all_star_cells_planted()`，不再走 `gim_other.seeing_stars_outline`。

## 关键决策与理由

- **保留 `PlantCell.only_allow_plant_types` / `forbidden_plant_types` 与种植第一道闸不动**
  —— 那是「格子能不能种某种植物」的通用能力，不是观星逻辑；观星只是往里塞数据。
- **新增 `init_level_items()` 钩子而不是在 `run_flow()` 里打限制** —— 进关时玩家已经能动手了，
  留到流程里（选完卡之后）限制生效太晚，原实现专门为这事把创建动作塞进了 `GIM_Other`。
- **绘制层改名 + 删除旧文件**（而不是就地改 class）—— 让「观星」字样从非脚本文件里彻底消失，
  后来者一眼看得出规则在哪；`.tscn` 用 `path` 引用脚本，新建文件不必造 `.uid`（编辑器会补）。

## 踩坑

1. 一开始想「干脆把节点也删了，用 `_draw()` 挂在别的现成节点上」→ 关卡脚本是 Resource，
   没有 `_draw()` 也没有子节点 → **正解**：必须留一个 Node 承载绘制，但让它彻底变哑
   （数据 + 判定全由脚本传进去）。
2. 探针原断言 `mg.game_para.is_seeing_stars` → 字段已删 → **正解**：改成断言脚本上的
   `star_cells.size() == 21` 与 `star_overlay != null`，把「规则在脚本上」这件事也验进去。

## 给后来者的最简路径

1. 特殊玩法要在进关时摆场 / 打限制 → 覆写 `LevelScriptBase.init_level_items(mg, item_root)`，
   在里面 `item_root.add_child(自己的节点)` 并给 `PlantCell` 打限制；**不要**去 `GIM_Other` 加分支。
2. 需要画东西 → 用/写一个「不含规则的」通用绘制层（参考 `CellStarOverlay`），
   由关卡脚本传数据与达标判定。
3. 特殊胜负条件 → 脚本里 `await mg.main_game_start()` 后自己轮询，别用 `prefab.start_battle()`。

## 补充（2026-10-04）：绘制层文件跟着挪到关卡侧

承接上文的第 2 条：`CellStarOverlay` 当时虽然已经不含规则，文件却还留在本体目录
`src/items/mini_game/` → 按硬约束 §1-8 挪到 `src/levels/mode_minigame/cell_star_overlay.gd/.tscn`
（与唯一使用者 `minigame_07_seeing_stars.gd` 同目录）。

踩到的两点：

1. **模式目录 = 关卡目录**：`LevelRegistry._scan_dir()` 会把 `mode_*/` 下**每个 .gd 都登记成关卡 id**，
   直接丢进去会在迷你游戏组里多出一个假关卡 id `cell_star_overlay`（现在选关界面还硬挂在 .tscn 上，
   所以看不出来；等切到注册表就会冒出来）。**正解**：给注册表加一条通用判据
   `LevelRegistry.is_level_file_name()` —— 模式目录里的关卡脚本文件名以目录名去掉 `mode_` 为前缀
   （`mode_minigame` → `minigame_`），不符合的一律不登记；`test/scenarios/probe_levels.gd`
   里那份「同款」遍历同步改成了调用它。
2. **关卡侧的东西要自己收拾**：本体不会再管这个节点，所以 `CellStarOverlay.free_item()`
   （断格子信号 + `queue_free()`，可重复调用）与关卡脚本的 `_free_star_overlay()` 成对加：
   `init_level_items()` 开头先清一遍（重进关不留两叠虚影），`run_flow()` 末尾再清一遍
   （赢 / 输 / 僵尸进家都从那里往下走，奖杯位置已经取过了）。

验证：带窗口跑 `probe_seeing_stars`。
