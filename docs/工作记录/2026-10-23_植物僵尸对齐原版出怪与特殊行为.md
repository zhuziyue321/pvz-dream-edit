# 2026-10-23_植物僵尸对齐原版出怪与特殊行为

> **本次任务**：把植物僵尸（ZomBotany）剩下的 4 处与原版的行为差异改掉：
> 关 2 出怪表多普僵、两关旗帜波多「旗子僵尸 + 普僵」、窝瓜僵尸只压一株、辣椒僵尸「碰植物才炸」。
> **耗时 / 轮次**：约 6 轮；**未开游戏**（编译门禁通过；`probe_zom_botany` 因有 Godot 进程在跑没跑成）。
> **推荐度**：推荐（原版口径靠读 `../PvZ-Portable-main` 定，不靠记忆）。

## 目标

上一轮已经对齐了耐久 / 战力权重；本轮对齐**行为**。判断依据一律是原版 C++：

| 差异 | 原版依据 |
| --- | --- |
| 两关只出植物僵尸，不出普僵 | `Board::InitZombieWaves` 旗帜波那段对 `WAR_AND_PEAS` / `_2` 特判跳过「补普僵 + 旗子僵尸」 |
| 关 2 的可用僵尸只有 6 只 | `Challenge::GetZombiesForMode` 的 `WAR_AND_PEAS_2` 白名单 |
| 窝瓜压整格 | `UpdateZombieSquashHead` → `SquishAllInSquare` |
| 辣椒到点自爆 | `UpdateZombieJalapenoHead`：`mPhaseCounter == 0` 才烧行、`DieNoLoot()`，与是否碰到植物无关 |

## 最简路径（步骤）

1. **先确认 tick 口径**：原版 `SECONDS_PER_UPDATE = 0.01f`（100 tick/s）。
   由此 `mPhaseCounter = 150` 就是 1.5 秒 —— 所以本仓库豌豆僵尸 `attack_cd = 1.5` **本来就已经对齐**，
   不用改。同理机枪 1.5 秒一轮也对，只是 4 发间隔 0.12s vs 原版 0.17s（可忽略）。
2. **出怪表**：删掉关 2 `zombie_list` 里的 `ZombieIds.NORM`。
3. **旗帜波**：在 `ResourceLevelData` 加总开关 `spawn_plain_zombie_extra`（默认 true），
   `ZombieWaveCreateManager.init_zombie_wave_create_manager()` 读进成员，
   `get_curr_wave_zombie_list()` 里包住**两处**：旗帜波段（`FLAG` + 4/8 普僵）与点数残差补普僵。
   两关 `_init()` 写 `false`。
4. **窝瓜僵尸**：`_squash_target_cell(target)` 取 `target.plant_cell` 遍历整格，读槽位走 `PlantCell.get_plant()`。
5. **辣椒僵尸**：`ready_norm()` 抽 18~30 秒倒计时，`_physics_process` 累减，到点 `_burn_lane()` + 自毁。
   停表条件对照原版 `IsImmobilizied()` = 冰冻陷阱 / 黄油（`influence_speed_factors` 的
   `IceFreezeSpeed` / `Butter` 两档为 0），**减速档不算**。
6. 探针补一条 `_check_levels()`：`load(关卡脚本).new().spawn_plain_zombie_extra == false`。
7. `test/check_scripts.ps1` → `real compile errors = 0`。

## 弯路 / 踩坑（三段式）

- **试过**：`var plant := cell.get_plant(place)`（`cell` 来自无类型的 `Array`）。
- **因为**：`cell` 是 Variant，`get_plant()` 的返回类型推不出来，`:=` 直接 Parse Error。
- **结论**：先 `var plant_cell := cell as PlantCell` 再读，或显式标类型。门禁会直接报 `Parse Error`。

- **试过**：想用 `move_component.curr_speed_product == 0` 判断「被定住」。
- **因为**：`curr_speed_product` **默认就是 0.0**（只有 `signal_update_speed` 发过一次才有值），
  拿它判 0 会让辣椒僵尸永远不自爆。
- **结论**：改读 `influence_speed_factors` 字典里 `IceFreezeSpeed` / `Butter` 两档（有键且为 0 才算停住）。

- **试过**：`test/run_autopilot.ps1 -Scenario probe_zom_botany`。
- **因为**：本机有用户开着的 Godot（pid 2124），脚本按残留进程判 `STALE_PROCESS` 退出。
- **结论**：不杀进程；改用编译门禁 + 静态核对（开关赋值、出怪表内容）交付，探针留给用户关掉编辑器后跑。

## 推荐度与理由

推荐。要点：**原版是「时间驱动」的不是「碰撞驱动」的** —— 辣椒僵尸到点自爆（被植物挡住边啃也会炸），
窝瓜是跳起压整格。这两条靠 wiki 文字看不出来（wiki 只写 "explodes, destroying all plants in its lane"），
必须读 `Zombie.cpp` 的 `UpdateZombieXXXHead` 才定得下来。

踩坑（第二轮）：

- **试过**：想用 `RandomPicker.update_item_weight(type, 0, false)` 把「首次允许波次」没到的僵尸权重归零。
- **因为**：`update_item_weight()` 里对 `<= 0` 的权重直接 `push_error`，不接受 0。
- **结论**：只能整项 `remove_item()` / `add_item()`，变了再 `rebuild_alias_table()`；
  顺带要跳过 `power <= 0` 的类型（建池时本来就被跳过，加回会凭空多出僵尸）。

- **试过**：想直接把窝瓜僵尸的 `ori_speed` 调大。
- **因为**：普通僵尸是**动画驱动位移**（`MoveComponent.E_MoveMode.Ground`），位移跟着动画 TimeScale 走。
- **结论**：必须走 `update_speed_factor()`（速度因子通道会同时写动画与移动），
  且要重写 `init_random_speed()` 而不是在 `ready_norm()` 里改 —— 父类是 `call_deferred("init_random_speed")`，
  帧末才写，改早了会被盖掉（`zombie_jackson.gd` 是同样的先例）。
