# 2026-10-24_僵尸实现与原版差异核查

> **本次任务**：把仓库里 25 只内置僵尸与原版《植物大战僵尸》C++ 参照实现逐条对一遍，找出当前仍存在的差异（只核对、不改代码）
> **耗时 / 轮次**：约 4 轮（3 个只读子代理并行 + 人工复核 + 补查 B 组）；**未开游戏**
> **推荐度**：推荐（"派子代理初筛 + 人工逐条复核"能把 25 只僵尸的核对压到一轮，但**子代理结论必须复核**）

## 目标

`docs/参考存档/植物僵尸逻辑对照.md` 已记录到第四轮校准（§4.4，2026-10-24），但那是"边改边记"，
**没有覆盖过的地方可能还留着偏差**。这次做一次独立复查：核心机制（啃食 / 血量阶段 / 移速 / 控制 / 死亡）
+ 25 只内置僵尸逐只对照原版 `Zombie.cpp`，产出可执行的差异清单。

## 最简路径（步骤）

1. **取基线**：先读 `植物僵尸逻辑对照.md`（含判等标准：原版 100 tick/秒，`tick ÷ 100 = 秒`）与
   `src/AGENTS.md`，把"已对齐项"和"有意保留差异"列成两张清单 —— 本轮**只报这两张清单之外的**。
2. **取原版**：`../PvZ-Portable-main/src/Lawn/Zombie.cpp` 为主参照（10 万行），
   `../re-plants-vs-zombies-main/Lawn/Zombie.cpp` 交叉验证。关键锚点：
   `ZombieInitialize()`（每类型 HP / 速度 / 阶段）、`PickRandomSpeed()`、`UpdateZombie<Type>()` 系列、
   `CanBeChilled()` / `CanBeFrozen()` / `EffectedByDamage()`（谁能被控 / 能被打）、
   `EatPlant()`（啃食与梯子）、`ZamboniDeath()` / `TakeDamage()`。
3. **派子代理初筛**：3 个 `code-explorer` 并行（核心机制 / 特殊僵尸 A 组 / 特殊僵尸 B 组），
   每个都要求"每条给原版 `文件:行号+数值` + 本仓库 `文件:行号+数值` + 等同/偏差 + 置信度"。
4. **人工复核**：**逐条**回原版与本仓库源码核对（这一步不能省，见「弯路」）。
5. **数值表用脚本抓**：`Select-String -Path "…\zombie\*.tscn" -Pattern "max_hp = |ori_speed = |armor_type = "`
   一次列出全部僵尸场景的血量 / 速度 / 防具，比逐个读文件快两个数量级。
   ⚠️ `search_content` 的 `glob` **不支持花括号**（`zombie_{a,b}.tscn` 匹配 0 条），要分次搜或用上面的 PowerShell。
6. **落文档**：差异写进 `植物僵尸逻辑对照.md` §4.5（P0 / P1 分级 + 「本轮证伪的怀疑项」+ 「已核实无偏差」抽样），
   并订正 §3 的血量表、给 §5.3「梯子」条目加复查注记（那条原先被归进"视觉等价"，本轮发现语义相反）。

## 弯路 / 踩坑（三段式）

- **试过**：让子代理直接给出"原版 vs 本作"的差异结论，再一次性写进文档。
- **因为**：子代理对**"原版为什么这么判"**的背景推断不可靠 —— 它报了一条"原版黄油对二类防具无效，
  本作 `is_immune_butter()` 是空壳"，看起来很有据（因为 `component_armor.gd:330` 确实恒返回 false）。
  但回原版一看，`ApplyButter()` 只判 `!mHasHead || !CanBeFrozen()`，而 `CanBeFrozen()` 判的是
  **阶段 / 类型**（跳跃中、飞行中、小丑爆炸前摇…），**跟防具类别毫无关系** ⇒
  铁门 / 报纸 / 梯子被黄油定身是**原版行为**，本作一致，那条"偏差"根本不成立。
- **结论**：子代理的每一条都要**回原版把判定条件读全**再落文档；凡是"看起来是漏实现"（空壳方法、
  恒 false 开关），先确认原版那条判据到底管什么 —— 原版**没有**这个豁免时，空壳往往才是对的。

- **试过**：把"本作某场景没写 `max_hp`"当成"作者忘了配"。
- **因为**：`zombie_base.tscn` 的 `max_hp = 270` 会被所有场景继承 —— 撑杆 / 海豚 / 蹦极三个场景都没覆写，
  于是三个都成了 270，而原版分别是 500 / 500 / 450。
- **结论**：查血量**先查"有没有覆写"再查"配的是多少"**；一张场景血量表一次性抓完，比逐只读 `.tscn` 可靠。

- **试过**：子代理并行时把 B 组（报纸 / 梯子 / 潜水 / 舞王 / 小丑 / 雪人）也塞进第三个代理。
- **因为**：那轮代理返回了空结果（`Too Many Requests` 限流），白等一轮。
- **结论**：子代理返回空 / 报错就**当场自己读**，别重试到限流；子代理适合"撒网"，关键结论仍要自己落到行号。

## 本轮结论（摘要，完整清单见 `植物僵尸逻辑对照.md` §4.5）

- **P0（玩家直接可见）6 条**：冰车被地刺扎从"爆胎残废滑行"变成"当场爆炸"；**梯子语义与原版相反**
  （原版梯子让僵尸爬上去继续吃，本作让植物免被普通僵尸吃）；撑杆 / 海豚 / 蹦极血量 270 vs 500/500/450；
  巨人投小鬼落点 150~410 px vs 原版 40~140 px；矿工**缺出土后晕眩阶段**；蹦极"靶子先落地、僵尸迟到 2 秒"。
- **P1（数值 / 细节）8 条**：巨人砸僵尸 1800（原版正式逻辑根本不砸）、小鬼飞行期可被冻、
  小鬼不继承寒意、雪人逃跑由"15~20 秒必跑"变成"20% 概率"、冰车不减速且不该有 HP 三阶段、
  水中死亡淡出 1.0s vs 0.1s、出水位移、死后血量仍流失。
- **证伪 3 条**（避免下轮重复查）：黄油对二类防具（原作就是有效）、小鬼 HP 500（误传，原作 270）、
  巨人投小鬼触发阈值（本作等价）。

## 推荐度与理由

推荐，但**只在"先证伪再报告"的前提下**。这次最有价值的产出不是那 14 条差异，而是那条**证伪**记录：
`is_immune_butter()` 恒 false 看着像漏实现，实际是原版口径 —— 如果不复核就"修"，会把原版行为改坏。
**给后来者的坑**：① 差异结论要带双方行号，能被复核；② 判定条件要读全（`CanBeFrozen` 管的不是防具）；
③ 原版有 `DO_FIX_BUGS` 分支的地方要注明"正式逻辑 vs 修复分支"（巨人砸僵尸 500/1000 就在修复分支里）；
④ 没开游戏，§4.5 #2 梯子那条只到代码级，建议补一次实机确认再定性。
