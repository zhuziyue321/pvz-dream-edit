## 步骤

1. **先摸清哪些块能安全搬**：全仓 grep 每个候选函数的调用点，确认「只有 1 个外部调用者 or 纯内部」才动（`be_mowered_run` 只有 `lawn_mower.gd:83`、`be_butter` 只有 `bullet_butter.gd:10`）。`character_death_disappear` / `character_death_not_disappear` 被十几个地方调用（含 4 个探针），**不动**。
2. **排除「不能拆」的**：`_fade_and_remove` / `in_water_death_start` 看着像死代码（.gd 里 grep 不到调用），实际是**动画 `.tres` 轨道里的方法调用**（`"method": &"_fade_and_remove"`）—— .gd 里搜不到不代表没人调，**任何准备删/改名的函数都要连 `animation/` 一起 grep**。
3. B5 新建 `src/entities/character/zombie/zombie_000_base/` 三个 static util（`zb_butter_util` / `zb_mower_run_util` / `zb_garlic_lane_util`），基类只留同名转发。
4. **顺手修硬约束**：基类原来重写了 `_ready()`（违反 [项目规范](../项目规范.md) §1-3），且与 `ready_norm()` 里重复了一遍「找头节点」。删掉 `_ready()`，把 `update_mini_zombie()` 和头节点查找并进 `ready_norm()` 一处。
5. B6 新建 `pcm_pot_util.gd`，罐子那 350 行整块搬走；管理器只留 `init_pot` / `cerate_pot` / `clear_all_pot` / `plant_cell_creat_pot` 四个转发 + 状态字段（`curr_pot_num` 有探针在读，必须留下）。
6. 每加一个新脚本跑一次 `--headless --import`，再跑探针。

## 关键决策与理由

- **用 static util 而不是组件节点 / 子管理器** —— 26 个僵尸场景要挂组件就得逐个改 `.tscn`；罐子逻辑也没有独立生命周期。而 GDScript 没有 partial class，`butter_splat` / `curr_pot_num` 这类状态搬不出去，**做成组件只能 `get_parent()` 回头改宿主**，正好踩硬约束 §1-2。static + 显式传 `self` / `pcm` 是「不动场景」这个前提下唯一干净的拆法，B4/B5/B6 现在统一用这一套。
- **状态留在宿主、只搬逻辑** —— 拆分的价值在于「这段逻辑现在有一个自己的文件、能单独读」，不在于把字段也搬走。硬搬字段会逼出 `get_parent()`。
- **把 `await` 换成绑在节点上的 `Tween`** —— 碾压表现原来用 `await get_tree().create_timer(0.1)` 逐个掉落，大蒜换行用 `await create_timer(0.5)`。`SceneTreeTimer` 挂在 SceneTree 上，**节点被 `queue_free` 后计时器照跑**，回调里再去动已释放的节点会报错。改成 `tween_callback` + `tween_interval` 后节点一释放整条 Tween 一起没，行为更安全，也顺带让 util 不必写成协程。
- **不改 `Fixd` 这个枚举拼写** —— 它是资源配置里的既有写法，改了要连带改 `ResourceLevelData`，与本次重构无关。

## 踩坑

1. **ripgrep 结果会被截断，漏掉调用点** —— 全仓 grep 罐子相关符号时输出被截掉 19 条，结果漏改了 `start_next_game_plant_cell_manager_update()` 里的一处 `init_plant_cell_row_on_zombie_row_type()`，直到 `--import` 报 `Function "init_plant_cell_row_on_zombie_row_type()" not found in base self` 才发现 → **正解**：看到「结果被截断」提示就换个更窄的 pattern 再查一遍；**删函数前先 grep 函数名本身**。
2. **GDScript 的 lambda 对外部局部变量是值捕获** —— 探针里写 `func(): lane_updated = true` 改不到外面的 bool，信号明明发了却断言失败 → **正解**：用字典当盒子（`var box := {"updated": false}`，lambda 里 `box.updated = true`），改对象属性能回传。
3. **`.gd` 里搜不到的函数不一定是死代码** —— 见步骤 2，动画 `.tres` 会通过方法轨道调用。
4. **删大块用 `replace_in_file` 容易因全角字符 / 换行匹配不上** → **正解**：按行号用 `[System.IO.File]::ReadAllLines` + 区间过滤重写，写完 grep 一下 `^#region` 与 `^#endregion` 条数是否相等（`plant_cell_manager` 这次是 5:5，平衡）。
5. **探针第一次跑会超时** —— 新场景脚本第一次要重新导入/编译，比后续几次慢很多，`run_autopilot.ps1` 的管道输出还带缓冲 → **正解**：直接调 Godot 把输出重定向到临时文件再读（`cmd.exe /c ... > out.txt 2>&1`），能即时看到进度，超时被杀也留得下日志。

## 给后来者的最简路径

1. 先 grep 候选函数的**所有**调用点（含 `animation/*.tres`），只有「1 个外部调用者 or 纯内部」的才搬；被十几个地方调用的别动。
2. 判断这段代码的**状态归谁**：改的全是宿主自己的字段 → 用 static util（`class_name XxxUtil` + 全 `static func`，显式传宿主进来），不要做组件节点。
3. 新建 `src/<所在目录>/<宿主名>/xx_util.gd`（僵尸）或和宿主同级的 `pcm_xxx_util.gd`（管理器），文件头写清「为什么单独放一个文件 / 约定 / 不要顺手改什么」。
4. 宿主里把原函数换成一行转发，字段名与签名一律不变（外部和探针都在用）。
5. `--headless --import` → 跑相关探针 → 没有覆盖到的块**自己写一个 `probe_*.gd`**（这次为黄油 / 大蒜换行 / 碾压新写了 `probe_zombie_death_fx`）。
