# 2026-10-05 · 其它 · 受击层从 7 层简化为 4 层，魅惑敌我改由归属阵营判断

> **任务类型**：其它
> **推荐度**：**推荐**（下次动受击层就照这条走）
> **耗时与成本**：约 2 轮对话，未开游戏（本机没有 Godot 可执行文件），已给出人工验证清单
> **验证方式**：免验证 + 已给出人工验证方法（改动触达玩法行为，开游戏才能证明）
> **补充自**：无

## 目标

把「受击层」从 7 个（layer 2/3/5/6/9/10/11）砍到 4 个，让层只回答「我是植物还是僵尸、是索敌框还是伤害框」，
把「魅惑」这个敌我维度从碰撞层搬到脚本里，由 `BulletCampConfig` 一处集中判断。

## 步骤

1. 先摸清每层到底谁在用，再决定砍哪些 —— 在 `src/` 里按位值搜（`1024` / `32` / `16` / `collision_mask = 34`），
   硬编码点只有 4 处，其余全在 `component_detect.gd` 的三张掩码表和 `BulletCampConfig` 的两个字典里。
2. 砍 `layer 6 / 11`（魅惑变体）：新增 `BulletCampConfig.get_owner_camp()`，`is_enemy()` 改用归属阵营。
3. 僵尸方 mask 把敌方层写全：`ZombieEnemy` 从 `2+32` 改 `2+4`（检测）、`256+1024` 改 `256+512`（真实），
   再由 `DetectComponent._judge_enemy_is_can_be_attack` 与子弹命中处的 `is_enemy` 把非魅惑同伴过滤掉。
4. 补「魅惑后周围不重判」的洞：`Character000Base.be_hypno()` 里 `EventBus.push_event("character_be_hypno")`，
   所有 `DetectComponent` 订阅后把 `need_judge` 置真。
5. 逐个补非子弹判定点的阵营过滤：`component_bomb_norm` / `component_magnet` / `plant_squash` / `lawn_mower` / `bullet_bowling`。
6. ~~顺手也砍掉 `layer 5`（攻击态前移框）~~ → **放弃原因**：见「关键决策」第 2 条。
7. 改 `project.godot` 的层名（6 / 11 加 `Deprecated_` 前缀）+ 更新 `docs/参考存档/子弹与碰撞.md`。

## 关键决策与理由

- **保留 `layer 5`（ZombieHurtBoxDetectionOnAttack）没砍** —— 因为查了 `zombie_base.gd` 的
  `E_BeAttackStatusZombie`，枚举里**没有「攻击中」这一位**，攻击态只能用框表达；而且
  `change_area_attack_appear()` 只改位置不改 `monitorable`，非攻击时该框与本体框**重叠**，
  所以砍掉它只有两种结果：普通植物提前 20px 开火，或窝瓜/大嘴花检测范围缩 20px，两者都是行为变化。
  最终受击层收敛为 **layer 2 / 3 / 5 / 9 / 10**。
- **`is_enemy` 用「归属阵营」而不是「类型阵营」** —— 魅惑僵尸类型上仍是 `Zombie000Base`，
  但敌我必须反转（归属植物方）。同一个 `get_owner_camp()` 同时服务攻击方和目标方：
  魅惑僵尸归属植物方 → 它是僵尸方的敌人、植物方的自己人；它自己索敌时也按植物方找僵尸，
  于是「啃普通僵尸、不啃植物」自动成立，不用另写分支。
- **保留检测层 / 真实层的二分** —— 索敌框（`HurtBoxDetection`，还承担屋顶斜坡判定）与伤害框形状不同，
  合并会改掉斜坡判定与投手瞄准点；杨桃 `is_dectection = false` 也会失效。

## 踩坑

1. **想砍 `layer 5` 差点改坏行为** → 原因：以为它是「只打正在啃的僵尸」的过滤器，实际是「攻击时把框前移 20px」的范围增量
   → **正解**：先读 `E_BeAttackStatusZombie` 与 `change_area_attack_appear()` 确认语义再动手，没把握的层别砍。
2. **魅惑后同伴不会啃它、豌豆不会松口** → 原因：Area2D 只在**进入**时触发一次 `area_entered`，
   原来靠「切层」让物理引擎重新派发 entered/exited，层不变就没有事件了
   → **正解**：`EventBus.push_event("character_be_hypno")` 广播，所有 `DetectComponent` 订阅后 `need_judge = true`。
3. **Godot 4 静态类型报错**：`character is Zombie000Base and character.is_hypno` 里 `character` 形参是 `Node`，
   直接取 `is_hypno` 会报属性不存在 → **正解**：先 `is` 判断，再赋给类型化局部变量 `var zombie: Zombie000Base = character`。
4. **炸弹 / 磁力菇 / 窝瓜 / 小推车会误伤魅惑僵尸** → 原因：这些判定点原来靠「mask 里没有 1024 / 32」天然过滤，
   层合并后魅惑僵尸落进它们的 mask 里，而它们只看 `can_attack()` 不看阵营
   → **正解**：逐个补 `BulletCampConfig.is_enemy(...)`；`is_enemy` 已经把魅惑考虑进去，不用各写一遍。
5. **保龄球会在魅惑僵尸经过时刷 `Log.error`** → 原因：`bullet_bowling.gd` 里「检测到的不是僵尸」是 error 级，
   现在同层会照常触发 → **正解**：改成先判 `is Character000Base` 再判 `is_enemy`，不满足就静默 `return`。

## 给后来者的最简路径

1. 只改 4 个常量/字典：`BulletCampConfig.C_CampEnemyMask` + `C_AllCampMaskBits`、
   `DetectComponent.C_LayTypeValueDetection` + `C_LayTypeValueReal`（僵尸方那一行都要把敌方层写全）。
2. 新增 `get_owner_camp()`，`is_enemy()` 换用它 —— 敌我逻辑只在这一处。
3. 搜 `get_overlapping_areas` 与 `_on_area_2d_attack_area_entered` 的所有实现，凡是只判 `can_attack()` 的，
   全部补一次 `is_enemy`。
4. 魅惑要广播重判，否则「已经重叠着的目标」不会重新算敌我。

## 补充 / 评价（同日追加：layer 5 也砍了，受击层最终 4 个）

主程随后指出「**僵尸攻击时不应该前移框**」，上一节「保留 layer 5」的结论被推翻，一并删掉：

- 删 `HurtBoxDetectionOnAttack` 整个节点：`zombie_base.tscn` 的定义，
  以及 `zamboni` / `gargantuar` / `bobsled` / `catapult` 四个继承场景里对它的形状覆盖
- 删 `component_hurt_box_zombie.gd` 的 `x_correct_on_attack` / `change_area_attack_appear`，
  以及 `zombie_base.gd` 里 `signal_change_is_attack` 到它的连接
- 删 `DetectComponent` 的 `is_detect_attack` / `C_AttackZombieDetection` 与三个植物场景里的 `is_detect_attack = true`
- `project.godot` layer 5 → `Deprecated_OnAttackDetection`

**为什么「砍不得」的判断是错的**：当时以为删掉会让普通植物提前 20px 开火。实际
`update_curr_collision_lay` 里 `is_detect_attack` 只做 `curr_collision_lay |= 16`，
而这些植物本来就检测 layer 3（值 4）—— layer 5 的真实作用是「僵尸啃食时**多给** 20px 提前量」，
根本不存在「只打正在啃的僵尸」这回事。砍掉只影响这三种植物对**啃食中**僵尸的触发范围少 20px。

**额外收获**：该框还登记在 `node2d_detect_in_slope`（屋顶斜坡 Y 补偿节点列表）里，
它前移会让斜坡判定的采样点跟着动 —— 删掉顺带消除了这个抖动源。

**教训**：判断一个层能不能砍，光查「谁的 mask 含它」不够，还要查它在哪些 `NodePath` 数组里被登记；
反过来，看到「某层被某种机制用到」也别急着保留，先确认那个机制本身该不该存在。
