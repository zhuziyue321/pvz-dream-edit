# 产脑光墓碑（DLC VSGravestone → 僵尸卡模组）

把 `..\PVZ_DLC` 的对战墓碑 **VSGravestone**（贴图 Stone / Stone1~5 + Tombstone_glow）接进僵尸卡模组：
玩家对战里 50 脑光、行为类似向日葵 —— 种下去周期性给僵尸方银行入账脑子。

## 做了什么

- **素材**：48 张贴图 + 反编译 reanim 拷进 `mods_builtin/zombie_card/reanim/VSGravestone/`；
  `PVZ_reanim2godot_animation_cpp.exe -om auto` 转出全量 37 段，**剪成**「根 + AnimLib + 90 部件」
  精简 tscn + 只留 `idle`（0 长度静帧）/ `rise`（出土 0.5 s）两段 .tres（7.3 MB → 12 KB）。
- **实体**：`vsgravestone/plant_vsgravestone.tscn` + `vsgravestone_plant.gd`（extends
  `PlantSunProducerBase`）+ `component_create_brains.gd`（继承本体产阳光组件，只覆写
  `_spawn_sun()` → `ZombieCardPvpWiring.add_brains(25)` + 脑子光效）。
- **接线**：对战选卡面板末尾追加墓碑候选（植物类卡）；`costs_brains()` 让它花脑子；
  `add_brains()` 是僵尸方第一笔收入口；`uninstall` 撤条件 / 摘卡 / 清注册表。
- **落位**：自定义种植条件 `condition_zombie_side_plant.gd`（落位资格看
  `can_common_zombie`，不看植物的「禁种」标记），走
  `CharacterRegistry.set_runtime_plant_condition()` 换上。

## 踩坑

1. **本体 `set_cards` 只认内置角色**（`ResourceCardReference.is_valid()`），模组卡发不进卡槽 ——
   本任务最终走选卡面板 `put_card_at`，没动本体；若以后要让模组卡走 `set_cards`，
   得换 `AllCards.has_template()` 判（与 `all_cards.gd` 自己的「认模板」口径一致）。
2. **我是僵尸关里全场格子带「禁种」标记**（红线关的 `IsNoPlantBowling`），植物类卡默认条件
   一格都放不下 —— 墓碑是僵尸方单位，条件资源换成跟僵尸同一套资格线。
3. **探针重复开模组 → 「卡牌身份重复注册」**：模组随存档默认开着（开局已 install），探针再开
   一遍就叠一份卡，卸载只摘得到后装那份 → 卡面/目录清不掉全是它连带的。
   解法 = 模组入口 `install()` 加**幂等保护**（已装着就跳过）+ 探针先关再开。
4. **0 长度静帧**：`anim_idle` 是 1 帧，播完 `current_animation` 不一定挂着名，
   断言「正在播 idle」不可靠 —— 探针改验部件姿态（Stone 停在 idle 第 0 帧位置）。
5. **贴图大小写**：转换器写进 .tres 的路径大小写按原常量来（`Chunk4.png`），
   与 DLC 解包文件名（`chunk4.png`）不一致 —— 导出 PCK 是大小写敏感的，入库前统一过一遍。

## 推荐度 / 最简路径

推荐度：高（「DLC 单位 → 模组」的完整链路样本：素材 → R2Ga 转换 → 剪裁 → 运行期植物 → 分池货币）。
最简路径：拷素材（贴图名对齐常量大小写）→ `-om auto` 转换 → 剪 tscn 留部件树 →
PlantRuntimeKit 注册（配 card_face_anim / fallback）→ 自定义种植条件 →
货币路由在接线里单独判这张卡 → 探针先关再开模组。

  `AnimLib` 覆写节点的 `parent` 路径也要跟着改（漏改 = 库没挂上、动画不动、部件全落回 (0,0)）。

  与植物阳光计数同一套换算（`标记全局位 + 相机位`）给出飞行终点，`sun_brain.pick()` 改飞这里；
  拿不到银行时退回植物计数器口径（总比原地消失强）。落位规则就此对齐：
  植物阳光飞植物计数器，脑光飞僵尸银行。

## 补充 / 评价（同日返工：卡面是灰色长方形）

开窗口一看，选卡面板末尾那张墓碑卡是一块**灰色长方形**，看不出墓碑。

- **根因（不是灰底本身，是裁剪模式）**：`clip_children = 1`（ONLY）裁的是「**直接子节点**」，
  而本株裁剪板的直接子节点是动画挂点 `VSGravestoneAnim`（自己一个像素都不画）→ 裁剪区域为空
  → **整棵动画连同板都不渲染**。场上 / 卡面只剩板的底：默认 `StyleBoxFlat`（0.6 灰底）那块
  90×110 的板（比墓碑大一圈）就成了卡上的**灰色长方形**。
- **四种配法的实测结果**（一次性探针：500×300 黑底格子 + 逐像素统计，rise 第 0 帧 = 石碑完全
  在地下，裁剪正常时格子里不该有石碑；idle 帧用来区分「裁住了」和「整棵被剔除」）：

  | 配法 | rise 帧 | idle 帧 | 结论 |
  | --- | --- | --- | --- |
  | `clip=1` + 灰底（原样） | 只剩灰板，石碑 0px | 石碑 0px | 整棵被裁没 |
  | `clip=2` + 灰底 | 石碑裁到地面线 1375px | 2209px | 裁剪对，但底露 8525px 灰 |
  | `clip=2` + `StyleBoxEmpty` | 2084px，露到格底（没裁） | 2209px | 完全不裁 |
  | `clip=2` + bg alpha 1/255 / 0.02 | 0px | 0px | 绘制被剔除 → 裁剪区空 → 整棵没 |
  | **`clip=2` + `StyleBoxFlat` + 全透明 shader** | **1375px，bbox 与灰底完全一致** | 2206px、无灰 | **裁剪对且板看不见** ✓ |

- **最终改法**：`clip_children = 2` + 普通 `StyleBoxFlat`（命令照常提交 → 裁剪区成立）+
  `mask_invisible.gdshader`（`fragment()` 里 `COLOR = vec4(0.0)`，光栅化阶段抹掉 → 看不见）。
  shader 不能省：低 alpha 会被引擎当透明命令剔除，剔除就等于没提交、没有裁剪区。
- **两次改错，别再走这两条**：
  · 模式仍 1、底换 `StyleBoxEmpty` → 墓碑整截从地下滑出来（反馈「裁剪不见了」）；
  · 底取 alpha 1/255（模式仍 1）→ 连墓碑都不见（反馈「墓碑不见了」）。
  两次都错在「用底色去解决裁剪问题」—— 底色管的是「露不露灰」，裁剪管的是「模式 2 + 有绘制」。
- **另一个不能这么干的写法**：把裁剪板 `visible = false` —— 父节点一藏，子节点跟着不画。
- **教训**：`clip_children` 的裁剪区跟着「节点**提交了什么绘制**」走：不提交 = 不裁，
  但 alpha 低到被剔除也等于没提交；要「有矩形、没像素」只能靠 material/shader 在光栅化阶段抹。
  套动画场景时中间会多一层挂点（本体墓碑的精灵是直接挂在板下的，所以 `= 1` 没事），这一层就是坑。
- **定位方法（值得复用，这次靠它一次收敛）**：
  · 探针节点挂 `CanvasLayer(layer=100)` 再截 `tree.root.get_texture()` —— 直接挂 `root` 会被
    主菜单盖住；`SubViewport` 里渲染不稳（同一配置前后两跑结论会翻），别用。
  · 每个变体垫一块**黑底**、按格子**逐像素统计**（数量 + 包围盒），别靠肉眼看小图。
  · 用**动画中间帧**当测试帧：idle 帧的内容本来就结束在地面线，裁没裁看起来一模一样
    （我上一轮就是拿 idle 帧「验证」通过，实际什么都没验证到）。
  · `Panel` 是 `Control` 不是 `Node2D`：探针里 `find_child(...) as Node2D` 恒为 null，
    会让「摘板参照」悄悄变成「没摘」—— 用 `CanvasItem` 接。
- **验证**：`check_scripts.ps1` PASS；场景原样探针（rise 第 0 帧）只画出 1473px 且齐刷刷截在
  地面线、板零像素。开窗口再确认两处：选卡面板末尾那张（墓碑本体、无灰块）+ 种下去看出土
  0.5 s（石碑从地面线以下升起，不该整块悬空滑上来）。
