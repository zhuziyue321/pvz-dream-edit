# 2026-10-03 · 关卡与地图 · 小推车改成「准备-安放-植物」之前从屏幕外逐个入场

> **任务类型**：关卡与地图
> **推荐度**：**推荐**
> **耗时与成本**：约 3 轮对话；没开窗口，用无头探针跑真实关卡流程取证（画面 / 手感仍需人工看一眼）
> **验证方式**：无头探针（真实流程：`probe_mower_protect` / `probe_critical_value` / `probe_zombie_death_fx` 全 PASS）+ 已给出人工验证方法
> **补充自**：[2026-10-03\_僵王关搬进关卡流程.md](2026-10-03_僵王关搬进关卡流程.md)（同一套「加一个时间轴事件」的路子）

## 目标

小推车不再在 `GameItemManager.init_manager()` 里一进关就生成并站在草坪最左边，而是：

1. 由关卡流程里的新事件 **初始化小推车**（`LevelTimelineEventLawnMover`）负责生成；
2. 推车**出生在屏幕外左侧**（看不见）；
3. 入场是**从下到上**依次发车（路上可以同时有几辆在开），**整个过程不阻塞流程**（见文末补记：初版是 await 的，被玩家吐槽要干等）。
4. 生成这一步排在「准备…安放…植物」红字**之前** —— 但事件自己发完车就返回。

## 步骤

1. 加事件脚本 `src/levels/core/timeline_event/level_timeline_event_lawn_mover.gd`（继承 `ResourceLevelTimelineEvent`，无参数，`is_lawn_mover` 为 false 时直接 return），
   在 `LevelPrefabs` 加一行门面方法 `init_lawn_mover()`（依据：[关卡时间轴.md](../参考存档/关卡时间轴.md)「加一种事件 = 新建一个脚本」）。
2. `GameItemManager.init_manager()` 里删掉 `gim_lawn_mover.init_lawn_movers()`：布车的时机交给流程，管理器只管「怎么布」。
3. `GIM_LawnMover` 加三个 `@export` 参数（`appear_offscreen_offset` / `appear_duration` / `appear_interval`）
   和两个方法：`init_or_replenish_lawn_movers()`（第一次布全场，多轮关卡第 2 轮起只补缺的）、`play_appear_animation()`（串行的入场）。
   `create_lawn_mover()` 加 `is_defer_appear` 形参：true = 出生在屏幕外、登记待入场；false = 照旧自己滑一小段。
4. **批量把这行插进 93 个关卡脚本**（`run_flow()` 里 `await prefab.ready_set_plant()` 前面一行）——
   LevelScriptBase 的默认实现也补一行，两个不走默认流程的关卡（1-1 教程、4-5 砸罐子）单独挑位置。
   用 python 按行精确改写（先扫一遍缩进异常的，再整体插，最后手工处理那 2 个特例）。
5. 跑真机取证 → 发现车压根没动 → 修 `_stand_position_x()`（见踩坑 1）。
6. 无头探针被牵出来的改动（见踩坑 2）：新增 `test/scenarios/probe_util.gd` 两个共用 helper，
   三个依赖推车的探针改用它；顺手把 `probe_critical_value` 行号写死的问题修了。

## 关键决策与理由

- **布车时机整体搬到流程里，而不是「照旧在 init 里生成 + 事件只播动画」** ——
  用户要的就是「事件串行的开始初始化小推车」；而且一旦保留 init 里的生成，多轮关卡第 2 轮重复跑流程会重复 `create_all_lawn_movers()`
  （旧的节点不会自动回收，会越堆越多）。现在用 `is_lawn_movers_inited` 兜住：第 2 轮起走补充那条路。
- **`add_child()` 之后再往左挪车** —— 屋顶清洁车在 `_ready()` 里按「站位」算了屋面斜面修正，
  得先让它按最终 x 算完 y，再挪出屏幕，否则 y 会算错。
- **目标 x 取自 `all_lawn_movers_global_pos[lane]` 而不是车当前的 x** —— 车当前就在屏幕外，取当前 x 等于原地不动（踩坑 1）。
- **1-1 教程关的事件排在 `camera_back()` 之后、`allow_operation()` 之前** —— 1-1 首次通关不走「准备安放植物」，
  那里是本关唯一能让车进场的位置；排在 camera_back 之后玩家才看得见。

## 踩坑

1. **现象**：流程跑完推车也没出现（视镜了都看不到）→ **原因**：先把车挪到屏幕外、再从 `lawn_mover.position.x` 取目标值，
   补间的起点和终点是同一个 x，车**原地不动**一直停在 x=-180 → **正解**：目标 x 从地图给的站位取
   （`GIM_LawnMover._stand_position_x()`），当地图站位查不到时才退回 `当前 x + appear_offscreen_offset`。
2. **现象**：给新事件 `class_name` 的头一次启动必然报 `Identifier "LevelTimelineEventLawnMover" not declared`，整份依赖链编译失败
   → **原因**：运行期的全局类表是上一次启动的快照 → **正解**：`godot --headless --path . --import` 重新生成 `.godot` 缓存与 `.uid`（不是代码写错，别去改脚本）。
3. **现象**：无头探针里推车永远取不到（`probe_mower_protect` FAIL）→ **原因**：这些探针在流程还在「展示僵尸 / 选卡」时就 `main_game_start()`，
   时间轴停在选卡那一步，躲在后面的事件一件都跑不到 → **正解**：`test/scenarios/probe_util.gd` 提供
   `click_start()`（等 `is_timeline_waiting_choose_card` 真的为真，再 `is_timeline_waiting_choose_card = false; await choose_card_finish()`，
   **不能**图省事直接 `main_game_start()`）+ `wait_lawn_mowers()`（等入场播完再断言）。
4. **现象**：`probe_critical_value` 一直报「行0/行1小推车不存在」→ **原因**：1-1 用的 `map_front_1row` 只有最中间一行有车，
   行号是写死的（与我这次改动无关，顺带修）→ **正解**：按 `_mower_lane()`（第一行真的有车的行号）建僵尸 / 取车，
   并把「触发」的正例挪到反例**之后**（正例一触发车就走了，反例就测不成了）。
5. **批量改 93 个关卡脚本**：`replace_in_file` 对「带缩进的多行片段」偶发匹配不上（爪不住 Tab），
   → **正解**：跨文件批量一律用 python 脚本按行精确改写（写完自证 found: 1），别拿 IDE 的替换硬戳。

## 给后来者的最简路径

1. 加事件脚本 + `LevelPrefabs` 门面（照本记录第 1 步）。
2. 新脚本落地后**先跑一次** `godot --headless --path . --import`（踩坑 2），否则下一次启动全线编译失败。
3. 管理器侧只改「怎么布」，`@export` 三个时间/距离参数，别把数字写死在流程脚本里。
4. 批量插行：`await prefab.init_lawn_mover()` 一行 + 一行注释，python 按行插，
   再单独处理**没有** `ready_set_plant()` 的关卡（4-5）和把它放在分支里的关卡（1-1）。
5. 验证：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_mower_protect`
   （会打印「小推车已就位（行N）」）；要看推车的 x 从 ≥-180 走到 20 且顺序是行号从大到小，用同一个通道起一个临时探针 dump 即可。

## 补记（2026-10-03 · 用户实测反馈后的两处调整）

1. **入场不该 await**：原实现让「初始化小推车」事件 `await gim.play_appear_animation()`，
   流程要等最后一辆到位才往下走 —— 站在玩家角度就是「点完开始还要干等」。
   → **正解**：事件只发车（`init_or_replenish_lawn_movers()` + `play_appear_animation()`），**不 await**；
   车在「准备…安放…植物」那几秒里自己开进来。**判断标准**：这是玩家感知不到的后台演出，不该进关卡流程的进度条。
2. **间隔太大**：原来是「前一辆**到位**才发下一辆」，N 辆车总时长 ≈ N×duration + (N-1)×interval（原参数 0.35 / 0.1 → 5 辆要 2.15s）。
   → **正解**：改成**发车间隔**（`appear_interval` 只错开发车时机，路上可以同时有几辆在开），参数也下调（duration 0.2 / interval 0.05），
   5 辆车总时长 ≈ (N-1)×interval + duration = 0.4s。**别把入场的等待写进时间**：这类排队的等待要么串行超时而拖流程，要么被 juniors 当成 await 点。

**二次取证**（1-2，无头）：点开始后 `-180 → 20` 三辆车在 0.3s 内全部到位，流程在 t=2.8s 进 MAIN_GAME（`probe_mower_protect` PASS）。

## 验证方式（人工，可选）

进 1-2（或任意冒险关）：选完卡点「开始游戏」→ 镜头归位后应看到**最下面那辆车**先从左边屏幕外开进来，
一行一行往上，全部到位后才出「准备…安放…植物」红字；开战之后僵尸走到车前仍应照常触发（车向右开出屏幕、压死这一行僵尸）。
