> **补充自**：[2026-10-14\_新增原版平衡模组框架.md](2026-10-14_新增原版平衡模组框架.md)（本条是它的第二版：把「阳光 / 冷却百分比」那套**清掉**，换成 10 条具体调整）

## 目标

做「原版平衡」模组：把原版已有的数值改成同人口径 —— 豌豆射手 75 阳光、格子新增光照等级
（向日葵每级 +5）、寒冰菇伤害 100、火炬树桩照十字四格、路灯花照周围八格、仙人掌子弹穿 3 个、
卷心菜索敌三行、咖啡豆 25、机枪 6 连发、吸金磁 125 阳光且能吸 3 个铁器。

## 步骤

1. 先判落位：改的是**原版数值** + 一条**原版没有的机制**（光照）→ 都不属于原版 → 全部做成模组，
   本体只补「通用口子」（照 [模组机制](../参考存档/模组机制.md) §6.6 的边界）。
2. 逐条摸清数值在哪、能不能运行期改（这一步最花时间，见下面「关键决策」）。
3. 本体加 7 个通用口子（**默认行为全部零变化**）：
   `PlantCell.light_level` / `PlantCellManager.get_plant_cell_cross()` /
   `CharacterRegistry.set_runtime_plant_stat` / `BulletRegistry.set_runtime_bullet_stat` /
   `DetectComponent.add_extra_ray_area()` / `AttackComponentBulletBase.burst_num`+`burst_extra_num` /
   `MagnetComponent.max_iron`。连发顺手上移，删掉僵尸版里重复的那一份。
4. 模组按「三层」重写：settings（数）→ patcher（数据层）/ wiring（实例层）→ 入口（装 / 卸 + 清单）。
5. 写无头探针 `probe_balance_mod.gd`（进 1-1 白天关、直接 `create_plant()` 造植物验），
   **装前装后各验一遍**（只验"改成了新值"等于没验）。
6. 门禁 PASS + 探针 PASS failed=0。

~~机枪连发直接设 `burst_num = 6`~~ → **放弃原因**：原版那 4 发是**写在射击动画里**的
（`gatling_pea_shooting.tres` 有 4 个 `_shoot_bullet` 方法轨道），动画是原版资源不能改，
设 6 会变成 4×6 = 24 发 ⇒ 改成「动画之外补差额」的 `burst_extra_num = 2`。

~~卷心菜靠改子弹属性关掉同行限制~~ → **放弃原因**：`is_activate_lane` 不是 `@export`，
`create_bullet()` 之后写会被随后 `init_bullet()` 用参数盖掉 ⇒ 改源头：把检测组件的 `is_lane` 关掉
（攻击组件从它取值，两个都关）。

## 关键决策与理由

- **本体只给「通用能力」，不认识模组**：光照等级是格子上的一个通用整数，口子的注释里不提平衡二字；
  默认 0 / 默认 1 / 空覆盖表 ⇒ 关掉模组 = 原版，这么做才守得住「原版有 → 本体，原版没有 → 模组」。
- **格子属性要跟着植物生灭**：接 `PlantCell.signal_plant_create` / `signal_plant_free`，
  每次**全场从零重算**（几十个格子，成本可忽略，且不会算错；增量维护要记「谁给谁加过」）。
- **吸金磁的吸铁能力照磁力菇那份复制**：`MagnetComponent` 本来就有，
  `instantiate()` 一份磁力菇场景取那个节点当模板 → `duplicate()` 挂到吸金磁下；
  两个坑必须处理：① `duplicate` 带过来的 `curr_iron_container` 仍指向模板里的容器，**要显式改指**
  到新本体 `Body` 下新建的 `CurrIronContainer`；② `@onready` 在 `add_child()` 入树时才求值，
  所以**先建容器、再挂组件**。
- **阳光走覆盖表而不是改 const 表**：Godot 4.4 起常量字典只读（第一版框架就撞在这上面）。
- **分子弹 / 植物两套覆盖表**：子弹是每颗新实例，`PackedScene` 里的默认值运行期改不了，
  只能在 `create_bullet()` 里造完之后照表写属性。

## 踩坑

1. **`const` 字典在 Godot 4.4+ 只读** → 就地改报 `Dictionary is in read-only state.` → 走覆盖表。
2. **机枪的连发写在动画里**（4 个 `_shoot_bullet` 轨道）→ 组件侧只能补差额，不能设总数。
3. **幂等守卫别用「子节点数」判断**：`DetectComponent` 下本来就有 Area2D + 掩码组件两个子节点，
   写 `get_child_count() > 1` 会让卷心菜那条**永远不执行** → 按 `all_ray_area.size()` 判。
4. **`user://` 下脚本没有类型推断**：`var x := 无类型的返回值`（从数组 / `get_node_or_null()` 取出的）
   会被判编译错误 → 一律显式写类型（`var cell: PlantCell in row`）。
5. **门禁报错会骗人**：残留的 `--headless` 进程占着临时输出文件时会打出
   `Function "_resolve_mod_roots()" not found in base self` 这种**与本改动无关的假错** →
   先用 `Get-CimInstance Win32_Process` 分清编辑器（`--editor`，别动）与残留无头进程，杀掉后者再跑。
6. **`is_activate_lane` 不是 `@export`** → 子弹属性覆盖对它无效，得改源头 `DetectComponent.is_lane`。

## 给后来者的最简路径

1. 定要改哪几类数值 → 判它们落在**数据层**（注册表 / 子弹表）还是**实例层**（植物组件 / 格子）；
2. 本体缺能力就加一个**默认零变化**的通用口子（注释里不提某个模组），不要给模组开后门；
3. 模组三层：settings 存「新值 + 原版值」→ patcher 改数据层（改完记得 `AllCards.rebuild()`）
   → wiring 改实例层（接格子的种植 / 移除信号，全场重算）；
4. 探针：进一个白天关 + `cell.create_plant()` 造植物，**装前装后各验一遍**。
