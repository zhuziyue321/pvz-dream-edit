# 2026-10-15 · 其它 · 伤害信息新增秒杀字段 `is_instant_kill`，替掉「真伤抬到血量上限」

> **任务类型**：其它
> **推荐度**：**推荐**（「要一个'必死'的效果」照这个走：加一等字段 → 结算层加一条清空分支 → 把老调用点逐个换过来）
> **耗时与成本**：约 1 轮，未开游戏
> **验证方式**：免验证 + 已给出人工验证方法（改动集中在伤害管线，语义等价替换；`check_scripts.ps1` PASS 0 error）
> **补充自**：无（机制说明见 [伤害系统 §3](../参考存档/伤害系统.md)）

## 目标

给 `DamageInfo` 加一个**秒杀**字段，让「必死」成为一个显式意图，而不是「把伤害值抬到 `get_all_hp()` 再走 `E_DamageMode.Real`」这个约定俗成的写法。判据：全仓不再有 `amount = get_all_hp()` 当秒杀用的地方。

## 步骤

1. **先摸清「秒杀」现在散在哪**：搜 `get_all_hp()` 的调用点 → 落到三只僵尸（`bobsled` / `zamboni` / `catapult` 的地刺便条翻译）、`Character000Base.be_attack_to_death()`、`HpComponent.hp_loss_to_death()` 三处。
2. **字段落在 `DamageInfo`**（`src/core/damage/damage_info.gd`）：`is_instant_kill: bool` + 链式 `with_instant_kill()` + 调试串加一项。
3. **结算层加分支**：`HpComponent` 新增 `clear_all_hp()`（植物 = 本体清零），`HpComponentZombie` 重写成「`armor_list` 逐层归零 + 本体清零」；两个 `hp_loss()` 在 `info.is_instant_kill` 时走它。
4. **放行 0 伤害**：`DamageSystem._apply_effect_damage()` 原来 `amount <= 0` 直接 return false，秒杀时伤害值不参与结算，要改成 `amount <= 0 and not is_instant_kill`。
5. **换老调用点**：三只僵尸改成 `info.is_instant_kill = true`；`be_attack_to_death()` / `hp_loss_to_death()` 也开秒杀（伤害值照填，只为 `DamageResult` 上的数字好看）。
6. **同步文档**：[伤害系统](../参考存档/伤害系统.md) §1 / §3（新增秒杀小节）/ §9 / §11 / §12 / §13；`ConstDamage.E_DamageMode` 注释里补一句「秒杀不是模式」。

## 关键决策与理由

- **做成一等字段，不做成新效果（`EFFECT_INSTANT_KILL`）** —— 秒杀不是"额外施加的一个东西"，它是**伤害效果的一种结算方式**（跟 `mode` 同级：不看伤害值，直接清空）。做成效果还得回答"它自己算不算一次结算"；做成字段，修饰器 / `process_damage()` 把它改回 `false` 就是天然的「免疫秒杀」写法。
- **清空的活放在血量组件，不放 `DamageSystem`** —— 防具只有 `HpComponentZombie` 认识（基类连 `armor_list` 都没有），系统里写"遍历防具归零"就等于系统认识了防具。加一个 `clear_all_hp()` 让子类重写，系统一行都不用动。
- **老写法为什么必须换**（写进字段注释与文档的三条）：① 仍要过防具的吸收规则，减伤 / 固定吸收的防具（模组里那几种矿石桶）会让它**打不死**；② `Real` 只跳过**二类**防具，语义不是"无视一切"；③ 伤害值在 ② 加工阶段读血，到 ③ 结算时血量可能已经变了。
- **秒杀仍然要带 `EFFECT_DAMAGE`** —— 系统靠它认领这次结算（`create()` 一定会带上），`amount` 写 0 也放行。不额外给"无伤害包"开口子，免得多一条静默失效的路径。

## 踩坑

1. **秒杀时 `amount` 可能是 0，会被 `_apply_effect_damage()` 的早退挡掉** → 症状是"开了秒杀却一点血不掉、还返回 `ZeroAmount`" → **正解**：早退条件加 `and not info.is_instant_kill`（第 4 步）。
2. **僵尸的 `clear_all_hp()` 要先 `begin_damage_settlement()`** → 否则上一次结算残留的 `is_hit_this_time` 会让没被打到的防具也补发掉血信号 / 音效 → **正解**：清空前统一 `begin_damage_settlement()`，再逐层 `curr_hp = 0` 并置 `is_hit_this_time = true`。
3. **本体已死的秒杀不该再算"本体挨打"** → 否则会对一个已 `queue_free` 的角色补发 `signal_hp_loss` → **正解**：`is_body_hit = curr_hp > 0` 要在**清空之前**取，与常规分支的口径一致。

## 给后来者的最简路径

1. `DamageInfo` 加字段 + `with_instant_kill()` + 调试串。
2. `DamageSystem._apply_effect_damage()` 早退条件加 `and not info.is_instant_kill`。
3. `HpComponent.clear_all_hp()`（本体清零）+ `HpComponentZombie` 重写（防具逐层清零）；两个 `hp_loss()` 加秒杀分支。
4. 全局搜 `get_all_hp()` / `max_hp` 找"抬伤害当秒杀"的老写法，逐个换成 `is_instant_kill = true`。
5. 同步 [伤害系统](../参考存档/伤害系统.md) + 跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`。

## 补充：扎爆车辆后地刺自损 → 改成「载具反伤」（同一任务的第二 / 三轮）

原版地刺扎爆车之后自己也没了，所以接着上一轮补「受损」这一半。

- **第二轮（已作废）**：车在 ③ 末端往同一个包里回塞 `EFFECT_VEHICLE_WRECKED`，地刺结算完读自己的包自行受损（`on_vehicle_destroyed()`：地刺直接死 / 钢地刺扣 50）。⊙ **被要求是「0 伤害的载具反伤」**，且**不要硬编码新量**，于是整条推翻重做。
- **第三轮（现行）**：车被地刺类扎到 → 反过来对 `info.attacker` 打一下**0 伤害** + 一张 `EFFECT_VEHICLE_BACKLASH` 便条，后果由**受击方**在 ② 加工阶段自己写进字典：地刺置 `is_instant_kill = true`（直接报废、不掉落），钢地刺把 `info.amount` 填成自己的受损值。⊙ 受损数值**落在 `effects[EFFECT_DAMAGE]` 里由受击方填**，车这边一个数字都没有，也不认识任何一种地刺（硬约束 §1-8）。
- **前提：发起方写包必须填 `info.attacker`** —— 车是靠它找反伤目标的，漏填整条链静默不发生（不报错，症状是"扎爆车地刺没反应"）。地刺 / 钢地刺的两条写包路（`_attack_once()` 与 `be_flattened_from_enemy()`）都补上了。
- **数值不写脚本常量**：钢地刺的受损值做成 `@export var vehicle_backlash_damage = 50`（与 `attack_value` 同层，归场景配）。
- **循环保护**：反伤是同步发生的，地刺可能当场就没了 → `_attack_once()` 每扎完一个判 `if is_death: break`。
- **只在 `_attack_once()` 那条路生效**：`be_flattened_from_enemy()` 另有压扁流程，不叠加（且车根本压不到地刺）。
- **第四轮（现行）：雪橇车小队退出地刺互动**。⊙ `Zombie014Bobsled` 原本也把 `EFFECT_CALTROP` 翻译成秒杀，是错的 —— 雪橇车小队与地刺**不该有特殊互动**，删掉它的 `process_damage()` 重写，回归"不认识 → 正常挨 20 点"。⊙ 于是怕地刺的只剩洗冰车 `zamboni` / 投石车 `catapult`（也是仅有的两个接受载具反伤的）。
- **顺带统一了称呼**：仓库注释里"冰车"既指 `zamboni` 又指 `bobsled`，混淆不清。现在一律写**洗冰车** = `zamboni`、**雪橇车小队** = `bobsled`，涉及地刺的注释全部Rewrite（`damage_system` / `const_damage` / `character_base` 的示例 / 两种地刺 / `component_attack_zombie_zamboni` / `伤害系统.md`）。
- ⊙ 坑：`DamageInfo.attacker` 声明成 `Node`，直接 `info.attacker.apply_damage(...)` 静态检查过不去 → 先 `as Character000Base` 再判空。

## 人工验证方法（未开游戏，改动后建议照这几条过一遍）

1. 冒险任意关放地刺，让**冰车 / 洗冰车 / 投石车**压过去 → 当场散架 / 报废，走正常死亡（冰车亡语掉出四只小雪橇僵尸）。
2. 同一关让**巨人**踩地刺 → 一点血都不掉（免疫那条路没被本次改动碰到）。
3. 大保龄球（`bullet_bowling_big`）撞任意僵尸（含戴铁桶的）→ 直接打死；锤子模组开「一键秒杀」→ 范围内僵尸全死。
4. 铲子铲植物 / 海草拖僵尸 → 照常消失，没有残留血条或"死了还在跑"的尸体。
5. 种一片地刺，放**洗冰车 / 投石车**过来 → 车当场报废爆炸，同时**那棵地刺消失**（原版行为）。
6. 换成**钢地刺** → 车同样报废，钢地刺**掉 50 血**（血条往下走一截，不消失）；连续扎爆多辆 → 每次都掉 50。
7. 放**雪橇车小队**踩过地刺 → 只是正常挨伤害（每 0.75 秒 20 点），**不会**被秒杀、地刺也不会自损。
