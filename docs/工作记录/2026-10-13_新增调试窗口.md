# 2026-10-13 · 新增内容 · 加一个 Ctrl+Q 呼出 / 隐藏的半透明调试窗口

> **任务类型**：新增内容
> **推荐度**：**推荐**（下次「要一个调试面板」照这个走）
> **耗时与成本**：约 1 轮对话 / 未开游戏 / 无需人工介入（给了人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（画面类改动，门禁只证明能编译）
> **补充自**：无（这条是第一次做，但它自己属于 [控制台](../参考存档/控制台.md) 那条路线的延伸）

## 目标

1. 开启「调试模式」后，Ctrl+Q 能呼出 / 隐藏一个调试窗口；
2. 窗口 UI 半透明，不要求符合画风；
3. 里面要有一些可用的调试功能；
4. 调试模式关着时按 Ctrl+Q 不该弹出来。

## 步骤

1. **先查清「调试模式」到底是什么** —— 它不是引擎的 debug build，
   而是控制台里的一条条目：`ConsoleBuiltinEntries.DEBUG_MODE_KEY`（`"debug_mode"`），
   值落在 `ConfigService.console_values`，运行期镜像在 `GlobalGameState.is_debug_mode`。
   判定统一收成一句 `Global.config_service.get_console_value(...)`。
2. **定热键落点** —— 项目没有全局输入管理器，散着用 `_unhandled_key_input`。
   现成先例是 `global.gd` 的 Ctrl+D 与 `main_game_manager.gd` 的 Ctrl+K。
   这里**没有照抄到 `Global`**，理由见「关键决策」。
3. **加输入映射** —— `project.godot` 的 `[input]` 段照 `ShortcutKeys_KillAllZombie` 的块格式
   加 `ShortcutKeys_DebugWindow`（`ctrl_pressed":true` + `physical_keycode":81`）。
   ⚠️ 注意 `ShortcutKeys_WinLevel` 那条实际写的是 `ctrl_pressed":false`（疑似存量 bug），别照它抄。
4. **写窗口** `src/ui/debug/debug_window.gd`（造界面 / 分页 / 认热键 / 定时刷新）。
5. **写条目** `src/ui/debug/debug_window_entries.gd`（一条一行，动作另放一个 region）。
6. **接线** `Global._ready()` 末尾 `_spawn_debug_window()`。
7. 跑编译门禁（`real compile errors = 0`）+ 补文档与索引。

## 关键决策与理由

- **条目形态复用控制台的 `ConsoleEntry` + `ConsoleEntryControl`，但不进 `ConsoleRegistry`** ——
  控制台是「开关面板」、调试窗口是「动作 + 状态面板」，两者内容不同源；
  渲染器共用一份即可，注册表各走各的，控制台面板不会多出这些按钮。
- **热键挂在 `DebugWindow` 自己身上，不是 `Global`** —— `Global` 继承到
  `PROCESS_MODE_PAUSABLE`，菜单一开树就暂停，那时它收不到 `_unhandled_key_input`；
  调试窗口恰要在暂停时呼出来看状态，所以给它 `process_mode = PROCESS_MODE_ALWAYS` 自己收键。
- **根 CanvasLayer 常显、只切内部 Panel 的 visible** —— 不可见节点收不到按键，
  整层藏起来就再也按不出来了。
- **不加 `.tscn`** —— 窗口常驻在 autoload 下、内容全运行时造，`DebugWindow.new()` 就够，
  省掉一份只有一个根节点的场景 + `.uid`；也避免碰 `assets/`（不入 git）里的字体贴图。
- **调试窗口不暂停游戏** —— 调试时暂停反而没法观察；靠 `PROCESS_MODE_ALWAYS` 保证自己还能交互。

## 踩坑

1. **想当然把热键挂 `Global`** → `Global` 在暂停时收不到按键，窗口按不出来 →
   **正解**：`process_mode = PROCESS_MODE_ALWAYS` 的节点才收得到，挂在窗口自己身上。
2. **`ConsoleEntryControl._create_button()` 不读 `entry.is_enabled()`**，
   所以给 Button 设 `set_enabled_getter()` 不会置灰 →
   **正解**：按钮的可用性判在动作里（打一条 `Log.warn` 就够），别指望置灰。
3. **`Timer` 会被 `Engine.time_scale` 影响**，倍速拉到 0 冻结游戏时状态行就不刷了 →
   **正解**：`timer.ignore_time_scale = true`（仓库里 `scary_pot.gd` 有先例）。
4. **窗口会挡住点击，也会吃点击** → 给根 Panel `mouse_filter = MOUSE_FILTER_STOP`，
   免得点窗口的时候顺便在游戏里种了棵植物。

## 给后来者的最简路径

1. 条目加一行：`src/ui/debug/debug_window_entries.gd` 的 `_register_*_entries()` 里 `_add(...)`；
2. 动作加一个：同文件 `#region 动作` 里写一个 `static func`；
3. 新分组：`CATEGORY_*` 常量 + `get_categories()` 插一项 + 一个 `_register_*_entries()`；
4. 交付前跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`。

> 机制说明见 [调试窗口.md](../参考存档/调试窗口.md)。

## 补充 / 评价（2026-10-13 修编译错误时追加，不改正文）

- **`var x := Global.xxx.yyy()` 推导不出类型** —— 本条记录交付后，Godot 报
  `Cannot infer the type of "num" variable because the value doesn't have a set type.`
  （`debug_window_entries.gd` 151 / 156 / 188 三处，全都是 `:= Global.<成员>.<成员或方法>()`）。
  同一个 `Global` 用在**不需要推导**的地方（`Global.save_service.save_now()`、
  `Global.global_game_state.coin_value += value`）完全没问题，
  说明**只是「跨 autoload 做类型推导」这条路不通**（`Global` 是 `.tscn` 型 autoload、脚本也没有 `class_name`）。
  **正解**：显式写类型 `var num: int = ...` / `var name: String = ...`。
  全仓库此前没有第二处 `:= Global.*`，所以这是第一次踩到。
- **编译门禁会假绿** —— `test/check_scripts.ps1` 里写死的 Godot 路径
  `C:\Users\a a\Desktop\Godot_v4.6.2-stable_win64.exe` 在本机已不存在（实际是 `C:\Users\a a\Desktop\godot.exe`），
  Godot 根本没启动，stderr 只有两行 cmd 的「找不到命令」，不匹配任何 `$RealPattern`，于是照样输出 **PASS**。
  已修：默认路径改真 + 加了「exe 不存在直接 FAIL」的守卫。
  顺带一个坑：该 `.ps1` 是**无 BOM 的 UTF-8**，Windows PowerShell 5.1 会按 ANSI(GBK) 解码，
  新加的中文注释可能把紧随其后的 `'` 吞成 GBK 后字节，导致脚本整份解析失败（报「数组索引表达式丢失」那种莫名错误）。
  已给它加上 UTF-8 BOM。**在这份 ps1 里加中文注释时要留意这一点。**
