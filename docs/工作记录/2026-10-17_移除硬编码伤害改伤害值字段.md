# 2026-10-17_移除硬编码伤害改伤害值字段

> **本次任务**：把 `src/` 里散落硬编码的伤害数值全部改为「导出字段 / 命名常量」配置
> **耗时 / 轮次**：约 2 轮（未开游戏，编译门禁 PASS）
> **推荐度**：推荐

## 目标

`src/` 内所有发起方伤害数值不再写字面量：原版固定口径提成 `ConstDamage` 常量，角色 / 组件专属数值提成 `@export` 字段（场景可配），保持改动前后数值完全一致。

## 最简路径（步骤）

1. 全仓枚举：正则搜 `be_attacked_bullet(\d|be_bomb(\d|be_squash(\d|DamageInfo.create(...,\d|be_ice_freeze(...\d|be_attack_once(\d|hp_loss(\d`（glob `*.gd`），`src/` 命中 14 处、`test/` 与注释若干。
2. 原版固定口径 → `src/core/consts/const_damage.gd` 加常量：`JALAPENO_DAMAGE := 1800`（辣椒两处共用）、`SQUASH_DAMAGE := 1800`（倭瓜）、`ICE_FREEZE_DAMAGE := 20`（寒冰菇，`be_ice_freeze` 一族 4 处签名默认值 + `ice_all_zombie` 默认参）。
3. 角色 / 组件专属 → `@export` 字段（照 `zombie_squash.gd` 的 `squash_attack_value` 先例）：
   `Zombie038MagnetShroom.magnet_attack_value`(9999)、`Zombie014Bobsled.off_ice_road_damage`(100)、
   `AttackComponentZombieGargantuar.attack_value`(1800)、`BrainOnZombieMode.attack_value`(25)、
   `Plant047SpikeRock.flatten_self_damage_ratio`(1/9)；`Plant043GloomShroom` 直接用角色基类 `attack_value`，场景 `plant_gloom_shroom.tscn` 补 `attack_value = 20`。
4. 大脑 `be_attack_once()` / `_hp_loss()` 去掉数值参数改读字段；调用方 `component_attack_zombie_norm.gd` 同步改为无参调用。
5. 文档：`docs/参考存档/伤害系统.md` §7 补「伤害数值配置一览」总表（含每项配置处与「探针数字是测试夹具」的说明）。
6. 跑 `test/check_scripts.ps1` 确认 `real compile errors = 0`。

## 弯路 / 踩坑（三段式）

- **试过**：给 `Zombie038MagnetShroom` 直接写 `@export var attack_value`。
- **因为**：角色基类上一轮刚加了同名成员 `attack_value`，GDScript 不允许子类成员变量遮蔽基类，会直接 Parse Error。
- **结论**：专属机制用专属字段名（`magnet_attack_value`）；只有「发射类攻击」才复用角色基类的 `attack_value`（如 `plant_gloom_shroom`，配在 `.tscn` 里）。
- **试过**：把「0 伤害包」（洗冰车 / 投石车载具反伤）和 `DamageSystem` 里显式传 0 的 `be_ice_freeze(..., 0)` 也一并清理。
- **因为**：前者是「便条 + 受击方自填后果」的有意设计（见伤害系统.md §3），后者是防冰冻与包内伤害双算的显式口径。
- **结论**：保留，并在文档总表末尾注明「这两类 0 是有意为之，不是漏改」。

## 推荐度与理由

推荐。枚举靠一条正则就能扫全，改动机械且数值零变化；常量集中在 `ConstDamage`（与 `BOWLING_*` / `HAMMER_*` 同源），专属数值走 `@export` 默认值 + 场景配置，与仓库「数值归场景配」一致。注意 `test/scenarios/` 探针里的数字是测试夹具，**不要**顺手改成字段——那会破坏回归断言。
