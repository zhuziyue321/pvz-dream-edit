# 2026-10-02 · 关卡与地图 · 冒险 4-6 掉礼盒解锁解谜模式

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 6 轮对话，开了游戏 5 次（含 3 次回归），无需人工介入
> **验证方式**：打开游戏实测（`probe_puzzle_unlock` + 3 个既有探针回归）
> **补充自**：无

## 目标

照 3-2「掉礼盒解锁迷你游戏」的写法，让冒险 **4-6** 中途掉落礼盒解锁**解谜模式**，
玩家点开后能看到解锁提示。

## 步骤

1. 先确认「解谜模式」已经存在：`ConstUnlockLevel.PUZZLE_UNLOCK_ADVENTURE_LEVEL = 36`、
   主菜单按钮置灰、选关界面名额、30 个 `mode_puzzle/` 关卡资源**全都就绪** —— 缺的只有掉落表现。  
   → 结论：**只改关卡 `.tres`，一行 `.gd` 都不用动**（[选关界面与解锁.md](../参考存档/选关界面与解锁.md#关卡掉落解锁道具原版的戴夫掉落礼物盒车钥匙表现) 里也写了「加同样的表现只要补这几行」）。
2. 在 `adventure_04_06.tres` 补两行：`drop_unlock_wave = 5` + `drop_unlock_tip`。
3. 写探针 `test/scenarios/probe_puzzle_unlock.gd`，带窗口跑出 `[PUZZLEUNLOCK] result=PASS`。
4. 跑 `probe_adventure_reward` / `probe_car_key` / `probe_shop_expand` 三个既有探针做回归。
5. 同步文档：配置表加一行、夹紧机制补一段说明、探针清单加一行。

## 关键决策与理由

- **用「中途第 5 波」而不是「通关掉落」** —— 4-6 首次通关的奖励是杨桃（`ConstPlantUnlock` 36 号），
  `create_adventure_reward_drop()` 会优先用关卡资源的 `drop_unlock_on_level_complete`，
  配成通关掉落就把那包种子顶掉了。3-2（三线射手）当初也是这个处境，所以选了同一条路。
- **波次取 5** —— 本关 `max_wave = 10`，波索引有效范围 0..9，取中段；超出范围就永远不触发（`curr_wave` 只到 `max_wave - 1`）。
- **顺手修了 `get_clamp_drop_position()`**（见踩坑 1）—— 不修的话礼盒有概率掉到画面外点不到，功能等于没做完。

## 踩坑

1. **礼盒掉在画面外，点不到** →
   `get_clamp_drop_position()` 把掉落点夹到 `[0, 视口宽]`，但那是**世界坐标**，
   而主游戏画布原点约 `(150, 0)`，屏幕左上角不对应世界原点，
   右边 150 像素范围内掉出来的礼盒全跑到屏幕外，玩家只能眼看它 15 秒后消失。
   → **正解**：`get_viewport_visible_rect()` 先用 `get_canvas_transform().affine_inverse()` 把视口矩形换算回世界坐标再夹，
   并向内留半个礼盒（`DROP_EDGE_MARGIN`）；无偏移时逆变换是单位阵，结果与原来一致，花园场景不受影响。
2. **探针点礼盒总点空** → 用了 `Present.global_position` 当屏幕坐标，关卡里有 Camera2D，两者不是一回事。
   → **正解**：点之前现算 `AutopilotProbe.screen_center_of(dropped.texture_button)`（`[AI调试通道.md](../AI调试通道.md)` 第六节）。
3. **探针开场阶段清场不生效、僵尸走到家关卡直接失败** →
   过早调用 `main_game_start()`，时间轴后面的「准备安放植物 / 开战」事件会在已经开战之后补跑一遍，
   把关卡塞回 `PREPARE`，`shortcut_kill_all_zombie()` 有阶段门禁因此什么都不做。
   → **正解**：只在 `MainGameManager.is_timeline_waiting_choose_card` 为真时按一次「开始」；
   清场循环里直接调 `zombie_manager.death_all_zombie()`（与 Ctrl+K 同一入口），别合成按键事件。
4. **多个 Godot 实例同时在跑，报错是假的** —— 上一轮跑批没退出就开新一轮，
   两个进程互相写坏 `.godot` 缓存，报出 `Could not find type "GIM_Rake"`、`shader_gles3 f.is_null()`，
   甚至还能读到**上一次探针**的输出，很容易误判成自己改坏了代码。
   → **正解**：每次跑批前先 `Get-Process Godot* | Stop-Process -Force`，一次只跑一个。

## 给后来者的最简路径

1. 在该关 `.tres` 的 `[resource]` 段补 `drop_unlock_wave`（波索引要在 `0 .. max_wave-1` 内）+ `drop_unlock_tip`；
   本关有首次通关奖励的**必须**用这条，别用 `drop_unlock_on_level_complete`。
2. `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_puzzle_unlock -Windowed`，
   改这里前先把 `LEVEL_04_06` / `EXPECT_WAVE` / `EXPECT_TIP` 换成目标关卡。
3. 涉及掉落 touch 时顺手回归 `probe_adventure_reward` / `probe_car_key` / `probe_shop_expand`。
4. 跑批前先杀干净残留的 Godot 进程。
