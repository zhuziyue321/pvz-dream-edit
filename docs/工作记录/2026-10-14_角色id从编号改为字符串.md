# 2026-10-14 · 其它 · 角色（植物 / 僵尸 / 僵王）id 从 int 编号改成 StringName（子弹试点之后铺开）

> **任务类型**：其它
> **推荐度**：**推荐**（「一张大枚举换成 id 字符串」照这个走：先定存档口径 → 建 id 表（带老编号映射）→ 脚本批量改代码 → 脚本批量改资源 → 改代码里的数字键字典 → 无头跑探针）
> **耗时与成本**：约 4 轮对话，未开窗口（门禁 PASS 0 error + 8 个自动回归 probe + 无头启动零脚本错误）
> **验证方式**：免验证（玩法零变化），已给出人工验证方法（见文末）
> **补充自**：[2026-10-13_子弹id从编号改为字符串.md](2026-10-13_子弹id从编号改为字符串.md)（同系列的第一次试点）

## 目标

把 `CharacterRegistry.PlantType` / `ZombieType` / `ZombieBossType` 三套 int 编号枚举
（`P001PeaShooterSingle = 1` … `Z001Norm = 1` … `ZB001Doctor`）换成 **StringName 语义 id**
（`PlantIds.PEA_SHOOTER_SINGLE` / `ZombieIds.NORM` / `ZombieBossIds.DOCTOR`），
卡牌的 `content_id` 与卡牌模板键一起去掉数字。

判定标准：
- `.gd` 里搜不到 `CharacterRegistry.PlantType` / `ZombieType` / `ZombieBossType` 的**代码**引用（只剩注释里的迁移说明）；
- `.tscn` / `.tres` 里搜不到 `plant_type = \d+` / `zombie_type = \d+` / `content_id = \d+`；
- 关卡脚本里搜不到以数字为键的「出怪表 / 砸罐子随机表 / 传送带权重表」；
- 编译门禁 `real compile errors = 0`；
- 无头启动主场景**零脚本错误**；自动回归探针与迁移前**同 PASS / 同 FAIL**。

## 步骤

1. **开工前先定两处口径**（这两条不定就动手会返工）：
   - **老存档怎么办** → 用户选「**加一次性迁移**」：读档时遇到 int 就按映射表转 id 再写回
     （`PlantIds.from_legacy()` / `ZombieIds.from_legacy()` / `ZombieBossIds.from_legacy()`），
     玩家解锁进度、上次选卡、存档文件名都不丢。**这正是与子弹那次的差别**：子弹 id 不进存档，
     可以硬切换；角色 id 会写在玩家磁盘上，不能作废。
   - **卡牌 `content_id` 怎么办** → 用户选「**也改成字符串 id**」：卡牌资源存 id 字符串，
     模板键从 `Vector2i(类别, 编号)` 改成 `&"plant:pea_shooter"` 这种人能读的字符串键。
2. **建三张 id 表**（`src/core/consts/plant_ids.gd` / `zombie_ids.gd` / `zombie_boss_ids.gd`）：
   `const X := &"snake_case"` + `ALL` 列表 + `is_valid()` + **`LEGACY_INT_TO_ID` 老编号映射表**。
   `character_registry.gd` 里删三个 enum，留下「为什么删 + 写法怎么换」的说明注释。
3. **脚本批量改 `.gd`**（两条 PowerShell，带 unmapped 兜底）：成员引用 525 处（105 文件）+
   僵尸 / 僵王 828 处；再手工清 enum 定义、热注册段、解锁表与存档那十几处。
4. **脚本批量改资源**：`test/tmp_migrate_res.ps1` 改 101 个 `.tscn` / `.tres`、338 处
   （`plant_type = 1` → `plant_type = &"pea_shooter_single"`；`content_id` 按上一行的 `card_type`
   选映射表；`all_cards.tscn` 的三个字典块连 `Dictionary[int, int](` 头一起换）。
5. **脚本批量改代码里的数字键字典**（第二波，39 文件 310 处）：关卡脚本里的
   `random_pot_plant.assign({1: 9})`、`conveyor_weights = create_plant_weights({4: 2, 5: 1})`、
   `create_plant_order({0: 1001})`（**`_order` 那类表的键是槽位序号、值才是 id**，别改反了）。
6. **修运行期错误**（编译门禁查不出来的那部分，见「踩坑」1、2）：`StringName(x)` 构造、
   三元分支推断成 Variant。
7. **验证**：门禁（单独跑）+ 8 个自动回归 probe + 无头启动；再用 `git worktree` 建迁移前的
   干净副本，把 3 个 FAIL 的 probe 跑一遍**确认是迁移前就失败**的既有问题。
8. **同步文档**：`僵尸热注册.md`（编号段 → id 前缀）、`Agent协作协议.md`（植物 / 僵尸编号段配额作废）、
   本记录 + 索引补行 + 在子弹那条第 7 步里提到的文档链路。

## 关键决策与理由

- **老存档加迁移层，不硬切换** —— 与子弹那次唯一的实质差别，理由见上面第 1 条；
  映射表只在 `from_legacy()` 里用，业务代码一律 `PlantIds.XXX`，不反向查它。
- **热注册的 9001–9999 编号段作废** → 改成 `runtime_zombie_` 前缀 + 自增序号：
  字符串 id 没有「段用完」这回事，模组想注册几只就注册几只。
- **卡牌模板键用「人能读」的字符串** —— `&"plant:pea_shooter"` 打日志时一眼看得出是哪张卡，
  比原来的 `Vector2i(1, 1)` 强得多；顺带把「类别 + 编号两个 int」这个耦合也拆了。
- **`all_cards.tscn` 里 `@export` 的 `Dictionary[int, int]` 必须连头一起改** ——
  只换键不换头，Godot 会在加载时报 *Cannot assign contents of "Dictionary[int, int]" to
  "Dictionary[StringName, int]"*，节点直接降级成 `Control`（表现为后面一串莫名的属性访问失败）。

## 踩坑

1. **`StringName(x)` 不是构造函数**（本次最大的坑，编译期查不出来）：
   Godot 4 里 `StringName` 没有可调用的构造，运行期报 *Invalid call. Nonexistent 'StringName'
   constructor*，只在真正执行到那一行时才炸。→ **正解**：交一个 `String` 回去，靠返回类型 /
   变量类型 / 容器元素类型隐式转换（`return str(value)`、`arr.append(str(x))`、
   `func f() -> StringName: return "前缀" + str(x)`）。本次改掉 12 处，包括三张 id 表的
   `from_legacy()`、卡牌引用的 `create()` / `get_template_key()`、注册表热注册 id 的拼装。
2. **三元分支两边类型不一致 → 推断成 Variant，被门禁判错**（*The variable type is being
   inferred from a Variant value … Warning treated as error*）：
   `var t := zb_type[i] if i < zb_type.size() else ZombieBossIds.NULL`（`String` vs `StringName`）。
   → **正解**：显式标注 `var t: StringName = …`。
3. **PowerShell 5.1 的 `[regex]::Replace` + scriptblock 没把所有匹配都换掉** ——
   单行多键字典 `{4: 2, 5: 1, 8: 2}` 只换了第一个键，而且**没有任何报错**。
   → **正解**：`[regex]::Matches` 收集后**从后往前**逐条 `Substring` 替换（索引不失效）。
   这个 bug 很隐蔽：第一遍跑完看着 changed 数很大就以为完事了，是抽查文件时发现的。
4. **批量脚本的「当前是植物还是僵尸」状态会跨行残留、误伤无关文件** ——
   探测脚本里「关卡序号 → 植物」的表（`probe_night.gd` 的 `1: 10,`）会被当成植物编号改坏。
   → **正解**：**先限定扫描目录**（只在 `src/levels` + `data/levels` 跑），
   目录外的 int 键逐个人工确认（里程碑高度、连击长度、舞王伴舞槽位号都不是 id）。
5. **`user://mods/` 里的模组副本不会跟着仓库脚本改** —— 门禁会报
   *Failed to load script "user://mods/netplay/netplay_mod.gd"*，很容易误判成「仓库代码坏了」。
   → **正解**：改完 `mods_builtin/` 后 robocopy 同步一遍再跑门禁：
   `robocopy <src> <dst> /E /XO`（`/XO` 只覆盖较新的，不动用户自己的配置）。
6. **怎么判断某个 probe FAIL 是本次引入的回归还是早就坏了** ——
   → **正解**：`git worktree add <临时目录> HEAD` 建一个**迁移前的干净副本**（不碰当前工作区，
   比 `git stash` 安全），先 `--import` 再用同一套 `run_all_scenarios.ps1` 跑同一个 probe 对比。
   本次 `probe_plant` / `probe_column_mode` / `probe_night` 三个 FAIL 就是这样确认的：
   **失败条目逐条一致**（连 `probe_night` 报的出怪表内容都从 `[1, 3, 4, 5]` 变成了
   `[&"norm", &"cone", &"pole_vaulter", &"bucket"]` —— 数据是对的，是断言本身过期）。
   对比完 `git worktree remove --force <临时目录>`。
7. **`run_all_scenarios.ps1` 的默认引擎路径在本机不存在**（`Godot_v4.6.2-stable_win64.exe`），
   不传 `-Godot` 时每个 probe 0.3 秒就 "ERROR no-result-line"，看着像全崩了。
   → **正解**：显式传 `-Godot "C:\Users\a a\Desktop\godot.exe"`。
8. **`all_cards.tscn` 的 `Card` 节点在 `--import` 期会报**
   *Invalid access to property or key 'card_type' on a base object of type 'Control (Card)'* ——
   `@tool` 脚本在导入期跑 `_ready()` 时子节点的脚本类还没注册完。**无头真实启动不报**，
   属于导入期噪声，不用管。

## 给后来者的最简路径

1. 先问清两件事：**这个 id 会不会写进存档**（会 → 加 `from_legacy()` 迁移）、
   **有没有别的地方 depent 在「它是 int」上**（卡牌 `content_id`、模板键、网络快照）。
2. 建 `src/core/consts/<域>_ids.gd`：`class_name <域>Ids` + `const X := &"snake_case"` + `ALL` +
   `is_valid()` + `LEGACY_INT_TO_ID` + `from_legacy()`。
3. registry 里删 enum（留迁移说明）、字典键 / 函数签名改 `StringName`、`%d` 改 `%s`、
   日志里的「编号」改「id」。
4. 全仓搜旧枚举名 → 脚本批量换 `Ids.X`（**带 unmapped 兜底**，映射缺失就报出来而不是静默跳过）。
5. 资源：先 `Select-String` 列全量 → 按映射表批量改 → **抽查两个文件确认** → 复查 unmapped=0。
6. 代码里的数字键字典单独处理（**区分「键是 id」与「值是 id」**，看函数名里有没有 `_order`）。
7. 门禁**单独跑**（别和别的 Godot 进程并行）；再无头启动一次看运行期错误
   （`StringName()` 构造这类问题只有跑起来才现形）。
   收尾用下面这五条扫一遍残留（本次扫完的结果见后表）：
   - `.gd` 里 `CharacterRegistry.PlantType|ZombieType|ZombieBossType`，排除注释行；
   - `.gd` 里 `PlantType\.P\d{3}|ZombieType\.Z\d{3}|ZombieBossType\.ZB\d{3}`；
   - `.tscn`/`.tres` 里 `(plant_type|zombie_type|boss_type) = \d+`、`content_id = [0-9]`；
   - `int(...(plant_type|zombie_type|boss_type|content_id)...)`、`(……_type|content_id) (==|!=|=) 0`；
   - 数字键字典（`^\s*\d+:`）—— **这一条不能直接照改**：本次扫到 19 处，只有两张
     `LEGACY_INT_TO_ID` 是编号（**故意保留**，给老存档迁移用），其余全是别的东西：
     智慧树里程碑高度、`SUN_BY_CHAIN_LEN` 的连击长度、`create_plant_order` 的**槽位序号**
     （键是槽位、**值才是 id**，改反了整条传送带就乱了）。
   资源里 `= [0.0, 500.0, ...]` 这种 22 处裸数字数组是粒子的 `_limits`，与 id 无关。
8. probe FAIL 了先别急着修 —— 用 `git worktree` 确认是不是迁移前就 FAIL。
9. 同步文档 + 本目录新建一条记录（含踩坑，尤其 1、3、4 这三条静默失败的）。

## 人工验证方法（改动很大，建议开一局过一遍）

1. 主菜单 → 冒险模式，进 1-1 种几株植物、看阳光扣除与冷却正常。
2. 选卡界面：卡片图标 / 名字 / 花费正确，模仿者能选中一株植物。
3. 打一关到通关掉落种子包（种子包上显示的植物名对）。
4. 「我是僵尸」模式：僵尸卡的图标与召唤正确；僵王关（5-10）僵王正常出场。
5. 砸罐子 / 传送带 / 三消（迷你游戏）：随机池与出怪表正常。
6. 退出重进：解锁进度、上次选卡、存档文件都在（老存档迁移的关键验证）。

## 补充：迁移完之后清掉老逻辑（同一天下午）

迁移完隔了一轮才回来收尾：`from_legacy()` 当时铺了 42 处，其中**一多半是迁移期的临时兜底**，
迁完就该摘了。清理的判据不是"能不能删"，而是**"这个值有可能不是 id 吗"**：

| 数据从哪来 | 会不会出现 int | 处置 |
| --- | --- | --- |
| **玩家磁盘上的存档**（`user://<用户名>/GlobalSaveGame.json`） | 会 —— 老档就这么写的 | **保留** `from_legacy()` |
| **仓库内的数据**（卡资源 / 关卡脚本 / 联机快照 / 配置字典） | 不会 —— 全在本轮扫过、改过 | **删掉兜底**，让代码里只剩一种口径 |

删了 6 处（`card_slot_norm` 3、`level_data` 2、`netplay_card_sync` 1），
保留了 `save_service` / `global_game_state` / 花园三处 / `card_reference`（**数据层边界**，
`@tool` 脚本被编辑器加载器直接反序列化，传进来的值不受本仓库代码控制）。

### ⚠️ `LEGACY_INT_TO_ID` 看着像死代码，**不能删**

判据来自实测而不是推理 —— 当时扫了 `user://` 下的存档：

- 当前用户（`"1"`）的 `curr_zombie` **已经是字符串 id**（`["norm", "flag", …]`）⇒ 这套兜底对它确实不再触发；
- 但 `default user` 那份**还是数字编号**（`[1, 2, 3, …]`），它一直没被新版加载过。

删掉 = 那个档的解锁植物 / 上次选卡 / 僵尸图鉴全变空。已在 `plant_ids.gd` 的表注释里写明
理由和收窄后的调用面，免得下一个 Agent 照着"没用到就删"把它清掉。

> **一句判据**：清理前先扫 `user://` 下的存档看还有没有数字编号 ——
> 有就说明迁移层还在生效，不是死代码。

### 踩坑

1. **`robocopy /E /XO` 同步 `mods_builtin` → `user://mods` 不可靠** —— 漏掉了新文件
   （`balance_wiring.gd` 没过去），门禁却报成 `Static function "xxx()" not found`，
   完全指向错的地方。改用 `Copy-Item -Recurse -Force`（已写进
   [验证流程.md §1.1](../验证流程.md#11-跑门禁前先把内置模组同步到-usermods)）。
2. **门禁 PASS 不代表能跑**：`probe_netplay_session` 的 `bad_snap` 还按老样子构造
   `cd_id` 为 `PackedInt32Array`，解包端已改成 `PackedStringArray` ——
   编译期查不出来（字典里塞的是 Variant），只有跑起来才报
   *Trying to assign value of type 'PackedInt32Array' to a variable of type 'PackedStringArray'*。
   **改了容器类型的数组字段，记得把构造它的测试也一起改。**
3. **probe FAIL 先分清是不是自己的**：`probe_card_lock` 这次报 8 项、
   `probe_netplay_session` 报 2 项，看着吓人，实际全都与本次清理无关 ——
   前者读的是 `game_para.get_max_choosed_card_num()` / 商店商品数（probe 的期望值是旧的）；
   后者第 7 节的前置条件要求"默认存档只解锁极少数植物"，而同一支 probe 前面几节已经解锁了 46 张，
   前置条件被自己污染。这类**前置条件被前面步骤破坏**的 FAIL 要认出来，别去改业务代码。
