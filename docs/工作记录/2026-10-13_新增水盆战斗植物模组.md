## 目标

新增一只**战斗植物**「水盆」：`P050WaterBowl`，**花盆的水生形态** —— 跟花盆一样摆在草地 / 屋顶上
（25 阳光、冷却 7.5 秒、占格子下层、承载上层植物），**唯一的差别是盆里装的是水，上面只接水生植物**
（海蘑菇 / 缠绕海草）。结果：草地上也能种海蘑菇 —— 原版没有这只植物、也没有这个组合，所以做进模组。
动画直接套用花盆场景里那条 `Pot_waterplants`，一行都没重写。

## 步骤

1. 摸清底部植物的机制：`PlacePlantInCell.Down` 那一层的两只（睡莲 / 花盆）靠 **XOR 地形位**改格子
   （睡莲：水 8 ↔ 睡莲 16；花盆：位置 4），判据是「植物条件 & 格子条件」（`condition_plant_base.gd`）。
2. 发现现成的动画：战斗侧 `plant_flower_pot.tscn` 的 AnimationTree 早就按 `is_water` 分了
   `Pot_idle` / `Pot_waterplants` 两支，但**战斗侧根本没有 `is_water` 这个属性**（只有花园花盆有），
   所以花盆永远播 `Pot_idle` —— 补上这个属性就能切到水盆那一支。
3. 本体开五个通用口子（都不叫「水盆」）：
   `PlantType.P050WaterBowl` 编号槽位、`register_runtime_plant()` / `clear_runtime_plant()`
   （`PLANT_INFO` 是 const，运行期写不进去）、`Plant000DownBase.own_condition_bit`
   + `PlantCell.down_plant_change_condition(is_water, own_bit)`、`@export_flags` 加一位「64 水盆」、
   `AllCards.rebuild()`（插卡后重排 `card_id`）。
4. 模组三件：`plant_water_bowl.tscn`（实例花盆 + `water_bowl_plant.gd` 打开 `is_water`、
   声明 `own_condition_bit = 64`）+ `water_bowl_mod.gd`（登记植物 / 换水生植物条件 / 插卡 / 解锁）。
5. 探针 `probe_water_bowl.gd`：注册 → 卡位页码 → 地形判据 → 动画 → 卸载，五步全绿。
6. 文档同步：`mods_builtin/README.md` 加一行、[模组机制.md](../参考存档/模组机制.md) §五新增第 10 / 11 条 +
   §6.4 整节重写。

## 关键决策与理由

- **动画套现成的，不复制**：水盆场景就是花盆场景 + 一个 `is_water = true`。同一套 Pot 贴图、
  同一套动画资源，只是状态机走另一支 —— 改动画只要改花盆那一份。
- **地形位由底部植物自己声明**（`own_condition_bit`）：本体不知道水盆是什么，只认「这只底部植物
  说自己占位 64」→ 种下后格子条件 = 1 无 + 64，移除就还原原地形。睡莲 / 花盆那两套原逻辑
  （`down_plant_change_condition` 按水池行走分支）**一个字没动**。
- **上层只接水生是「换条件」而不是「加白名单」**：把种植条件纯水（8）的那几株（现扫现算，
  现在是缠绕海草 20 / 海蘑菇 25）换成 8 + 64，走现成的 `set_runtime_plant_condition()` ——
  不动本体数据；陆生植物（条件 22：草地 / 花盆 / 睡莲）认不出 64，自动被挡在外面。
- **编号 P050 而不是 P037**：P037 已经是**大蒜**（P037~P048 全满）。「接在花盆后面」落在**卡片顺序**上
  （水盆卡插在花盆卡后 → card_id 34，选卡界面第 1 页），编号取正式段后面的空号。
- **分页没改**：`card_slot_candidate.gd` 的「每页多少张」取模板容器子节点数、页数按 `size()` 现算，
  本来就是自适应的 —— 插一张卡后面整体后移一格，调试植物仍在第 2 页（回归探针已验证）。
- **解锁先做「装了就能用」**：模组装载时 `unlock_plant()`，并且**每局 `install_to_main_game()` 补一次**
  （读档会按存档重建 `curr_plant`，只装一次的话玩家一读档水盆就没了）。正式的通关 / 商店解锁留待办。

## 踩坑（值得记）

- **需求方向错了两轮**：「水盆」先被理解成禅境花园水族馆页的**容器**（`GardenFlowerPot` 的 `is_water`
  形态），做了一半才发现要的是**战斗里的一只新植物**。`mods_builtin/water_bowl/` 整个改写了一遍。
  ⇒ 下次遇到「动画 / 类名在两个系统里同名」先问一句「哪个系统里的」。
- **改 `_ready()` 时把函数体插进了循环里**：给 `all_cards.gd` 抽 `rebuild()` 时缩进带错了
  （`func _ready` 缩进在 for 循环体内），报的是 `Expected indented block after lambda declaration`，
  一眼看不出是缩进问题。⇒ 插函数后先看一眼缩进层级。
- **`PackedScene` 插卡要重排编号**：`AllCards` 的 `card_id` 是按源目录**节点顺序**现算的，
  光 `add_child` 不生效，必须 `rebuild()`。

## 人工验证（还没做，要开游戏看）

1. 模组页面打开「水盆」→ 进任意草地关卡：待选第 1 页花盆后面多一张水盆卡（形象借的是花盆那份）。
2. 种水盆 → 上面点海蘑菇能种、点豌豆射手种不上（虚影是红的）。
3. 看水盆的**动画**是不是水盆那一支（叶片形态与花盆不同、盆里有水）。
4. **影子**：海蘑菇种进水盆后**看不到影子**（探针已覆盖，这里再肉眼确认一次）；
   把水盆铲掉 → 海蘑菇留在草地上、影子重新出现。

6. 关掉模组 → 卡片消失、海蘑菇回到只能种水里。

## 补充 / 评价（2026-10-13 · 移除水盆中植物的影子）

接着上面那条记录做的小修：盆里装的是水，上层植物（海蘑菇 / 缠绕海草）的影子落在水面上看着别扭，
要求藏掉。**改法只有一处：`water_bowl_plant.gd` 的 `ready_norm()` 那一组**，本体一行没动
（本体不认识「水盆」，这条本来就该留在模组里 —— 见 [模组机制.md](../参考存档/模组机制.md) §6.4）。

### 踩坑（两个都是 Godot 节点树的老问题，不查根本看不出来）

1. **`child_entered_tree` 早于 `_ready()`**：上层植物进容器那一刻发信号，它的 `@onready`
   （含 `shadow`）**还没赋值**，直接取是 null → 藏不掉，而且**不报错**，探针一跑才发现。
   ⇒ 取之前先看 `is_node_ready()`，没 ready 就挂它的 `ready` 信号（`CONNECT_ONE_SHOT`）。
2. **容器被搬回格子时会整棵重新入树**：水盆被铲 / 被啃掉时 `PlantCell` 会把 Norm / Shell 容器
   `remove_child` 再 `add_child` 回格子，**容器里每株植物都会再发一次 `child_entered_tree`** ——
   于是刚在 `_on_up_container_out` 里还回去的影子，又被 `_on_up_plant_in` 藏掉了
   （症状很怪：种下时没藏，等水盆没了反而藏了）。
   ⇒ 两个都做：出去时 `disconnect` 撤盯梢；`_on_up_plant_in` 里再判一次
   `down_plant_container.is_ancestor_of(up_plant)`，不是挂在自己下面就当没看见。

  `test/check_scripts.ps1 -Godot "C:\Users\a a\Desktop\godot.exe"` PASS。
