# 2026-10-07 · 排查调试 · 修 `portal_manager.gd` 的 get_world_2d 报错，并实测出编译门禁的盲区

> **任务类型**：排查调试
> **推荐度**：**推荐**（下次遇到「门禁 PASS 但编辑器/游戏报错」时，直接按这个思路怀疑门禁覆盖不到，别再怀疑自己的改动）
> **耗时与成本**：约 1 轮对话 / 未开游戏 / 无需人工介入（用户从 Godot 编辑器提供的报错）
> **验证方式**：免验证 + 已给出人工验证方法（编译门禁 PASS；**真正的确认必须进第 11 关，见文末**）
> **补充自**：无

## 目标

修掉用户报的 `错误 (146, 18)： Function "get_world_2d()" not found in base self.`

## 步骤

1. 全局搜 `get_world_2d`，定位到 `src/managers/portal_manager.gd:146`（斗转星移第 11 关的传送门管理器）。
2. 查 `PortalManager` 的继承链：`extends MainGameSubManager` → `main_game_sub_manager.gd` 是 `extends Node`。
   **`Node` 没有 `get_world_2d()`** —— 那是 `CanvasItem`（Node2D / Control）和 `Viewport` 的方法。根因确认。
3. 修成 `Node.get_viewport()` 取最近视口，再 `viewport.get_world_2d().direct_space_state`。
   `get_viewport()` 本身是 `Node` 的方法，任何节点都能调；且本函数只在 `_physics_process` 里被调用，此刻必在场景树中。保留了 `viewport` / `space` 两道判空，与原代码风格一致。
4. **顺手扫同类错误**（因为门禁抓不到，很可能还有别的）：列出 10 个高频 CanvasItem 方法的所有调用点，逐个核对接收者。
5. 把「门禁漏报」这个实测结论写进 `test/check_scripts.ps1` 头部注释。

## 关键决策与理由

- **改用 `get_viewport()` 而不是别的取法** —— 候选有 `get_tree().root.get_world_2d()`（root 是 Window，可行）和用场上某个 Node2D 的 `get_world_2d()`（耦合到具体节点，且门可能还没创建）。`get_viewport()` 是 `Node` 自带方法、语义就是「最近的视口」，最贴切且不引入新依赖。传送门判定发生在主视口的 2D 世界，与场上角色同一空间，等价。
- **没有去改门禁的行为** —— 曾经想过让它跑编辑器全量扫描来覆盖这类错误，但那是 §1-7 硬约束依赖的工具，改动影响面太大（编辑器模式会写 `.godot` 缓存、耗时长）。改成**如实记录局限 + 给出规避方法**，成本低且不会误伤现有流程。

## 踩坑

1. **编译门禁会漏报「方法在基类上不存在」这类语义错误** —— 修复前门禁输出 `real compile errors = 0`，我把门禁收集的 stderr 全文打出来核对，**里面一行相关输出都没有**。而 Godot 编辑器明确报错。
   根因：`--import` 只编译 Godot 真正加载到的脚本，且不对所有脚本做方法调用解析；`portal_manager.gd` 挂在 `main_game_base.tscn` 上，并没有被完整分析到。
   → **正解**：`check_scripts.ps1` 头部原本写着「Errors in existing scripts are always caught」，这句**已被证伪**，已改写为 KNOWN LIMITATION 2，并列明它能抓什么、抓不到什么。以后涉及「在非 CanvasItem 的 Node 上调 2D 方法」，必须在编辑器里确认一遍。
2. **按方法名全局扫会大量误报，必须核对接收者** —— 我扫出 4 处可疑点，逐个读完全是安全的：
   `beghouled_manager.gd:232/261` 是 `cell.get_local_mouse_position()`（`cell` 是 `PlantCell extends Control`）、
   `drop_item_manager.gd:170` 是 `get_viewport().get_canvas_transform()`、
   `global_utils.gd:83` 是 `viewport.get_screen_transform()`、
   `bullet_movement_track.gd:72` 的基类 `BulletMovementBase extends Node2D`。
   它们的方法名命中了，但接收者都不是 `self`。
   → **正解**：判定这类错误看的是「方法在**谁的**类型上不存在」，只搜方法名会把 `xxx.get_yyy()` 这种安全调用一起捞进来。

## 给后来者的最简路径

1. 遇到 `Function "xxx()" not found in base self` → 先查该脚本的 `extends` 链，确认这个方法属于哪个类（Godot 文档里查），再找同语义但基类上有的替代方法。本次的正解是 `Node.get_viewport()`。
2. **不要因为门禁 PASS 就排除编译错误**。门禁覆盖不到语义错误，编辑器报错以编辑器为准。
3. 想批量查同类错误：按方法名全局搜 + 逐条核对接收者的类型，别只看方法名。
