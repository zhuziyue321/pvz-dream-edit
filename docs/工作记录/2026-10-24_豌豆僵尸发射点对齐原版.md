## 原版口径（三段代码串起来才够）

`Zombie.cpp` `Zombie::UpdateZombiePeaHead()`（第 2338-2339 行；机枪 `UpdateZombieGatlingHead()`
第 2458-2459 行是同一套）：

```cpp
aOriginX = mPosX + aTransform.mTransX - 9.0f;
aOriginY = mPosY + aTransform.mTransY + 6.0f - mAltitude;
```

`aTransform` = 身体 reanim 里 **`anim_head1` 轨道的当前帧**变换 → 发射点跟着走路摇头 / 点头动。

**但 `mPos` 不是脚底，是头顶**：普通僵尸的碰撞框 `mZombieRect = Rect(36, 0, 42, 115)`，
从 mPos 往下 115 才到脚底（`GetDrawPos()` 里 `mZombieRect.Offset(mX, mY + mBodyY)` 直接拿它当
世界矩形，若 mPos 是脚底的话整只僵尸的受击框会跑到地面以下）。

**reanim 原点也不在 mPos 上**（`Zombie::DrawZombieWithParts()`）：

```cpp
float anOffsetX = aDrawPos.mImageOffsetX + 15.0f;
float anOffsetY = aDrawPos.mImageOffsetY + aDrawPos.mBodyY - 28.0f + 20.0f;
aBodyReanim->SetPosition(anOffsetX + 30.0f - mScaleZombie * 30.0f,
                         anOffsetY + 120.0f - mScaleZombie * 120.0f);
```

普通僵尸 `s = 1`、`mImageOffset = (0,0)`、`mBodyY = 0` → **reanim 原点 = mPos + (15, -8)**。
（`mImageOffset = mPos - mX` 只在被击退等特殊位移时非零，原版发射点公式没算它 —— 那是原版的小毛病，
仓库这边以「头节点真实世界位置」为准，反而更准。）

三段合起来：

```text
发射点 = mPos + mTrans + (-9, +6)
       = (头贴图左上角 - (15, -8)) + (-9, +6)
       = 头贴图左上角 + (-24, +14)
```

仓库侧的两个对应关系（都实测过，不是估的）：
- `Body/BodyCorrect/Anim_head/Anim_head1` 的 `position` **就是**原版轨道 `mTrans` ——
  `pak/reanim/Zombie.reanim` 的 `anim_head1` 第 0 帧写着 `<x>6.7</x><y>8.8</y>`，Godot 侧
  `zombie_walk.tres` 第 0 帧 `Vector2(6.7, 8.8)` 完全一致；节点原点 = 头贴图左上角；
- `Body/BodyCorrect` 的原点 = 原版 reanim 原点（`BodyCorrect.position = (-56,-116)` 就是
  「reanim 原点 → 角色根」的换算常量）。

`mAltitude` 在两式里各出现一次（发射点 `- mAltitude`、`mBodyY = -mAltitude`），**正好抵消** ——
所以不需要单独处理跳跃高度，头节点的世界位置已经带上了。

## 关键决策与理由

- **不在场景里手摆一个「看起来对」的静态点** —— 头在动画里一直在晃（±10 像素），静态点永远只在某一帧对得上；
  原版既然每帧读轨道，这里也每帧读。
- **不读 `plant_head`（头顶植物）的位置，也不读「植物的嘴」** —— 原版读的是 `anim_head1` 轨道，
  不是植物本体（两者差一层 `AttachBasePoseInverse × attach.offset`，且头顶植物比僵尸头多一棵「茎」）。
  照原版读轨道才是可复现的；「嘴」只是用来人工判断合理性的参照，不是判据。
- **偏移常量写成推导式而不是拍数字** —— `(-24, +14)` 是从
  `(-9, +6) - (15, -8)` 来的，注释里保留两个原版常量的出处，后人改 `scale` 相关逻辑时能顺着式子重算。
- **保留 `markers_2d_bullet`** —— 它仍是「一次发几颗」的配置来源与探针断言点（`probe_zom_botany` 会检查
  「发射点已解析成 Marker2D」），只是位置不再由它决定。

## 踩坑

1. **原版 `mPos` 不是脚底，是头顶** —— 第一反应会拿「僵尸节点原点（脚底）」当 mPos，
   算出来豌豆从地面附近冒出来（`(-2.3, 14.8)`）。判据：`mZombieRect = Rect(36, 0, 42, 115)`。
2. **原版 reanim 原点也不在 mPos 上**（`SetPosition(... + 15, ... - 8)`），
   漏掉这步会差 (15, -8)，看着「有改但还偏一点」。
3. **`scale.x = -1` 之后 `global_scale` 分解出来是 `(1, -1)`**
   → 用 `global_scale.x < 0` 判断「body 被水平镜像」永远不成立。
   → **正解**：判 `global_transform.x.x < 0`（第一列 x 分量）。
4. **刚改完 `scale` 立刻读子节点的 `global_position` 拿到的是旧值** —— 变换传播要等一帧，
   探针里镜像分支必须 `await process_frame` 再读。
5. **`Anim_head1` 的静态 `position` 和动画第 0 帧不是同一个值**（`25.9` vs `6.7`）——
   算「静态兜底值」时用编辑器静态值，这样在编辑器里看场景也是对的。
6. **`var x := load(...)` 推断不出类型**（老坑，§工作记录 2026-10-05 踩坑 4）：探针里要写显式类型。
