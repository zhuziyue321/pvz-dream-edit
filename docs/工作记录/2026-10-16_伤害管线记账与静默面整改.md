## 目标

「吸收并入 ②」之后，防具的**取消与扣血都发生在同一步**，于是出现三类问题：
① 取消返回的结果丢了已扣的血（记账）；② 「重写 `process_damage()` 必须 `super()`」这条约束只有注释没有机制（静默）；③ 保龄球 / 锤子的固定数值散在两处 `match`（漏改 = 静默不掉血）。
另有一条纯性能项：每次伤害都广播一个 **0 订阅方**的事件。

## 弯路 / 踩坑（三段式）

- **试过**：把 L-17 的彻底解写成「把吸收挪到子类不可重写的外层入口」（模板方法）。
- **因为**：那会**推翻上一轮的明确要求**（用户要求吸收在防具自己的 `process_damage()` 里），而且模板方法要动 `ArmorComponent` 的公开 API —— 改完还得再验证模组那三个 `absorb_damage()` 重写。
- **结论**：本轮只做**检测**（`Log.error` 自检），把「静默」变「可见」；模板方法作为彻底解留在 TODO 条目里，单开一轮再做。**做减法比做重构更适合本轮**。

- **试过**：只在 `probe_armor_component` 里把 `_ArmorImmuneBomb` 改成 `return super(info)` 就以为覆盖了「忘 super」的坑。
- **因为**：探针只能证明**这一层**写对了，证明不了「别人写错会被发现」—— 没有自检时，一个漏了 `super()` 的防具**照样全绿**。
- **结论**：护栏要加在**引擎侧**（`_verify_armor_absorbed()`）而不是探针侧；探针侧的改动只用来**触发**这条路径（`_check_cancel_keeps_absorbed_hp` 里内层就是故意取消的那层）。

- **试过**：改完代码才发现「取消分支回填血量」会让 §4.2 文档里那句「取消 = 一滴血不掉」变成错的。
- **因为**：机制文档把「整包取消」写成了绝对的「一滴血不掉」，而吸收前移之后它只对**最外层取消**成立。
- **结论**：改行为必须同轮扫一遍机制文档里对同一件事的**绝对化表述**（这次改了 `伤害系统.md` §4.2 与 `防具.md` §3.2 两处）。

## 推荐度与理由

**推荐**：三处改动都不碰玩法数值（固定值逐值等价、取消分支只是补数据、事件短路语义等价），却把两类**静默失败**变成了**红灯或日志**，收益 / 风险比很划算；两个探针把「6 种模式都掉血」「靠里取消不丢账」锁死了。

**照做前必须先接受这三条设计取舍**（已写进 `伤害系统.md` §4.2 / §10 与 `防具.md` §3.2）：

1. **修饰器排在防具之后**：②-c 读到的 `info.amount` 已是「走完防具剩下的」——按比例减伤只作用到打本体那部分。
2. **靠里的取消不回滚**：本体 / 内层防具 / 修饰器 `return false` 只挡更内层与本体；要「连防具也不掉血」必须让**最外层**防具取消。**取消结果的 `hp_loss` 仍反映外层已扣的血**，别读成 0。
3. **重写 `process_damage()` 的防具必须 `return super(info)`**：漏了那层永久不掉血；现在 debug 构建下会 `Log.error` 点名（只报不改）。

## 补充 / 评价（2026-10-16 · 护栏假阳性）

> **本次记录**：[2026-10-16_防具自检排除秒杀假阳性.md](2026-10-16_防具自检排除秒杀假阳性.md) ←→ 被补充：本文件

- **补充**：L-17 的护栏**上线即有假阳性** —— 玩家日志里 `模式=Norm / amount=640 / 宿主 Zombie003Cone` 那条报错，640 其实是 `get_all_hp()`（370 + 270），来自 `be_attack_to_death()` / `hp_loss_to_death()` 的**秒杀**包（`is_instant_kill`，防具刻意不吸收，清空交给 ③ `clear_all_hp()`）。`_verify_armor_absorbed()` 已补 `if info.is_instant_kill: return`，详见链接记录。
- **评价**：L-17 的检测思路不用改，但「合法不掉血的例外」当时只列了 `amount <= 0` 与规则 `None`，漏掉秒杀 ⇒ 每次大保龄球 / 铲除 / 清场都会刷一条假 ERROR。**护栏的假阳性会盖掉真阳性**，加自检时要一次把"刻意的合法例外"列全。
- **更省的做法**：写完自检后，按 `ConstDamage` 里那些"不看伤害值"的字段口径（`is_instant_kill` / 掉落 / 音效）逐个回读一遍早退条件，比等玩家日志来报快。
