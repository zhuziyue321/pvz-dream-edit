## 2. 弯路

1. **先想「重写一个 TreeOfWisdom 新类」**：其实页面、商店、工具栏、51 档动画全都是好的，坏的是**行为口径**。
   重写会把已经验证过的 51 档动画接线（节点集合按轨道并集反推）一起赔进去。正确做法是**只换判定与表现层**。
2. **想过按 wiki 推「高度→台词」表**：wiki 只写了「每袋一英尺」+ 三个里程碑，推不出 1..49 的对应。
   C++ 参照里 `TreeOfWisdomGiveWisdom` 一行就给出了 `clamp(aTreeSize - 1, 1, 49)` ——
   **有 C++ 参照就别查 wiki 猜**（[AI查wiki避坑.md](../参考存档/AI查wiki避坑.md)）。
3. **一开始想保留「常驻台词 Label」**：原版是气泡 + 只在 talk 状态出现；保留常驻会让「气泡位置按树高三档」
   这条根本没意义。直接换气泡，旧 Label 从场景里删掉。

## 3. 踩坑（三段式）

1. **坑**：`Animation` 取轨道 path 的方法名是 `track_get_path()`，顺手写成 `track_path_get()`。
   **现象**：编译门禁会报（`Function "track_path_get()" not found`），但只有跑到那句才暴露。
   **解法**：改回 `track_get_path()`；这类「API 名字前后颠倒」在 Godot 4 里很常见（`get_track_path` 的注册名就是 `track_get_path`）。

2. **坑**：原版计时全是 **100Hz 的 tick**（`mChallengeStateCounter` 每帧 -1），直接当秒用会让树 0.7 秒就嘟囔一次。
   **现象**：如果照抄数字（700~1500）当秒，玩家进页要等 12~25 分钟；当帧又太快。
   **解法**：统一 `ConstTreeOfWisdom.TICK := 0.01` 换算成秒，所有定时器写成 `N * TICK`，源注释里保留原版 tick 数便于对照。

3. **坑**：原版 `TreeOfWisdomInit` 把档位 `clamp(size,1,50)`，`TreeOfWisdomGrow` 却 `clamp(size,1,51)`。
   **现象**：看着像 off-by-one，担心高树重进页面会"缩一档"。
   **解法**：比对 `treeofWisdom_grow50.tres` / `grow51.tres` 后确认两档几乎等价（只差一条尾巴轨道），
   照抄原版两个上限，并在常量里分别命名 `ANIM_STAGE_INIT_MAX` / `ANIM_STAGE_GROW_MAX`。

4. **坑**：探针里数台词条数写成 79。
   **现象**：`[NG] 台词表共 79 条 80` —— 实际是 49 + 10 + 5×3 + 6 = **80**。
   **解法**：断言改成 80 并在注释里写清加法；这类"自己算错"的假红很容易被当成代码 bug。

## 4. 推荐度 / 最简路径

- **推荐度：做**（行为对齐，不涉及新素材；气泡用的是仓库里早就有的 `Store_SpeechBubble2.png`）。
- 最简路径（下次对齐别的原版 Widget 也照这个套路）：
  1. **先定位原版函数族**（`Select-String -Path 'src/Lawn/*.cpp' -Pattern '<名字>'`），把 Draw / Update / Init 三处一起读，
     因为「状态机在 Update、表现全在 Draw」是原版的一贯写法。
  2. **数据与判定进 const**（编号表 / 矩形 / 计时），页面脚本只留状态机与画面 —— 这样探针能直接断言常量函数。
  3. **写一条 `test/scenarios/probe_<名字>.gd`**：常量函数断言 + 真进场景断言接线与状态迁移，
     末尾打 `[XXX] result=PASS|FAIL`。比开窗口点一遍快，也能进 CI。
  4. 用户已经开着 Godot 时**别用 `run_autopilot.ps1`**（共享 `ap_out.txt` 会判 STALE_PROCESS）：
     手动 `godot.exe --headless --path <项目> -- --scenario=res://...`，并自己把 `$env:APPDATA` 指到临时目录、
     输出重定向到独立文件，就不会和用户那 4 个 Godot 抢文件。

## 7. 用户反馈后的第二轮（同日）

用户实测两条：「**没有拉伸动画**」「**肥料动画有偏移**」。两条都是上一轮引入/遗留的表现层问题，口径没动：

1. **拉伸动画消失**：`animation/garden/tree_of_wisdom/*.tres` 在上一轮被"单帧定妆"压成每轨 1 帧（为了 14MB → 3.3MB），
   施肥时自然没有过程。原版 `TreeOfWisdomGrow` 是 `PlayReanim("anim_growN", PLAY_ONCE_AND_HOLD, 0, 8.0f)`，
   素材 12fps ⇒ 8 帧/秒播，一档 5~10 帧要 0.5~0.8 秒。
   **解法**：不走 R2Ga（51 段会崩、要拆批、贴图路径还要修），改由
   [tools/gen_tree_wisdom_anims.py](../../tools/gen_tree_wisdom_anims.py) 直接读 `pak/reanim/treeofWisdom.reanim`（XML）
   逐帧生成：按 `anim_growN` 标记轨道切区间 + 展开继承语义 + 只在"值变了"的帧写关键帧。
   结果仍是 **3.4MB**，但每档有 5~9 个关键帧；`_apply_tree_visual` 长高时按 `8 × step ≈ 0.67` 倍速真播、进场才 `seek(length)` 定妆。
2. **肥料落点偏移**：`tree_food.tscn` 的 `Body` 为了手持时把袋子居中在光标上带了 `(-40,-46)`，
   上一轮把落点改成原版的 `(340,300)` 却没减掉这个偏移 ⇒ 袋子整体偏左上 40×46 像素。
   **解法**：`clone.global_position = tree.get_feed_position() - body.position`（`body` 用基类 `ItemBase` 的那个）。

踩坑（三段式）：

- **坑**：给 `TreeFood` 写 `@onready var body: Node2D = $Body`。
  **现象**：编译门禁 33 个 "Failed to compile depended scripts"，根因只有一行 `The member "body" already exists in parent class ItemBase`。
  **解法**：基类 `ItemBase` 已经有 `body`，直接用；改完 0 错。
- **坑**：想用 `_anim_player.paused = false` 解除进场时的 `pause()`。
  **现象**：`Invalid assignment of property or key 'paused' ... on a base object of type 'AnimationPlayer'` —— Godot 4 的 AnimationPlayer **没有** `paused` 属性。
  **解法**：解暂停就靠 `play(name)`（会从 0 重新播），判断是否在播用 `is_playing()`。
- **坑**：以为 reanim 的 `x/y` 是贴图中心，给动态建的 Sprite2D 写了 `centered = false` 后又怀疑是不是反的。
  **现象**：一旦反了整棵树每个部件都会偏半个身位。
  **解法**：查原版 `Reanimation::DrawTrack`：矩阵先 `+celWidth/2, +celHeight/2` 再套变换 ⇒ `x/y` 就是**左上角**，`centered = false` 正确；
  用 `grass` 轨道交叉验证（`y=392.8` + 800×207 的图 ⇒ 正好铺在 600 高屏幕的最底部，与页面里的静态草坡 `y=393` 一致）。

验证（无头）：
- `test/check_scripts.ps1`：`real compile errors = 0` / `result=PASS`。
- `probe_tree_of_wisdom`：`[TREEWISDOM] result=PASS failed=0`，新增 6 条断言 ——
  grow2 的 `Tree1:position` 有多帧（`keys=6`）、`speed_scale ≈ 0.667`、长高时 `is_playing()`、
  `seek(0.45)` 与末帧对比 `y 309.9 → 325.2 / sy 1.18 → 1.00`（拉伸确实存在）、
  落点 `(340,300)`、袋子首帧左上角 `(338.6, 302.9)`（与原版一致）。
- 仍建议人工看一眼：喂一袋，树应该在 0.5~0.8 秒里"拉长再收回"，袋子正好倒在树根上而不是偏左上。

## 8. 第三轮：新贴图从左上角平移过来（同日）

用户反馈："拉伸并切换贴图时新的贴图会从左上角平移过来"。这是 XML 直出动画的两个**只体现在画面上**的语义坑：

1. **隐藏期的坐标是 `(0,0)`**：半路出场的部件（`grow2` 的 `Tree1`、`grow12` 的一堆叶子）在出场帧之前根本没有坐标，
   展开继承语义拿到的是 `(0,0)`。照抄成关键帧后，Godot 从 `(0,0)` 线性插值到出场坐标 —— 就是"滑进来"。
   修法：`visible == false` 那段用**出场那一帧的姿态**顶住，并在出场帧补钉一个关键帧（否则运动仍会提前开始）。
2. **`visible` 轨道也走插值**：`false@t0 → true@t1` 在中点就翻成 `true`（实测 `grow2` 的 `Tree1` 在 t=0.25 就显示了，
   而坐标到 t=0.4167 才到位）。修法跟 R2Ga 一致：切换前一帧再放一次旧值，把跳变压进 1 帧；`interp = 0`（nearest）没用，
   它同样按中点取近。

验证：逐帧采样 `grow2`（t=0 … 0.833 共 21 个采样点）—— 现在 `Tree1` 在 `visible=false` 期间坐标一直是 `(381, 308.2)`，
第一次 `visible=true` 时坐标/缩放正好是出场姿态（308.2 / sy 1.196），之后才收到 325.2 / 1.0。
另做了一次全量离线扫描（984 个"从 0 帧起就隐藏"的部件，坐标从 `(0,0)` 开始的数量 = **0**）。
`probe_tree_of_wisdom` 也补了一条断言（隐藏期 y ≈ 308.2 且 `visible == false`）。
