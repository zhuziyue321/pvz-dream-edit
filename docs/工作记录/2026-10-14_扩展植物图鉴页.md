# 2026-10-14 给「模组植物 / 调试植物」新开一页图鉴

> **任务类型**：新增内容（UI 新页 + 图鉴数据）
> **一句话**：图鉴加第 3 页「扩展植物」，收录调试模式专属四种植物与模组新增植物（水盆），
> 并把「追加类植物」的判据 / 顺序从选卡界面抽到 `AllCards`，两处共用同一份。

---

## 1. 先确认现状：这两类植物为什么进不了植物页

植物页 `AlmanacPlantPage.init_plant_card()` 有第二道过滤 ——
`if Global.global_read_data.data_almanac["Plant"].has(curr_plant_name)`：
**没有原版图鉴文本的植物压根不建卡**。于是两类植物永远进不去：

- 调试模式专属（三保龄球 + 反向双发，见 `ConstPlantUnlock.DEBUG_MODE_PLANT_TYPES`）；
- 模组新增（运行期注册的，见 `CharacterRegistry.is_runtime_plant()`，例如水盆）。

> **套路**：植物页那句 `has(...)` 是「图鉴只收有原版文本的」这一设计的唯一体现，
> 想让新植物进图鉴**不是给它补一条 json**（模组植物本体不该认识），而是另开一页。

## 3. 两个设计决定

1. **`ExtraPlant` 段按植物 id 建键**，与 `Plant` / `Zombie` 段按 PlantName 建键**不同**。
   理由：这一页里有一半植物是模组运行期注册的，本体拿不到稳定的 PlantName
   （水盆的 `plant_name` 是模组自己填的，随时可能改；id 才是唯一稳定标识）。
2. **水盆的条目不在本体 json 里**，由模组 `install()` 自己登记、`uninstall()` 摘掉 ——
   本体不认识任何一个模组（硬约束），关掉模组就不该在图鉴里看见一个谁都种不出来的盆。
   登记口子 `GlobalReadData.register_extra_almanac_entry()` 是通用口子，谁都能用。

## 4. 坑

1. **兜底条目必须存在**：模组可以只装植物不写文本，点开卡片时面板不能空白 / 报错。
   所以 `get_extra_almanac_entry()` 三级兜底（运行期 → json → 按注册表兜一条），
   且面板读字段一律 `.get(键, 默认)`，参数项 `mini(条数, 5)`（面板只摆了 5 行）。
2. **空页不能停在上一株**：`init_almanac_page()` 里 `extra_plant_types` 为空要走
   `almanac_update_empty_extra_panel()`，还要 `clear_show_character()` ——
   不然右侧面板会留着上一次看的植物且「花费 / 冷却」显示旧数值。
3. **新脚本的 `.uid` 要等 Godot 导入后才有**：先在 `.tscn` 里写不带 `uid` 的
   `ext_resource`，跑一次 `godot --headless --import` 生成 `.uid`，再把 uid 补回去
   （不补也能跑，但仓库里所有 `ext_resource` 都带 uid，保持一致）。
4. **探针里别用没注册过的植物 id 试兜底**：`CharacterRegistry.get_plant_info()` 会对
   未注册类型打 `Log.error`，污染 stderr。借一株本体植物（豌豆射手）当「临时模组植物」即可。
