# 2026-10-24_对战入口牌按模组开关显隐

> **本次任务**：主菜单木牌上那张「MULTIPLAYER」牌（woodsign3 贴图）改成**按玩家对战模组的开关显隐** —— 模组没开就不显示
> **耗时 / 轮次**：约 6 轮；没开游戏（探针无头跑过 + 编译门禁过）
> **推荐度**：推荐

## 目标

- 玩家在模组页面里关掉「玩家对战」后，主菜单木牌上那块「MULTIPLAYER」牌**不该还显示**（原来按下只会弹一句「要在模组页面里打开」）。
- 运行期在模组页面里拨开关要**立刻生效**（模组页面就在主菜单场景里，牌就在眼前）。

## 最简路径（步骤）

1. `ModManager` 加一个通用信号 `mod_enabled_changed(mod_id, enabled)`：
   在 `src/mods/mod_manager.gd` 的 `_apply_enabled_state()` 里发（开 / 关都发）——
   那里是开关真正翻面的**唯一**入口（`set_mod_enabled()` 与 `reload_for_current_user()` 都走它）。
   ⚠️ 发信号前要把原来那几处 `return` 改成 if/else 结构，否则 `mod == null` 时信号发不出去。
2. 本体 `src/menus/start_menu/start_menu_root.gd`：
   - 常量 `MULTIPLAYER_SIGN_PATH := "WoodSign/ButtonMultiplayer"`；
   - `_apply_multiplayer_sign_state()`：按 `ModManager.is_mod_enabled(ModIds.PLAYER_BATTLE)` 设 `visible`；
   - 在 `_update_mode_lock_state()` 里调它（`_ready()` 与换用户都会走到）；
   - `_ready()` 里连 `ModManager.mod_enabled_changed` → `_on_mod_enabled_changed()`（只认 `ModIds.PLAYER_BATTLE`，别的模组不管）。
3. 探针 `test/scenarios/probe_player_battle_mod.gd`：先 `set_mod_enabled(..., false)` 断言牌**不显示**，
   再 `set_mod_enabled(..., true)` 断言牌**出现** + 槽位注入（原来只测了开着时的样子）。
4. 门禁：`powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`（`real compile errors = 0`）。
5. 回归：`test/scenarios/probe_player_battle_mod.gd`（见下面的跑法）。

## 弯路 / 踩坑（三段式）

- **试过**：把显隐判断放进 `_on_multiplayer_pressed()`（按下时才发现没开 → 弹提示）。
- **因为**：那是「已经看见这块牌了」才补救，牌照样显示着 —— 与需求（**不该显示**）相反。
- **结论**：显隐要在**入口就位前**决定（进主菜单时算一次），运行期变化靠信号补一次。

- **试过**：让本体每帧 / 定时轮询 `is_mod_enabled()`。
- **因为**：没找到现成的「模组开关变了」的广播机制，想靠轮询凑。
- **结论**：`ModManager` 里补一个信号更干净 —— 开关翻面本来就有唯一入口（`_apply_enabled_state()`），
  在那里发一次信号，本体谁关心谁连。**这类「模组开关变了」的通用口子，本仓库此前没有**，加一个就够复用。

## 推荐度与理由

推荐：改动只有「一个通用信号 + 主菜单几行」，本体仍然只问 `ModManager.is_mod_enabled(ModIds.XXX)`
（守 [模组机制](../参考存档/模组机制.md) §五 边界规则 1：不 import 模组），不碰模组里的任何路径。

后来者注意：

- **本体这一侧仍然留着**那块牌与它的两张贴图（`pak/images/SelectorScreen_WoodSign3.png` / `_press.png`）——
  本次只改「什么时候显示」，没改贴图与位置。
- `_on_multiplayer_pressed()` 里那句「要在模组页面里打开」的提示**留着当兜底**（模组开着但槽位没注入时仍可能走到）。
- 换用户时 `ModManager.reload_for_current_user()` 会给**每个**模组发一次 `mod_enabled_changed`，
  所以新用户的模组开关一变，主菜单的牌也跟着重算 —— 不必额外处理。
- 探针跑法（避开用户正在跑的 Godot 进程）：
  ```
  $env:APPDATA = "$env:TEMP\pvz_autopilot_pb\userdir"   # 独立用户目录，不动真存档
  "C:\Users\a a\Desktop\godot.exe" --headless --path "<仓库>" -- --scenario=res://test/scenarios/probe_player_battle_mod.gd --autopilot-max-seconds=180
  ```
  （`test/run_autopilot.ps1` 会在有 Godot 进程在跑时直接拒绝 —— 那是防「读到上次那份报告」，别用 `-KillStale`。）
