# 2026-10-11 · 其它 · 模组入口挪进控制台，主菜单「选项设置」改名「控制台」

> **任务类型**：其它
> **推荐度**：**推荐**（「把一个独立入口收进已有面板」照这个走；关键是**让被引用的页面挂进引用方的场景**，别跨场景找节点）
> **耗时与成本**：约 1 轮对话，未开游戏（门禁 PASS + 无头 `probe_mod_page` / `probe_console_registry` / `probe_start_menu_layout` 均 PASS，画面需人工看一眼）
> **验证方式**：免验证 + 已给出人工验证方法（改动集中在 UI 挂载与文案，无头探针已覆盖「引用连上 + 点得开 + 关得掉」）
> **补充自**：[2026-10-11_模组页面左右分栏.md](2026-10-11_模组页面左右分栏.md)（那条把入口做成了选项面板里的独立按钮，本次把它收进控制台）
> **关联**：[控制台.md](../参考存档/控制台.md) ｜ [模组机制.md](../参考存档/模组机制.md) §七 ｜ [M-06](../参考存档/规范细则存档.md#m-06-跨节点的引用export-节点类型在手写-tscn-里解析不到)

## 目标

1. 主菜单 → 选项 里那个独立的「模组」按钮撤掉，模组页面改从 **主菜单 → 选项 → 控制台 → 入口页最后一个「模组」按钮** 进；
2. 主菜单 → 选项 里「选项设置」这个按钮**改名为「控制台」**；
3. 游戏内暂停菜单那份控制台（主菜单之外的另一份）**不受影响**：它没挂模组页面，入口页就不该出现「模组」按钮。

## 步骤

1. 先确认现状：`start_menu.tscn` 里 `StartMenuOptionDialog/Button4` = 「选项设置」挂着
   `control_canvas_layer.tscn`（控制台），`Button5` = 「模组」挂着 `mod_page.tscn`（模组页面），
   两个都是 `CanvasLayer`，靠按钮的 `pressed` 信号连各自的 `appear_*()`。
   （同理，游戏内是 `main_game_base.tscn` 的 `MainGameMenuOptionDialog/Option/Button4`，
   而 `canvas_layer_control.gd` 是**两份共用的脚本** —— 所以「有没有模组按钮」不能写死在脚本里。）
2. 场景侧：删掉 `Button5` 整段（含它的 `Panel` / `Label` / `CanvasLayer` 与那条 `pressed` 连接），
   把模组页面实例挪到 **`StartMenuOptionDialog/Button4/ModPage`**（与控制台同挂在「控制台」按钮下），
   `Button4/Label` 的 `text` 改成「控制台」。
3. 脚本侧：`CanvasLayerConsole` 加 `@export var mod_page_path: NodePath`，`_ready()` 里
   `get_node_or_null()` 一次存进 `var mod_page`；`_build_index_page()` 末尾加一个「模组」翻页按钮
   （带 `NAV_META`，与分组按钮同款），点了调 `mod_page.appear_mod_page()`。
4. 开 / 关的收尾：`appear_canvas_layer_control()` 与 `_on_texture_button_pressed()` 都顺手把
   模组页面 `visible = false`（上次停在模组页面就关掉控制台 → 下次打开不会直接弹出来）。
5. 探针：`probe_mod_page` 的入口断言全部改到新路径，并**加一段真点一遍**的验证
   （入口页有「模组」按钮 → 点了页面显示且控制台还在 → 关页面回到控制台 → 关控制台时页面一起收掉）。
6. 文档：`控制台.md` / `模组机制.md` / `联机模组.md` / `联机模组规范.md` 与各 `.gd` 注释里的
   「主菜单 → 选项 → 模组」统一改成「主菜单 → 选项 → 控制台 →「模组」」。

## 关键决策与理由

- **模组页面挂进「控制台」按钮下面，而不是留在原处让控制台跨节点找它** —— 引用方与被引用方在同一个父节点下，
  一个相对 `NodePath("../ModPage")` 就说清楚了；也让「哪份控制台有模组入口」这件事只由场景决定。
- **有没有「模组」按钮由 `@export mod_page_path` 决定，不是写死在脚本里** —— 控制台脚本被主菜单与游戏内
  两份场景共用，写死会让游戏内那份多出一个点了没反应的按钮。
- **模组页面盖在控制台上，不隐藏控制台** —— 它自己是全屏背景的 `CanvasLayer`，关掉（右下角「关闭」）
  自然回到控制台入口页，省掉一条「回到控制台」的反向调用。
- **游戏内那份暂停菜单的「选项设置」按钮没跟着改名** —— 需求写的是「主菜单 → 选项 → 选项设置」，
  游戏内那份是另一条路径（`暂停 → 选项设置 → 控制台`），不在本次范围内。

## 踩坑

1. **现象**：先写成 `@export var mod_page: ModPage = null` + `.tscn` 里 `mod_page = NodePath("../ModPage")`，
   探针报 `控制台认得模组页面` FAIL（拿到的 `mod_page` 是 `null`，且不报任何错）。
   → **原因**：手写的 `NodePath` 指向**文件里排在它后面的兄弟节点**（`ModPage` 在 `CanvasLayer` 之后），
   加载按文件顺序建节点时那个节点还没建出来，解析结果为 null；节点类型的 `@export` 在 `.tscn` 里
   就是这样被静默丢掉的。
   → **正解**：改 `@export var mod_page_path: NodePath = ^""` + `_ready()` 里 `get_node_or_null()`，
   与节点在文件里的先后顺序无关（已沉淀为 [M-06](../参考存档/规范细则存档.md#m-06-跨节点的引用export-节点类型在手写-tscn-里解析不到)）。
   → **顺带的教训**：只断言「节点挂上了」不够，**一定要再断言「引用真的指向那个节点」** —— 这次挂上了却没连上，
   是加了 `console.mod_page == page_in_menu` 这条才暴露的。

## 给后来者的最简路径

1. 场景里把被引用的页面实例挪到引用方**同一个父节点下**（如 `Button4/ModPage`），删掉原来的入口按钮与其 `pressed` 连接。
2. 引用方脚本加 `@export var xxx_path: NodePath` + `_ready()` 里 `get_node_or_null()`（**不要**用节点类型的 `@export`）。
3. 面板里加按钮时带上 `NAV_META`，免得探针统计「条目带来的控件」时被算进去。
4. 探针里补两条：`引用 == 那个节点` + `点了真的打开 / 关掉真的回去`。
