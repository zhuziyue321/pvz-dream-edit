# 2026-10-16_防具自检排除秒杀假阳性

> **本次任务**：玩家运行日志里 `防具 ArmorComponent（宿主 Zombie003Cone）本该吸收 640 点伤害却没有掉血…模式=Norm` 是**假阳性** —— 给 `_verify_armor_absorbed()` 补上「秒杀不看伤害值」这个合法例外。
> **耗时 / 轮次**：1 轮；编译门禁 ×1（PASS），未开游戏
> **推荐度**：推荐（3 行改动，但请先看「踩坑」里的**误判链**）

## 目标

上一轮加的 debug 护栏（`_verify_armor_absorbed()`，见 [2026-10-16_伤害管线记账与静默面整改.md](2026-10-16_伤害管线记账与静默面整改.md)）报了一条 `Log.error`，但**没有任何防具漏 `return super(info)`**。要求：让护栏不再误报，且不削弱它抓真问题的能力。

## 现象与根因

- **日志**：`模式=Norm`、`amount=640`、宿主 `Zombie003Cone`（路障）、防具节点名 `ArmorComponent`，清场后连报两次。
- **640 的来源**：`370`（路障防具）+ `270`（僵尸本体）= `hp_component.get_all_hp()`，正是
  `HpComponent.hp_loss_to_death()` / `Character000Base.be_attack_to_death()` 填伤害值的写法（`const_damage.gd` / 全仓 `.gd` 里搜 `640` **一个常量都没有** —— 这是判"它不是真伤害值"的第一个信号）。
- **这两个入口都开秒杀**：`info.is_instant_kill = true`。而 `ArmorComponent.process_damage()` 在秒杀时**刻意** `return true` 且不吸收 —— 防具与本体由 ③ 的 `HpComponentZombie.clear_all_hp()` 一起清空（秒杀绕开所有吸收规则，这是设计）。
- **护栏漏了这个例外**：它只看「活着 + `amount > 0` + 规则非 `None`，却 `is_hit_this_time == false`」，没排掉秒杀 ⇒ 每条 `be_attack_to_death()` / `hp_loss_to_death()` 路径（大保龄球、铲除、死亡消失…）都会稳定误报一次。

## 最简路径（步骤）

1. `src/entities/character/components/hp_component/component_hp_zombie.gd` → `_verify_armor_absorbed()`：在 `OS.is_debug_build()` 门槛之后、其余判定之前加
   `if info.is_instant_kill: return`，并写明理由（合法例外，不是漏 `super()`）。
2. `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`（`real compile errors = 0`）。

**没做的事**（有意）：不给秒杀路径补 `is_hit_this_time`，也不改 `clear_all_hp()` —— 那里已经正确置位，改反而会牵动 ③ 的信号补发。

## 弯路 / 踩坑（三段式）

- **试过**：先按报错字面去查「哪个防具重写了 `process_damage()` 却没 `return super(info)`」—— 把 `ArmorComponent` 的三个子类（气球 / 报纸 / 植物头）与 `mods_builtin/` 全扫了一遍，一个重写都没有。
- **因为**：报错文案（`_verify_armor_absorbed` 写的那句话）把**所有**「没掉血」都归因成「忘了 `return super()`」，于是照着它找必然一无所获。
- **结论**：看到护栏报错先问「这条路径上**有没有一种刻意不掉血**的合法语义」。目前在防具链上一共有三种：**秒杀**（`is_instant_kill`，本次新增排除）、**规则是 `None`**（该类防具本就跳过这种模式，早已排除）、**`amount <= 0`**（没有伤害可吃，早已排除）。加护栏时应当把这三条一次列全。

## 推荐度与理由

**推荐**：改动只在 debug 自检的早退条件上，结算路径一行没动，编译门禁 PASS。踩坑本身比代码值钱 —— 护栏的"合法例外清单"要一次列全，否则**假阳性会盖掉真阳性**（人一旦习惯忽略这条日志，护栏就等于不存在）。

**人工验证方法**（本机 debug 构建）：进任意关卡，用大保龄球砸死一只戴防具的僵尸（走 `be_attack_to_death()`），或对僵尸走任何 `hp_loss_to_death()` 的路径（铲除 / 清场）；控制台**不应**再出现 `防具 … 本该吸收 … 却没有掉血`。反向验证：临时给一个防具子类重写 `process_damage()` 只 `return true`，该日志应立刻出现。
