# 2026-10-25_拉杆二修

> **本次任务**：用户反馈拉霸（迷你 03）四个症状——① 杆和球略有错位（待机时球悬空 13px）；② 「横杆」不见了（原版待机只见一截深色短杆从面板后伸出，我们画成整根亮银色斜杆横在面板上）；③ 位置不对（整条机器系比原版实机左移 ~10px）；④ 遮挡不对（拉杆画在机器面板上面，原版在面板后面）
> **耗时 / 轮次**：约 8 轮（大头在「对照原版实机截图逐像素定口径」）；**开了游戏**（三张截图前后对照 + `[SLOT] result=PASS failed=0`）

## 目标
拉杆组件与原版实机截图逐像素对齐：球压杆端无缝、杆被面板遮挡只露一截、整机位置对齐、待机呈暗色脉动。

## 最简路径（步骤）
1. **拿原版基准**：wiki（plantsvszombies.wiki.gg）拉霸页的实机截图（MediaWiki API `prop=images` → `imageinfo` 拿直链，PS `Invoke-WebRequest` 下载）。待机图（"Pull handle for new seeds!"）、回弹中图（"Sun Jackpot!"）、结算图各一。
2. **验素材**：桌面 `b/assets/reanim`（官方安卓解包）与 `PVZ_DLC/_unpacked`（PC 系）的 `SlotMachine.reanim` + base/shaft/ball/Overlay/SunBank 全部与本仓 MD5 一致 —— 素材没问题，差异全在摆位口径。
3. **遮挡**（代码实证）：原版 `Board::Draw` 里 `DrawBackdrop`（含 `Challenge::DrawSlotMachine` → 拉杆 reanim）先画、种子银行（含覆盖层）后画 → UI 里把 `_build_lever()` 挪到 `_build_overlay()` 之前（HandleButton 保持最上层可点）。
4. **着色**（代码实证）：待机可拉时原版对整个拉杆 reanim `SetColorizeImages(true)` + `GetFlashingColor(mMainCounter, 75)` = **灰度三角波 55..255**（PvzpCommon.cpp 969，1 tick=10ms）；滚动 / 奖杯时不着色。替换原来的「白色发光闪烁」。
5. **+10 位置校准**（截图实证）：对 w1/w3/w4/w5 逐行扫面板红框（200..480）、窗口深框（259/317/376）、亮色包面跨度 → 原版机器系整体在 PvZ-Portable 常量 +10 处（PvZ-Portable 的 189/247/473 是 -10 转写偏差）→ 覆盖层 199、包 257+59i、热区 x=483、拉杆关键帧 x+10、阳光数字 +8。
6. **球待机位**：轨道 frame0 球心 (486.4,11.2) 与杆上端 (496.7,37.8) 差 13px（数据本身如此）；原版实机待机球心 ≈(505,21) 压住杆端 → 待机帧（0/8）y 校到 24.4，其余帧保持轨道值（中段本就与杆相连）。
7. **验证**：`check_scripts.ps1` PASS → 视觉探针（悬停菜单/拉杆命中 + 三张截图）→ 与 w3 并排放大对比：球位、杆位、遮挡、着色全部对上 → `probe_slot_machine` PASS。

## 弯路 / 踩坑（三段式）
- **试过**：从 reanim 数据 + PvZ-Portable 常量硬推原版画面，反复解不出「球比推算低 11px」。
- **因为**：一个 placement 同时满足杆（+10,0）和球（+10,+11）在数据上无解，纯推理死循环。
- **结论**：画面类问题**以原版实机截图为最终基准**，数据只用来定动画段的相对形状；绝对位置靠截图量。

- **试过**：用颜色滤镜像素扫描直接量球/杆 bbox。
- **因为**：待机拉杆被着色变暗、栅栏/草地颜色干扰，滤镜口径稍微一松就扫到背景。
- **结论**：像素扫描适合量**高对比结构**（面板红框、窗口深框、亮色卡面）；量球/杆这种小目标不如高倍放大目测 + 多张互证。

- **试过**：把 wiki 截图用 `cmd /c curl -o` 下载。
- **因为**：cmd 引号嵌套把 `-o` 吃了，二进制全喷到 stdout；`b/`、`PVZ_DLC` 路径里带空格的目录在 cmd 里也各种翻车。
- **结论**：下载 / 文件操作一律写 `.ps1` 脚本跑（`Invoke-WebRequest -OutFile` / `Get-FileHash`），别在 cmd 引号里纠缠。

## 推荐度与理由
推荐。**通用价值**：① 复刻项目的硬编码像素常量可能有系统性偏差，用原版截图逐像素互证才是硬基准（本仓已沉淀「对 wiki 截图扫描面板/窗口跨度」的反查手法）；② reanim 驱动的 UI 件**绘制顺序本身就是口径的一部分**（`Board::Draw` 的层序决定遮挡）；③ `GetFlashingColor(counter, N)` = 灰度三角波 55..255 这个原版通用闪烁件，别的关卡闪烁提示（墓碑、闪光提示）大概率同源。**给后来者**：原版基准截图在 wiki 关卡页，API 两步拿直链；桌面 `b/assets`（官方安卓解包）+ `PVZ_DLC/_unpacked` 可做素材 MD5 基准。
