> **验证方式**：免验证 + 已给出人工验证方法（见文末）
> **补充自**：[2026-10-17_潜伏芹菜动画导入.md](2026-10-17_潜伏芹菜动画导入.md)（同一条 `.pam.bin` 路线；本篇新增**碎图模式**与**离线合成取帧**）

## 1. 目标

`tmp/goopeashooter_pam/` 里有一份 PVZ2 毒液豌豆（Goo Peashooter）的素材：

- `pvz2_anim/goopeashooter.pam.json`（PopStudio 导出，1.8 MB，325 帧 / 29 图 / 20 sprite / 6 段状态）；
- `texture/goopeashooter/*.png`（**29 张碎图**，一个部件一张，不是图集）；
- `pvz2_anim/goopeashooter.pam.bin`（更早一次烘焙的产物，**贴图路径写的是 `res://texture/goopeashooter/`，仓库里没有这个目录**）。

要求：只把**动画**导进 `mods_builtin/pvz2/`（做成植物是下一步的事）。

## 2. 做了什么

1. **给 `tools/bake_pam_bin.py` 加碎图模式**：`--texture-dir` + `--texture-res`，不需要 `--resources` / `--atlas`。
   图集模式代码一行没动。
2. **落位** `mods_builtin/pvz2/goopeashooter/`：29 张 png + `goopeashooter.pam.bin`（365,915 字节）+ `goopeashooter_anim.tscn`。
3. **装扮**：`hidden_parts = ["custom_01", "_custom"]`（前者是那顶草帽）。
4. **新工具** `tools/render_pam_bin.py`：把 bin 的某一帧离线合成成 PNG，用来判部件 / 装扮。
5. **探针** `test/scenarios/probe_pvz2_goo_anim.gd`，无头 PASS failed=0。
6. 文档：[../参考存档/动画导入.md](../参考存档/动画导入.md) §1 / §5 / §8。

## 3. 关键决策与理由

### 3.1 碎图而不是拼图集

素材只有碎图，没有 `RESOURCES*.json`（拼图集要自己算 29 个矩形）。运行时 `_bind_textures` **本来就支持多贴图**
（一张就整张复用，多张按 `part_name` 精确匹配文件名），所以直接碎图落位：省一步，代价是 29 个纹理对象。

### 3.2 碎图的 `src_rect` 与 `draw_size` 必须分开

碎图 PNG 的**像素尺寸比 PAM 的逻辑尺寸大 1.28 倍左右**（导出时带的 padding）：

| 部件 | PAM `size` | PNG 像素 |
|---|---|---|
| `goopeashooter_30x24` | 30×24 | 39×31 |
| `goopeashooter_206x206` | 206×206 | 264×264 |
| `goopeashooter_119x119` | 119×119 | 153×153 |

所以 `src_rect` 取整张 PNG（`0,0,w,h`）、`draw_size` 取 PAM 的 `size`；反过来写就是整体放大 28%。

### 3.3 装扮只能靠渲染判断

`custom_01` 在**每一段状态里都在用**，既不在名字上露馅（和 `peashooter_*` 混在一起）、也不存在「没用到的就是装扮」
这种捷径。做法是离线合成同一帧两次（有 / 无 `custom_01`）对比：带它是「草帽 + 透明披风」，去掉就是干净的毒液豌豆。
`_custom` / `peashooter_head_*` 这类空 sprite 同理不影响。

### 3.4 旧 bin 不复用，重烘

旧 bin 的贴图路径绑死在 `res://texture/goopeashooter/`，搬进模组后就整株不画（`_bind_textures` 逐条 `Log.error`）。
重烘顺手当了一次回归：新工具产物与旧 bin **字节数相同、帧数 / 图数 / sprite 数 / 尺寸全一致**，只有贴图路径顺序
（旧的按文件名排序、新的按 PAM image 顺序）与个别浮点末位 1 ULP 的差别 —— 都无影响。

## 4. 踩坑

1. **只看 json 里 `size` 会以为碎图没 padding**：`size` 是逻辑尺寸，PNG 实际更大，两者都得用上（见 §3.2）。
2. **`custom_01` 别按名字猜**：第一版没关装扮，渲染出来头上是草帽；关掉才对。
3. **`.import` 不要手抄**：29 张碎图搬进模组目录后由 Godot 自己生成（本次是跑一次无头探针顺带导入的），
   之后 29 个 `.import` 要跟 png 一起提交。
4. **`tmp/.gdignore` 已存在**：素材留在 `tmp/` 不会触发编辑器反复导入；搬进 `mods_builtin/` 才会进导入管线。
5. **`--texture-res` 是写进 bin 的路径**：漏写就会按 `--texture-dir` 相对当前目录推导，路径不对运行时就是「贴图不存在」。

## 5. 给后来者的最简路径

1. `python tools/render_pam_bin.py --bin <旧bin> --list`（或读 json）确认帧数 / 状态名 / 部件名。
2. 把碎图搬进模组目录，然后
   `python tools/bake_pam_bin.py --json <x.pam.json> --texture-dir mods_builtin/pvz2/<角色> --texture-res res://mods_builtin/pvz2/<角色> --out .../<角色>.pam.bin`
   （先跑 `--check-only`；看「相邻帧完全相同占比」是不是个位数）。
3. `python tools/render_pam_bin.py --bin ... --texture-dir ... --state idle --frame 5 --out tmp/a.png`，
   再 `--hide <可疑装扮>` 出一张对比，把装扮名填进 `hidden_parts`。
4. 抄 `goopeashooter_anim.tscn` 写场景：`binary_path` 指 bin、`oneshot_states` 填非循环段（`attack` / `plantfood` / `water`）。
5. 探针照 `probe_pvz2_goo_anim.gd`（数据 / 碎图绑定 / 状态帧数 / 装扮 / 循环与单次 / 缓存共享），
   过 `check_scripts.ps1` 再 `run_autopilot.ps1 -Scenario probe_pvz2_goo_anim`。

## 6. 人工验证方法（画面类，机器只能证明「数据对」）

1. 开游戏 → 模组页面打开「PVZ2」→ 进任意关卡。
2. 临时把 `mods_builtin/pvz2/goopeashooter/goopeashooter_anim.tscn` 拖到场上某个 `Node2D` 下：
   应看到**不带草帽**的毒液豌豆在待机（紫色毒液顺着花茎往下滴）。
3. `attack` 段是「仰头 → 甩头喷毒液」，`plantfood` 段会甩出一颗巨大的紫色毒液球（球会飞出画布右侧，正常）。
4. 关注三点：比例（`.tscn` 目前默认 `scale = 1`，当植物用时按本体尺寸缩）、
   站位（画布 390×390 以中心为原点）、图层（不该压住血条 / 卡片冷却遮罩）。
