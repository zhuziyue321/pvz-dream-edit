## 目标

加一个「紫卡直接种植」模组：紫卡（升级植物）**不必先种基座植物**，可以直接种在空地上，
代价是那一格多付**基座植物的阳光 + 50**（惩罚阳光可调）。

## 步骤

1. 摸清紫卡判定的落点：判据在 `ResourcePlantCondition.judge_is_can_plant()` /
   `judge_purple_card_can_plant()` 两个**方法**里（`get_preplant_purple()` 找基座），
   玉米加农炮是「特殊紫卡」，判据在 `judge_special_plants_condition()` 另一支。
2. 拿到「当前手上的卡」与「扣钱口径」：`ConstEventName.HAND_CARD_TAKE/RELEASE` 带卡片发出来；
   扣钱是 `CardSlotBattle.card_use_end()` 照 `card.sun_cost` 扣的。
3. 注册两处：`ModIds.PURPLE_DIRECT_PLANT` → `src/mods/mod_manager.gd` 的 `MOD_SCRIPT_PATHS` 加一行
   （**不用手写版本号**：同步按安装源内容指纹判定）。
4. 本体加一个通用口子 `CharacterRegistry.set_runtime_plant_condition()` /
   `clear_runtime_plant_condition()`（与 `register_runtime_zombie()` 同思路），
   `get_plant_info(..., PlantConditionResource)` 运行时覆盖优先。
5. `mods_builtin/purple_direct_plant/` 四件：入口 `purple_direct_plant_mod.gd` +
   规则文件 `purple_direct_plant_rule.gd` + 两份条件资源
   （`condition_purple_direct.gd` / `condition_purple_direct_cob_cannon.gd`）。
6. 文档同步：`mods_builtin/README.md` 加一行；[模组机制.md](../参考存档/模组机制.md) §二文件表 +
   §五第 9 条 + §六新增 6.5 小节。
7. 跑 `test/check_scripts.ps1`：PASS（real compile errors = 0）。

## 关键决策与理由

- **改判定 = 整份换条件资源，不是改字段**：能不能种写在**方法**里，字段改不动；
  所以才在本体加 `set_runtime_plant_condition()` —— 只加通用口子（本体不认识模组），
  换上去的是模组自己造的新实例（条件资源是共享的，多种植物共用同一份 `.tres`，不能改原对象）。
- **价格跟着鼠标走**："种在基座上 / 没种在基座上"只有判定时（鼠标进格子）才知道，
  于是 `judge_is_can_plant()` 顺手把手上那张卡的 `sun_cost` 改成"这一格种下去的价"，
  卡面立刻显示，点下去扣的就是它；种完本体那次 `update_card_purple_sun_cost()` 会刷回标准价。
- **规则单独一个文件**：入口与两个条件资源都要用它，互相 `preload` 会成环
  （`glove_settings.gd` / `hammer_settings.gd` 是同一个套路）。
- **只改出战卡槽里的卡**：传送带上的卡 `sun_cost` 恒为 0、不花阳光，标价反而误导，也不判阳光够不够。
- **玉米加农炮单独一份**：它走 `judge_special_plants_condition()`；没有两株玉米投手时要求
  **后轮两格都空着**（加农炮自己会占住后轮那一格，见 `Plant048CobCannon.ready_norm()`）。

## 踩坑

1. 仓库里 `src/mods/` 只剩 `mod_manager.gd`，模组现役源码在 `mods_builtin/`（运行时真身是
   `user://mods/`）—— 读文档里的旧路径会读到不存在的目录，以 `mods_builtin/` 为准。
2. 编译门禁**能**覆盖 `mods_builtin/` 下新加的模组脚本（scenarios 那一阶段会真的装载模组），
   但报错信息是 `Could not preload resource script "user://mods/..."` + `Parse error`，
   「Failed to load script」才是根因，别被第一条误导去查同步逻辑。
3. 紫卡要冒险 3-4 之后才在商店上架，**靠手点进关卡实测几乎走不到那一步**；
   想自动回归就写 `test/scenarios/probe_*.gd`（本次用户选择免验证，探针没跑，已删除）。

## 给后来者的最简路径

1. 注册两处：`ModIds` 加 id → `MOD_SCRIPT_PATHS` 加一行（**不用改版本号**）。
2. 要改本体的**判定方法**：先找本体现成的「运行期覆盖表」（`register_runtime_zombie()` 那套）照抄一个，
   再让模组自己造资源换上去；本体里不许出现模组的名字。
3. 模组内部跨文件一律 `const X := preload("xxx.gd")`，两边都要读的东西抽第三个文件（防 `preload` 成环）。
4. 设置走 `ModManager.get/set_mod_value(ModIds.XXX, key, default)` + `ConsoleEntry.create_slider(...).bind()`。

## 人工验证方法（未开游戏，验证时按此走）

1. 主菜单 → 选项 → 控制台 →「模组」→ 开「紫卡直接种植」（右侧详情应有规则说明与「惩罚阳光」滑条）。
2. 进一个**卡槽能带紫卡**的关卡（紫卡要商店买过；没有就先挑机枪射手 / 玉米加农炮）。
3. 空地上：紫卡卡片应当**点得亮**（原版没有基座时是灰的），指到空地上卡面价格变成
   「紫卡原价 + 基座阳光 + 50」；阳光不够时不给种（蜂鸣 + 无虚影）。
4. 种下去：紫卡直接出现在空地上，阳光按卡面那个数扣（不是原价）。
5. 指回基座植物上：卡面价格回到标准价，种上去行为与原版完全一致（基座植物消失、紫卡上位）。
6. 玉米加农炮：没有两株玉米投手时，后轮两格空着就能直接种加农炮（它自己占住后轮那一格）。
7. 关掉模组：紫卡回到「必须先种基座」的原版行为。
