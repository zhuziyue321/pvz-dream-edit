# 2026-10-04 · 其它 · 迷你游戏 06「隐形战争」的僵尸隐形设定从关卡数据搬进关卡脚本

> **任务类型**：其它
> **推荐度**：**推荐**（下次「只有一关要用的角色设定要从本体搬出去」照这个走）
> **耗时与成本**：约 1 轮；带窗口跑探针 `probe_invisi_ghoul`（22 断言全过，含 1-1 对照组）
> **验证方式**：打开游戏实测（带窗口探针，`[INVISIGHOUL] result=PASS failed=0`）
> **补充自**：[2026-10-04_实现隐形战争.md](2026-10-04_实现隐形战争.md)（那次把开关加在了 `ResourceLevelData` 上，这次搬出）

## 目标

`zombie_manager.gd` 里搜不到 `is_invisible_zombie`：隐形不再是本体上的关卡开关，
而是「僵尸初始化参数里的一关专属项」，由 `minigame_06_invisi_ghoul.gd` 自己下发（§1-8）；
视觉表现（本体 + 影子 alpha=0、冰冻 / 黄油现形、可被攻击）保持原样。

## 步骤

1. 先定位本体侵入点：`ResourceLevelData.is_invisible_zombie` → `ZombieManager.create_norm_zombie`
   → `zombie_init_para[E_ZInitAttr.IsInvisible]`。全仓库只有**一处**读，是最轻的那一处。
2. `ResourceLevelData` 删掉 `is_invisible_zombie` 字段，新增**通用**钩子
   `get_zombie_init_para_extra() -> Dictionary`（返回 `E_ZInitAttr → 值` 的表，基类返回空表）。
3. `ZombieManager.create_norm_zombie` 里换成一行
   `zombie_init_para.merge(game_para.get_zombie_init_para_extra(), true)` —— 本体只负责「并表」，
   不认识任何具体玩法。
4. `minigame_06_invisi_ghoul.gd` 覆写钩子返回 `{ Zombie000Base.E_ZInitAttr.IsInvisible: true }`，
   删掉 `_init()` 里的 `is_invisible_zombie = true`，头文件注释的链路同步改。
5. 把注释里的玩法名去掉：`E_ZInitAttr.IsInvisible` 与 `Character000Base.is_invisible` 改成
   「通用外观项」口径 —— 枚举本身是通用的，只是注释里挂着「隐形战争」。
6. 探针 `probe_invisi_ghoul.gd`：① 改读 `para.get_zombie_init_para_extra()`；
   补一条「可被攻击（受击掉血）」断言，把验收里的「可被攻击」也盖住。
7. 顺手把新钩子登记进 [D-07](../参考存档/规范细则存档.md#d-07-关卡脚本-vs-游戏本体一次性机制的落位) 的
   「关卡脚本里能写什么」清单。

## 关键决策与理由

- **走「初始化参数通用项」，不走「新增显示组件」** —— 渲染本来就在组件里
  （`BodyCharacter.set_invisible()` 走 `E_ChangeColors` 合成，`Character000Base.update_invisible_show()`
  只做转发），缺的只是「谁把开关喂进来」；新建组件要给 200+ 个角色场景挂节点，代价远超收益。
  任务给的两条路线里选了最轻的那条。
- **钩子而不是导出一个 `Dictionary` 字段** —— 覆写方法是仓库里既有的「关卡脚本可覆写」套路
  （`init_level_items()` / `should_run_tutorial()` / `get_tutorial_data()`），类型写得清、注释挂得上；
  导出一个 untyped Dictionary 只会让关卡作者猜键名。
- **`merge(..., true)` 让关卡覆盖出怪方** —— 关卡显式写的值应当赢，同时不覆盖其它键。
- **注释里的玩法名一起清掉** —— 自检口径是「`src/` 下搜玩法名」，
  `src/managers`、`entities` 里出现「隐形战争」字样同样算机制漏进本体。

## 踩坑

1. 第一次跑探针撞上 `Cannot find member "Weight" in base "ConstLevelData.E_PotMode"` →
   连带半个项目 `Failed to compile depended scripts`（`ResourceLevelData` 直接解析不出来）。
   → **原因**：疑似另一个 agent 正在并行删 `E_PotMode.Weight`（`pcm_pot_util.gd` 的注释已指向一份
   还没落盘的 10-05 记录），中途状态不一致；几分钟后 `level_data.gd` 自己补齐了。
   → **正解**：看到一片 `Failed to compile depended scripts` 先**从 stderr 最上面那条**判断是不是自己改的；
   不是就等并行改动落地再重跑，不要去改别人的文件（所有权见 [Agent协作协议.md](../Agent协作协议.md)）。
2. `run_autopilot.ps1` 报 `godot.log 正由另一进程使用` → 上一次 Godot 还没退干净 / 别人在跑。
   → **正解**：`Start-Sleep -Seconds 20` 后重跑，不要手工删 `%TEMP%\pvz_autopilot`。

## 给后来者的最简路径

1. 本体里全局搜玩法名 / 关卡字段名，确认只有一处读（多处读就先想清楚要不要一起搬）。
2. 在本体加一个**通用**钩子（基类空实现 / 返回空表），把「值是什么」的决定权交给关卡脚本；
   本体侧只留一行「并表 / 转发」，并把注释里的玩法名清掉。
3. 关卡脚本覆写钩子，删掉原来的字段赋值与头文件注释里的旧链路。
4. 探针改读新钩子，保留一个默认关卡做对照组；验收里写了「可被攻击 / 可通关」就补对应断言，
   别只靠肉眼。
