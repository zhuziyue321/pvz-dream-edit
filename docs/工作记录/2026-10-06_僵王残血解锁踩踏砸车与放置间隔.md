# 2026-10-06 · 其它 · 僵王残血解锁：低于 50% 才踩踏 / 砸车，同时放置间隔 6s→4s

> **任务类型**：其它
> **推荐度**：**推荐**（给 boss 技能加血量门槛时照这个走：先找现成的同类门槛 → 阈值导出 + 公共判定 → 无头探针逐档改血量断言）
> **耗时与成本**：约 1 轮对话；3 个无头探针全 PASS（0 失败），**未开窗口**
> **验证方式**：免验证（纯数值门槛、无新资源无新动画）+ 无头探针 `probe_zomboss_low_hp_skills` /
> `probe_zomboss_spawn_interval` / `probe_zomboss_bungee_hp` 全过；观感（残血后出招节奏）需人工开窗口看一眼
> **补充自**：无

## 目标

用户一句话：「僵尸博士血量低于 50% 后开始使用踩踏，砸车，同时放僵尸频率提升到 4s 一次」。
拆成两条可判定：① 剩余血量 < 50% 前，踩踏 / 砸车**不进入**技能随机池；② 剩余血量 < 50% 后，
放置僵尸的批内间隔从 6s 变 4s。

## 步骤

1. **先找现成的同类门槛** —— grep `can_start` 发现 `ZB001DoctorSkillBungee` 已经有
   `bungee_hp_ratio = 0.8` + `_is_low_hp()` 的写法（还有现成探针 `probe_zomboss_bungee_hp`），
   说明「血量门槛 = 技能效果组件自带的阈值导出」，**不要另起一套**。
2. `ZB001DoctorSkillBase` 新增公共判定 `is_hp_below_ratio(ratio)`（owner 是博士、血量组件有效、
   `max_hp > 0` 三道守卫都在里面），把蹦极的私有 `_is_low_hp()` 换成它，三处共用同一口径。
3. `StompSkill` 加 `stomp_hp_ratio = 0.5`，`can_start()` 改成
   `is_hp_below_ratio(stomp_hp_ratio) and not _get_candidates().is_empty()`（踩踏本来就要求区域内有植物）。
4. `ThrowRVSkill` 加 `throw_rv_hp_ratio = 0.5`，`can_start()` 直接返回血量判定（砸车允许砸空，无目标要求）。
5. `ZB001DoctorStateSpawn.spawn_low_hp_ratio` 由 `0.47` 改 `0.5`（间隔 6s / 4s 两档本来就有，只调阈值）。
6. 三个组件的 `get_configuration_error()` 各补一条阈值区间校验（0~1、有限数）。
7. 新探针 `test/scenarios/probe_zomboss_low_hp_skills.gd`（照 `probe_zomboss_bungee_hp` 的结构）：
   全场摆花盆 → 逐档改 `hp_component.curr_hp` 断言 `can_start()`：满血 / 恰好 50% 不开，
   跌破 50% 与 25% 开，回满血再关。
8. 同步 `probe_zomboss_spawn_interval` 的 `LOW_RATIO` 0.47→0.5，同步 [特殊关卡.md](../参考存档/特殊关卡.md)。

## 关键决策与理由

- **门槛写在效果组件、不写在状态里** —— 状态层的 `can_be_selected()` 只是转发 `effect_component.can_start()`，
  蹦极的先例也在组件里；写在状态里会和「状态只组织流程、数据归组件」这条主线打架。
- **阈值各自导出（0.5 / 0.5 / 0.8）而不是全局一个** —— 蹦极已经是「每技能一个阈值」的口径，
  而用户这次只点名踩踏 / 砸车 / 放置间隔；统一成一个全局值会顺手改掉蹦极的 80%，属于没被点名的改动。
- ~~**第一版把 `low_hp_ratio` 放到了 `ZB001DoctorStateMachine 上，让三个状态共用**~~ → **放弃原因**：
  与蹦极现有的「组件自带阈值」写法分叉，且状态机不持有血量语义；发现蹦极先例后回退重做。
  （弯路成本：3 次编辑 + 3 次回退，先 grep `can_start` 就能省掉。）

## 踩坑

1. **踩踏光看血量不够，还要区域内有活植物** —— `can_start()` 里 `_get_candidates()` 默认
   `require_plant = true`，探针不摆植物的话「跌破 50% 应该可用」会假阴性。
   → **正解**：探针里先 `cell.create_plant(P034FlowerPot)` 摆满（本关 5×9，摆出 25 个即可），
   再断言「跌破阈值后可用」——这样能证明假阴性是血量导致的、不是没目标。
2. **`roundi(max_hp * 0.5)` 正好落在阈值上** —— 判定是严格 `<`，所以「恰好 50%」必须断言**不可用**。
   探针里三条边界（满血 / 恰好阈值 / 阈值 −1）缺一条就测不出差一错误。

## 给后来者的最简路径

1. 给 boss 技能加任何「条件门槛」前，先 `grep -n "func can_start" src/entities/character/zombie_boss/` ——
   现有技能（蹦极 = 血量、踩踏 = 有植物）就是模板，**照它的落位加**，别新造一套。
2. 阈值做成 `@export_range(0.0, 1.0, 0.01)`，判定走 `is_hp_below_ratio()`，再补一条 `get_configuration_error()` 校验。
3. 探针照 `test/scenarios/probe_zomboss_bungee_hp.gd` 抄：进关 → 等 `get_living_bosses()` →
   摆目标 → 逐档改 `hp_component.curr_hp` 断言 `can_start()` → `a.quit_game()`。
4. 跑：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario <探针名>`。
