
# 2026-10-06 · 其它 · 僵尸迷阵的关卡进度条换成「配对次数 / 75」

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话；无头 + 带窗口各跑一次 `probe_beghouled`
> **验证方式**：打开游戏实测（带窗口跑探针）+ 新增断言全过
> **补充自**：[2026-10-06_关卡进度条控制器与数据源.md](2026-10-06_关卡进度条控制器与数据源.md)（照它 §「最简路径」第 1 条做的）

## 目标

迷你游戏第 5 关「僵尸迷阵」原本把关卡进度条**整条关掉**（`set_enabled(false)`，因为原版没有波次旗帜）。
改成：**进度条显示配对次数 / 75**，不画旗帜。

判据：进关开战后进度条可见且 0%；消除一组后进度 = `match_num / 75 × 100`；通关后进度条自己收起。

## 步骤

1. 读 [关卡进度条.md](../参考存档/关卡进度条.md) 确认口子（关卡脚本 `create_progress_provider()` 返回数据源实例即可）。
2. 新建 `src/levels/script/mini_game/beghouled/beghouled_progress_provider.gd`（`extends LevelProgressProvider`），
   与三消其它代码同侧（硬约束 §1-8）：实现 `get_progress()` / `is_bar_visible()` / `get_flag_num()`。
3. 关卡脚本 `minigame_05_beghouled.gd`：加 `var progress_provider := BeghouledProgressProvider.new()`，
   `create_progress_provider()` 返回它；`_init_beghouled()` 里建好管理器后 `progress_provider.bind_manager(beghouled)`。
4. 删掉 `beghouled_manager._hide_wave_progress_bar()`（不再整条关掉；`set_enabled()` 只做「没有对应口径」时的总闸）。
5. 探针补断言（`probe_beghouled` STEP2.5 / STEP3 / STEP6）+ 同步文档（[关卡进度条.md](../参考存档/关卡进度条.md) §6、[特殊关卡.md](../参考存档/特殊关卡.md) 僵尸迷阵段）。

## 关键决策与理由

- **数据源持有三消管理器引用，而不是反过来找** —— 管理器建得比数据源晚（数据源在
  `level_progress_controller.setup()` 时就被挑中，管理器要等关卡初始化回调），
  所以由关卡脚本建好后 `bind_manager()` 补一次；每帧读 `match_num`，不做事件订阅。
- **`is_bar_visible()` 加「玩法进行中」判据**（`is_running` 且 `main_game_progress == MAIN_GAME`）——
  开战前（展示僵尸 / 铺盘）与通关结算后都不该留一条 0% 的孤儿进度条，口径同 `ZombossProgressProvider`。
- **不画旗帜**（`get_flag_num() = 0`）—— 本关原版是无限波，`max_wave = 100` 那串旗帜没有意义。

## 踩坑

1. **新建脚本的 `class_name` 在探针里报 "Could not find type … in the current scope"** —— 没开编辑器时新脚本不在
   `.godot/global_script_class_cache.cfg` 里，无头跑直接 Parse Error（而且探针会空转到看门狗超时，stdout 只看得到「超时」）。
   → **正解**：先跑一次 `"<Godot>.exe" --headless --path <项目> --import` 重建缓存，再跑探针。
2. **本仓库有 agent 并行改同一批文件**（本次改到一半，`const_beghouled` / `beghouled_ui` / `probe_beghouled` 被另一处
   「死局提示」改动更新过）。→ **正解**：改前重新 `read_file`（不要用上一轮的缓存内容），改完再看一眼确认自己的行还在。

## 给后来者的最简路径

1. 新建 `extends LevelProgressProvider` 的数据源（放在该玩法自己的目录），实现 `get_progress()` / `is_bar_visible()`。
2. 关卡脚本里 `create_progress_provider()` 返回它的实例；玩法管理器建得晚就补一个 `bind_manager()` 之类的绑定。
3. 先 `--import` 重建类缓存，再 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_beghouled`。
