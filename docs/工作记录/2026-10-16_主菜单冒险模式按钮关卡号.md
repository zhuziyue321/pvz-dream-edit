## 目标

主菜单的冒险模式木牌按进度换两张贴图：通关 1-1 **前**用 `SelectorScreen_StartAdventure_Button1`
（「开始冒险模式」），通关 1-1 **后**用 `SelectorScreen_Adventure_button`（「冒险模式」），
并在木牌上那行「关卡 __」里填当前关卡（几杠几，如 `1-2`）。
后续追加需求：两个数字各自再挪一点（第一个数左 2px，第二个数左 2px、下 2px）。

## 步骤

1. 全仓搜两张贴图名 —— `SelectorScreen_Adventure_button` 只在 `pak/reanim/` 躺着、**没有任何代码引用**，
   属于「有素材没接戏」，所以是纯新增功能，不用改别人的逻辑。
2. **先量贴图再写代码**（省掉后面来回试坐标）：用 PowerShell + `System.Drawing` 把木牌上那行横幅
   打成 ASCII 亮度图，读出「关卡」两个字、木牌底色、以及短横占位的位置，
   再用同样的方式读按钮节点的 `offset_*`（331×146）换算贴图 → 按钮本地的缩放比。
3. 写代码：`ConstUnlockLevel` 加门槛常量 + `is_adventure_started()` / `get_adventure_button_level()`，
   `start_menu_root.gd` 加 `_apply_adventure_button_state()` 并挂进 `_update_mode_lock_state()`
   （这样 `_ready()`、切用户 `refresh_for_current_user()`、探针三条路径都自动覆盖）。
4. 场景侧在 `BG_Right/Menu/Button1/LevelText` 下挂**两个** Label（大关号 / 小关号），
   短横直接用贴图自带的（原版也这么干，见 `pak/images/SelectorScreen_LevelNumbers.png`）。
5. **带窗口截图核对**：临时写一个 `test/scenarios/_tmp_*.gd` 造进度、截图，把按钮裁出来放大比对，
   按实测像素调字号 / 两个数字的位置 / 颜色，核对完删掉临时脚本与截图。
6. 把这套判定补进 `probe_start_menu_unlock.gd`（STEP6 / STEP7），跑无头确认全绿。
7. 文档：`docs/参考存档/选关界面与解锁.md` 补一节 + 常量表补一行。

## 关键决策与理由

- **换贴图不换节点**：两块木牌 331×146 / 329×143，尺寸几乎一样，点击遮罩继续用
  「开始冒险模式」那张 `SelectorScreen_StartAdventure_Button1_Mask.png`，不另做美术。
- **贴图自带的短横就是分隔符，不自己画连字符**（第二轮改的口径）：
  第一轮为了压住贴图里那条横线，塞了一块同底色的 ColorRect 再叠一个整串 `Label("1-2")`；
  但那样两个数字捆在一个 Label 里，**没法各自挪位置**。改成「两个数字各挂一个 Label、
  横线用贴图里的」，既贴原版口径，又拿到了独立的 x/y。
- **区分两个数字的左/右边界**：大关号右对齐（贴住短横左边）、小关号左对齐（往右长，
  这样 `2-10` 的 `10` 不会反压到短横上）；对齐方式带来的**字形边距（bearing）约 2px**，
  所以 rect 边界要比想要的墨迹边界多留 2px，这个数字是量出来的、不是猜的。
- **Label 的最小高度会顶掉 `offset_bottom`**：`font_size = 24` 时 Label 最小高约 29px，
  写 `offset_bottom = 22` 没用，实际高度还是 29；好在上边界是照写的，`offset_top ± 2` 能照样生效。
- **数字颜色抄贴图字色**（`#C8C9D9`）而不是纯白：木牌上刻的「关卡」就是这个色，
  纯白会显得像后期贴上去的。
- **全部通关后停在 5-10**：`get_current_adventure_level()` 是「已通关最大序号 + 1」，
  通关 5-10 后会算出 51 = 「6-1」这种不存在的关卡，所以显示值夹到 `ADVENTURE_FINAL_ADVENTURE_LEVEL`。
- **临时探针用完即删**：`test/scenarios/` 是回归目录，只留长期探针；一次性的取证脚本不留。

## 踩坑

1. **PowerShell 里 `$x - 1` 报「Object[] 不包含 op_Subtraction」**（在 `$runs.Add(($start, $x - 1))`
   这种写法里）→ 猜是临时脚本被按 ANSI 解析出的怪毛病。**正解**：别跟它较劲，
   改成「只打印 ASCII 亮度图、自己用眼睛读坐标」，量一次就够，省掉整段聚合脚本。
   （量像素的临时脚本一律写成独立 `.ps1` 文件跑，别塞在一条 `-Command` 里。）
2. **`New-Object System.Drawing.Bitmap(170*5, 45*5)` 会被当成数组参数** →
   必须 `New-Object System.Drawing.Bitmap -ArgumentList 170*5, 45*5`。
3. **Godot 的 Label 垂直居中 ≠ GDI+ 的居中**：同一字号，先按 GDI+ 合成图定的位置，
   在游戏里实测偏低约 3~5px（Godot 按 ascent/descent 居中，数字没有下伸部就偏下）。
   **正解**：GDI+ 只用来「挑字体 / 看风格」，最终位置一律以**带窗口截图的实测像素**为准，至少校一轮。
4. **木牌贴图被缩放 1.006 / 1.021 倍后，细特征会被滤镜糊淡**：贴图里那条 4px 高的短横
   在截图里只剩 `lum 100~150`（贴图里是 195~211），所以**别拿截图的亮度阈值去量短横的位置** ——
   量数字用截图的墨迹、量短横/细线用贴图原图，两者坐标系换算一次即可。
5. **`font_size` + 同色 `outline_size` 会糊**：一开始想用 `outline_size = 2` 加粗，结果数字发虚。
   最后是 `font_size = 24` + `outline_size = 1`；再大就不能靠描边，得换更粗的字重。
6. **`LabelSettings` 只写 `font_color` 不够**：留给 `outline_size` 的默认值会跟主题串味，
   要么显式写死，要么接受主题的描边。

## 给后来者的最简路径

1. 目标贴图上要叠动态文字 → **先量像素**：`System.Drawing` 读尺寸 + 打 ASCII 亮度图，
   一次拿到「字号 ≈ 字高、色块范围、可用宽度」三件事，别在 Godot 里反复试。
2. **贴图里已有的分隔符（短横 / 下划线）优先直接用**，别自绘再把原图盖掉 ——
   盖掉那一步会把「每个元素一个节点」的手感一起盖没（这次就是第一轮盖了、第二轮又拆掉重来）。
3. 需要逐个元素微调位置 → 一个元素一个 Label，配 `horizontal_alignment` 定住贴边的那一侧；
   注意字形边距（约 2px）与 `Label` 最小高度会顶掉 `offset_bottom` 这两件事。
4. 写完先跑 `test/check_scripts.ps1`，再做**带窗口截图**核对落点，最后跑无头探针锁死行为。
5. 截图核对脚本：造进度 → `menu._update_mode_lock_state()` → `await RenderingServer.frame_post_draw`
   → `root.get_texture().get_image().save_png("res://tmp_xxx.png")`，核对完删脚本与图。
