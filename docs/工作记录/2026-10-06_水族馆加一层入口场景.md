# 2026-10-06 · 其它 · 给僵尸水族馆加一层入口场景（壳），能脱离主游戏单独跑

> **任务类型**：其它
> **推荐度**：**推荐**（下次「给某个挂 MainGameManager 的玩法单独开个可跑的场景」照这个走）
> **耗时与成本**：约 2 轮对话，跑了两个无头探针（关卡线 + 独立线，`failed=0`），**未开窗口**（画面需人工看一眼）
> **验证方式**：两条路径的玩法闭环都被无头探针覆盖，属「确定不会出问题」；**已给出人工验证方法**（见文末）
> **补充自**：[2026-10-04\_实现僵尸水族馆.md](2026-10-04_实现僵尸水族馆.md)（已在该文件末尾追加「补充 / 评价」，双向引用）

## 目标

给迷你游戏第 8 关「僵尸水族馆」单独拉出一个**入口场景**：

1. **方便编辑器里预览 / 测试** —— 选中场景按 F6 就能跑，不用先进第 8 关；
2. **第 8 关改指向这个新场景** —— 关卡脚本不再自己 `add_child` 玩法本体，由新场景负责挂，
   阳光仍走出战卡槽、存档与结算仍走关卡流程（玩家侧行为零变化）。

半路的方案（让用户二选一确认后才动手）：「完全独立主场景（自带一套阳光 UI + 进 MainScenes）」
还是「只抽一层壳 + 第 8 关改指过去」—— 用户选了后者，所以**没有**动 `MainSceneRegistry`。

## 步骤

1. **先摸清本体对主游戏的依赖**（在本体里搜 `_mg` / `_card_slot_battle`）：
   只有五处：① `position = camera_2d.position` ② `_hide_lawn_ui()` ③ 阳光进出 `CardSlotBattle.sun_value`
   ④ 产阳光要 `_mg.suns` 层 ⑤ 判负要 `save_manager` + 失败演出。
   → 结论：本体不用重写，只要让这五处在「没有主游戏」时各自降级。
2. **改本体为「可选主游戏」**（`zombiquarium_manager.gd`）：
   - `init_zombiquarium(main_game)` 允许传 `null`（`_mg == null` 即独立预览）；
   - 新增 `_local_sun` + `signal signal_sun_value_changed`：`get_sun_value/spend_sun` 在没有出战卡槽时走内部那份，
     产阳光也直接进账（没有 Suns 层，省掉「点了才算收到」）；
   - `_lose_game()` 无主游戏时不碰存档与红字，只播失败曲 + 发信号。
3. **新建壳** `src/zombiquarium/zombiquarium.gd`（`class_name ZombiquariumScene`）+ `.tscn`：
   根 Node2D → 子节点是 `zombiquarium_manager.tscn` 实例 + `StandaloneHud`（CanvasLayer layer 13，
   只放「阳光：N」与结论两行 Label）。对外只有三个口子：`init_zombiquarium(mg)` / `init_standalone()` /
   `signal_finished`，并把本体的两个信号转发出去。
4. **「有没有人初始化」怎么判**：`_ready()` 里 `standalone_hud.visible = false` 并连信号，然后
   `_auto_standalone.call_deferred()` —— 关卡脚本是 `add_child` 之后同一帧就 `init_zombiquarium(mg)`，
   延迟一拍再看 `_is_inited`，就是可靠的判定。
5. **登记 + 改调用方**：`SceneRegistry.ZOMBIQUARIUM_SCENE`（旧的 `ZOMBIQUARIUM` 本体条目保留，壳内部用路径引用）；
   `minigame_08_zombie_aquarium.gd` 改成实例化壳。
6. **探针**：
   - `probe_zombiquarium.gd`：原来 `mg.get_node("Zombiquarium")` 拿不到本体了（深了一层），
     改成 `get_node("ZombiquariumScene") → get_manager()`，并补一条「关卡模式不显示预览 HUD」；
   - 新增 `probe_zombiquarium_standalone.gd`：切到入口场景 → 断言自动进独立预览、自带 50 阳光、
     造脑子扣费且 HUD 跟上、全饿死判负。
7. **文档同步**：[特殊关卡.md](../参考存档/特殊关卡.md) 的落位表加一行「入口场景」+ 写清两种开法 + 两个探针。

## 关键决策与理由

- **壳只做「转发 + 预览 HUD」，不搬玩法** —— 本体要挂在 `MainGameManager` 下（位置按相机对齐、
  压在 `Suns` 层 4002 之下），这属性没法改；把「有没有主游戏」收在壳里，本体不用知道谁在开它，
  关卡那条线的行为与加壳前逐帧一致（探针原样跑通）。
- **阳光在两种模式下走不同的账本，但 UI 只有一份源头** —— 本体发 `signal_sun_value_changed`，
  谁要显示谁订阅；关卡模式继续用主游戏的阳光条，独立模式由壳的 HUD 接。这样本体不必问「我在哪」。
- **不改 `MainSceneRegistry`、不加菜单入口** —— 用户明确只要「一层壳 + 第 8 关改指过去」，
  主菜单 / 选关加入口是另一个决定（要的话单独做）。

## 踩坑

1. **新 `class_name` 不在全局类缓存里 → 无头跑直接 Parse Error** —— stderr 是
   `Could not find type "ZombiquariumScene" in the current scope`（探针与关卡脚本同一处炸），
   但 stdout 只显示「看门狗超时」，很容易误判成探针写挂了。
   → **原因**：`.godot/global_script_class_cache.cfg` 里没有这个新脚本（另一个 Godot 编辑器实例正在开项目，
   无头启动没重新扫描）。**正解**：在该 cache 里按字母序补一条 `{base/class/is_abstract/is_tool/language/path}`
   条目（或从编辑器里打开一次项目让它自己重写）；**新脚本 + 新 class_name 之后第一次跑无头必须先看 stderr**。
2. **`run_autopilot.ps1` 的 userdir 被别的 Godot 进程占着** —— `Remove-Item` 报 `godot.log 正由另一进程使用`
   （旧记录「多 agent 并行」那条坑的另一种表现，这次是别人的编辑器实例）。
   → **正解**：临时 `.ps1` 里把 `$env:APPDATA` 指到自己的临时 userdir、输出重定向到自己的 txt，跑完删文件。
3. ~~把 PowerShell 命令内联进 `execute_command`~~ → **不成立**：`$` 会被外层吞掉（`$o` 变成 `=o`）。
   → **正解**：写成 `.ps1` 文件再 `-File` 跑。
4. ~~新脚本手工补 `.uid`~~ → **不做**：`uid` 是 Godot 自定义格式，手写的可能不合规；
   缺着不影响加载（`.tscn` 的 `ext_resource` 只写 `path` 也能解析），交给编辑器下次开项目时自己补。

## 并行协作的补充（同一批文件被另一个 agent 同时改）

动手期间，`ZombiquariumManager` / `minigame_08` / `probe_zombiquarium.gd` 被并发伙伴改成了「**买东西走出战卡槽里的
两张自定义种子包**」（`try_buy_pet()` / `try_buy_trophy()` + `create_custom_seed_packet()` + 进度条换成阳光口径）。
两边正好互相补位：他们拿走主游戏里的按钮入口后，右下角那排按钮**只服务独立预览**（`_setup_ui()` 里
`visible = _mg == null`），独立模式下没有卡槽，这一排按钮就是唯一的买东西入口 —— 壳随之从「图方便」变成必需品。
合并后两个探针各跑一遍，`failed=0`。

→ **教训**：改「玩法本体」这类公共文件时，**动手前先读一遍、交付前再读一遍**（看看有没有被别人改过），
最后重跑探针 —— 两边各自跑通不代表合并后跑通。

## 给后来者的最简路径

1. 先在本体里搜 `_mg` / 主场景专属依赖，列出「没有它时会炸的几处」。
2. 本体加「主游戏可选」：外加一个私有的替代账本 + 一个变化信号，所有差别写在 `if _mg == null` 分支里，
   不要让调用方感知。
3. 新建 `<玩法>.tscn` 作壳：根 Node2D → `instance` 本体 + 一个预览 HUD（CanvasLayer，层号比本体 UI 大）。
4. `_ready()` 里 `_auto_standalone.call_deferred()`：没人来 init 就自己起；有外部 init 就自动让位。
5. 场景登记进 `SceneRegistry`，调用方（关卡脚本 / 探针）改指向壳。
6. 跑两个探针（关卡线 + 独立线）；**新 class_name 记得先看 stderr**（坑 1）。

## 人工验证方法（无头跑不出画面，这两条需要开窗口各看一眼）

1. **第 8 关**（原先那条线，应与加壳前完全一致）：主菜单 → 迷你游戏 → 第 8 关「僵尸水族馆」；
   整屏一口鱼缸、左上角阳光 50、2 只潜水僵尸在游；点鱼缸扣 5 阳光掉脑子；左上角**只显示一份**阳光
   （主游戏那条，不出现「阳光：N」的预览 HUD）；≥1000 点奖杯通关 / 全饿死判负。
2. **独立预览**：编辑器里选中 `res://src/zombiquarium/zombiquarium.tscn` → F6（Run Current Scene）；
   直接是一口鱼缸 + 左上角「独立预览：没有主游戏…」与「阳光：50」；点鱼缸 → 阳光变 45；
   放着不喂 → 僵尸发绿黄并饿死，全死后第一行文案变「失败：宠物僵尸全部饿死了」。
