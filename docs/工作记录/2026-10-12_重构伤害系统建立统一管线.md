# 2026-10-12 · 其它 · 重构伤害系统：建一条「发起 → 修饰器 → 结算」的统一管线

> **任务类型**：其它（底层系统重构）
> **推荐度**：**推荐**（下次要「为扩展预留口子」照这个走：先把管线和接口立起来，不改任何行为）
> **耗时与成本**：约 2 轮对话，未开游戏（门禁 PASS + 无头 `probe_critical_value` PASS failed=0）
> **验证方式**：免验证 + 已给出人工验证方法（见文末）
> **补充自**：无

---

## 1. 目标

用户要求「重构伤害系统，为扩展做准备，尽量统一逻辑」。改前现状（摸底结论）：

- 结算只有 `HpComponent.Hp_loss(value, mode, drop, sfx, drop2)` 一个，**但它是被各语义入口直接调的**，没有中间层；
- 伤害类型 `BulletRegistry.AttackMode` 挂在**子弹注册表**里，可锤子 / 爆炸 / 啃食 / 残血流失都在用 —— 名不副实；
- **没有修饰层**：想做免疫 / 反伤 / 加成没有落点，只能在每个发起处各自乘；
- **没有伤害事件**：联机模组只能直接赋值 `curr_hp` 再补一次 `Hp_loss_death()`（该文件自己的注释就在吐槽）。

目标定成：立一条**所有伤害都必须经过**的管线，顺带留好修饰器与事件两个扩展点，**行为一个字节都不变**。

## 2. 步骤（按顺序做，每步都单独过门禁）

1. **摸底**：先用只读探索把「谁在调 `Hp_loss`、伤害类型定义在哪、死亡流程谁触发」问清（这步省不掉，后面 17 处散点全靠这份清单）。
2. **建常量表** `src/core/consts/const_damage.gd`（`ConstDamage`）：`E_DamageMode`（怎么结算，值**与旧枚举一一对应**）+ `E_DamageCause`（谁打的，纯标记）+ `E_CancelReason`。
3. **建管线** `src/core/damage/`：`damage_info.gd`（描述）/ `damage_result.gd`（结果）/ `damage_modifier.gd`（修饰器基类）/ `damage_system.gd`（autoload 入口）。
4. **注册 autoload**（`project.godot`，放在 `EventBus` 之后）+ 事件名进 `ConstEventName.DAMAGE_APPLIED`。
5. **改结算层**：`HpComponent.Hp_loss(...)` → `hp_loss(info: DamageInfo)`，`Hp_loss_death` → `hp_loss_to_death`（**发起层**，内部走管线）。僵尸子类用「取出 `info.amount` / `info.mode` 赋给老变量名」的办法，**分配逻辑一行没改**。
6. **改角色基类**：新增 `apply_damage()`（入口）与 `take_damage()`（末端）；各语义入口改成分装 `DamageInfo`。
7. **清散点**：17 处直接调 `Hp_loss` 的地方逐个改成走管线（见 §4）。
8. **两处全局重命名**：`Hp_loss_death`→`hp_loss_to_death`；`BulletRegistry.AttackMode`→`ConstDamage.E_DamageMode`（13 处 + `test/` 3 处），旧枚举从 `BulletRegistry` 删除。
9. **补探针**：`test/scenarios/probe_critical_value.gd` 里的 3 处掉血改成走 `DamageSystem`（顺带回归管线本身）。
10. **验证**：门禁 PASS（108 scripts，0 error）+ 单探针 PASS failed=0。

## 3. 关键决策（为什么要这么切）

| 决策 | 理由 |
|---|---|
| 语义入口（`be_attacked_bullet` / `be_zombie_eat` / `be_bomb` …）**保留原签名** | 30+ 个老调用点一行都不用改；它们现在只负责**组装 DamageInfo**，派发统一走 `apply_damage()`。僵王在 `be_attacked_bullet` 里做受击窗口判断 —— 绕过它会丢掉那层保护，所以**不能**让发起方直接调 `DamageSystem` |
| 新增 `apply_damage()` / `take_damage()` 两个而不是一个 | 一个是「业务代码进来」、一个是「管线出去」。混成一个将来没法在角色侧重写结算行为 |
| `DamageSystem` **不加 `class_name`** | 加了之后 `DamageSystem.apply()` 会被当成调静态方法，编译直接失败（见 §5 坑 1） |
| `attack_value`（子弹 / 炸弹的数值字段）**不改名** | 它是 `.tscn` 里的 `@export`，改名会让存量场景全部失效 |
| 枚举值**一一对应**、不重排 | 存量 `.tscn` 存的是 int，值不变就**一个场景文件都不用改** |
| 修饰器**本体一个都不注册** | 改前改后行为完全一致；先把接口立好，将来要加免疫 / 反伤只写一个类 |
| 修饰器做成**组件**（`DamageModifierComponent`） | 裸修饰器的生命周期没人管，切关就泄漏；组件版跟着角色启用 / 禁用、`_exit_tree` 自动注销 |

## 4. 17 处散点的映射口径（最容易改错的地方）

旧签名是 5 个位置参数 `(value, mode, is_drop_on_death, trigger_sfx, is_drop_2)`，新写法是 5 个同名字段。**逐个核对默认值**，有两个坑：

- `hp_component.Hp_loss(v)`（只传伤害值）→ `trigger_sfx` 默认是 **true**；而 `_clear_armor_hp()` 我默认给了 false。气球僵尸（`zombie_balloon.gd`）就踩了这个，必须显式传 `true` 才与旧行为一致。
- 磁力菇吸铁器 vs 搭梯子：都是清一层防具血，但 `is_drop_2` 一个是 true 一个是 false → `zombie_base._clear_armor_hp()` 加了两个开关参数来对齐。

其余（`be_bomb` / `be_chomper_eat` / `be_rake_attack` / `be_squash` 的 `Penetration + 不掉落 + 不播音效`）收成 `_apply_penetration_damage()`，差别只在 `cause`。

## 5. 踩坑

1. **⭐ `class_name` 遮蔽 autoload 单例** —— `damage_system.gd` 写了 `class_name DamageSystem` 后，全局标识符被「类」占用，Godot 报 *Class "DamageSystem" hides an autoload singleton*，紧接着所有 `DamageSystem.apply(...)` 报 *Cannot call non-static function "apply()"*。**解法：autoload 脚本不写 `class_name`**（与 `EventBus.push_event()` 的写法一致）。已把这条写进该文件头部注释。
2. **重写函数签名不一致**：基类 `hp_loss(info) -> int`，僵尸子类原本**没有 return**（旧函数没标返回类型所以没报错），加返回类型后立刻报 *Not all code paths return a value*。给僵尸版补 `return curr_hp`。
3. **`get_all_hp()` 没标返回类型**，`var hp_before := ...` 报 *Cannot infer the type* → 显式写 `var hp_before: int`。
4. **新枚举成员漏定义**：`hp_loss_to_death()` 用了 `E_DamageCause.Death`，但枚举里只写到 `Script` → *Cannot find member "Death"*。
5. **全局替换会误伤自己刚写的注释**：批量替换 `BulletRegistry.AttackMode` 时，把它在**新文档注释**里的历史说明也替换了，句子变成「原先挂在 ConstDamage.E_DamageMode 名下」—— 语义反了。**批量替换后要回头读一遍被改的注释**。
6. **`test/` 不在门禁的可达集里**（与旧记录里 netplay 那个坑同源）：`check_scripts.ps1` 报的是主脚本 0 error，但 `test/scenarios/probe_critical_value.gd` 里的 3 处旧写法是**单独一节**报出来的，要一起改。

## 6. 验证

- 编译门禁：`real compile errors = 0`，108 scripts。
- 无头探针 `probe_critical_value`：PASS failed=0（它正好用 `DamageSystem.apply()` 掉血 → 覆盖「管线通不通」+ 掉血信号 + 死亡流程）。
- **想跑全量回归**：`powershell -ExecutionPolicy Bypass -File test/run_all_scenarios.ps1`（批量，耗时长，本次被手动取消，只跑了这一条）。

## 7. 人工验证方法（未开游戏，建议这么看）

1. 进冒险 1-1，种豌豆射手打普僵：伤害数字、掉手 / 掉头表现与改前一致。
2. 用樱桃炸弹 / 土豆雷炸一群僵尸：灰烬后消失，与改前一致。
3. 让僵尸啃坚果：啃食音效每 8 帧一次、坚果三段外观按血量切换。
4. 磁力菇吸铁桶僵尸的铁桶：铁器掉落 + 外观切换（这条走的是 `_clear_armor_hp`，最易漏）。
5. 锤僵尸模式：一锤子打死，本体血清空。
6. 5-10 僵王：僵王血条能掉，「抬头 / 低头」受击窗口照旧（僵王 `be_attacked_bullet` 的重写保留）。

## 8. 最简路径（下次照这个走）

> 立管线 = **「新目录四件套 + autoload + 角色基类两个函数」**，然后**按搜索清单逐个把散点改成走管线**。
> 三件事千万别做：① autoload 脚本写 `class_name`；② 为了「统一」把 `be_*` 语义入口砍掉（僵王的受击窗口会丢）；③ 改 `.tscn` `@export` 字段名（`attack_value`）。
> 枚举迁移一律**保持值不变**，这样 `.tscn` 不用动。
