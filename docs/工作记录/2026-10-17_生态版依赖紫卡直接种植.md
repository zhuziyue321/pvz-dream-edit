# 2026-10-17_生态版依赖紫卡直接种植

> **本次任务**：让生态版声明依赖「紫卡直接种植」（打开生态版 → 紫卡直种一并打开）
> **耗时 / 轮次**：约 2 轮对话，没开游戏（编译门禁 + 两个无头探针）
> **推荐度**：推荐（依赖机制 2026-10-17 刚建好，这是第一个用上它的现役模组）

## 目标

生态版改的阳光里唯一一张**紫卡**是吸金磁（50 → 150；它自己是紫卡、基座是磁力菇），
而紫卡直种的价 = 紫卡原价 + 基座植物的阳光 + 惩罚阳光，两项都照注册表**现读**
⇒ 两个模组是同一套经济口径。用框架现成的 `ModBase.get_mod_dependencies()` 把这条依赖声明出来，
不让"开着生态版却没开紫卡直种"这种半套经济存在。

## 最简路径（步骤）

1. 入口脚本 `mods_builtin/eco/eco_mod.gd` 重写 `get_mod_dependencies()` 返回 `[ModIds.PURPLE_DIRECT_PLANT]`，
   注释写清机理（哪张紫卡、价格公式在哪现读）；
2. 补开 / 环保护 / 页面渲染 / 存档持久化**框架全有**（`ModManager.set_mod_enabled()` 递归补开、
   `_ensure_dependencies_enabled()` 启动与换用户时补齐、模组页面详情末尾的依赖块）——
   模组侧只写声明，不自己判 `is_mod_enabled(别的模组)`；
3. 两个探针同步修（**容易漏**）：
   - `probe_eco_mod.gd`：STEP2 开生态版会连带开紫卡直种（只补开、不连锁关）⇒ 开跑前记下它的开关，
     STEP6 照原样还原 —— 不然 `save_mods()` 会把紫卡直种 persist 成开着，带歪后面的探针；
   - `probe_mod_page.gd`：原断言「现役模组都没有声明依赖」会 FAIL ⇒ 改成
     「只有生态版声明依赖、且正是紫卡直种」，末尾再补一条真实声明的渲染核对；
4. 文档三处：`模组机制.md` §6.6 加依赖条目（含理由）、§6.5 加反向引用、`mods_builtin/README.md` 生态版行；
5. 编译门禁 + `probe_eco_mod` / `probe_mod_page` 两个无头探针。

## 弯路 / 踩坑（三段式）

- **试过**：只改入口脚本加一行声明就交付；
- **因为**：`probe_mod_page.gd` 里有一条反断言「现役模组都没有声明依赖」（依赖机制今天的探针写的，
  当时确实一个都没声明），不改它探针直接 FAIL；`probe_eco_mod.gd` 也会把紫卡直种的开关
  persist 成开着、带歪后续探针；
- **结论**：声明依赖 = 入口脚本一行 + 两个探针的状态卫生 / 断言同步改，别漏探针。

- **试过**：在生态版里自己判「紫卡直种开没开」来决定行为；
- **因为**：框架的依赖声明就是干这个的（递归补开 + 启动补齐 + 页面列出），自己再判一套是重复造轮子；
- **结论**：用 `get_mod_dependencies()`，模组代码里不出现对别的模组开关的判断。

## 推荐度与理由

推荐。机理上这两个模组确实耦合（吸金磁的新价喂紫卡直种公式），依赖声明把"该一起开"变成
框架行为，玩家在模组页面详情末尾也能看到依赖块与跳转按钮。后来者加依赖时记住口径：
**只补开、不连锁关** —— 关掉被依赖的模组不会连带关掉依赖者，玩家在依赖块里看得到"未启用"。
