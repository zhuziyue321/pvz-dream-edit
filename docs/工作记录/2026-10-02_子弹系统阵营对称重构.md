# 2026-10-02 · 重构 · 子弹系统阵营对称化（为植物僵尸铺路）

> **任务类型**：其它（重构）
> **推荐度**：**推荐**
> **耗时与成本**：约 1 轮；未开窗口游戏，跑了无头探针（2 个）
> **验证方式**：免验证 + 已给出人工验证方法（见「验证」一节）
> **补充自**：无

## 目标

让子弹系统不再写死「子弹属于植物方」，使**同一份子弹场景能被双方复用**，
这样将来实现植物僵尸（僵尸头顶带植物、向玩家植物开火）时不必为僵尸方复制一套子弹场景。

可判定：给 `init_bullet` 传 `BulletCamp = Zombie`，豌豆 / 卷心菜这类植物子弹的
`Area2DAttack` 层会自动切到僵尸方（layer8 / mask 植物真实框），且能命中植物。

## 步骤

1. 先摸清现状：`docs/参考存档/子弹说明.md` + `子弹与碰撞.md`，再用 code-explorer 全仓搜 `bullet_camp` / `collision_layer` / 索敌函数，
   列出所有「写死植物方」的点（8 处，见「关键决策」）。
2. 新增 `src/entities/bullet/bullet_camp_config.gd`（`BulletCampConfig`，全 static）：阵营 → 碰撞层 / 敌人层 / 敌人类型 / 索敌方向的集中映射。
3. `Bullet000Base` 加 `signal_bullet_camp_changed` + `set_bullet_camp()` + 可重写的 `apply_bullet_camp()`；
   `Bullet000NormBase` 重写它，把层写进 `Area2DAttack`。
4. `E_InitParasAttr` 加 `BulletCamp`；`get_bullet_paras()` 一并输出（火炬树桩升级靠它复制参数，漏了会把阵营退回植物方）。
5. `AttackComponentBulletBase.get_bullet_paras()` 用 `BulletCampConfig.get_camp_of_character(owner)` 自动填阵营。
6. 命中判定从「植物/僵尸双分支 + 同阵营 return」改成 `BulletCampConfig.is_enemy(bullet_camp, enemy)` 一次判定。
7. `DetectTargetStrategy.pick_enemy_for_track_bullet()` 加 `camp` 参数（原来对 `Plant000Base` 只 `pass`，植物永远选不中）。
8. `SpatterComponent` 按所属子弹阵营同步 `Area2DSpatter` 的层，方法改名 `spatter_all_area_enemy()`（旧名保留转发）。
9. 补 `BulletRegistry` 里缺失的保龄球 1001/1002/1003 登记（硬约束 4：类型映射走注册表）。
10. 写回归探针 `test/scenarios/probe_bullet_camp.gd`，锁死「同场景 / 两阵营 / 两组碰撞层 + 额外层不丢」。

## 关键决策与理由

- **阵营由发射方决定，不新增僵尸版场景** —— 因为植物僵尸的子弹与同名植物子弹完全同款，复制场景会让两套数值漂移。
- **碰撞层从「场景写死」改成「运行期按阵营计算」，但保留场景里的额外层** ——
  直线子弹要 layer1 World 判斜坡、保龄球要 layer7 Bowling 给撑杆跳检测；
  所以 `apply_camp_collision()` 先用 `~C_AllCampLayerBits` / `~C_AllCampMaskBits` 剥离出额外位再并回去，**一个 .tscn 都不用改**。
- **不改全局检测组件的检测层** —— 它是香蒲（植物方追踪）的开关来源，
  把 mask 从「只僵尸」放宽会让香蒲在场上只有植物时也开火。僵尸方追踪子弹留 TODO（真要做再补一个僵尸视角的全局检测组件）。
- **不动 `update_first_enemy()` 的 x 比较方向** —— 现在固定「x 更小优先」（植物视角）。
  改成按阵营反转是投手僵尸的正确行为，但会改现有玩法（投石车僵尸的目标选择），本次不做，只在索敌策略里留了 `is_nearer()`。
- **不合并三处 `get_first_be_hit_plant_in_cell`** —— 直线 / 抛物线 / `DetectTargetStrategy` 的优先级顺序不一致
  （Shell 优先 vs Norm 优先），`detect_target_strategy.gd` 顶部注释明确警告过，合了会改行为。

## 踩坑

1. **新建 `.gd` 后 Godot 认不到 class_name**（报 `Identifier "BulletCampConfig" not declared`）
   → 原因是没有 `.uid` 文件、缓存没刷新
   → **正解**：跑一次 `godot --headless --path <项目> --editor --quit` 让它导入；仓库惯例是每个 `.gd` 都带 `.uid`，手写补一个即可。
2. **`var is_sky_enemy := enemy is Zombie000Base and ...` 编译不过**（`Cannot infer the type`）
   → GDScript 推断不出 `and` 表达式的类型
   → **正解**：显式写 `var is_sky_enemy: bool = ...`。
3. **抛物线子弹 `init_bullet` 形参是类型化字典 `Dictionary[E_InitParasAttr, Variant]`**，直线/追踪基类却不是
   → 用字面量构造参数会在运行期报参数类型错误
   → **正解**：把 `Bullet000ParabolaBase.init_bullet` 的签名放宽成无类型 `Dictionary`，与基类一致。
4. **`bullet_paras[E_InitParasAttr.EnemyGloPos]` 下标取值**（缺键直接崩，违反 S-06）
   → **正解**：改 `bullet_paras.get(..., Vector2.ZERO)`。
5. **跑 `run_autopilot.ps1 -Scenario probe_plant` 实际跑的是 `probe_zomboss`**
   → 该 ps1 的 CLI 传参被覆盖（且 `probe_zomboss.gd` 自身有 parse 错误，是别人的在途文件）
   → **正解**：直接调 Godot：`godot --headless --path <项目> -- --scenario=res://test/scenarios/<名>.gd --autopilot-max-seconds=N`。

## 验证

- 全项目脚本编译：`godot --headless --path <项目> --quit` → 无 `SCRIPT ERROR` / `Parse Error`。
- 新探针 `probe_bullet_camp` → `[BULLETCAMP] result=PASS failed=0`（覆盖豌豆 / 篮球 / 保龄球三种场景 × 两阵营 + 纯函数）。
- 保龄球探针 `probe_bowling_redline` → `[BOWLINGSTRIPE] result=PASS failed=0`（回归：行 y 取值改走 `MainGameManager.get_row_base_global_y()`）。
- `probe_plant` 在**种植**这一步 FAIL（手持中但没种下），与本次改动无关（种植不经过子弹），未深究。

**人工验证方法**（开窗口进任意白天关）：
1. 种豌豆射手 → 豌豆应正常飞出、命中僵尸、僵尸掉血（植物方链路未回归）。
2. 种火炬树桩 + 豌豆射手 → 豌豆过桩变火豌豆，仍能打僵尸（验证 `get_bullet_paras()` 带出了阵营，升级后的子弹没退回植物方）。
3. 保龄球关（坚果保龄球）→ 保龄球换行、撞击僵尸正常（验证额外层 Bowling 没丢）。
4. 屋顶关 → 直线子弹撞斜坡破碎正常（验证额外层 World 没丢）。

## 给后来者的最简路径

1. 改阵营相关常量只动 `src/entities/bullet/bullet_camp_config.gd` 一处。
2. 新增子弹：**不要**在 `.tscn` 里手改 `Area2DAttack` 的层，阵营交给 `init_bullet`。
3. 要验证：`godot --headless --path <项目> -- --scenario=res://test/scenarios/probe_bullet_camp.gd --autopilot-max-seconds=60`。
4. 接着做植物僵尸时，先补一个僵尸视角的全局检测组件（否则僵尸的追踪子弹索不到植物），再按
   [子弹说明 §3](../参考存档/子弹说明.md) 给僵尸挂 `AttackComponentBulletBase` 系组件即可。
