
# 2026-10-09 · 其它 · 控制台去掉滚动条改成「入口页 + 每分组一页」

> **任务类型**：其它
> **推荐度**：**推荐**（下次改控制台 UI 照这个走）
> **耗时与成本**：约 1 轮对话 / 未开游戏 / 跑了无头探针
> **验证方式**：免验证 + 已给出人工验证方法（无头探针 `probe_console_registry` PASS + 编译门禁 PASS）
> **补充自**：[2026-10-08_控制台改成可扩展条目注册表.md](2026-10-08_控制台改成可扩展条目注册表.md)（顺带给它追加评价）

## 目标

控制台面板（`CanvasLayerConsole`）从「一个 `ScrollContainer` 里从上往下堆所有分组」改成**分页**：
每个分组独占一页，**整屏没有滚动条**；打开控制台先停在入口页，入口页上每个分组一个按钮，点进去才看到那一组的控件。

## 步骤

1. 先读 [控制台.md](../参考存档/控制台.md) ＋ `canvas_layer_control.gd` ＋ `control_canvas_layer.tscn`，
   确认现状是「`ScrollContainer` + 空 `VBoxContainer`（`OptionBG/ConsoleScroll/EntryList`），
   `build_console_panel()` 往里按分组塞小标题 + `GridContainer`」。
2. 场景：`ConsoleScroll` / `EntryList` 两节点换成普通 `Control`（`OptionBG/PageRoot`，anchors 全屏 + offsets 沿用原值）；
   顶部 `Label` 宽度加宽（-150 ~ 150），因为它现在要显示「控制台 / 自动 / 显示 / 调试 / 模组 / 联机」各种长度的标题。
3. 脚本：重写「造页面」部分 —— `_build_index_page()`（入口页：每分组一个按钮）+ `_build_category_page()`（控件网格 + 底部「返回」）+ `_add_page()`（入树 + 先藏）+ `show_page()`（切 `visible` + 换标题）。
   页面在 `build_console_panel()` 里**一次造齐**，翻页只切 visible，不重建 —— 这样隐藏页的 `_update_console_panel()` 依然能把值刷新。
4. 探针里给按钮统计加 `NAV_META` 过滤（见「踩坑」第 2 条）。
5. 跑 `test/run_autopilot.ps1 -Scenario probe_console_registry`（PASS）+ `test/check_scripts.ps1`（PASS）。
6. 同步 [控制台.md](../参考存档/控制台.md)：面板结构、场景节点名、探针的过滤口径、历史追加一行。

## 关键决策与理由

- **保留「入口页」而不是 TabContainer 的标签条** —— 需求是「在控制台入口加一个按钮进入这些页面」，
  标签条会把按钮藏成标签；而且后期分组可能变多（模组随时会加一组），竖排按钮比横向标签条更不容易挤。
- **页面一次造齐而不是翻页时才造** —— `find_children` 不看 visible，探针照旧能数到全部控件；
  也让 `_update_console_panel()` 的回写逻辑（原来那段一行没改）继续成立。
- **翻页按钮打 meta `NAV_META`** —— 面板需要向外界区分「条目渲染出来的 Button」与「面板自己造的翻页按钮」。

## 踩坑

1. **`_add_page()` 只把页面塞进数组，忘了 `page_root.add_child(page)`** → 探针基线 勾选框 / 滑条 / 按钮全为 0，
   「应比基线多 1」连报 3 条 FAIL。→ **原因**：页面没入树，`find_children` 自然一个都找不到。
   → **正解**：入树这件事收到 `_add_page()` 里做（一处保证），不要指望调用方记得 add_child。
2. **面板自己多出来的 Button 会污染探针的增量断言** —— 探针按「基线 → 增量」数 Button，
   而新增一个分组会同时多一个入口按钮，一次新增 Button 条目本应 +1、实际 +2，断言必 FAIL。
   → **正解**：翻页按钮统一 `set_meta(ConsoleLayerConsole.NAV_META, true)`，
   探针 `_count_controls()` 里跳过带这个 meta 的节点（数量跟着分组数变的东西不参与「条目带来的控件」统计）。
3. **别在 for 循环里直接把循环变量捕获进 lambda** —— 入口页五个按钮若共用同一个 `category_name`，
   会全部跳到同一页。这里把分组名当**函数参数**传进 `_connect_nav_to_category(button, category_name)`，
   每次调用都是新的一份，零风险。
4. **跑批脚本报「godot.log 正由另一进程使用」** —— 上一轮 Godot 进程还没退干净（`Remove-Item` 抢锁）。
   → **正解**：`Get-CimInstance Win32_Process -Filter "Name like 'Godot%'"` 确认进程已退出后再重跑，不必改脚本。

## 给后来者的最简路径

1. 改面板结构：动 `canvas_layer_control.gd` 的 `_build_index_page()` / `_build_category_page()` 两个函数就够了，
   页面容器是 `OptionBG/PageRoot`，切页用 `show_page(page)`，构建完默认回到入口页。
2. 加一个开关：仍然**只**在 `ConsoleBuiltinEntries` 或模组的 `register_console_entries()` 里登记一条
   `ConsoleEntry` —— 面板 / 场景 / `ConfigService` 都不要碰；登记到一个新分组会自动多一个入口按钮 + 一页。
3. 验证：改完跑 `-Scenario probe_console_registry`（秒级，无头）+ `check_scripts.ps1`；
   画面部分跑到这里为止，**布局观感需要人工看一眼**：进任意关卡 → 暂停 → 选项设置 → 控制台，
   应停在入口页、点分组进对应页、全程没有滚动条。
