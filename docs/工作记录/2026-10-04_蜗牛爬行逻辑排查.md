# 2026-10-04 · 排查调试 · 修掉蜗牛「爬到爬行范围边界就卡住反复转身」等四处逻辑缺陷

> **任务类型**：排查调试
> **推荐度**：**推荐**（下次改蜗牛 / 花园物件行为照这个走）
> **耗时与成本**：约 1 轮对话；跑无头探针 `probe_snail_chocolate`（画面需人工看一眼转身动画）
> **验证方式**：免验证 + 已给出人工验证方法（改动集中在数值与朝向，无头探针已覆盖掉头 / 计时两条判定）
> **补充自**：无

## 目标

修掉 `src/garden/stinky.gd` 里几个会真实卡死蜗牛的逻辑缺陷，并给每条补上能复现的回归断言。

## 步骤

1. 先跑既有探针 `probe_snail_chocolate`（无头）确认主干没坏：买断 → 出现 → 点醒 → 喂巧克力 → 捡钱全绿。
   → 说明问题不在「有没有蜗牛」，而在蜗牛自己的爬行循环里。
2. 逐行读 `_process` / `_move` / `_start_turn`，找出 5 处缺陷（见「关键决策与理由」）。
3. 改 `stinky.gd` 后，在探针里补 STEP7（边界掉头）与 STEP8（转身期间清醒计时照走）。
4. **反向验证**：把边界那两行改回旧写法再跑一次，确认 STEP7 报 NG（蜗牛停在 `x=670` 朝右不动），
   再改回来跑一遍全绿 —— 否则这条回归等于没写。

## 关键决策与理由

- **撞边界要强制掉头**（`if _is_at_x_edge(): wanted_direction = -direction`）
  —— 旧代码撞边界时传的还是原朝向，`_start_turn` 收到相同朝向就不翻面，
  于是「播 0.58s 转身动画 → 只爬一帧又被夹回边界 → 再播转身」无限循环。
- **清醒 / 加速计时挪到转身判断之前**
  —— 旧代码 `if is_sleep or _is_turning: return` 把倒计时和翻身绑在一起，蜗牛每转一次身就冻结一次清醒时间。
- **追钱加朝向死区 `DIRECTION_DEAD_ZONE`**
  —— `to_coin.x >= 0.0` 在钱的正下方会在 0 附近抖动，导致左右反复转身。
- **单步位移不许超过剩余距离**（`minf(speed * delta, to_coin.length())`）
  —— 免得在钱底下左右来回蹭。
- **`sleep()` 里清 `is_turn`**
  —— 状态机里转身只连回爬行、不连睡眠，睡着时还挂着转身动画会卡在转身态。
- **`_start_turn` 的 await 后加 `is_instance_valid(self)`**
  —— 等动画期间退出花园会释放节点，恢复协程后不该再去动 `body`。
- **朝向映射改成 `body.scale.x = float(-direction)`**（同日补修：往右爬却头朝左）
  —— 素材默认**朝左**（`stinky.tscn` 里 Antenna/头 x≈3.6、Tail/尾 x≈57.9），
  旧代码 `scale.x = float(direction)` 在向右爬时不翻面，于是「往右走朝左」。
  顺带把翻面抽成 `_apply_facing()`，`_ready()` 里也调一次，出生朝向才和 `direction` 一致。
- **`_ready()` 里给 `_idle_turn_cd` 一个随机初值**
  —— 初值 0 会让蜗牛一醒就在原地翻个身。

- **纵向漫游要放在分支外（常驻），追钱时只动横向**（同日再补修：加了漫游后还是不上下动）
  —— 第一版把纵向漫游写在「没钱闲逛」的 `else` 分支里，可花园里几乎总有钱，
  蜗牛一直走追钱分支：纵向被 `to_coin.normalized()` 拉到钱的投影 y（条带顶边 480）就钉住了，
  于是一路横线爬。现在追钱只改横向，纵向漫游常驻；
  拾取判定本来就只看横向对齐（`_try_pick_coin`），纵向漂着不影响收钱。
- **拾取距离 `PICK_COIN_DISTANCE` 30 → 12**
  —— 30px 时蜗牛还隔着一大段就把钱吸走，看着像隔空取物。
- **拾取改用真实横向距离 + 新增「够得着」高度 `REACH_UP_DISTANCE = 100`**（同日补修：站在最下面能收最上面的钱）
  —— 旧判定拿 `_get_coin_target_pos()`（把钱 clamp 进地面条带后的投影点）算距离，
  于是钱在多高都行、只要 x 对齐就算"爬到了"。现在只有落在地面往上 100px 以内的钱才算目标
  （最下一排植物落钱点约 y=390~420，地面顶边 y=480，故取 100），更高的既不去追也捡不到。

## 踩坑

1. **第一版 STEP7 测不出 bug**（旧写法也 PASS）
   → 原因：`_idle_turn_cd` 初值是 0，蜗牛第一帧就触发「随机掉头」，把边界卡死掩盖了
   → **正解**：探针里先把 `stinky._idle_turn_cd = 999.0` 顶住随机掉头，只留边界这一条翻转路径；
   同时把初值问题本身也修掉。
2. 写完回归**必须反向验一次**（改回旧代码看它是否 NG）
   → 否则「全绿」可能只是断言太松，等于没测。
3. **探针只在"场上没钱"时测纵向漫游，于是漏掉了真实场景**（第一版 STEP10 全绿但用户仍说不动）
   → 原因：花园里几乎总有钱，蜗牛绝大多数时间在追钱分支，纵向被钉在条带顶边
   → **正解**：漫游逻辑要放在分支外常驻；探针补 STEP12「追钱时也上下挪」。
4. **探针里直接改 `stinky.direction` 测不出朝向**（第一版 STEP9 全 OK 但其实是假绿）
   → 原因：朝向只在 `_start_turn()` 里翻，外部强设 `direction` 不会触发翻面
   → **正解**：靠「把钱放在左 / 右边」引导蜗牛自己转身，再断言 `body.scale.x` 的符号。

## 给后来者的最简路径

1. 跑一次 `powershell -ExecutionPolicy Bypass -File test\run_autopilot.ps1 -Scenario probe_snail_chocolate` 看基线。
2. 改 `src/garden/stinky.gd`；蜗牛的行为常量（速度 / 清醒时长 / 爬行范围）全在这个文件顶部，不动别的脚本。
3. 探针补断言 → 再**改回旧写法跑一遍确认会 NG** → 改回来跑一遍确认全绿。
4. 人工验证方法：进禅境花园，买蜗牛，点它一下叫醒，
   看它爬到最左 / 最右的地面尽头会不会掉头往回爬（旧版会原地抖着转身不动）。

## 补充 / 评价（2026-10-04，见 [2026-10-04\_花园掉钱落回植物附近.md](2026-10-04_花园掉钱落回植物附近.md)）

本条里「拾取改用真实横向距离 + 加够得着高度 `REACH_UP_DISTANCE`」这条**实现方式已被推翻**：

- 起因：花园里的钱改成落在产出它的植物旁边（不再飞到屏幕最下面），高处架子上的钱蜗牛够不着。
- 先试了本条的旧做法（`REACH_UP_DISTANCE = 120`），代价是上面两排的钱蜗牛直接不追不捡，
  用户当场问「蜗牛为什么不去捡高处的钱」。
- 现在的做法：**把 `move_range` 扩到整个花园**（蜗牛能爬上架子），
  够不着就统一按「钳进爬行范围后的落脚点与钱的距离 > `PICK_COIN_DISTANCE`」判定，
  拾取回到**真实二维距离**，不再需要「够得着高度」这个魔数。
- 本条其余结论（撞边界掉头、清醒计时不受转身冻结、追钱朝向死区、睡着清转身态、
  朝向映射 `scale.x = -direction`、纵向漫游常驻）**仍然有效**。
- 追钱倍率已从 2 提到 3，且爬行动画倍速接上了移动倍速（详见上面那条记录）。
