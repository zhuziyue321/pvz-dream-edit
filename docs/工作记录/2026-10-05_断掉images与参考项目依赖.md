# 2026-10-05 · 资源改名 · 断掉 images/ 与 PVZ-Godot-main/ 两个外部目录的依赖

> **任务类型**：资源改名
> **推荐度**：**推荐**（下次「清掉某个遗留 / 参考目录」照这个四条走：先找引用 → 迁引用物 → 再落 `.gdignore` + `.gitignore` → 最后才问删不删文件）
> **耗时与成本**：约 1 轮对话，未开游戏（本机 Godot 需手填路径，用户选择免验证）
> **验证方式**：免验证 + 已给出人工验证方法（改动只有 5 处贴图引用，均为同图换 path/uid）
> **补充自**：无（本次是第一次做这类清理；相关背景见 [2026-10-05_移植僵王动画资源.md](2026-10-05_移植僵王动画资源.md)，它解释了 PVZ-Godot-main 当初为什么进来）

## 目标

根目录下两个**不入库但会被 Godot 扫描**的目录彻底变成「可有可无」：`images/`（遗留素材）与 `PVZ-Godot-main/`（参考项目副本）。判定标准 —— 全仓库再无任何 `res://images/` / `res://PVZ-Godot-main` 运行期引用，删掉这两个目录后游戏照样能跑。

## 步骤

1. **先量清引用面，再动手**：全仓搜 `res://images/` 与 `res://PVZ-Godot-main`。
   - `res://images/` 的实际引用只有 **5 处**（3 张图：`Almanac.png` / `WateringCan.png` / `Store_FirstAidWallnutIcon.png`）—— `images/*.png.import` 里那 500 多条是 `.import` 自述的 `[deps] source_file`，随目录走，不算项目依赖，不用管。
   - `res://PVZ-Godot-main` 只有 **一处真实引用**：`tools/port_zomboss_animations.py` 里写死的参考动画目录；另外 `addons/todo_controller/config/config.tres` 有 **348 行** `res://PVZ-Godot-main/**.gd` 是插件扫描缓存，`src/` 里 3 处是**注释**（移植来源说明）。
2. **迁移 3 张图到 `assets/` 并改引用**（[项目规范 §1-5](../项目规范.md)：资源 `res://` 绝对路径）：
   - `WateringCan.png`、`Store_FirstAidWallnutIcon.png` 在 `assets/image/garden/`、`assets/image/store/` **已存在** → 直接把 5 处引用的 path+uid 换成 assets 那份（uid 从 assets 的 `.import` 读）。
   - `Almanac.png` 在 assets 里**没有** → 复制 png 到 `assets/image/main_game_item/`（与 `Taco.png` / `CarKeys.png` 同类的冒险掉落物），另写一份新 `.import`。
   - 改动文件：`src/menus/choose_level/adventure_choose_level.tscn`（2 行）、`src/store/goods_wall_nut_first_aid.tscn`（1 行）、`src/core/consts/const_adventure_reward.gd`（2 处 preload）。
3. **清掉参考项目的痕迹**：删 config.tres 里 348 行 PVZ 缓存，并把 `res://PVZ-Godot-main` 加进 `black_dirs` 防止下次扫描又被写回来；`tools/port_zomboss_animations.py` 的参考目录改为 `--ref <目录>` 可覆盖 + 目录不存在时打印「参考项目不随仓库发布」的提示，不再硬失败。
4. **让 Godot 彻底不认识这两个目录**：各放一个空 `.gdignore`；同时在 `.gitignore` 加 `/images/` 与 `/PVZ-Godot-main/`（这两个目录此前**未跟踪也未被忽略**，`git add .` 会把约 2700 个版权素材 / 第三方副本一次性提交）。
5. **文件删除权交给用户**：目录保留在本地由用户手动删 —— **先断依赖、后删文件**，删错了不影响已经改好的引用。

## 关键决策与理由

- **`.gdignore` 而不是直接删目录** —— Godot 见到 `.gdignore` 会整个跳过该目录：不扫描、不导入、也不会因为两个项目里同名资源的 uid 打架；目录还能留着给一次性移植脚本复用。删目录是**不可逆**且可能连 assets 备份素材一起没的动作，必须用户点头。
- **3 张图迁到 `assets/` 而不是让 images 入库** —— `assets/` 是仓库既定的素材根（[项目目录说明](../参考存档/项目目录说明.md)），且已在 `.gitignore` 里；`images/` 里的东西大多是版权素材，入库会出事。
- **`src/` 里 3 处 PVZ-Godot-main 注释保留** —— 那是「移植自参考项目」的来源注释，不是依赖；`AGENTS.md` 的查 wiki 规范也要求留来源。
- **Almanac 落 `main_game_item/`** —— 与它同列的 `Taco.png` / `CarKeys.png` 同为「冒险通关掉落物」，语义一致；`assets/image/Almanac/` 目录里放的是图鉴 UI 组件（CloseButton / IndexBack…），本体图不适合混进去。

## 踩坑

1. **统计"引用数"时被 `.import` 骗了一眼** —— 全仓搜 `res://images/` 返回 546 条，看着像大工程。
   → **原因**：`images/*.png.import` 自己的 `[deps] source_file="res://images/xxx.png"` 占掉 541 条。
   → **正解**：判定「有没有依赖」只看 **`.gd` / `.tscn` / `.tres`** 里的引用，`.import` 是 Godot 生成物，随目录一起删。
2. **迁移图片不能连 `.import` 一起原样复制** —— 复制过去会和源目录**撞 uid**，Godot 会因同一 uid 指两个路径报冲突。
   → **正解**：目标位置的 `.import` 里写一个**新的** uid，并把受影响的引用一起改掉。`.godot/imported/xxx.ctex` 的文件名不必算准，Godot 下次打开会重导并在 `.import` 里自己修正。
   → 顺手验证过命名算法：文件名后缀是 `md5(res://<完整路径>)` —— `md5("res://images/Almanac.png") == 946e8fb6c65956cf751507c2aaeb5d93`，与磁盘上的 ctex 文件名一致，写新 `.import` 时直接照算即可。
3. **`addons/todo_controller/config/config.tres` 是插件自己写的扫描缓存**，光删 PVZ 行还不够：下次编辑器一开，只要目录还在就会被重新扫进去。
   → **正解**：删行的同时在 `black_dirs` 里加上 `res://PVZ-Godot-main`。
   → 该文件是 **LF 无 BOM**，PowerShell 改写要用 `[IO.File]::WriteAllText(..., (New-Object Text.UTF8Encoding($false)))`，别用 `Set-Content`（会改 CRLF + BOM）。

## 给后来者的最简路径

1. 全仓搜 `res://<待清理目录>`，**限定 `*.gd` / `*.tscn` / `*.tres`**（排除 `.import`），确认引用面。
2. 被引用的资源先迁到规范目录（已存在就只改 path+uid；不存在才复制 png + 自造 uid 的 `.import`）。
3. 目录根放 `.gdignore`（Godot 不再扫描）+ `.gitignore`（防止误提交）。
4. 目录的物理文件**留给用户删**，先别自己删。
