# 2026-10-03 · 关卡与地图 · 地图枚举槽位下沉为关卡自带 map_data

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次「某关要用特殊地图」照这个走）
> **耗时与成本**：约 1 轮对话，跑了 4 次无头探针（`probe_boss_map` / `probe_level_map_override` ×2 / `probe_tutorial` / `probe_tutorial_1_2`），未开窗口人工看表现
> **验证方式**：无头探针实机全绿（5-10 / 1-1 / 1-2）+ 新增静态探针全绿
> **补充自**：[2026-10-02\_僵王关夜屋顶地图.md](2026-10-02_僵王关夜屋顶地图.md) —— 该记录第 4 步引入的 `MainGameBoss` 枚举被本次撤销，已在其文末追加补充 / 评价

> **背景**：这是「排查全仓库还有哪些逻辑对特定关卡特判」的结论之一。排查结论是**没有** `if level_id == "1-1"` 这类硬编码关卡号分支，
> 但有四类「软特判」（全局枚举为单关开槽 / 通用管理器按冒险关卡序号分支 / 通用管理器塞单关专属数值 / 玩法 match 散落各 manager）。
> 本次处理的是第一类里最典型、也最没必要的那一处：**为选一张地图而单开场景枚举**。
> 同一批任务的第一项（僵王关 `_spawn_zomboss_if_needed` 搬进关卡流程）见
> [2026-10-03\_僵王关搬进关卡流程.md](2026-10-03_僵王关搬进关卡流程.md)，做法可照抄。

## 目标

去掉 `MainSceneRegistry.MainScenes` 里为具体关卡单开的三个枚举值
（`MainGameFront1Row` / `MainGameFront5Row` / `MainGameBoss`），
改由关卡自己的 `map_data` 指定地图。可判定：三个枚举值在仓库里零引用；
`DEFAULT_MAP_PATHS` 只剩前院 / 泳池 / 屋顶 3 项；1-1 / 1-2 / 1-3 / 5-10 实机地图装配与改动前一致。

## 步骤

1. **先摸清使用面再动手**（这步省不得，决定了删不删得动）：
   - `game_sences` 有三类用途：`MainScenesMap` 选场景文件、`resolve_map_data()` 反查默认地图、
     `choose_level_start_game()` 切场景。三个主游戏槽位在 `MainScenesMap` 里指向**同一个**
     `main_game_base.tscn` —— 所以「单关槽位」存在的唯一理由就是 `DEFAULT_MAP_PATHS` 那一格。
   - `ResourceMapData.game_sences` **业务代码无人读取**（只有 `probe_map_analysis` / `probe_boss_map` 读），是纯标注字段。
   - `src/levels/` 下已经没有 `.tres` 关卡（全是 `.gd`），所以受影响的只有 4 个关卡脚本 + 3 张地图 `.tres`。
2. 4 个关卡脚本的 `_init()` 里写
   `map_data = preload("res://data/map/xxx.tres") as ResourceMapData`；
   5-10 的 `game_sences` 改成 `MainGameRoof`，1-1 / 1-2 / 1-3 直接删掉（默认值就是 `MainGameFront`）。
3. 删 `main_scene_registry.gd` 的 3 个枚举值 + `MainScenesMap` 3 行 + `DEFAULT_MAP_PATHS` 3 行，
   并在枚举上方写明「**不要为某一关单开枚举值**」。
4. 同步 3 张地图 `.tres` 里的 `game_sences` 数字（见踩坑 1）。
5. 改探针：`probe_boss_map` 的断言从「场景槽位 = MainGameBoss」改成「关卡自带 map_boss」；
   `probe_zomboss` 的切场景改成读 `para.game_sences`；新增 `probe_level_map_override` 锁住新契约。
6. 改文档：[地图实现.md](../参考存档/地图实现.md)（现状段 / 登记表 / 探针清单）、
   [特殊关卡.md](../参考存档/特殊关卡.md)（5-10 开关表加 `map_data` 一行）。

## 关键决策与理由

- **只删枚举，不动 `resolve_map_data()` 的回落逻辑** —— 其余 91 个关卡仍然不写 `map_data`、
  靠 `game_sences` 取场景默认图，这条回落路径必须留着。删它等于强迫 91 个关卡都补一行 `map_data`。
- **保留 `ResourceMapData.game_sences` 字段，只把值改成配套的通用槽位** —— 它确实没有消费方，
  但删字段要动 5 个 `.tres` + 2 个探针，超出本次范围；改值只要 3 行，且仍表达「这张图配哪类场景」。
- **5-10 的 `game_sences` 取 `MainGameRoof` 而不是 `MainGameFront`** —— 三者指向同一份场景、行为完全等价，
  但语义上僵王关是屋顶；将来若真按场景分文件，这个值才是对的。
- **加 `as ResourceMapData` 显式转换** —— `preload` 一个 `.tres` 的静态推断类型不保险，
  项目里 `resolve_map_data()` 本来就有 `as ResourceMapData` 的写法，沿用。

## 踩坑

1. **地图 `.tres` 里的 `game_sences` 存的是整数，删枚举名不会报错**
   → 现象：删掉 `MainGameBoss`(5) / `MainGameFront5Row`(4) / `MainGameFront1Row`(3) 之后，
   `map_boss.tres` 里仍然是 `game_sences = 5`，Godot 照常加载成功（枚举本质就是 int），
   但这个数字在枚举里已经**没有对应成员**，成了只有肉眼能看出来的孤儿值。
   → **正解**：删枚举必须同步把 `.tres` 里的数字改成它实际配套的那个槽位
   （`map_boss` → 2，两张 front 图 → 0）。用 `^\s*game_sences\s*=` 在 `*.tres` 里搜一次就能捞全。
2. **跑探针时临时 userdir 被另一个无头进程占着**
   → 现象：`Remove-Item … godot.log: 文件正由另一进程使用`，`run_autopilot.ps1` 直接失败（exitCode=1）。
   → 原因：`run_autopilot.ps1` 固定用 `%TEMP%\pvz_autopilot\userdir`，两个 Godot 实例不能同时用。
   → **正解**：先 `Get-Process -Name 'Godot*'` 看有没有残留，**等它退出再跑**；
     别急着 `Stop-Process`（那可能是别人正在跑的探针，本次就撞上了一个 `probe_night`）。

## 给后来者的最简路径

1. 新加一张专用地图：写 `data/map/map_<名字>.tres`（抄最接近的那张）。
2. 在关卡脚本 `_init()` 里加一行
   `map_data = preload("res://data/map/map_<名字>.tres") as ResourceMapData`。
3. **完事** —— 不要动 `MainSceneRegistry` 的任何一张表，也不要往 `MainScenes` 里加枚举值。
4. 要回归：跑 `probe_level_map_override`（静态，秒出）+ 该关的实机探针。
