# 2026-10-15 · 新增内容 · 招笑版模组加第二只植物：豌豆射手 → 「傻豆射手」（打傻豆攒怒气、满怒散射豌豆）

> **任务类型**：新增内容（模组）
> **推荐度**：**推荐**（「把一只本体植物的攻击整个换掉」照这个走：抄发射点 → 腾空 → 接现成信号，本体一行不改；两条坑都是实测出来的）
> **耗时与成本**：约 3 轮对话（含用户两处口径修正与一次探针假绿排查），未开游戏（无头探针 + 门禁）
> **验证方式**：免验证 + 已给人工验证方法（无头探针验得到逻辑与几何，观感需人工看一眼）
> **补充自**：无（同目录 [2026-10-15\_模组素材接口与more_armor去侵入.md](2026-10-15_模组素材接口与more_armor去侵入.md) 是同一层「模组内聚」的方向，但不同机制）

## 目标

给「招笑版」模组（`mods_builtin/zhaoxiao/`，原来只改向日葵）再加一只植物，五条需求：

1. 豌豆射手改名「傻豆射手」；
2. 普通攻击打出去的是一颗**随机**的「傻豆」，并积累怒气；
3. 怒气让整株贴图**逐渐变红**，满了放大招；
4. 大招期间怒气**匀速**减少，同时在一定角度内散射速度在一个区间里的**普通豌豆**；
5. 傻豆两种：一类看着像正常豌豆但到僵尸前面会掉到地上，一类射偏（上 / 下）；
6. 傻豆**没有碰撞箱**，视觉与僵尸重合也不掉血。

（用户随后补了两条口径，见「步骤」第 9 / 10 步。）

## 步骤

1. 先按 [AGENTS.md](../../AGENTS.md) §2 取文档：[模组机制.md](../参考存档/模组机制.md)（模组边界 / 通用口子）+ `mods_builtin/README.md`（`user://` 脚本的三条硬限制）。**结论：能用的只有「每局 `install_to_main_game()` 现场挂节点 + 改实例字段」**，没有「组件替换」框架。
2. 摸清本体那条射击链路（`component_attack_bullet_base.gd`）：计时器 → 播攻击动画 → **动画的方法轨道**调 `_shoot_bullet()` → `_shoot_bullet_once()` 里 `BulletRegistry.create_bullet()` 造弹。**模组插不进动画那一步**。
3. 反着做（**本方案的核心**）：把射击组件的发射点 `markers_2d_bullet` **抄一份**到自己手上，再把那份 `clear()` —— 组件照旧循环它、只是循环了 0 次（一颗本体豌豆都不造），而动画 / 音效 / 计时 / 索敌**全部照旧**；观察者接的是组件现成的 `signal_shoot_bullet`，在**同一个时机**造自己的傻豆。
   - ⚠️ 必须先抄后清：位置要读原来那个 `Marker2D`（挂在 `stem_correct` 下、被动画逐帧写位置），自己记死坐标过两帧就不准。
4. 傻豆 = 模组自己 new 的一个纯 `Node2D`（`zhaoxiao_shadou.gd`）：一张豌豆贴图 + 一张影子，**连 `Area2D` 都不挂**（需求 6 由此天然成立）。**不复用** `Bullet000Base` —— 那套的碰撞框是它的立身之本，与「不造成伤害」正好相反。
5. 怒气 / 大招 / 染色都写在观察者里（`zhaoxiao_peashooter.gd`）：怒气满 → 2 秒内匀速降到 0，期间按固定间隔用**注册表的真子弹** `BulletIds.PEA` 散射（方向 = 射线方向 ±25° 随机、速度 220~420 随机，初始参数照抄组件自己的 `get_bullet_paras()`）。染色走 `BodyCharacter.base_color`（见「关键决策」）。
6. 入口脚本 `zhaoxiao_mod.gd` 的改名逻辑从「向日葵专用」抽成 `_rename_plant(图鉴键, 新名)`，原名按**图鉴键**记在 `_original_names` 里（两只植物共用一套还原逻辑）；挂观察者按 `plant.plant_type` 分派。
7. 写探针 `test/scenarios/probe_zhaoxiao_shadou.gd`（无头可跑），覆盖：改名 / 发射点腾空 / 一发的四件事 / **没有碰撞箱** / 两类傻豆的行为 / 满怒大招的全过程。
8. **弯路（第一版，被用户否掉）**：
   - 掉地上那种写成「离僵尸中心 34 像素就往下掉 + 落到地上躺 0.9 秒再消失」；
   - 射偏那种写成「相对正前方随机偏 14~38 度」。
   → 用户要求改成：**掉得再靠前一点（掉到僵尸前面）并在消失时播「豌豆命中」动画**；**偏转要恰好打不中僵尸**。
9. **改后的掉落口径**：不再看僵尸中心，改看它**受击框的前缘**（僵尸朝左走，面对豌豆的那一侧是左缘），前缘离我不到 `SHADOU_FALL_GAP`（60 像素）才开始掉 → 掉落点落在僵尸前面一段；落到本行地面那一下：**原地播一次本体的「豌豆命中」特效，然后这颗傻豆自己消失**（不再躺地上）。
10. **改后的射偏口径**：方向**算出来**，瞄准那只僵尸受击框的**上缘 / 下缘再往外 `SHADOU_OFF_CLEARANCE`（16 像素）**那个点，于是偏上擦头顶、偏下贴脚底，永远打不中 —— 即「恰好」；还要加**提前量**（见「关键决策」）。前面一只僵尸都没有时才退化成「随便偏一个角度」。

## 关键决策与理由

- **接管射击用「腾空发射点 + 接现成信号」而不是替换组件** —— 因为模组没有组件替换框架，而 `signal_shoot_bullet` 是现成的、时机与本体完全一致；腾空后本体那条「造弹」支路自然变成空转（连报错都不会有，`create_bullet` 都没被调到）。
- **傻豆不复用 `Bullet000Base`** —— 需求要「没有碰撞箱」，而那套基类的一切都围绕攻击框；新造一个纯 `Node2D` 反而更短、也不用跟「阵营 / 行 / 升弹」那套打交道。
- **受击框从实例上读（`HurtBoxComponent/HurtBoxReal` 下的 `CollisionShape2D`），不写死尺寸** —— 原版僵尸的受击框各不相同（普僵是 40×100 的竖直胶囊、巨人更高、雪橇车斜着放）。掉落判据与射偏瞄准都用它。
- **射偏必须算提前量** —— 僵尸是**朝豌豆走过来的**：直接瞄它此刻的位置，等豌豆飞到那儿它早已挪开，视线与它的交角会让豌豆实际擦得**比预期更贴近**（余量 16 像素会被吃掉 4~10 像素，有打中的风险）。做法是把瞄准点往它走的方向挪一个「相遇点」（`gap / 速度` 估一下，慢速僵尸够用）。
- **染色走 `BodyCharacter.base_color` + `_update_modulate()`** —— `base_color` 是身体颜色的**乘法合成根**（与受击闪白 / 冰冻 / 隐形相乘），染色与它们互不覆盖；**不能**改各张贴图的 `modulate / self_modulate`：动画给每个部件都带了 `self_modulate` 轨道、逐帧写回，改那儿下一帧就被盖掉（`BodyCharacter.set_invisible()` 的注释里也是这个理由）。
- **命中特效借本体 `BulletIds.PEA` 场景里的 `BulletEffect` 子树**，不自己攒一套粒子参数 —— 与本体豌豆打中时播的是同一份东西。它照「自己挂在子弹下面」写（用 `owner.get_parent()` 把自己挪到子弹的父层），所以临时造一个空壳当它的爹，让它自己搬去 `%Bullets`，壳子搬完就回收。
- **溅射帧用 `tween_property` 驱动**（见踩坑 1）。

## 踩坑

1. **`Tween` 的 `tween_method` 回调绑在傻豆身上 → 帧数一动不动、而且不报错**
   现象：命中特效里那张 4 帧溅射贴图停在 `frame = 0`，探针断言 FAIL，但 stderr 里**一行相关报错都没有**。
   原因：回调的 `Callable` 绑在**本颗傻豆**身上，而傻豆落地那一下自己就 `queue_free()` 了（需求就是「落地即消失」）—— 回调打在一个已释放的实例上。
   **正解**：换成 `tween_property(splats, "frame", 3, 0.2)`（只认「目标对象 + 属性名」，没有 Callable 包袱），并且 Tween 建在**特效**上（它要活到粒子播完）、排在特效自己 `reparent()` 搬完家之后建。
2. **借来的 `BulletEffect` 直接挂新父节点 → 引擎警告「owner 不一致」**
   现象：`WARNING: Adding 'BulletEffect' as child to 'ShadouPeaHitHolder' will make owner 'Bullet001Pea' inconsistent`。
   原因：它的 `owner` 还指着那颗被剖开的豌豆壳子，而 owner 必须在同一条祖先链上。
   **正解**：`sample.remove_child(effect)` 之后先 `effect.owner = null`，挂到空壳下再 `effect.owner = holder`。
3. **探针「整段静默跳过」→ `failed=0` 假绿**（本次最危险的一条）
   现象：`spawn_shadou` 的 `set_kind` 加了第二个参数，探针按两参调用，运行期报
   `Invalid call to function 'spawn_shadou' ... Expected 1 argument(s)`；而探针把断言写在**调用之后**，
   于是那一段一条断言都没跑，**结果照样报 `result=PASS failed=0`**。
   正解（两条一起做）：① `run_autopilot.ps1` 的输出里**必须单独看 stderr**（仓库早有这条约定，见 [模组机制.md](../参考存档/模组机制.md) §6.8.2 与 `probe FAIL ≠ 没有脚本错误` 那条旧记录）；② 探针收尾**把跑过的断言条数一起报出来**（`checks=44`），条数掉了就说明有段落没跑到。
4. **改接口不要只改一处**：`zhaoxiao_shadou.gd` 的 `set_kind(kind, off_sign)` 改了签名，观察者的 `spawn_shadou(forced_kind)` 忘了透传 —— 编译门禁抓不到（跨文件方法调用是运行期），只有跑探针才会炸出来。**动模组必须跑探针，不能只看门禁 PASS。**

## 给后来者的最简路径

1. 要换掉某只本体植物的**攻击行为**：别想着替换组件 —— 把它的发射点数组**抄一份再 `clear()`**，接 `signal_shoot_bullet`（或对应组件现成的那个信号），自己造想要的东西。动画 / 音效 / 计时 / 索敌一律不动。
2. 要让新造的东西「不参与碰撞」：就别挂 `Area2D`，也别继承 `Bullet000Base` —— 直接 `Node2D` + `Sprite2D`，素材按需借本体的原版贴图。
3. 要用「僵尸受击框」做几何判断（掉落点 / 瞄准点）：从 `HurtBoxComponent/HurtBoxReal` 下的 `CollisionShape2D` 读形状与 `global_position`，**按形状类型分别算**（胶囊的 `height` 是**含两端半圆**的总高），不要写死尺寸。
4. 要借本体的特效子树：`instantiate()` 后 `remove_child()` → `owner = null` → 挂到自己的空壳下 → `owner = 空壳` → 调它自己的激活方法（它会自己搬去该去的那一层）。
5. 要在「会自己消失的节点」上跑 Tween：用 `tween_property`（不要 `tween_method` 挂 `self` 的方法），并把 Tween 建在**活得久的那一个节点**上。
6. 探针收尾报出 `checks=N`，跑完**同时看 stderr**。

## 人工验证方法

打开游戏（模组页面把「招笑版」打开）→ 随便进一个白天关 → 种一株豌豆射手：

- 名字应显示「傻豆射手」（图鉴 / 商店卡说明也一起变）；
- 它打出来的豌豆看着正常，但**一颗都不掉血**：贴着僵尸飞过去也不掉血；
- 两类傻豆：一类在僵尸前面一段掉到地上、落地时冒一下绿色溅射 + 粒子，然后它自己没了；
  一类贴着僵尸头顶 / 脚底擦过去（偏上偏下随机），永远打不中；
- 每打几发整株会越来越红（5 发满），满了自动放大招：2 秒内红色褪回去，同时朝前方扇形喷出一堆**会掉血**的普通豌豆；
- 关掉模组 → 名字回到「豌豆射手」，攻击回到原版。
