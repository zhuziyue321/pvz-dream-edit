> **任务类型**：关卡与地图（关卡脚本写法收拢）
> **推荐度**：**推荐**（下次屋顶关照这个走）
> **耗时与成本**：约 2 轮（1 轮加工具 + 1 轮批量换写法），未开游戏（已给人工验证方法）
> **验证方式**：人工进任一屋顶关（5-1 / 生存屋顶 / 排山倒海）看开局左侧花盆；或跑
> `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_pogo_party -Windowed`
> **补充自**：无（同类可参照 [2026-10-03\_关卡流程数据改run\_flow传参.md](2026-10-03_关卡流程数据改run_flow传参.md)）

## 目标

屋顶关开局要沿整列铺花盆（裸屋顶没花盆种不下任何植物）。原写法是 `_init()` 里一列一条
`PrePlantResource`（铺 4 列 13 行、铺 8 列 25 行，17 个关卡脚本各抄一遍），
而且塞在 `all_pre_plant_data` 里只在**进关初始化时种一次**——多轮关切轮清场后花盆不会回来。
改成：`LevelScriptBase` 上一个流程方法，`run_flow()` 开头一句话。

## 步骤

1. 先确认老口径：`plant_cell_pos` 的 `x = 0` 表示整列、列号从 1 起
   （见 `PlantCellManager.pre_plant_one`），所以「第 y 列整列」= `Vector2i(0, y)`；
   批量造这一串就是新工具的全部内容。
2. 在 `SystemPlantResource`（`src/levels/core/system_plant_resource.gd`，当时还叫 `PrePlantResource`）加静态工厂
   `create_flower_pot_columns(col_count, begin_col = 1)`：只造数据，不碰关卡字段。
3. 在 `LevelScriptBase` 加**流程方法** `plant_flower_pot_columns(col_count, begin_col = 1)`：
   内部 `await system_plant(...)`，走现成的「系统种植」事件，不消耗阳光 / 不需要卡片。
4. 17 个屋顶关（冒险 5-1~5-10、屋顶测试关、生存屋顶 ×3、排山倒海、蹦蹦舞会、僵王复仇）
   逐个：删 `_init()` 里那串 `PrePlantResource`，在 `run_flow()` **第一行**加 `await plant_flower_pot_columns(N)`。
5. 探针里查花盆的两处断言要跟着搬：`probe_pogo_party` / `probe_boss_map` 原来是读
   `para.all_pre_plant_data.size()`（现在恒为 0），改成进关后数场上左侧 4 列的 Down 槽位花盆。
6. 同步文档：`特殊关卡.md` 5-10 那张表、`关卡数据与出怪表.md` 屋顶段。

## 关键决策与理由

- **工具做成流程方法（`await`）而不是 `_init` 里的字段填充**：`all_pre_plant_data` 只在
  `PlantCellManager.init_manager()` 消费一次，写在 `run_flow()` 里必须真去种 —— 顺带让多轮关
  每轮切回来都重新铺一次（切轮会清场，这是老写法的行为 bug）。
- **走 `system_plant` 而不是自己调 `create_plant`**：复用「系统种植」事件的语义（不计阳光、不走手牌），
  且 `PlantCell.create_plant` 自带「该槽位已有植物就跳过」的判据，重复铺是幂等的。
- **工厂留在数据类 `SystemPlantResource` 上**（当时叫 `PrePlantResource`）：时间轴的 `system_plant()` 事件也要 `Array[SystemPlantResource]`，
  摆造型 / 中途补种能直接用同一个工厂；屋顶测试关那条「第 1 列走模仿者材质」的特例就是这么保留的。
- **放在 run_flow 开头**（玩家能动手之前），否则「先有盆再种」的顺序就反了。

## 踩坑

1. **批量替换时 old_str 吞掉了相邻行** → 现象：屋顶测试关 `game_sences` / `game_BG` 三行被一起删掉
   → 原因：old_str 起止跨到了后面几行 → **正解**：替换完立刻回读那一段，别只信工具返回的「成功」。
2. **探针断言口径要跟着搬** → 现象：`all_pre_plant_data` 现在是空的，两条断言必挂
   → 原因：数据层断言查的是「老写法的位置」→ **正解**：改成运行期数格子（`get_plant(Down)`），
   顺便加个轮询（最多 10 秒）免得流程还没走到就判失败。

### 踩坑（这次新增）

3. **新增 `class_name` 后无头跑起来报 `Could not find type "XXX" in the current scope`** →
   现象：脚本明明写好了、IDE 也不报错，但 `run_autopilot.ps1` 里全线 parse error →
   原因：`class_name` 要在 `.godot/global_script_class_cache.cfg` 里登记过才能解析，
   **新增 / 删除 / 改名带 `class_name` 的脚本后必须让引擎重扫一次**
   → **正解**：`& '<godot.exe>' --headless --path <工程> --import` 重扫（约十几秒），再跑探针。
   （这条对「删文件 + 加新文件」的改名操作必现，别误判成自己写错了。）

## 给后来者的最简路径

1. 加关卡侧的批量工具：工厂放**数据类**上（`static func create_xxx`），关卡脚本这一侧再包一层
   `await` 的流程方法，两行搞定，别在 17 个关卡脚本里各写一遍。
2. 批量换写法：先 `search_content` 抓出所有老写法的位置与列数，再逐文件替换；
   每替换完一个就回读一次确认相邻行没被吃掉。
3. 只要动过「数据里能查到的东西」，**同步去 `test/scenarios/` 里搜这个字段名** —— 探针大概率也查它。
