# 2026-10-16_可选植物列表门禁

> **本次任务**：给「进选卡界面」加一道显式门禁 —— 热注册一株植物（调试模式 / 模组）不再自动可选，要多登记一项才进待选区
> **耗时 / 轮次**：1 轮；**没开游戏**（跑编译门禁 + 6 支无头探针，含新写的 `probe_selectable_plant`）
> **推荐度**：推荐（改动面小、探针已锁死口径）

## 目标

选卡界面原来「注册了就等于可选」：热注册的植物只要解锁就会出现在待选区。
但注册的植物未必都想给玩家挑（只给关卡脚本 / 传送带发货的也有），两件事分不开。
本次加一份 **可选植物列表** 作为**唯一判据**，初始内容 = 原版常规植物。

## 最简路径（步骤）

1. `src/ui/card/all_cards.gd`：新增 `_appended_selectable_plants` + `add_selectable_plant()` /
   `remove_selectable_plant()` / `is_selectable_plant()`；把 `get_plant_types_in_choose_order()`
   改成返回这份列表 = **原版常规植物（源目录顺序）** + **显式追加项（追加顺序）**，
   追加项里「卡片已不在目录」的条目滤掉（模组卸了 / 类型写错）。
2. **调试模式那四株**：`GlobalGameState._sync_debug_mode_plants()` 开时 `add_selectable_plant()`、
   关时 `remove_selectable_plant()`（与 `unlock_plants` / `lock_plant` 同一段）。
3. **模组那一路**：`PlantRuntimeKit.make_selectable()` 一行登记进列表；`uninstall()` 里自动摘掉。
   内置两个会注册植物的模组（`mods_builtin/water_bowl`、`mods_builtin/pvz2`）各补一行。
4. **消费侧防崩**（门禁生效后必然出现的状态：已解锁但列表里没有 / 列表里有但卡没了）：
   `card_slot_candidate.gd` 两处点亮循环改按**容器字典**判（没有卡位就跳过）；
   `card_slot_norm.gd` 的「重选上次卡片」同样按容器判（原来直接按 `card_id` 索引）。
5. 新探针 `test/scenarios/probe_selectable_plant.gd`；跑 `test/check_scripts.ps1` + 6 支探针。

## 弯路 / 踩坑（三段式）

- **试过**：把列表里的「原版常规植物」按**已获取**过滤（`curr_plant` ∩ 常规植物），即「列表只装已获取的」。
- **因为**：页面数由植物总数算（每页 48 格），一过滤就变成了「随解锁进度漂移」——
  已拥有的植物会因为新解锁一株而整体挪位，「第 1 页 = 普通植物 / 第 2 页 = 追加类」这条既有口径
  连同 `probe_bowling_debug_mode`（断言 3 页、页码 = `card_id / 每页格数`）一起失效。
- **结论**：列表里的常规植物仍是**源目录里的全部**（顺序固定、谁都不用登记），
  「玩家实际能挑哪些」继续由 `curr_plant` 点亮决定 ⇒ 玩家可见集合没变，只有追加类多了门禁。

- **试过**：让 `PlantRuntimeKit.install()` 顺手把植物也 `make_selectable()`（模组零改动）。
- **因为**：那就等于「装了模组就自动可选」，本次要拆开的正是这一件事 ——
  模组应该能注册一株「只给关卡脚本用、不给玩家挑」的植物。
- **结论**：登记留给模组自己写一行（`make_selectable()`），撤销由 Kit 代劳（`uninstall()`）。

## 推荐度与理由

推荐：门禁只有一处（`AllCards` 的列表），两个提供方（调试模式 / 模组）各一句话，
消费侧不新增分支（只是把「按 card_id 直取」改成「按容器取」）。
后来者注意两点：

1. **新增一株会注册植物的模组，别忘了 `make_selectable()`** —— 少这一行，植物能被关卡脚本
   发牌、能种，但选卡界面里没有它（`probe_water_bowl` 的「待选区里有水盆的卡位」会当场报红）。
2. **图鉴的「扩展植物」页与选卡界面同一口径**（都取这份列表）⇒ 没登记进列表的植物，
   图鉴里也不会收录。这是有意的：不可选的植物不该出现在图鉴里。
