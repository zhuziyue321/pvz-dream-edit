# 2026-10-15 · 排查调试 · Ctrl+Q 调试窗口「弹了但看不见」：面板被 anchors preset 甩到视口右边界之外

> **任务类型**：排查调试
> **推荐度**：**推荐**（「UI 按热键没反应」照这个走：先查开关 → 合成真实输入 → 量矩形 → 截图）
> **耗时与成本**：约 1 轮对话；**开了游戏**（带窗口探针跑 4 轮，其中第 4 轮带截图）
> **验证方式**：打开游戏实测（探针量矩形 + 截图双证）
> **补充自**：无 —— 本次修的是 [2026-10-13_新增调试窗口.md](2026-10-13_新增调试窗口.md) 那轮遗留的缺陷
> （那一轮「未开游戏」，所以这个缺陷一直没被发现）

## 目标

用户报「Ctrl+Q 没反应」。判定：是热键链路断了，还是窗口压根没画出来。

## 步骤

1. **先排除前置条件**：直接读真实存档 `user://default user/config.ini` —— `[console] values` 里
   `debug_mode` **已经是 `true`**，所以不是「没开调试模式」那条只打提示的设计分支。→ 是真问题。
2. **静态核对链路**：`Global._spawn_debug_window()` 无条件创建、`input` 里 `ShortcutKeys_DebugWindow` = Ctrl+Q 在、
   `DebugWindow._unhandled_key_input` 在 —— 静态看不出断点（门禁与 IDE 诊断全绿）。
3. **实机取证**（项目红线：排查一律打开游戏）：新写带窗口探针
   `test/scenarios/probe_debug_window_hotkey.gd`，用 `Input.parse_input_event` 合成真实 Ctrl+Q。
4. **第一轮探针只验了 `visible` 布尔 → `result=PASS`，是假绿。**
5. 补上 `get_global_rect()` + 截图 → 抓到 `rect=[P: (800.0, 0.0), S: (420.0, 600.0)]`：
   **视口只有 800 宽，面板整个落在屏幕右边之外**（`visible` 却是 `true`）。
6. 修 `src/ui/debug/debug_window.gd` 的 `_build_window()`：anchors 与**四个 offset** 一起写死（见「踩坑」）。
7. 复跑：`rect=[P: (380.0, 0.0), S: (420.0, 600.0)]`，截图里右侧半透明面板完整可见。

## 关键决策与理由

- **不先改代码，先取证** —— `visible == true` 与「看得见」是两件事，只读布尔值必然误判（第 4 步已经误判过一次）。
- **锚点用显式 offsets，不用任何 preset** —— 两个 preset 都会在「运行时新建的 0×0 Control」上算错（见踩坑 1 / 2）。
- **探针保留为回归资产**并登记进 [AI调试通道 §9](../AI调试通道.md)：它验的是「真的画在视口里」，
  而这类缺陷**编译门禁、IDE 诊断、只看 `visible` 的探针都抓不到**。

## 踩坑

1. **`set_anchors_preset(PRESET_RIGHT_WIDE)` 在 0×0 的新控件上会把高度算成 0**
   → 它按控件**当前矩形**（运行时 `Panel.new()` 是 0×0）反算 offsets，把 `offset_bottom` 写成 `-视口高`；
   实测 `offset=(-420, 0, 0, -600)`，于是高度 = `(1×600 - 600) - (0 + 0)` = **0**。
2. **换成 `set_anchors_and_offsets_preset(PRESET_RIGHT_WIDE)` 一样不行**
   → 它的左边距取自 `get_minimum_size()`，而宽度写在 `custom_minimum_size` 里（**不参与该计算**）
   ⇒ 宽度先算成 0，再被最小尺寸按 `GROW_DIRECTION_END`（默认）**向右**撑开
   ⇒ 面板整体落到视口右边界之外。**正解**：`set_anchors_preset` 之后把 `offset_left/top/right/bottom` 四个全写死。
3. **`visible == true` 不等于看得见**
   → 排查「UI 没弹出来」必须打 `get_global_rect()`，再与 `get_viewport().get_visible_rect()` 对一下；
   能截图就截一张（本次截图是最终拍板的那条证据）。
4. **`run_autopilot.ps1` 的 `-Godot` 默认路径 `Godot_v4.6.2-stable_win64.exe` 已失效**
   （2026-10-13 已记过一次，现在仍在）→ 显式传 `-Godot "C:\Users\a a\Desktop\godot.exe"`。
5. **探针里调 `get_parent_anchorable_rect()` 会报 `Nonexistent function in base 'Panel'`** —— 它不是公开 API
   → 想看布局就打 `size` / `anchor_*` / `offset_*` / `get_global_rect()`。

## 给后来者的最简路径

1. 用户报「某个 UI 按热键没反应」→ 先读真实 `user://<用户>/config.ini`（或对应设置文件）排除开关门槛。
2. 写一个带窗口探针，**合成真实输入**（`Input.parse_input_event`）驱动，而不是只看 `visible`。
3. 打 `get_global_rect()` 与 `get_viewport().get_visible_rect()` 对照，再截一张图。
4. 给运行时新建的 `Control` 贴边定位时：**`set_anchors_preset` + 四个 offset 全写死**，别用 preset 算偏移。
