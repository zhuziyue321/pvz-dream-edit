# 2026-10-13 · 其它 · 子弹类型 id 从 int 编号改成 StringName（编号去化的第一次试点）

> **任务类型**：其它
> **推荐度**：**推荐**（「把一处编号枚举换成语义字符串 id」照这个走；量规模 → 建 id 表 → 改代码 → 脚本批量改资源 → 无头实测）
> **耗时与成本**：约 1 轮对话，未开窗口（门禁 PASS 0 error + 一次性无头探针 5 条断言全 PASS）
> **验证方式**：免验证 + 已给出人工验证方法（玩法零变化，但改了 39 个资源文件，建议开一局打几发豌豆）
> **补充自**：无（本仓库第一次做「id 字符串化」，无旧记录可参考）

## 目标

把 `BulletRegistry.BulletType` 这套 int 编号枚举（`Bullet001Pea = 1` … `Bullet1003BowlingBig`）换成
**StringName 语义 id**（`BulletIds.PEA` …），并且**硬切换**：旧 int 值一律不再认识。
它同时是「编号系统要不要整个去掉」的试点 —— 先做最小的那张表（子弹），跑通再决定植物 / 僵尸 / 主场景。

判定标准：
- `.gd` 里搜不到 `BulletType` 的**代码**引用（只剩注释里的迁移说明）；
- `.tscn` / `.tres` 里搜不到 `(attack_bullet_type|bullet_type) = \d+`；
- 编译门禁 `real compile errors = 0`；
- 无头加载样本场景，`bullet_type` 读出来是预期的 StringName。

## 步骤

1. **先量规模再动手**（避免盲目开工）：`PlantType` 701 / `ZombieType` 1025 / `MainScenes` 231 /
   `BulletType` 47 / `ZombieBossType` 32 处 `.gd` 引用，另有 138 处 int 值序列化在 118 个资源文件里。
   用户据此选了**先做 BulletType 试点 + 硬切换**。
2. 新建 `src/core/consts/bullet_ids.gd`（`class_name BulletIds`）：19 个 `const X := &"xxx"` + `ALL` 列表 + `is_valid()`。
   放 `src/core/consts/` 是照 `ConstDamage` / `ConstArmor` 的先例（与 registry 分开：id 定义 vs id→资源映射）。
3. `bullet_registry.gd`：删 `enum BulletType`（留下迁移说明注释），`BULLET_SCENE_PATHS` / `_scene_cache` 键改 `StringName`，
   三个函数签名改 `StringName`，日志 `%d` → `%s`。
4. 改调用点：8 个业务脚本（子弹基类 `@export`、三个攻击组件、火炬树桩 / 火炬僵尸升级表、玉米炮 ×2）+ 5 个探针 + 联机 `netplay_state_sync.gd`。
5. **批量改资源**：一条 PowerShell + `[regex]::Replace` 按 `编号 → id` 映射表改写 39 个 `.tscn`（`bullet_type = 1` → `bullet_type = &"pea"`），
   带 unmapped 兜底（映射缺失就不改并报出来），实测 changed=39 / unmapped=0。
6. 编译门禁 + 一次性无头探针实测（`bullet_pea` / `bowling_big` / `winter_melon` / `plant_snow_pea` / `zombie_catapult` 全 PASS），探针用完删除。
7. 同步文档：`架构总览.md` 注册表表与「新增子弹」步骤、`子弹说明.md` 注册步骤、`联机模组.md` 的 `b_type` 口径、
   `Agent协作协议.md` 的子弹编号段（改「不占段」）、`规范细则存档.md` M-03 的表格与正例。

## 关键决策与理由

- **用 `StringName` 而不是 `String`** —— id 主要当字典键和做相等比较，StringName 是 Godot 的惯用法，
  本仓库已有先例（`ConsoleRegistry` 的 `&"builtin"`、`SoundManager` 的 `&"Throw"`）。
- **独立 const 脚本，不塞回 `BulletRegistry`** —— GDScript 的 `enum` 只能是 int，想保留 `BulletType.X` 的写法
  只能上 inner class（静态常量访问可行但别扭）。独立 `class_name BulletIds` 引用最短，也避免
  `var t: BulletType` 这种注解被误当成「对象类型」。
- **不保留 int 兼容层（硬切换）** —— 双轨会让「同一个子弹有两个 id」长期存在，正是这次要消掉的东西。
- **联机快照 `b_type` 改 `PackedStringArray`** —— 比 int 多几个字节，换来客户端不必再维护编号对照表；
  代价明确写进 `联机模组.md`。
- **子弹脚本的 class_name 编号（`Bullet016CobCannon` 等 13 个）本次没动** —— 那是类名不是 id，
  属于另一件事，留作后续（改动面另算）。

## 踩坑

1. **想直接给 `enum` 换个类型** → Godot 4 的 `enum` 只能是 int，改不了 → **正解**：换成 `const` StringName 集合，
   所有 `BulletType` 类型注解改成 `StringName`。
2. **`godot --script xxx.gd` 跑探针报 `Identifier not found: Global`** → `--script` 起的 SceneTree **不注册 autoload**，
   子弹场景的依赖链里有依赖 autoload 的脚本，编译直接失败 → **正解**：走项目自己的 autopilot：
   `godot --headless --path <项目> -- --scenario=res://test/scenarios/<探针>.gd --autopilot-max-seconds=120`。
3. **资源里的 int 值编译门禁查不出来** → `--import` 只编译脚本，字符串/int 不匹配要运行时才炸 → **正解**：
   批量脚本改完后再用无头探针实例化样本场景，实测读出来是不是预期的 StringName。
4. **同一轮里并行跑两个 PowerShell（门禁 + 搜索）** → `check_scripts.ps1` 报 *The process cannot access the file
   because it is being used by another process*，且 `scenarios` 段显示 `scripts=? (autopilot did not finish)`
   （虽然仍判 PASS，但那一段实际没跑） → **正解**：门禁**单独跑**，别与别的 Godot 进程并行。
5. **格式化符没跟着改** → `Log.error("…: %d" % bullet_type)` 对 StringName 会打出 0 → **正解**：`%d` 一律改 `%s`
   （`bullet_registry.gd`、`probe_bullet_camp.gd` 各一处）。

## 给后来者的最简路径

1. 建 id 表：`src/core/consts/<域>_ids.gd`，`class_name <域>Ids`，`const X := &"snake_case"`，附「旧编号 → 新 id」对照注释。
2. registry 里删 enum、把字典键与函数签名改成 `StringName`、`%d` 改 `%s`。
3. 全仓搜旧枚举名，逐个调用点换成 `Ids.X`，类型注解换 `StringName`。
4. 资源里的 int：先 `Select-String "(字段) = \d+"` 列全量 → 按映射表 `[regex]::Replace` 批量改 → 复查 unmapped=0。
5. 门禁（单独跑）+ 一次性无头探针实例化几个样本场景确认解析正确 → 删临时探针 → 同步文档（架构总览 / 专题文档 / 协作协议编号段）。

## 补充 / 评价（2026-10-14 · 照这条记录铺开了植物 / 僵尸 / 僵王）

**结论：推荐度维持「推荐」**，本条的最简路径照着走了一遍，可行；下面是铺到更大的表时
**新增的三条经验**（详细版见 [2026-10-14_角色id从编号改为字符串.md](2026-10-14_角色id从编号改为字符串.md)）：

1. **动手前先问「这个 id 会不会写进存档」** —— 子弹不进存档，可以硬切换；
   植物 / 僵尸 / 僵王的 id 会写在玩家磁盘上（`curr_plant` / `selected_cards` / 存档文件名），
   硬切换 = 玩家进度作废。→ 补一条 `from_legacy()` + `LEGACY_INT_TO_ID` 映射表
   （**只在读档时用**，业务代码不反向查它）。这一步本条记录里没有，是铺开时新加的。
2. **`StringName(x)` 不是构造函数**（`String` → `StringName` 只能靠隐式转换），
   而且**编译期查不出来**，只在执行到那一行时才报错 —— 本条最简路径第 2 步的
   「函数签名改 `StringName`」要跟着改：**别在函数体里写 `StringName(...)`**。
3. **`[regex]::Replace` 一次换多个键时只换了第一个、且零报错** → 改用 `Matches` +
   从后往前替换；改完**必须抽查两个文件**再跑门禁（本条记录第 4 步的「复查 unmapped=0」
   只能兜住「映射缺失」，兜不住「只换了一部分」）。

另外：本条记录里提到的「编号段」概念在角色侧已经整个消失 ——
热注册僵尸的 9001–9999 段换成了 `runtime_zombie_` 前缀自增，
`Agent协作协议.md` 的植物 / 僵尸编号段配额也随之作废（改成「id 表加常量，天然不撞段」）。
