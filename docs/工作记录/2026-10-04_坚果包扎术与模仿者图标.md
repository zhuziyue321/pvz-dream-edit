## 目标

1. 商店补上原版商品「坚果包扎术」（$2000，通关冒险模式后上架，买断即售罄）。
2. 买了之后关卡里真的能用：手持坚果 / 高坚果 / 南瓜头卡片，直接补种在**已经掉手或裂开**的同种植物上。
3. 商店里模仿者商品的图标不再空白。

## 步骤

1. **先查 wiki 定口径**（[AI查wiki避坑.md](../参考存档/AI查wiki避坑.md)）：
   `plantsvszombies.wiki.gg/wiki/Wall-nut_First_Aid` → 一代 $2000、通关冒险模式后上架、
   机制是「把新的防御植物种在受损的同种植物上，不先挖掉」、只作用于 Wall-nut / Tall-nut / Pumpkin、
   **外观完好（只是掉血没裂）的不能补种**、大蒜与地刺王不在其列。
   数值与口径写进 `ConstShop` 常量注释（含来源 URL），不散在业务脚本。
2. **常量 + 存档**：`ConstShop.WALL_NUT_FIRST_AID_PRICE` / `WALL_NUT_FIRST_AID_PLANT_TYPES` / `is_first_aid_plant()`；
   `GlobalGameState.is_wall_nut_first_aid_bought` + `buy_wall_nut_first_aid()`（照钉耙那套 `rake_use_num` 写）；
   `save_service` 的**读、写两处**都加键（只加一处不报错但会静默丢档）。
3. **商品**：新建 `src/store/goods_wall_nut_first_aid.gd/.tscn`（照 `goods_rake` 的四件套：
   `_ready` 设售价 → `super()` → `_refresh_goods_state()` → `judge_can_get_goods()`），
   图标直接用仓库里现成的 `images/Store_FirstAidWallnutIcon.png`，戴夫对话新建 `data/dave/dialog_detail/store/wall_nut_first_aid.tres`。
4. **上架与货架顺序**：它不是植物卡片，不走 `PLANT_CARD_ROWS` 动态生成，直接摆进 `store.tscn` 的 `RowUpgradeThird`；
   模仿者商品是运行期 `add_child` 的，会排在静态节点**前面**，所以 `StoreManager._ready()` 里补一句
   `row_upgrade_third.move_child(goods_wall_nut_first_aid, -1)`，才对上原版「模仿者 → 坚果包扎术」。
5. **关卡内生效**：`PlantCell.get_first_aid_plant(plant_type)` 判定（买了 + 同种 + 血量阶段 ≥ 1），
   `Plant000Base.be_first_aid_heal()` 回满血 + 复原外观，`HandComponentCharacter` 在
   `_update_cell_shadow()` 里给可补种的格子照常出虚影、`click_cell()` 里走修复而不是 `create_plant()`（柱子模式同理）。
6. **模仿者图标**：`GoodsPlantCard._create_icon()` 从 `AllCards.all_plant_card_prefabs` 取卡片，
   模仿者卡片不在这个字典里（见下）→ 加 `_get_card_prefab()`，模仿者改取 `AllCards.imitater_card`。
7. **探针**：新建 `test/scenarios/probe_first_aid.gd`，一次覆盖常量 / 商店上架 / 购买扣钱 / 模仿者图标 / 补种修复 / 四个反例。

## 关键决策与理由

- **回血而不是"删掉旧植物重建一株"**：原版表现是新株顶替，但删节点会让正在啃它的僵尸握着已释放引用（仓库历史上
  `plant_in_cell` 槽位残留就崩过，见 [规范细则存档](../参考存档/规范细则存档.md) 的 Imitater 越界事故）。
  回满血 + 复原外观的结果与顶替一致，风险低得多。
- **血量阶段组件加"满血外观快照"**：`HpStageChangeComponent` 只能单向改外观（换纹理 / 显隐精灵），没有反向操作，
  所以 `_ready()` 末尾存一份满血快照，`reset_hp_stage()` 用它退回去。
- **模仿者不塞进 `all_plant_card_prefabs`**：选卡界面按这个字典的**顺序**和 `plant_card_ids` **下标**生成候选卡位
  （`card_slot_candidate.gd`），混进去会多出一张候选卡并错位，所以只在 `AllCards` 上单独留一个 `imitater_card` 引用。
- 修复条件用「血量阶段 ≥ 1（外观已裂）」而不是「掉过一点血」，对齐原版 Trivia。

## 踩坑

1. **基类加成员与子类撞名**：给 `Plant000Base` 加 `@onready var hp_stage_change_component` 后，
   `plant_wall_nut / tall_nut / pumpkin / garlic / spike_rock` 五个脚本全部
   `Parse Error: The member "hp_stage_change_component" already exists in parent class`，场景直接实例化失败。
   → 原因：这些子类早就各自声明了同名成员。
   → **正解**：基类不声明，改成函数里 `get_node_or_null(^"HpStageChangeComponent") as HpStageChangeComponent` 现取。
   → 教训：给基类加成员前先 `grep` 子类同名变量；**无头探针的第一条 stderr 就是这类错误的唯一出口**（编辑器不跑就看不到）。
2. **图标素材不在 `assets/image/store/`**：`Store_FirstAidWallnutIcon.png` 躺在仓库根目录 `images/` 下
   （`images/` 里还有一批未归位的原版素材）。没搬（搬素材要连 `.uid` / `.import` 一起走且需先关编辑器），
   直接按 `res://images/...` 引用 —— 仓库里已有先例（`adventure_choose_level.tscn`、`const_adventure_reward.gd`）。

## 给后来者的最简路径

1. wiki 定口径 → 常量（带来源注释）+ 存档读写两处 + `goods_xxx.gd/.tscn` 四件套（抄 `goods_rake`）。
2. 关卡内生效：找一个"判定入口"函数（本次是 `PlantCell.get_first_aid_plant`）+ 一个"执行"函数（本次是 `Plant000Base.be_first_aid_heal`），
   再挂到已有的手持 / 点击链路上（`HandComponentCharacter` 的虚影与 `click_cell`）。
3. 写 `test/scenarios/probe_*.gd`，`powershell -File test/run_autopilot.ps1 -Scenario <name>` 跑，
   **先看 stderr 有没有 Parse Error**，再看 `[XXX] result=` 行。
4. 同步 `docs/参考存档/选关界面与解锁.md` 的货架表与售罄表。

## 人工验证方法（画面 / 手感）

- 存档通关冒险模式 + 金币 ≥ 2000 → 进商店翻到第二页：下排应是「模仿者、坚果包扎术」，包扎术 $2000。
- 买下后开一关（带上坚果卡片）：让坚果被啃到裂开，手持坚果卡片悬停该格应出现虚影，点击后
  坚果**裂纹消失、血量回满**，并正常扣阳光与卡片冷却；没裂开的坚果点上去应是蜂鸣（buzzer）且不扣卡。

## 补充 / 评价（同日后续：商店种子包图标改成直接复用出战卡片）

> 改的是本文第 6 步建立的 `_create_icon()` 渲染方式，评价附在这里，不另开一条记录。

- **改法**：`goods_plant_card.tscn` 里手工拼的种子包（`Bg` 的 Sprite2D 底图 + 独立 `PlantContainer` + 20 号 `Cost` Label，
  整体 `scale 0.5`，植物还要再乘 2 还原）整块删掉，容器改成 `Control`（50x70，按 67x68 商品格居中，offset `(8.5, -1)`）；
  `_create_icon()` 直接把 `AllCards` 的卡片 prefab `.duplicate()` 成整张 `Card` 挂进去 —— 底图 / 紫卡灰卡 / 静态形象 /
  阳光花费全部由 `Card` 自己渲染，与出战卡槽、掉落种子包同一套代码路径。
- **为什么**：两套渲染必然漂移（植物缩放、卡片裁剪、紫卡底图、花费字号全靠手工对齐），复用 `Card` 之后商店图标与卡槽永远一致，
  新增植物不用再管商店图标。
- **踩坑**：`Card` 里的 `Button` / `Cost` 默认吃鼠标事件，**直接挂上去会挡住商品按钮，商品点不动**。
  `Control.MOUSE_FILTER_IGNORE` 只作用于自己、不传导给子节点，必须递归把整棵 `Card` 子树都设成 IGNORE
  （`GoodsPlantCard._set_mouse_filter_recursive()`）；探针 `probe_first_aid` 里加了一条断言守着这点。
- **验证**：`probe_first_aid` 无头 + `-Windowed` 各跑一次，20 项断言全 PASS；
  画面（卡片在商品格里的居中与裁剪观感）仍需人工看一眼。
