
# 2026-10-03 · 关卡与地图 · 戴夫对话 / 教程数据不再在 `_init()` 赋值，改在 `run_flow()` 现场构造并传参

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 3 轮对话，未开游戏（改动触达玩法行为，**必须**人工开游戏实测，见「验证方式」）
> **验证方式**：免验证 + 已给出人工验证方法（本次窗口内未开游戏；对话 / 教程只有打开游戏才看得见）
> **补充自**：[2026-10-02_关卡时间轴固化到关卡资源.md](2026-10-02_关卡时间轴固化到关卡资源.md)（同一条时间轴演进的下一步）

## 目标

关卡脚本里「戴夫对话 / 新手教程」的数据不再写进 `_init()` 的字段，改成在 `run_flow()`
里现场构造并当参数传给预制体，让流程一眼看出这一句在播什么：
`await prefab.dave_dialog(_build_dave_dialog())`、`await prefab.tutorial(_build_tutorial())`。

## 步骤

1. **先摸消费点与时序**（这一步不能省，它决定了整个方案）：
   `grep crazy_dave_dialog|tutorial_data` → 数据在 `run_flow()` **之前**就被读：
   `MainGameManager.init_tutorial_manager()`（第 345 行，早于 `run_timeline()`）、
   `TutorialManager._ready()`、`is_skip_level_dave_dialog()`、`is_dave_sell_possible()`。
   → 结论：字段可以不再赋值，但**判定必须先改成走可覆写方法**，否则一进关就全空转。
2. **`ResourceLevelData` 加三个可覆写方法**（默认读字段，老 `.tres` 关卡行为不变）：
   `get_tutorial_data()` / `has_tutorial()` / `has_dave_dialog()`；
   并把 `is_tutorial()` → `has_tutorial()`、`is_opening_tutorial_level()` → 走 `get_tutorial_data()`、
   `is_dave_sell_possible()` → 走 `has_dave_dialog()`。
3. **`LevelPrefabs` 两个预制体加可选参数**，事件脚本加对应字段，传了就用传的、没传回落字段。
4. **时序改造**：`init_tutorial_manager(data_override)` + 新增 `setup_tutorial_manager(data)`，
   教程事件在 `run()` 里把「流程才造出来的数据」补交给 `TutorialManager`（管理器没建就现建）。
5. **迁移 10 个关卡脚本**（1-1 / 1-2 / 1-5 / 2-1 / 3-1 / 4-1 / 4-5 / 4-6 / 5-1 / 5-5）。
6. 同步探针（`probe_tutorial*` / `probe_4_5` / `probe_glove_unlock`）与 4 份文档。
7. ~~写 Python 脚本批量搬运数据块~~ → **放弃原因**：05-05 的对话块有 650 行、注释归属规则复杂，
   脚本出错排查成本高于收益；改用下面第 5 步的「换函数头」技巧，一行都不用搬。

## 关键决策与理由

- **判据改成可覆写方法，而不是删字段** —— 因为 `init_tutorial_manager()` 在 `run_flow()` 之前跑，
  数据此刻还没被 new 出来，必须有一个「本关有没有教程 / 对话」的静态声明入口；
  让关卡脚本覆写 `has_tutorial() -> true` / `has_dave_dialog() -> true` 是最小代价（各 3 行）。
- **教程数据由事件补交给管理器**（`MainGameManager.setup_tutorial_manager`） ——
  这样「开场教程」（1-5，在流程里等它跑完）和「普通教程」（1-1 / 1-2，进 MAIN_GAME 后才跑）
  共用一条路径：写在 `run_flow()` 里的 `await prefab.tutorial(...)` 对前者是「跑完」、对后者是「登记」，
  事件自己按 `is_opening_tutorial()` 判断。
- **4-5 三批对话改成三个方法**（`_build_dave_dialog_1/2/3`） —— 本关是 `is_one_shot_flow`，
  三批写在同一段流程里，按批点名比「按轮次下标取 `crazy_dave_dialog_next_round`」好读。
- **`_init()` 里保留 `pre_plant` 等纯属性构造** —— 只有「对话 / 教程」是流程内容，别的属性不动，
  避免把 `_init()` 拆得七零八落。

## 踩坑

1. **想整体换函数头却撞上 `pre_plant`** → 05-01 / 05-05 / 01-05 的 `_init()` 开头先是
   `pre_plant_in_level_*`（属性要用，不能搬走）→ **正解**：不搬代码，在对话块**第一行前**插入
   `func _build_dave_dialog() -> CrazyDaveDialogResource:`，在块末尾补 `return xxx` +
   `func _init() -> void:`，让后面的属性块自动成为新的 `_init()` 体。全程只改边界几行，
   650 行的对话块原地不动 —— 手抄大块最容易错，这个技巧把它降到 4 处小编辑。
2. **`is_tutorial()` 与 `has_tutorial()` 互相调用会死循环** → **正解**：让 `has_tutorial()`
   只调 `get_tutorial_data()`（默认返回字段），`is_tutorial()` 只调 `has_tutorial()`，单向。
3. **`should_run_tutorial()` 取不到数据会改变行为** → 教程数据现在为 null，
   原判据 `not tutorial_data.only_first_playthrough` 会短路成「已通关就不播」；
   `only_first_playthrough` 默认 true，1-1 / 1-2 / 1-5 走的本来就是这条分支 → **行为不变**，
   但代码里要显式写「数据为 null 时按默认规则判」，别让人以为漏了。
4. **换函数头换出了两个 `_init`**（最严重，改完一定要自检） → 05-01 / 05-05 / 01-05 的
   `_init()` 开头是 `pre_plant_*`（属性要用、不能搬），我在属性块前又补了一个 `func _init()`
   → 同文件两个 `_init`，且属性块里的 `all_pre_plant_data.assign([pre_plant_in_level_0 …])`
   根本取不到另一个函数体的局部变量 → **正解**：属性块必须并进**第一个** `_init()`
   （紧跟 `pre_plant` 之后），`_build_*()` 放在它后面。
   自检：`grep -c 'func _init(' ` 每个关卡脚本必须**恰好 1 个**。
5. **`probe_glove_unlock` 指的还是 `.tres`** → 4-6 早已迁移成 `.gd`，`.tres` 只在
   `.backup_levels_20261002/` 里，这个探针的静态段本来就失效（迁移遗留，非本次引入）→
   **正解**：顺手改成加载 `.gd` + `.new()` + 调 `_build_dave_dialog()` 取对话。

## 给后来者的最简路径

1. 先 `grep crazy_dave_dialog|tutorial_data` 摸清**谁在 `run_flow()` 之前读数据**（第 1 步，别跳）。
2. `ResourceLevelData` 加 `get_tutorial_data()` / `has_tutorial()` / `has_dave_dialog()` 三个可覆写方法，
   把内部判据切过去（老关卡默认读字段，零影响）。
3. 预制体 + 事件加可选参数（传了优先，没传回落字段）；教程事件补一段
   `main_game.setup_tutorial_manager(data)`。
4. 迁移关卡：用「换函数头 + 插 return + 补 `func _init()`」改边界，**不要搬运大块**；

5. 同步探针与文档；**打开游戏**：1-1 / 1-2（教程在开战后）、1-5（开场教程 + 对话）、
   2-1 / 3-1 / 4-1 / 4-6 / 5-1 / 5-5（开场对话）、4-5（三批对话各一段）逐关过一遍。
