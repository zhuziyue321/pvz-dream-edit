# 2026-10-10 · 联机同步 · 客户端自己拿起植物（本地校验），种下时在房主处校验

> **任务类型**：其它（联机同步）
> **推荐度**：**推荐**（下次动联机的「玩家操作」先按这条分工判归属）
> **耗时与成本**：约 1 轮对话，未开游戏（无头探针 `probe_netplay_session` PASS + 编译门禁 PASS，已给人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（改动只在模组内、模组默认关闭；种植手感必须双实例人工看）
> **补充自**：[2026-10-10_联机客户端禁用出怪逻辑.md](2026-10-10_联机客户端禁用出怪逻辑.md)（同一条"生成 / 判定归主机"纪律的延伸）

## 目标

联机客户端**能拿起植物**：点卡本地生效（本地校验阳光 / 冷却 / 紫卡前置）；种下（`click_cell`）在房主处校验。
改之前客户端点了卡**永远拿不到植物**。

## 步骤

1. 先定位"为什么拿不起来"：点卡上行的是 `card_index + plant_type`，而两端**各挑各的卡**
   （[联机模组.md](../参考存档/联机模组.md) §4.2.2 只保证不重复）⇒ 同样第 0 张常常不是同一株，
   主机 `_card_of()` 按下标取卡必然对不上 ⇒ 主机跑不动 ⇒ 不下行 ⇒ 客户端永远拿不起来。
2. 按"战斗域 / 本地域"判归属（[联机模组规范.md](../参考存档/联机模组规范.md) §3.4）：
   **拿起**不改变场上任何东西 ⇒ 本地域；**种下**改变实体集合与阳光 ⇒ 战斗域。
3. 网关 `NetplayActionGateway._may_take()` 让 `ClickCard` 返回 false（不接管 = 本地跑）；
   `NetplayCommand` 删掉 `OP_CLICK_CARD` / `ARG_CARD_INDEX` / `ARG_PLANT_TYPE` / `card_index_of()` / `battle_cards()`。
4. `click_cell` 参数改为 row / col + **`ARG_CARD_REF`**（`ResourceCardReference.to_dict()`）+ **`ARG_SUN_COST`**；
   卡的身份由新增的 `NetplayCommand.held_card()` 从"手上那一张"取，不再走卡槽下标。
5. `NetplayBattleSync._replay_click_cell()` 三步：照身份拿起同一张 → 补一次 `mouse_enter(cell)` → 走本体 `_on_click_cell()`。
6. 同步文档（[联机模组.md](../参考存档/联机模组.md) 新增 §4.6.1 + 改重放表与已知风险 1 / 7；
   [联机模组规范.md](../参考存档/联机模组规范.md) §3.2 战斗域表 + §3.3 本地域加一条）+ 改探针断言。

## 关键决策与理由

- **拿起留本地，而不是"客户端也上行一次点卡"** —— 上行只能换来半个 RTT 的空手等待，
  而主机那一局里根本没有这一张卡，照样拿不起来。
- **命令带卡的**身份**（`ResourceCardReference`）而不是下标** —— 下标两端对不上，
  身份两端一致，且可直接进 RPC（与 §4.12 出卡同步同一套 `to_dict()/from_dict()`）。
- **主机没有这一张时临时造一张**（`AllCards.get_template()` → `duplicate()` → 入树 → 用完 `queue_free()`）
  —— 而不是替本体抄一份"种植逻辑"：造出来之后走的仍是 `MAIN_GAME_CLICK_CARD` → 手持组件 → `click_cell()`，
  地形 / 占用 / 坚果包扎术 / 音效 / 扣阳光全都不用模组再抄一遍。
- **阳光花费随命令上报**（`ARG_SUN_COST`）—— 紫卡的价随场上株数涨，主机自己算不出来；
  不带上就会两端钱数永久分叉（阳光总量是战斗域，主机权威，见 §4.9）。

## 踩坑

1. **症状：联机客户端点了卡没反应** → 命令按**卡槽下标**找卡，而两端各挑各的卡、下标对不上
   → **正解**：命令一律带卡的身份；干脆把"拿起"整个划成本地，种下才上行。
2. **主机重放"点格子"种不出东西** → `is_shadow_in_cell`（能不能种）由**鼠标悬停**算出来，
   而主机并没有把鼠标放到客户端点的那一格上 → **正解**：重放前补一次
   `hand_manager._on_cell_mouse_enter(cell)`，让本体判的是**这一格**（铲子的高亮同理）。
3. **临时造的卡拿不起来**（`enter_hand()` 里 `_create_hand_static()` 失败）
   → `character_static` 是 `@onready`，不入树取不到 → **正解**：先 `mg.add_child(card)` 再推事件。
4. **模仿者会被种成原版那一株** → `template.duplicate()` 后 `make_reference_unique()` 只是复制模板的身份，
   而模板**不区分**是不是模仿者（`get_template_key()` 只认类别 + 角色编号）
   → **正解**：直接 `card.card_reference = reference`（用命令里那一份）。
5. **门禁覆盖不到整个 netplay 模组**（沿用上一轮的结论：入口是运行时 `load()` 字符串路径）
   → **正解**：动模组**必须**跑 `probe_netplay_session`，不能只看门禁 PASS。

## 给后来者的最简路径

1. 先判"这一步会不会改变场上"：不会 ⇒ 本地跑（网关 `_may_take()` 返回 false）；会 ⇒ 上行，
   主机跑成再下行。
2. 命令里只带**身份**，不带下标；主机缺对象就用 `AllCards.get_template(ref)` 临时造一个，
   走本体事件让它自己跑完，用完回收。
3. 重放"点格子"类操作前，先补一次 `mouse_enter(那一格)`。
4. 改完跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_netplay_session`；
   手感 / 视觉必须双实例人工看（见 [联机模组规范.md](../参考存档/联机模组规范.md) §四）。
