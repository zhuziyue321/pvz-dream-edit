# 2026-10-14 · 其它 · 模组改成「玩家目录优先 + 缺文件退回内置源」两根加载

> **任务类型**：其它（分发形态驱动的加载兜底）
> **推荐度**：**推荐**（「本仓库的东西要保证在只有一份分发文件时也能跑」照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（无头场景 + 隔离用户目录三段验证 + 门禁 PASS 0 error）
> **验证方式**：免验证（改动集中在 autoload 的加载判定）+ 已给出人工验证方法
> **补充自**：[2026-10-13_模组搬到user目录.md](2026-10-13_模组搬到user目录.md)

## 目标

玩家只拿到**一个游戏文件**（pck 嵌进 exe）时，内置模组也一定能跑起来：

- `user://mods/` 里没有 → 从 `res://mods_builtin/`（包里）复制过去；
- 两边都有 → **用 `user://mods/` 那份**（玩家改的是自己的）；
- `user://mods/` 那一份不可用（写不进去 / 缺文件 / 导出后被转成引擎读不出的形态）→ **整个模组退回内置源**，不许静默消失。

## 步骤

1. 保留既有的播种 `_sync_builtin_mods()`（缺的文件才复制，指纹变了才覆盖）—— 它就是「没有则复制过去」。
2. 在 `_ready()` 里播种**之后**加一步 `_resolve_mod_roots()`：按**模组整目录**给每个 id 定加载根。
3. `_mod_script_path()` 由「固定 `user://mods`」改成「`_mod_root(id)` + 相对路径」，`_extends_mod_base()` 两根的 `mod_base.gd` 都认。
4. `_create_mod()` 加最后一重兜底：`load()` 返回空且当前用的是玩家那份 → 退回内置源再 load 一次。
5. 打一行 `Log.info("ModManager: 模组加载根 —— 玩家目录 N 个 [...]，内置源 M 个 [...]")`，让「从哪加载」在运行期一眼可见。

## 关键决策与理由

- **判定粒度是「模组整目录」而不是「单文件」** —— 模组内部靠 `preload("相对路径")` 互相引用（如 `more_armor` 的 `extends "ore_bucket_zombie_base.gd"`），同一个模组一半来自 `user://`、一半来自包里会错位报错，比**整个退回**更难查。
- **目录不存在时不报警** —— 第一次跑、或玩家压根不想放本地副本是常态；只有「目录在但缺文件」才算异常。
- **仍然要复制** —— 「玩家能直接改 `user://mods/`」是这套机制的初衷；退回内置源只是**保底**，不是替代。
- **`res://` 这份可以放心加载** —— 查过 `mods_builtin/` 下只有 `ModIds` / `ModConfig` 带 `class_name`（本来也要给本体用的），其余全写相对路径，不会污染全局类名。

## 踩坑

1. **想把内置模组装到 `user://` 之外、一路以为 `DirAccess.dir_exists_absolute()` 会先检测到「同名文件」** → 实测 `make_dir_recursive_absolute()` 在这个坑面前不报错，`_copy_dir()` 只是悄悄复制 0 个文件 → **正解**：不要在播种里判断成败，交给后面的 `_resolve_mod_roots()` 统一兜底。
2. **验证时想把 Godot 的 stdout 丢掉（`| Out-Null`）** → 日志全丢，看不出实际走了哪根 → **正解**：重定向到文件再 `Select-String -Pattern 'ModManager'`。
3. **`run_autopilot.ps1` 的 `-Godot` 默认值已失效**（`Godot_v4.6.2-stable_win64.exe` 不在了）→ 手动跑 Godot 时必须写真实路径 `C:\Users\a a\Desktop\godot.exe`，否则「没启动」会被判成安静通过。

## 给后来者的最简路径

1. 先确认需求是不是「只有一份分发文件时也要保证内置模组能跑」—— 是 → 加一个兜底根，别改播种逻辑。
2. 复制前先用 `test/run_autopilot.ps1 -Scenario probe_ext_script_load -Godot <真实路径>` 在**隔离用户目录**里跑一遍（它会真的启动游戏 → autoload 会真的跑）。
3. 想验证兜底分支：**把 `user://mods` 目录换成同名文件**（`New-Item -ItemType File`）⇒ 播种必然失败，看日志里「内置源 8 个」+ 模组照样装载；再删掉那个文件跑一次，应当回到「玩家目录 8 个」。

## 人工验证方法（没开窗口，画面 / 手感未实测）

1. 正常启动：日志应出现「模组加载根 —— 玩家目录 8 个 [...]」，各模组在模组页面上照常存在。
2. 把 `%APPDATA%/Godot/app_userdata/PVZ-Dream-Edit/mods` 整个删掉后启动：应当重新复制 52 个文件，模组照旧。
3. 在同一个路径上放一个**名为 `mods` 的文件**（挡住建目录）后启动：日志应出现「内置源 8 个」，已启用的模组**照样装载**（旧行为是全部静默失效）。
4. 导出成 exe 后至少跑一次：若日志里出现「内置源 8 个」，说明导出环节把 `user://` 那份转成了引擎读不出的形态 —— 此时把 `export_presets.cfg` 的 `script_export_mode` 改成 `0`（脚本按文本导出）重新导出再验一次。
