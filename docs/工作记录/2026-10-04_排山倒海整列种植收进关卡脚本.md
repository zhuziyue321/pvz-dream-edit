# 2026-10-04 · 其它 · 迷你游戏 12「排山倒海」整列种植从手持组件收进关卡脚本

> **任务类型**：其它（架构收拢：一关专属机制归位）
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 3 轮（1 轮勘察 + 1 轮改码 + 1 轮带窗口探针），开了游戏（带窗口跑 `probe_column_mode`）
> **验证方式**：打开游戏实测（`probe_column_mode` 15 项断言全过，含通关结算）
> **补充自**：无（同类可参照 [2026-10-04\_观星逻辑收拢进关卡脚本.md](2026-10-04_观星逻辑收拢进关卡脚本.md)）

## 目标

`is_mode_column`（柱子模式）只有 `minigame_12_column.gd` 打开，却在
`hand_component_character.gd` 里留了 6 处分支 + 一段专属兜底（虚影泄漏补丁）—— 违反硬约束 §1-8。
改成：手持组件只做通用校验（问格子能不能种），整列种植与整列虚影全部由关卡脚本自己创建与清理。

## 步骤

1. 先确认玩法口径（**这一步别省**）：任务描述写的是「只能种在第 N 列」，代码实际是
   「点一格 → 整列都种上」—— 两者是不同玩法。**先跟用户确认口径再动手**（本轮选了保留原版整列种植）。
2. 找现成落位模板：观星（`minigame_07_seeing_stars.gd`）已经示范了
   「专属逻辑全在关卡脚本 + `init_level_items()` 进关接线 + 关卡脚本自己收摊」，照它的结构写。
3. 手持组件删分支：`is_mode_column` 变量、`_ready_component` 的赋值、`enter_hand` / `mouse_enter` /
   `mouse_exit` / `click_cell` 里的判断、整个「柱子模式额外操作函数」region（含 `_clear_curr_data_column`）。
4. 关卡脚本接管：
   - `init_level_items()` 里给所有格子接 `signal_plant_create` / `cell_mouse_enter` / `cell_mouse_exit`，
     并订阅 `EventBus` 的 `hand_card_take` / `hand_card_release`；
   - `_on_plant_create()`：持卡时把同列其它「能种的行」补上同一种（坚果包扎术优先修复）；
   - 整列虚影：一行一个，形象取 `card.character_static.duplicate()`，挂
     `MainGameManager.canvas_layer_temp`（**不是** `item_root`：背景层在草坪之下会被盖住）；
   - `_free_column_items()`：断信号 + 退订事件 + 释放虚影，**幂等**（关卡结束与重进关都会走）。
5. 删掉已经没人读的关卡数据字段 `is_mode_column`（`level_data.gd`），同步改 `probe_levels.gd` 的日志行。
6. 写探针 `probe_column_mode` 带窗口跑，顺手把「手持组件源码里搜不到 is_mode_column」做成断言。

## 关键决策与理由

- **整列补齐挂在 `PlantCell.signal_plant_create` 上**，而不是去改本体 —— 本体只认识「一格」，
  「一整列」是本关语义；用自己的 `create_plant` 会递归触发同一信号，用 `is_filling_column` 挡掉。
- **没持卡时不补齐**：`curr_card == null` 直接返回，开局预置的 8 个花盆因此不会被整列复制。
- **虚影挂 `canvas_layer_temp` 而不是 `init_level_items` 给的 `item_root`** ——
  `item_root` 在 `CanvasLayerBG`（layer −10），会被草坪与植物盖住；挂临时层与手持组件的格子虚影同层，
  观感与改造前一致。
- **僵尸卡不参与整列种植**：本关传送带只发植物，僵尸分支没跟着搬（真有僵尸关要用时再在关卡脚本里补）。

## 踩坑

1. **任务描述与代码口径不一致** → 现象：「只能种在第 N 列」与「点一格种一整列」是两种玩法
   → 原因：任务描述是二手概括 → **正解**：动手前先问一句选哪个，别自己猜。
2. **探针 `var card := await _wait_conveyor_card(...)` 解析失败**（「Cannot infer the type」）
   → 原因：辅助函数没写返回类型 → **正解**：给辅助函数补 `-> Card`。
3. **探针跳最后一波没有通关** → 现象：`start_next_wave()` 调完僵尸没刷出来，一直停在 MAIN_GAME
   → 原因：最终波内部有「一大波僵尸正在接近」的 `await`，不 `await` 这个调用就只跑半个函数
   → **正解**：`await wave_manager.start_next_wave()`，再 `test_death_all_zombie` 清场。

## 给后来者的最简路径

1. 一关专属玩法要从本体组件里摘出来 → 先确认玩法口径 → 在关卡脚本里覆写 `init_level_items()`
   接格子信号 / 订阅 EventBus，写在关卡脚本里、自己收摊（幂等）。
2. 本体组件只留「问格子能不能种」这类通用校验（`judge_is_can_plant`），删掉所有 `is_xxx_mode` 分支，
   连关卡数据上的那个字段一起删（没人读就是死字段，探针里引用它的那行也要改）。
3. 验证写一个 `test/scenarios/probe_*.gd`，把「源码里搜不到那个玩法分支」做成静态断言，
   再带窗口跑一遍玩法本身 + 通关结算。
