# 2026-10-13 · 其它 · 关卡内手套的获取改为「与商店里的园艺手套同时获取」

> **任务类型**：其它
> **推荐度**：**推荐**（「模组的解锁要挂到本体既有状态上」照这个走：优先复用本体的存档记录，别自己再存一份解锁位）
> **耗时与成本**：约 1 轮对话，未开游戏
> **验证方式**：免验证 + 已给出人工验证方法（改动是纯判定口径，编译门禁 PASS 0 error）
> **补充自**：[2026-10-08_手套功能改造成模组.md](2026-10-08_手套功能改造成模组.md)（解锁口径那一段的后续调整）

## 目标

关卡内手套（搬植物那只）不再靠「通关冒险 4-5（序号 35）」解锁，改为**在商店买下园艺手套（$1000）的那一刻同时到手**：
存档里 `garden_data.bought_garden_tools` 里有园艺手套 = 关卡内手套已解锁。

## 步骤

1. 先摸清两套手套：关卡内手套是**模组**（`mods_builtin/glove/`，旧口径 `UNLOCK_ADVENTURE_LEVEL = 35`，
   由通关记录推导、不落库存档）；商店的园艺手套是**本体**（`GardenManager.E_GardenTool.GardeningGlove` = 4，
   买断写进 `garden_data.bought_garden_tools`，见 `global_garden_state.gd`）。
2. 改判据：`glove_settings.gd` 删掉 `UNLOCK_ADVENTURE_LEVEL`，改成常量
   `GLOVE_GARDEN_TOOL`（= 园艺手套）+ `is_unlocked()` 读 `GlobalGameState.is_garden_tool_bought()`。
3. 改调用方：`hand_component_glove.gd` 的 `is_unlocked()` 去掉参数（旧实现要传 `max_success_adventure_level`）。
4. 改模组页面文案：`glove_mod.gd` 的解锁说明与「进度」行改成「有没有买园艺手套 / 花园解锁了没」。
5. 拆掉旧赠礼演出：`adventure_04_06.gd` 里那段「戴夫送手套」的 8 句对话不再播（4-6 早于 5-5，
   改成商店口径后 4-6 根本拿不到手套，留着只会自相矛盾）；台词与手持物资源留在 `data/` 下没删。
6. 同步探针：`probe_glove_unlock` 整支重写（静态改成「买断记录 = 解锁」、实机改成买 / 撤园艺手套），
   `probe_hand` 的 `_set_glove_unlocked()` 从「改 4-5 通关状态」改成「改园艺手套买断记录」。
7. 同步文档：[手持物实现.md](../参考存档/手持物实现.md) §五、[模组机制.md](../参考存档/模组机制.md) §6.1、
   [选关界面与解锁.md](../参考存档/选关界面与解锁.md)、[验证流程.md](../验证流程.md)、
   [AI调试通道.md](../AI调试通道.md)、[架构总览.md](../../架构总览.md)。

## 关键决策与理由

- **解锁口径复用商店的买断记录，不再自己存一份** —— 原版里这两只本来就是同一只手套（原版手套只用于禅境花园），
  关卡内搬植物是它的同人扩展用法；跟买断记录走，玩家只买一次、存档只记一份，不用维护第二个解锁位。
- **`is_unlocked()` 改成无参** —— 它读的是当前存档而不是通关进度，`GloveSettings` 里对
  `Global == null` / `global_game_state == null`（还没进游戏、模组页面在编辑器里）做了兜底返回 false。
- **4-6 赠礼演出移除而不是改条件** —— 「只在已解锁时播」等于永不触发（手套最早要等 5-5 之后），
  留一句永不执行的代码比删掉更误导；资源文件保留，想恢复接在 `run_flow()` 开头即可。
- **模组侧引用本体枚举 `GardenManager.E_GardenTool`** —— 方向是「模组 → 本体」，符合边界规则
  （本体不 import 模组）；写 `const GLOVE_GARDEN_TOOL: GardenManager.E_GardenTool = ...` 显式带类型，
  避免把 int 喂给带 enum 注解的参数。

## 踩坑

1. `Array.has(int(tool))` 判买断会失效（存档走 JSON，读回来是 float 4.0）→ 本体已有注释，
   探针撤记录时也必须**逐个 `int()` 比**（`probe_glove_unlock` / `probe_hand` 都是这么写的）。
2. 改判据会连带探针：`GloveMod.is_unlocked(35)` 这种带参调用改成无参后，`test/` 不在门禁可达集里但跑起来必挂
   ⇒ 改解锁口径时**先搜一遍 `is_unlocked(` 的全部调用点**（本体 + 探针 + 文档）。

## 给后来者的最简路径

1. 定解锁依据（优先复用本体已有的存档字段，别新建解锁位）。
2. 改 `glove_settings.gd` 的判据 → 改 `hand_component_glove.gd` 的 `is_unlocked()` → 改 `glove_mod.gd` 的页面文案。
3. 全局搜 `is_unlocked(` / `UNLOCK_ADVENTURE_LEVEL`，把探针与文档一次改完。
4. 跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`。

## 人工验证方法（本次未开游戏）

1. 开手套模组，用一个**没买园艺手套**的档进任意可操作草坪的关卡：卡槽里**没有**手套，按 G 无反应。
2. 通关 5-5 解锁花园 → 进商店第 3 页买下「园艺手套」$1000 → 再进任意关卡：卡槽里**出现**手套，
   按 G 能拿起植物并搬到另一个格子（植物状态不中断）。
3. 模组页面（控制台 → 模组 → 手套）：没买时显示「还没买园艺手套 —— 商店（通关 5-5 解锁花园后上架）…」，
   买了之后显示「已买下园艺手套 —— 关卡内手套已到手」。
4. 进 4-6：开场**不再有**「戴夫送手套」对话，直接展示僵尸。
5. 探针：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_glove_unlock -Windowed`
   与 `-Scenario probe_hand -Windowed`，输出 `[GLOVEUNLOCK] result=PASS` / `[HAND] result=PASS`。
