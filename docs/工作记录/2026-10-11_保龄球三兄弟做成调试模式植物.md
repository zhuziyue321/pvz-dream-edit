# 2026-10-11 三种保龄球做成「调试模式」可选的植物

> **任务类型**：其它（已有内容的开关化）
> **一句话**：三种保龄球**本体与卡片早就齐了**（植物场景 + AllCards 第二页的卡位），差的只是「从来不给玩家解锁」——
> 加一个控制台开关「调试模式」，勾上就把 1001/1002/1003 并进已解锁植物，它们随即出现在选卡界面第 2 页的头三格。

## 1. 先确认现状（这一步省不得）

用户一句话需求进来时，仓库里其实**已经有两件之一**：

- 植物：`CharacterRegistry` 的 `P1001/P1002/P1003` + `plant_wall_nut_bowling{,_bomb,_big}.tscn` + `plant_info_data` 登记齐全；
- 卡片：`all_cards.tscn` 的 `PlantCards2`（`all_cards.gd` 里当成「第二页植物」）第 1~3 张就是这三种，`content_id` = 1001/1002/1003。

所以这次真正要补的是第三件：**解锁**。
判据：`CardSlotCandidate` 只把 `GlobalGameState.curr_plant`（已解锁）里的植物卡容器置为 visible，
而 1001~1003 从不进 `curr_plant`（`ConstPlantUnlock` 只按冒险关卡给白卡、商店给紫卡），玩家自然一辈子选不到。

> **套路**：这类「看着没做完」的需求，先分别在「类型注册 / 场景 / 数据表 / 卡片容器 / 解锁列表」五处各查一遍，
> 查出到底缺哪一环再动手 —— 直接照字面新建一个植物会立刻撞上「卡位重复注册」报错。

## 2. 页码怎么定的（结论：不用调顺序）

选卡界面不是按 `PlantCards / PlantCards2` 分容器翻页的，而是按**下标**：

```gdscript
## CardSlotCandidate._init_card_slot_candidate_plant()
var num_card_every_page = grid_container_plant.get_child_count()   # 模板里的占位数量 = 48
page_i = int(float(i) / num_card_every_page)                        # i = 该卡在 all_plant_card_prefabs 里的顺序
```

于是 card_id 0~47（`P001~P048`）在第 1 页，**48/49/50 正好是第 2 页的头三格**。
`PlantCards2` 的子节点顺序恰好是 `Card(1001) / Card2(1002) / Card3(1003) / Card4(P049)`，所以什么都不用挪。
（第 4 格是 P049 反向双发 —— 它本来就在那儿。）

## 4. 两个坑

1. **开关不能只写在内存里**：`SaveService._build_curr_plant()` 每次读档都用「存档记录 ∪ 通关推导」重建 `curr_plant`，
   只把 `is_debug_mode` 置 false 的话，上一次开着调试写进存档的那三株**下次读档还会回来**。
   所以 `_sync_debug_mode_plants()` 关掉时必须真的 `curr_plant.erase()`，而且要在
   `reload_session_for_current_user()`（读档 + 读配置之后、也是切用户的唯一入口）再同步一次。
2. **`selected_cards` 要跟着清**：「重选上次卡片」是照存档条目直接点待选卡位的
   （`CardSlotNorm._on_re_card_button_pressed`），卡片容器在关掉调试后已经不可见，
   条目留着就会选进去一张看不见的卡 → 清容顺手也要清存档条目。
