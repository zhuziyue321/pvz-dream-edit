# 2026-10-17_角色攻击力字段接入子弹伤害

> **本次任务**：给植物 / 僵尸加「攻击力」字段，发射子弹时把攻击力写进子弹
> **耗时 / 轮次**：约 3 轮（未开游戏，编译门禁 PASS）
> **推荐度**：推荐

## 目标

角色（植物 / 僵尸共用）身上有一个可配的攻击力 `attack_value`，发射类攻击时它作为伤害值进入子弹，覆盖子弹场景自身的 `attack_value`；不配时行为与改动前完全一致。

## 最简路径（步骤）

1. `src/entities/character/character_base.gd`：新增 `@export_group("角色攻击力")` + `@export var attack_value: int = -1`（默认 -1 = 不设置，保证存量行为不变）。
2. `src/entities/character/components/attack_behavior_component/component_attack_bullet_base.gd`：新增 `get_shoot_attack_value()` 实现三级优先——组件 `attack_value_bullet` > 角色 `attack_value` > -1（让子弹用自己的场景值）；`get_bullet_paras()` 的 `AttackValue` 键改调它。子弹侧 `init_bullet()` 本来就只对 >0 的值做覆盖，一行不用改。
3. 子类若自己抄了 `get_bullet_paras()` 要同步补 `AttackValue` 键（豌豆僵尸 `component_attack_zom_botany_pea.gd`）。
4. 检查全仓有没有子类已声明同名 `attack_value`——GDScript 不允许成员变量被基类同名成员遮蔽，地刺 / 钢地刺两个植物脚本里各有一份 `@export var attack_value := 20`，删掉声明改用继承字段（`.tscn` 里已显式存 20，行为不变）。
5. 文档同步：`docs/参考存档/伤害系统.md` §7 补「角色攻击力怎么流到子弹」三级优先表；`docs/参考存档/子弹说明.md` §2 初始化参数表补 `AttackValue` 行。
6. 交付前跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`，确认 `real compile errors = 0`。

## 弯路 / 踩坑（三段式）

- **试过**：直接在 `component_attack_zom_botany_pea.gd` 的 `_get_bullet_paras()` 里调 `get_shoot_attack_value()`。
- **因为**：该组件 extends 的是 `AttackComponentZombieNorm`（啃咬组件），不是 `AttackComponentBulletBase`，基类没有这个方法，编译报 Parse Error。
- **结论**：按该文件「只抄一份最小实现」的既有模式，本地写了个只读角色 `attack_value` 的 `_get_shoot_attack_value()`（该组件没有组件级覆盖字段，只有角色一级）。

## 推荐度与理由

推荐。字段放角色基类、取值逻辑放发射组件基类，与仓库「数值归场景配、宿主只转发」的既有口径一致；默认 -1 哨兵值让 40 多个存量植物 / 僵尸场景零影响。注意：啃食 DPS（`init_attack_value_per_min`）、炸弹（`bomb_value`）、大嘴花（`eat_attack`）不走这条链，改那些数值要去各自字段。
