# 2026-10-03 · 资源改名 · 把 `data/level_date_resource/` 移到仓库根目录并改名 `src/levels/`

> **任务类型**：资源改名
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（纯路径搬迁 + 全局替换）
> **验证方式**：免验证 + 已给出人工验证方法（见「验证」）
> **补充自**：无（同类旧记录里没有目录搬迁的条目）

## 目标

- `data/level_date_resource/` → 根目录 `src/levels/`；
- 全仓库 `res://data/level_date_resource/...` 引用改成 `res://src/levels/...`；
- 改完仓库里 `level_date_resource` 出现次数为 0，且每个 `res://src/levels/...` 引用都指向真实存在的文件。

## 步骤

1. 先 `search_content` 全仓库搜 `level_date_resource`，确认引用只有 `res://data/level_date_resource` 这一种写法（69 个文件；`.tscn` 的 `[ext_resource ... path=]`、`.gd` 常量 / 探针、`.tres`、`addons/todo_controller/config/config.tres`、docs）。
2. `Move-Item -LiteralPath "resources\level_date_resource" -Destination "level"`（同盘整目录改名，`.uid` 跟着走，uid 引用不断）。
3. 全局替换（PowerShell，UTF-8 无 BOM 写回，保留原换行）：
   - `res://data/level_date_resource` → `res://level`
   - 再 `data/level_date_resource` → `level`
   - 再 `level_date_resource` → `level`（兜住 md 里的裸目录名）
   - 扫 `.gd/.tscn/.tres/.md/.cfg/.json/.txt/.gdshader/.import`，排除 `.godot\` `node_modules\`。
4. 校验：正则抽出所有 `res://src/levels/...`，逐个 `Test-Path` —— 160 条引用里 30 条 `.tres` 缺失，核对后确认是**关卡脚本化重构遗留的旧引用**（`src/levels/` 下已无 `.tres`），与本次搬迁无关，未动。
5. 同步文档指针：`data/AGENTS.md` 子目录表、`data/README.md`、`src/levels/AGENTS.md` + `src/levels/README.md`（新建）、`docs/README.md` §3 索引、根 `AGENTS.md` §6 索引表各补 / 改一行。

## 关键决策与理由

- **整目录 `Move-Item` 而不是逐个文件搬运** —— `.uid` 与脚本在同一目录内，整目录改名让 uid 引用自动保持有效（硬约束 §1-5 的前提）。
- **替换顺序先 `res://` 长串后短串** —— 否则 `level_date_resource` → `level` 会把 `res://data/level_date_resource` 先改成 `res://data/level`，再补一刀也行但容易漏，按长→短最稳。
- **不加 `git mv`，用文件系统移动后 `git add -A -- level data/level_date_resource`** —— 见踩坑 1。

## 踩坑

1. **`git mv` 报 `fatal: bad source, source=data/level_date_resource/mode_adventure/adventure_01_01.tres`** → 该 `.tres` 在工作区**早已被删但未提交**（关卡脚本化重构的未提交改动），`git mv` 要求源文件在磁盘上存在 → **正解**：直接用 `Move-Item` 搬目录，之后 `git add -A -- <旧路径> <新路径>` 让 git 自己配对（结果：`A x246 / R100 x3 / D x105`，删除项就是那批早就不存在的 `.tres`）。
2. **Godot 编辑器开着会"复活"旧文件** —— 搬完后 `data/level_date_resource/script/timeline_event/level_timeline_event_tutorial_end.gd` 又出现了，内容与新位置那份完全一致（编辑器持有该文件并回写，见硬约束 §1-5「批量改名必须先关闭 Godot 编辑器」）→ **正解**：搬之前先关编辑器；已经发生的就删掉残留目录，并**关掉 Godot 再重开**，让编辑器按新路径重建 uid 缓存。
3. **替换脚本会顺手改到 `.backup_levels_20261002/` 这类未跟踪的备份目录**（110+ 个 `.tres`）→ 本例中改完内容仍自洽（备份里的引用也指向新路径），但严格说备份应保持原样 → **正解**：下次跑全局替换前先排除 `.backup*` / 隐藏目录。

## 验证

- 免验证理由：纯路径搬迁，无玩法逻辑改动。
- 人工验证方法（打开游戏前先看这两条）：
  1. 全仓库搜 `level_date_resource` → 除本记录文件里的历史叙述外 0 条；
  2. 打开游戏进冒险 1-1 / 解谜 / 生存各一关，确认能正常载入关卡（关卡路径由 `LevelRegistry.LEVEL_DIR = "res://level"` 扫目录得到）；**记得先关闭再重开 Godot 编辑器**。

## 给后来者的最简路径

1. 关 Godot 编辑器。
2. 搜 `level_date_resource`（或任何旧目录名）确认引用写法。
3. `Move-Item` 整目录（含 `.uid`）。
4. 全局替换（长串 → 短串，排除 `.godot\` `.backup*`），UTF-8 无 BOM 写回。
5. 抽出所有 `res://<新目录>/...` 逐个 `Test-Path` 校验。
6. `git add -A -- <旧路径> <新路径>`；改目录指针 md（`data/AGENTS.md` + 新建 `src/levels/AGENTS.md` `src/levels/README.md` + `docs/README.md` §3 + 根 `AGENTS.md` §6）。
