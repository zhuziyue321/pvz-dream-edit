## 原版口径

**① 魅惑态发射点与方向**（`UpdateZombiePeaHead()` / `UpdateZombieGatlingHead()` 的
`DO_FIX_BUGS` 分支，两个参照项目逐字一致）：

```cpp
if (mMindControlled)  // hypnotized: fire a friendly pea instead
{
    aOriginX += 90.0f * mScaleZombie;
    Projectile* aProjectile = mBoard->AddProjectile(aOriginX, aOriginY, mRenderOrder, mRow, ProjectileType::PROJECTILE_PEA);
    aProjectile->mDamageRangeFlags = 1;

```

即：发射点在普通口径上再前移 90（豌豆僵尸是普通僵尸，s = 1），改发**植物方**豌豆
（不带 `MOTION_BACKWARDS` → 朝右飞，打右边还没被魅惑的同类）。

**② 定身停表**（`Zombie.cpp` 通用更新里）：

```cpp
if (mPhaseCounter > 0 && !IsImmobilizied())
{
    mPhaseCounter--;
}
```

`IsImmobilizied() = mIceTrapCounter > 0 || mButteredCounter > 0` —— **寒冰菇冰冻停滞 / 玉米投手黄油**
时 `mPhaseCounter` 不递减，吐豆僵尸同样不开火；冰豆 / 冰瓜的**减速**不算（只减速、不停表）。

## 复核结论：两条「差异」不成立

1. **发射频率**：`mPhaseCounter = 150`，逻辑 tick = `PvzpLib/Reanimator.h` 的
   `SECONDS_PER_UPDATE = 0.01` → **100 Hz** → 150 tick = **1.5 秒**。仓库 `attack_cd = 1.5`
   本来就对。（我先前按 60fps 口算成 2.5s，是错的；仓库
   `component_attack_zombie_norm.gd` / `zombie_jalapeno.gd` 的注释也一直写着 100 tick/s。）
2. **击退位移（mImageOffset）**：`Zombie.cpp` 里 `mX = (int)mPosX`、`GetDrawPos()` 里
   `mImageOffsetX = mPosX - mX` —— 它只是 `mPosX` 的**小数部分**（< 1px），不是什么击退量。
   原版发射点公式直接用连续量 `mPosX`，仓库用头节点真实世界位置（同样连续），两者**等价**。
   2026-10-24 上一份工作记录里「原版漏算 mImageOffset」的说法不成立，以本条为准。

## 关键决策与理由

- **魅惑偏移照抄原版 +90，不用镜像取反**：镜像取反得到的是 (24, 14)，原版是 (66, 14)；
  任务是「对齐原版」，且头节点世界位置已含镜像，直接叠原版常量才是可复算的。
- **方向与阵营分开管**：阵营不用动 —— `BulletCampConfig.get_owner_camp()` 已随 `is_hypno`
  翻成植物方（豌豆变友好、只打僵尸）；只有方向（原版 `MOTION_BACKWARDS` 的有无）要在组件里翻。
- **停表沿用仓库既有 pattern**：`speed_product == 0 → timer.paused = true`，
  剩余时间保留，与原版「计数器冻结」语义一致；不引入新的 `_physics_process` 轮询。

## 踩坑

1. **先按 60fps 把 150 tick 算成 2.5s**，差点把 `attack_cd` 从 1.5 改成 2.5。
   判据：`SECONDS_PER_UPDATE = 0.01`（100Hz）。涉及「原版 tick 数 → 秒」的换算一律先查这个常量。
2. **`mImageOffset` 不是击退位移**，是 `mPosX - (int)mPosX` 的小数部分；
   别信「只在被击退时非零」的转述，回代码看赋值处。
3. **探针跑不起来**：用户的 Godot 编辑器（`godot - man.exe --editor`）开着，
   `run_autopilot.ps1` 的 stale-process 守卫会直接 `STALE_PROCESS` 拒绝启动；
   **不能** `-KillStale`（那可能是用户的编辑器）。要么等编辑器关掉，要么用独立临时目录
   手动跑 `godot.exe --headless --path <项目> -- --scenario=res://test/scenarios/<name>.gd`
   （注意 APPDATA 重定向到临时 userdir，输出别用共享的 `%TEMP%\pvz_autopilot`）。
