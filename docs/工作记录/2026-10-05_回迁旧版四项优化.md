## 目标

对照 `PVZ-Godot-main/`（上游快照）找出当前版本退化的点并回迁四项：

1. **场景过场**：旧版 `scene_transition.gd`（autoload，淡入淡出 + 后台预载 + 防连点）→ 新版只有 `GlobalUtils.change_scene` 硬切。
2. **按钮悬停反馈**：旧版 `PVZ_button_base.gd` 有 hover 1.06 放大回弹 → 新版只剩按下位移。
3. **僵尸场外加速入场**：旧版 `zombie_000_base.gd` 出生在可见区外时速度 ×2、进可见区恢复 → 新版整段被删。
4. **HUD 锤子入口**：旧版卡槽工具栏有锤子按钮（快捷键 + 冷却遮罩）→ 新版锤子关无任何 HUD 入口。

## 步骤

1. 先做对照分析（文件名集合 diff + 按类名/信号名配对读码），把「真缺失」与「已改名/主动删除」分开，避免误回迁。
2. 场景过场：新建 `src/core/autoload/scene_transition.gd`（CanvasLayer layer=100），`project.godot` 注册 `SceneTransition`；`GlobalUtils.change_scene` 改为委托，**19 处调用点零改动**。
3. 按钮悬停：`src/ui/pvz_button_base.gd` 补 `mouse_entered/exited` + TRANS_BACK 回弹 Tween（照抄旧版，含 `pivot_offset = size/2` 与悬停前 position 记录）。
4. 场外加速：`character_base.gd` 的 `E_Influence_Speed_Factor` 末尾加 `OutBattlefield`（**加末尾**，枚举被当字典键用，改中间位置会动到已有 int 值）；`zombie_base.gd` 的 `ready_norm()` 末尾 `call_deferred("judge_battlefield_update_speed")` + 0.3s Timer 轮询。阈值不写死 800：`MainGameCamera.CAM_POS_ORI.x + VIEW_WIDTH = 810`（相机归位时可见区右缘，分辨率改 800x600 后的口径）。
5. HUD 锤子入口：
   - 新建 `src/ui/card/hammer_in_ui.gd`（class_name UIHammer，TextureRect，与 UIShovel/UIGlove 同款结构：槽背景 + 图标 + Button + 快捷键 Label + 冷却遮罩 ColorRect）。
   - `main_game_base.tscn` 在 ShovelContainer 下加 `UIHammer`（offset 140..210，跟铲子 0..70 / 手套 70..140 排成一排），`load_steps` 90→92，加 2 条 ext_resource（不带 uid，仓库已有先例）与 1 条 connection。
   - `hammer.gd`：订阅 `main_game_click_hammer`（HUD 点击/H 键 → 切换拿起/收起）；`set_is_used` 推 `hammer_state_changed`；新增 `@export cool_time := 0.0`（挥中僵尸后收起 + 推 `hammer_cool_down`），**默认 0 保持两关连锤现状**；挥锤 `_input` 改 `_unhandled_input`（点 UI 不挥锤，点草坪才挥）+ 右键收起。
   - `LevelRuleHammerZombie.install()` 里 `_install_hud()`：`mg.get_node_or_null("%UIHammer").visible = true` —— 本体不认识锤子，入口由玩法规则点亮（硬约束 §1-8）。
   - `project.godot` 加 `ShortcutKeys_Hammer`（物理键 H=72）。

## 关键决策与理由

- **过场不做 BGM 映射表**：各主场景自己的 `_ready` 会 `play_bgm`（start_menu_root:37 / choose_level:98 / main_game_manager:401 / garden_manager:143），而 `change_scene_to_packed` 在全黑期间才执行，换曲天然落在黑屏内，效果等同旧版「全黑瞬间换曲」还省一份路径表。
- **`GlobalUtils.change_scene` 保持 fire-and-forget 签名**：全部调用方零改动；过场内部自己 await。`reload_current_scene`（重开本关）不走过渡，保持原行为。
- **锤子冷却默认 0**：旧版冒险 2-5 的 60 秒冷却会让本关上百只僵尸根本打不完（旧版本身即如此设计，无法通关），回迁时保留**能力**（`cool_time` 可配 + HUD 遮罩）但默认不启用，不改变现有关卡节奏。
- **HUD 入口常驻场景、由规则点亮**：不在本体写 `is_hammer` 字段 / `card_manager` 分支，遵守硬约束 §1-8。
- **`_install_hud` 里不写 `as UIHammer`**：见踩坑 1。

## 踩坑

1. **现象**：首次带窗口跑 `probe_hammer_zombie` 全挂，stderr `Parse Error: Could not find type "UIHammer"`，连锁把 `minigame_15_hammer_zombie.gd` 拖到编译失败。
   → **原因**：新建脚本的 `class_name` 要等 Godot 编辑器重建全局类缓存（`.godot/global_script_class_cache.cfg`）后才对**运行时**可见；命令行直接跑游戏不会扫。
   → **正解**：引用方不写该类型标注（`var ui_hammer: Node = mg.get_node_or_null(...)`），`.tscn` 里按 path 挂脚本不受影响。等编辑器打开过一次后，类型标注才能用。
2. **现象**：第一版探针输出 `Could not find type` 前还有一个 `Cannot infer the type of "ui_hammer"`。
   → **原因**：`:=` + `as UIHammer`（右侧类型解析失败）双重踩 1 的坑。
   → **正解**：显式 `: Node` 类型。
3. 旧版冒险 2-5 无 `is_hammer` 字段 → HUD 按钮不显示但锤子照常生成：分析阶段差点把「HUD 入口 + 60s 冷却」当成 2-5 的玩法回迁，读出怪波次（10 波×10 组上百只）才发现旧版这套在 2-5 根本不可通关，属上游自身的残留缺陷。

## 遗留（人工验证项）

- 探针断言不了「观感」：按钮 hover 回弹、切场景黑幕时长（0.22s×2）是否舒服、锤子入口图标/H 标签位置是否与铲子/手套对齐、冷却遮罩视觉 —— 需人眼确认。
- 场外加速只有「不崩」级覆盖（`probe_init` 明细里僵尸 x=932 时 judge 正常启动）；「走进 810 内速度恢复」无断言，肉眼在 1-1 开局看僵尸入场是否明显变快即可。

## 给后来者的最简路径

1. 回迁旧版功能前先做「真缺失 vs 改名/主动删除」判别（用 `search_content` 按类名/信号名/中文注释在新仓全仓搜），别按文件名 diff。
2. 新建带 `class_name` 的脚本当天就要被其它脚本按类型引用 → **别写类型标注**，或先用 `Node` 接住；跑一次编辑器后类缓存才可用。
3. 统一切场景入口只改 `GlobalUtils.change_scene` 一处，调用方零感知。
4. 收尾按 E-04/E-05 归档（本文即）。
