> **推荐度**：**推荐**（下次「接一只 PVZ2 角色」照这个走；帧数上千的角色只能走这条）
> **耗时与成本**：约 1 轮对话 / 未开窗口 / 无头探针 `probe_pvz2_celery_anim` PASS failed=0
> **验证方式**：免验证 + 已给出人工验证方法（见文末）
> **补充自**：[2026-10-15_PVZ2模组菜问.md](2026-10-15_PVZ2模组菜问.md)（菜问是另一条烘焙路线，对比着看）

## 目标

`tmp/` 里有一份 PVZ2 素材（`pvz2合计`）+ 一份第三方的 PAM 运行时草稿（`Core/` `Base/`）。
要求：修掉草稿里必要的问题，把**潜伏芹菜（Celery Stalker）**的动画导进 `mods_builtin/pvz2/`。

## 做了什么

1. **先摸清素材**：`pvz2合计` 里只有原始 `.PAM`（297 KB，二进制）和一张图集
   `PLANTCELERYSTALKER_1200_00.png`（952 KB，1024×1024）；`.PAM` 的动画数据要靠
   PopStudio 导成 json 才读得动。**PopStudio 没有命令行**（`--help` 只弹 GUI 窗口），
   所以那份 json 由人工导了一次（4.29 MB，573 帧 / 94 图 / 52 sprite）。
2. **图集矩形**从 `pvz2-plants-image/plant1/PROPERTIES/RESOURCESPLANT1.json` 里抽：
   潜伏芹菜 117 条 `ax/ay/aw/ah`，全在同一个图集，`aw/ah` 与 PAM 的 `size` 逐条相等。
3. **写离线烘焙工具** `tools/bake_pam_bin.py`：json + 矩形表 + 图集 → 自包含 `.pam.bin`
   （格式 PAM2 v1，带回读自检）。产物 714 KB。
4. **落位** `mods_builtin/pvz2/`：`celerystalker/`（bin + 图集 + 场景）、`pam/`（运行时 5 个脚本）。
5. **写探针** `test/scenarios/probe_pvz2_celery_anim.gd`，无头 PASS failed=0。

## 关键决策与理由

- **不生成节点树**：菜问那株是 57 个 `Sprite2D` 复用槽 + `AnimationPlayer`（4.8 MB `.tscn`）。
  潜伏芹菜 573 帧 × 平均 24 个部件，换成动画资源要几十万关键帧 ⇒ 只收「一张图集 + 一个 bin」，
  由一个 `Node2D` 在 `_draw()` 里画四边形。
- **运行时放模组目录、不写 `class_name`**：模组会被拷到 `user://mods/` 跑，那里的脚本不注册全局类
  （与 `pvz2_mod.gd` 同一条口径），相互引用一律 `preload`。
- **bin 而不是 `.tres`**：`.tres` 存 `PackedByteArray` 会膨胀到 5~10 倍；`.bin` 是非资源文件，
  代价是导出要加 `include_filter`（已加）。
- **不做半截兜底**：贴图按 `part_name` 精确匹配，单图集模式才整张复用；匹配不上就 `Log.error`
  + 不画，绝不拿别的图顶上（顶上去的画面是「能跑但部件错乱」，比报错难查得多）。

## 踩坑

1. **草稿的 `animation_finished` 每帧连发**：非循环状态播完后 `_state_time` 不再增长，
   草稿用「前后帧号相等」判结束，于是**每帧**发一次；它自己声明了 `_finish_emitted` 却从没读过。
   本版改成时间轴判据 + `_finished_emitted` 幂等（探针里专门有一条「只发 1 次」）。
2. **草稿每个实例各自解析一遍 `.bin`**：场上 20 株就解析 20 份（几万个 `RefCounted`）。
   改成按路径的静态缓存共享（探针里验「两个实例 `_data` 是同一个对象」）。
3. **PAM 的 `change.transform` 是部分更新**：6 元完整矩阵、**3 元 = `(旋转弧度, x, y)`**、
   2 元 = 只改平移。第一版当「一律 6 元」处理，打包长度直接对不上（少 99 KB），
   而且会把旋转件打飞。3 元那条是对着同一实例的 6 元帧反推出来的
   （`-0.662 rad` ↔ `-37.87°`，同一平移 `(183.2, 173)`）。
4. **`.tscn` 的 `ext_resource` 相对路径**：`path="pam/pam_animator.gd"` 会按**场景所在目录**解析，
   报 `referenced non-existent resource`；写 `res://` 绝对路径（或 `../pam/...`）。
5. **GDScript 静态推断**：`var x := 某个 Variant 表达式` 直接编译失败，必须写 `var x: int = ...`；
   `Log.warn()` 最多 5 个参数（msg + 4），多了要自己 `%` 拼。
6. **`.bin` 不进导出包**：`export_filter="all_resources"` 只导资源，非资源文件要靠 `include_filter`。
7. **`tmp/` 会让 Godot 反复导入上万张 PVZ2 素材**：加了 `tmp/.gdignore` 让引擎整个忽略该目录
   （要让引擎重新看见临时素材时删掉这个文件）。

## 给后来者的最简路径

1. 拿到 PAM 的 json（PopStudio 导，它的 json 才有 `main_sprite.frame`；`pvz2_out/*.pam.json`
   那批是坏解码 —— 只有 image，sprite 帧全空）。
2. `python tools/bake_pam_bin.py --json ... --resources ... --atlas ... --atlas-dst ... --out ...`
   （`--check-only` 先验一遍；它会打印 image / 帧 / 状态 / 实例总数并回读自检）。
3. 模组目录放 `xxx_anim.tscn`（挂 `pam/pam_animator.gd`、`binary_path` 指 bin、装扮填 `hidden_parts`）。
4. 探针照 `probe_pvz2_celery_anim.gd`：数据 / 贴图绑定 / 状态帧数 / 装扮 / 循环与单次 / 缓存共享。
5. `check_scripts.ps1` 过了再 `run_autopilot.ps1 -Scenario probe_xxx`；导出前确认 `include_filter`。

## 人工验证方法（画面类，机器只能证明「数据对」）

1. 开游戏 → 模组页面打开「PVZ2」→ 进任意关卡。
2. 临时把 `celerystalker_anim.tscn` 拖到场上某个 `Node2D` 下（或照 §6.7 做成植物），
   应该看到**不带海盗帽**的潜伏芹菜在做待机动作；`attack` 段能看到拳头往左打、撞出白色冲击星。
3. 关注三点：比例（`.tscn` 目前 `scale = 1`，当植物用时按本体植物尺寸缩）、
   站位（画布 390×390 以中心为原点）、图层（不该压住血条 / 卡片冷却遮罩）。

## 补充 / 评价

### 2026-10-17 · 补：动画「冻住几秒再突然跳一下」——烘焙时帧快照被别名共享

当时只验了「状态帧数 / 播放推进 / 只发一次 animation_finished」，**没验画面**，于是漏了这个：

- **现象**：场上（关卡内也一样）帧号在正常推进，但**整株冻住几秒、零件一换又突然跳一下**。
- **根因**：`tools/bake_pam_bin.py` 的 `flatten_frames()` 写的是
  `timeline.append([active[k] for k in sorted(active)])` —— 把 `active` 里那个实例 dict
  **直接**放进帧列表。后续帧的 `change` 就地改同一份 dict（`xform` / `color` / `anim_frame`），
  于是**每一帧都在改历史帧**，573 帧里 459 帧和前一帧一模一样（`idle` 50 帧只剩 21 种姿态）。
  参考工程 `tmp/Core/pam_instance_state.gd` 的 `snapshot()` 本来就是拷贝，是 Python 移植时丢的。
- **为什么自检是绿的**：`read_back()` 只比 `index / resource / is_sprite` 和帧数、实例数，
  变换和颜色没比。现已补上逐帧 `xform / color / anim_frame` 比对，并把
  「相邻帧完全相同占比」打进自检（> 50% 直接失败；本次修完 0.7%，坏的时候 ~80%）。
- **取证手法**（下次查「动画卡」照这个走，比肉眼可信）：
  1. 直接读 bin 数「实例集合+变换完全相同的相邻帧数」——冻结=占比极高；
  2. `SubViewport` 单独渲染播放器，逐帧 `get_texture().get_image().get_data()` 比字节，
     冻结时会出现长串「像素没变」（修前 41/90，修后 0/100）；
  3. 关卡内逐帧记「帧号 / 状态时间 t / is_processing / delta>50ms / TreePauseManager 暂停」，
     用来区分「时间停了」和「画面没换」——本次证明**时间一直在走，是画面没换**。
- **修完**：重烘 `celerystalker.pam.bin`（731432 字节，sha1=65366b98cef4），
  `probe_pvz2_celery_anim` / `probe_pvz2_mod` 均 PASS。
