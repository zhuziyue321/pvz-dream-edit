## 目标

用户点名要求「僵尸博士放僵尸应该按照原版逻辑」。此时 `zombie_boss.gd` 是当天刚推倒重写的**参考项目口径**
（每轮一只、行号 0~4 随机、前 2 轮 `POOL_EARLY`、第 3 轮起 `POOL_LATE`），本次把**放僵尸这一项**改回原版：

1. 开局固定剧本：4 只普通 → 4~5 只路障 → 低头吐球 → 4~5 只铁桶（偶尔混 1 只路障）→ 再低头吐球。
2. 剧本走完后类型完全随机，且**不再出普通僵尸**；随机池补上原版 Summoned 列表里漏掉的跳跳（`Z019Pogo`）。
3. 投放的**行**优先挑「小推车还在」的行（原版会避开清洁车已被僵尸触发的行）。
4. 一批是**连着放**，不是一只一停。

**只改放僵尸**：踩踏范围（单行 4 列）、蹦极 / 房车解锁时机、死亡不清场这几项用户没点名，保持参考口径不动。

## 关键决策与理由

- **只改被点名的那一项，其余列出来给用户挑** —— 上一轮「闷头全改」的代价是全部被推倒重来
  （见 [2026-10-05\_僵王放僵尸对齐原版.md](2026-10-05_僵王放僵尸对齐原版.md) 的教训）。
  本次在反馈里明确列出「踩踏 2 行 × 4 列 / 蹦极·房车按低头次数解锁 / 死亡清场」这三条**仍是参考口径、未动**。
- **剧本做成可断言的数据而不是写进流程代码** —— 探针可以直接读 `_build_opening_script()` 逐条比对，
  不靠「跑几分钟看它放了啥」这种不可复现的验证。
- **剧本期间冻结低头随机冷却** —— 原版开局两次低头是剧本里的固定节点；不冻结的话 20 秒冷却会抢在剧本前面，
  「先放 9 只再低头」永远走不出来。
- **投放动画播完再接下一只，不足 `SPAWN_GAP_BY_STAGE` 的部分才补等** —— 投放动画 `length = 1.75s`，
  gap 是 3.5 / 3.0 / 2.6，直接 `await` 两个时间会拖到 5s+/只；用 `maxf(gap - anim_len, 0)` 才既用上
  参考的间隔表又不磨叽。
- **删 `POOL_EARLY` / `spawn_early_rounds` 而不是留着当死常量** —— 剧本里类型是写死的，
  这两个常量只剩「前 N 轮分池」一个用途，留着就是误导（会让人以为还在按轮数分池）。

## 踩坑

1. **探针第一条断言写成 `types == [norm]`，实际 types 是 `[1,1,1,1]`（4 只）** → 长度不等，`==` 恒 false。
   → **正解**：断言改成 `size() == OPENING_NORM_COUNT and all(t == norm)`；
   「一批 N 只」的断言别用「等于单元素数组」表达。
2. **`_batch()` 里 `types` 是 `Array[int]`、`Dictionary` 取出后是 `Array`** —— 混 1 只路障那段写
   `bucket_types["types"][i] = cone` 没问题，但探针侧要显式声明 `var x: Array = ...get("types", [])`
   才能用 `.all()` / `.count()`，不然静态类型推不出来。
3. **探针里把推车 `is_moving` 置 true 会让它真的开走并 `queue_free()`** —— 断言完要还原
   （`for m in movers: m.is_moving = false`），否则本局的推车被探针测没了，后半程断言全飘。

  ① **踩踏 2 行 × 4 列** —— 候选从「有植物的行」改成「**行对起始行**」，结算从压 1 行改成
  `_smash_stomp_rows()` 压 `STOMP_ROW_COUNT` 行，**音效提到结算函数里**（放逐行会响两声）；

  `_forced_next_action`，`_build_round_queue()` 里它排在**最前**（比踩踏优先），两次解锁后每轮 50% 追加；
  ③ **死亡清场** —— `_die()` 里在推 `boss_defeated` 之前调 `zm.death_all_zombie()`。

  用户第二轮直接说「这三条都要」，没有任何返工。**列差异清单比闷头全改或全不动都好**：
  全改会被推倒（当天已经发生过一次），全不问则要猜用户想要哪几条。
