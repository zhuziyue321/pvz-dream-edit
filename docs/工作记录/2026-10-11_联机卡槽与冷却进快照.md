## 目标

开打之后，客户端的出战卡槽**整体以主机为准**：有哪几张卡、每张还剩几秒冷却都照主机下发的快照摆。
改之前主机改了卡槽 / 改了冷却，客户端那一局完全不会跟着变。

⚠️ **选卡阶段不动**：`CHOOSE_CARD` / `RE_CHOOSE_CARD` 两端仍**各挑各的卡**
（[联机模组.md](../参考存档/联机模组.md) §4.2.2 只保证不重复），照主机覆盖会把玩家刚挑好的卡冲掉。

## 步骤

1. 先问清口径（快照是**主机 → 客户端**单向的，"放进快照"有四种读法，改法差别很大）：
   确认是"完全镜像主机（缺的补建、多的删掉）"+ 选卡阶段仍各挑各的。
2. 按"战斗域 / 本地域"重判（[联机模组规范.md](../参考存档/联机模组规范.md) §3.4）：
   卡槽内容会改变**两端手里到底有什么** ⇒ 战斗域；选卡那一会儿才是本地。
3. 本体加两个**通用**能力（不含联机字样，本体不认识联机）：
   `Card.cool_remain`（读剩余秒数）+ `Card.set_card_cool_remain(秒)`（按剩余秒数摆冷却）；
   `CardSlotBattle.set_cards(references)`（按身份整体替换卡槽：相同身份**留在原位**复用、缺的照模板补、多的退）。
4. `NetplayStateSync.collect_snapshot_extra()` 增发 `cd_type / cd_id / cd_imit / cd_cool`
   （身份拆成三个数字，不走 `to_dict()` 的字典数组）；`_apply_snapshot_extra()` 增 `_align_cards()`。
5. 同步文档（[联机模组.md](../参考存档/联机模组.md) §4.2.2 / §4.9 表 / 阶段表；
   [联机模组规范.md](../参考存档/联机模组规范.md) §3.2 表 + §3.3 拿起植物那条）+ 改探针断言。

## 关键决策与理由

- **只在开打之后（`MAIN_GAME`）对齐** —— 选卡阶段卡槽正被玩家自己摆弄，照主机覆盖等于把刚挑的卡冲掉。
- **卡列表变了才重建**：比的是身份压成的 `PackedInt32Array`（`_card_sig_of`），每帧只刷冷却 ——
  重建会把每张卡正在跑的遮罩 / 位置一并打断。
- **身份与冷却在**同一个循环**里成对取**（`_cards_of` 一次返回 `refs` + `cools`）：
  分两趟各丢一次非法编号的话，"第 i 张卡"对上的就不是"第 i 个冷却"。
- **主机这一帧没报全就整个不动**（`cd_cut`）：截断下来的是残缺名单，照它对齐会把没报上来的那几张
  当成"主机撤掉了"给删掉 —— 宁可差这一帧，也不能删错卡。
- **`cool_time`（冷却总长）故意不发**：它几乎不变，而每发一条要从**植物名册**的预算里扣 4B × 卡数；
  满盘 45 株 + 满槽 12 张卡 + 阳光预留刚好卡在 1300B，多这 4B 名册掉到 43 株。缺它只影响遮罩填充比例，
  能不能点不受影响（能改总长的只有罐子模式那类零冷却卡，那种卡主机报的剩余本来就是 0）。
- **撤掉的卡退回待选区而不是 `queue_free()`**：玩家挑的那一张本来就是待选区容器里那个节点
  （选卡时只是挪进了占位里），free 掉之后多轮关卡第二轮重新选卡会点到已释放的实例。

## 踩坑

1. **探针里 `has_method("get_cool_remain")` 查不到** → Godot 4 的**内联 getter**（`var x: float: get:`）
   不会另外挂出一个 `get_x()` 方法 → **正解**：属性存在性用 `"cool_remain" in node` 判。
2. **加字段会挤掉已有的那一类** → 第二包是"先到先得填预算"，卡槽的字节是从植物名册那份里扣的。
   探针原来那条"45 株装得下"是**不含**卡槽预留自己算的，照旧跑会 PASS 而实际已经装不下
   → **正解**：把卡槽预留一起算进 `p_cap` 再断言，让纸面数字与实际一致（顺带逼出了上面"砍 `cool_time`"的决定）。
3. **直接 free 撤掉的卡会弄坏第二轮选卡**（上面决策最后一条）→ 退回待选区。
4. **`is_instance_valid()` 挡不住 `card_reference` 为空**：采集侧要先判引用合法再取三个字段，
   否则主机会把一条 `Null` 身份塞进包里。

## 给后来者的最简路径

1. 往快照里加东西前，**先算字节**：`BYTE_BUDGET - 已有各类预留 - 新增的` 还够不够现有那一类的**满盘**数量，
   不够就砍新字段里"最不影响判定"的那一个。
2. 一批东西要一起对齐时，**在同一个循环里成对取**，别分两趟各自过滤。
3. "整体替换 UI 列表"这类能力放在**本体**那个容器类上（`CardSlotBattle.set_cards`），
   模组只负责传数据 —— 别把界面搬进模组。
4. 改完跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_netplay_session`；
   手感 / 视觉必须双实例人工看（见 [联机模组规范.md](../参考存档/联机模组规范.md) §四）。

## 人工验证方法（本次未开游戏）

两个实例连同一房间（控制台「开启房间」/「加入房间」），客户端这一侧：

1. 选卡阶段**各自挑卡**不被冲掉（客户端挑的卡留在自己的卡槽里）；
2. 开打后客户端的卡槽与主机**同一副卡**、编号顺序一致；
3. 任一端种一株 ⇒ **两端**那一张卡同时进入冷却，遮罩大致同步走完（允许约半个 RTT 的差）；
4. 找一关能让主机中途改卡槽的（关卡脚本加 / 撤一张）⇒ 客户端跟着加 / 撤；
5. 传送带关（没有出战卡槽）⇒ 两端都不报错、卡槽那一组压根不发。
