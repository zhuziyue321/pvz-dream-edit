# 2026-10-01 · 文档规范 · 新增「踩坑即时沉淀」与「流程归档」两条规范

> **任务类型**：文档规范
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，纯文档改动
> **验证方式**：免验证（改动面只有 `docs/` 与 `AGENTS.md`，不触达玩法行为，符合 [V-01](../参考存档/规范细则存档.md#v-01-改动较小可免验证)）

## 目标

把「踩过的坑必须写进文档」「每次任务结束必须归档工作流程」变成硬规则，让后来的 Agent 能查历史流程、选最简路径。

## 步骤

1. 读 [docs/README.md](../README.md) 与 [项目规范.md](../项目规范.md) §7「扩展本规范」，确认规范类内容只进项目规范.md、按 `E-` 编号（已有 E-01/02/03 → 取 E-04、E-05）。
2. 新建记录载体（流程记录，非规范文档，故不违反「规范只进项目规范.md」）。
3. 在 [项目规范.md](../项目规范.md) §9 之后新增 §10「经验与流程的沉淀」，放 E-04、E-05 两张卡片。
4. 同步所有引用点：§0.1 速查表、§8 红线清单、附录 B 无自动兜底清单、文档头部关联表与红线条数字样。
5. 同步 [AGENTS.md](../../AGENTS.md)：路由表、硬约束速查、标准流程步骤。
6. 同步 [docs/README.md](../README.md)：索引表登记一行 + 红线条数。

## 关键决策与理由

- 记录独立成文件/目录，而不是把流程塞进项目规范.md —— 规范只写约束（[E-03](../参考存档/规范细则存档.md#e-03-规范与文档的边界)），流程记录是**积累型数据**，混进规范会让规范越读越长。
- 编号接在 `E-` 段（E-04 / E-05）而不是新开前缀 —— 这两条本质是「规范自身如何演进」的规则，属 E 段语义。
- 把两条都升级进 §8 红线清单 —— 只写在 §10 容易被当成"建议"，写进红线才会在自检表里被逐条核对。

## 踩坑

1. 改红线条数文案时，该字样散落在 3 个文件（项目规范.md 头部、docs/README.md 索引表、AGENTS.md §3）→ 只改一处会造成文档自相矛盾 → **正解**：改完用 `grep "条红线"` 全仓复核一遍再收尾。
2. 要求「开工前查记录」，但记录为空时规则落不了地 → 新建载体时**必须**同时归档第一条记录（本条），否则后来者查到空索引就不会再查第二次。

## 给后来者的最简路径

1. 要加规范 → 只在 [项目规范.md](../项目规范.md) 加卡片（`E-` 段取下一个空闲号）→ grep 同步所有引用它的地方（速查表 / 红线清单 / 附录 B / AGENTS.md / README.md 索引）。
2. 要记流程 → 在 [docs/工作记录/](README.md) 新建 `<日期>_<主题>.md`，并在目录索引补一行。
3. 开工前 → 先扫目录索引找同类条目，再决定怎么做。
