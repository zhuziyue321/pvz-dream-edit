## 目标

冒险 5-10 打起来是原版那场僵王战：僵王站在最右侧、只有低头才能被打到、血量走关卡进度条、
自己放僵尸 / 吐冰火球 / 踩踏 / 扔房车 / 空投蹦极，打死僵王即通关。

## 步骤

1. 查 wiki 定口径（[Dr. Zomboss (PvZ)](https://plantsvszombies.wiki.gg/wiki/Dr._Zomboss_(PvZ))）：
   血量 40000（首次）/ 60000（重打）、掉 20% / 50% 换外观、招式清单、火球被寒冰菇扑灭、冰球被同行辣椒化解。
2. 注册表：`ZombieType.Z999Boss = 999` + `ZombieRowType.Zomboss` + `ZombieInfo` 登记，
   并加进 `GlobalReadData.blacklist_zombie_types`（不进自然出怪池）。
3. 本体：`zombie_999_boss.gd` / `.tscn`（继承 `zombie_000_base`，身体直接实例化仓库里现成的 `zombie_boss.tscn`）。
4. 冰火球：`zombie_999_boss_ball.gd` / `.tscn`（`SceneRegistry.ZOMBOSS_BALL`）。
5. 编排：`zm_zomboss_manager.gd`，挂到 `Manager/ZombieManager/ZombossManager`，本体挂新增的 `%ZombossRoot`。

7. 写探针 `test/scenarios/probe_zomboss.gd` 跑无头验证，顺手回归 `probe_boss_map`。

## 关键决策与理由

- **本体只管表现、编排全放 Manager** —— 因为要遵守硬约束「组件只通过 owner / 信号 / 场景配置通信」，
  把血量 / 血条 / 出招节奏塞进本体就会变成「宿主复制管理器状态」。
- **复用 `zombie_000_base` 而不是从零写 Node2D** —— 白拿 HpComponent / HurtBox / Charred / 掉落等一整套组件，
  只需要关掉移动、攻击，并把受击框换成覆盖躯干的大矩形。
- **`AnimComponentPlayer` + 根 `AnimationPlayer`（`root_node` 指进实例里）**，不走 AnimationTree 状态机 ——
  boss 的动画是「一段一段被编排播」的，没有 is_walk / is_attack 这种状态可喂给状态机；
  顺手给 `AnimComponentPlayer` 加了 `play_anim()`。
- **血条复用关卡进度条 `FlagProgressBar`** —— 原版僵王血条就在波次进度条那个位置；`create_flag(0)` 清掉旗帜即可。
- **5-10 的 `monster_mode` 设 `Null`** —— 本关没有波次，胜利条件也换成了「打死僵王」。

## 踩坑

1. **新建的 `.tscn` 带 BOM → `Parse Error: Expected '['`** → Godot 文本资源解析器不认 UTF-8 BOM →
   **正解**：新建 `.tscn` / `.tres` 一律写成**无 BOM 的 LF UTF-8**（PowerShell `Set-Content` 会加 BOM + CRLF，别用）。
2. **`Could not find type "ZombossManager"`** → 非编辑器启动时全局类列表读的是 `.godot/global_script_class_cache.cfg`，
   手写的新脚本不在里面 → **正解**：往该文件末尾按同样格式追加 `base/class/icon/is_abstract/is_tool/language/path` 一条。
3. **`.tres` 里写 `##` 注释 → 后面的属性全没生效**（`monster_mode` 仍是默认值、字典读出来是空的）→
   Godot 文本资源的属性块不认 `##` 注释，会把整段解析打断 → **正解**：注释只写在脚本 / md 里，`.tres` 里别写。
4. **`SwimBoxComponent` 没有 `disable_component`**（它 extends Node2D，不是 `ComponentNormBase`）→
   调用报错会**中断 `ready_norm()` 剩下的代码**（受击窗口没关、动画信号没连，表现为僵王发呆不出招）→
   **正解**：别对它调组件方法；`ready_norm()` 里任何一个报错都会让后面几行静默不执行，值得单独确认一遍。
5. **`await 单参数信号` 拿到的是参数本身，不是数组** → 写成 `var args:Array = await xxx` 会报类型错误 →
   **正解**：`var finished_name:StringName = await boss.signal_boss_anim_finished`。
6. **动画键大小写**：文库里是 `Zombie_boss_RV_1`（大写 RV），写成 `rv_1` 就播不出来 →
   **正解**：等一个不存在的动画会永久卡住出招循环，所以 `_await_anim()` 先 `has_boss_anim()` 兜一道。
7. **首次通关 5-10 掉的是「本关奖励」不是奖杯** → 探针里搜不到 `Trophy` →
   **正解**：探针先把 5-10 标成 `{"IsSuccess": true}` 再进关，走重打那条线才会出奖杯（顺带验到重打血量 60000）。

## 给后来者的最简路径

1. 先在 wiki 定口径（血量 / 招式 / 克制关系），再动手 —— boss 类单位的数值全靠它。
2. 注册表登记 → 本体继承 `zombie_000_base`（复用现成躯干场景）→ 独立 Manager 编排 → 关卡数据加开关。
3. 新建资源文件**一律无 BOM + LF**，并把新 `class_name` 补进 `.godot/global_script_class_cache.cfg`。
4. 最后写 `probe_*` 跑一遍：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss`。

## 补充 / 评价（2026-10-02 · 冰火球手感调整：必须贴屋面 / 慢一些 / 都碾压植物）

> **本次改动**：见本条记录 §「关键决策」里冰火球那两条的现状 —— 已被下面这版取代（表现在是：
> 冰球 / 火球**都碾碎**滚过的植物，冰球先把植物冻住再碾成冰饼）。

- **改了什么**：`zombie_999_boss_ball.gd`
  ① 两种球都调 `cell.plant_be_flattened()`（原来只有火球碾、冰球只冻住）；
  ② 速度 260 → 120 px/s；
  ③ 新增 `_update_roof_y()`：每帧
  `y = get_row_base_global_y(lane) + main_game_slope.get_all_slope_y(x) - 球半径`，
  出生时就压到屋面上、之后顺着斜坡往左下滚（与僵尸入场落位、抛物线影子同一套算法）。
- **为什么这么改**：冰球只冻住不碾，玩家看着像「球从植物身上穿过去了」；球从嘴的高度平着飞过去、
  不贴屋面也不像在屋顶上滚。
- **新增探针段 `STEP6.5`**（`test/scenarios/probe_zomboss.gd`）：量球底与屋面误差 < 2px、
  实测速度 = 配置速度、滚进斜面段后 `y` 变大（往左 = 往下）、冰球与火球各碾掉一株植物。
- 踩坑（补进上面「踩坑」段的同类）：
  **`Global.main_game` 没有静态类型，写 `var main_game := Global.main_game` 会 `Parse Error: Cannot infer the type`**
  → **正解**：读 autoload 里这种弱类型字段一律写 `var main_game = Global.main_game`（不加 `:=`）。
  **探针里「等固定秒数再看」会 flaky**：僵王死亡流程是 4s 动画 + 清场 + 出奖杯，原先按
  「等僵尸清零 + 3s」掐表，僵尸清零得早时会在出奖杯之前就断言 → **正解**：改成
  `while not 事件 and waited < 15s` 轮询目标状态，别用固定秒数赌。同理「僵王会放僵尸」这条也别赌随机到哪一招
  （权重 5/16，40s 内有 ~15% 概率一直没抽到出兵）→ 改成先验 `action_num > 0`（循环在跑），
  再直接驱动一次 `_action_spawn_zombie()` 验出兵本身。
- **评价**：本体与编排的设计不用动，这三条都只是球脚本内部的调整 —— 应验了「编排 / 表现分开」的好处。
- **更省的做法**：无（探针侧可以用 `probe_zomboss` 现成的 STEP6.5 抄）。
