## 取数的关键：别用 `?action=raw`

单页 `?action=raw` 一律 **403**（总表也一样）。能用的只有 API：

```
https://pvz-dlc-edition.fandom.com/api.php?action=parse&page=<页名>&prop=wikitext&format=json
```

用 PowerShell `Invoke-RestMethod` 取 `$r.parse.wikitext.'*'` 写本地文件再 grep，比让模型读网页**稳得多** —— 数值不会被总结改写。

⚠️ `Plants` 总表里 `Health / Attack Damage / Avg Attack Interval` 三列**全是空的**，只有 `Sun cost` 有值。
伤害 / 生命 / 攻速 / 射程必须逐株取单页 infobox；部分带 `?`（如 Oak Archer `80(?)`），要拿 `Projectiles` 表交叉验证（Mortar-shroom infobox 写 `100(?)`，Projectiles 表是 2 豌豆 = 40，取 40）。

## 踩坑

1. **动作段比攻击间隔长 → 动画被 `play()` 从头重置**（§9 已有条目）。
   wiki 给的两个攻速（Bonk Choy 0.36 s、Beeshooter 1.5 s）**都短于**动作段（0.833/0.917 s、2.0 s）。
   解法不是把 CD 拉长（那就没对齐 wiki 了），而是**给动作段加一层播放倍率** `段长 ÷ attack_cd`
   （`JAB_ANIM_SPEED = 2.32`、`SHOOT_ANIM_SPEED = 1.34`），全场加速倍率叠在外面一层 ——
   于是需要 `_speed_product` 记住「全场加速」那一层，回待机时再写回。

2. **「全场」改「3×3」后探针直接 FAIL**：探针把植物种在 `root` 下的独立 `PlantCell` 里（不在场地上），
   与僵尸相距大半个屏幕。改射程的株（缩小紫罗兰）必须在种下前把 `cell.global_position` 挪到僵尸身边，
   否则新的射程过滤一条都命中不了。

3. **改字段名时 grep 探针要连断言值一起 grep**：`discharge_damage` → `discharge_dps` 时我只改了断言文案、
   漏了 `== 100` 那个比较值，探针报「阳光 = 225 ← 225」这种看着自相矛盾的错，其实是**比较值没改**。

4. **`run_autopilot.ps1` 报 `STALE_PROCESS`**：上一轮 godot 还没退（最长 300 s）就发起下一次，它检测到残留
   就拒绝跑、直接吞掉输出。串行跑 / 先 `Get-Process godot` 确认没有残留再跑。**别用 `-KillStale`**：
   那可能杀掉用户开着的编辑器。

5. **wiki 的 `3x5` 是「行 × 列」**：与 `1x9`（1 行 9 格）、`3x3` 同一口径 —— Volt-shroom 的 3×5 = 3 行 × 5 列
   = 260 × 380 px，不是 228 × 260。

## 最简路径（下次照做）

1. `api.php?action=parse&prop=wikitext` 把单页拉到本地 → grep `cost=|recharge=|damage=|health=|range=|firerate=`。
2. 改数值前先量**动作段时长**（`animation/.../<ArtName>_<段>.tres` 的 `length`）：
   `attack_cd` 短于段长就加播放倍率，不要拉长 CD。
3. 改完数值 → 同一次改 **dlc_mod 常量 + S6/S7 文案 + 探针断言 + §8 登记表**（四处，缺一处就漂移）。
4. `check_scripts.ps1`（门禁）→ 串行跑改动株的探针（先确认无 godot 残留）。

## 补记（同日）：臼炮蘑菇「打不到近处」是误读造成的 bug

用户反馈「臼炮蘑菇打不到近处的东西」。查下来是我上一轮**把 wiki 读错了**：

- wiki 的 `range = Lobbed` 只说明它是**抛射**（弹道是抛物线），不说明只能打远处；
- wiki 正文写的是「Changes target when the enemy is close（敌人靠近时**换目标**）」—— 近身照样打；
- 我之前却照「Lobbed = 只轰远处」把 `DetectComponent` 碰撞框左边缘设到 **+114 px（1.5 格）**，
  于是贴到脸上的僵尸根本进不了框 → 打不到、也不出弹。这个"盲点"在登记表里还被写成
  「刻意保留的偏差」，属于把误读当成了设计。

修法：框左边缘压回自己脚下、再往左留 20 px（宽 480 / 中心 220 → 覆盖 -20 .. 460）。
同步改了文件头注释、`dlc_mod.gd` 的 S6/S7 文案与图鉴「描述 / 简介 / 参数」、探针、§8 登记表。

**教训**：wiki 的 `range` 字段只讲**形状**（Lobbed / 1x9 / 3x5），讲**行为**的是正文那句
`special` / 描述 —— 两者都要读，别拿 range 去推断"打不到哪"。
探针补了一条「左边缘 ≤ 0」的断言专门防这个回归（只断言框尺寸抓不到这类问题）。
