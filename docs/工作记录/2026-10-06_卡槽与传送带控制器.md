
# 2026-10-06 · 其它 · 卡槽 / 传送带控制器（两者可共存 + 僵王战传送带权重）

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话；无头探针 4 个（新探针 + 3 个回归），未开窗口
> **验证方式**：无头探针 `probe_card_slot_conveyor` 全过 + 回归 `probe_bowling_redline`（传送带）/ `probe_zomboss_damage`（僵王关）/ `probe_card_slot_conveyor`（画面需人工看一眼）
> **补充自**：无（机制文档新开 [卡槽与传送带.md](../参考存档/卡槽与传送带.md)）

## 目标

1. 卡槽和传送带各加一个控制器，允许两者**同时出现**（卡槽在上）；
2. 默认卡槽走选卡，传送带的出卡种类由**关卡内配权重**；
3. 能查询传送带内的植物；
4. 僵王战里：场上空花盆 <= 5 → 花盆权重下降；传送带上花盆 >= 4 → 寒冰菇 / 辣椒权重上升。

## 步骤

1. 先摸清现状：传送带其实已经是「固定序号 `conveyor_order` + 其余走 `conveyor_weights` 权重随机」的混合模式，
   权重池是 `CardRandomPool`（初始化时建成累计表，**没有运行期改单项的接口**）；
   而卡槽与传送带是**结构性互斥**：`E_CardMode` 单值枚举 + `CardManager.init_manager()` 的 `match` 二选一 + `CardSlotRoot.curr_cards` 只指向一组卡。
2. `E_CardMode` 加 `Both`；`ResourceLevelData` 加 `has_norm_card_slot()` / `has_conveyor_belt()` 两个判定，
   `_apply_card_mode_constraints()` 只在**纯传送带**时禁选卡 / 关天降阳光（Both 要保留选卡）。
3. 加 `CardSlotController`（原 `CardManager` 里 Norm 那一支整个搬进去）+ `ConveyorBeltController`（建 / 启动 / 间隔 / 权重 / 查询）。
   `CardManager` 只做转发，并保留 `card_slot_norm` / `card_slot_battle` / `card_slot_conveyor_belt` 三个别名
   （教程管理器 / 结算还在读它们）。
4. 传送带加 `signal_before_create_card`（出卡前发一次）+ `set_card_weights()`，控制器接这个信号
   把权重重算一遍：**先回到底表，再让每条规则各调一次**（和进度条数据源同一套「每次都问」的拉模式）。
5. 权重规则基类 `ConveyorWeightRule`（RefCounted）+ 僵王战那条 `ZombossConveyorWeightRule`（放进 `src/levels/core/zomboss/`，5-10 / 迷你 20 共用）；
   两个僵王关在 `run_flow()` 里各加一行 `add_conveyor_weight_rule(...)`。
6. 快捷键：`CardSlotRoot` 加 `second_cards`（传送带那组），数字键先数卡槽再数传送带。
7. 补探针 + 同步文档（新开 [卡槽与传送带.md](../参考存档/卡槽与传送带.md)、改 [卡片与选卡流程.md](../参考存档/卡片与选卡流程.md)、AGENTS.md 路由表补一行）。

## 关键决策与理由

- **两个控制器而不是一个**：卡槽和传送带是两套独立的出卡方式，合成一个只会把 `match` 换个地方；
  分开之后 `card_mode = Both` 只是「两个都建」，不用改任何分支。
- **权重规则做成「每次出卡前重算」**：规则不用记住上一次改了什么，也不会出现
  「场上变了但权重还是上个状态的权重」——传送带里卡的数量变了，下一张卡就能反映出来。
- **权重底表留副本**：`ResourceCardWeight` 是共享资源，运行期改它会直接污染关卡数据。
- **僵王战规则放在 `src/levels/core/zomboss/`**：两关共用（≥2 关才上浮，硬约束 §1-8），且与僵王其它代码同侧。
- **别名保留**：`card_manager.card_slot_battle` 这类字段被教程 / 结算读着，一次性全改风险大，先留别名。

## 踩坑

1. **同时出现时两条卡槽叠在一起**（`get_global_rect()` 一模一样）—— `CardSlotContainer` 是 `PanelContainer`，
   **容器会把子控件铺满同一个矩形**，改 `position.y` 会被布局重置。
   → **正解**：Both 模式下传送带**不挪进容器**（`keep_out_of_container`），留在 `CardSlotRoot` 上按自己的 position 摆。
   （探针里用全局矩形断言「卡槽底 <= 传送带顶」+「两条都在屏幕内」，这一步靠断言才发现的，肉眼看日志很难发现。）
2. **新脚本的 `class_name` 在无头跑批里找不到**（`Could not find type "ConveyorBeltController"`）——
   引擎的全局类缓存 `.godot/global_script_class_cache.cfg` 还没刷新，会连带让依赖它的脚本一起编译失败。
   → **正解**：新增 `class_name` 之后**先跑一次 `Godot --headless --editor --quit`**（让它重新导入），再跑探针。
3. **探针里 `var x := ...` 推断不出类型**（`Global.main_game` 是弱类型链式取值）。
   → **正解**：显式写 `var cm: CardManager = mg.card_manager`。**第一次跑探针一定要先看 stderr 的 Parse Error**，
   否则场景脚本加载失败 → 探针空转到看门狗超时，stdout 上只看到「超时」。
4. **「空花盆」的口径跟预想不一样**：5-10 开局是**一整片预置花盆**（4 列 × 5 行 = 20 个空花盆），
   不是我以为的 4 个。规则按字面实现后是「打到后期草坪快种满了才少给花盆」，反而更合理；
   但探针最初按「开局 4 个」写断言就一直是红的。
   → **正解**：探针别猜，先把实际数量打出来（`开局空花盆 = 20`），再按真实数量设计断言。
5. 跑回归时撞到 `adventure_05_10.gd` 的 Parse Error（`pre_plant_flower_pot_columns` 不存在）——
   **是另一个 agent 正在并发改这个文件**（它后来改成了 `plant_flower_pot_columns(4)`，函数加在 `LevelScriptBase`）。
   → **正解**：多 agent 并行时遇到别处文件的解析错误，先确认是不是并发编辑的瞬时状态（重跑一次），别急着改别人的文件。

## 给后来者的最简路径

1. 换传送带权重口径 = 写一个 `extends ConveyorWeightRule`，实现 `apply_weights(conveyor)`，
   里面调 `conveyor.set_plant_weight*`；关卡脚本 `run_flow()` 里
   `_mg.card_manager.add_conveyor_weight_rule(MyRule.new())`。
2. 查传送带内容：`mg.card_manager.conveyor_controller.get_card_plant_types()` / `count_card(plant_type)`。
3. 让卡槽和传送带同时出现：关卡 `_init()` 里 `card_mode = ConstLevelData.E_CardMode.Both`，
   传送带权重照旧写 `conveyor_weights`。
4. 验证：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_card_slot_conveyor`。
