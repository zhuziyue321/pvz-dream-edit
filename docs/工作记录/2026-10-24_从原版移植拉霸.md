## 目标
把 `src/levels/mode_minigame/minigame_03_slot_machine.gd` 这一关从「自创玩法」改成**原版 1:1 移植**：屏幕左上角的机器（阳光银行 + 3 个种子包转轮 + 覆盖层 + 拉杆）、每次 25 阳光、按原版权重随机、转轮逐帧滚停、两个/三个相同的奖励、当前余额 2000 过关掉奖杯。

## 最简路径（步骤）
1. **定权威口径**：桌面两份 C++ 参照里 `../PvZ-Portable-main/src/Lawn/` 为主 —— `Board.cpp`（`InitLevel` 里种子包位置 / 初始符号 / 起始阳光 50）、`Challenge.cpp`（`SlotMachineGetHandleRect` / `UpdateSlotMachine` 的结算与过关 / `PickNextSlotMachineSeed` 的权重）、`SeedPacket.cpp`（`SlotMachineStart` 倒计时 300、翻转曲线域 400、两层堆叠绘制）。`../re-plants-vs-zombies-main/` 交叉验证。
2. **算原版坐标**：`SlotMachine.reanim` 的三条轨（base / shaft / ball）按 reanim 原点 (96,-20) 换算成机器坐标；覆盖层 `SlotMachine_Overlay.png` 的三个透明窗口用像素扫描量出来（相对覆盖层 62 / 121 / 180 × 19，各 42x42），据此把 `seeds.png` 的 6 帧（种子包图标）当转轮贴图。
3. **机器摆位**：UI 是脚本 `_ready()` 现场搭的 `Control`（全屏 rect 当坐标系，机器坐标 = 屏幕坐标）：
   阳光银行 `pak/images/SunBank.png` (0,0) + 黑字数字 (34,78)；转轮 `x = index*59+247, y = 8`（每帧 50x70）；覆盖层 (189,-2) 后画（盖住转轮）；拉杆 base/shaft/ball 按 reanim 轨摆、点热区 (473,0,55,80)。
4. **机制**：拉杆 → 扣 25 → 三个转轮**同时**各 300 帧、每秒翻转 `6 - 4*(400-countdown)/400` 次 → 停稳结算；权重表（向日葵/豌豆/寒冰豆/坚果/太阳 100、钻石 30、豌豆随场上株数 200→100、第 3 轮与前两轮一致的符号 x1.5）抽成纯函数 `_symbol_weights()` 方便探针确定性核对。
5. **奖励落地**：太阳币走本体 `SunSpawner.pop_up`；钻石币是 UI 层自绘掉落物（`pak/reanim/Diamond.png`），点它 `add_sun_value` 入账；免费植物用 `CardManager.create_temp_card` 掉一张临时卡（25 秒后消失）。
6. **过关**：当前余额 ≥ 2000 判胜（不是累计收集）→ 关卡脚本掉奖杯（位置 = 原版 `SpawnLevelAward(4,2)` 那格的中心）；进度条用本关专属数据源 `SlotMachineProgressProvider`（进度 = 阳光/2000）。

## 弯路 / 踩坑（三段式）
- **试过**：探针里写 `para.is_lawn_mower`。
- **因为**：`ResourceLevelData` 的字段是 `is_lawn_mover`（一个 w），探针一访问就 `Invalid access to property or key ... on a base object of type 'Resource'` 直接崩，后面所有断言都跑不到（旧探针也带着这个笔误，等于一直是坏的）。
- **结论**：探针里断言关卡字段，**先照 `level_data.gd` 抄准字段名**；崩在断言行就说明字段名/结构漂移了，别急着改关卡脚本。

- **试过**：探针在判胜后继续读 `ui._sun_value` / `btn.disabled`。
- **因为**：判胜 → 关卡流程 `await game_finished` → `queue_free` UI，探针下一轮轮询就拿到了**已释放对象**，带类型标注的参数在传参那一步就报 "previously freed"。
- **结论**：**UI 被关卡流程收走 = 判胜成功的信号**；探针里凡是可能跨过关卡收尾的引用，一律去掉类型标注并先 `is_instance_valid()`，别在判胜后还去读关卡内部状态。

- **试过**：奖杯掉出来后不点它、放着等它过期。
- **因为**：`mgm_reward_manager.gd` 的 `gain_loot` 走 else 分支时把**已释放**的掉落物传给带类型的 `wait_unlock_drop_closed(new_drop)` → 报 "previously freed"，**并把后面的 `win_main_game()` 一起带崩**（本关就卡在结算画面出不来）。
- **结论**：奖杯/奖励类掉落物有「自动消失」这条路径，调用方要自己判 `is_instance_valid`（已在 `gain_loot` 里加兜底）；探针要**把奖杯点开**再等结算。

- **试过**：用 `Button` + `Label` 叠一层做拉杆热区。
- **因为**：`Button` 不支持 `label_settings`（运行时拒绝），盖在上面的 `Label` 默认又拦截点击。
- **结论**：热区用**透明 `Button`**（`StyleBoxEmpty` 覆盖各态），数字/文字一律单独 `Label` 且 `mouse_filter = IGNORE`；本关所有装饰件（转轮 / 覆盖层 / 阳光银行 / 拉杆三块）都设 IGNORE，机器区域不挡草坪点击（与原版一致：原版机器只吃拉杆与种子包的点击）。

- **试过**：把权重公式写在随机函数里。
- **因为**：随机结果没法在探针里确定性断言（`randi()` 没法复现），第六种符号 30 权重也难稳定命中。
- **结论**：**权重表抽成纯函数**（`_symbol_weights(reel_index, peashooter_count)`），随机只负责按表取号；探针直接断言表（0 株豌豆 → 200、5 株 → 100、钻石 30、第 3 轮一致 → 150）。

## 推荐度与理由
推荐。**价值在「原版坐标与权重全都有出处」**：机器每一块的摆位都能指回 `Board.cpp` / `Challenge.cpp` / `SeedPacket.cpp` / reanim 轨；后来者要改数值或加符号，照那几处抄比对着截图猜靠谱。**给后来者的坑**：① 转轮是**逐帧**驱动的（`countdown -= 1` 后才算翻转速度），不能改成按 delta 直接算，否则快慢曲线对不上；② **倒计时走完但这一格没翻完时要再给一帧**（原版 `else if (mSlotMachineCountDown == 0) mSlotMachineCountDown = 1;`），漏了会停在半格；③ 停稳后要把「下一个包」藏起来（原版倒计时 <= 0 时只画当前包）；④ 原版**过关看当前余额不是累计**，这一条最容易照抄错；⑤ 本关没有波次，进度条得自己写数据源，且**判胜后 UI 会被收走，数据源要缓存最后读到的阳光**（否则过关那下进度条掉回 0%）。
