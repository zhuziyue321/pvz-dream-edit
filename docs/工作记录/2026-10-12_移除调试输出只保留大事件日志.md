
# 2026-10-12 · 其它 · 移除全部调试输出，日志只报大事件（撤掉 `Log.debug`）

> **任务类型**：其它
> **推荐度**：**推荐**（下次做「全仓批量删一类调用点」照这个走）
> **耗时与成本**：约 2 轮对话 / 未开窗口 / 无头探针 + 全量解析校验
> **验证方式**：免验证 + 已给出人工验证方法（编译门禁 PASS、773 个 `.gd` 逐个 `load()` 只有 1 个**既有**坏文件、6 个无头探针 PASS）
> **补充自**：无

## 目标

- 全仓**物理删除** `Log.debug` / `Log.info` 调用点（283 + 27 处，分布在 193 个文件），不留调试输出。
- 只保留 `warn` / `error`，并把**关卡级里程碑**（关卡 / 轮次开始、波次、判胜判负、通关解锁）从 `Log.debug` 提升为 `Log.info` 保留下来。
- `logger.gd` 撤掉 `DEBUG` 级别与 `debug()` 方法，默认级别改成 `INFO`（不新增 API）。

## 步骤

1. **先量化再动手**：统计全仓 `Log.debug` 283 / `info` 27 / `warn` 73 / `error` 316，确认规模；同时确认 `Level.DEBUG` 全仓只有 `logger.gd` 自己用（撤掉不会踩空）。
2. **人工挑「大事件」清单**：先把 310 条调用点全量列出（`文件:行号:原文`），再按「玩家可感知的里程碑」挑 21 条提升为 `Log.info`（关卡开始 / 下一轮次 / 判胜 / 判负 / 旗前波 / 最后一波 / 携带解锁道具的波 / 通关解锁新植物与道具 / 商店与图鉴解锁 / 观星与水族馆的通关判负 / 蹦极闪电战开启），另保留 21 条原本就是 `info` 的启动类输出（模组装载、联机会话与结算、调试通道自己的报告路径）。
3. **一次性脚本批量删**：`tools/` 下临时 PowerShell 脚本（用完即删），从后往前删整条语句（括号配平支持跨行调用），顺手清掉整行被注释掉的 `#Log.debug(...)`（约 40 行）。
4. **处理删完的空块**：块里只剩日志的分支会变空，脚本补 `pass`；再用第二遍脚本按「块头下一句的层级」判定**误插**的 `pass` 并删掉（块内本来还有别的语句就不该补）。
5. **人工收尾**：约 20 处按上下文改成更干净的写法（`if err == OK: pass else: …` → `if err != OK: …`；整块只有日志的 `if` / `for` 直接删；`zb_base.be_mowered_run()` 这种「本来就是空实现」的留 `pass`；`gim_rake` 那条**条件有副作用**（`consume_rake_use()`）必须保留 `if`）。
6. **同步文档**：`规范细则存档 S-02`（删 `Log.debug` 示例 + 级别表）、`验证流程`（四级→三级）、`TODO清单 L-07`（那行注释已被删）、`logger.gd` 头注释、`debug_channel` 的日志自检（四级→三级）。

## 关键决策与理由

- **物理删除而不是调级别静音** —— 用户明确选了这条（可逆的静音会留下 300 处死代码，下次还是要清理）。
- **不新增 `Log.big()` 之类的大事件 API** —— 用户口径是「把少数几处提升为 `Log.info` 并保留」，新增 API 会让「什么算大事件」再开一套判定。
- **撤掉 `DEBUG` 级别与 `debug()`** —— 调用点已清零（含 `.tscn` 内嵌脚本与注释一并搜过），留着只会让人以为还能打调试日志；先 grep 确认全仓 0 处引用才敢删。
- **保留调试通道 / `test/autopilot.gd` 的 `Log.info`** —— 它们是 AI 调试通道自己的对外报告（只在不跑探针时完全不出现），删了探针就没法告知报告路径。

## 踩坑

1. **PS5.1 把无 BOM 的 `.ps1` 当 GBK 解析** → 中文注释变乱码、脚本直接 `ParserError`。→ **正解**：临时脚本写完用 `[System.Text.UTF8Encoding($true)]` 重写一遍加 BOM（`.gd` 则必须**无 BOM**，写回用 `UTF8Encoding($false)`）。
2. **读写 `.gd` 必须自己管编码与换行** —— `Get-Content` 默认按 GBK 读、`Set-Content -Encoding UTF8` 在 5.1 会加 BOM；仓库里 335 个文件 CRLF、534 个含裸 LF。→ **正解**：`[IO.File]::ReadAllLines(path, UTF8)` 读，写回时按原文有没有 `\r\n` 决定换行并只在原文结尾有换行时补一个。
3. **`Compress-Archive` 用绝对路径打包会丢掉目录层级**（zip 里只剩文件名）。→ **正解**：备份要么按叶子名回填（先确认全局只有 `main_panel.gd` / `plugin.gd` 重名），要么整目录拷；我最后靠「按文件名回填 + 上下文窗口比对」才定位出自己插入的 `pass`。
4. **删日志会让分支变空，自动补 `pass` 极易补错** —— 两种错：① 块里本来就还有别的语句却补了 `pass`（多行函数签名、多行 `if` 条件的**续行**会被误判成块头）；② 缩进按「字符数」算，Tab 缩进的文件补出「空格 + Tab」混排。→ **正解**：块头要沿 `\` / `,` / `(` 结尾往回找**语句起点**；`pass` 缩进按「语句起点层级 + 1 个 Tab」重写；块头下一句层级 > 语句起点层级 ⇒ 这个 `pass` 是多余的，直接删。
5. **脚本里「先删注释行、后删日志行」会让行号错位** —— `main_game_manager.gd` 的「下一轮次」「主游戏开始」两条本该保留，却因为在它们之前删掉了一行 `#Log.debug(...)` 而被误删。→ **正解**：保留清单要么按**内容**匹配，要么删注释放在删除之后；事后我用备份的原文把它们补回去了。
6. **编译门禁有覆盖盲区**（脚本头 KNOWN LIMITATION 1/2：只编资源管线可达的脚本、不做方法解析）。→ **正解**：补一道临时校验 —— `--headless --script` 跑一个 `extends SceneTree` 的小脚本，把 `src` / `test` / `tools` 下 773 个 `.gd` 逐个 `load()` 一遍；本次靠它确认全仓只有 1 个解析错误，且是**既有**坏文件 `src/entities/bullet/bullet_track_base.gd`（`_physics_process` 中间插了一个 `var`，见 [TODO清单](../TODO清单.md)，与本次改动无关，`git status` 显示它未被我碰过）。
7. **判定「失败是不是我引入的」**：`probe_zomboss_damage` 报 FAIL。→ **正解**：把 108 个改动文件**整体还原到改动前**再跑同一个探针，结果同样是 FAIL ⇒ 既有问题，不背锅；随后换回我的版本并复跑门禁确认 PASS。这套「save → 还原 → 跑 → 换回」值得照搬（前提是确认这批文件里没有重名，压缩包按叶子名回填才安全）。

## 给后来者的最简路径

1. 先全量列出调用点（`文件:行号:原文`）→ 人工挑出要保留的「大事件」清单（按里程碑，不按「看起来重要」）。
2. 一次性脚本从后往前删整条语句（跨行靠括号配平），**先删日志、最后再删被注释掉的调试行**（避免行号错位吞掉保留项）。
3. 空块补 `pass` 后**必须**再跑一遍「误插检测 + 缩进规范化」，剩下的逐个人工改成更干净的写法；条件里有副作用（`consume_rake_use()` 这类）的 `if` 不能整块删。
4. 验证三件套：编译门禁 → 全量 `load()` 解析校验 → 抽 3~6 个覆盖改动面的无头探针；探针 FAIL 时先「还原改动重跑」判定是不是既有问题。
5. 同步文档（规范里的示例与级别表、自检措辞、TODO 里引用了被删代码那行）→ 删临时脚本与备份。
