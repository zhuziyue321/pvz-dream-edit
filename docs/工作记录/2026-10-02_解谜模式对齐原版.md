# 2026-10-02 · 关卡与地图 · 解谜模式改成与原版相同的 10+10 关

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮长对话，未开游戏（改完时 Godot 编辑器开着，不能同时跑批）
> **验证方式**：免验证 + 已给出人工验证方法（见文末）
> **补充自**：无

## 目标

把解谜模式从「仓库自己攒的 20 个砸罐子关 + 10 个我是僵尸关」改成**与原版一致的两页各 10 关**
（花瓶终结者 9 关 + 无尽、僵尸公敌 9 关 + 无尽），关卡名用原版字符串，罐子内容 / 可用僵尸按原版配置。
无尽关本身不重做（用户明确说「不用管无尽」），只保留每页一个。

## 步骤

1. **先定「原版到底有几关」**，别照仓库现状猜：
   - 仓库里的 `data/strings/lawn_strings.txt` 就是原版字符串文件 → `SCARY_POTTER_1~9` + `SCARY_POTTER_ENDLESS`、
     `I_ZOMBIE_1~9` + `I_ZOMBIE_ENDLESS`。**关卡名直接抄它**，不要自己翻译。
     （`SCARY_POTTER_10「不留情面」`没有对应关卡，是残留字符串，跳过。）
   - wiki 的 `Template:Puzzles` 与成就「Win all 9 Vasebreaker Trophies / all 9 I, Zombie Trophies」
     交叉确认 = 各 9 个正式关 + 1 个无尽。
2. **逐关配置取 `Puzzle Mode/Strategy guide`**：每关都写了
   `Zombies: … / Plants: … / Vases per row: N`，而且**植物数 + 僵尸数 = 每排罐子数 × 5**，
   9 关全部对得上 —— 这条等式就是自检手段。
3. 重写 `src/levels/mode_puzzle/puzzle_pot_01..09`（罐子内容）、
   `puzzle_zombie_01..09`（可用僵尸 + 纸板植物权重）。
4. `puzzle_pot_10` 改成无尽（`game_round = -1`，沿用原 `puzzle_pot_18` 的罐子配置），
   删掉 `puzzle_pot_11..20`（先确认只被选关场景引用）。
5. 改 `src/menus/choose_src/levels/puzzle_choose_level.tscn`：删掉页 1 的 `ChooseLevelButton11..20`
   与 `pot_11..20` 的 `[ext_resource]`，再把 20 个按钮的 Label 改成原版关卡名。
6. 同步文档：在 [特殊关卡.md](../参考存档/特殊关卡.md) 新增「解谜模式」一节（两张关卡表 + 配置字段 + 踩坑），
   更新 [参考存档 README](../参考存档/README.md) 索引那行的一句话。

## 关键决策与理由

- **关卡名一律取 `lawn_strings.txt`，不自己翻译** —— 原版中文名就在仓库里（僵尸公敌 / 地道战 / 死亡气球 /
  力拔山河 / 太空舞步 / 飞檐走壁 / 大混战…），wiki 的英文直译反而对不上（如 `Dead Zeppelin` ≠ 死亡飞艇）。
- **罐子内容全写进 `random_pot_plant` / `random_pot_zombie`（棕色神秘罐），再用 `pot_hint_num` 挑 2 个换绿罐**
  —— 与冒险 4-5 同一套写法；直接写 `plant_pot`（绿罐）会把具体植物泄底。
- **「每排罐子数」用 `pot_col_range` 的起始列表达**，结束列恒为 9（见踩坑 1）。
- **僵尸公敌的 `start_sun = 50`** —— 原版「阳光不够放最便宜的僵尸就算输」，最便宜的僵尸正好 50。
  为了不出现「全场没有向日葵 → 必然打不下去」，给每关加 `all_must_plants_on_zombie_mode = {2: N}` 兜底，
  并把向日葵权重给到 6。
- **`max_choosed_card_num` = 本关可用僵尸个数** —— 否则卡槽右侧会空出一排占位（默认 10 槽、只填 3 张卡）。
- **两页全部改回夜晚前院** —— 原版所有解谜关（除 Last Stand）都在夜晚前院；
  仓库原本多出来的「泳池罐子 / 屋顶罐子 / 泳池僵尸 / 屋顶僵尸」不是原版内容，随关卡一起删掉。
- **不碰 `puzzle_zombie_10`（无尽）** —— 用户说不用管无尽，保留原样（它的 `start_sun = 300` 也没动）。

## 踩坑

1. **`pot_col_range` 的结束列写 10 会让关卡直接崩** →
   `PcmPotUtil.init_plant_cell_row_on_zombie_row_type()` 里
   `if pot_col_range.y > row_col.y: pot_col_range.y = row_col.y`，前院 `row_col = (5, 9)`，
   所以 `(4, 10)` 会被**静默夹成** `(4, 9)` = 4 列 = 20 个候选格子，
   而配置里写了 25 个罐子 → `_init_pot_mode_fixed()` 的 `assert(pot_num <= num_pot_candidate)` 崩。
   → **正解**：结束列一律写 9，想加宽就把**起始列**往左挪（5 排 → `(4,9)`、6 排 → `(3,9)`、7 排 → `(2,9)`）。
2. **改选关 `.tscn` 时，删按钮和删 `[ext_resource]` 必须一起做** →
   只删按钮、留着 `pot_11..20` 的 `[ext_resource]`，再删掉那 10 个 `.tres` 文件，
   场景会因为引用了不存在的资源而加载失败。
   → **正解**：一次脚本里按路径正则同时过滤两类行；删完再全局搜一遍确认没有残留引用。
3. **删 `.tres` 前 Godot 编辑器开着** —— 项目规范要求「批量改名 / 移动必须先关闭 Godot 编辑器」，
   开着删会写坏 `.godot` 缓存、报出一堆误导性错误。
   → **正解**：动手前先确认没有 `Godot*` 进程；这次发现时已经删了，只能让用户**重启编辑器**让它重新扫一遍。
4. **PowerShell 脚本里写中文会被 PS 5.1 当 ANSI 读**（`run_autopilot.ps1` 注释里也写了这条）→
   需要改中文文本时**不要**塞进 `.ps1`，用 `replace_in_file` 改；
   脚本只做纯 ASCII 的结构化改动（按正则删行、插数字）。

## 给后来者的最简路径

1. 关卡名：`data/strings/lawn_strings.txt` 搜 `SCARY_POTTER_` / `I_ZOMBIE_`。
2. 每关配置：`https://plantsvszombies.wiki.gg/wiki/Puzzle_Mode/Strategy_guide?action=raw`，
   照抄 `Plants` / `Zombies` / `Vases per row`，并用「植物数 + 僵尸数 = 每排数 × 5」自检。
3. 写 `.tres`：`pot_col_range` 结束列恒为 9；罐子内容进 `random_pot_*`；绿罐用 `pot_hint_num`。
4. 改选关场景：按钮块与 `[ext_resource]` 一起删，再改 Label。
5. 动手前先确认 Godot 编辑器没在跑；改完让用户重启编辑器再进游戏。
