## 目标

用户指名「实现迷你游戏-打僵尸」。开工前先判断这关现状，结论是：**它早就不是空实现**（其它空关卡都带 `⚠️ 空实现` 头，本关没有），

所以本次不是「从零实现」，而是**按原版口径把还差的点补齐 + 把误导性的死数据删掉**。

## 关键决策与理由

- **不为「加强版」拍脑袋填难度数字**：wiki 只说本关是 2-5 的加强版，没有量化数据（对照 [AI查wiki避坑](../参考存档/AI查wiki避坑.md) 的「来源分级」）。
  于是沿用 2-5 那套默认参数，把旋钮的位置写进注释，谁要调自己填。
- **删出怪表而不是「改成正确的三种」**：留在那儿会让人以为本关在按这张表出怪（实际不是），删了最诚实；
  原版那三种正好等于管理器自带候选（普通 → 第 4 波加路障 → 第 6 波加铁桶），写在注释里。

## 踩坑

1. **多 agent 并行时没法自己跑游戏验证** —— `run_autopilot.ps1` 报 `The process cannot access the file because it is being used by another process.`，
   打屏的 STDOUT 其实是**别人的探针**（`probe_zombie_nimble.gd`）留下的旧内容，文件名 xxx ≠ 跑的就是你的脚本；
   同时 stderr 一片 `Could not find type "TreeFood"/"TreeOfWisdom"`（花园那块正被另一个 agent 改，全仓连带编译失败）。
   **正解**：同一时刻只跑一个游戏实例（[Agent协作协议](../../docs/Agent协作协议.md) §4）；跑之前先看 STDOUT 里的
   `场景脚本:` 行是不是自己的场景，是别人的就说明报告被串了，别拿它的结论当证据。
2. **锤僵尸出怪模式不读 `zombie_refresh_types`** —— `HammerZombieManager` 用的是自己的候选队列
   `curr_zombie_type_candidate`（开局只有 Z001Norm，第 4 波 append Z003Cone、第 6 波 append Z005Bucket），
   关卡数据上那份表只有普通 `E_MonsterMode.Norm` 才消费。**在这类关卡里写出怪表只是装饰。**
3. **「文件存在」不等于「实现过了」也不等于「没实现」** —— 空关卡有统一的 `⚠️ 空实现` 头 + TODO 列表可以看，
   开工前先 grep 这一句比通读代码快得多。

## 验证

**人工验证方法**（仓库能编译后，主菜单 → 迷你游戏 → 第 3 行「打僵尸」）：

1. 进关**立刻**看到整块草坪 + 左侧小推车，**不是**先看到房子（相机 `camera_init_x` 生效）；
2. 出战卡槽只有 3 张：寒冰菇 / 墓碑吞噬者 / 土豆地雷，阳光 0，天上不掉阳光；
3. 鼠标是锤子：点草地右侧的墓碑附近，普通僵尸 1 下死、路障 2 下、铁桶 3 下；
4. 锤死僵尸偶尔掉 3 颗阳光（共 75），拾了能种上述植物；
5. 墓碑吞噬者啃掉墓碑会掉一枚银币；墓碑被打光后会自己冒新的出来。

未跑探针 / 未开窗口：原因见「踩坑」第 1 条。改动本身只碰关卡脚本的两个字段 + 注释，
`camera_init_x` 的用法与 `start_battle()` 无参调用都已在冒险 2-5 / 多个既有关卡里跑通过，风险低。
