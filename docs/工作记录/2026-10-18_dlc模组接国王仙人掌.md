# 2026-10-18_dlc模组接国王仙人掌

> **本次任务**：把 DLC 模组里已导入的动画接出第一株能种的植物 —— **国王仙人掌**（KingCactus，**全屏索敌 + 八方向散射**，尖刺走「径向匀加速 + 轴向匀加速」），含配方登记 / 卡面 / 图鉴 / 装卸。
> **耗时 / 轮次**：4 轮（写代码 → 探针发现动画库取不到 → 覆盖 `AnimLib` 的库；后续按反馈改缩放口径、改八方向散射、改全屏索敌与加速度）；**开了游戏**：无头探针，未开窗口
> **推荐度**：推荐（探针 35 条断言全绿）

## 目标
1. 从 33 只只有动画的角色里挑一株最干净的（`idle` + `shooting` 两段就能跑）做成能种的射手。
2. 走本体通用口子（`PlantRuntimeRecipe` / `PlantRuntimeKit`），本体零改动。

## 最简路径（步骤）
1. 选题：`mods_builtin/dlc/animation/character/plant/KingCactus/` 只有 `idle` / `shooting` / `blink` / `face` 四段，没有头身分离、没有皮肤变体 —— 最适合当第一株。
2. 量尺寸：DLC 动画的 `Sprite2D` 全是 `centered = false`，`position` 是**左上角**。用 Python 读 `KingCactus_idle.tres` 第 0 帧的 `position` / `scale` / `rotation` / `texture` 轨道，四角过变换求包围盒 → `x[-1.5, 82.0] / y[-2.8, 84.4]`（整株 ≈ 84×87 px），脚底中心 `(40.3, 84.4)`。
3. 场景 `kingcactus/plant_kingcactus.tscn`：继承 `plant_base.tscn`，`Body` 下挂 DLC 的 `KingCactus.tscn`（**不设 scale**，`position = -(脚底中心) = (-40.3, -84.4)`），加 `Marker2D`（刺飞出处）、`DetectComponent`（全屏框，见第 7 步）、`AttackCdTimer` + `ShootTimer`，`AnimComponent` 换成 `component_anim_empty.gd`（没有 AnimationTree）。
4. 脚本 `kingcactus/kingcactus_plant.gd`：`extends Plant000Base`，照 PVZ2 火焰豌豆那条路 —— `DetectComponent` 的两个信号 + 冷却计时器驱动 `AnimationPlayer`，`ShootTimer`（0.5 秒）到点齐射。**不要**用 `AttackComponentBulletBase`（它写死 `AnimationTree`）。
5. 子弹 `kingcactus/kingcactus_spike.gd` + `kingcactus_spike.tscn`：继承本体 `bullet_cactus.tscn`，重写 `_physics_process` 自己维护速度向量（初速 50；径向匀加速 160；**速度方向每帧按恒定角速度 0.9 rad/s 旋转**，`axial_sign` 决定转向），按 `axial_sign` 决定往哪边弯；植物每轮翻转符号（`_volley_index` 奇偶）。
6. 八方向：`Vector2.RIGHT.rotated(TAU * i / 8)`，齐射 8 根；**子弹不吃行属性**（`IsActivateLane = false`），否则 45°/90° 那几根永远打不到别的行。
7. 全屏索敌：检测框做成 2400×1600 的大矩形（视口 800×600，植物种在角落也罩住整场），并关掉 `DetectComponent.is_lane` 的行过滤。
8. `dlc_mod.gd`：`install()` 里建配方 → `PlantRuntimeKit.install()` + `make_selectable()`，`uninstall()` 里 `kit.uninstall()` + 摘图鉴条目，`install_to_main_game()` 里补 unlock。
9. 探针 `test/scenarios/probe_dlc_kingcactus.gd`：注册 / 卡位 / 图鉴 / 种下去 / 四段动画 / 全屏检测框 / 八方向 / 轨迹弯向 / 切段 / 卸模组。

## 弯路 / 踩坑（三段式）
- **试过**：直接用动画场景里的 `AnimLib` 播 `KingCactus_idle`。
- **因为**：探针报 `Animation not found: "KingCactus_idle"`。翻 `.tscn` 才发现转换工具把**每段动画各放进一个独立 `AnimationPlayer`**（`Anim_KingCactus_idle` 等），而 `AnimLib` 的库里**只有一条名叫 `ALL_ANIMS` 的合并动画**，不是分段名。卡面取帧（`AnimationFrameUtil`）找的偏偏是第一个播放器 = `AnimLib`，所以连卡面都取不到。
- **结论**：在**自己的**植物场景里覆盖 `AnimLib` 的 `libraries`，把要用的几段 `.tres` 合成一个 `AnimationLibrary` 挂上去。一个播放器分段播，取帧也顺带修好。不要改生成出来的 `animation/` 目录（那是工具产物，重转一次就覆盖）。
- **试过**：给 DLC 动画节点加 `scale = 0.7`，以为转换产物是 1:1 像素、要缩到格子里。
- **因为**：只看 PNG 尺寸（整株 98×96 原始像素），没看**动画的 `scale` 轨道**。实际上转换工具已经把原版 reanim 的每部件缩放写进轨道了（DLC 这部 0.762，本体仙人掌 0.8，同一量级），根节点再加一层就整株只剩 53%。
- **结论**：动画根节点**不设 scale**，只按包围盒算 `position`；包围盒也必须把部件的 `scale` / `rotation` 算进去（四角过变换），否则量出来偏大。探针里断言 `KingCactusAnim.scale == Vector2.ONE` + 场上内容尺寸落在 70~100 px，防止后人再叠一层。
- **试过**：只按 `position` 轨道 + PNG 尺寸量包围盒。
- **因为**：`Sprite2D` 是 `centered = false`，节点 `position` 是左上角、坐标原点在画布左上，直接按 PNG 原始尺寸算会把整株量大约三成。
- **结论**：包围盒 = 每个部件 `(0,0)-(w,h)` 过 `scale` / `rotation` / `position`，再合并；`position` 取 `-(包围盒水平中心, 包围盒底边)`。
- **试过**：把检测框放大到覆盖全场，就以为「全屏索敌」做完了。
- **因为**：`DetectComponent` 自己还有一道行过滤 —— `_on_area_2d_area_entered()` / `_judge_enemy_is_can_be_attack()` 里 `if is_lane and owner.lane != enemy.lane: return`。框再大，别的行的僵尸也进不了可攻击列表。
- **结论**：全屏索敌要**两处一起**改 —— 检测框放大（2400×1600，视口 800×600）+ `DetectComponent.is_lane = false`。探针同时断言这两条，只改一条就会漏。
- **试过**：八方向散射时沿用了原来的 `IsActivateLane = detect.is_lane`（true）。
- **因为**：`Bullet000NormBase._on_area_2d_attack_area_entered()` 里 `is_activate_lane and lane != enemy.lane` 会直接返回 —— 45° / 90° 的刺即便攻击框压在别的行僵尸身上也不算命中。
- **结论**：散射子弹一律传 `IsActivateLane = false`，命中只由攻击框与受击框的空间重叠决定（行号仍传，只用于 `z_index`）。
- **试过**：模组自己 `preload` 子弹场景直接 `instantiate()`（不走 `BulletRegistry`，因为注册表是 `const` 静态表、没有运行期注册口）。
- **因为**：`BulletRegistry.create_bullet()` 除了造实例还做两件事 —— `entity_id` 领号、联机闸门判断；绕过它就会漏号（联机里两颗子弹同号）。
- **结论**：模组内复用同一个口子的三件事：`bullet.entity_id = Character000Base.take_next_entity_id()`、读 `GlobalUtils.bullet_spawn_gate`、再 `add_child`。想要更干净可以给本体加一个「运行期注册子弹场景」的口子（本次没动本体）。
- **试过**：把子弹的 `radial_acceleration` 改名成 `radial_from_axial_ratio` 后，只改了脚本，没动场景。
- **因为**：`.tscn` 里残留 `radial_acceleration = 100.0` —— Godot 对已经不存在的导出属性只会警告 / 忽略，场景照常能开，实际生效的却是另一组旧值（本次场景里 `speed` / `axial_acceleration` 也都停在手调过的旧值），探针一跑才发现「初始速度 50」跟自己写的不一致。
- **结论**：改 / 删导出变量名时全仓搜一遍，把 `.tscn` 里的旧行一起清掉；探针把关键数值打进日志（本探针每次打印 speed / axial / ratio），能第一时间看出「场景值 ≠ 脚本默认值」。
- **试过**：先做「径向加速度 ∝ 轴向速度」，后来改成「轴向加速度 ∝ 径向速度」，以为只是两个变量换位置。
- **因为**：两个量的**初始值不同** —— 径向速度起步就是初速（50，不为 0），轴向速度起步是 0。所以「轴向 ∝ 径向速度」一出手就有侧偏加速度（1.2×50=60）；而「径向 ∝ 轴向速度」一出手径向加速度是 0（先直后弯）。
- **结论**：换正比方向要连带检查初始条件与手感；探针里「刚出手的加速度」直接断言出来，换方向时会立刻红一条，比看代码靠谱。
- **试过**：把轴向从「加速度 ∝ 径向速度」改成「恒定角速度转向」。
- **因为**：两者形状完全不同 —— 垂直于**固定方向**加加速度是越飞越弯的抛物线；每帧旋转速度向量则是圆弧，曲率半径 `v/ω` 随速度变大（半径越转越大）。
- **结论**：角速度口径直接断言「转过的角度 = ω × 已飞行时间」（本次 0.465 = 0.9 × 0.5167），比看位移更可靠；`_elapsed` 顺手留给探针用，别只靠 `await` 推算时间。
- **试过**：用 `AnimationFrameUtil.get_content_rect(anim_root)` 量位置，再手动 `+ anim_root.position` 换算成 Body 坐标，结果算出差 91 px、以为整株悬空。
- **因为**：`get_content_rect()` 内部是 `_collect_rect(root, IDENTITY)`，**root 自己的 transform 已经算进去了** —— 返回值本来就是「相对 root 父节点」的坐标，再加一次 position 等于减了两次。
- **结论**：量「相对 Body 的位置」直接用返回值；要相对 root 自身的局部坐标才需要减 position。把这条写进探针注释，别再二次加。
- **试过**：让动画的「最低点」对齐到植物原点（`position.y = -84.4`），以为就是贴地。
- **因为**：本体仙人掌的内容底部在 Body 坐标 **+6.9**（植物整体比原点低一点才「贴地」），DLC 这株又没有根 / 花盆，只对齐最低点会悬在格子上半部。
- **结论**：以本体同类植物为基准量底部（本体仙人掌 +6.9），再按需要下压：先 10 px（+9.9），按反馈又下压 10 px（现底部 **+19.9**，比本体低 13 px）。探针断言「底部比本体低 10~25 px」，换角色时改动画节点 position 即可。
- **试过**：攻击间隔 1.4 秒，短于 `KingCactus_shooting` 的 1.417 秒。
- **因为**：CD 到点时 `_start_attack()` 会 `play(shooting)` **从头重置**，开火动画永远播不完 —— 看起来就是「动画和发射对不上」。
- **结论**：`attack_cd` 必须 > 开火动画时长（现 1.6 秒）；**出刺时机按动作峰值取** —— `ShootTimer` 1.0 秒 = `KingCactus_shooting` 第 12 帧（17 帧 @12fps），那一帧所有可见部件的平均 `position.y` 最大，也就是整株蹲得最低的时候。
- **踩过**：跑探针时习惯性带 `-KillStale`（沿用 H-08 的「跑批前先杀残留」说法）。
- **因为**：`Get-Process *godot*` 会把**用户正开着的编辑器 / 游戏窗口**一起算进去，`Stop-Process -Force` 直接杀掉，未保存的场景与脚本全丢 —— 本次被明确要求停手。
- **结论**：跑批自检**只查不杀**；遇到 `STALE_PROCESS` 先等它自己退（`run_autopilot` 每批一份独立 usrdir，正常会 `quit_game()`），再请用户关窗口；要并行跑用 `-UsrDir` 另开临时目录。规则已写进 [AI调试通道.md §十](../AI调试通道.md#十跑批命令照着抄)。

## 推荐度与理由
推荐。整株只有"一个场景 + 一个脚本 + 一段配方"，本体零改动；`DetectComponent` + 计时器 + `BulletRegistry` 这条路 PVZ2 模组已经踩平，DLC 只是把动画来源从 PAM 换成 `AnimationPlayer`。

后来者注意：① 接下一只前先看它的动画段有没有 `shooting`（纯投手 / 近战还得另写判定）；② 同一角色若带皮肤变体（`PultShroomC1_*` / `BonkChoyF_*` 那种），要自己挑一套，别把两套一起挂；③ 跑探针遇到 `STALE_PROCESS` **不要 `-KillStale`、也不要 `Stop-Process *godot*`** —— 那个 godot 很可能就是用户开着的编辑器 / 游戏窗口，杀了会丢未保存内容；等它自己退或请用户关（详见 [AI调试通道 §十](../AI调试通道.md#十跑批命令照着抄)）。
