# 2026-10-23 动画封装：驱动源（本地代码 / 包分发）+ 联机接管下沉

> **任务类型**：架构整理（把散在模组里的能力收回本体）
> **一句话**：动画本来只有「组件」没有「封装」——`AnimComponentBase` 只管速度与上报，
> 「播哪条」单人靠场景里的 `advance_expression` 自己推、客户端靠联机模组递归找播放器硬拽。
> 这次给组件加**驱动源**（`LOCAL` / `REMOTE`）与统一 API，模组只负责打包解包，植物 / 僵尸 / 僵王一次性打通。

---

## 1. 动手前的现状（为什么说"不算封装"）

| 现象 | 位置（改前） |
|---|---|
| 采集问组件，驱动却绕过组件 | `netplay_state_sync.gd`：`update_current_anim()` 问组件，`play()` / `seek()` 自己干 |
| 模组必须知道角色内部结构 | `_anim_player_of()` 自己 `as AnimComponentNorm` → 取 `animation_tree.anim_player`（NodePath） |
| 模组往角色身上打标记 | `character.set_meta(&"netplay_anim_taken")` + 直接 `animation_tree.active = false` |

结论：**能力长在模组里，本体没有对外的"动画控制"接口**。宿主结构一改（树挪进 Body），客户端动画静默失效。

## 2. 设计（薄封装，不动存量场景）

关键判断：**不重写 240 个 `.tscn` 的动画树**。存量植物继续用 `advance_expression` 自动推导，
新写法用 `request_state()` 显式点名；两者都归组件管，客户端一律吃"下标 + 相位"。

```
AnimComponentBase（唯一入口，%AnimComponent）
  ├ LOCAL  : request_state() / request_one_shot() / cancel_one_shot()
  ├ REMOTE : take_over() / release() / apply_anim_index() / apply_anim_phase() / apply_packet()
  └ 共性   : snapshot() / anim_index_of() / anim_name_at() / get_animation_player() / update_current_anim()
```

## 5. 踩坑记录（下次直接抄结论）

1. **`host_node_of` 换掉 `$"../AnimationTree"` 必须先验**：取不到不会报错，只会打一条 WARN 且每次运行只打一次。探针里显式断言 `norm.animation_tree != null`，别只靠"没报错"。
2. **裸 `new()` 的角色没有 `anim_component`**：`@onready` 没跑。模组里的 `_apply_anim` / `_apply_anim_phase` 必须判空，否则 probe 一跑就崩（`probe_netplay_session` 正是用裸节点测的）。
3. **`travel()` 到当前状态会从头重播**：`request_state()` 必须短路"已经在目标状态"，否则检测信号每帧触发 = 动画永远停在第一帧。
4. **`advance_expression` 与手动 travel 打架**：迁一株植物的状态切换必须**同时**改 `.tscn` 里那两条转换 —— 只改脚本等于没改。
   ⚠️ 正确写法是 `advance_mode = 1` + `advance_condition = &"__manual_travel"`（恒假条件）：
   只删 `advance_mode`（默认 DISABLED）可能 travel 不走；`advance_mode = 1` + 空条件则会每帧自动推进。
5. **状态机不是 `tree_root`**：本仓约定树根是 `AnimationNodeBlendTree`，状态机是它下面名为 `StateMachine` 的节点。
   写成 `tree_root is AnimationNodeStateMachine` 判断恒为 false ⇒ `request_state()` 静默什么都不做（**地刺不攻击就是这么来的**）。
   要按 `PLAYBACK_PARAM` 的第二段去 `AnimationNodeBlendTree.get_node()` 取。
6. **`travel()` 有 xfade**：调用后要等过渡（0.2 秒）结束再读 `get_current_node()`，等 3 帧读到的还是旧状态（探针第一次就是因此误报 FAIL）。
7. **远端驱动下不能写 timescale**：树已停，写它无效；速度差靠 `apply_anim_phase()` 硬拉（阈值 `PHASE_RESYNC_EPS` 由量化噪声决定，别往下调）。
8. **`run_netplay_pair.ps1` 的 Godot 默认路径是旧的**（`Godot_v4.6.2-stable_win64.exe` 不存在），要显式传 `-Godot "C:\Users\a a\Desktop\godot.exe"`。
9. **探针没覆盖的路径别当它是对的**：远端 API 全测了，`request_state()` 没测 ⇒ 地刺不攻击这个 bug 是在交付后才由用户发现的。新增机制时给**本地**入口也写一条断言。

## 6. 第二批：全量原版植物迁移（同日）

运行期会变化的状态切换已全部改成脚本点名，涉及 **18 株植物 / 38 条转换**：

| 组 | 植物 | 做法 |
|---|---|---|
| 地刺类 | 地刺、钢地刺 | 检测信号 → `request_anim_state` |
| 攻击类 | 窝瓜、玉米加农炮、磁力菇 | 脚本信号 / 计时器里点名 |
| 啃咬类 | 大嘴花 | `change_is_attack` / 咀嚼计时器 / 动画轨回调 |
| 生长类 | 阳光菇、土豆雷、小胆菇 | 成长 / 准备 / 害怕组件信号 |
| 姿态类 | 仙人掌、保护伞 | 攻击状态变化 / 撞击事件 |
| 睡眠类 | 10 株蘑菇 | **基类一条逻辑**：睡眠组件信号 → 后缀匹配 `*_sleep` / `*_idle`（冰菇展示态走 `_idle_only`） |

**故意保留表达式**的边：`Start → *`（`is_idle` / `is_show` 决定初始状态，对植物是常量）、`*_aquarium`（`is_garden_aquarium` 只在 `init_garden_component()` 赋一次）、坚果 `is_face` / 花盆 `is_water`（字段不存在，恒假）。

验证：`probe_anim_component` 扩到 **17 株状态名存在性 + 地刺/钢地刺双向切换 + 10 株睡眠切换**，`result=PASS failed=0`。

踩坑补两条：
- **`switch_mode = 2`（At End）的转换，`travel()` 要等动画播完才生效**（钢地刺回待机实测 0.35 秒不够，探针误报过一次）。
- 状态名不等于"植物名 + 动作"：大嘴花的啃咬状态叫 **`Bite`**（不是 `Chomper_Bite`），磁力菇是小写 **`Magnetshroom_*`**。改 `.tscn` 前先用脚本按 `(from, to)` 精确匹配，别按命名猜。

`docs/参考存档/动画封装.md` §3 已补「已迁移清单」与「故意不改的边」两张表。

## 7. 第三批：连初始化边也收进代码（全植物收口）

第二批保留的 `Start → *` 初始化边（靠 `is_idle` / `is_show` / `is_sleeping` / `is_garden_aquarium` 决定初始状态）这一批也改成手动 travel，初始状态统一由 `Plant000Base._apply_initial_anim_state()` 选：

| 顺序 | 判据 | 结果 |
|---|---|---|
| 1 | `is_sleeping` | `*_sleep` |
| 2 | `is_show` | `show_anim_state` → `*_idle_only` → `*_idle` |
| 3 | 花园 + `is_garden_aquarium` | `*_idle_aquarium` → `*_idle` |
| 4 | 出战 | `norm_anim_state` → `*_idle` |

新增两个 `@export`（配在 `.tscn` 根节点）：`norm_anim_state`（出战一次性出场动画）、`show_anim_state`（展示特殊形态）。

- 出场类 12 株配了 `norm_anim_state`：三叶草、樱桃、咖啡豆、毁灭菇、墓碑吞噬者、模仿者、辣椒、土豆雷、魅惑菇、胆小菇、小喷菇、海蘑菇。
- 展示特殊 2 株配了 `show_anim_state`：阳光菇（grow）、土豆雷（rise）。
- 毁灭菇覆盖 `_after_anim_wake()`：白天被唤醒直接切 `DoomShroom_explode`（原靠 `not is_idle` 自动触发）。
- 死条件表达式（坚果 `is_face`、花盆 `is_water`）一并清掉。

规模：**27 株植物 / 88 条转换**（含前两批），57 个植物场景中带状态机的已全部处理。

验证：`probe_anim_component` 新增「27 株展示体已离开 `Start`」断言 —— 任何一株漏了初始状态 request 会停在 Start（完全没动画），该断言会立刻暴露。`result=PASS failed=0`，`probe_gameplay_core` PASS。

踩坑补一条：
- **判据不能写 `anim_name_now != &""`**：仙人掌的初始状态是**混合树**（`BlendTree`），下钻拿不到叶子动画名（改动前也读不到），要用 `playback.get_current_node() != "Start"` 判断。
