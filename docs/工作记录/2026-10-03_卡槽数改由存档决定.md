# 2026-10-03 · 其它 · 出战卡槽数改由存档决定，关卡按需覆盖

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（一次性脚本实测取值范围）
> **验证方式**：免验证 + 已给出人工验证方法（跑了一次性取值脚本，UI 未开窗口看）
> **补充自**：无

## 目标

`max_choosed_card_num`（出战卡槽数）不再由关卡资源决定：
- 关卡**没写** → 取存档的卡槽数（原版初始 6 + 商店已购扩充，上限 10）；
- 关卡**写了非 0 值** → 覆盖存档值（2-5 固定 3 张卡、僵尸公敌「可用僵尸数」这类设计值）。

## 步骤

1. 改 `src/levels/core/level_data.gd`：字段默认值 `10` → `0`（0 = 不覆盖），
   `get_max_choosed_card_num()` 改成「非 0 用关卡值，否则 `Global.global_game_state.get_card_slot_num()`」，
   删掉原来「只给冒险模式 + 可选卡关卡加扩充」的三分支。
2. `GlobalGameState` 新增 `get_card_slot_num()`（= `ConstShop.BASE_CARD_SLOT_NUM + card_slot_upgrade_num`，上限 `MAX_CARD_SLOT_NUM`）；
   存档字段仍只有 `card_slot_upgrade_num`，不新增字段、不动存档格式。
3. 批量删掉 48 个冒险关卡脚本里的 `max_choosed_card_num = 6`（PowerShell 正则整行删，保留换行与编码）。
4. 给「默认值变了会掉卡」的关卡补写覆盖值：`puzzle_zombie_10 = 10`（10 只可用僵尸，不写会被 6 槽挤掉 4 张）、
   `minigame_02_hammer_zombie = 3`（固定 3 张卡，对齐 2-5）。
5. `DaveSellManager` / `GoodsCardSlot` / `ConstShop` 的注释与显示统一走 `get_card_slot_num()`。
6. 测试探针 `probe_card_lock` / `probe_night` 改读 `get_max_choosed_card_num()`（原来直接读字段）；
   `probe_night` 另加一条「关卡资源覆盖值」断言。
7. 文档同步：`docs/参考存档/卡片与选卡流程.md` 的「卡槽基准与扩充」段、`特殊关卡.md` 两处。

## 关键决策与理由

- **存档侧不新增字段，只加 getter** —— 卡槽唯一的可变量就是「买了几次扩充」，
  存次数（`card_slot_upgrade_num`）已经够了，再加一个 `card_slot_num` 就要维护两份、还要做存档迁移。
- **关卡字段用 0 表示「不覆盖」而不是删字段** —— 保留「关卡能固定卡槽数」这条通道
  （2-5 / 僵尸公敌 / day_test 的 15 槽都靠它），`@export_range(0, 15)`。
- **冒险关卡必须把 `= 6` 删掉** —— 留着就是覆盖值，商店买的扩充在那关永远不生效，等于没改。

## 踩坑

1. **整行删空了 `_init()`** → GDScript 空函数体是 **Parse Error**（`Expected indented block after function declaration`），
   1-6 / 1-7 / 1-8 / 1-9 四个关卡直接编译不过。
   → **正解**：关卡没有需要预置的属性时**整个 `_init()` 都不写**（`LevelScriptBase` / `ResourceLevelData` 都没有 `_init`，
   删掉等价于空实现），别留 `pass` 空壳 —— 与 `survival_flag_01_day.gd` 的修法一致。
   批量删行后必须扫一遍「`func xxx:` 后面没有缩进块」，逐个处理。
   → **顺手补了生成器**：`test/scenarios/tool_level_tres_to_script.gd` 原来在无属性时会输出
   `func _init() -> void:` + `pass`，现改成整块不输出，以后批量生成不会再留空壳。
2. **`godot --check-only --script x.gd` 报 `Identifier not found: Log/Global`** —— autoload 在该模式下解析不到，
   不能拿它当「编译通过」的判据；但它**能**报出 Parse Error，用来扫语法够用。
   → **正解**：要取值就用 `--script` 真跑一个一次性脚本（autoload 在运行时可用）。
3. **`run_autopilot.ps1` 报 `The process cannot access the file`** —— 临时目录写死
   `$env:TEMP\pvz_autopilot`，两个人同时跑会抢同一个输出文件（本次就撞上了）。
   → **正解**：撞锁时别等，换一次性取值脚本验证核心逻辑，UI 部分交人工。
4. **默认值从 10 变 6 会静默丢卡** —— `CardSlotNorm.init_pre_choosed_card()` 在
   「预选卡数 > 卡槽占位数」时是 `break + Log.warn`，不报错、直接少几张卡（僵尸公敌 10 就中招）。
   → **正解**：凡是关卡自带预选卡的，都要写死 `max_choosed_card_num = 预选卡个数`。

## 给后来者的最简路径

1. 改 `get_max_choosed_card_num()`：非 0 用关卡值，否则 `Global.global_game_state.get_card_slot_num()`；字段默认改 0。
2. `GlobalGameState` 加 `get_card_slot_num()`（BASE + 已购扩充，夹上限）。
3. 批量删冒险关卡的 `= 6`，**删完扫空函数体补 `pass`**。
4. 带预选卡的关卡补写覆盖值，跑一次性脚本打印「覆盖值 / 生效卡槽数」核对。
5. 人工开一关看选卡界面槽数。
