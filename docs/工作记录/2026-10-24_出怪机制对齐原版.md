# 2026-10-24 · 玩法 · 出怪机制对齐原版（一波怎么凑出来）

> **任务类型**：玩法（出怪 / 波次构成，对齐原版 `Board::PickZombieWaves`）
> **推荐度**：**推荐**（同类「把某条数值/编排逻辑对齐原版」照这个走：先读原版函数，把每个分支逐条落到本仓库的数据表，再删掉没有原版依据的本地发明）
> **耗时与成本**：约 2 轮对话；无头探针**未跑**（用户有 Godot 进程占着共享输出，`run_autopilot.ps1` 回报 `STALE_PROCESS`；手动起第二个实例的写法把终端卡住了，已放弃）
> **验证方式**：`test/check_scripts.ps1` → `real compile errors = 0`；节奏 / 密度需人工看一眼（方法见文末）
> **补充自**：无

## 目标

`ZombieWaveCreateManager` 凑一波的算法与`Board::PickZombieWaves()` 有 7 处不一致，要求向原版靠拢。

## 步骤

原版基准（本机只读参照）：`../PvZ-Portable-main/src/Lawn/Board.cpp:534-768`（`PickZombieWaves` /
`PickZombieType` / `PutInMissingZombies`）、`src/Lawn/Zombie.cpp:80-113`（`gZombieDefs[]`）；
`../re-plants-vs-zombies-main/Lawn/Board.cpp:2517+` 逐行交叉验证一致。

1. **大波普僵数**：原版 `aPlainZombiesNum = min(aZombiePoints, 8)`（`aZombiePoints = 波数/3+1`），
   本仓库此前写死「第 10 波 4 只、其余 8 只」→ 改成 `mini(calculate_base_wave_points(wave), 8)`，
   并把旗帜僵尸放到普僵**之后**（原版顺序）。第 20 波因此从 8 只变 7 只。
2. **买不起先排除**：原版 `PickZombieType()` 先按 `剩余点数 < mZombieValue` 过滤再按权重抽；
   本仓库此前是「抽一只、买不起就重抽」。改成 `pick_zombie_within_power(剩余点数)`（临时建一个
   只含买得起的类型的 `RandomPicker`）；一只都买不起时才退回「用普僵补余额」（等价于原版从空权重表落到 0 号普僵）。
3. **最后一波补齐**：新增 `_put_in_missing_zombies()`（原版 `PutInMissingZombies()`）——
   冒险关最后一波把本关出怪表里本波还没出现的类型各补一只，雪人除外。
4. **首次允许波次**：注册表新增 `ZOMBIE_FIRST_ALLOWED_WAVE`（`zombie_info_data.gd` + `CharacterRegistry`
   的 `get_zombie_first_allowed_wave()`），取原版 `mFirstAllowedWave`：撑杆 / 铁门 / 橄榄球 / 舞王 = 5，
   潜水 / 冰车 / 雪橇 / 海豚 / 小丑 / 气球 / 矿工 / 跳跳 / 扶梯 / 投篮 = 10，伽刚特尔 = 15，其余 1。
5. **删掉按波权重衰减**：`_update_weights()`（普僵 `4000-(波-5)*180`、路障 `4000-(波-5)*150`）
   查无原版依据 —— 原版的权重衰减只在**生存模式**按已过旗帜数生效，冒险模式用 `mPickWeight` 原值。
   一并删掉随之失去意义的 `min_power` / `curr_zombie_weight_upper_limit` / `calculate_all_zombie_weight()`。

## 关键决策与理由

- **首次允许波次 / 最后一波补齐只对冒险模式生效**：小游戏 / 生存 / 我是僵尸在原版里各自另写一套出怪规则
  （原版还专门豁免蹦蹦舞会 / 全面冻结 / 蹦极闪电战）。本仓库这些关卡的出怪表已按各自规则写好，
  再套一层会让波数少的关卡前几波空场（蹦蹦舞会出怪表只有蹦蹦，该类型首次允许波次是 10）。
  植物僵尸那几个「第 10 波起」的类型不受此限（原版 ZomBotany 硬规则）。
- **不改成「开局预生成全波次表」**：原版是在 `InitZombieWaves()` 里一次算完整关的 `mZombiesInWave[][]`；
  本仓库逐波现算。逐波现算对构成没有可观察差异（每波只算一次、按序推进），改动面却大得多，故不动。
- **余额补齐保留**：它不是原版明文规则，但对应「空权重表时 `PickZombieType` 落到 0 号 = 普僵」的
  实际效果，且 `probe_pogo_party` 早就把它写进期望，删了反而偏离。

## 踩坑

1. **权重衰减藏得深**：`zombie_weights` 是运行期副本，衰减直接改它，看起来像「数据表」而不是逻辑，
   只看 diff 容易漏掉「后期普僵越打越少」这条非原版行为。
2. **改大波普僵数会打挂探针**：`probe_pogo_party` STEP5 原本写死 `4 if wave == 9 else 8`，
   对齐后第 20 波是 7 只 → 已把期望改成同一条公式 `mini(floori(波/3)+1, 8)`。
3. **别用 `cmd /c` 手动拼 godot 命令行**：路径带空格 + 多重引号在 PowerShell 里会被再转义，
   拼错后 `cmd` 报错、`Get-Content` 又读到上一轮遗留的报告，看起来像「跑了却拿到别人的结果」。
   同步等 headless 进程（`ReadToEnd()`）也会把终端卡住——探针要跑一两分钟，别这么干。

## 第二批（同一天补齐）

6. **二周目点数公式**：`is_second_round_adventure()` = 冒险模式 + `is_from_second_round()` + 关卡不是 1-5
   （原版 `mLevel != 5` 例外），命中后 `calculate_base_wave_points()` 用 `波数*2/5+1`。
   二周目点数更高，大波普僵数（`min(点数, 8)`）跟着一起变。
7. **新登场僵尸固定出场**：注册表新增 `ZOMBIE_STARTING_LEVEL`（原版 `mStartingLevel`）+ `CharacterRegistry.get_zombie_starting_level()`；
   出怪管理器新增 `get_introduced_zombie_type()` / `is_introduced_zombie_wave()`，在**大波之后、补齐与随机填充之前**
   插入一只（原版顺序），中间波 = 每轮波数 / 2，矿工 / 气球提前到第 7 波起。
   实现上只认「本关出怪表里也有」的类型，原版的鸭子圈 / 蹦极 / 雪人三条排除因此天然成立。
8. **顺便修正补齐顺序**：`PutInMissingZombies` 从「随机填充之后」挪到**之前**（原版顺序），
   补齐占的点数会从余额里扣掉 —— 扣成负数时本波就不再随机抽，最后一波的构成更接近原版。

## 评估后不做：开局预生成全波次表

原版 `InitZombieWaves()` 一次算完整关，本仓库逐波现算。对**构成**没有可观察差异（每波只算一次），
但会打掉两个本仓库独有的钩子：`before_wave_spawn`（按局势改密度，如全面冻结融冰后普僵变多）、
`set_banned_spawn_rows`（隐形关前几波禁最下行）。结论：**保留逐波现算**，理由写进
[僵尸波次.md § 为什么不改「开局预生成全波次表」](../../参考存档/僵尸波次.md)。
真要做，先改造这两个钩子的时序，别只改出怪管理器。

## 人工验证方法（约 3 分钟）

1. `F5` → 冒险 **1-8**（普僵 / 路障 / 铁桶）打到大波：第 10 波应是 **4 只普僵 + 1 旗帜僵尸 + 铁桶等**，
   第 20 波（没有 20 波则换 1-9 / 1-10）应是 **7 只**普僵（旧实现一律 8 只）。
2. 冒险 **3-3**（普僵 / 路障 / 潜水）：**前 9 波不应出现潜水僵尸**（原版首次允许波次 = 10），第 10 波起才出。
3. 冒险 **5-8**（普僵 / 路障 / 伽刚特尔，20 波）：**前 14 波不出巨人**，第 15 波起才出；最后一波必定带巨人。
4. 冒险 **2-1 / 2-10** 打到最后一波：应同时看到本关全部出怪类型（2-10：普僵 / 路障 / 铁门 / 橄榄球 / 舞王）。
5. 冒险 **2-1** 的**第 5 波**（中间波，10 波关）与最后一波：必定有 1 只**读报僵尸**（本关新登场僵尸）。
   同理 1-3 第 5 波必有路障、1-6 必有撑杆、5-8 中间波必有巨人。
6. **二周目**（通关后重玩）：同样波次僵尸明显变多（点数 `波数*2/5+1`，第 30 波 13 点 vs 首周目 11 点）；1-5 例外不变多。
