## 目标

僵王博士（`ZB001Doctor`）是从 1066x600 的 v1.3.0 整体移植的，进冒险 5-10 / 迷你 20 后
**整只机甲都在画面外**（屏幕 x 1758~2093，视口只有 800）。要求整体位移，让机甲在 800x600 下
视觉上站在草坪右侧、驾驶舱与腿可见。

## 现状测量（改之前）

- 出生点 `boss_spawn_position = Vector2(1030, 330)`（`adventure_05_10.gd` / `minigame_20` 两处硬编码，
  是移植 v1.3.0 时新填的——**v1.3.0 的关卡资源里根本没配这个字段**，默认 `Vector2.ZERO`，
  所以 1030 没有任何「1066 时代调好的视觉」可参照，本身就是错的）。
- 博士场景的构图：`Body/BodyCorrect = (100, 0)`，机身各部件局部 x 高达 900~1050，
  实测机身（不含手臂）相对根节点 **x ∈ [733, 1075]、y ∈ [-253, +463]**（高 715 > 屏高 600，
  怎么摆都必然上下各裁一部分——原版博士机甲本来就是上下出屏的）。
- `ZombieBossRoot`（`main_game_base.tscn`）无任何 position/scale，`boss.position` 即世界坐标。

## 步骤

1. **算 `screen = world - camera.position.x`**（相机归位 `CAM_POS_ORI.x = 10`，见
   [2026-10-03_分辨率改成800x600.md](2026-10-03_分辨率改成800x600.md) 补充 4）。
2. 新增探针 [test/scenarios/probe_zomboss_layout.gd](../../test/scenarios/probe_zomboss_layout.gd)：
   进冒险 5-10 → 等博士出场并回到 Idle → dump 机甲所有可见 Sprite2D 的**屏幕矩形** +
   关键锚点（头 / 双脚 / 影子 / 受击框）+ 截图到 `test/shots/zomboss_layout.png`。
3. 依据测量把出生点 `1030 → -240`（整体左移 1270）：机身落在屏幕 x 490~823（右溢出 23），
   驾驶舱 `(643, 117)`、内侧脚 `(509, 436)`、外侧脚 `(526, 609)`、受击框 `(658, 669)` 全部在画面内。
4. `minigame_20_zomboss_revenge.gd` 同步同值（两关同口径）。

## 关键决策与理由

- **只改出生点，不动 `data/character/zombie_boss/001_doctor/*.tres`**：技能的 `part_position`
  全是「相对博士根的绝对局部位置」（`skill_base.apply_visual_position()` 直接赋给部件），
  博士整体平移后技能部件、冰火球嘴部生成点、奖杯点、受击框全部**自动跟着平移**，
  不存在「列定位点要反补 1270」的问题。
- **Y 保持 330 不动**：机身高 715 必然上下出屏；330 时驾驶舱顶 y=77、内侧脚 y≈437 都在最舒服的区间，
  与原版「机甲上半身在屏幕内、外侧脚伸到屏幕下缘外」的构图一致。
- **入场演出不再有「从屏外驶入」**：`Zombie_boss_enter.tres` 没有任何根/Body 位移轨道
  （v1.3.0 也一样），博士本来就是原地播入场动作，出生点在屏内不影响表现。

## 踩坑

1. **无头跑僵王关会静默卡死**：`--headless` 进冒险 5-10 后探针停在「主游戏开始」，
   看门狗 180s 强杀且无任何报错（疑似博士场景的粒子/离屏渲染在无头下挂起）。
   → **正解**：涉及博士的场景一律 `run_autopilot.ps1 -Windowed`，跑完手动 `Stop-Process` 清 Godot。
2. **「1066 时代的值」未必存在**：搜遍 v1.3.0 找不到 1030 的出处（关卡资源没配 `boss_spawn_position`），
   别按「1066 下是对的、平移 266 就行」的惯性去算，先实测再定数。
3. **量几何别信场景静态 `position`**：博士部件全 `visible=false`，真正姿势由动画轨道决定，
   必须实例化 → 播 idle → 再量 `get_global_transform_with_canvas()`（探针里已封装 `_screen_rect`）。

## 遗留（本次未做）

- `bungee_first_column_position` / `throw_rv_cell_one_position` 三个场地配置的「第 1 列标定基准」
  在移植前后都对不上（蹦极三个手指锚点彼此只差 ~12px，而列距 ~85px，一个 InnerArm 位置不可能
  同时对准三列）；蹦极代码里用 `to_local(格子)` 动态补偿列差，基准本身的偏差属于
  v1.3.0 移植质量问题，等实际跑蹦极 / 砸车技能发现落点歪了再修。

## 人工验证方法

1. `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss_layout -Windowed`
   → 看 `[ZOMBOSSLAYOUT]` 报告与 `test/shots/zomboss_layout.png`。
2. 进冒险 5-10（或迷你 20）亲眼确认：博士站在草坪右侧、驾驶舱可见、血条不被完全遮挡、
   放僵尸 / 冰火球 / 脚踩 / 蹦极四个技能的落点与动画协调。
