# 2026-10-10 · 联机同步 · 把渲染所需的信息全部放进快照

> **任务类型**：其它（联机同步）
> **推荐度**：**推荐**（"渲染态不能让客户端自己推，要显式下发"这条判据可直接照用）
> **耗时与成本**：约 1 轮，未开游戏（编译门禁 PASS，已给双实例人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（改动只在模组 + 一处通用字段，模组默认关闭；但**快照字段变了必须双实例看画面**）
> **补充自**：[2026-10-10_联机客户端禁用出怪逻辑.md](2026-10-10_联机客户端禁用出怪逻辑.md)

## 目标

联机客户端的僵尸已经是"只渲染"（判定组件整体禁用）了，但**渲染本身**还差几样 ——
把下面 4 类渲染信息全部放进快照，让客户端照主机报的数据演，而不是自己推：

1. 僵尸**是否断手 / 掉头**（含防具破损）
2. **当前是动画的哪一帧**
3. 僵尸**受击变亮**
4. **向日葵准备产出变亮**

判定口径：客户端画面上能看到的东西，凡是由"本地状态"推出来的、而那个状态两端未必一致的，
都归这一类。

## 步骤

1. 先派 `code-explorer` 做**只读溯源**（very thorough），把 4 类渲染状态各自"由哪个字段驱动、在哪读、往哪写"摸清楚 —— 这一步省掉了后面 4 次盲改。**关键产出**：4 类里有 3 类的"想当然的写法"是错的（见踩坑）。
2. 本体加**一个**通用字段：`BodyCharacter.body_light_count`（每 `body_light()` 一次 +1）。与 `entity_id` / `GameRng` 同款：通用能力、不含联机字样、不参与判定（边界规则 2）。
3. `netplay_state_sync.gd` 加一个「渲染状态」region：位布局常量 + 打包 / 解包 / 写回三套函数。
4. 采集侧：僵尸 `z_render`、植物 `p_render` 各一条 `PackedInt32Array`（各 4B/实体）。
5. 对齐侧：`_apply_zombie_render()` / `_apply_plant_render()`；并让 `_spawn_zombie()` / `_spawn_plant()` **返回实体**，补种那一下当场写渲染态（否则新生的那一只要等下一帧才拉齐，那一帧它是按本地默认值演的）。
6. 改 `BYTES_PER_ZOMBIE` 28→32、`BYTES_PER_PLANT` 16→20（MTU 预算要跟着变，否则算出来的上限是假的）。
7. 同步文档：`联机模组.md` §4.9 加 6 行 + 修掉一条被证伪的注释 + §五 阶段四状态。

### 走过的弯路

- ~~让客户端照血量自己推掉手~~ → **放弃**：`curr_hp` 的 setter 不发 `signal_hp_loss`，客户端是**直接赋值**拉齐的 ⇒ 永远走不到 `judge_body_change()`。这条弯路的价值在于：它同时否掉了"血量下发 ⇒ 表现自然一致"这个想当然的推论（文档里原来就是这么写的）。
- ~~客户端禁用 `CreateSunComponent`、改由快照发"产阳光计数"驱动发光~~ → **放弃**：`create_sun()` 末尾会调 `change_production_interval()` 直接 `create_sun_timer.start()`，组件虽然被 `disable_component()` 禁了，计时器照样被这条语句重新点起来 ⇒ 客户端自己又会在错误的时间亮一次。改成"把计时器对到主机的剩余时间"就没这个副作用。
- ~~受击变亮发"当前亮度"~~ → **放弃**：发光是 0.5 秒 tween 的瞬时脉冲，一帧只能读到一个中间值；而且直接写 `change_color[HitColor]` 不会 kill 旧 tween，下一帧就被盖回去。

## 关键决策与理由

- **渲染态一律"显式下发"，不让客户端推** —— 客户端已经是"只渲染"了，它的本地状态（动画相位、产阳光间隔、掉血信号）都不再可信；让它推等于把"已经在纠的分叉"再引回来一遍。
- **每类实体挤成 1 个 int（4 字节）而不是开多条数组** —— 快照贴着 ENet 的 MTU（1300B/包），僵尸 7 条 × 4B = 一只就 28B。这也是既有 `z_anim`（7 个动画字段挤 1 个 int）的同一套做法，保持一致。
- **阶段号发的是"阶段 + 1"** —— 让 0 同时表示"这个角色没有血量阶段组件"，省掉一条"有没有"的标志位；解包时 `stage - 1 == -1` 会让 `curr_hp_stage < -1` 恒假，天然不动它。
- **补掉手时只传"目标阶段对应的临界值"给 `judge_body_change()`** —— 它内部 `for` 循环里 `curr_hp_stage = i` 是**当场**更新的，一次调用就把欠下的所有阶段级联补上，不用自己写循环。
- **动画帧只在偏差 > 0.15s 时才 `seek()`** —— 每帧硬拉播放头会跟 AnimationTree 的 `advance_expression` 打架（抖动）。两端 TimeScale 一致时纠一次就够了。
- **向日葵发"还剩多久"而不是"正在发光"** —— 发光时机由 `CreateSunTimer` 决定，对表 = 让两端的计时器到点在同一刻，零新增命令。

## 踩坑

1. **"血量是主机下发的 ⇒ 表现自然一致"是错的** → `HpComponent.curr_hp` 的 setter 只更新血条与死亡信号，**不**发 `signal_hp_loss`（只有 `Hp_loss()` 发），客户端又是直接赋值 ⇒ 掉手 / 掉头在客户端一次都不演 → **正解**：阶段号单独进快照，客户端用 `judge_body_change(目标阶段的临界值)` 补。
2. **`get_node_or_null(&"Xxx")` 编译不过** → `&"..."` 是 **StringName**，`get_node_or_null()` 要的是 **NodePath**（`^"..."`）→ **正解**：写 `^"HpStageChangeComponent"`。仓库里现成的正例是 `zombie_base.gd` 的 `get_node_or_null(^"CriticalValueComponent")`。
3. **`var tree := anim.animation_tree` 编译不过** → `anim_component` 是**基类** `AnimComponentBase`，基类上取不到 `.animation_tree`（取到的是 Variant，`:=` 推断不出类型）→ **正解**：先 `as AnimComponentNorm` 再取。
4. **`AnimationTree.anim_player` 是 NodePath 不是节点** → 要 `tree.get_node_or_null(tree.anim_player)`。
5. **植物的接口不统一** —— `Zombie000Base` 把 `hp_stage_change_component` 挂在基类属性上，而坚果 / 南瓜头 / 大蒜是各自脚本里 `$HpStageChangeComponent` 取的，`Plant000Base` 上**没有**这个属性 → **正解**：先 `_has_prop()` 探属性（按脚本缓存），探不到再按节点名找。
6. **植物的"产阳光组件"也不在基类上** —— 只有 `character_base.gd` 里出现过一次 `get_node_or_null("CreateSunComponent")` → **正解**：模组侧照抄这个节点名查法，不动本体。

1. 先在 `netplay_state_sync.gd` 文件头的「渲染状态」region 里把**位布局**定下来（几类、各占几位、量化步长），再动手。

## 第二轮（2026-10-11 · 掉头与死亡动画）

> 同一个任务的延续（用户追加"僵尸掉头和死亡动画也要写"），**不**新建索引行、不改原文件正文。

### ⊙ 这一轮最重要的发现：掉手 / 掉头压根没演，而且是被"血量拉齐"那一行自己搞没的

第一轮的 `z_render` 阶段号是**对的**，但它救不了场 —— 因为**同一帧里更早的一行**已经把僵尸弄死了：

```gdscript
z.hp_component.curr_hp = int(z_hp[i])   # ← 元凶
```

`HpComponent.curr_hp` 的 setter 是：

```gdscript
set(value):
    ...
    if value <= death_hp and not is_death:
        is_death = true
        signal_hp_component_death.emit()
```

而僵尸的 **`death_hp` 是掉头线、不是 0** —— `HpStageChangeComponent` 把它写成 `boundary_value_hp` 的最后一项（默认本体满血的 1/3，`component_critical_value.gd` 头注里写得明白："低于它就等于已经掉头 / 倒下"）。

于是"直接赋值 30 血" ⇒ setter **就地判死**，这条路**绕开了 `Hp_loss()`**：

- ❌ 不发 `signal_hp_loss` ⇒ `judge_body_change()` 不跑 ⇒ **不掉手、不掉头**
- ❌ `z.is_death` 已 true ⇒ `_apply_zombie_anim()` 里那句 `Hp_loss_death` 兜底也不会触发
- ⇒ 客户端的僵尸只会"血量一过掉头线就地倒下"

**第一轮那句"`z_render` 阶段号能补掉手 / 掉头"因此是无效的**：阶段号确实发了、也确实解包了，但僵尸在那一刻已经"跳过掉头死了"。

### 正解

`_apply_zombie_hp()`：**活着才直接赋值，该死的那一刀走 `Hp_loss()`**。

```gdscript
if hp > hp_comp.death_hp:
    hp_comp.curr_hp = hp          # 活着：直接拉齐（不走流程，避免每帧刷信号）
    return
hp_comp.Hp_loss(maxi(hp_comp.curr_hp - maxi(hp, 0), 1), Norm, false, false)
```

走 `Hp_loss()` 就都齐了：扣血 → setter 判死（倒地动画）→ **同时 emit `signal_hp_loss`** → `judge_body_change()` 把掉手 / 掉头一并演出来。一次调用串起一整条原版死亡表现。

⚠️ 参数：`is_drop_on_death=false`（掉落归主机下发，客户端那份已被掉落闸门拦住）、`trigger_be_attack_SFX=false`（这不是挨了一下打）。

### 死亡动画的三个配套

1. **已经死了的不再对动画帧**（`_apply_anim_phase` 里 `if character.is_death: return`）。
   死亡 / 倒地是**一次性**动画，主机那只多半早播完了（`current_animation_position` 停在末尾），照着 `seek()` 会把整段倒地**直接跳过** —— 客户端看到"走着走着突然躺平"。一次性动画没有循环对齐的意义。
2. **补种的僵尸要当场写 `z_anim`**（第一轮只写了 `z_render`）。主机报的常常是正在倒地的僵尸，不写 anim 的话补出来的这只这一帧还是"活着站着"的。
3. **植物同源同坑**：`death_hp` 就是 0，`curr_hp = 0` 会就地判死 ⇒ `Hp_loss_death()` 永远走不到 ⇒ 坚果最后一道裂纹没了。`_apply_plant_hp()` 改成**先补死亡、再赋值**。

### 踩坑（四条）

1. **"阶段号发了就能补表现"是假的安全感** → 同一帧里更早的一行已经把角色判死、且那条路不发 `signal_hp_loss` → **正解**：先查"这个状态是谁触发的、走的是不是本体的公开入口"，再决定要不要另发一条。
2. **`death_hp` 不是 0** → 僵尸的死亡临界 = 掉头线（`boundary_value_hp` 最后一项）→ **正解**：任何"直接写 `curr_hp`"的地方，只要可能跌破 `death_hp`，就必须改走 `Hp_loss()`。
3. **一次性动画不能 `seek()` 对齐** → 主机播完了 phase 停在末尾，seek 过去等于跳过整段 → **正解**：只对循环动画（走路 / 啃食 / 待机）对表，已死的不对。
4. **补种路径容易漏字段** → 第一轮给补种的僵尸只补了 `render` 没补 `anim` → **正解**：补种时把所有下发的字段**全部**当场写一遍，别只补"这次新加的那个"。

### ⏸ 留下的缝（已登记，未做）

被倭瓜压死 / 被樱桃炸弹炸死时，主机是 `queue_free()` **直接删**（不播倒地），客户端却照 `ANIM_DEATH` 播一段倒地 ⇒ 两端不一致。要对齐得再加一条"直接消失"的标志位。

### 验证

- 编译门禁 PASS；`probe_netplay_session` **PASS failed=0**（stderr 无 SCRIPT ERROR）。
- 未开游戏。人工双实例验证方法沿用第一轮那 5 条，**重点加看**：主机把普僵打到掉手 → 打到掉头 → 打死，客户端应在同一刻依次看到**掉手 → 掉头 → 倒地**三段（改前客户端只有最后一段，且是"凭空躺平"）。

## 第三轮（2026-10-11 · 推倒重来：改成统一发"播哪条动画 + 第几秒"）

> 同一个任务的第三轮。**第二轮那套"补触发"被推翻了**，下面写清为什么、以及新的统一口径。

### ★ 用户的判词：不该有这些问题，应该统一发送播放的动画和帧

这句话是对的，而且**点出了前两轮的方向性错误**。我前两轮一直在做的事是：

> 发 7 个状态字段（`is_death` / `is_attack` / `walk_status` / `death_status` …）→ 客户端写回本体字段 → 让**本体的 AnimationTree 自己推导**出该播哪条动画。

这条路的问题不是"某个字段漏了"，而是**结构性的**：客户端在**用自己的逻辑猜**主机那边发生了什么。所以推导链断在哪儿，就得往哪儿补一个"触发本地流程"的补丁 —— 第二轮一口气补了三个：

1. 补 `Hp_loss_death()` 才有倒地
2. 补 `z_render` 阶段号才有掉手 / 掉头
3. 给一次性动画开"不对帧表"的特例，免得倒地被 `seek()` 跳过

**三个补丁全都是"客户端自己加戏"的症状**，不是解法。

### 新口径

主机只发两个数，客户端只做两件事：

| 通道 | 内容 | 客户端动作 |
|---|---|---|
| `z_anim` / `p_anim` | 当前动画在 `AnimationPlayer.get_animation_list()` 里的**下标**（单字节 `PackedByteArray`） | 名字不一样 ⇒ `play()` |
| `z_render` / `p_render` 的 phase | 播到**第几秒** | 偏得多了 ⇒ `seek()` |

**没有推导、没有补触发。** 掉头不再是"客户端自己判死之后要补的东西"，它就是一条动画 / 一个阶段号。

### ★ 这次最漂亮的一点：下标天然对齐，不需要任何映射表

本来的担心是"动画名怎么塞进贴着 MTU 的快照"。答案是**下标**：

两端实例化的是**同一份 .tscn** ⇒ 动画列表与插入顺序完全一致 ⇒ 同一下标就是同一条动画。

于是**不需要任何"动画名 → 编号"的硬编码表** —— 这正好落在硬约束 §1-4「类型映射一律走注册表，禁止业务代码散落映射表」的精神里。而且顺带把 `z_anim` 从 4 字节压到 **1 字节**（`BYTES_PER_ZOMBIE` 32 → 29），比原来那套挤位方案还省。

### ⚠️ 唯一的硬前提：客户端必须先"接管"动画

普僵那条路是 AnimationTree 用 `advance_expression` 每帧读 `is_death` 等字段**自己挑**动画 —— 我们 `play()` 的那一条，下一帧就被它换回去，**"发了等于没发"**。

所以客户端第一次见到一个角色就 `_take_over_anim()` 把 `animation_tree.active = false`，AnimationPlayer 完全归快照管。这一步没做，整套方案就是空转。

### 顺带清掉的东西

- 删除 `ANIM_*` 七个位常量、`_pack_anim` / `_apply_zombie_anim` / `_apply_anim_status` / `_anim_status_of`（布尔/变体字段那一整套）
- `_apply_zombie_hp` / `_apply_plant_hp` 合并成 `_apply_hp_display`：**连 `curr_hp` 都不写了**，只画血条
- `_apply_anim_phase` 里那个"已死不对表"的特例删掉（统一按帧号）
- **"死亡方式"那条缝自动合上了**：被倭瓜压死时主机直接 `queue_free()`，客户端现在只是照播主机最后报的那条动画、随后靠缺席回收删掉，**不再自己演一段倒地**

### ⚠️ 唯一例外：僵王

它的死亡是"编排式"的 —— 播完死亡动画还要 `start_death_remain()` 撑一段时间才淡出、还要发奖杯。光播对一条动画**撑不起**整套流程，所以僵王仍走 `zb_death` 触发本地死亡流程。已在 `netplay_state_sync.gd` 头注和 `联机模组.md` §4.9 都写明"这是唯一例外"。

### 踩坑（三条）

1. **`get_meta(key, 默认值)` 在键不存在时照样 `push_error`** → 引擎日志刷一行 ERROR（探针 `result=PASS` 但 stderr 脏）→ **正解**：先 `has_meta` 再 `get_meta`，默认值只是让它不崩、不让它安静。
2. **静态函数调不到非静态函数** → `_anim_index_of` / `_apply_anim` 写成 `static` 后调 `_anim_player_of` 直接编译失败 → **正解**：`_anim_player_of` 本身也不碰实例状态，一并标 `static`。
3. **改语义要连探针一起改** → 探针里那几条 `ANIM_ATTACK` / `ANIM_SWIM` 断言是照旧语义写的，删常量后直接编译不过 → **正解**：探针改成验**新契约**（不接管 / 越界 / 空角色都不崩、下标 ↔ 名字往返一致、列表缓存得住）。

### 推荐度（给后来人）
