# 2026-10-17_模组依赖机制

> **本次任务**：给模组框架加「依赖」机制 —— 模组内声明依赖、模组页面详情末尾列出依赖（可点击跳转）、打开模组时自动补开依赖
> **耗时 / 轮次**：约 4 轮；**开了游戏**（无头跑 `probe_mod_page`，纯 Control 界面，无头足够）
> **推荐度**：推荐

## 目标

1. 模组入口脚本能声明「我依赖哪些模组」（`ModBase.get_mod_dependencies()`）；
2. 模组页面右侧详情**末尾**显示依赖列表，每个依赖一个按钮、点击跳转到那个模组的详情；
3. 打开（启用）本模组时，依赖的模组被**一并打开**（存档里也照此存）。

## 最简路径（步骤）

1. `mods_builtin/mod_base.gd`：加虚方法 `get_mod_dependencies() -> Array[StringName]`（默认空数组），
   与 `get_mod_categories()` 放同一段、同一口径（多标签、常量数组）。
2. `src/mods/mod_manager.gd`：
   - 对外加 `get_mod_dependencies(mod_id)`：`has_method()` 防御式转调（`user://` 下旧版入口脚本
    没有这个方法），剔掉未登记 id / 自身 id（打 error），去重保序；
   - `set_mod_enabled(id, true)` 里先跑 `_enable_dependencies_first(id, {})`（递归 + `visited` 防环）；
   - `_install_enabled_mods()` 拆成「先建齐全部实例 → `_ensure_dependencies_enabled()` → 再 install」
     （依赖声明要读模组自己，实例不齐读不到）；`reload_for_current_user()` 里也补一次。
3. `src/ui/mod_page/mod_page.gd`：`_build_detail()` 末尾恒加 `_create_dependency_box(mod)`
   （起名 `DependencyBox`，探针靠名字找）；每个依赖一个 Button，点击 = `_selected_mod_id = dep_id`
   + 清空分类过滤 + `build_mod_page()`（清过滤是为了跳过去时列表里看得见它）。
4. 文档：`docs/参考存档/模组机制.md` 加 §2.3 + §三装载时序图补一行 + §四「可选第 5 步」+
   §七详情结构补一条；`mods_builtin/README.md` 加「同时声明它的依赖」小节。
5. 验证：`test/check_scripts.ps1`（PASS）→ `run_autopilot.ps1 -Scenario probe_mod_page`（无头，failed=0）。

## 弯路 / 踩坑（三段式）

- **试过**：探针里按模组**显示名**（`_find_list_button(page, "手套")`）重新选中手套，跑「自动补开」那一端。
- **因为**：探针给手套临时换了 `set_script()` 的依赖脚本，没重写 `get_mod_name()` → 显示名变成 `"glove"`，
  按名字点不到，选中项留在锤子上，断言 FAIL（`result=FAIL failed=1`）。
- **结论**：换过脚本之后一律按 **id** 选中（`page._selected_mod_id = ModIds.GLOVE; page.build_mod_page()`），
  别走列表按钮那条路。

- **试过**：断言写 `b.text.contains("已启用")`。
- **因为**：「已启用」是「未启用」的**子串**，未启用那一端也会命中，断言形同虚设。
- **结论**：带括号写全 `"（已启用）"`；同理「未启用」不受影响（它不含括号版已启用）。

- **试过**：用 `GDScript.new()` + `source_code` + `reload()` 在探针里临场造一份「声明了依赖」的脚本，
  再 `set_script()` 到手柄模组实例上。
- **因为**：现役内置模组一个依赖都没声明，不这么干，「详情末尾依赖块 / 点击跳转 / 自动补开」三端
  永远是空跑，验不到东西。
- **结论**：可行（`set_script` 对 RefCounted 系脚本实例有效，跑完 `set_script(原脚本)` 还原即可）。
  临时脚本里**别引用全局类**（`ModIds` 之类），id 用 `&"hammer"` 字面量写，断言再拿 `ModIds.*` 比 ——
  写歪了会当场 FAIL。另：手套 / 锤子都没重写全局 `install()`，探针里开它们不会装出节点。

- **试过**：大段插入 GDScript 时直接写制表符缩进。
- **因为**：插入的代码块有若干行**丢了前导制表符**（GDScript 对缩进敏感，直接解析错误），
  且 `\t` 转义会被当成字面文本写进文件。
- **结论**：插入后必须 `read_file` 逐行核对缩进（或 `search_content` 数），缺的行单独 `replace_in_file` 补。

## 推荐度与理由

推荐。整条链路都长在既有扩展点上（`ModBase` 虚方法 + `ModManager` 一个入口 + 模组页详情末尾一块），
本体依旧不认识任何具体模组。后来者注意：

- 依赖**只补开、不连锁关**（关掉被依赖者不自动关依赖者）—— 这是有意口径，别"顺手完善"成连锁关；
- 「打开时补开」的口子在 `set_mod_enabled()`，别在 UI 按钮里另写一套；
- `get_mod_dependencies()` 的返回值已经过滤过（未登记 / 自身），UI 直接渲染即可，别再筛一遍；
- 依赖块**不**跟「模组未启用」一起禁用（它是导航，不是设置）—— 探针里有对应断言。
