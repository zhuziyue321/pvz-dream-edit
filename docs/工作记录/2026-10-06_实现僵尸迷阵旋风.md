# 2026-10-06 · 新增内容 · 实现迷你游戏第 9 关「僵尸迷阵 旋风」

> **任务类型**：新增内容
> **推荐度**：**推荐**
> **耗时与成本**：约 2 轮，带窗口跑探针（两次： Twist 探针 + Beghouled 回归）
> **验证方式**：带窗口跑 `probe_beghouled_twist` PASS；回归 `probe_beghouled` PASS
> **补充自**：照 [2026-10-04_实现僵尸迷阵Beghouled.md](2026-10-04_实现僵尸迷阵Beghouled.md) 与 [2026-10-05_补全僵尸迷阵植物升级逻辑.md](2026-10-05_补全僵尸迷阵植物升级逻辑.md) 的实现路径复刻

## 目标

原版迷你游戏第 9 关「僵尸迷阵 旋风」(Beghouled Twist)  playable：
- 与第 5 关「僵尸迷阵」共用棋盘、阳光、升级、弹坑、进度条等规则；
- 玩家操作改为**顺时针旋转 2×2 植物方块**来凑三消；
- 累计 75 次配对通关，不靠波次；
- 在迷你游戏选关界面显示并可选。

## 步骤

1. 在 `src/levels/script/mini_game/beghouled/` 下新增 `beghouled_twist_manager.gd`，继承 `BeghouledManager`。
   - 覆盖 `_on_click_cell()`：点击后取以该格为左上角的 2×2 方块（点在最后一行/列时往左上缩），旋转；不成交则转回。
   - 覆盖 `_has_possible_move()`：在类型副本上模拟 2×2 顺时针旋转，检查四个格是否成线。
   - 加 2×2 方块高亮，`_clear_select()` 里顺手清掉。
2. 重写 `src/levels/mode_minigame/minigame_09_beghouled_twist.gd`，仿照 `minigame_05_beghouled.gd`：
   - 用 `preload()` 加载 twist 管理器脚本（不用 `class_name`，见「踩坑」）；
   - 设置夜晚、无限波、无选卡/铲子/小推车、五张自定义种子包；
   - `run_flow()` 走 `show_zombie → camera_back → setup_board → start_beghouled`。
3. 在 `src/menus/choose_level/mini_game_choose_level.tscn` 里给 `ChooseLevelButton10` 补上 `level_script` 和 `preview_icon`（用已导入的 `213_thumb20` Bejeweled Twist 图标）。
4. 新增回归探针 `test/scenarios/probe_beghouled_twist.gd`（仿 `probe_beghouled.gd`，把「找一步有效交换」改成「找一步有效旋转」）。
5. 更新 `docs/参考存档/特殊关卡.md` 里「僵尸迷阵 旋风」段落与音乐表名称。

## 关键决策与理由

- **继承而不是重写整个 Manager** —— 消除、下落、阳光、升级、弹坑、洗牌、死局刷新等逻辑与 Beghouled 完全一致，只覆盖「玩家操作」和「可行步判定」两个方法，改动最小。
- **Twist Manager 不用 `class_name`** —— 关卡脚本是动态 `load()` 的，如果 twist 管理器也写 `class_name`，首次运行时探针/关卡脚本会报 `Could not find type "BeghouledTwistManager" in the current scope`。改为关卡脚本 `preload()` 后，依赖在加载关卡脚本时一起解析，问题解决。
- **2×2 方块取法：点击格尽量当左上角，越界则往左上缩** —— 这样点击棋盘任意一格都有可旋转的 2×2，符合原版「点哪里都能转」的手感；同时避免点到最后一行/列时无响应。
- **无效旋转自动转回** —— wiki 明确「unlike Bejeweled Twist, the player must make a twist that makes a match」，即不成交时不能真的改变盘面。

## 踩坑

1. **动态加载的关卡脚本里引用新的 `class_name` 会解析失败**
   - 现象：第一次跑 `probe_beghouled_twist` 时，探针和关卡脚本都报 `Could not find type "BeghouledTwistManager" in the current scope`，游戏停在开始菜单看门狗超时。
   - 原因：新脚本的 `class_name` 没有被预扫描进全局类缓存；关卡脚本是运行时 `load()` 的，编译时找不到该类型。
   - **正解**： twist 管理器只保留 `extends BeghouledManager`，去掉 `class_name`；关卡脚本用 `const TWIST_MANAGER := preload("res://.../beghouled_twist_manager.gd")` 加载。探针里 likewise。

2. **2×2 方块高亮节点如果不清会残留在格子上**
   - 现象：旋转高亮在第二次点击时累加，或换场/通关后仍留在界面。
   - 原因：高亮是运行时 `add_child` 的 ColorRect，没有自动跟随格子清理。
   - **正解**：在 `_clear_select()`（基类多处调用）里调用 `_hide_block_highlight()`，手动移除并 `queue_free`。

## 给后来者的最简路径

1. 把新玩法管理器写成现有 Manager 的子类，只覆盖真正不同的方法。
2. 如果关卡脚本是动态加载、且新管理器没有其它场景引用，**不要用 `class_name`**；改由关卡脚本 `preload()`。
3. 先写探针再跑带窗口验证，能一次确认：摆场、操作、阳光、弹坑、升级、死局刷新、通关、进度条。
4. 复用已有的 `ConstBeghouled`、`BeghouledUI`、`BeghouledProgressProvider`，不要再造一套。

   第 5 关改成调共用那份（本地常量与 `_set_packet_face()` 删掉）。

  新全局类名首次运行可能解析不到（本条「踩坑 1」）。放进已有的 `ConstBeghouled`（有 `class_name`，
  09 关脚本本来就在用）最省事，静态函数照调。
