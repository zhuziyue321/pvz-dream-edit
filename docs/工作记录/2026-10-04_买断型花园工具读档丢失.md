# 2026-10-04 · 排查调试 · 买断型花园工具读档后丢失（JSON 读回 float）

> **任务类型**：排查调试
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，无头探针 `probe_garden_tool_save`（未带窗口）
> **验证方式**：无头探针 31/31 全绿（含真实购买链路 + 读盘 + 重开读档）；回归 `probe_garden_tool_bar` / `probe_watering_can` / `probe_store_rules` / `probe_garden_bg` 全绿
> **补充自**：[2026-10-04_花园工具栏买了立刻出现.md](2026-10-04_花园工具栏买了立刻出现.md)（同一批花园改动，本次是它的验证环节挖出来的新问题）

## 目标

验证「所有园艺工具的购买记录都在存档里」：7 件工具（黄金水壶 / 留声机 / 园艺手套 / 蜗牛 买断，
肥料 / 杀虫剂 / 巧克力 消耗）买完后落盘、重开游戏一件不少。

## 步骤

1. 写探针 `test/scenarios/probe_garden_tool_save.gd`：实例化 `goods_garden_tool.tscn` 逐个
   `comfirm_get_this_goods()`（真实购买链路，含扣钱与 `save_now`）→ 直接读盘上 JSON → 清空内存再
   `load_global_game_data()` 模拟重开。
2. 探针报红：**4 件买断型工具读档后全部丢失**，消耗品（走字典 + `int()`）正常。
3. 定位：`is_garden_tool_bought()` 用 `Array.has(int(tool_type))`，而 `JSON.parse_string` 把数字一律读成
   float（存档里是 `4.0`），`Array.has()` 认不出 `4.0 == 4`。
4. 修：读取侧逐个 `int()` 比（老存档救得回来）+ `SaveService` 读档后调
   `GlobalGameState.normalize_garden_data_numbers()` 把 float 转回 int（新存档不再越存越浮点）。

## 关键决策与理由

- **只改读取侧不够，也不只改写入侧** —— 只改写入侧，老存档（已经存成 float 的）永远读不回来；
  只改读取侧，写档仍然写 float，存档里一直显示 `4.0`。两边都做才闭环。
- **不做「存档版本号升级迁移」** —— `SaveGameVersion` 是整档一个版本号，为两个键做迁移不划算，
  读取侧容错已经等价。

## 踩坑

1. 现象：买断型工具重开游戏后像没买过（商店又能再买一次、花园工具栏空了）
   → 原因：JSON 读回 float，`Array.has(int)` 判不中（`curr_plant` / `curr_zombie` 早就有 `int()` 转换，
   唯独 `bought_garden_tools` 漏了）→ **正解**：逐个 `int()` 比 + 读档归一化。
2. 现象：探针 STEP3「存档文件里有记录」一开始也报红 → 原因：探针自己用 `Array.has(int)` 去比
   `JSON.parse_string` 的结果，是探针写错了不是产品错 → **正解**：探针里也用同样的 `int()` 容错比较
   （`_has_int`），别把「读盘方式」的坑当成产品 bug。

## 给后来者的最简路径

1. 写探针：真实购买 → `save_now()` → 读盘 JSON → 清空内存 → `load_global_game_data()` → 断言。
2. 凡是「存档里的 int 数组 / int 字典值」，读取侧一律 `int()` 容错，别信 `Array.has()`。
3. 顺手在 `load_global_game_data()` 里归一化，避免新存档继续写 float。
