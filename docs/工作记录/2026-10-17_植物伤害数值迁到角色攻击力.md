# 2026-10-17_植物伤害数值迁到角色攻击力

> **本次任务**：把 `ConstDamage` 里三个植物专属伤害常量（辣椒 / 倭瓜 / 寒冰菇）迁到各植物场景的 `Character000Base.attack_value`
> **耗时 / 轮次**：约 2 轮（未开游戏，编译门禁 PASS）
> **推荐度**：推荐

## 目标

`ConstDamage` 只留「不属于某个角色」的固定值（`BOWLING_*` / `HAMMER_ARMOR1`）；
植物的伤害数值统一配在**角色攻击力** `Character000Base.attack_value` 上，由发起方读自己的字段写包，改数值只改植物 `.tscn`。

## 最简路径（步骤）

1. 删 `src/core/consts/const_damage.gd` 的 `JALAPENO_DAMAGE` / `SQUASH_DAMAGE` / `ICE_FREEZE_DAMAGE`，段尾留一句指针（植物数值 → `attack_value`）。
2. 三个植物场景根节点补 `attack_value`：`plant_jalapeno.tscn`(1800) / `plant_squash.tscn`(1800) / `plant_ice_shroom.tscn`(20)；
   寒冰菇的 BombComponent 删掉 `bomb_value = 20`（伤害改由攻击力承载，避免两个真源）。
3. 发起方读自己的字段：
   - 辣椒：`BombComponentJalapeno._bomb_all_enemy()` 推 `[行号, owner_plant.attack_value]`；
     `ZombieManager.jalapeno_bomb_lane_zombie(lane, damage)` 两处（普通僵尸 `be_bomb` / 僵王 `be_jalapeno`）改用入参。
   - 倭瓜：`Plant018Squash.squash_all_area_zombie()` 调 `zombie.be_squash(attack_value)`；`Zombie000Base.be_squash()` 去掉默认值。
   - 寒冰菇：`BombComponentIce._bomb_all_enemy()` 推 `[time_ice, time_decelerate, owner_plant.attack_value]`。
4. 删除「默认 20」的兜底：`be_ice_freeze()` 一族（`Character000Base` / `ZB000Base` / `ZombieBalloon` / 医生火球订阅）`damage` 默认值改 0，
   `ZombieManager.ice_all_zombie()` 的 `damage` 改为必填。默认 0 = 只冻不打，伤害一律由发起方给。
5. 同步事件签名表：`ConstEventName.EVENT_PAYLOAD_SIGNATURES.JALAPENO_BOMB_LANE_ZOMBIE` 改 `[INT, INT]`。
6. 探针只补显式入参（数字仍是测试夹具，**不**改成读字段）：`probe_zomboss_damage` / `probe_zomboss_ice`。
7. 模组跟着改（它们原本靠 `bomb_value` 改这两个植物）：生态版 `_apply_ice_shroom` 改设 `plant.attack_value`；
   明日方舟精英化 `_apply_damage_buffs` 的爆炸分支：`attack_value > 0` 的按攻击力放大，其余仍按 `bomb_value`。
8. 文档：`伤害系统.md` §7 配置一览 + §13 坑位、`特殊关卡.md` 僵王冰冻口径。
9. 跑 `test/check_scripts.ps1` 确认 `real compile errors = 0`。

## 弯路 / 踩坑（三段式）

- **试过**：寒冰菇保留 `bomb_value` 当伤害来源，只把常量的默认值删掉。
- **因为**：`BombComponentBase.bomb_value` 是炸弹类通用口径，生态版 / 明日方舟模组都在它上面加数值。
- **结论**：`ConstDamage` 里的值终究是「这个植物的攻击力」，跟「炸弹伤害」是两回事；统一到 `attack_value` 后两个模组必须同步改，
  否则它们对辣椒 / 寒冰菇的加成会**静默失效**（不报错、只是数值不再变）。改完记得全仓搜模组里的 `bomb_value`。

- **试过**：把 `be_ice_freeze()` 的 `damage` 参数直接删掉要求必填。
- **因为**：GDScript 子类覆写不能少写参数，且事件回调签名要跟 payload 对得上。
- **结论**：保留参数、默认值改 0（只冻不打），`DamageSystem` 那条路本来就显式传 0，行为不变。

## 推荐度与理由

推荐。植物伤害归植物场景、`ConstDamage` 只留通用固定值，与「数值归场景配」一致；
代价是有两个模组依赖旧的 `bomb_value` 通道，必须一起改并写明口径。
