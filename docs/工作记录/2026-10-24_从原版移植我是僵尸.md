# 2026-10-24_从原版移植我是僵尸

> **本次任务**：把解谜模式「僵尸公敌」（原版 PvZ1 的 I, Zombie）逐项对齐到原版 —— 纸板植物逐关布局、红线列数、起始阳光、判负口径
> **耗时 / 轮次**：一轮（未开游戏；改动集中在关卡数据层 + 摆放算法，编译门禁与探针均已过）
> **推荐度**：推荐

## 目标

「我是僵尸」= 原版 `GAMEMODE_PUZZLE_I_ZOMBIE_1..9` + `_ENDLESS`（解谜模式的第二个分支）。
玩家扮演僵尸，用阳光买僵尸卡，把僵尸放到**红线右侧**，一路向左啃掉纸板植物、啃掉每行尽头的**脑子**，
**吃光 5 个脑子即通关**；僵尸全死且阳光不够再放一只 = 失败。

本仓库原先已有这套玩法，但**纸板植物是「种类权重随机」出来的**（`all_plants_weight_on_zombie_mode`），
与原版「逐关固定种类 + 固定数量、只有位置随机」完全不同 —— 关卡难度与原版对不上。这次按原版 C++ 重做。

## 最简路径（步骤）

1. **取原版权威数据**：`../PvZ-Portable-main/src/Lawn/Challenge.cpp:4001-4624` 是全部 I'm Zombie 逻辑
   （`IZombieInitLevel` 摆纸板植物、`IZombiePlacePlants` / `IZombiePlacePlantInSquare` 两种摆法、
   `IZombieUpdate` 判负、`IZombieDrawPlant` 画纸板质感）；
   `../PvZ-Portable-main/src/Lawn/Board.cpp:1348-1489` 给起始阳光（**150**）、僵尸卡阵容、**红线限 `aLimit`**。
   `grep -n "IZombie" src/Lawn/Challenge.cpp` 就能定位全部落点。
2. **原版摆纸板植物只有两种**（照抄即可，仓库侧合成一张布局表）：
   - `IZombiePlacePlantInSquare(种类, 列, 行)` —— 固定格位；
   - `IZombiePlacePlants(种类, 数量, 行)` —— 在「红线左侧前 N 列 × 限定行」里等概率随机，
     **坚果与火炬只进最右 3 列**，放过的格不再复用，数量 = `min(写死的数量, 候选格数)`。
3. **数据模型**：新增 `level_data.zombie_mode_plant_layout`（每项一个字典：
   `plant` / `row`（-1 = 不限行）/ `col`（-1 = 随机落位）/ `count`）；
   `col >= 0` = 固定格位，`col = -1` = 随机落位；**按表顺序执行**即与原版等价。
   删掉旧的 `all_plants_weight_on_zombie_mode` / `all_must_plants_on_zombie_mode`。
4. **摆放算法**落在 `PlantCellManager.create_plant_on_zombie_mode()`（本体只认布局表，不认具体玩法 —— 硬约束 §1-8）。
5. **无尽关的阵型是运行期随机的**（原版每轮重掷）：关卡脚本 `_init()` 只跑一次，
   所以用**数据层钩子** `get_zombie_mode_plant_layout()` —— 基类返回静态表，无尽关覆写它按轮次现算
   （小喷菇数量随轮次递增 + 伤害阵 / 混合阵 / 控制阵 / 秒杀阵四选一）。
   仓库的「每轮重摆」时机本来就现成：`PlantCellManager.start_next_game_plant_cell_manager_update()` 里已经每轮调一次摆放。
6. **判负对齐**：原版 `IZombieUpdate` 除了「僵尸数 = 0 且阳光 < 50」，还要排除 `anActive`
   （窝瓜正在砸 / 大嘴花正在啃 / 土豆雷爆炸粒子）—— 仓库补 `_has_active_plant_action()`。
7. **文档**：新增 `docs/参考存档/我是僵尸原版对照.md`（原版常量 / 摆法算法 / 逐关数据表 / 仓库字段对照 / 已知差异），
   并把 `docs/参考存档/特殊关卡.md` 的僵尸公敌节改成原版口径。
8. **验证**：`test/check_scripts.ps1`（`real compile errors = 0`）+ 新增探针
   `test/scenarios/probe_i_zombie_mode.gd`（逐关布局表与原版逐项对照，无头可跑）。

## 弯路 / 踩坑（三段式）

- **试过**：把原版的「红线左侧 4 列」直接写进 `plant_cell_col_j`。
- **因为**：仓库把原版的**一个** `aLimit` 拆成了两个字段 —— `plant_col_on_zombie_mode`（纸板植物能占几列）
  与 `plant_cell_col_j`（红线画在哪）。红线是**贴在第 `plant_cell_col_j` 列的右边缘**，
  左区 = 第 0~`plant_cell_col_j` 列，所以左边实际是 `plant_cell_col_j + 1` 列。
- **结论**：照抄原版时这两处要一起改 —— `plant_cell_col_j` 必须 = `plant_col_on_zombie_mode - 1`
  （仓库原先 10 关一律写 4，等于左区 5 列，与原版的 4 列不符）。

- **试过**：照抄原版「纸板植物全部 `animRate = 0`（静止）」。
- **因为**：仓库的僵尸攻击是**动画方法轨**驱动（`attack_once` 挂在攻击动画上），
  而「向日葵被啃一口掉一颗阳光」正是挂在 `attack_once` 这条链路上；
  停掉动画 = 方法轨不再触发 = 阳光链路整条断掉。
- **结论**：**没做**这一条（纯观感差异），写进对照文档 §5 已知差异，不假装已对齐。

- **试过**：把原版脑子的「70 口」直接写成 70 点血。
- **因为**：原版一口 = 4 tick（100 Hz → 0.04 秒），仓库的「口」= 攻击动画方法轨的一次调用，两者不同频；
  直译会让啃一个脑子从 4 秒变成几十秒。
- **结论**：**没改**脑子耐久（仓库 100 HP / 每口 25 = 4 口，与原版 2.8 秒体感接近），记进已知差异。

- **试过**：在关卡脚本里把无尽关的阵型算成一张写死的表。
- **因为**：原版无尽关是**每轮重掷**（`mSurvivalStage` 递增），写死就等于把无尽关变成普通关。
- **结论**：走数据层钩子 `get_zombie_mode_plant_layout()`，关卡脚本覆写它现算（本体不认玩法，硬约束 §1-8）。

- **试过**：`test/run_autopilot.ps1 -Scenario probe_i_zombie_mode`。
- **因为**：用户开着 Godot 编辑器，脚本检测到有引擎进程就直接退出（不抢用户的进程）。
- **结论**：改用同一条引擎命令但把**报告目录**换到 `%TEMP%` 下自己的一份
  （`--headless --path <仓库> -- --scenario=res://test/scenarios/probe_i_zombie_mode.gd`，
  同时把 `APPDATA` 指到临时 userdir 免动真实存档），探针照常跑通。
- **补充（第二次踩同一个坑）**：命令执行器走的是 **cmd**，不是 PowerShell ——
  cmd 在**命令行模式**下会把未定义的 `%VAR%` 展开成空、把 `!VAR!` 原样留给程序；
  于是 `set "APPDATA=%TMPD%\userdir"` 里的 `%TMPD%` 被吃掉，Godot 按**相对路径**在**仓库根**落了个 `%TMPD%/` 目录。
  正解：路径里要出现 `%` / `!` 时用 PowerShell 的 `[string][char]37` 拼字符、再 `Remove-Item -Recurse -Force` 删残留。

- **试过**：沿用关卡基类的默认流程，在僵尸关里也留「准备…安放…植物」阶段。
- **因为**：`run_flow` 是照普通关抄的，但原版我是僵尸关**根本不走选卡 / 准备阶段**：
  `Board::CreateLawnMowers` 对僵尸模式直接 return（无小推车），
  `LawnApp::ShowSeedChooser` 也不给僵尸模式开选卡界面；
  玩家扮演僵尸，**进关就能点僵尸卡放僵尸**，原版没有那行「准备…安放…植物」红字。
- **结论**：10 个关卡的 `run_flow` 只留「红线 → 开战」，删掉 `ready_set_plant()`；
  各关 `is_lawn_mover = false`（本来就有，推车事件据此跳过）；
  探针加两条断言（「没有小推车」「没有『准备…安放…植物』阶段」），
  断言直接读关卡脚本源码判（流程步骤就写在 `run_flow` 里），防止以后被抄回来。

### 做了什么

1. **静止**：原版 `IZombieSetupPlant`（`Challenge.cpp:4087`）把纸板植物的 reanim `animRate` 置 0、
   `mBlinkCountdown` 置 0（不眨眼）。
   仓库做法：`Plant000Base._setup_paper_plant()` → `is_anim_frozen = true` + 动画树 `TimeScale = 0` + 禁眨眼。
   **冻结锁 `is_anim_frozen`（`Character000Base`）是必需的**：植物的速度倍率系统会调
   `AnimComponentNorm.owner_update_speed()`，把 `TimeScale` 写成 `原始速度 × 倍率`，把 0 覆盖回来看得见的速度；
   所以动画组件在冻结时**一律写 0**（`owner_update_speed` / `update_anim_speed_scale` / `_on_release` 三处）。
   死亡时 `character_death()` **先解冻再还原速度**，不然死亡动画会卡在第 0 帧。
2. **纸板质感**：原版 `IZombieDrawPlant`（`Challenge.cpp:4505`）用同一个 reanim 画 4 遍
   （白滤镜 + 三层偏移的深/中棕剪影 + 原位淡肤色本体）。
   仓库做法：本体一层淡肤色材质 + **把 Body 的视觉子树复制 3 份**当描边层
   （各自偏移 ±2/±4 px、纯色剪影材质、`z_index` 更小画在本体下面）。
   纸板植物完全静止 → 副本不必跟动画同步，复制一次就是最终形态。
   新增 `src/entities/character/plant/paper_plant_look.gd` + `shaders/my_shader/paper_plant.gdshader`。
3. **静止照样开火**：原版开火走 `Plant::mShootingCounter`（与 reanim 无关），所以纸板植物照吐豌豆。
   仓库的攻击原本挂在攻击动画的方法轨上（`on_anim_event("shoot")`），动画一停就断；
   做法是僵尸模式下 `AttackComponentBulletBase._on_bullet_attack_cd_timer_timeout()` 改走 `shoot_burst()`（直接发射）。

### 弯路 / 踩坑（三段式）

- **试过**：只用「用父节点材质」（`use_parent_material`）把纸板材质传给贴图节点。
- **因为**：贴图节点有多个，逐个挂材质麻烦，而父材质机制看着正好干这事。
- **结论**：**Godot 的父材质查找只往上找一层**（直接父 CanvasItem 自己的 `material`）——
  贴图节点与 `%Body` 之间夹着 `BodyCorrect`（自己没材质）→ 链断了，画面**完全没变化**。
  **材质要直接挂在每个贴图节点上**（贴图节点共用同一个 ShaderMaterial 实例）。

- **试过**：把原版颜色按 0~255 写进 shader uniform（`Color(255, 201, 160)`）。
- **因为**：原版源码里就是 RGB 0~255 的数字，直接抄最省事。
- **结论**：**Godot 的 `Color` 构造不归一化** —— `Color(255, 201, 160)` 的分量就是 255/201/160，
  塞进 uniform 被 clamp 成纯白 → 画面上纸板全是白的（探针只查材质参数，查不出来，**只有截图能看出来**）。
  **传给 uniform 前一律除 255**；shader 里也**不要**加 `source_color` 提示（会多做一次 sRGB→线性转换，颜色会偏）。
  顺带绕了两段弯路：先怀疑「参数上传时机」（新建材质时设的参数传不到 GPU），实测证明参数**创建时就能上传**，
  真正原因就是颜色没归一化。定位手段：给 shader 加 `debug_mode` 分支
  （分别直接输出 `paper_tint` / `tex.rgb` / `v_modulate`），一次跑出 5 张对比截图，一次定位。

- **试过**：探针用「场上的子弹数」判断纸板豌豆射手有没有开火。
- **因为**：最直观的指标。
- **结论**：僵尸放得近时豌豆很快命中并消失，子弹数会回到 0 → 判不出开没开火。
  改成**数 `signal_shoot_bullet` 的次数**（发射前就挂上，别漏第一发）。

- **试过**：探针把僵尸放在 `shooter.global_position.x + 120`、y 用行节点的 `global_position.y`。
- **因为**：看着像「植物右边 120 px」。
- **结论**：行节点的原点跟地面差一截，僵尸落在植物那条**只有 5 像素高**的索敌带外面 → 植物永远发现不了它，
  表现就是「静止的豌豆射手不开火」（假故障）。
  y 要用 `row.zombie_create_position.global_position.y`（仓库放僵尸一律用这个）。

- **试过**：描边层用 `body.duplicate()` 造，三层都叫 `PaperPlantOutline`。
- **因为**：想按固定名字找层。
- **结论**：同名节点加进同一父节点时 Godot 会自动改名（`PaperPlantOutline2`）→ 按名字只找得到 1 层。
  名字要带序号（`PaperPlantOutline0/1/2`），探针按前缀判定。
  另外副本的 `owner` 必须清掉（`%Body` 是 `unique_name_in_owner`，带着原 owner 进树会抢唯一名、引擎刷 ERROR）。

- **试过**：`test/run_autopilot.ps1`。
- **因为**：这是仓库的正路。
- **结论**：用户开着 Godot 编辑器时脚本会直接退出（不抢用户的进程）→
  改用同一条引擎命令但把**报告目录**换到 `%TEMP%` 下自己的一份
  （`--headless --path <仓库> -- --scenario=res://test/scenarios/xxx.gd`，同时把 `APPDATA` 指到临时 userdir 免动真实存档）。
  **要人眼看观感时**去掉 `--headless`（带窗口跑一次并截图），headless 取不到视口图像（`get_image()` 返回空）。
