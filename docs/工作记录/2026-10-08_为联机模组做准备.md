## 关键决策与理由

- **选状态同步，不选帧同步** —— 因为本体主循环是 `await` 协程链 + Timer（`level_timeline_manager` →
  `LevelScriptBase.run_flow`），**没有 tick / 帧号**，波次时长是 `randf_range(25,31)` 的真实时间。
  帧同步要先把全仓库 Timer 改成固定步长驱动，改造量是整个关卡系统；状态同步只要"主机算、客户端画"。
- **先只改两处随机** —— 164 处 `randi*/randf*` 里只有约 30 处影响判定；先接「抽怪类型 + 出怪行」两个收口点，
  证明 `GameRng` 可用，剩下的（波次时长 / 阳光 / 掉落 / 墓碑）留到阶段二批量替换。
- **`GameRng` 不做成 autoload** —— 写成 `RefCounted` + `class_name GameRng`（静态函数），
  少改一个 `project.godot`、少一个 autoload 顺序风险；调用姿势与 autoload 一样是 `GameRng.randf()`。
- **随机发生器用惰性初始化**（`_ensure()` 里 `new()`），不写 `static var _rng := RandomNumberGenerator.new()` ——
  静态变量初始化器能不能跑任意表达式不确定，惰性写法零风险。
  **未播种时仍 `randomize()`**，保证单机行为与改动前一致。
- **会话挂 `SceneTree.root`，不挂 `MainGameManager`** —— 连线要跨场景存活（先在主菜单连上，再一起进关卡）；
  挂在主游戏下会跟着关卡一起被销毁。
- **房间 UI 用代码搭，不建 `.tscn`** —— 它是模组现场挂的调试雏形，不值得为它新增场景资源 + `.uid`；
  真做正式 UI 再照 `glove_slot.tscn` 落成场景。

## 踩坑

1. **`MAIN_GAME_CLICK_CARD` 的 payload 是 `Card` 对象**，过不了网络 → **正解**：命令里换成
   `card_index`（`card.get_index()`）+ `plant_type`，主机侧再按下标还原。
2. **`create_norm_zombie()` 有个 `init_zombie_special: Callable` 参数**，同样不可序列化 →
   已记进文档 §八，阶段二改成枚举 id（本次未动，避免扩大改动面）。
3. 编译门禁**抓不到「方法在基类上不存在」这类语义错误**（既有发现，见
   [2026-10-07 那条](2026-10-07_排查调试_get_world_2d与编译门禁盲区.md)）→ 新写的 RPC / 回调**必须**人工开一次游戏确认。
4. 想一次把 164 处随机全替换 → **放弃原因**：其中约 130 处是纯表现（眨眼 / 断肢弹道 / 音效 / 花园），
   不同步也不影响胜负，全改只会把改动面扩大 4 倍且引入回归风险。
5. **`NetplaySession.is_connected()` 撞 `Node` 的引擎方法** → 编辑器报
   `The function signature doesn't match the parent. Parent signature is "is_connected(StringName, Callable) -> bool"`
   → **正解**：改名 `is_linked()`。挂在 Node 上的类起名前先过一遍引擎 API。
6. **模组在 autoload `_ready()` 里 `add_child` 被拒**（`Parent node is busy setting up children`），
   会话节点进不了树 → `multiplayer` / RPC 全废 → **正解**：`tree.root.call_deferred("add_child", node)`。
   **这两条编译门禁都抓不到**（门禁只编译被资源引用到的脚本，新脚本整份漏）——
   → **正解**：新脚本配一个探针跑一遍；本轮新增 `test/scenarios/probe_netplay_session.gd`
   （会话挂载 / 拦截器 / `GameRng` 可复现 / `entity_id` 分配器，四项全过）。
7. 探针第一版自己写错了断言（种子只播一次却连取两组，本来就该不同）→ **正解**：
   每次取值前重新播种；`set_seed()` 只把发生器拨回起点，之后仍是连续取值。

## 补充二（同日追加）：界面全收进控制台，删掉房间面板与主菜单入口

用户要求「状态显示等都放在控制台」—— 于是：

1. 本体补两种**通用**能力（不带联机字样，谁都能用）：
   - `ConsoleEntry.E_Kind.Readout`：一行只读文本（名字 + 值），只有取值没有 setter —— 给「状态」这种随时间变的东西用。
   - `ConsoleRegistry.request_refresh()` → `values_changed`：值在外面被改了就喊一声，面板**只重读不重建**
     （原先只有 `entries_changed` → 整体重建，状态频繁变太贵）。
2. 模组那一栏扩到五行：**目标输入框 + 开启房间 / 加入房间 + 状态 / 最近一条流水**；
   `_status_text()` 显示 `连接状态 ／ 角色 ／ 本地 peer id ／ 房里几人`，会话的
   `state_changed / peer_joined / peer_left / session_log` 全部接到 `_request_console_refresh()`。
3. **删掉 `netplay_room_ui.gd`（房间面板雏形）和主菜单「联机」入口按钮** —— 面板被控制台取代后，
   那个入口按钮点了也没地方去；联机现在是**控制台唯一入口**。

**踩坑**：`session.multiplayer.get_peers()` 在**还没创建过 peer 时**会打 ERROR（`No multiplayer peer is assigned`），
而控制台每次重建 / 刷值都要读一次状态 → 日志里全是噪音。正解：先判
`_session.multiplayer != null and _session.multiplayer.multiplayer_peer != null` 再问，没连过时房里就是 1 人。

## 补充一（同日追加）：控制台「联机」栏

用户要求「模组启用后在控制台加一栏：输入框 + 开启房间 / 加入房间两个按钮」。

1. 控制台原本只有三种形态（Toggle / Button / Slider），**没有输入框** → 给本体加第四种通用形态
   `ConsoleEntry.E_Kind.Text`（`create_text()` + `set_placeholder()`，面板造「名字 + LineEdit」，
   回车 / 失焦写回，**回写时跳过正在获得焦点的输入框**）。
2. `NetplayMod.register_console_entries()` 挂三条：`netplay_target`（输入框，键 `netplay.target` 持久化）、
   `netplay_host`、`netplay_join`，同在「联机」组；`_parse_target()` 支持 `地址:端口` / 只写端口 / 只写地址 / 空串回退。
3. 探针补第 5 段（条目形态 + 分组 + 三种解析），无头跑 `[NETPLAY] result=PASS failed=0`（12 项）。

**经验**：控制台是模组挂调试项的正路（一行一条、不改场景、不改 `ConfigService`、关模组自动撤销），
缺形态就先给本体补**通用**形态，不要在模组里自己去摸面板节点。

**顺带修的既有缺陷**：`probe_console_registry` 按**绝对数量**断言面板控件（滑条=1 按钮=1），
联机模组一开多出 2 个按钮就误报 FAIL → 改成**先数基线、只断言自己这批带来的增量**，
滑条按行首名字标签定位（`HSlider` 自己没有文本）。教训：探针要验"可扩展性本身"就不能假设场上只有自己。

## 补充（同日追加）：选卡协商（不跳过 + 不重复 + 撞车让路）

用户要求"选卡无论如何都不跳过，因为双方不能选重复的卡，需要协商"。

1. **不跳过**：本体原来有一条"没得选就替玩家全选并跳过"（`is_no_choose_permission()`）。
   抽头的难点是**时机** —— 清 `is_locked_card_slot` / `prechosen_cards` 必须早于
   `card_manager.init_manager()`（那之后卡槽已照预选卡填好、待选卡已隐藏），
   而原先唯一的钩子 `install_to_main_game()` 排在其**之后**。
   → 给本体加通用钩子 `ModBase.on_level_para_ready()`（`_ready()` 里 `init_para()` 之后、
   `init_manager()` 之前），`ModManager.notify_level_para_ready()` 转发。不带联机字样。
2. **不重复**：新文件 `netplay_card_sync.gd`（随本局挂、随场景灭）。每帧比对出战卡槽快照，
   变了就 rpc 全量广播；对面挑走的用 `set_plant_card_banned()` 置灰；**只还原自己加过的禁选**
   （不碰关卡本来就禁的那批）；模仿者按同一株植物去重。
3. **撞车**（几乎同时挑同一张）：`must_yield()` —— peer id 大的一方让，自动点掉自己那张。
   两端同一条规则，不必多一次往返。
4. 探针第 7 段用**用户现场同款数据**（拥有 1 张植物、卡槽 6 个）复现并覆盖：
   单机保留原行为、联机找回 UI、让路规则、植物卡 / 模仿者 / 僵尸卡身份判定 —— **27 项全 PASS**；
   编译门禁 PASS。

**经验**：本体"替玩家做主"的优化（这里 = 自动全选跳过选卡）往往藏在业务判据里，
多端场景一改就要推翻 —— 与其在模组里补动作，不如给本体加一个**时机正确的通用钩子**，
本体行为不变、模组有地方插手。

## 补充（第三次追加）：客户端的「开始摇滚吧」变「准备」，人齐了房主才开始

1. **改文案这件事本身才是难点**：选卡那颗按钮的文字**烘焙在贴图里**（`SeedChooser_Button_Glow.png`），
   既没有 Label 也没有代码赋值 —— 无从改起。做法是**把原版那颗藏起来**（`visible = false`，数据一概不动），
   照它的位置尺寸补一颗：跟本体「开始战斗！」那颗同一份 `pvz_theme.tres` + 同一个 `PanelButtonBG` 变体，
   中文字体现成就有。`NetplayReadyFlow` 退场时会把原按钮还原，不会让下一局缺一块。
2. **闸门锁在 `MainGameManager._on_card_slot_norm_start_game()`**：那是"点按钮 / 跳过选卡 / 调试入口"
   三条路的**唯一汇合点**，在 UI 层拦会漏掉另外两条。本体按既有套路留一个通用口
   `choose_card_start_gate`（返回 false = 不许收工），没人接管时恒 true。
3. **房主与客户端走的是同一条本体路径**：房主 `_press_start()` / 客户端收到房主的"收工"之后，
   都做同样的两步（`save_choosed_cards()` + push `CARD_SLOT_NORM_START_GAME`），
   不会出现"房主打起来了、客户端还站在选卡界面"。
4. 没走上选卡界面的那一局（传送带 / 没有选卡权）**自动替本机报准备** —— 那种关卡没有「准备」可以按，
   不然房主会永远等一个不可能按键的人。
5. 探针第 9 段（准备判据 / 两颗按钮的文案 / 客户端按了也不会开始 / 可以按回取消）**51 项全 PASS**；
   `probe_unlock` 回归 PASS（未连线时选卡→开战→解锁行为不变）；编译门禁 PASS。

**踩到的坑（第三次踩同类）**：`request_ready()` 是引擎 `Node` 的方法（"我要重新跑一遍 ready"），
在 `NetplaySession` 里取同名会**编译不过**（签名不符的覆盖 + 覆盖原生方法警告被当错误）。
这是 `is_connected()` 那次的翻版 —— **给 Node 的子类起名前先在脑子里过一遍 Godot 内置的那几个常用的**
（`request_ready` / `is_node_ready` / `is_connected` / `connect` / `emit_signal` …），
这次改成 `declare_ready()`。

## 补充（第四次追加）：战斗同步 —— 主机权威（阶段三）

1. **先立"事实只有一份"这条**，不要一开始就做实体快照：客户端按下的操作**不在本地生效**
   （`EventBus` 拦截器在客户端返回 true），上行给主机；主机在自己这一局上跑成的那一遍再
   `battle_op.rpc()` 下行，屋里的每一个人（含发起者）重放。**主机跑不动就不下发** ——
   两端不会记下一笔歪账。
2. **重放尽量推本体的同一条事件**（`MAIN_GAME_CLICK_CARD` 等），而不是替本体调 API：
   推同一个事件就还是本体的同一条链路，音效 / 生命周期 / 冷却与阳光够不够的校验都不用再抄一遍。
   种植物与铲植物共用 `hand_manager._on_click_cell()` —— 手里拿着什么就做什么，重放时不猜意图。
3. **新加的本体口只有一处**：`HandManager.cell_click_gate`（返回 true = 本地不处理）。
   点格子原先**不走 EventBus**（是鼠标信号直接调），没这个口客户端就上行不了"点了哪一格"。
4. **随机同源**：主机每开一关换一颗种子下发，两端 `GameRng` 种同一颗；后加入的人补发。
5. 探针第 10 段（命令打包解包 / 接管规则 / 种子同源 / 跑不动就不下发）**十段全 PASS**；
   `probe_unlock` 回归 PASS（未连线时种植与解锁完全照旧）；编译门禁 PASS。

**踩到的坑（第四次踩"命名 / 类型"这类）**：

- `var mg := Global.main_game` **编译不过** —— `Global.main_game` 出来是 Variant，`:=` 推断不出类型，
  必须显式写 `var mg: MainGameManager = ...`。
- 由此派生一条排查经验：**新加的 `class_name` 脚本如果自己没编译过，引用方会报
  `Identifier "XXX" not declared in the current scope`**（看上去像"类没注册"，其实是自己文件里的错）。
  用 `godot --headless --check-only --script res://…/xxx.gd` 可以**单独**查这一个文件
  （代价：autoload 认不到，会假报 `Identifier not found: EventBus`，见真错就行）。
- ⚠️ 编译门禁 PASS 但**没抓到**上面那个错（门禁的已知局限：够不着的脚本不编译；这次连
  引用方 `netplay_mod.gd` 都没被加载）。**新加脚本后必须跑一次探针**，不能只看门禁。
