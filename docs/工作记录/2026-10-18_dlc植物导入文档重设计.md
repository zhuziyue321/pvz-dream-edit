# 2026-10-18_dlc植物导入文档重设计

> **本次任务**：15 个 agent 照《DLC植物导入.md》并行接了 15 株 DLC 植物，结果在命名 / 注册 / 探针 / 文案四处漂移；把这份文档从「两株特例教程」重设计成「并行作业契约 + 填空式角色卡 + 单一登记表」。
> **耗时 / 轮次**：1 轮（只改文档，未开游戏、未跑探针）
> **推荐度**：（待后来者照做后回填）

## 目标

让「并行接 N 株 DLC 植物」的产出形状一致、共享文件不互相覆盖，并且文档不再把「已接两株」这类现状写死在正文里。

## 现状证据（重设计前的实测）

- `mods_builtin/dlc/dlc_mod.gd` 1102 行：16 株的常量 / 图鉴 / 配方三段各自穿插，同一件事两种命名（`FALLBACK_PLANT` 与 `*_FALLBACK_PLANT` 并存；环轨仙人掌的图鉴函数叫 `_register_almanac_entry()`，没有角色名）。
- `install()` / `uninstall()` 各手写 16 行调用，加一株要动 4 处。
- 15 份 `test/scenarios/probe_dlc_*.gd` 共 197~298 行不等，`_plant` / `_spawn_zombie` / `_hp` 等辅助函数各写各的。
- 光照蘑菇（`glowshroom/`）有场景、有配方，**没有探针**。
- `get_mod_description()` 与 `create_detail_control()` 漏了光照蘑菇、增幅鹅河菊。

## 最简路径（步骤）

1. 清点并行产物：`mods_builtin/dlc/*/` 目录清单、`dlc_mod.gd` 的 region 划分、`probe_dlc_*` 清单，列出「有配方没探针 / 有株没文案」的缺口。
2. 重写 `docs/参考存档/DLC植物导入.md`，新结构：
   - §1 并行契约（文件归属矩阵 / `dlc_mod.gd` 的 S1~S7 追加槽位 / 6 条红线 / 派活模板 / DoD）
   - §2 命名口径（原先散在正文，现在一张表）
   - §5 角色卡（数据 / 场景 / 脚本 / 子弹 / 配方 / 探针，填空式）
   - §6 技术要点（按主题查：动画卡面、摆放、节奏、静默失败）
   - §8 现状登记表（16 株，唯一来源，含欠账）
   - §10 复盘（15 agent 混乱现象 → 根因 → 对应条款）
3. 同步索引与目录指针：`docs/参考存档/README.md` 的索引行、`mods_builtin/dlc/README.md` 里「两株」的过期表述。

## 弯路 / 踩坑（三段式）

- **试过**：在原文档上补一节「并行注意事项」。
- **因为**：旧文档把 8 步流程与「已接两株」的现状混在正文里，补注意事项治不了「每个人自由发挥」这个根因。
- **结论**：改成「契约（不能碰什么）+ 可复制模板（照填空）+ 单一登记表（现状只在一处）」，并删掉正文中所有「两株」的现状描述。

- **试过**：顺手把 `dlc_mod.gd` 的 16 组重复收敛成 `DlcPlantSpec` 数据表。
- **因为**：本次只要求重设计文档；且该重构会与在途的植物分支全冲突。
- **结论**：写进新文档 §10 的「推荐（可选）」，注明必须由 main 单独一笔提交。

## 推荐度与理由

文档层重设计成本低（1 轮），能直接约束下一批并行 agent 的产出形状。真正的收敛（spec 表）仍待 main 单独做。
