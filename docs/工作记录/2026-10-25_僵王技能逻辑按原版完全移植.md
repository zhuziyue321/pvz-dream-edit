## 目标

## 原版口径清单（照 `Zombie.cpp` 逐条抄）

**调度（`UpdateBoss()`）**：四条技能线各持一个倒计时计数器，**并行倒计时**（每 tick 递减，
`mIceTrapCounter > 0` 即被冻住时暂停）；Idle 每轮 `mPhaseCounter` 100~200 tick 后按
**固定 else-if 优先级**发招：

1. **破损阶段变化**（`GetBodyDamageIndex()` 对 BOSS 特判：`< max/2` 阶段 2、`< max×4/5` 阶段 1）：
   进阶段 1 **立即** `BossBungeeAttack()`，进阶段 2 **立即** `BossRVAttack()`；
2. `mBossStompCounter == 0` → 踩踏（`BossStompAttack` **先重置计数再查目标**，无目标提前返回、本轮不发招）；
3. `mBossBungeeCounter == 0` → 冒险 1/4、其余 1/2 概率 `BossRVAttack()`，否则蹦极；**两种结果都先重置蹦极计数**；
4. `mBossHeadCounter == 0` → 吐球；
5. `mSummonCounter == 0` → 召唤；都不满足则 `mPhaseCounter = 100~200` 继续等。

**计数器初值与重置**：入场给 `mSummonCounter=500`、`mBossHeadCounter=5000`，
`mBossStompCounter` / `mBossBungeeCounter` = **-1（锁定）**；各技能开跑写回自己的计数器：
召唤按阶段 **450~550 / 350~450 / 150~250**，脚踩 **5500~6500**，蹦极 **4000~5000**，吐球 **4000~5000**；
**砸车落地**（`BossRVLanding`）统一重置：召唤 500、吐球 5000、脚踩 4000（阶段 ≥1）、蹦极 6500（阶段 ≥2）。

**召唤（`BossSpawnContact`）**：一次一只；类型按 `mZombieAge` 分段：**<3500 普僵 / <8000 路障 / <12500 铁桶**，
之后从 `gBossZombieList`（路障、铁桶、橄榄球、撑杆、小丑、扶梯、冰车、投石车、跳跳、读报、铁门、巨人）等权随机，
**`mTargetRow == 0` 时把巨人从池里剔除**；行先由 `PickRowForNewZombie` 选。

**踩踏**：行对起始行 0~3 中挑「该行或下一行 `mPlantCol >= 5` 有植物」的（`BossCanStompRow`），
落地帧压 2 行 × 显示列 6~9；触发帧 0.5（行 0~1）/ 0.55（行 ≥2）。

**蹦极**：3 只，列 `mTargetCol(0~2)+i`；**砸车**：行 0~3、列 0~2 的 2 行 × 3 列区域碾压。

**吐球**：行 0~4 等权、冰火各半；低头前待机 500 tick、吐球后 300 tick。

## 关键决策与理由

- **只换「调度 + 数值」层，架构层（状态机 / 技能组件 / 动画控制器 / 事件关键帧）原样保留** ——
  那套是 2026-10-06 v1.3.0 移植的接入契约（受击窗口 / 音效 / 部件平移 / 死亡演出），与玩法口径正交。
  原版的「阶段 + 计数器」映射到「`select_skill()` 返回哪个技能状态」正好是同一抽象层级。
- **计数器用「动作秒」递减而不是裸 delta** —— 冻结时动画倍率为 0 → 四条线同步停住，
  等价原版 `mIceTrapCounter > 0` 不递减的口径，不用再引入一套冰冻判断。
- **阶段判定复用 `hp_stage_change_component.curr_hp_stage`** —— 博士场景的破损阈值
  （32000 / 20000）**本来就是原版的 80% / 50%**（`GetBodyDamageIndex` 对 BOSS 是特判值，
  不是普通僵尸的 2/3、1/3），`curr_hp_stage + 1` 直接就是 `mBossMode`，一行都不用改数值。
  此前文档写的「剩余 50% / 25%」是旧口径残留，已纠正。
- **开局固定剧本彻底删除** —— 2026-10-05 那轮按 wiki 描述做的「4 普僵 → 4~5 路障 → …」剧本，
  在 C++ 里**不存在**：wiki 的观感是 `mZombieAge` 分段自然涌现的（35 秒内放的全是普僵 ≈ 4 只）。
  两条「原版口径」打架时以 C++ 为准（AGENTS.md 的行号基准口径）。
- **蹦极无目标时仍重置计数** —— 原版 `BossBungeeAttack` 进函数就写回计数器；
  仓库侧蹦极 `can_start` 要求有偷取目标，不补这条的话首次阶段 1 强制蹦极落空后
  `bungee_counter` 会停在 -1，蹦极线永久锁死。
- **踩踏区域从 2×3 改 2×4** —— 三份 `.tres` 里 `top_left=(行,7)` + 默认 `size=(2,3)` 只盖显示列 7~9，
  原版是 `mPlantCol >= 5`（显示列 6~9）。顺手发现文档写的「2 行 × 最右 4 列」与配置对不上，一并修正。

## 踩坑

1. **`GetBodyDamageIndex()` 不是全局的 2/3、1/3** —— 普通 `Zombie.cpp:5812` 起手就是对
   `ZOMBIE_BOSS` 的特判（`< max/2` → 2、`< max×4/5` → 1），照普通僵尸口径推「2/3 掉手、1/3 掉头」会全错。
2. **四计数器是「并行倒计时 + 优先级检查」，不是「冷却轮换」** —— 计数器在技能动画播放期间也照减
   （原版 `UpdateBoss()` 的递减不在任何 phase 分支里），所以长动画（低头吐球约 10 秒）期间
   脚踩 / 蹦极计数照样走，落地可能「出完招立刻又满足条件」。移植时别把它写成「技能结束后才重新计时」。
3. **`Rand(4) == 0` 的分支里蹦极计数也要重置** —— 原版在 `BossRVAttack()` 之前就写了
   `mBossBungeeCounter = RandRangeInt(4000, 5000)`；漏掉会让「抽中砸车」的轮次白吃一次蹦极轮换。
4. **用户的 Godot 编辑器开着项目 → autopilot 拒跑**（`result=STALE_PROCESS`，进程带窗口标题
   `PVZ-Dream-Edit`）—— 按老规矩不杀编辑器，本轮只交编译门禁 + 重写好的探针，跑批留给下次编辑器关着时。
5. **探针里的血量断言要直接调 `judge_body_change()`** —— 直接给 `hp_component.curr_hp` 赋值不会触发
   `signal_hp_loss`，`curr_hp_stage`（以及由此推出的破损阶段）不会更新，断言会假阴性。

## 给后来者的最简路径

1. 「按原版移植某角色」先照 C++ 把**行为清单**逐条抄下来（计数器初值 / 重置点 / 优先级 / 随机区间），
   标出与现状的每一处差异，再决定哪些落代码、哪些落场景配置 —— 本轮 80% 的差异是配置和常量。
2. 原版常量统一「tick ÷ 100 = 秒」换算后写进 `@export` 区间，保留 tick 原值在注释里方便回对。
3. 验证：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss_spawn_interval`。
4. 人工验证清单（开窗口看表现）：
   - 开局 ~5 秒第一次伸手放僵尸，之后每 4.5~5.5 秒一只；前 35 秒全是普僵，35~80 秒全是路障，80~125 秒全是铁桶；
   - ~50 秒第一次低头吐球（冰火各半），受击窗口只在低头期间开；
   - 打到 80% 血以下立刻天降 3 只蹦极；此后每 40~50 秒一轮蹦极（冒险 1/4 概率变成扔房车）；
   - 打到 50% 血以下立刻扔房车，落地后每 55~65 秒踩一次（压最右 4 列的 2 行）、放置变快；
   - 砸车落地后 5 秒内就会再次伸手放僵尸。
