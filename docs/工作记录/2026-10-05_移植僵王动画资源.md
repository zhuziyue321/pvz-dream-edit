## 目标

把参考项目 `PVZ-Godot-main` 的僵王博士 23 段动画资源搬进本仓库，让僵王的动画表现与参考一致。

## 步骤

1. **先比轨道构成，别急着拷文件**：各取一份 `idle` 动画统计 track 数 / 类型 / 属性分布 ——
   本仓库 85 条（49 节点，只有 `visible` + 9 个节点的 `position/rotation/scale/skew`），
   参考 504 条（72 节点 × 7 属性，含 `texture` / `self_modulate`）。**差异一眼就定位了。**
2. **核对节点名能不能对上**：拿参考动画的 track 节点名与本仓库 `zombie_boss.tscn` 的部件节点名做集合差集
   —— 49 个部件**完全一致**（注意有 8 个是 `Boss-xxx` 减号命名，按 `Boss_*` 过滤会漏，要用 `Boss` 前缀取）。
3. 查清两边的播放器结构差异：参考**23 个 AnimationPlayer 各挂 1 段**（另有 23 个遗留的短名节点），
   本仓库**1 个 AnimationPlayer 挂 23 段** —— 脚本的 `_cache_anim_players()` 两种都能处理，
   所以**场景不用动**，只要把 23 个 `.tres` 的内容换掉。
4. 写一次性转换脚本 `tools/port_zomboss_animations.py`（支持 `--apply` 预演/写入），做四件事：
   保留本仓库文件 uid、剔除 `Anim_*` 轨道、修正贴图路径、重写贴图 uid。
5. 预演 → 确认统计与缺失项 → `--apply` 写入。
6. 校验：编码（无 BOM + LF）、uid 未变、`resource_name` 与脚本里 `_play_anim()` 用的名字一致（含大写 `Zombie_boss_RV_1`）、
   `zombie_boss.tscn` 的 `AnimationLibrary` 里 23 个 key 与脚本一一对应。
7. 无头编辑器解析 → 跑探针 → 给探针补一条「贴图轨道」回归断言。
8. 同步文档：[特殊关卡.md](../参考存档/特殊关卡.md#僵王博士dr-zomboss本体)（表格加「动画」一行）、
   [animation/AGENTS.md](../../animation/AGENTS.md)（加「这 23 段是移植版，别用工具重新生成覆盖」的例外说明）。

## 关键决策与理由

- **移植体是「内容」不是「文件」** —— 直接拷参考的 `.tres` 会把 uid 也带过来，
  而本仓库 `zombie_boss.tscn` 的 `AnimationLibrary` 是按 uid 引用这 23 段的，拷过去等于 23 处引用全断。
  → **保留本仓库 uid、只换 `[resource]` 主体**，tscn 一行都不用改。
- **剔除 23 个 `Anim_*` 节点的轨道**（504 → 343，每段剔 161 条）—— 那些是参考场景里的 AnimationPlayer 节点
  （它有 23 个，本仓库只有 1 个），本仓库没有这些节点，留着会在播放时一直报 node not found。
  343 = 49 部件 × 7 属性，正好是全量覆盖。
- **贴图路径自动修正**：参考动画引 `Zombie_boss_neck.png` / `Zombie_boss_upperbody.png`，
  本仓库这两张源图是 jpg，配套 png 带下划线（`neck_` / `upperbody_`）→ 脚本探测到文件不存在就换成 `_` 版本，
  并用本仓库 tscn 里的 uid 重写引用（顺手做了 path → uid 映射）。
- **给探针加一条「贴图轨道」断言** —— 这次的坑就是「动画看着有、其实缺了贴图序列」，
  加一条 `texture` / `self_modulate` 的存在性断言，以后再被精简覆盖会立刻 NG。

## 踩坑

1. **一开始只看文件大小（39KB vs 274KB）不敢下结论** → 用脚本统计 track 数与属性分布，
   10 秒就定位到"缺 `texture` / `self_modulate`" → **正解**：比资源先比**结构**（轨道类型分布），
   别靠肉眼估。
2. **按 `Boss_*` 过滤节点会漏 8 个 `Boss-xxx`（减号命名）** → 本仓库场景数出来 41 个，
   与动画里的 49 个对不上，差点误判"节点对不齐" → **正解**：这批 reanim 部件两种分隔符都有，
   过滤用 `Boss` 前缀而不是 `Boss_`。
3. **PowerShell 的 `[System.IO.File]::ReadAllBytes()` 认的是 .NET 工作目录，不是 `cd` 之后的 PS 目录**
   → 相对路径报"找不到文件" → **正解**：拼接绝对路径。
4. **`Get-Content` 被拦（要求显式 `-Encoding`）** → 加 `-Encoding UTF8` 即可；写回 Godot 资源时更要小心，
   统一用 Python `open(..., encoding="utf-8", newline="\n")` 保证**无 BOM + LF**。
5. **改探针时把新函数插进了别的函数体里**（替换锚点选在了函数中间）→ GDScript 直接语法错 →
   **正解**：加辅助函数时锚点选**函数之间的空行**，改完先 `read_lints` 再跑。

## 给后来者的最简路径

1. 从参考项目搬资源前，**先统计两份资源的结构差异**（轨道 / 字段 / 节点），确认"到底缺什么"。
2. 核对**引用方的 key**（本仓库 tscn 用 uid 引动画、用动画名做 `_data` 的 key）—— 移植时保留本仓库的 uid 与动画名。
3. 写一次性转换脚本并做成 `--apply` 两态（先预演看统计与缺失，再写入），别直接覆盖。
4. 校验三步：无 BOM + LF、uid 未变、名字对得上；再跑
   `godot --headless --path . --editor --quit` 排错误，最后跑
   `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss`。
5. **动画表现必须开窗口人工看一眼**（僵王登场 / 低头吐球 / 踩踏 / 死亡），无头只证明资源能加载、逻辑跑通。

## 补充（2026-10-05 · 同日修复）：上文「换成 `_` 版本」是错的 —— `xxx_.png` 是黑白蒙版，不是贴图

本节推翻上文「关键决策」里 **贴图路径自动修正** 那一条：`Zombie_boss_neck_.png` /
`Zombie_boss_upperbody_.png` **不是**「配套 png」，而是 PVZ 原版 `xxx.jpg`（彩色）+
`xxx_.png`（配套**黑白蒙版**，白 = 不透明）里的蒙版。把它们当贴图引用的结果是：
脖子（驾驶舱）与上身在动画里显示成**黑白蒙版图**。

**正解：先把蒙版烘进 alpha，再引用烘焙产物** —— 仓库早有这条约定与工具
（`src/items/pool.gd` 的泳池底图就是这么来的）：

```powershell
powershell -ExecutionPolicy Bypass -File tools/merge_alpha.ps1 -Name assets/reanim/Zombie_boss_neck
powershell -ExecutionPolicy Bypass -File tools/merge_alpha.ps1 -Name assets/reanim/Zombie_boss_upperbody
# 等价 ffmpeg：jpg 的 RGB + mask 的灰度 → RGBA png（白 = 不透明；极性反了才加 -Invert）
godot --headless --path . --import   # 让 Godot 生成 .import 与 uid
```

然后把引用改到烘焙后的 png：14 个动画 `.tres` 的 `ext_resource`（path + uid）
以及 `zombie_boss.gd` 的 `TEX_NECK` / `TEX_UPPERBODY`。

同时改了**根因** `tools/port_zomboss_animations.py`：

- `fix_ext()` 不再「文件不存在就退化成 `xxx_.png`」，改为记 `[NG]` 并提示先跑 `merge_alpha.ps1`；
- uid 改为**优先取贴图自己的 `.import`**。原来取 tscn 的贴图映射，而 neck / upperbody 根本不在
  tscn 的 `[ext_resource type="Texture2D"]` 表里（`Boss_neck` 节点没有 texture），
  于是重跑脚本会把参考项目的旧 uid 写回来。

**验证**：`--import` 零错误 + `probe_zomboss` 全绿（`result=PASS failed=0`）；
无头只证明资源能加载，脖子 / 上下身的实际观感需**开窗口人工看一眼**。

**给后来者的一句话判据**：仓库里 `X.jpg` 与 `X_.png` 成对出现时，`X_.png` **是蒙版**，
**永远不要**把它当贴图引用；先 `merge_alpha.ps1 -Name X` 烘出 `X.png` 再用。
