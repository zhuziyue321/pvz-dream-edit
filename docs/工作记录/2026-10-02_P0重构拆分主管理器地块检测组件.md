# 2026-10-02 · 其它 · P0 重构拆分：主管理器 / 地块 / 检测组件

> **任务类型**：其它
> **推荐度**：**推荐**（下次拆主游戏系列脚本照这个走）
> **耗时与成本**：约 3 轮对话，开了游戏（无头探针 + 一次带窗口）
> **验证方式**：打开游戏实测 —— `probe_adventure_reward / probe_car_key / probe_rake / probe_unlock / probe_tutorial / probe_hand / probe_glove_unlock / probe_mower_protect` 全 PASS，另跑了一次 `-Windowed` 的 1-1 教程关 PASS
> **补充自**：无（首条，方案本身在 [重构拆分方案.md](../参考存档/重构拆分方案.md)）

## 目标

按 [重构拆分方案.md](../参考存档/重构拆分方案.md) 的 P0 三件（S1 主管理器 / S2 地块 / S3 检测组件）落地拆分，行为不变，跑通回归。

## 步骤

1. 先读方案文档 §2「仓库既有拆分范式」定位到两种既有模式：场景节点子管理器（`extends MainGameSubManager`，靠 `owner` 取主引用）与运行时 `new()` + `manager.add_child()`（TutorialManager / DaveSellManager / LevelTimelineManager）。
2. S1 拆 `main_game_manager.gd`：新建 `src/managers/main_game_manager/` 三个子管理器（`mgm_reward_manager` / `mgm_save_manager` / `mgm_lose_manager`），**只保留对外 API 不变、内部实现搬走**，主文件只留阶段机与编排。主文件剩 707 行，三个子管理器 193 / 117 / 61 行。
3. 给 `MainGameSubManager._get_main_game()` 补一条 `Global.main_game` 兜底 —— 原来只认 `owner`，运行时 `new()` 出来的子管理器 owner 为 null 会 `push_error`。
4. 用 `Select-String` 全仓扫 `main_game\.(被搬走的方法名)`，改掉 7 处外部调用点（5 个 test 探针 + 主游戏菜单「重新开始」）+ `background_manager` 的进家面板赋值。
5. S2 地块：只做「三处重复的底部植物容器重父化」收敛 + 邻居查询下沉到 `PlantCellManager`；原计划把手套区 / 特殊状态区拆成子脚本**放弃**（理由见「关键决策」）。
6. S3 检测组件：新建 `detect_target_strategy.gd`（105 行，全 static、无状态），把「格子内首个可攻击植物 / 空中僵尸 / 追踪子弹选敌」三段搬走，组件剩 374 行、只留转发。
7. **每加一个新脚本都要重新 `--import`**（见踩坑 1），再跑回归。

## 关键决策与理由

- **子管理器用运行时 `new()` 而不是改 `.tscn`** —— 只改一份 `main_game_base.tscn` 也要手写 `uid://` + `.uid` 文件，手搓 uid 有风险；而 TutorialManager 已经证明了运行时创建的路子，配一条 `Global.main_game` 兜底就通了。
- **`_is_curr_level_success()` 改成公开的 `is_curr_level_success()`** —— 子管理器要从外面调它，`_` 前缀只是约定不是权限，但跨对象调私有看着别扭，顺势公开。
- **S2 不拆手套区 / 特殊状态区** —— 这两块全是「改 PlantCell 自己的字段」（`plant_in_cell` / `curr_condition` / `tombstone` / `pot`…），拆成子节点后只能 `get_parent()` 抓宿主改字段，正好踩 [项目规范](../项目规范.md) 硬约束 §1-2。GDScript 没有 partial class，**这类「自身状态 + 自身 API」的胖脚本不该硬拆成节点**。
- **S3 不顺手统一子弹里的 `get_first_be_hit_plant_in_cell`** —— `bullet_000_parabola_base` 是 Norm > Shell > Down，`bullet_000_linear_base` 是 Shell > Norm > Down，优先级顺序不一样，合并会改行为；已在策略文件头部写死「不要合并」的警告。

## 踩坑

1. **新加的 `.gd` 脚本第一次跑报 `Could not find type "MgmRewardManager"`** → Godot 的全局类来自 `.godot/global_script_class_cache.cfg`，新建脚本不会自动进缓存 → **正解**：跑一次 `"<Godot>.exe" --headless --path <项目> --import` 让它重新扫描（顺带生成 `.uid`），再跑探针。
2. **`MainGameSubManager` 对运行时创建的子管理器会 push_error** → 基类只认 `owner`，运行时 `add_child` 的节点 owner 为 null → **正解**：基类 `_get_main_game()` 加 `Global.main_game` 兜底（`MainGameManager._enter_tree` 已注册，根节点先进树，子节点的 `_enter_tree` 一定能取到）。
3. **删大段代码块时 `Get-Content` 会用 ANSI 读 UTF-8 中文，容易写坏文件** → 行号也对不上（`Measure-Object -Line` 给的是 711，实际 975）→ **正解**：用 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` 读写，写入用 `New-Object Text.UTF8Encoding($false)`（无 BOM），行号校验也用同一套 API。
4. **删掉大块代码后 `#region` / `#endregion` 会失衡**（`main_game_manager` 多出一个孤儿 `#endregion`）→ 它只是注释，Godot 不报错、探针也照过 → **正解**：删完块 grep 一下 `^#region` 与 `^#endregion` 的条数是否相等，顺手补平。
5. **回归里有 3 个探针本来就 FAIL** —— `probe_plant`（点卡后阳光没扣，UI 坐标问题）、`probe_night`（2-5 / 2-10 的 `game_BGM` 数据漂移）、`probe_critical_value`（`_mower_of(0)` 取不到小推车）、另有 `probe_bungi_blitz` / `probe_card_lock`（`card_slot_candidate.gd:119` 取 `999` 键报错）→ 这三个**都不触及本次改动的任何 API**（已 grep 确认），是工作区本来就脏导致的 → **正解**：改前先跑一遍目标探针留基线，或至少 grep 确认失败点不涉及自己改动的符号。

## 给后来者的最简路径

1. 新子管理器文件放 `src/managers/main_game_manager/mgm_*.gd`，`extends MainGameSubManager`，实现 `init_manager()`（没初始化逻辑就 `pass`），事件订阅写在这里。
2. 主文件加 `var xxx_manager: MgmXxxManager` + 一个 `init_xxx_manager()`（`new()` → `name` → `manager.add_child()`），在 `_ready()` 里**早于任何存档逻辑**调用。
3. 原来被搬走的方法如果在别处被调用，全仓 `Select-String 'main_game\.<方法名>'` 改一遍；`EventBus.subscribe` 跟着方法一起搬。
4. 跑 `--import`，再跑相关 `-Scenario` 探针。
