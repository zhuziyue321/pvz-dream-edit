# 2026-10-13 僵尸卡片做成「调试模式」可选（选卡界面第 3 页）

> **任务类型**：其它（已有内容的开关化）
> **一句话**：僵尸卡片本体全齐（26 张僵尸卡 + 1 张僵王卡 + 预选通道 + 手持放僵尸），只是
> `ConstFeatureSwitch.ZOMBIE_CARD_ENABLED = false` 整片隐藏 —— 给判据加一条「或控制台『调试模式』打开」，
> 勾上后僵尸页出现在选卡界面**第 3 页**。
> **补充自**：[2026-10-04_隐藏选卡界面僵尸卡片.md](2026-10-04_隐藏选卡界面僵尸卡片.md)（开关就是那条记录加的）

## 1. 先确认「缺的是哪一环」

照 [2026-10-11 保龄球做成调试模式植物](2026-10-11_保龄球三兄弟做成调试模式植物.md) 第 1 节的五处自查
（类型注册 / 场景 / 数据表 / 卡片容器 / 解锁列表）过一遍：

- 僵尸类型、场景、卡面、预选通道、手持放置（`hand_component_character`）**全都在**；
- `GlobalGameState.curr_zombie` 默认就含全部 26 种僵尸，`curr_zombie_boss` 含博士 —— 不需要解锁那一环；
- 唯一缺的是「**生成僵尸候选卡页**」：`CardSlotCandidate._ready()` 里被 `ZOMBIE_CARD_ENABLED` 挡住了。

所以这次不是补内容，是**给判据加一条通道**。

## 2. 页码怎么就是第 3 页（结论：什么都不用挪）

页序 = `all_card_page_array` 的追加顺序（植物页 → 僵尸页 → 僵王页），
每页卡数 = 网格模板的占位数量（植物 48 / 僵尸模板远大于 27）：

| 页 | 内容 | 什么时候可见 |
| --- | --- | --- |
| 1 | 植物 card_id 0~47 | 有解锁植物就可见 |
| 2 | 植物 card_id 48~51（保龄球三兄弟 + 反向双发） | **只在调试模式下可见** |
| 3 | 僵尸 26 张 | 调试模式打开才生成 |
| 4 | 僵王 1 张 | 同上 |

因为第 2 页只装调试模式专属植物，**打开调试模式 = 第 2 页点亮 = 僵尸页正好排在第 3 页**，
顺序不用动。翻页列表 `all_show_page` 会滤掉不可见的页，所以不开调试模式时一共只有 1 页。

## 4. 关键决策与理由

- **判据收成一个方法，不再散着读常量** —— 原来三处调用点直接读 `ConstFeatureSwitch.ZOMBIE_CARD_ENABLED`，
  加第二条通道就要改三处且容易漏；现在它们只问
  `Global.global_game_state.is_zombie_card_enabled()`，注释里写明「别直接读常量」。
- **判据放 `GlobalGameState` 而不是 `ConstFeatureSwitch`** —— 后者是纯常量文件，
  让它回头去依赖 `Global` 这个 autoload 会破坏 `src/core/consts/` 的定位；运行状态本来就该住在 `GlobalGameState`。
- **关掉调试模式要清 `selected_cards` 里的僵尸 / 僵王条目** —— 与保龄球那条记录同一个坑：
  「重选上次卡片」是照存档条目直接点卡位的，容器没生成时索引直接越界（僵王分支原本有 `has()`，僵尸分支没有，顺手补上）。

## 5. 踩坑

无（改动是一次成型的）。若硬要说：**僵尸卡片是否可用，判据现在有两层**，
以后再加通道（比如做成模组）只要改 `is_zombie_card_enabled()` 一处，不要到调用点加 `or`。
