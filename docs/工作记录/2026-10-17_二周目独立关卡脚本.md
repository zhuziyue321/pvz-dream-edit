# 2026-10-17 · 玩法 / 冒险进度 · 二周目改成「一关一套独立关卡脚本」（50 份）

> **任务类型**：玩法机制（冒险模式关卡组织方式）
> **推荐度**：**参考**（「把运行期分支换成显式文件」的活，关键不在复制，而在**先给变体找一个不污染注册表的位置**）
> **耗时与成本**：约 1 轮对话；**未开游戏**；编译门禁 PASS（120 个 scenarios）；50 份关卡脚本由一次性 PowerShell 脚本批量生成
> **验证方式**：`test/check_scripts.ps1` PASS；探针改动未实跑（`probe_level_registry_order` / `probe_adventure_next_level` / `probe_card_lock` 已按新口径更新断言）
> **补充自**：[2026-10-16_冒险模式二周目.md](2026-10-16_冒险模式二周目.md)（承上：那条把二周目差异做成 `map_data_from_second_round` 一个字段，这条把它换成 50 份显式脚本）

## 目标

二周目不再是「同一批脚本 + 运行时读周目」，而是**每一关都有自己的第二套脚本** `adventure_XX_YY_round2.gd`（50 关各一份，完整复制正本再改差异）。差异三条：

1. **普通关多 10 波**（10 → 20、20 → 30）；1-1 由 4 波改成 10 波；4-5 砸罐子、5-5 蹦极、5-10 僵王、以及本来就 `-1`（默认 30）的几关**不动**；
2. **开局锁定前 3 个随机卡槽**（从已拥有植物里随机挑 3 株占住前 3 槽，玩家只能编辑后面的槽）；
3. **1-1 ~ 1-3 满 5 行草皮**（变体脚本里 `map_data` 直接写 `map_front.tres`）。

## 最简路径（步骤）

1. **先给变体找位置**：`LevelRegistry` 加 `ROUND_VARIANT_SUFFIX = "_round2"` + 独立的 `_round_variant_path_by_id`，
   `_scan_dir()` 遇到该后缀只登记进变体表（`get_level()` 取得到，但**不进 `ids_by_mode()` / `all_ids()`**）；
   `has_level()` / `get_level_path()` 查两张表。
2. **路由只加一个参数**：`LevelRegistry.get_adventure_level_id(序号, 周目 = 1)`（周目 ≥ 2 且变体存在 → 返回变体 id），
   唯一消费方 `GlobalGameState.build_adventure_level_para()` 把 `curr_adventure_round` 传进去。
3. **锁卡槽走现成链路**：`ResourceLevelData` 加 `locked_random_card_num`，`_resolve_locked_random_cards()` 把随机取到的 N 株写进 `prechosen_cards`，
   填槽与锁定全交给已有的 `CardSlotNorm.init_pre_choosed_card()` —— **UI 零改动**。
4. **批量生成 50 份**：一次性脚本按「完整复制 + 改差异」产出，改完抽查 + 编译门禁。
5. **探针按新口径改断言**，文档同步。

## 关键决策与理由

- **变体不进 `ids_by_mode()`**：id 是选关顺序与存档语义的锚点（「冒险关恰好 50 个、第 n 位 == 第 n 关」）。
  变体混进去 → 断言立刻炸、将来选关页会把一关显示成两关，而且**不报错只错位**。单独一张表最省事。
- **不给变体另立存档键**：`save_game_name` 由 `set_choose_level()` 按序号拼，与「加载哪个文件」无关 ——
  二周目与一周目共用 `101_0_0001` 这类键，进度靠记录里的 `Round` 区分（沿用上一版的设计）。
  换键等于把「10 关一页、按钮序号 == 关卡序号」那条老口径改掉，会静默挪移所有人的进度。
- **锁卡槽复用 `prechosen_cards`，不碰 UI**：现有预选卡已经做到「从第 0 槽顺序填 + 预选卡点不动 + 取消不了」，
  缺的只是「随机取哪几张」。所以新机制只有「挑卡」这一步，选卡界面一行没改。
- **三条边界写进函数注释**：不置 `is_locked_card_slot`、N 夹到 `卡槽数 - 1`（至少留 1 槽）、剔除禁选植物 ——
  任何一条踩了都会从「锁前 3 槽」静默退化成「整关跳过选卡」或塞进本关禁掉的卡。
- **`map_data_from_second_round` 保留为兜底**：变体缺失时会回退正本，那时仍要能满草皮。
  但新差异一律写变体脚本，别再往这个字段上加（否则两个真相源）。

## 弯路 / 踩坑（三段式）

- **试过**：把中文注释/头模板直接写进 PowerShell 一次性脚本（`write_to_file` 产出的是无 BOM UTF-8）。
- **因为**：没注意 5.1 解析 `.ps1` 的编码规则。
- **结论**：`$PSVersionTable` 是 **5.1**，无 BOM UTF-8 脚本按 ANSI 解码 → 脚本里的中文全乱码、正则匹配不到。
  正解：**脚本本体保持纯 ASCII，中文模板放进一个 UTF-8 的 JSON**（用 `Get-Content -Encoding UTF8` 读）。

- **试过**：波数用链式 `-replace` 改：先 `start_battle(10` → 20，再 `start_battle(20` → 30。
- **因为**：想让替换规则最短。
- **结论**：第二步会把第一步刚改出来的 20 又变成 30。正解：**先落到不会互相匹配的占位符再回填**。
  另外正则必须是 `await start_battle\((-?\d+)`：有几关写作 `start_battle(20)`（没有第二个参数），
  只匹配 `\((\d+),` 会**漏改**那几关，而且不报错。

- **试过**：地图替换的正则分组写成 `(…map_front_)(?:1row|5row)(\.tres…)`，替换串里再补一个 `map_front`。
- **因为**：写正则时把非捕获组当成「整段丢弃」，忘了分组里已经含 `map_front_`。
- **结论**：产出 `map_front_map_front.tres`。**生成脚本一定要带自检**（这里加了 `if ($text -match 'map_front_(1row|5row)') { throw }`），
  再抽查 2~3 个产出文件 —— 机械改 50 份时，肉眼扫不过来的错只能靠断言挡。

## 推荐度与理由

**参考**。这类「把运行期 `if 周目` 换成显式文件」的活，难点不在复制，而在**两个不动**：
不动 id 清单（变体单独登记）、不动存档键（靠序号拼）。这两条守住了，剩下就是批量文本改写 + 门禁。
反过来若先动手复制 50 份，回头再发现注册表被污染、存档键被改，就得到处回滚。

## 遗留

- **双份维护**是这次选择的已知代价：一周目正本改了 bug，要手动同步到对应的 `_round2` 变体（50 份）。
- **三周目及以后沿用同一份 `_round2`**（周目无上限，但差异只有这一套）。
- **4-5 砸罐子 / 5-5 蹦极 / 5-10 僵王关没有加波**（按需求不动），15 波以上的普通关也按「+10」处理过。
- **没有新开专门探针**：`_round2` 的字段护栏（波数 / 锁卡槽）目前只由人工抽查与编译门禁守着；
  `probe_level_registry_order` 加了注册表侧护栏（50 个变体都在、不进 `ids_by_mode`、按周目取脚本）。
- **探针未实跑**：本次只跑了编译门禁，三条被改动的探针（`probe_level_registry_order` / `probe_adventure_next_level` / `probe_card_lock`）
