# 2026-10-02 · 关卡与地图 · 实现僵王博士战斗的地图（5-10 夜屋顶）

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次给某一关加「自己的地图 / 背景」照这个走）
> **耗时与成本**：约 1 轮对话，跑了无头探针（`probe_boss_map` 2 次 + 回归探针 4 个），未人工窗口验收
> **验证方式**：免验证 + 已给出人工验证方法（数据层与实机装配都用无头探针通过了，
> 想要肉眼验收的手动方法见本文「验证方式」一节）
> **补充自**：[2026-10-02_关卡时间轴固化到关卡资源.md](2026-10-02_关卡时间轴固化到关卡资源.md)

## 目标

给冒险 5-10 僵王关（Dr. Zomboss）做一张**属于它自己的地图**：与原版「Night Roof」场景对齐的
5 行 × 9 列夜色屋顶，并让 5-10 真正走到这张图上去（几何与原 `map_roof` 一致，只换背景 / 地图资源）。

## 步骤

1. **先查有没有同名资产**：全仓库搜 `zomboss` / `僵王` / `boss`，撞出
   `assets/image/background/background6boss.jpg` 和 `background6_gameover_mask.png` 两张已经躺好的图，
   `src/entities/character/zombie/zombie_boss.tscn` 也早就挂好了 —— 于是任务范围收成「地图层」，
   僵王本体（Z999 的脚本 / 注册表）不在本次做。**先搜再动手，别上来就自己造资源。**
2. **比对两张底图**：用 PowerShell 的 `System.Drawing` 读尺寸 →
   `background5.jpg` 与 `background6boss.jpg` 都是 **1080×440**，
   `background5_gameover_mask.png` 与 `background6_gameover_mask.png` 尺寸也相同
   → **几何可以直接抄 `map_roof`，一个像素都不用挪**。这一步省掉了重算 45 个格子坐标。
3. **新增三件套**（三者必须一起改，改任一件另外两件会漂移）：
   - `data/map/map_boss.tres` —— 抄 `map_roof.tres`，改 `game_sences = 5`、
     `display_name`、`map_bg_scene`；`map_bg_script` 复用 `map_bg_anim_roof.gd`
     （参考存档 [地图实现.md](../参考存档/地图实现.md#45-背景动画脚本mapbganimbase) 明说没新表现可以复用）。
   - `src/world/background/main_game_bg_boss.tscn` —— 抄 `main_game_bg_roof.tscn`，
     换底图 + 多挂一个 `Background6GameoverMask`（位置与 `Background5GameoverMask` 同为 `(108, 139)`）。
   - `ConstLevelData.GameBg` 加成员 `Boss` → `GameBgTextureMap` 指 `background6boss.jpg`。
4. **注册**：`MainSceneRegistry.MainScenes` 加 `MainGameBoss`，补 `MainScenesMap`（指向唯一的主游戏场景）
   与 `DEFAULT_MAP_PATHS`（指向 `map_boss.tres`）。
5. **关卡指向**：`adventure_05_10.tres` 改 `game_sences = 5` / `game_BG = 5`（Boss）/
   `game_BGM = 6`（Brainiac Maniac）/ `is_day = false`（夜里蘑菇不睡）。
6. **写探针**：`test/scenarios/probe_boss_map.gd` —— 静态（关卡指向 / 注册表 / 与 `map_roof` 逐行几何一致 /
   背景子场景契约）+ 实机（进 5-10 后核对底图贴图、房门遮罩、5×9 全 Roof 格子、5 台屋顶清洁车、
   5 行陆地僵尸行、斜面行碰撞区）。**用无头跑得起的方式做回归**，后续改 `map_roof` 也能立刻发现夜屋顶漂移。

## 关键决策与理由

- **新开一份 `map_boss` 而不是复用 `map_roof` 的 `bg_base_texture`** —— 因为草皮 / 无草皮那条
  `bg_base_texture` 覆盖语义是「前院未铺草皮」，把 Boss 夜色图塞进去会让地图资源的语义打架；
  而且有了自己的地图条目，后面「僵王复仇」迷你游戏 / 夜屋顶生存关也能直接指向同一张图。
  几何抄自 `map_roof`（抄完就是副本，日后改一边会漂移）：探针里加了逐行比对，漂移立刻炸出来。
- **`GameBg` 直接加成员，而不是复用 `Roof`** —— 原版 Night Roof 是独立第 6 场景
  （[Night_Roof](https://plantsvszombies.wiki.gg/wiki/Night_Roof)），
  `GameBGM.Boss` 也早有自己的成员，背景跟 BGM 用同一套口径，后来者不会歧义。
- **顺便修了传送带关卡死（顺手做，但必要）** —— 不改的话 5-10 永远停在选卡阶段，
  地图再对也没法实测；详见「踩坑」第 1 条。

## 踩坑

1. **5-10 进不去战斗：停在 `main_game_progress = 1`（CHOOSE_CARD）**
   → 现象：无头跑进 5-10，`main_game_progress` 一直是 1，stdout 报
   `Invalid call. Nonexistent function 'move_card_slot_battle' in base 'Nil'`
   （`card_manager.gd:120` ← `enter_choose_card_progress` ← 时间轴「选卡」事件）。
   → 原因：**不是本次改动引入的**。传送带关（card_mode = 2）没有普通卡槽，
   `CardManager.card_slot_norm` 是 `null`，但它的**固化时间轴**上带了一条「选卡」事件
   —— 那条固化轴按「未跑 `init_para()`」的默认轴生成（那时 `can_choosed_card` 还是默认 true），
   而运行时 `init_para()` 会把它压成 false，于是 `is_no_choose_permission()` 命中不了任何一条，
   直接去操作不存在的普通卡槽。**全仓库 7 个关卡受影响**：
   1-10 / 2-10 / 3-10 / 4-10 / 5-5 / 5-10 + 迷你游戏 `minigame_05_column`。
   → **正解**：两条一起改（改一条只会换个地方崩）
   ① `ResourceLevelData.is_no_choose_permission()` 增加第 0 条：`not can_choosed_card` 即视为没有选卡权；
   ② `CardManager.card_slot_disappear_choose()` 判 `card_slot_norm == null` 直接返回
   （跳过选卡那条路最后要收待选卡槽，不判空会崩在 `choose_card_finish()`）。
   → 验证：改完 1-10 / 2-10 / 5-10 都能在 ~10 秒内进到 `MAIN_GAME`，无脚本错误。
2. **`MainGameHome.door_downs` / `door_masks` 的下标与 `GameBg` 枚举一一对应**
   → 现象：给 `GameBg` 加了 `Boss`(下标 5) 后，其它 5 份背景子场景**没有**
   `Background6GameoverMask` 节点，`@onready` 数组里直接 `$Door/DoorMask/Background6GameoverMask`
   会在每张图上报错；不补又会让 `door_masks[5]` 取越界。
   → **正解**：新增的那一项用 `get_node_or_null(...) as Sprite2D` 取（取不到就是 null），
   `init_home()` 里先判下标范围、再 `is_instance_valid` 后才 `.visible`。
   → 这条已经写进 [地图实现.md](../参考存档/地图实现.md#232-夜屋顶僵王关的底图与背景子场景)，
   后来者加第 7 张背景时按同款写法补。
3. **探针初版断言写错（不是地图的问题）**
   → 现象：`slope.all_slopes.size()` 断言 5，实机给 1。
   → 原因：`RoofSlope` 下只有 **1 个** `slope.tscn` 实例，5 条行碰撞区 `Area2DReal`
   在实例内部的 `SlopeReal` 下（等同白天屋顶，`probe_map_analysis` 里也是 1）。
   → **正解**：断言改成「有 slope 实例 + `SlopeReal` 下 5 个 children + `get_all_slope_y(x)` 能取到有限值」。
   → 教训：**写探针前先跑 `probe_map_analysis` 抄一遍真实数值**，别凭注释里的「5 行」想当然。
4. **既有探针 `probe_card_lock` 有 3 条 NG**（商店 9 个商品实为 13、第 2 页两个容器断言）
   → 与本次改动无关：NG 全在商店段（`PlantCardGoodsContainer` 现在除了紫卡还手摆了卡槽 /
   钉耙 / 水路小推车 / 屋顶小推车），且报 `Invalid access to property or key '999'` 的位置是
   `goods_plant_card.gd` 的售价表。动的是选卡逻辑，没碰商店。
   时间留给后来者：**要把该探针的商店段期待值更新到现在的样子**。

## 验证方式

无头探针全绿（本次）：
`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_boss_map`
→ `[BOSSMAP] result=PASS failed=0`（5-10 于 ~11 秒进到 MAIN_GAME）。
另跑了 `probe_timeline_data`（全 PASS，固化轴没漂）、`probe_timeline` / `probe_4_5` 无 NG。

**人工肉眼验收方法**（可选，本次没做）：跑
`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Windowed`
后从选关界面进冒险 5-10，确认：① 场地是**夜色**屋顶（不是白天屋顶）；② 5 行 9 列、
开局每行左侧有屋顶清洁车；③ 开局有 4 列预置花盆；④ 传送带在跑、BGM 是 Brainiac Maniac；
⑤ 僵尸进场时会顺着屋顶斜面（斜線）走，平移后在屋檐上稳定停住。前四条看到即为通过。

## 给后来者的最简路径

1. 全仓库搜要做的东西是不是已经有美术 / 场景躺好了（本次 `background6boss.jpg` + `zombie_boss.tscn`）。
2. 用 PowerShell / 任何看图手段确认**新底图与目标旧底图尺寸一致** —— 一致就整份抄 `.tres`，0 改坐标。
3. 抄 `data/map/map_<最接近的>.tres` → 改 `game_sences` / `display_name` / `map_bg_scene`。
4. 抄 `src/world/background/main_game_bg_<同上>.tscn` → 换贴图 + 补新的 `backgroundN_gameover_mask` 节点。
5. 动 `GameBg` 就**必须**同步 `MainGameHome.door_downs` / `door_masks`（用 `get_node_or_null`）。
6. `MainSceneRegistry` 补两处（MainScenesMap 仍指向唯一主游戏场景、DEFAULT_MAP_PATHS 指新图）。
7. 关卡 `.tres` 改 `game_sences` / `game_BG` / `game_BGM`。
8. 写探针：静态比一遍「新图 vs 抄的那张图」，再实机进一次关；先跑 `probe_map_analysis` 抄真实数值。

> **索引推荐度**：**推荐**（未改）

- **补充**：本记录第 4 步「`MainSceneRegistry.MainScenes` 加 `MainGameBoss`、补 `DEFAULT_MAP_PATHS`」
  这一步**已被撤销**。理由：三个主游戏槽位（`MainGameFront` / `MainGameBack` / `MainGameRoof`）
  在 `MainScenesMap` 里指向的是**同一个** `main_game_base.tscn`，为 1-1 / 1-2 / 1-3 / 5-10 单开的
  `MainGameFront1Row` / `MainGameFront5Row` / `MainGameBoss` 只为「选一张不同的地图」而存在 ——
  等于把关卡差异顶到了全局枚举上。现在地图由关卡自己的 `map_data` 指定
  （`adventure_05_10.gd` 里 `map_data = preload(".../map_boss.tres")`），
  `game_sences` 回落到 `MainGameRoof`，只负责「加载哪份主游戏场景」。
- **踩坑**：`data/map/*.tres` 里的 `game_sences` 存的是**枚举的整数值**
  （`map_boss.tres` 是 `5`、`map_front_5row.tres` 是 `4`）。删枚举名不会让 Godot 报错，
  但这些数字会变成**孤儿值**（枚举里已无对应成员），只能靠肉眼看出来。删枚举必须同步把
  `.tres` 里的数字改成它实际配套的那个槽位（`map_boss`→`2`、两张 front 图→`0`）。
- **评价**：**本文件的第 1~3、5~6 步依然成立**（夜屋顶三件套、关卡的 `game_BG`/`game_BGM` 开关、
  探针的逐行几何比对都照旧），只有「往场景枚举里加成员」这一步不要再照做。
- **更省的做法**：新加一张专用地图时，**只写 `.tres` + 让关卡 `preload` 它**，两步就够，
  不必动 `MainSceneRegistry` 的任何一张表。
