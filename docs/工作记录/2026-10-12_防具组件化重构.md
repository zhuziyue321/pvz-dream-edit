# 2026-10-12 · 新增组件 · 防具改成组件：可多层、同类可叠加、效果由防具自己定义

> **任务类型**：新增组件
> **推荐度**：**推荐**（下次要做「某个东西从宿主的固定字段变成可挂多个的组件」照这个走）
> **耗时与成本**：约 3 轮对话，未开游戏（门禁 PASS 0 error + 无头 `probe_armor_component` PASS failed=0，画面需人工看一眼）
> **验证方式**：免验证 + 已给出人工验证方法（见文末）
> **补充自**：无

## 目标

把防具从「`HpComponentZombie` 上两个固定槽位（`max_hp_armor1/2`）+ `HpStageChangeComponent` 上两个换皮数组」
重写成组件，并满足三条：

1. 防具是一个组件（一个角色可以挂多层）；
2. **同类防具可以叠加**（同一个僵尸戴两个路障）；
3. **防具存在时可以带特殊效果**（铁门挡减速、气球浮空、报纸破防暴走…），且效果由防具组件自己定义。

## 步骤

   `judge_body_change_armor` / `signal_armorX_death`），列出要迁移的 22 个 `.tscn` 与 10 处 `.gd`。

   再写气球 / 报纸 / 头顶植物三个子类承载效果。

   所有 `ArmorComponent`** 并排序，`hp_loss()` 遍历它们。

## 关键决策与理由

- **组件自己向宿主注册 vs 宿主收集组件** → 选**宿主收集**（`owner.get_children()` 里筛 `ArmorComponent`）。
  因为 Godot 先跑子节点 `_ready()` 再跑父节点，若让防具在 `component_ready()` 里调
  `owner.hp_component.register(self)`，宿主的 `@onready` 此刻还是 `null`，**连接/注册静默失败**
  （这正是旧 `ZombiePlantComponent` 踩过的坑）。宿主收集则没有任何时序依赖。
- **同类叠加的先后** → 用 `absorb_priority`（数值越大越外层、先挨打），而不是靠节点顺序。
  节点顺序在编辑器里拖一下就变了，不该当语义用。
- **六种伤害模式的行为** → **逐条原样翻译**，不做任何"顺带修正"。
  `Penetration` 的二类防具"照扣但不消耗伤害"、`BowlingSide` 二类"扣 1800 再传 1800"这些不对称行为
  看着别扭但是原版口径，改成"统一"就是行为漂移。
- **`IronType` 枚举** → 保留 `Null` / `IronItem`，把 `IronItem` **显式写成 3**，
  这样存量 `.tscn` 里存的 `iron_type = 3` 继续有效；防具类铁器移到 `ArmorComponent.iron_node`。
- **打掉一层防具** → 新增 `HpComponentZombie.break_armor()`，用「从最外层到目标层的血量之和」当伤害值
  走一次 `Norm`，靠溢出规则刚好扣光那几层。不用新增 `DamageMode`（新增模式要同步两处，漏一处静默不掉血）。

## 踩坑

1. **新脚本没有 `uid`，`.tscn` 的 `ext_resource` 该怎么写** → Godot 的 uid 由编辑器生成，手写不出来 →
   **正解**：`[ext_resource type="Script" path="res://..." id="9_armor"]` **不写 `uid=`**。
   仓库里已有 230 条这样的条目，Godot 按路径解析得很好，编辑器下次保存会自己补上 uid。
2. **Node 类型 `@export` 的路径是相对本节点解析的** → 铁器节点从根节点搬到防具节点后，
   `NodePath("Body/BodyCorrect/IronNode")` 就找不到（防具是根的直接子节点）→
   **正解**：写成 `NodePath("../Body/BodyCorrect/IronNode")`。
   同款坑见 [M-06](../参考存档/规范细则存档.md#m-06-跨节点的引用export-节点类型在手写-tscn-里解析不到)。
3. **`get_all_hp()` 没写返回类型** → 调用处 `var ori_hp := get_all_hp()` 报
   *Value of type Variant cannot be assigned* → **正解**：调用处显式标注 `var ori_hp: int = ...`。
4. **探针在关卡之外实例化僵尸打伤害** → 防具破损掉落要挂 `zombie_manager`，关卡之外报 `Nil`，
   而 `run_all_scenarios.ps1` 见到 `SCRIPT ERROR` 会判 ERROR → **正解**：探针**先进一个普通白天关**
   （只为拿到 `zombie_manager`），再打伤害。注意本体掉手那条路同样如此，不是防具引入的问题。
   顺手把 `Zombie000Base.ready_norm()` 里 `get_main_game().main_game_slope` 加了空挡。
5. **PowerShell 批量改 `.tscn` 时混着 CRLF** → 14 个植物僵尸里 `zombie_tall_nut.tscn` 是 CRLF，
   脚本按 LF 匹配直接 MISS → **正解**：脚本报 MISS 的文件手工改，不要盲信脚本的 OK 数量。
6. **`AttackComponentBase` 上没有 `E_AttackValueFactor`** → 它在 `AttackComponentZombieNorm` 上 →
   **正解**：报纸破防提速那里写 `AttackComponentZombieNorm.E_AttackValueFactor.Speed`。

## 给后来者的最简路径

1. **枚举**放 `src/core/consts/`，**组件**放 `src/entities/character/components/<名字>_component/`。
2. 宿主侧**收集**组件（`owner.get_children()` 里筛类型），别让组件反向注册 —— 时序会静默失败。
3. 需要"多个同类"时给它一个 `priority` 字段决定先后，不要靠节点顺序。
4. 组件的"效果"用**可重写的钩子**（`on_x_equip()` / `on_x_break()` / `is_immune_*()`），
   宿主只做只读转发，本体不认识任何具体类型。
5. 迁移存量场景：同类整齐的用一次性脚本批量改（改完**抽查两个 + 看脚本报没报 MISS**），
   结构各异的手工改。
6. 收尾必跑：`check_scripts.ps1` + 一个专门的 `probe_*`，并把机制说明写成 `docs/参考存档/<主题>.md`。

## 人工验证方法（未开游戏，画面部分需人工看一眼）

1. 进冒险 1-5 之类有路障 / 铁桶的关：路障被打掉应有掉落物、僵尸血条上那一类防具的条归零后隐藏。
2. 报纸僵尸：报纸打掉后应提速 + 播怒吼，且掉报纸。
3. 铁门僵尸：寒冰豌豆打上去**不减速**（二类防具挡减速）；铁门掉了之后会被减速。
4. 气球僵尸：气球破了落地；磁力菇放到铁桶 / 铁门 / 梯子上应把铁器吸走。
5. 植物僵尸（迷你游戏第 1 关）：头顶植物打掉后消失，僵尸变回普通僵尸。
