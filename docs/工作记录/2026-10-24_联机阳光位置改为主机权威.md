# 2026-10-24 · 联机阳光位置改为主机权威（每一颗的位置都逐帧抄主机）

## 1. 起点：位置其实**已经在传**了，缺的是"客户端肯采纳"

用户的要求是"联机时阳光的同步，传每一个阳光的位置"。动手前先测绘，发现位置同步**早就有**：

- 第二包快照带 `s_id / s_value / s_x / s_y`（`netplay_state_sync.gd` 的 `collect_snapshot_extra`），
  主机每帧把**每一颗**阳光的坐标都发出去；
- 客户端 `_align_suns()` 按 `entity_id` 对齐，位置覆盖。

真正没做到"每一个"的是**客户端这一侧**：`_align_suns()` 里有一条**刻意的跳过** ——
"正在跑下落 tween 的那颗不要覆盖位置"（早先的 `_is_sun_falling()`）。

为什么当初要跳？因为客户端那颗阳光是**自己重放**的：命令通道下发"起点 / 落点 / 时长"，
客户端照着起一遍 tween（`SunSpawner.replay_fall()`）。快照每帧吸附会跟这条 tween 打架
（tween 每帧写位置、快照也每帧写位置 ⇒ 抖成两处）。

⇒ 于是形成了一个**两头不讨好**的局面：位置虽然每帧都在传，但**下落那一段客户端不采纳**；
而客户端自己重放的那条时间轴是**从收到命令那一刻**开始的，比主机晚整整一个 RTT ——
落点对得上，过程对不上。

## 2. 做法：位置一律以主机为准，客户端不再自己演那一下

| 改动 | 文件 |
|---|---|
| 位置覆盖**不再跳过任何一颗**（含正在下落的） | `mods_builtin/netplay/netplay_state_sync.gd`（`_align_suns`） |
| 客户端**不再重放那一下下落**（`SunSpawner.replay_fall()` 随之删除，本体少一个没有调用方的死函数） | `mods_builtin/netplay/netplay_sun_sync.gd` / `src/items/drop/sun_spawner.gd` |
| 自动收集的"落地那一刻"改由**位置到达落点**来判 | `netplay_state_sync.gd`（`_check_sun_landed`） |

`_check_sun_landed()` 的要点：

- 判据是 `position.distance_to(spawn_target) <= 2px`（落点由命令里的 `ARG_TO` 带下来）；
- **一颗只判一次**（`meta` 记着）—— `on_sun_tween_finished()` 里会 `request_pick()`，
  判两遍就把拾取流程走两遍；
- `spawn_target == ZERO` 的不判（快照补种出来的那种没有落点）。

落点判定放在 `_align_suns()` 里：那里已经在逐颗遍历并写位置，顺手判一次，不额外扫场。

> 顺带修掉的**既有隐患**（同一处代码，逻辑上必须一起改）：
> 客户端不再有 tween ⇒ `finished` 回调没了 ⇒ 自动收集（`Sun.on_sun_tween_finished()`）
> 在客户端永远不会触发 ⇒ **开着"自动收集阳光"的客户端会一直不捡**。
> 落点判定就是补这一刀（收不收仍由本体自己判，模组只负责"通知它落地了"）。

## 3. 踩坑

- **`has_method()` 查静态函数恒为 false** —— `SunSpawner.replay_fall()` 是**静态**函数，
  `Object.has_method()` 只查实例方法表 ⇒ 断言会**永远通过**（假绿）。
  → 改查源码：`FileAccess.get_file_as_string("res://src/items/drop/sun_spawner.gd").contains("replay_fall")`。
- **`run_autopilot.ps1` 会在有别的 Godot 实例在跑时直接拒绝**（`result=STALE_PROCESS`）——
  它用**固定**的输出文件路径，别的实例占着就可能读到别人的报告。
  脚本自己明确说了"**不要** `-KillStale`，那可能是用户开着编辑器"。
  → 绕法：照它的命令行手跑一份，把 `APPDATA` 与输出文件都指到**自己的**临时目录。
- **`run_netplay_pair.ps1` 默认的 Godot 路径在本机不存在**（`Godot_v4.6.2-stable_win64.exe`，
  真实的是 `godot.exe`）→ 必须带 `-Godot "C:\Users\a a\Desktop\godot.exe"`，否则静默跑不起来。
- **双进程对拍比的是阳光的*编号*，不是位置** —— 位置对拍在局域网下也区分不出改动前后
  （RTT 差 × 下落速度都只有零点几个像素）。所以这一刀的双进程价值是**回归确认**，
  真正的判据得靠人工看两端画面。

## 4. 还没做的（同一条路上的剩余项）

- **客户端自己长的阳光仍然不同步**（没有主机编号 ⇒ 主机那一局上不存在它 ⇒ 位置无从下发）。
  它现在还会被快照的缺席回收在 30 帧后删掉（本地老路 vs 快照名册打架）。
- **被字节预算截断、排在名册后面的阳光永远采不到位置**（没有僵尸那样的 `_z_cursor` 轮转采集）——
  它们在客户端会僵在原地。
- **快照补种出来的阳光没有落点**（快照里没有落点字段）⇒ 自动收集对它不触发。

## 5. 验证

- 单进程探针 `probe_netplay_session` PASS（`[NETPLAY] result=PASS failed=0`），
  新增 4 条断言**确认真的执行了**（日志里能看到 `[OK]`）：
  客户端不再自己重放下落 / 位置到落点=落地 / 没到落点不算落地 / 一颗只判一次。
- 双进程 `run_netplay_pair.ps1` PASS：
  `HOST: reports=30 transient=3 persistent=0 phantom=0 sun_match=true`、
  `CLIENT: snapshots=3682 render_only_bad=0`。
- ⚠️ **仍未开游戏**（用户手上有三个 Godot 实例在跑，没有抢它们的窗口）。
  人工验证方法见 [../参考存档/联机模组.md](../参考存档/联机模组.md) §四 验收清单第 4 条：

  **两端同时看一颗正在下落的阳光，它应当始终在同一个像素位置**（改动前差半个 RTT 的位移）；
  客户端开着"自动收集阳光"时，那颗落地后应当照旧被收走（两端一起没）。

## 6. 补充 / 第二刀（2026-10-24 同一天）：上一节那三条遗留全处理

> 与上面同一主题，按「补充不新建文件」的约定追加在这里。
> §4 列的三条遗留（客户端自长的不同步 / 截断后排着的采不到 / 补种的没有落点）这一刀全部收掉。

### 6.1 三条各自的解法

| 遗留 | 解法 |
|---|---|
| 客户端自己长的那颗不同步、还会被快照**凭空删掉** | 客户端发现它 ⇒ **删掉本地那颗** + 上行新命令 `sun_claim` ⇒ 主机照同样的数据也长一颗 ⇒ 两端一致 |
| 被字节预算截断、排在名册后面的那些**永远采不到位置** | 阳光采集改成**轮转**（`_s_cursor`，与僵尸同一套），每颗最多隔 `ceil(总数 / s_cap)` 帧必被采到一次 |
| 快照补种出来的那颗**没有落点** ⇒ 自动收集对它不触发 | "快照先到、命令后到"时，命令到达处**补写落点 / 用时**（落点是落地判定的依据） |

### 6.2 最难的一处：**不能拿编号认"主机给的"**

两端的 `entity_id` 是**各自独立自增**的 ⇒ 同一颗阳光在两端拿到的本地编号**往往相同** ⇒
"客户端自己长的那颗"与"主机的某一颗"编号撞上 ⇒ 拿编号根本分不开（我第一版就是这么想的，
写到一半发现不对）。

⇒ 改用**实例级标记**：主机给的阳光（命令下发的 / 快照补种的）都打 `META_SUN_FROM_HOST`；
客户端每帧扫一遍，**没打标记的**才是"自己长的"。

⚠️ 两条防线（判错就是**误删主机的阳光** ⇒ 两端直接对不上）：

1. **名册还没到**（第一包快照之前）⇒ 一律不判断（否则把主机下发的全当成"自长的"）；
2. **名册被截断**（`s_cut`）⇒ 一律不判断（名册不完整 ⇒ "这帧没采到"≠"主机没有"）。

### 6.3 客户端自长的那颗：初版"删了重建"会闪 ⇒ 第三刀改成"原地改编号"

初版做法是「**删掉本地那颗** + 请主机长一颗，等主机的下发到了再新建」——
玩家看到的是那颗阳光**闪一下**（出现 → 消失 → 一个 RTT 后再出现）。

⇒ 第三刀改成**原地改编号**：

| 环节 | 做法 |
|---|---|
| 客户端发现 | 上行 `sun_claim` 时带上**自己的本地编号**（`ARG_SUN_SRC_ID`）；本地那颗先换成**临时编号** `PENDING_SUN_ID`（主机永远不会发这个号 ⇒ 不会与主机名册撞上）并打「等认领」标记 ⇒ **不进对齐视野**（不被快照覆盖位置、不被缺席回收删掉） |
| 主机 | 照数据长一颗 ⇒ **回填它那颗的编号进命令**（`args` 是**引用** ⇒ `handle_local_command()` 广播的就是改过的那份）⇒ 打「认领来的」标记 ⇒ **事件路径不再单独下发**（命令已带全，再发一遍标准 `sun_spawn` 会让客户端同编号长出两颗） |
| 客户端 | 收到认领命令 ⇒ 按本地编号找到那一颗 ⇒ **原地改成主机的编号** + 补落点 / 用时 + **收掉本地那一下下落**（位置从此归快照管，不收就是两个东西抢同一个位置 ⇒ 抖）⇒ **屏幕上自始至终是同一颗** |
| 房里的其它客户端 | 本地没有那一颗 ⇒ **新建**（数据都在命令里） |

⚠️ **临时编号这一手是必须的**：两端 `entity_id` 各自独立自增，同一颗在两端编号往往**相同** ⇒
客户端自长那颗若还顶着本地编号，会被主机的同号那颗"串位"（位置被覆盖 ⇒ 阳光瞬移到别处）；
换成主机不会发的临时编号就躲开了。

⚠️ 认领那一刻的**中间态**：客户端会短暂多一颗（主机名册里的同号那颗在客户端补种出来）——
局域网几乎无感（一个 RTT 内收敛），互联网约 50ms。

⚠️ **上行不带编号 = 客户端只能删了重建 = 闪一下**；带上了（并且主机**回填**编号）才谈得上"原地改"。

### 6.4 踩坑

- **`has_method()` 查静态函数恒为 false** —— `SunSpawner.spawn_at()` 是静态的，
  `Object.has_method()` 只查实例方法表 ⇒ 断言会永远通过（假绿）⇒ 改查源码。
- **`netplay_command.gd` 没有 `class_name`** —— 模组可能被搬到 `user://` 下（实测 Godot 4.6.2
  不注册成全局类）⇒ `netplay_state_sync.gd` 里引用它的常量必须 `preload`。
- **门禁的第二道会被占用的输出文件挡住** ⇒ 脚本照样打印 `result=PASS`，但那第二道
  **根本没跑完**（工作记录里早就记过"不能只看门禁的 PASS"）⇒ 用独立临时目录手跑那一道。

  「请主机长一颗」认得出操作名 / 带得回落点与用时 /「主机给的」是实例级标记 / 本体有"照数据长一颗"的入口。
