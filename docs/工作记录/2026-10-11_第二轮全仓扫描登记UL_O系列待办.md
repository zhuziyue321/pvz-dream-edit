## 关键决策与理由

- **只登记不改代码** —— 31 条里 A 档（会致数据/行为不一致）有 4 条、B 档（违反硬约束）5 条，
  每条的整改都要开游戏或跑探针，混在一轮里做等于每条都做不干净；先落清单，后续按档位排期。
- **编号分三个系列**（`U-` 不统一 / `L-` 逻辑不全 / `O-` 可优化）——「不统一」和「没接完」是两种病：
  前者要**选一个真相源**，后者要**补完或删掉**。混在一张表里，整改时容易把「死事件」当成「两套写法」去合并。
- **给子代理带上「已销项清单」** —— 第一轮 U 系列扫完已把 13 条移进 §4；不告诉子代理就会把 `Global.main_game`、
  `SoundManager` 那几条又报一遍，白白占掉输出预算。

## 踩坑

1. **子代理会报「看起来很像 bug」的误报，必须回读原文件**
   - ~~`reminder_information.gd:15-18` 的 `queue_free()` 写在 for 循环体内、第 2 条及以后永远不显示~~

   - ~~`garden_item_02/03/04_*.gd` 三个文件是空的 → 肥料/杀虫剂/留声机买了没效果~~
     → 回读 `garden_item_plant_need_base.gd:20` 发现基类 `use_it()` 是**完整通用实现**，空子类是有意的；整条删除。
2. **`docs/TODO清单.md` 在扫描期间被改过** —— 我第一次读到的版本 U-09~U-13 还在表里，
   第二次读时它们已被移到 §4（同仓多 agent 协作，见 [Agent协作协议.md](../Agent协作协议.md)）。
   → **正解**：编辑前重新 `read_file`，别拿上一轮的快照当 `old_str`。
3. **`uid://` 不能拿全仓 grep 的结果直接下结论** —— 886 处命中里 99% 是 `*.gd.uid` 文件本身和 `.tscn` 里的合法引用。
   → **正解**：`uid://` 体检要加 `glob *.gd`，且只算**字面量**（本轮结论：`.gd` 层面 0 处违规，唯一命中是 `sound_manager.gd:337` 的注释）。
4. **"定义了没人读"不能只看声明处没命中** —— `WIN_MAIN_GAME` 在 `const_event_name.gd` 里有常量 + payload 签名 + 订阅方，
   唯独没有 `push_event`。→ **正解**：这类要**分开搜发布点与订阅点**再比命中数（已写进 §5 的体检口径）。
