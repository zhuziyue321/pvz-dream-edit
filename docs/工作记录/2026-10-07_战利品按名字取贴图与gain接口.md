# 2026-10-07 · 其它 · 战利品按名字取贴图生产，关卡脚本 `await gain("taco")` 一条龙收尾

> **任务类型**：其它
> **推荐度**：**推荐**（加一种战利品 = 注册表加一行，本体不动）
> **耗时与成本**：约 1 轮，带窗口跑了 3 个探针（编译门禁 PASS）
> **验证方式**：打开游戏实测（带窗口探针 `probe_slot_machine` / `probe_adventure_reward` / `probe_hammer_zombie` 全 PASS）
> **补充自**：[2026-10-03_通关种子包对齐卡片并改僵尸掉落.md](2026-10-03_通关种子包对齐卡片并改僵尸掉落.md)（共用「掉落物 + 收尾表演」那条线）

## 目标

1. 提供一个「**战利品名字 -> 贴图 -> 生产一个掉落物**」的函数（`trophy` / `peashooter_seed_packet` / `taco`）；
2. 用它**重写关卡结束掉奖杯的逻辑**（奖杯不再是独立场景）；
3. 关卡脚本里一句 `await gain("taco")` 就能掉出这个战利品，玩家点开 -> 播收尾动画 -> 切场景。

## 步骤

1. 摸清旧线：`MgmRewardManager._spawn_trophy()` 实例化 `trophy.tscn`（`Trophy.gd` 自己播光芒/辉光 5 秒，
   再推 `WIN_MAIN_GAME` 结算）；而 4-4 的玉米卷走的是 `Present` + `icon_texture` + `is_level_complete_drop`
   -> `CanvasLayerWhiteScreen` 播「居中 -> 发光 -> 白屏」-> `LEVEL_COMPLETE_PICKUP_FINISHED` -> 结算。
   **两条线做的事一样**，只是掉落物不同 —— 于是统一成后者。
2. 新增 `src/items/drop/loot_registry.gd`（`LootRegistry`）：名字 -> 贴图 / 植物编号 / 音效三张表
   （硬约束 §1-4：类型映射走注册表；种子包类没有现成贴图，登记的是 `CharacterRegistry.PlantType`）。
3. `DropItemManager.create_loot_drop(名字, 位置, 提示)`：贴图类 -> `Present` 换贴图，种子包类 -> `SeedPacket`；
   顺手给 `Present` 加两个开关（`is_show_open_tip` / `open_sfx`）—— 奖杯没文案、要播 `winmusic`。
4. `MgmRewardManager` 加 `gain(名字, 位置)` / `gain_loot(名字, 位置)`：生产 -> 标记 `is_level_complete_drop`
   -> 等点开 -> 等收尾表演 -> `win_main_game()`；`_spawn_trophy()` 退化成 `gain_loot("trophy", …)`。
5. `LevelScriptBase.gain(名字)` 转发过去；`win_with_trophy()` 里改成 `await _spawn_trophy()`。
6. 删掉 `src/items/trophy.tscn` + `src/ui/main_game_ui/trophy.gd`（含 `.uid`）与 `SceneRegistry.TROPHY`。
7. 改 4 个探针（见踩坑 2）。

## 关键决策与理由

- **不新建「战利品场景」**：`Present` 本来就有「换贴图 + 点击区按贴图重算 + 呼吸光 + 超时自毁 +
  `is_level_complete_drop`」全套，4-4 的玉米卷已经在这条线上跑通了，直接复用比再造一个 `.tscn` 稳。
- **种子包类单独一档**：全仓库没有「豌豆射手种子包」这张独立贴图（种子包是卡片底图 + 植物形象
  运行时拼的，见 `SeedPacket.set_plant`），所以注册表里登记植物编号，交给 `DIM_SeedPacket` 现拼。
- **掉落物建不出来就直接结算**：`gain_loot()` 里 `create_loot_drop()` 返回 null 时不重试、
  直接 `win_main_game()` —— 少看一次表演远好过把玩家一直卡在场上。
- **奖杯保留抛掷**：`throw_to()` 只对 `Present` 类战利品用（种子包自己有 `launch()` 抛物线）。

## 踩坑

1. **翻车点：断言「重打不再掉奖励」用掉了的数量差** —— 奖杯原来掉在 `canvas_layer_temp`，
   现在与奖励掉在**同一个容器**（`all_drop_garden_plant_parent`），数量差必然 +1。
   → **正解**：按**类型 / 贴图**分辨（`is SeedPacket` / `icon_texture.resource_path`），不要数个数。
2. **探针里的 `Trophy` 类引用会编译失败** —— `probe_slot_machine` / `probe_hammer_zombie` 里
   `c is Trophy`、`TrophyButton` 都指着删掉的脚本。
   → **正解**：改成找「`is_level_complete_drop` 为真」的那个掉落物（通用、不认具体类名），
   点击用它自己的 `global_position`（掉落层不受相机画布变换影响，与旧的 `Trophy` 一致）。
3. **点开掉落物后 2 秒它还在树上** —— 收尾表演（居中 1.2s + 发光 1.6s + 白屏 1.5s）跑完才 `queue_free`。
   → **正解**：探针判「已被拾取」看 `is_opened`，不要看 `is_queued_for_deletion()`。
4. **遗留（本次未修，既有漂移）**：`probe_car_key` 前三条仍 NG —— 它读的是 `drop_unlock_*`，
   而 3-4 的声明早就搬到 `level_complete_drop_*` 了（见 [2026-10-07_关卡胜利条件改为流程跑完.md](2026-10-07_关卡胜利条件改为流程跑完.md)）。

## 给后来者的最简路径

1. 加一种战利品：`src/items/drop/loot_registry.gd` 加一行 —— 贴图类进 `TEXTURE_MAP`
   （要提示就再进 `TIP_MAP`），种子包类进 `PLANT_SEED_PACKET_MAP`。
2. 关卡脚本掉它：`run_flow()` 最后一句写 `await gain("名字")`（要 `await`，且后面不要再写流程）。
3. 验：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_slot_machine -Windowed`。

## 补充（同日第二轮）：50 关全部改走 `gain()`，旧字段 `level_complete_drop_*` 全删

> 上一轮只造了 `gain()`，还没有任何关卡用它 —— 冒险 50 关仍靠 `_init()` 里的
> `level_complete_drop_plant` / `_tip` / `_icon` 三个字段声明「本关掉什么」。这一轮把它们全清掉。

### 改法

- 三个字段合并成**一个字符串字段** `level_complete_loot`（战利品名字），`_init()` 里一行：
  `level_complete_loot = "shovel"` / `"sunflower_seed_packet"` / `LootRegistry.TROPHY`（本关没奖励）。
- `run_flow()` 末尾统一成：
  ```gdscript
  	if is_curr_level_success():
  		win_with_trophy_only()          ## 已通关过：只出奖杯
  	else:
  		await gain(level_complete_loot) ## 首次通关：掉本关战利品，掉完直接结算切场景
  ```
  没有奖励的 6 关（1-9 / 2-9 / 3-9 / 4-9 / 5-9 / 5-10）写 `await gain(LootRegistry.TROPHY)`。
- 删：`MgmRewardManager.drop_adventure_reward_on_level_complete()` + `is_adventure_reward_drop_done`、
  `DropItemManager.create_adventure_reward_drop()` / `_create_reward_seed_packet()`；
  `win_with_trophy()` / `win_with_item()` 不再管「本关奖励」，只剩解锁道具 + 奖杯兜底。
- 「本关解锁哪株植物」的答案源没变（还是关卡脚本自己声明），只是从植物编号换成战利品名字：
  `LevelRegistry.get_adventure_level_reward_plant()` -> `LootRegistry.get_plant_type(level_complete_loot)`。

### 踩坑（这一轮新增）

5. **`level_complete_loot` 不能删**：`LevelRegistry.get_adventure_level_reward_plant()`（解锁植物）
   和**选关界面第 2 页的「本关看点」图标**都要按关卡序号反查「本关给什么」，
   而 `run_flow()` 里的 `await gain(...)` 是代码、查不到 —— 所以本关掉什么必须留在 `_init()` 的字段上。
   删掉的只是「怎么把这个掉落物造出来」那三个字段（贴图 / 提示 / 植物编号），那一层归 `LootRegistry`。
6. **多轮关卡要给 `gain()` 加轮次守卫**：`win_on_level_complete()` 有「还有下一轮就先切轮」的判据，
   `gain()` 原本没有 —— 已补上（`mg.curr_game_round != game_para.game_round` 直接返回）。
7. **批量改 53 个脚本要用带 BOM 的 ps1**：PowerShell 5.1 读无 BOM 的 UTF-8 脚本会把中文当 ANSI，
   中文字符串直接把解析器搞崩（`Missing ')'`）。先 `UTF8Encoding($true)` 转一份 BOM 副本再跑。
   `Get-ChildItem -LiteralPath` 不吃通配符，批量要用 `-Path`。
8. **「切场景后 run_flow 的协程会不会炸」实测**：在 `main_game` 下挂一个临时节点，
   起一条 `await gain(...)` 之后再干活的协程 —— 场景切走后协程**正常醒过来**，没有 "previously freed"
   报错（`change_scene` 是延迟到帧末执行的，`run_flow` 返回后那几行同步代码还在有效对象上跑）。
9. **`probe_night` 有 6 条既有 NG**（波数口径漂移，与本次无关）；本次改到的
   `probe_adventure_drop_source` / `probe_adventure_reward` / `probe_car_key` /
   `probe_level_complete_fx` 全 PASS —— 后三个靠 `create_trophy` 触发奖励的那套已经不通了，
   改成 `reward_manager.gain(game_para.level_complete_loot, 位置)`。
