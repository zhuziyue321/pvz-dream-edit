## 目标

修复「僵尸博士在一次低头期间，20 个投手 + 2 个辣椒只造成 78 点伤害」的异常，并留下可复跑的回归探针。

## 步骤

1. 先确认僵王生命值是 40000 / 60000 且 `HpComponent` 没有任何减免 → **排除**「数值减伤 / 冷却 / 命中去重」（全文搜 `invincible|iframe|冷却|cooldown`，0 命中）。
2. 顺着「谁在调用 `be_attacked_bullet` / `be_jalapeno`」反查调用方，`be_jalapeno` 在 `src/` 里**只有定义没有调用者** —— 移植时漏了。
3. 拿参考快照 `PVZ-Godot-Dream_20261005_v1.3.0/` 做逐点对照（`docs/AI查wiki避坑.md` 口径的「同源仓库对照」，比猜快得多），定位三处漏项，见「关键决策」。
4. 修完先临时回退代码跑一遍探针，确认**修复前探针会 FAIL**，再恢复 —— 否则探针没有捕获能力，等于没写。

## 关键决策与理由

- **改 `_on_area_2d_attack_area_entered` 而不是给僵王补 `lane`** —— 僵王不加入 `all_zombies_2d` 任何一行，给它编一个假行号会让「普通僵尸的同行判定」和「火箭(ˇ)在屏幕上的表现」产生歧义；v1.3.0 的口径就是「僵王由空间碰撞决定」（`_can_attack_character()` 里 `enemy is ZB000Base` 分支直接 `return true`，绕开行号），照它来。
- **辣椒 / 寒冰菇这类「全场货」补在场 callers 上，不改检测链** —— 它们本来就是「管理器遍历存活僵王」的结构，缺的只是遍历那一行。
- **寒冰菇（`ice_all_zombie`）只报告、没动手改** —— 它会额外引发「僵王被冻结后技能暂停」的玩法口径问题，不属于本次「伤害异常」的范围，交给用户拍板（见「给后来者」）。

## 踩坑

1. **现象**：带行属性的子弹（豌豆 / 卷心菜 / 西瓜…）打僵王全部不掉血，只剩 `SpatterComponent` 溅射那一条路，且被 `clampi(..., 1, 13)` 压到单体最多 13 点 —— 这正是报告里那个奇怪的 78（≈ 6 × 13）。
   **原因**：`Character000Base.lane` 默认 `-1`，僵王从头到尾没有被赋过行号；而 `bullet_norm_base._on_area_2d_attack_area_entered` 里 `if lane == enemy.lane` 永远不成立 → 子弹发现自己和目标「不在同一行」，直接放行不打也不结算。
   **正解**：`if is_activate_lane and lane != enemy.lane and not enemy is ZB000Base: return`（与 `component_detect._judge_enemy_is_can_be_attack` 已有的僵王豁免口径一致）。
2. **现象**：探针第一次报 NG，日志却显示 `前/后=40000/39980`（其实已经掉了 20）。
   **原因**：命中过的子弹自己会 `queue_free()`，探针再 `bullet.queue_free()` 报 *previously freed*，**该错误会让协程的返回值丢成 null**，被 `var dealt: int =` 兜成 0。
   **正解**：收尾前 `if is_instance_valid(bullet)`；写探针时凡是「用完即弃」的对象都要这样。
3. **现象**：探针脚本一开始是 Parse Error。
   **原因**：`var boss := _wait_boss(a)` —— 被调用函数是协程必须 `await`，且无返回值类型的函数不能用 `:=` 推导。
   **正解**：`var boss = await _wait_boss(a)`。
4. **`probe_plant` 在本机会 FAIL**（报「种子包不足，跳过选卡阶段」）—— 是临时 `userdir` 里没解锁植物卡的**环境问题**，与本次改动无关；改用 `probe_portal_combat`（真打）做回归，PASS。

## 给后来者的最简路径

1. 怀疑「某次跨版本移植漏了东西」时：**先 grep 目标函数在本仓库有没有调用者**，再拿参考仓库做**逐点对照**—— 先用调用链缩小范围，比直接 diff 两份同名文件快得多。
2. 修完一定要做一次**回退对照**：临时还原 → 探针 FAIL → 还原回去 → 探针 PASS，这才能证明探针不是在走过场。
3. 回归：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss_damage -Windowed` → `[ZOMBOSSDAMAGE] result=PASS`。
4. **已知的同类遗漏（未修，待用户拍板）**：`ZombieManager.ice_all_zombie()` 同样缺「遍历 `get_living_bosses()` 调 `be_ice_freeze`」这一段，v1.3.0 里是有的 —— 修好后寒冰菇才会在受击窗口内对僵王造成 20 点伤害并冻结它。

### 关键决策

- **冰冻仍受受击窗口限制，不开后门** —— v1.3.0 的 `僵王说明文档.md` §2.2 写明「完全冰冻和火爆辣椒共用 `_can_receive_damage()`」，
  本仓库 `z_b_000_base.gd` 也是这条口径。玩家的正确用法是「趁低头冻住」，冻住时动作计时器停摆 → 低头窗口被延长 → 多打一轮，
  这本身就是原版寒冰菇打僵王的价值所在。
- **冰块位置只在基类改一处** —— 僵王没有自己的冰块逻辑，改基类同时修好所有角色的移植回归，不必在僵王侧特判。

### 踩坑

1. **僵王「被冻住」不等于「被打断」** —— 冻住是靠角色速度倍率 0 → `SpeedTimer` 原生 `paused` → 动作计时器停摆实现的；
   解除冰冻的计时器（`GlobalUtils.create_new_timer_once`）是**普通 Timer**，不接速度信号，所以零速期间它照常走完、
   不会把自己冻死（写僵王控制逻辑时凡是「解除控制用的计时器」都不能接 `signal_update_speed`）。
2. **`ice_effect = ice_effect` 这种自赋值是移植事故** —— 静态检查器早就删了，肉眼扫 `character_base.gd` 也不会报；
   发现方式是「拿 v1.3.0 同名函数逐行对照」，同一套排查法在本记录第 2 步已经用过一次，仍然有效。
