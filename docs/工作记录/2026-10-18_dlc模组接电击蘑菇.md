# 2026-10-18_dlc模组接电击蘑菇

> **本次任务**：照 DLC 导入那条流程，把 DLC 模组里的 `VoltShroom` 动画接成能种的植物 —— **电击蘑菇**（100 阳光 / 周围约 3×3 放电 AOE / 白天睡觉），含配方、卡面、图鉴、探针。
> **耗时 / 轮次**：若干轮；**开了游戏**：无（本会话有多个 Agent 在并发改同一 `dlc_mod.gd`，编译门禁被他人的半成品卡红，探针没能端到端跑起来 —— 见踩坑第 3 条）
> **推荐度**：推荐（代码自体编译干净、`real compile errors = 0`；摆放 / 卡面落点待探针实测回填）

## 目标
1. 复用 `mods_builtin/dlc/animation/character/plant/VoltShroom/` 的动画，做成**周围放电 AOE** 植物。
2. 数值对齐原版电击蘑菇（100 阳光 / 400 伤害 / 3×3 / 白天睡觉）；DLC Edition wiki 没有 VoltShroom 单页，取不到就按原版口径，注释里写清。
3. 本体零改动；关模组 = 回到原版。

## 最简路径（步骤）
1. **动画段**（`.tres` 里的 `length`）：`idle` 1.5s / `charge` 0.667s（蓄电）/ `shooting` 0.333s（放电）/ `fin` 0.333s（收尾）/ `sleep` 1.5s。攻击链 = `charge` → `shooting`（**在这一刻结算 AOE 伤害**）→ `fin` → 回 `idle`；`attack_cd = 7.5`（> 三段总时长 ~1.33s，别让 CD 到点重置开火段）。
2. **场景** `voltshroom/plant_voltshroom.tscn`：继承 `plant_base.tscn` + 实例化 `VoltShroom.tscn`（**不设 scale**）+ `DetectComponent`（`is_lane = false` 跨行；`RectangleShape2D 228×260` ≈ 3 列 × 3 行，`Area2D` 在 `(0,-30)` 居中略上移到植株中部）+ `AttackCdTimer`(7.5) + `AnimComponent` 换 `component_anim_empty.gd`；`SleepComponent.is_sleep_in_day = true`，`DetectComponent` 进 `sleep_influence_components`。**没有 Marker2D / ShootTimer**（AOE 直伤，不发射子弹）。
3. **覆盖 `AnimLib` 五段库**（同前几株：转换工具只留一条 `ALL_ANIMS` 7.5s，不分段）。`VoltShroom.tscn` 子节点很多，`AnimLib` 是根下**第 23 个 → `index="22"`**（用脚本数 `parent="."` 的节点数得到，别照抄国王仙人掌的 20 / 投掷蘑菇的 11）。
4. **脚本** `voltshroom/voltshroom_plant.gd`：`extends Plant000Base`（不写 `class_name`）；`DetectComponent` 两信号 + 冷却计时器驱动 `AnimationPlayer`；`_on_animation_finished` 里 `charge`→`shooting`+`_apply_aoe_damage()`→`fin`→`idle`；AOE 用 `_detect_component.get_all_enemy_can_be_attacked()` 拿范围内**所有**僵尸，逐个 `DamageInfo.create(enemy, 400, E_DamageMode.Real, E_DamageCause.Bomb)` + `DamageSystem.apply()`（全仓唯一伤害入口）。睡眠信号换 `VoltShroom_sleep`；`signal_update_speed` 折算计时器。
5. **配方 / 图鉴**：`dlc_mod.gd` 加 `VOLT_SHROOM` 常量 + `VOLT_SHROOM_SCENE` preload + 数值常量、`_build_voltshroom_recipe()`（普通卡、`card_face_anim = &"VoltShroom_idle"`、兜底小喷菇）、`_register_voltshroom_almanac_entry()`；`install()` 配方数组加一项、`uninstall()` 多摘一条图鉴。卡面 `card_face_scale/position` 先按蘑菇量级给 `(0.5,0.5)` / `(-18,-33)` 占位，待探针 `get_content_rect()` 实测回填（与闪电芦苇同口径）。
6. **探针** `test/scenarios/probe_dlc_voltshroom.gd`：注册 / 卡位 / 图鉴 / 五段动画 / 摆放（与小喷菇对齐）/ AOE 零件与数值（`is_lane=false`、228×260、7.5、400、白天睡觉）/ 蓄电→放电→收尾→待机 / 睡眠换姿势 / 卸载。

## 弯路 / 踩坑（三段式）
- **现象**：编译门禁报 `VoltShroom.tscn:1927 / 1931 - [ext_resource] referenced non-existent resource`（`VoltShroom_face 复制.tres` / `VoltShroom_face  复制 2.tres`），整株动画场景加载失败 → 植物场景、卡面一起崩。
- **因为**：转换工具把文件名含「复制」的两段动画写成了**乱码名**（`澶嶅埗`，`复制` 被双重编码），而 `.tscn` 里引用的却是正常的「复制」——两边对不上。
- **结论**：把乱码名文件按 `.tscn` 引用重命名回来（文件名里的非 ASCII 串替换成「复制」）。**务必用 Python `os.rename` 保 UTF-8**；第一次用 PowerShell 命令行改，控制台编码会把「复制」又写成乱码、看着像成功了其实没改对（用 Python `repr(name)` 核到 codepoint 是 `U+590D U+5236` 才作数）。已把这条写进 [DLC植物导入.md](../参考存档/DLC植物导入.md) §5 踩坑速查。
- **现象**：本会话多次 `replace_in_file` 编辑 `dlc_mod.gd` 失败（string not found）、编译门禁一直 `result=FAIL`。
- **因为**：**有多个 Agent 在并发改同一个 `dlc_mod.gd`**（这次会话里陆续出现了 bonkchoy / mortarshroom / reed / bloodorange / glowshroom / oakarcher / beeshooter / hurrikale / chardguard / ampliflower）。共享的 `install()` 配方数组那一行被反复改写，且别人的半成品（`_build_glowshroom_recipe()` / `_build_chardguard_recipe()` 调了没定义、`beeshooter_plant.gd` 的 `CanAttackZombieStatus`、`ampliflower_plant.gd` 的 `_exit_tree()`）会让**整个 `dlc_mod.gd` 解析失败**。
- **结论**：门禁红**不是电击蘑菇的问题**（`real compile errors = 0`、无任何 voltshroom 报错）；是他人未完工的半成品卡住共享文件。也因此**本次没能端到端跑 `probe_dlc_voltshroom`**（模组加载即 parse error）。电击蘑菇的四件套（场景 / 脚本 / 配方图鉴 / 探针）已齐，等并发方收尾后重跑 `test/run_autopilot.ps1 -Scenario probe_dlc_voltshroom` 即可验证；摆放 / 卡面落点按探针 STEP5 打印的 INFO 微调。

## 推荐度与理由
推荐。第三类攻击方式（AOE 直伤，非子弹）几乎是把前几株的「场景 + 脚本 + 配方 + 探针」四件套换个动画与伤害路径，**本体零改动**。新知识：① AOE 用 `get_all_enemy_can_be_attacked()` + `DamageSystem.apply()`，不走子弹；② 跨行 AOE 要 `is_lane = false`；③ `AnimLib` 的 `index` 得按目标动画场景实际数（VoltShroom 是 22）；④ 转换产物的中文文件名可能是乱码，加载失败先查这个。
