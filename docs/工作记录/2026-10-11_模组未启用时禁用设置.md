# 2026-10-11 · 其它 · 模组页面：模组没启用时，它那一块设置整块禁用

> **任务类型**：其它
> **推荐度**：**推荐**（「禁用交给页面统一做，不让每个模组自己判」可直接照用）
> **耗时与成本**：约 1 轮，未开窗口（无头探针 `probe_mod_page` PASS + 编译门禁 PASS）
> **验证方式**：无头探针（纯 Control 界面）+ 门禁 PASS；画面需人工看一眼（只是置灰，无新布局）
> **补充自**：[2026-10-11_模组页面左右分栏.md](2026-10-11_模组页面左右分栏.md)（页面是那条记录建的，本轮在它上面加禁用）

## 目标

模组页面里，**模组没启用**时，右侧「模组自己那一块」的所有元素都要**不能操作**
（关着的模组下一局根本不装载，那块里的设置改了也不生效）。

## 步骤

1. 定位落点：`src/ui/mod_page/mod_page.gd` 的 `_build_detail()` —— 详情里只有两处内容，
   名称 / 开关 / 说明是页面自己造的（**不能**禁用，那个按钮正是用来启用模组的），
   剩下的 `ModBase.create_detail_control()` 那一块才是"设置"。
2. 加递归工具 `_set_controls_enabled(root, enabled)`：按类型关——按钮类 `disabled`、
   输入框类 `editable`、滑条类（`Range`）`editable`，再遍历子节点。
   **不**改 `ConsoleEntryControl.refresh()` 的返回值语义（条目自己还有一套 enabled）。
3. `_build_detail()` 里判 `not ModManager.is_mod_enabled(mod.get_mod_id())`：
   先插一句提示 Label，再整块 `modulate` 压暗 + 递归禁用。
4. 补一道防回归：刷新回调（`DETAIL_REFRESH_META`）是照**条目自己**的 enabled 刷的，
   会把刚禁用的控件又开回来 ⇒ `_on_values_changed()` 刷完再补禁用一次（记下 `_detail_control`）。
5. 探针 `probe_mod_page` 加三条断言（手套那一块禁用 / 「启用」按钮不受影响 / 启用后恢复可操作），
   并把取"模组那一块"的办法从 `children[3]` 改成**最后一个子节点**（插了提示行，下标不固定了）。

## 关键决策与理由

- **禁用写在页面里，不写进每个模组** —— 页面本来就统一管"名称 / 开关 / 说明 + 模组那一块"，
  让 N 个模组各判一次"我开没开"等于 N 份重复（联机已经自己判了一次返回一句话，
  手套没判 —— 这就是不对称的来源）。页面统一处理之后模组可以不用管这件事。
- **按控件类型递归关，而不是让模组报一份"可禁用清单"** —— 页面不认识模组给了什么，
  类型判断对 Button / LineEdit / TextEdit / Range 四类已经够用，新增控件类型不用改模组。
- **开关按钮与提示行单独留着** —— 全禁了就没法启用模组了；提示行说明"为什么点不动"。

## 踩坑

1. 探针原来按**固定下标** `children[3]` 取"模组自己那一块" → 插了提示行之后取到的是提示 Label，
   下面那条"手套详情里写着解锁条件与用法"会 FAIL → **正解**：取 `detail_box` 的**最后一个子节点**
   （模组给的那一块恒在最后），并在注释里写清为什么不能按下标。
   ⚠️ 这类"运行时造控件"的界面，探针**不要**按下标取，按下标等于把页面结构焊死。
2. `ConsoleEntryControl.refresh()` 会按条目自己的 `is_enabled()` 重刷 `disabled` / `editable`，
   刷新一次就把页面的禁用冲掉了 → **正解**：刷新之后再补一次禁用（本次在 `_on_values_changed()` 里补）。

## 给后来者的最简路径

1. 在页面造完内容之后判一次状态 → 递归 `_set_controls_enabled()`（本文件可直接抄）
   + 整块 `modulate` 压暗 + 一句提示。
2. 凡是有"值在外面变、页面替它刷一遍"的回调，刷新后**再补一次**禁用。
3. 探针按"最后一个子节点"取动态内容，别按下标。
