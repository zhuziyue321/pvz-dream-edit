# 2026-10-24_战利品特效从原版移植

> **本次任务**：把原版「结算线上的战利品」那套表现（弹跳箭头 + 周期闪光 + 星星爆裂 + 掉出时屏幕闪光 + 拾取后放大飞向中心）搬进本仓库
> **耗时 / 轮次**：2 轮（第一轮：读原版 → 写代码 → 探针 → 文档；第二轮：补齐「永不过期 / 领奖屏 / 关卡淡出」+ 开窗口人工验证）；
> **验证**：编译门禁 + 11 个探针 + **带窗口截图人工看过**（第二轮）
> **推荐度**：推荐

## 目标

本仓库原来的通关收尾是「战利品移到屏幕中心 → 发光 → 白屏 → 切场景」，
是**自造的近似**，跟原版差三处最显眼的地方：

1. 战利品落在场上时**不闪、不跳箭头** —— 原版那个「黄色下箭头上下弹跳 + 物品周期闪光」是关卡奖励的标志；
2. 点开时**没有星星爆裂**；
3. 拾取后只是「略微放大」（×1.25），原版是放大到 **2.0**。

本次把这三处（外加「战利品掉出来时屏幕中央闪一下」）按原版口径移植。

## 最简路径（步骤）

1. **先读原版**：`../PvZ-Portable-main/src/Lawn/Coin.cpp` 是全部出处 ——
   `Coin::Draw`（闪光 + 光晕）、`Coin::UpdateFall`（落地挂箭头粒子）、
   `Coin::Collect` / `Coin::UpdateCollected`（星星爆裂 + 飞向中心放大）、
   `Coin::IsLevelAward` / `CoinGetsBouncyArrow`（哪些类型算「关卡奖励」）。
   粒子参数全在**本仓库的** `pak/particles/*.xml` 里（原版粒子表已原样搬过来），
   不用去原版工程找资源：`AwardPickupArrow.xml`（箭头）、`Starburst.xml`（爆裂）、
   `ScreenFlash.xml`（屏幕闪光）、`SeedPacket.xml`（种子包版箭头）。
   ⚠️ 原版工程**没有** `Present.cpp` —— 原版的「礼物盒」是 `Coin` 的 `COIN_PRESENT_PLANT` 那一类，
   别再去找不存在的文件。
2. **单位换算**：原版粒子 `LaunchSpeed` 是「像素/帧」（`TodParticle.cpp` 里 ×0.01 得到 5~18），
   搬到 Godot 要 ×60 换成像素/秒；`ParticleDuration 50` = 50 帧 = 0.83 秒。
3. **表现挂哪儿**：新增 `src/fx/other_effect/loot_pickup_arrow.gd`（箭头）+
   `loot_starburst.tscn/.gd`（爆裂，登记进 `SceneRegistry.LOOT_STARBURST`）；
   掉落物场景里加一个名为 `PickUpArrow` 的节点（基类按**节点名**接，跟 `PickUpGlow` 一个套路）。
4. **起停时机**：`DropItemBase.notify_loot_landed()` 起（落地那一刻，原版也是 `mHitGround` 才挂粒子）；
   `stop_level_award_effects()` 停（拾取 / 超时消失都要停）。
   抛物线结束（`launch()`）与抛掷结束（`MgmRewardManager.throw_to`）都要调到 `notify_loot_landed()`。
5. **收尾表演**：`CanvasLayerWhiteScreen` 里把放大倍率改成原版的 2.0、移动时长 1.2→1.6 秒；
   新增「掉出来时屏幕闪一下」（订阅新事件 `ConstEventName.LEVEL_COMPLETE_LOOT_SPAWNED`）。
6. **探针兜底**：新写 `test/scenarios/probe_loot_effects.gd`（进 1-4 掉道具类奖励，逐条断言）。
7. **门禁 + 探针**：`test/check_scripts.ps1`（real compile errors = 0）；
   `test/run_autopilot.ps1 -Scenario probe_loot_effects -Windowed` 与 `-Scenario probe_level_complete_fx`。

## 弯路 / 踩坑（三段式）

- **试过**：先把「战利品表现」整套塞进 `Present` / `SeedPacket` 两个类里。
- **因为**：原版是按「类型」分派的（`IsLevelAward()` 那套），本仓库也已经有 `is_level_complete_drop`
  这个横切标记，照着它做成基类上的三个钩子（`start_/stop_level_award_effects`、`get_level_award_arrow_offset`）
  比在两个子类里各抄一遍干净；箭头位置这类**每种掉落物不一样**的才留给子类重写。
- **结论**：横切的部分上基类，差异部分留子类重写（种子包重写箭头顶点）。

- **试过**：把星星爆裂做成战利品的子节点。
- **因为**：战利品被拾取后要放大到 2.0 飞向屏幕中心，子节点会被一起放大，火花会越飞越大。
- **结论**：爆裂挂在**掉落容器**里（`get_parent()`），自己播完 `queue_free()`。

- **试过**：闪光用 `_process` 每帧算原版那个三角波。
- **因为**：跟仓库里其它特效的风格一致（都是 tween），而且不用每帧过一遍逻辑。
- **结论**：用一条 `set_loops()` 的 tween 走「白 → 暗 → 白」两段 `TRANS_LINEAR`，正好是原版的三角波；
  但**必须**在淡出前 `kill_tween` 掉 —— 闪光在改 `modulate`，不抢就会「闪着淡出」。

- **试过**：跑 `probe_level_complete_fx` 一开始就挂了（`1-4 进入 MAIN_GAME` 超时，阶段=0）。
- **因为**：**别的 agent 正在改** `src/managers/plant_cell_manager/plant_cell_manager.gd`，
  改到一半的版本有解析错误（`create_plant_on_zombie_mode` 未定义），
  主游戏整个编译失败 → 进不了关卡。跟本次改动无关。
- **结论**：并发改动期间探针红了先看 stderr 的 `Parse Error` 出在哪个文件；
  等对方改完树恢复干净，重跑即 PASS（本次就是这样）。

## 推荐度与理由

**推荐**。要点：

- 原版的「关卡奖励」在 C++ 里就是 `Coin` 的一个类型分支 + 一堆粒子，
  搬到 Godot 之后按「节点名 + 三个基类钩子」接最省事；
- **粒子资源不用去原版工程搬** —— `pak/particles/*.xml` 里原版粒子表原样在，
  `pak/particles/DownArrow.png`、`Star40.png`、`AwardRays_star.png` 也都在，
  按 xml 里的参数换算成 `ParticleProcessMaterial` 即可；
- 坑只有三个：**闪光跟淡出抢 modulate**、**爆裂别挂在会缩放的节点上**、**箭头位置每种掉落物不一样**。

## 补充 / 评价（事后追加，见 §5）

### 第二轮（同日追加）：用户要求「都完成」—— 把上一轮列的未做项补齐

第一轮结尾留了三个「未做 / 待定夺」：开窗口人工验证、**原版领奖屏**、**原版关卡淡出**，
外加「结算线战利品永不过期」。本轮把这四件事做完。

**做了什么**

1. **战利品永不过期**：原版 `Coin::IsLevelAward()` 不走 `mDisappearCounter` ——
   本仓库 `DropItemBase.auto_free_time <= 0` 即永不过期，`DropItemManager.LOOT_NEVER_EXPIRE = 0.0`
   给结算线战利品（种子包 / 礼物盒）。
   ⚠️ 连带影响：掉落物不再自己消失后，结算流程要等满 `UNLOCK_DROP_WAIT_TIME`（20 秒）兜底才继续
   （原来靠「掉落物 10 秒后消失」提前结束）。原版就是「玩家不点就一直停在场上」，这条算是对齐。
2. **原版领奖屏**：新增 `src/ui/award_screen/award_screen.gd/.tscn`（登记进 `SceneRegistry.AWARD_SCREEN`），
   按 `AwardScreen::DrawAwardSeed()` 的坐标摆（标题 58 / 种子包中心 (350,129) / 植物名 326 /
   说明 (285,360,230,90) / 按钮 (324,500,156,42) / 180 帧白罩淡入）。
   触发点：`MgmRewardManager.gain_loot()` 查 `LootRegistry.get_plant_type()`，种子包类战利品才弹。
3. **原版关卡淡出**：淡出时长对齐原版 200 帧（`WHITE_TIME = 200/60`），
   冒险 1-9 / 2-9 / 3-9 / 4-9 / 5-9 淡成**黑色**、其余白色（`BLACK_FADE_ADVENTURE_LEVELS`）。
4. **箭头着色**：原版 `AwardPickupArrow.xml` 的粒子色是 (1, .9, .4)，本仓库 `pak/particles/DownArrow.png`
   本身是灰白 → 给两个 `Arrow` 节点加 `modulate = Color(1, 0.9, 0.4)` 才对上原版观感。

**人工验证（带窗口）**：`probe_award_screen` 用 `-Windowed` 跑，截图存 `user://autopilot_reports/shot_award_screen.png`。
第一张抓到的是淡入中途（整体发白），把等待从 1.6 秒改成 3.4 秒（等满原版 180 帧）重跑，
才看清标题被卡片压住下半截 → 按原版坐标把标题 Label 从 (40~78) 挪到 (34~58)，复跑确认正常。

**弯路 / 踩坑（三段式）**

- **试过**：在 `show_award_screen()` 里用局部变量 + lambda 等「继续」信号。
- **因为**：GDScript 的 lambda **按值**捕获局部变量，`is_continue_pressed = true` 写在 lambda 里外面看不到。
- **结论**：标志位必须是**成员变量**（`is_award_continue_pressed`）；顺带别用 `await 信号` ——
  领奖屏先被释放时会把协程留成永久挂起，改成轮询 + `is_instance_valid`。

- **试过**：探针报 `[AWARDSCREEN] result=PASS failed=0`，但画面上什么都看不清。
- **因为**：协程中途报错（漏定义 `@onready title_label`）会直接停掉，`_finish` 仍执行 → **假 PASS**。
- **结论**：探针末尾加一道 `_reached_end` 兜底断言，跑到最后才置位。

- **试过**：`probe_adventure_reward` / `probe_adventure_round` 一红。
- **因为**：① 植物类奖励现在多了一层领奖屏，探针没点「继续」就断言「已切回主菜单」；
  ② `probe_adventure_round` 那条「首次通关 5-10 进商店」**早就和实现对不上了** ——
  现有实现明确「5-10 是结局关，商店第四页只上架、不自动跳商店」。
- **结论**：探针断言要跟着机制更新（点「继续」再断言 / 改成「回主菜单」）；
  归属判定用 `git stash push -- <仅我的文件>` 跑一次对比 —— 与本轮无关的失败（`probe_hammer_zombie`
  墓碑数 9≠10、`probe_last_stand` 阳光 5250）回退本轮改动后**依然同样失败**，属并发改动/既有遗留。
