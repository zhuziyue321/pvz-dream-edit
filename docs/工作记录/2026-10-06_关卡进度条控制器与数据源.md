
# 2026-10-06 · 其它 · 关卡进度条加控制器 + 数据源（僵王关换血量百分比）

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话；无头探针 4 个（新探针 + 3 个回归），未开窗口
> **验证方式**：无头探针 `probe_level_progress_bar` 两条口径全过 + 回归 `probe_zomboss_damage` / `probe_hammer_zombie` / `probe_beghouled` 全 PASS（画面需人工看一眼）
> **补充自**：无（机制文档新开 [关卡进度条.md](../参考存档/关卡进度条.md)）

## 目标

给关卡右下角那条进度条加一个控制器，并让「进度条代表什么」可替换：

1. 默认 = 战斗进度（波次走完多少）；
2. 关卡能一句话换成自己的口径；
3. 僵王博士战 = 僵王的血量百分比。

判据：出怪侧（`ZombieWaveManager` / 出怪器）里搜不到 `flag_progress_bar`；僵王关进度条不画旗帜且进度 = 血量百分比。

## 步骤

1. **先摸清谁在写进度条**：`grep flag_progress_bar` —— 三处写方（波次管理器、锤僵尸出怪器、僵尸迷阵藏条）+ 一处转交（`ZombieManager.init_source()` 把节点递给运行期 `instantiate()` 的出怪器）。
2. **加数据源基类** `LevelProgressProvider`（`RefCounted`，每帧被问 5 件事：进度 / 显不显示 / 几面旗 / 升旗 / 收旗）+ 两个实现：战斗 `LevelProgressBattleProvider`、僵王血量 `ZombossProgressProvider`（放在 `src/levels/core/zomboss/` 与僵王同侧）。
3. **加控制器** `LevelProgressBarController`（常驻 `main_game_base.tscn`，`%LevelProgressBarController`），`MainGameManager.init_manager()` 里排在 `zombie_manager.init_manager()` **之后**调用 `setup(self)` —— 波数这时才定，旗帜数要读它。
4. **出怪侧改成「只算不写」**：波次管理器把 `battle_progress` / `is_wave_started` / `_flag_to_raise` / `_is_flag_reset_pending` 留在自己身上，由 `ZombieManager` 的「波次进度」区五个方法统一转发（内部按 `wave_source != null` 分流），数据源只认 `ZombieManager`；
   顺带把 `init_source()` 的进度条参数删掉（出怪器不再需要 UI 节点）。
5. **关卡换口径的口子**：`LevelScriptBase.create_progress_provider()`（返回 null = 用默认挑选）；挑选顺序「脚本指定 > `has_boss()` → 僵王血量 > 战斗进度」。
6. **删掉同位置的独立僵王血条**：`ZombossHpBar`（`zomboss_hp_bar.gd/.tscn`）与关卡进度条本来就摆在同一块位置，统一后不需要两份 —— 连带删 `LevelInfo.refresh_boss_progress()` 与 `ZombieManager._refresh_boss_progress()` 四处调用。
7. 僵尸迷阵的「藏进度条」改走 `level_progress_controller.set_enabled(false)`。
8. 补探针 + 同步文档（新开 [关卡进度条.md](../参考存档/关卡进度条.md)、改 [特殊关卡.md](../参考存档/特殊关卡.md) 僵王血条 / 僵尸迷阵两处、AGENTS.md 路由表补一行）。

## 关键决策与理由

- **拉模式（控制器每帧问）而不是推模式（出怪侧写）** —— 换口径时只动数据源，出怪侧一行不用改；原来波次管理器和出怪器各写各的，加一种口径要改两个地方。
- **过渡期仍保留赶动画**：`FlagProgressBar` 的 `real_value` / `chase_value` 平滑照旧，控制器只写 `real_value`，所以「进度倒退」（僵王掉血）也是平滑的。
- **旗帜做成事件通道**（`take_flag_raise_index()` / `take_flag_reset()`）而不是塞进返回值 —— 升旗 / 收旗是一次性事件，混进每帧的进度值里会让控制器每帧重复升旗。
- **僵王血量源留在关卡侧** `src/levels/core/zomboss/` —— 只有两个僵王关用它；被 ≥2~3 关复用才上浮（这正是硬约束 §1-8 的口子）。
- **自动挑选而不是让两个僵王关各写一遍** —— 判据用关卡数据已有的 `has_boss()`，关卡脚本零改动。

## 踩坑

1. **编辑 `ui_flag_progress_bar.gd` 时两次替换撞在一起**（先删 `init_flag_from_wave` 再补 `create_flag`，结果出现两个同名的 `create_flag` 和一个没有函数头的 `set_progress`）。
   → **正解**：大段改动前先 `read_file` 看清全文，一次替换写完整函数体；改完立刻 `read_lints` + 再读一遍确认。
2. **探针里 `var x := ...` 推断不出类型**（`Cannot infer the type of "flag_num"`）—— `Global.main_game` 是弱类型，`mg.game_para.max_wave` / `mg.zombie_manager.get_living_bosses()` 都跟着变 Variant。
   → **正解**：探针里显式写 `var flag_num: int = ...` / `var bosses: Array = ...`；**第一次跑探针一定要先看 stderr 里的 Parse Error**（场景脚本解析失败时探针会一直空转到看门狗超时，stdout 上只看到「超时」，误以为是关卡卡住）。

## 给后来者的最简路径

1. 加一种口径 = 新建 `extends LevelProgressProvider`（实现 `get_progress()` / `is_bar_visible()`，要旗帜再实现 `get_flag_num()`），然后在关卡脚本里 `func create_progress_provider() -> LevelProgressProvider: return MyProvider.new()`。
2. 运行期换口径：`mg.level_progress_controller.set_provider(MyProvider.new())`；整关关掉：`set_enabled(false)`。
3. 验证：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_level_progress_bar`（1-3 战斗进度 + 5-10 僵王血量，两条口径各断言一遍）。
