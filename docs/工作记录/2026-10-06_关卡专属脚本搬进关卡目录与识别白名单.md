# 2026-10-06 · 资源改名 · 关卡专属脚本搬进关卡目录 + 关卡识别改白名单

> **任务类型**：资源改名
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 2 轮对话 / 开了游戏（5 个带窗口探针）/ **必须人工先关 Godot 编辑器**
> **验证方式**：打开游戏实测（`probe_levels` + `probe_seeing_stars` / `probe_slot_machine` / `probe_beghouled` / `probe_beghouled_twist` / `probe_hammer_zombie` 全 PASS）
> **补充自**：无

## 目标

1. 新增规范：一关不止一个脚本时，辅助脚本**必须**与关卡本体 `.gd` 同目录，且**文件名以关卡文件名为前缀**。
2. 把「是不是关卡」的判据从「文件名以模式名为前缀」改成**白名单**（继承链上出现 `LevelScriptBase` / `ResourceLevelData`）。
3. 按这两条修掉不合规的脚本（`src/levels/script/` 整个目录 + `mode_minigame/` 里两个没带关卡前缀的）。

## 步骤

1. 先确认 `LevelRegistry` 的现状：判据是 `is_level_file_name()`（文件在 `mode_X/` 下且文件名以 `X_` 开头）。
2. 改成白名单 `LEVEL_BASE_CLASS_NAMES = ["LevelScriptBase", "ResourceLevelData"]` + `is_level_script(res_path)`：沿 `get_base_script()` 链比对 `get_global_name()`。
3. 落位规则进文档：`docs/参考存档/规范细则存档.md` D-07（含 ≥2 关共用 → `core/<玩法>/` 的例外）、`docs/项目规范.md` §1-8、`AGENTS.md` §3-8、`src/levels/AGENTS.md`、`关卡格式V2.md` §3.4。
4. 搬迁（**先关编辑器**，连 `.uid` 一起走）：
   - 只服务 1 关 → 关卡同目录 + 关卡名前缀：`minigame_03_slot_machine_ui.gd`、`minigame_05_beghouled_progress_provider.gd`、`minigame_09_beghouled_twist_manager.gd`、`minigame_07_seeing_stars_cell_star_overlay.gd/.tscn`、`minigame_07_seeing_stars_progress_provider.gd`
   - ≥2 关共用 → `core/<玩法>/`：`core/beghouled/`（05+09 共用）、`core/hammer_zombie/`（冒险 2-5 + 迷你游戏 15 共用）
   - 删掉空掉的 `src/levels/script/`
5. 改引用：`preload` 路径 4 处、`.tscn` 的 `ext_resource path` 1 处、注释若干、探针 2 个、`src/levels/README.md` 与 `AGENTS.md` 的目录表、3 份参考文档里的旧路径。

## 关键决策与理由

- **识别走继承链而不是文件名**：辅助脚本按新规约**也带关卡名前缀**，前缀分不出「关卡」与「辅助脚本」；实测 `mode_adventure/adventure_05_05_bungi_blitz.gd`（`extends Node`）正是被旧前缀判据误登记成假关卡的（修完选关表里少掉这个假 id）。
- **≥2 关共用进 `core/<玩法>/`**：跨模式目录（冒险 2-5 与迷你游戏 15）不可能同时满足「与关卡同目录」，沿用已有先例 `core/zomboss/`。
- **`src/items/mini_game/` 那三个（`hammer` / `portal` / `wallnut_bowling_stripe`）没动**：它们由本体（`main_game_base.tscn` / `gim_other.gd` / `portal_manager.gd`）引用，是本体侧道具，不属于「关卡脚本」。

## 踩坑

1. **`get_instance_base_type()` 判不出基类** → 它返回的是**原生**基类（关卡脚本一律 `Resource`）→ **正解**：用 `get_base_script()` 沿链比对 `get_global_name()`（实测 `extends LevelScriptBase` 的脚本链是 `LevelScriptBase` → `ResourceLevelData` → `Resource`）。
2. **搬完无头跑探针从 108 关掉到 102 关、stderr 一堆 `Could not find script for class`** → Godot 的**全局类缓存**（`.godot/`）还指向旧路径，`load()` 整批解析失败 → **正解**：搬完先跑一次
   `Godot --headless --path <工程> --import` 重建缓存，再跑探针（重建后回到 108 关、stderr 0 行）。
3. **PowerShell 里用变量拼相对路径做批量 `Move-Item` 会解析到错误目录**（报「未能找到路径中的某个部分」）→ **正解**：每条都写**完整绝对路径**，别用 `$root\$from` 拼接。

## 给后来者的最简路径

1. 关掉 Godot 编辑器 → 连 `.uid` 一起 `Move-Item`（绝对路径）。
2. 全局搜旧路径（`.gd` / `.tscn` / `docs/*.md`），改 `preload` 与 `.tscn` 的 `ext_resource path`。
3. `Godot --headless --path <工程> --import` 重建全局类缓存。
4. 带窗口跑受影响关卡的探针，外加 `probe_levels` 校验关卡总数。
