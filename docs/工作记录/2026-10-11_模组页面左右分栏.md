# 2026-10-11 · 其它 · 重做模组页面：左列模组列表 + 右侧详情（详情由模组自己给）

> **任务类型**：其它
> **推荐度**：**推荐**（「页面只认注册表 + 详情由模组自己造」这套可照搬到任何"列一批东西看详情"的界面）
> **耗时与成本**：约 3 轮（①建页面 ②修排版：full-rect 锚点 offset 用错 + 按钮被拉满 ③把模组从控制台撤干净 + 加反断言）
> **验证方式**：带窗口跑探针**实际截图核验**（手套 / 联机两张）+ 递归打印 `get_global_rect()` + 三个无头探针 PASS + 门禁 PASS
> **补充自**：无（第一次做这类页面；控制台的「条目注册表驱动」是它的模板）
> **后续**：同一天追加了「[把模组从控制台撤干净](#补充-2026-10-11同一天第二轮把模组从控制台撤干净)」（删钩子 + 反断言）

## 目标

模组页面重做：屏幕**左列**列出全部模组，选中一个后在**右侧**显示它的详情，
「具体显示什么」**由模组自己配置**（页面不认识任何一个具体模组）。

## 步骤

1. 先读 [模组机制.md](../参考存档/模组机制.md) ＋ [控制台.md](../参考存档/控制台.md) ＋ `canvas_layer_control.gd`，
   确认「条目 → 控件」的渲染已经存在（控制台在用），模组页面想显示模组自己的设置就该复用它，而不是抄第二遍。
2. **抽渲染器**：新建 `src/ui/console/console_entry_control.gd`（`ConsoleEntryControl`），
   把控制台里 `create_control / refresh / 按钮样式 / 输入框样式 / 滑条格式化`整段搬过去；
   控制台改成持有一个实例并委托（`_entry_builder`），自身只留翻页逻辑。
3. 建页面 `src/ui/mod_page/mod_page.tscn + mod_page.gd`：**场景里只有几个空容器**（标题 / 左列 / 右侧 / 关闭，
   与控制台同款），列表与详情全在 `build_mod_page()` 里运行时造。
4. `ModBase` 加钩子 `create_detail_control()`（返回 null = 只显示名称 / 开关 / 说明）
   ＋ 便捷方法 `create_detail_label()` ＋ 刷新约定的 meta 键 `DETAIL_REFRESH_META`。
5. 三个现役模组各自实现：手套（解锁进度 + 用法）／自制关卡（目录 + 扫到几个条目）／
   联机（把 `register_console_entries()` 里那一坨抽成 `_build_console_entries()`，控制台与页面共用同一份）。
6. 入口：主菜单「选项」面板加 `Button5`（照 `Button4`「选项设置」挂控制台的同款做法：
   按钮下挂一个 `CanvasLayer` 实例，`pressed` → `appear_mod_page()`）。
7. 写无头探针 `probe_mod_page`：验入口挂着页面 / 列表条数 = 登记数 / 详情里模组自己那一块 / 开关能真的开 / 关。

## 关键决策与理由

- **页面不认识任何具体模组** —— 左列直接遍历 `ModManager.all_mods`，
  新增模组只要登记进 `MOD_SCRIPT_PATHS` 就自动出现在列表里，页面零改动（硬约束 §1-4 的同一条思路）。
- **详情 = 三样固定的（名称 / 开关 / 说明）+ 模组自己那一块** —— 三样由页面造是"每个模组都该有"，
  剩下的交给 `create_detail_control()` 是"只有这个模组自己知道"。这是「由模组配置」的落点。
- **复用 `ConsoleEntry` 而不是另造一套配置格式** —— 联机的整块界面本来就是 8 条控制台条目
  （目标输入框 / 开启房间 / 加入房间 / 退出房间 / 快照频率 / 状态 / 最近一条 / 房间关卡），
  抽成 `_build_console_entries()` 之后控制台与模组页面是同一批开关，改哪边都一样，没有第二份真相。
- **开关只改本次运行** —— `data/mods/mod_config.tres` 在导出后是只读的 pck 内文件，写不回去；
  而 `ConfigService` 是按用户存档在**用户登录之后**才加载的（`ModManager._ready()` 在它之前），
  接不上。页面上直接写明"永久开 / 关改 `mod_config.tres`"，不假装持久化。
- **场景里只放空容器** —— 照控制台的做法（"加一项不用碰场景"）：布局写在 `.tscn` 里，
  内容全是运行时造的，将来条目 / 模组多了不用改场景。

## 踩坑

1. `custom_level_mod.gd` 里直接写 `CUSTOM_LEVEL_DIR` → **Parse Error: Identifier not declared**
   （这个常量在 `custom_choose_level.gd` 上）→ **正解**：引用 `CustomChooseLevel.CUSTOM_LEVEL_DIR`，不抄第二份常量。
2. 探针一开始断言"联机没启用时详情是一句话" → 实际 `data/mods/mod_config.tres` 里联机是**开着**的，FAIL
   → **正解**：探针按 `ModManager.is_mod_enabled()` 分两端断言（开着 = 8 条控件的面板，关着 = 一句话）。
3. 门禁 `--import` 抓不到**探针脚本**里的引用错误，第一次 FAIL 是第二道（scenarios 编译）抓出来的
   → 动探针 / 新增脚本后必须跑完整 `check_scripts.ps1`，不能只看 `real compile errors`。
4. 本次环境里 `Global.gd` **编译失败**（别人在改的 `zombie_boss/doctor/` WIP 把它拖挂了），
   于是 `Global.console_registry` 为 null、`Global.global_game_state` 为 null
   → 页面与手套详情都做了空判据（页面只是不接刷新信号，手套那行写"读不到通关进度"），没有连带崩。
   ⚠️ 副作用：`probe_console_registry` 在这个工作区跑不了（`Global.console_registry 为空`），
   控制台那边的改造只能靠「门禁 PASS + 模组页面探针实际渲染了 8 条控件」间接证明。
5. **`ListScroll` 在 full-rect 锚点下把 `offset_right` 写成 `300`**（想要"右边界在 x=300"）
   → full-rect 锚点下 `offset_right` 是**距右边缘的偏移**，正数是往屏幕外推，结果左列宽 1060px
   直接盖住右侧详情 → **正解**：写 `-500`（800 − 300）；`DetailScroll` 里 `-40` 这种"贴右边缘往里缩"
   的写法才是 full-rect 锚点的正确用法。
6. **详情里的按钮被 VBox 拉满整行**（440px，灰底图拉变形）→ 按钮类控件要显式
   `size_flags_horizontal = SIZE_SHRINK_BEGIN`（页面自己的开关按钮、联机面板里的三个按钮都补了）；
   滑条 / 输入框的"一行"反而要 EXPAND_FILL 占满。
7. **UI 排版别靠脑补**：写个临时探针 `root.get_texture().get_image().save_png(...)` 截图 +
   递归打印每个 Control 的 `get_global_rect()`，两个证据一起看，一眼定位（本次从"用户说排版有问题"
   到修完共两轮，全程没猜）。

## 补充 2026-10-11（同一天·第二轮）：把模组从控制台撤干净

**背景**：第一轮只是"把联机的那一批条目改成两边共用"，于是出现了**同一样东西两个入口**
—— 控制台里有「模组」「联机」两栏，模组页面里又有一样的内容。用户一句"清除原先控制台里的
模组和联机，把新的模组界面迁入"点破了这个重复。

### 做法

1. `ModManager`：删掉 `_register_mod_switch()`（给每个模组在「模组」组放开关）
   与 `_register_console_entries()` / `_unregister_console_entries()`，连带删它们的调用点
   （`_install_enabled_mods()` / `_install()` / `set_mod_enabled()`）。
2. `ModBase`：删掉 `register_console_entries()` 虚方法 —— **钩子没有调用方了就删干净**，
   留着会误导下一个 Agent 去重写它（它是**空实现**，写了也永远不会被调）。
3. `NetplayMod`：`_build_console_entries()` → `_build_panel_entries()`，**只喂给模组页面**；
   「控制台」字样的成员一律改名（`CONSOLE_CATEGORY`→`PANEL_CATEGORY`、
   `CONSOLE_KEY_*`→`CONFIG_KEY_*`、`_request_console_refresh`→`_request_panel_refresh`、
   `_on_console_create_host`→`_on_host_button_pressed` …）。
   ⚠️ 刷新机制**故意保留**：`ConsoleRegistry.request_refresh()` 那条 `values_changed` 总线
   仍是模组告诉前台"值变了，重读一遍"的最短路，模组页面就订阅它；
   借信号不等于还在往控制台挂条目，注释里写清了这一点。
4. `ConsoleRegistry`：删 `CATEGORY_MOD`（那组现在没有主人了），头部写明"模组不往这里挂"。
5. **反断言**（这一步是关键）：`probe_mod_page` 与 `probe_console_registry` 各加一条 ——
   `registry.get_entries("模组")/("联机")` 必须为空，否则 FAIL。
   搬家这件事**只有反断言能防止它悄悄长回来**。
6. 探针 `probe_netplay_session` 第 5 节原本从 `Global.console_registry.get_entry()` 取条目取证
   → 改成 `mod._build_panel_entries()` 按 id 组字典，再补一条"控制台里没有「联机」"的反断言。

### 这轮的坑

8. **Godot 把「变量从 Variant 推断」当错误**（`check_scripts.ps1` 会 FAIL，但 `real compile errors` 仍是 0）
   → `var target := by_id.get(&"netplay_target")` 这种 `Dictionary.get()` 的返回值是 Variant，
   **正解**：`var target := by_id.get(&"netplay_target") as ConsoleEntry` 显式转型。
   ⚠️ 只看 `real compile errors : 0` 会漏 —— 必须看 `result=` 那一行。
9. 替换常量名时图省事用整块替换，结果**误删了相邻的 `CATEGORY_DEFAULT`**（`console_registry.gd`）——
   教训：一次替换里带多个常量时，改完**立刻读回来瞄一眼**，别连着往下改。

### 结论

同一件事只留**一处**判定入口：模组的列表 / 开关 / 详情 = 模组页面；
控制台只管本体自己的调试开关。`ConsoleEntryControl` 这个渲染器两边共用 ——
它是"条目 → 控件"的工具，不是"控制台的私有财产"。

## 补充 / 评价（2026-10-11 · 模组没启用时，它那一块设置整块禁用）

> **本次记录**：[2026-10-11_模组未启用时禁用设置.md](2026-10-11_模组未启用时禁用设置.md) ←→ 被补充：本文件
> **索引推荐度**：**推荐** → **推荐**（已同步 / 未改）

- **补充**：本页面建完之后还差一条「模组没启用时右侧设置能不能改」的规则 —— 已由本次任务补上：
  `_build_detail()` 里判 `is_mod_enabled()` 后递归禁用 + 压暗 + 插一句提示，
  刷新回调（`DETAIL_REFRESH_META`）之后还要**再补一次禁用**（`refresh()` 是照条目自己的
  enabled 刷的，会把它冲掉）。**新增模组仍然不用碰页面** —— 禁用是页面统一做的。
- **评价**：照这套「页面只认注册表 + 详情由模组自己造」加一处状态处理很顺手，
  只改 `mod_page.gd` 一个文件就够，没有回头改三个模组。
- **更省的做法**：探针别按 `children[3]` 这种固定下标取「模组自己那一块」——
  一旦页面在中间插了提示行就会取错（本次已改成取最后一个子节点）。

## 补充 / 评价（2026-10-11 · 开关与设置统一存进 `user://<用户名>/mod_config.ini`）

> **本次记录**：[2026-10-11_模组开关与设置统一存档文件.md](2026-10-11_模组开关与设置统一存档文件.md) ←→ 被补充：本文件
> **索引推荐度**：**推荐** → **推荐**（已同步 / 未改）

- **订正上文「关键决策」第 4 条**（原文："开关只改本次运行 … 不假装持久化"）：**已作废**。
  开关现在**直接落进 `user://<用户名>/mod_config.ini`**（`ModManager.set_mod_enabled()` → 帧末 `save_mods()`），
  点了就永久生效；`data/mods/mod_config.tres` 降级成「没有存档文件时播种用的工程默认」。
  原来那条顾虑成立的一半仍在：**`data/` 里的 `.tres` 导出后写不回去** —— 正解不是放弃持久化，
  而是换到 **user:// 下**写（`ModManager._ready()` 排在 `Global` 之后，用户名那时已经读好了，接得上）。
- **补充**：模组自己的设置也搬进同一份文件（一个模组一段，`enabled` 是开关、其余键是设置），
  读写口是 `ModManager.get/set_mod_value()`；**不要用 `ConsoleEntry.bind_config()`**
  （那落在 `config.ini`，与开关不在一份文件里）。
- **坑（写探针必看）**：开关持久化之后，**开着模组跑完不还原会污染后续探针**
  （`probe_glove_unlock` → `probe_hand` / `probe_mod_page`），收尾必须 `set_mod_enabled(false)` + `save_mods()`。
  **运行时造控件的界面，探针一律按"最后一个子节点"或按类型找**。

## 给后来者的最简路径

1. 新增页面：`src/ui/<名字>/<名字>.tscn`（CanvasLayer 根 + 空容器）+ 同名 `.gd`，
   照 `mod_page.gd` 的 `build_*()` 三段式（清空容器 → 遍历数据造控件 → 挂回调）。
2. 让"具体显示什么"由别人配置：在基类（这里是 `ModBase`）加一个 `create_xxx() -> Control` 钩子，
   默认返回 null；页面负责兜底显示一句"没有要显示的东西"。
3. 要复用控制台那套控件就用 `ConsoleEntryControl`（一个实例造一堆、`refresh()` 一次刷全部）。
4. 入口照 `start_menu.tscn` 的 `Button4` 抄：按钮下挂 `CanvasLayer` 实例 + 一条 `pressed` 连接。
5. 收尾：写无头探针（纯 Control 界面无头就能跑）+ 跑 `test/check_scripts.ps1`。
