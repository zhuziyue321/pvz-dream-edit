# 2026-10-11 · 排查调试 · 新建的用户不再继承上一个账号的存档

> **任务类型**：排查调试
> **推荐度**：**推荐**（「读档 = 只覆盖读到的键，没有档时必须显式清空」这条判据可直接照用）
> **耗时与成本**：约 1 轮对话 / 未开游戏 / 无需人工介入（但要人工清一次已被污染的新档）
> **验证方式**：免验证 + 已给出人工验证方法（改动面 2 个文件、编译门禁 PASS）
> **补充自**：无

## 目标

新建一个用户后切过去，该用户必须是从零开始的新档（金币 0、无通关记录、花园 / 商店未解锁、只有初始植物），
不能带着上一个账号的进度。

## 步骤

1. 先确认「用户隔离」本身没问题：全仓搜 `user://` 的拼法（`SaveService._get_save_game_path()` /
   `ConfigService._get_config_path()` / `ResourceLevelData.get_save_game_path()` / `UserManager`），
   结论是**路径都带用户名**，盘上不存在串档。→ 泄漏只能发生在**内存里**。
2. 跟一遍切用户的调用链：`User._on_button_ok_pressed()` → `save_now()`（存旧档）→
   `set_current_user()` → `Global.reload_session_for_current_user()` → `SaveService.load_global_game_data()`。
3. 定位到 `load_global_game_data()`：新用户目录下没有 `GlobalSaveGame.json`，`_load_json()` 返回 `null`，
   函数**直接 return** —— 内存里上一个用户的 `GlobalGameState` 一个字段都没被覆盖。
   60 s 后自动存档（`start_autosave(60.0)`）把这份旧数据写进新用户的空目录，从「看着像继承」变成「真的继承」。
4. 修法：新增 `GlobalGameState.reset_to_defaults()`（把所有**落盘字段**清回默认值），
   在 `load_global_game_data()` 里判定「主档与 .bak 都不存在」时先 reset 再 return。

## 关键决策与理由

- **reset 放在 `load_global_game_data()` 里，而不是 `User._on_button_ok_pressed()` / `Global.reload_session_for_current_user()`** ——
  因为「读不到档 = 用默认值」是**读档函数**自己的语义，放在这里任何调用方都覆盖得到；放进 UI 流程里，
  下次有人从别处调读档又会漏一次（切用户这条链已经有「忘了发 `user_session_switched`」的前科，见
  [2026-10-03_主菜单未解锁入口改隐藏](2026-10-03_主菜单未解锁入口改隐藏.md)）。
- **判「新用户」要看主档 **和** `.bak` 两个文件** —— 只判主档的话，「主档没了但备份还在」会被误判成新档，
  把 `_load_json()` 的备份回退（损坏保护第二层）绕过去。
- **`reset_to_defaults()` 只清落盘字段，不动 `curr_zombie_boss`** —— 僵王列表没有写进 `save_now()` 的字段表，
  不属于存档，清它属于误伤。
- **顺手把 `curr_zombie` 的字面量提成 `DEFAULT_CURR_ZOMBIE` 常量** —— 否则 reset 时又要复制一份 26 行的枚举列表
  （两处写必漂移）。

## 踩坑

1. **新用户继承旧档** → 读档是「只覆盖读到的键」，没档时**一个键都不覆盖**，`GlobalGameState` 里的旧运行态原样留下 →
   **正解**：没有可用档时必须显式 `reset_to_defaults()`，**不能**靠「不动 state 就是默认值」的假设。
2. 同一个坑的**表兄弟**（仓库里已踩过两次，记在这里好一起想）：
   - 损坏档如果按「返回 `{}`」处理，60 s 后自动存档会把空档固化 → 正解是隔离 + 锁写（见
     [2026-10-08_批量回归跑批与存档损坏兜底](2026-10-08_批量回归跑批与存档损坏兜底.md)）。
   - 切用户后主菜单解锁表现不刷新 → 正解是 reload **之后**发 `user_session_switched` 信号。
   三件事的共性：**「内存里的运行态」和「盘上的档」不是一回事，凡是切换 / 重置的场合都要显式对齐。**
3. **已被污染的档不会被本次修改自动清掉** —— 修复只保证「以后新建的用户是干净的」，
   之前那个新用户目录里已经有一份写着旧数据的 `GlobalSaveGame.json`，必须人工删（见下）。

## 给后来者的最简路径

1. 先确认盘上路径带用户名（不带 = 真串档，先修路径）；带 = 泄漏在内存。
2. 跟切用户调用链到读档函数，看「文件不存在」那条分支是不是直接 return。
3. 加 `reset_to_defaults()`，在「主档 + .bak 都不存在」时调用；别只判主档。
4. 人工清污染档：删掉 `%APPDATA%/Godot/app_userdata/PVZ-Dream-Edit/<新用户名>/GlobalSaveGame.json`
   （连同 `.bak`、`.tmp`），重开游戏即可。
