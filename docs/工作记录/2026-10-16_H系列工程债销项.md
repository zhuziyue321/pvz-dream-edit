## 关键决策与理由

- **落盘不追求「历史漂亮」**：原本想按「伤害系统 / 各模组 / 文档」切，但 id 常量表迁移横跨 597 个文件，任何按目录切都会切碎同一条主线、产生不可编译的中间态。最终按「代码 / 模组 / 文档」切 4 笔 —— **先保证不丢**。
- **云端 CI 否决**：`assets/` 不入库（版权），云端 checkout 后 `--import` 引用不到贴图必然假红 —— 有 CI 也拿不到真信号，所以只做**本地 pre-push 钩子**。
- **`probe_plant` 判 SKIP 而非 FAIL**：种植失效经带窗口实测确认属合成输入限制、不是游戏问题；留着 FAIL 只会训练人忽略红色。
- **用 `git commit -- <paths>` 而非 `git add -A`**：发现工作区有**另一个会话**的未提交改动，精确提交避免把别人的半成品带进去。

## 踩坑

1. `probe_bullet_camp` 报「僵尸方 mask 769，期望 1281」→ **错的是探针**：它把已废弃的 layer 11（`Deprecated_BeHypnotizedReal`，位值 1024）当成了植物受击层；而 `BulletCampConfig.C_CampEnemyMask` 的正确口径是 **256 + 512**（512 必须含 —— 魅惑僵尸与普通僵尸同在 layer 10，敌我改由归属阵营判断）。**正解**：改探针期望值，并把数字口径写进注释；判断依据是「运行期实测值 + 配置注释」，不是猜。
2. 跑 `run_autopilot.ps1 -Scenario probe_bullet_camp` 却执行了 `probe_zhaoxiao_cherry` → 原以为是脚本 bug，实际是**有残留 Godot 进程占着输出文件**，读到了陈旧内容。**正解**：跑批前先 `Get-Process | Where-Object { $_.ProcessName -like "*godot*" } | Stop-Process -Force`，跑完再看一次残留数。
3. `git add -- './*.md'` 想只加根目录的 md → git pathspec 里 `./` 会被规范化掉，`*.md` **匹配所有层级**，把 4 个无关文档一并暂存并提交。**正解**：`git reset --soft HEAD~1` + `git restore --staged .`，改用**逐个明确路径** `git add -- '架构总览.md' 'docs/TODO清单.md' …`（中文路径参数可正常传入，不必绕道）。
4. 拿 `read_file` 的显示去做 `old_str` 时，误以为某行有 `**` 加粗，连试两次匹配失败 → 用 `search_content`（ripgrep 原文）核对才发现是自己抄错。**正解**：编辑长表格行前先用 `search_content` 取原文，别凭 read 的显示记忆。

## 给后来者的最简路径

1. `git status --short` 看清工作区 —— **先分辨哪些改动是自己的**（本次就撞上并行会话）。
2. 改动涉及 `.gd` → 先跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`（秒级）。
3. 要落盘 → `git add` **逐个明确路径**，别用 `-A` 或通配（尤其 `*.md`）。
4. 要跑探针 → 先杀残留 Godot 进程，再 `run_autopilot.ps1 -Scenario <名>`（默认引擎路径已修好，可不传 `-Godot`）。
5. 销项 → 在 `docs/TODO清单.md` 从 §3.x 移进 §4，写清「怎么解决的」。
