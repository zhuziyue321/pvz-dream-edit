# 2026-10-05 · 其它 · 补全僵尸迷阵（Beghouled）的植物升级逻辑

> **任务类型**：其它（既有玩法的逻辑补全）
> **推荐度**：**推荐**（下次给「异步换场类玩法」补保护照这个走：状态锁 + 收尾校验 + 探针断言）
> **耗时与成本**：约 1 轮对话，带窗口跑探针 `probe_beghouled`（24 断言全过），画面手感仍需人工看一眼
> **验证方式**：带窗口探针实测
> **补充自**：[2026-10-04\_实现僵尸迷阵Beghouled.md](2026-10-04_实现僵尸迷阵Beghouled.md)（本条是它的后续补全）

## 目标

把「僵尸迷阵」里三档植物升级（豌豆射手→双重射手 1000 / 小喷菇→大喷菇 500 / 坚果→高坚果 250）从
「能扣钱 + 能换实例」补成一条**闭环**：换场期间不许玩家插手、换完保证盘面还能玩、
计数器上的 UI 不再写死按钮数。原先只有「买成功」这一步是真的，换场过程与收尾都留了口子。

## 步骤

1. 先读 `beghouled_manager.gd` 的升级链路（`try_buy_upgrade` → `_replace_all_plants`），
   顺着「先 `character_death_disappear()` 再等两帧才能 `create_plant`」这个既有写法找空隙 ——
   这两帧里棋盘是半空的，而当时只有 `is_resolving` 一把锁，**管不到换场**。
2. 加 `_is_replacing` 状态位 + 统一的 `_can_operate()`，把 `_on_click_cell` / `try_shuffle` /
   `try_fill_crater` / `try_buy_upgrade` 四处判据收拢过去（原来各处分散写 `not is_resolving`）。
3. 抽 `_ensure_board_playable()`（无现成连线 + 有步可走，缺一就 `_shuffle_plants()`），
   原先只有 `_resolve_board()` 收尾有这段，现在开局口径、结算收尾、换场收尾三处共用。
4. `_self_removing` 的解锁从「同步遍历之后」延到「重新种完之后」，并在 `_on_plant_free` 里也认 `_is_replacing`：
   万一步回调延后一帧落到空档里，会被当成「被僵尸啃掉」留一个不该有的弹坑。
5. `beghouled_ui.gd` 的按钮数改由 `ConstBeghouled.UPGRADE_LIST.size() + EXTRA_BUTTON_NUM` 生成，
   `_on_button_pressed` 的 `match 0,1,2 / 3 / 4` 换成按下标区间判断 —— 加减升级档不用再改 UI。
6. 探针 `probe_beghouled.gd` 的 STEP5 补 4 条断言（换场后无连线 / 有步可走 / 买第二次返回 false / 锁已解开）。

## 关键决策与理由

- **不把 `try_buy_upgrade` 改成 `await`** —— 原来的注释写明「按钮要立刻拿到买成了的结果」。
  Godot 里同步调用协程函数拿不到返回值，改成 await 会连带把 UI 回调与探针断言（`mgr.try_fill_crater()` 那类）一起坏掉；
  所以保留「同步返回 bool + 内部起协程」的形态，用状态位加锁。
- **换场收尾用「保证还能玩」而不是「自动消一次」** —— 理论上 `from → to` 全量替换不会产生新连线
  （三个 `to` 相邻意味着三个 `from` 相邻，而那早就被结算掉了），所以此处只兜「可能出现」的情况；
  真出现时 `_shuffle_plants()` 一步同时满足「无连线 + 有解」，比临时写一套消除更省事。
- **`_replace_all_plants` 里顺手 `_clear_select()`** —— 换场会把玩家选中的那株删掉，不留才会留着一个指向空植物的选中框。
- **没动 `try_fill_crater`** —— 填坑补位同样可能凑成连线，但它现有行为（下一次操作时被 `_resolve_board` 一并结算）
  不算错，改它会把 `bool` 返回值变成协程返回值，风险大于收益，**留作后续**。

## 踩坑

1. **`str(to_type)` 打出来是 `8` 不是植物名** —— 枚举转字符串只给序号。
   → **正解**：日志改打数量「N 株植物已换成升级版」，要名字就在购买那条日志里打 `info["name"]`（那里有）。
2. **Godot 的 `set` 允许外部访问下划线私有变量** —— 探针直接断言 `mgr._is_replacing` 是能跑通的，
   代价是改动私有字段名会连探针一起坏；仓库其它探针（如 probe_beghouled STEP2 的 `mgr._build_type_grid()`）也是这个写法，保持一致。

## 给后来者的最简路径

1. 给「会 `await` 的玩法流程」补保护：加一个 `_is_replacing` 之类的状态位，再把所有「玩家能点」的入口
   收拢到一个 `_can_operate()`，别在每个函数里各写一遍 `not is_resolving`。
2. 「我自己拿走的」这类标志（`_self_removing`）要覆盖到**整个异步区间**，不能被 `await` 切成两段，
   否则中间的回调会被当成外部事件处理。
3. 任何会大改棋盘的操作（换场 / 洗牌 / 开局摆场）收尾都调同一个 `_ensure_board_playable()`：
   一处口径，三处复用。
4. 按钮数量写死（如 `for i in range(5)`）的地方，改成按常量表的 size 生成，顺手把 `match index` 换成区间判断。
5. 跑探针：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_beghouled -Windowed`
   → `[BEGHOULED] result=PASS`；不确定的地方先加断言再改代码。

## 人工验证方法（本次没盯画面的部分）

- 进迷你游戏第 5 关，底部按钮按豌豆 / 小喷菇 / 坚果的顺序排列三个升级 + 重置 + 填坑。
- 攒够阳光买一档升级：**那一瞬间全场的同类植物同时换成升级版**（约 2 帧的空档不可交互），
  按钮变「已购买」，再点没反应。
- 换完之后画面上不该出现「已经连成三个」的静止连线，也不该出现无处可走只能再花 100 洗牌的死局。
- 换场那两帧里连点 / 点相邻格子：点击不会被受理，棋盘不会错位，也不会在空白处留下弹坑。
