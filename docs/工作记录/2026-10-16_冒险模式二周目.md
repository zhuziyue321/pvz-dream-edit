# 2026-10-16 · 玩法 / 冒险进度 · 加入二周目（通关 5-10 后从 1-1 重打，解锁全继承）

> **任务类型**：玩法机制（冒险模式进度）
> **推荐度**：**推荐**（「给一个已有系统加一层维度」的活，关键在**先把旧口径拆成两条**再动数据）
> **耗时与成本**：约 1 轮对话；**未开游戏**；无头探针 4 次（1 条新的 + 1 条改写 + 2 条回归）
> **验证方式**：编译门禁 PASS（120 个 scenarios）+ `probe_adventure_round` PASS（含端到端真通关 5-10）/ `probe_adventure_next_level` PASS
> **补充自**：[2026-10-16_冒险模式去掉选关界面.md](2026-10-16_冒险模式去掉选关界面.md)（承上：那条把「按进度只能打下一关」定下来了，这条在它上面加周目）

## 目标

通关冒险模式 5-10 后**自动进二周目**：周目 +1、冒险进度回到 1-1、**已解锁的一切全部保留**；
玩法差异按原版只加一条：二周目起 1-1 ~ 1-3 直接给满 5 行草皮。周目无上限。

## 最简路径（步骤）

1. **先别动数据，先拆口径**：把「已通关最大冒险关卡」这件事拆成两条 ——
   `get_adventure_round_cleared_level()`（本周目，决定该打哪一关）与
   `get_max_success_adventure_level()`（历史最高，所有解锁门照旧读它）——再加周目字段与 `advance_adventure_round()`。
   拆完回头看：**「进度清零」根本不需要写**，它是过滤的结果。
2. 存档侧三处登记：`save_now()` 的字段表、`load_global_game_data()` 的 `data.get(键, 默认)`、`reset_to_defaults()`
   （**不用动 `_migrate_save_data()`**：老存档没有这个键 → 读成周目 1，正是「老档 = 一周目」）。
3. 通关写档时给**冒险模式**的记录补一个 `"Round"` 键（`MgmSaveManager.update_level_state_data_success()`）。
4. 进周目的唯一入口放 `MgmRewardManager.win_main_game()` 写档之后，两道前置：本关是 5-10 + 本周目全通（幂等）。
5. 玩法差异走数据：`ResourceLevelData.map_data_from_second_round` + `resolve_map_data()` 里按周目换图，
   1-1 / 1-2 / 1-3 各填一行 `preload(".../map_front.tres")`。
6. 界面：木牌关卡号改读本周目进度；`LevelText` 下加 `RoundText`（一周目隐藏，二周目起显示 `2周目`）。
7. 探针：新的 `probe_adventure_round`（含端到端 `shortcut_win_main_game()` 打 5-10 + 重读存档）、
   改写 `probe_adventure_next_level` 的「全通」那一步；文档新建 [../参考存档/二周目.md](../参考存档/二周目.md) 并回改三份旧文档。

## 关键决策与理由

- **解锁看历史、打关看本周目**（两条口径分家）：二周目要「继承」与「重来」同时成立，这两件事只能由两个函数分别承担。
  两个方向都推演过：让本周目驱动解锁门 = 商店 / 图鉴 / 迷你游戏全变回未解锁；让历史最高决定打哪一关 = 一进二周目又被丢回 5-10。
- **进度清零靠 `Round` 过滤，不删记录**：不删 → `save_service._build_curr_plant()` 照旧按记录重建植物，商店 / 花园 / 图鉴全不受影响；
  删 → 到处静默对不上。**「能算出来的状态不要写下来」**是这次最省事的一步。
- **进周目只认 5-10 + 全通，且幂等**：`win_main_game()` 里先按本关是不是 5-10 挡一道（迷你 / 解谜 / 生存通关不许碰周目），
  `advance_adventure_round()` 自己再核一遍全通 —— 重打 5-10、调试写半通都不会误进。
- **换图放 `resolve_map_data()`，不放「拼进关参数」**：进关的路不止主菜单一条（联机 / 探针 / 调试都自己拼参数），
  关卡数据自己看周目才不会漏；而且这是子管理器按图建格之前唯一的时机。
- **周目只显示在木牌上（`LevelText/RoundText`）**：挂在 `LevelText` 下，没开打冒险模式时随关卡号一起隐藏；
  一周目不显示 —— 玩家第一次通关前不该看到「周目」这回事。

## 弯路 / 踩坑（三段式）

- **试过**：在 `advance_adventure_round()` 里顺手把 `curr_all_level_state_data` 的冒险记录清掉（当作「进度清零」）。
- **因为**：那时把「进度」理解成一份数据；清完才发现 `_build_curr_plant()` 是按记录重建植物的，且商店 / 图鉴 / 花园的解锁门也是按它推的。
- **结论**：改成「只动周目数，进度靠 `Round >= 当前周目` 过滤算出来」。顺带老存档兼容也不用特判（没有 `Round` 键 = 周目 1）。

- **试过**：把「进周目」判定写成 `if get_adventure_round_cleared_level() >= 50` 就调 advance（不判本关是不是 5-10）。
- **因为**：觉得反正 `advance` 内部会核「本周目全通」。
- **结论**：**还是得先按本关挡一道** —— 调试快捷键（`Ctrl+D` `1`）会把当前周目写成全通却不进周目，
  这时去打任何一关（哪怕是迷你游戏）结算都会把周目顶上去。两层判定各管一件事：本关是 5-10（谁有资格）+ 本周目全通（条件够不够）。

- **试过**：`replace_in_file` 一次替换 70 行（STEP5 循环体 + STEP6 整段一起改）。
- **因为**：想省一次工具调用。
- **结论**：那次的 `new_str` 缩进整体漏了一层 tab（GDScript 直接编译不过）—— 大段替换后**立刻跑一次 `check_scripts.ps1`**，
  比肉眼看缩进快得多；替换超过 ~30 行时拆成两次。

## 推荐度与理由

**推荐**。这类「给已有系统加一层维度」的活，顺序反了就会白干：
先想清楚**哪些旧口径必须拆成两条**（这里是「解锁」与「打哪一关」）、**哪些状态该算出来而不是写下来**（进度清零），
数据层反而只剩三个登记点 + 一个 `Round` 键。周目这种「第二轮」的机制都长这样，可以照抄这次的骨架。

## 遗留

- 二周目的玩法差异**只有 1-1 ~ 1-3 满草皮**（按原版口径）。出怪表 / 难度 / 卡槽都没按周目变 ——
  想加就照 [../参考存档/二周目.md](../参考存档/二周目.md) §6 那个模板（字段声明在关卡、运行期两个合法时机读周目）。
- 二周目**没有任何提示演出**（只有日志 + 木牌上的 `N周目`）：原版也没有「第二轮开始」的过场，先这样。
- 探针覆盖不到「玩家真的点着打完 5-10」：端到端那段走的是 `shortcut_win_main_game()`（Ctrl+D 0），
  与「一波波打完触发 `force_win_on_flow_finished()`」是同一条结算入口但不同触发者。
