# 2026-10-13 · 排查调试 · 让联机模组在「没开房间」时完全没有行为

> **任务类型**：排查调试
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话 / 未开游戏窗口（无头跑 `probe_netplay_session` + `boot_level` 两个场景）/ 无需人工介入
> **验证方式**：打开游戏实测的**等价替代** —— 无头 autopilot 跑两个场景（联机地基探针 PASS + 单机一局输出里零联机日志）
> **补充自**：无

## 目标

启用联机模组但**没有开启房间**时，联机必须零行为：单机一局的输出里不该出现任何「联机模组」字样，
本局里不该多出任何联机节点，本体的闸门一个都不该被占住。

改之前的输出（用户贴的那一段）：

```
ModManager: 已装载模组 [netplay] 联机
联机模组：会话已就绪（默认端口 8912）      ← 没开房间却在报会话
联机模组: 已接入本局，玩家操作开始上行      ← 单机却在说"上行"
主游戏开始
```

## 步骤

1. 先定位两行日志的来源：`netplay_mod.gd` 的 `_ensure_session()`（`install()` 里调）与
   `NetplaySession.attach_main_game()`（`install_to_main_game()` 里**无条件**调）。
   → 结论：会话**在模组启用那一刻就建好了**，与本局有关的动作没有过 `is_linked()` 这道闸。
2. `install()` 改为**什么都不做**（会话懒加载），建会话的时机推迟到玩家按「开启房间 / 加入房间」
   的那一刻：`_ensure_session()` 返回值改成 `NetplaySession`，两个按钮先取会话再开 / 加入。
3. `_ensure_session()` 里**直接 `add_child()`**，不再 `call_deferred()`（详见踩坑 1）。
4. `install_to_main_game()` 开头加一道 `if 没会话 or not is_linked(): return`，
   并把下面每一处重复的 `if _session.is_linked():` 全部去掉（早退之后它们恒真，留着只会漂移）。
5. 同步更新探针：地基探针 1「会话挂载」改成先断言「没开房间时 `/root` 下没有会话」，
   再调 `mod._ensure_session()` 造出来；两个双进程对拍探针同样改用 `_ensure_session()` 取会话。
6. 文档：`联机模组规范.md` §1.1 / §1.3 写进「没开房间 = 零行为」这条纪律；`联机模组.md` 补懒加载、
   并把第 839 行那条「`add_child` 被拒 → 延迟挂」的旧坑改成历史 + 新结论。

## 关键决策与理由

- **会话懒加载，而不是"照旧建、只是不打印日志"** —— "启用模组"和"开了房间"是两件事：
  日志只是表象，真正的边界是**root 下有没有那个节点、本局有没有那批同步节点**。
  判据写成一句话：**开着联机模组单机玩一局，输出里不该出现「联机模组」这五个字**。
- **`install_to_main_game()` 用一次早退取代十余处 `is_linked()`** —— 原写法每个同步节点各判一次，
  新增一种同步时漏判一次就又"单机也装"；早退之后漏无可漏。
- **不再记 `_last_level_key` 的那句"不看有没有连线"** —— 它原本是为"房主先自己进关、之后才开房"留的；
  现在那条路本来就一个同步节点都不装，而 `_remembered_mode()` 还有 `Global.game_para.game_mode` 兜底
  （要退关的那一刻人还站在关卡里），少记这一笔换来的零行为更值。
- 状态行（面板「状态」）在没会话时写「未连接 ／ 没开房间」而不是「会话未就绪」 ——
  对玩家来说那一态就是"没在联机"，也顺带保住了探针里"状态初值为未连接"那条断言。

## 踩坑

1. **不能直接把 `call_deferred("add_child")` 原样搬到懒加载路径** —— 延迟挂的年代会话是在 autoload
   `_ready()` 里造的（`root` 还在装配子节点，直接挂会被拒）；改成按按钮时才造之后，装配早就结束了，
   而紧接着就要 `create_host()` / `join()` —— RPC 走节点路径，**人还没进树一条都发不出去**。
   → **正解**：`tree.root.add_child(session)` 当场挂，只在极罕见的"挂不进去"时退回帧末再挂一次。
2. **探针照旧去 `/root/NetplaySession` 取会话会全军覆没** —— 地基探针有 10 段、双进程对拍有 2 处
   都是"启用模组 → `await` 几帧 → `get_node_or_null("/root/NetplaySession")`"，懒加载之后一律取到 null。
   → **正解**：探针里显式走 `_ensure_session()`（那本来就是「开启房间」按钮走的那一步），
   并在第 1 段把"没开房间时 root 下没有会话"变成一条**断言** —— 零行为从此有回归守着。
3. **`_check_session()` 里加了 `await`，`run()` 里必须 `await` 调用** —— 不然后半段断言会在它挂起时
   抢跑（本仓库 `probe_netplay_session.gd` 里 `_check_sun_sync()` 那条注释是同一类坑）。

## 给后来者的最简路径

1. 判定"该不该在没连线时做"：**没开房间 = 什么都不做**（会话都不建）。
2. 入口收在 `NetplayMod._ensure_session()`（懒加载 + 当场进树）与 `install_to_main_game()` 开头那道
   `is_linked()` 早退；其余地方不要再造第二个入口。
3. 交付前跑两个无头场景即可（`boot_level` 看单机输出干净、`probe_netplay_session` 看契约没破）：

```powershell
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario boot_level -MaxSeconds 120
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_netplay_session -MaxSeconds 180
```
