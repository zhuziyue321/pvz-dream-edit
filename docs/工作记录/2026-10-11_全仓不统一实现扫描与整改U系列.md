## 关键决策与理由

- **U-05 选「移出 `components/`」而不是「接入组件基类」** —— 2026-10-08 已判定 `drop_body` 不接入（激活后 `reparent()` 走并自我销毁，不是「挂在角色上随角色生灭」的组件语义）。把目录挪出去同样消除「`components/` 下可以不继承基类」的误导，**且不动运行时语义**，比强行接入省事也安全。
- **U-02 合并前先逐行比对两份表** —— 万一有漂移，合并就等于「用一份静默覆盖另一份」。本例确认同值才敢删。
- **U-01 连转发属性一起删** —— 留着 `Global.main_game` 就会不停有人再写，双轨永远消不掉。删前确认全仓非注释行 0 处引用、无 `Global.get("main_game")` 动态访问。
- **U-11 的撞车枚举没改名，改成互相指名的注释** —— `E_PotMode`（关卡级：罐子怎么生成）与 `E_PotType`（单罐：装的是植物还是僵尸）语义本就不同；改名会让 2026-10-04 那批工作记录里的旧名对不上代码，收益 < 代价。
- **U-10 只改文件 / 目录名，类名 `ZB001Doctor*` 未改** —— 类名里的 `001` 是**角色编号**语义不是目录编号，改它要动 100+ 处引用，收益 < 风险。
- **历史工作记录里的旧名一律不改** —— 它们是当时的快照，改成新名等于篡改历史；只同步现行文档（架构总览 / 参考存档 / TODO）。

## 踩坑

1. **批量替换把「对表赋值」也改了** —— `MainScenesMap[X] = path` 被正则换成 `get_scene_path(X) = path`，编译报 `Only identifier, attribute access, and subscription access can be used as assignment target`。→ 我预判性地先搜过 `MainScenesMap(?:[^\[]|$)` 检查赋值写法，**但这个正则漏掉了 `MainScenesMap[X] =`（`[` 不匹配 `[^\[]`，所以整行没被搜出来）**。→ **正解**：检查「有没有非读取用法」要直接搜**赋值形态** `MainScenesMap\[[^\]]+\]\s*=`，不要绕道搜「后面不跟 `[`」；顺带给注册表补 `set_scene_path()` 供模组注入。
2. **`CharacterRegistry.get_zombie_info()` 编译报 `Cannot call non-static function`** —— 访问器是**实例方法**，按类名静态调用不行。→ **正解**：`Global.character_registry.get_zombie_info(...)`。
3. **给基类加 `owner_character` 后 3 个子类报 `member already exists in parent class`** —— 它们各自有 `@onready var owner_character`，会遮蔽基类同名成员。→ 删掉子类定义走基类。其中 `CharredComponent` 是 `extends Node2D` 根本拿不到基类访问器，**顺手让它接入 `ComponentNormBase`**（它本来就是 Node2D，场景节点类型不用改）。
4. **改了引用却忘了加定义** —— `sound_manager.gd` 里把 `load("uid://...")` 改成常量 `RAIN_SFX`，却没定义它，报 `Identifier "RAIN_SFX" not declared`。→ **正解**：「改用常量」和「定义常量」当**同一次**编辑，别分两刀。
5. **僵王重命名只改 `src/`，漏了 `animation/` 与 `data/` 下的同名目录** —— 编译虽然 0 错误，但资源加载报了一屏 `[ext_resource] referenced non-existent resource`（我把引用改成 `doctor/`，而那里的真实目录还叫 `001_doctor/`）。→ **正解**：**动手前先全仓搜「哪些目录 / 文件含这个字符串」**，别只搜自己那个子树；`.tscn` 的 ext_resource 有 uid 兜底也不顶用（uid 指向的是改名后的路径，而磁盘上还没改）。
6. **PowerShell `-Include` 写成 `.md`（漏了 `*`）** —— 那一轮 md 替换静默 0 命中，我以为同步过了。→ **正解**：写 `-Include *.gd,*.tscn,*.tres,*.md`，并在脚本末尾回显 `FILES=`/`HITS=` 计数跟预期对一下。
7. **登记阶段误判了 3 条**（U-07 / U-12 / U-13）—— 只比「命中数」不看「语义」就会冤枉人：
   - `ZB001DoctorStateMachine` 是 `extends CharacterStateMachine`（**继承扩展**，正是通用机文档写的「专用状态机扩展」，不是另起一套）；
   - `TreePauseManager` 实际有 **10 处调用**（我登记成「仅 2 处」），而 `process_mode = PROCESS_MODE_ALWAYS` 那 5 处每一处都是「全场暂停时仍要跑」的**豁免**（相机 / 卡槽 / 联机准备按钮 / 调试通道）—— 两者**互补**不是重复；
   - 「89+ 文件裸 `.play()`」里绝大多数是 `AnimationPlayer.play()`，`AudioStreamPlayer` 在 `src/` 下只出现 **2 处**，音效其实已收口到 `SoundManager`（87+ 文件调用）。

   → **正解**：**判定「不统一」前先确认两种写法是不是在解决同一个问题**；粒度不同（整树 vs 单节点、场景文件 vs 背景视觉）不算重复。
8. **`probe_plant` 长期 FAIL，不是本次引入** —— 症状「已种槽位=0、阳光未扣」在 10-02 / 10-03 / 10-04 / 10-06 / 10-08 五份记录里都出现过（教程关 1-1 拦住种植）。→ **正解**：改种植链路时用它回归会误判，改用 `probe_hand`（覆盖持卡 / 种植 / 铲子 / 取消，PASS）。

## 给后来者的最简路径

1. **先跑一遍目标探针留基线** —— 本仓没有全量基线（88 个探针跑一遍 30~60 分钟），「某个探针红了」无法自动区分新旧；至少 grep 确认失败点不涉及自己改的符号。
2. **批量替换前**：① 搜**赋值 / 非读取**用法（踩坑 1）② 先估一个预期命中数，替换完跟 `HITS=` 对一下（踩坑 6）。
3. **每批改完立刻跑门禁**，别攒。
4. **移动 / 改名目录**：先全仓搜「含这个字符串的目录与文件」—— 除 `src/` 还有 `animation/` `data/` `addons/`（踩坑 5）。
5. **判定「不统一」前先核实语义**，别只比命中数（踩坑 7）—— 本轮 13 条里 3 条是误报，占 23%。
6. 涉及视觉的用 `probe_zomboss_layout` 看「博士已出场」即可；它**必然看门狗超时**（信息输出型探针，不是失败）。
