# 2026-10-22_掉落物逻辑重构

> **本次任务**：把钱 / 巧克力 / 种子包 / 礼包 / 阳光五类掉落物的公共逻辑收进一个基类与两个生成口，并补上多轮关卡的掉落物清理
> **耗时 / 轮次**：一轮（先探索后改）；编译门禁 + 11 个探针验证（未开带窗口的游戏）
> **推荐度**：推荐

## 目标

掉落物原本是 3 条互不相干的链路，没有基类、没有统一注册表：
生命周期四套实现五个默认时长、抛物线复制四份、阳光的「弹起再落下」复制七份、
类型→场景的 if/elif 在 `DropItemManager` 与 `DIM_Coin` 各写一遍，`ItemRegistry` 是空壳。
本次按「允许小幅修正」的口径收成一条骨架 + 两个生成口，并顺手修掉落点夹取的坐标口径与残留。

## 最简路径（步骤）

1. `test/check_scripts.ps1` 先跑一次确认基线干净（改动前也要跑，便于区分既有失败）。
2. 新建 `src/items/drop/drop_item_base.gd`（骨架）、`drop_position_util.gd`（落点收敛）、
   `sun_spawner.gd`（阳光生成口）、`src/managers/drop_item_manager/dim_base.gd`（DIM 公共壳）。
3. 五个实体改成 `extends DropItemBase`，各自只留 `pick()`；给 `TweenUtil` 补 `fade_scale_out_and_free()`。
4. `ItemRegistry` 填 `E_DropKind` + `DROP_SCENE_MAP`；`DropItemManager` 留一个转发常量
   （老代码 / 联机模组 / 探针写的是 `DropItemManager.E_DropKind`）。
5. 七个阳光生成点改调 `SunSpawner`；僵尸掉钱改调 `DropPositionUtil`。
6. `DropItemManager.clear_all_drops()` 挂到 `MainGameManager.start_curr_round_game()`。
7. 再跑门禁，然后 `run_autopilot.ps1 -Scenario <name>` 跑相关探针（见下）。

## 弯路 / 踩坑（三段式）

- **试过**：让 `DIM_Base.instantiate_drop()` 一步到位（实例化 + `add_child`）。
- **因为**：编号 `entity_id`、存在时长 `auto_free_time`、提示时长 `tip_show_time` 都要在**入树之前**
  给（`_ready()` 当场就按它们分编号 / 起定时器），一步版会把这些字段设成无效值。
- **结论**：拆成 `create_drop()`（不挂树）+ `add_drop()`（挂树）两步，一步版 `instantiate_drop()`
  只在不需要预置字段的场合用；`Present.icon_texture` 补一个 setter，入树后再赋值也能自己应用贴图。

- **试过**：把 `Sun.collected` / `Coin.is_get` 直接删掉，全仓改成 `is_opened`。
- **因为**：`pointer_target_resolver.gd` 与 4 个探针在读 `sun.collected`，编译门禁**不报**（静态解析不到），
  只有跑探针才炸（`Invalid access to property or key 'collected'`）。
- **结论**：`collected` 一并改名（业务 + 探针都改）；`is_get` 留成映射到 `is_opened` 的属性
  （花园蜗牛在读）。教训：**改字段名后必须跑探针，不能只看门禁 PASS**。

- **试过**：相信 `probe_snail_eat_coin` 的超时是我引入的。
- **因为**：探针 `if coin.is_get or not is_instance_valid(coin)` 先取值再判空，
  钱超时被 `queue_free` 后在已释放对象上取值直接抛错、把整个探针协程打断 —— 与重构无关。
- **结论**：把判空提到前面（一行），探针就能跑完。**既有探针失败先读它的断言，别急着改业务代码**。

## 既有失败（与本次无关，别背锅）

- `probe_card_lock`：「商店生成 9 个植物卡商品」实际 10（工作区里加了 DLC 植物）。
- `probe_hammer_zombie`：出战卡列表为空（卡槽 / 卡片侧的问题）。
- `probe_shop_expand`：还在断言 4-4 的 `drop_unlock_*`，而 4-4 的玉米卷早已改走
  `level_complete_loot = "taco"`（战利品线）—— 探针过期。
- `probe_snail_eat_coin`：偶发「钱没生成」（蜗牛在 1.5 秒内就把钱吃掉了），属探针时序脆弱。

## 推荐度与理由

推荐。骨架落地后新增一种掉落物只需要：注册表加一行 + 新脚本写 `pick()` + `DIM` 挂一行。
后来者注意两点：① 入树前字段用 `create_drop()` / `add_drop()`；② 改字段名后一定跑一遍相关探针。
机制细节见 [../参考存档/掉落物说明.md](../参考存档/掉落物说明.md)。

## 补充 / 评价（2026-10-22 · 处理 4 个既有探针失败）

> **本次记录**：[2026-10-22_掉落物逻辑重构.md](2026-10-22_掉落物逻辑重构.md) ←→ 被补充：本文件

- **补充**：交付时留下的 4 个「既有失败」全部处理完（都不是本次重构引入的）：
  1. `probe_shop_expand` —— 探针还在断言 4-4 的 `drop_unlock_*`，而玉米卷早已改走
     `level_complete_loot = "taco"`（LootRegistry 战利品线）。改成断言 `level_complete_loot` +
     `LootRegistry.get_texture()`，掉落改调 `create_loot_drop()`。
  2. `probe_card_lock` —— 商店数出 10 个「植物卡商品」：坚果包扎术摆在模仿者同一行
     （原版货架顺序），它不是植物卡。改成只数 `GoodsPlantCard`，并另加一条「同行非植物卡商品 = 1」。
  3. `probe_hammer_zombie` —— 出战卡恒空：**`Card.card_plant_type` 是 `StringName`，不是老整数编号**，
     而探针写的是 `Array[int] = [15, 12, 5]`；把 StringName 塞进 `Array[int]` **不报错、静默丢空**，
     于是 `got` 一直是 `[]`。改成 `Array[StringName]` + `PlantIds.ICE_SHROOM` 等常量。
     顺带加了「等卡槽就绪（最多 20 秒）」的轮询。
  4. `probe_snail_eat_coin` —— 偶发「钱没生成」：等 1.5 秒再去看容器时，钱已经被蜗牛吃掉并释放了。
     改成 0.2 秒一趟轮询取第一枚（最多 3 秒）；连跑两次都是「吃到 4 / 4」。
- **评价**：4 个里有 3 个是**探针过期 / 脆弱**，1 个（3）是探针把字段类型写错。修完门禁 PASS、
  四个探针全 PASS。**判定「既有失败」的正确姿势**：先读探针那一行断言，看它断言的机制是否还存在；
  机制已变 → 改探针；机制还在、只是取不到值 → 八成是字段类型 / 时序。
- **更省的做法**：无。踩坑点：typed array 装错类型**静默失败**（不报错也不追加），
  排查时先看 `str(数组)` 是不是空的。
