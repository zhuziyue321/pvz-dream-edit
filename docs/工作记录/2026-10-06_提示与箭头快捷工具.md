# 2026-10-06 · 其它 · 提示 / 箭头两个快捷工具取代教程里的 advice / point_*

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 2 轮对话；跑了 4 个无头探针（`probe_tutorial` / `probe_tutorial_1_2` / `probe_tutorial_1_5` / `probe_first_coin_advice`，全 PASS）；**未开窗口**（画面需人工看一眼）
> **验证方式**：无头探针全 PASS（提示条 / 箭头只有开窗口才看得见，观感需人工确认）
> **补充自**：无（同类任务第一次做）

## 目标

1. 新增**提示快捷工具**：关卡能在屏幕下方显示一段文本，也能关掉（不依赖教程）。
2. 新增**箭头快捷工具**：关卡能让箭头指向某样东西，也能关掉（不依赖教程）。
3. 用这两个工具**取代原先教程里的 `advice()` / `point_card()` / `point_sun()` / `hide_pointer()`**，
   教程侧只留「放开手 / 等玩家操作 / 收尾」三件事。

## 步骤

1. **先抽公共解析**：把 `TutorialManager` 的 `#region 指向目标`（取卡片 / 找能种的格子 / 找阳光 / 铲子 / 草坪植物）
   整段搬进新类 `src/ui/pointer_target_resolver.gd`（全静态），`TutorialManager._resolve_pointer_target()`
   改为一行转发。**不抽就要复制 ~150 行**，两套解析迟早漂移。
2. `src/ui/tutorial_advice_ui.gd` 加两块：
   - `static find_level_hint()` / `ensure_level_hint()`：按节点名 `LevelHintUI` 在 `CanvasLayerUI` 下找 / 建，
     **两个工具共用同一实例**（否则一次提示挂出两条提示条）；
   - 跟随目标：`point_to_level_target()` / `hide_arrow()` / `_update_follow_pointer()`，
     `_process()` 里优先一次性提示（跟着金币走），其次跟随目标，都没有才 `set_process(false)`。
   - `signal_advice_changed(text)`：给探针 / 调试通道跟踪「说到哪一句」。
3. 新建两个事件脚本 `level_timeline_event_hint.gd` / `level_timeline_event_arrow.gd`
   （沿用「一种事件一个脚本」，参数即 `@export` 字段）。
4. `LevelScriptBase` 新增 `#region 快捷工具：提示与箭头`：`hint()` / `hide_hint()` /
   `arrow(目标, 植物)` / `arrow_card|lawn|sun|shovel|plant()` / `hide_arrow()`；
   删掉被取代的 `advice()` / `point_*()` / `hide_pointer()`，连两个事件脚本的 `.uid` 一起删。
5. `adventure_01_01` 的教程逐句改成 `hint()` + `arrow_*()`（`wait_*` 一行不动）。
6. `TutorialManager.begin_stepped_mode()` **不再预先建提示条**（改由 `_ensure_stepped_ui()` 懒建）：
   逐步模式的关卡现在用快捷工具出提示，管理器那条只在真要显示时才有，
   否则 1-1 界面层会同时挂着两条 `TutorialAdviceUI`。
7. 探针 `probe_tutorial.gd` 的提示文本改从关卡提示条读（`_hint()` / `_hint_text()`），
   箭头断言改看 `is_pointer_visible()`，`tut.get_advice_text()` 全部换掉。
8. 同步 `docs/参考存档/新手教程.md`（新增「提示与箭头」小节 + 事件表 + 探针口径）。

## 关键决策与理由

- **只剥离显示层，`wait_*` / `TutorialManager` / `ResourceTutorialData` 全部保留** —— 用户选的方案：
  教程仍然跟着玩家操作推进，改动最小。1-2 / 1-5 是**步骤数据驱动**的教程（有 `start_zombie_wave` /
  步骤内戴夫对话 / 1-5 的 `is_opening_tutorial`），没有 `advice()` 调用，所以**一行没动**。
- **提示与箭头各自独立开关**（`hint("")` 不收箭头）—— 两个工具要能单独用；
  代价是教程收尾变成 `hint("")` + `hide_arrow()` 两句。
- **共用一条提示条实例** —— 两个工具各自 `instantiate` 会在屏幕上叠出两条黑框。
- **新脚本必须让 Godot 重新导入**：命令行跑起来报
  `Identifier "LevelTimelineEventHint" not declared` —— 新 `class_name` 不在
  `.godot/global_script_class_cache.cfg` 里。跑一次
  `Godot --headless --path <项目> --import` 就好了（见「踩坑 1」）。

## 踩坑

1. **新建 `.gd` 后直接跑探针：`Identifier "LevelTimelineEventHint" not declared in the current scope`**
   → 现象很容易误判成「写错了类名 / 忘了 class_name」，其实是**全局类名缓存没刷新**：
   命令行（非编辑器）加载的是 `.godot/global_script_class_cache.cfg`，新建脚本不会自动登记
   → **正解**：`& "<Godot.exe>" --headless --path "<项目>" --import` 重导一次再跑探针
   （导入本身报的一堆 `RID leaked` 是 Godot 退出时的噪声，无视）。
2. **`hide_pointer()` 会被 `_process()` 按回来**
   → 只调 `hide_pointer()` 而不清 `_follow_target` / 不停 `_process`，下一帧又按原目标点亮
   → **正解**：`hide_arrow()` 里三件事一起做（清目标 + `set_process(false)` + `hide_pointer()`）。
3. **`hide_advice()` 原来的语义是「连箭头一起收」** —— 拆工具后改成只收文本；
   教程步骤那条路由 `TutorialManager._process` 每帧 `hide_pointer()`（步骤 target 为 None）兜住，
   所以 1-2 / 1-5 的箭头行为不变（探针验证过了）。

## 给后来者的最简路径

1. 新工具要解析箭头目标 → 直接调 `PointerTargetResolver.resolve(main_game, target, plant_type, hint_ui)`，**别再复制一份**。
2. 关卡里出提示 / 指箭头 → `await hint("文本")` / `await arrow_card(植物)`；关掉 → `await hint("")` / `await hide_arrow()`。
3. 改完跑：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_tutorial`（新脚本先 `--import`）。
4. 改了提示条 / 箭头的显示 → 同步 `docs/参考存档/新手教程.md` 的「三个工具」小节。

## 步骤

   （1-5 的教学要先 `allow_operation()`，旧逻辑靠「教程没跑完就压着传送带」避免卡片提前掉下来）。

## 关键决策与理由

- **三个工具各管一件事，没有「教程收尾」**：用完提示 / 箭头要自己关（`hint("")` + `hide_arrow()`），
  代价是每关多两行，好处是任何关卡（包括非教程关）都能单独用其中一个。
- **`allow_operation()` 会把阶段推进到 MAIN_GAME**，所以「教学跑在开局之前」这件事不再需要
  本体给特权（`is_lawn_playable()` 只看阶段）—— 本体彻底不认识「教程」。
- **1-2 的第一波**：教学排在开战之前，天降阳光也还没开，靠 `spawn_sun()` ×2 补上原版
  （旧实现是教学与开战**并发**跑，玩家一边种一边收天上掉的阳光）。

## 踩坑

1. **探针拿 `main_game_progress == MAIN_GAME` 当「开战」判据会误判** ——
   教学里的 `allow_operation()` 也推进到 MAIN_GAME（1-5 探针因此误报「开局后传送带已启动」失败）
   → **正解**：等开战就看传送带 / 第一波（1-5 探针的 `_wait_battle_started()`）。
2. **新脚本照旧要先 `--import`**（见上面「踩坑 1」），一次性新建 8 个事件脚本时尤其容易忘。
3. 顺手修掉 `src/levels/mode_adventure/adventure_04_02.gd:24` 行尾多出来的 `]di`
   —— 一个字符让 4-2 整个关卡脚本解析失败（与本次改动无关，是上次迁移留下的）。
