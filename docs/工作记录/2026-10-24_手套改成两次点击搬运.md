# 2026-10-24_手套改成两次点击搬运

> **本次任务**：把「手套」模组的搬运交互改成两段式 —— 第一次点植物只**选中**（植物留在原格子里，
> 屏幕上是一份跟着手套走的半透明虚影），第二次点目标格子才真的搬过去。
> **耗时 / 轮次**：约 4 轮；**无头探针跑通**（`probe_hand` PASS / `probe_glove_unlock` PASS），未开窗口肉眼验。
> **推荐度**：**推荐**（要改手套 / 要给"选中态"加表现的后来者照这份走）

## 目标

旧交互是「点植物 = 把它从格子里摘出来跟着鼠标走，点目标格子 = 放下」。
玩家反馈：**植物跟着鼠标飘走很难受**（看不清它本来在哪、也分不清手上拿的是哪一株），
希望改成「植物留在原地，只有一份像选卡虚影的东西跟着手套走，第二次点击才生效」。

## 最简路径（步骤）

1. 改 `mods_builtin/glove/hand_component_glove.gd` 的状态机：
   - 状态从「手上拿着一株植物」改成「**选中了一株植物**」：
     新增 `selected_plant` / `selected_from_cell` / `carry_ghost` 三个成员，
     删掉 `curr_carry_plant` / `carry_from_cell` / `carry_ori_z_index` / `CARRY_Z_INDEX_UP`。
   - `click_cell` 分两段：没选中 → `_select_plant()`（**不摘植物**，只建虚影）；已选中 → `_move_selected_plant()`。
   - `_select_plant()`：记两个偏移（格子中心→植物原点、植物原点→身体）、复制一份身体当虚影、固定高亮这一株。
   - `_move_selected_plant()`：点回原格子 = 取消选中；目标非法 = `buzzer` 且保持选中；
     合法 = `move_take_plant()` + `move_put_plant()`，成功才 `return true`（手套回卡槽）并起冷却。
   - `mouse_enter` / `mouse_exit`：选中期间**不动高亮**（否则光标一移开，选中的那株就不亮了）。
2. 虚影的做法：`plant.body.duplicate()`（`BodyCharacter` 没有 `_ready` / `_process`，复制出来不跑行为；
   同款用法见 `Plant000Base.be_bungi()`），`modulate = Color(1,1,1,0.5)` 挂在 `%TemporaryCharacter` 下，
   `hand_process()` 里按鼠标位置摆（`_update_ghost_position()`）。
3. 手套图标**全程可见**（旧实现"拿起植物就收起手套图标"删掉）—— 需求就是"虚影跟着手套动"。
4. 同步文档：`docs/参考存档/手持物实现.md` §五、`docs/参考存档/模组机制.md` §6.1、
   `docs/验证流程.md` §3 手持物行、`mods_builtin/glove/glove_mod.gd` 的用法说明。
5. 改探针 `test/scenarios/probe_hand.gd` 第 7 节（断言从"拿起后格子已空 / top_level"
   改成"植物仍在原格 / 有虚影 / 第二次点击才搬走 / 取消后留在原格"）。
6. 编译门禁：`powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1` → `real compile errors = 0`。
7. 探针：`probe_hand` / `probe_glove_unlock` 各跑一遍（本轮用**自建输出路径**的无头跑法，见"踩坑"）。

## 弯路 / 踩坑（三段式）

- **试过**：直接 `AnimationFrameUtil.create_frame_node()` 取一帧当虚影（观星关的植物虚影就是这么做的）。
- **因为**：取帧拿到的是"标准形态"，受损的坚果 / 带壳的南瓜全都一样，玩家对不上"是哪一株"；
  而且要拿到植物场景 + 动画名，多一层依赖。
- **结论**：改用 `plant.body.duplicate()` —— 复制的就是眼前这株的样子，一行代码搞定。

- **试过**：把虚影塞进 `temporary_character` 后等下一帧 `hand_process()` 再摆位置。
- **因为**：虚影建出来那一帧位置是 (0,0)，会在屏幕左上角闪一下。
- **结论**：建完立刻调一次 `_update_ghost_position()`。

- **试过**：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_hand -Windowed`。
- **因为**：机器上还有两个 Godot 进程在跑（可能是用户的编辑器），脚本的"陈旧进程保护"直接
  `result=STALE_PROCESS` 拒跑 —— **不许用 `-KillStale`**（会杀掉用户的编辑器）。
- **结论**：自己拼一条命令跑，输出与 userdir 都换到自己的临时目录，避开共享的 `ap_out.txt`：

  ```powershell
  $tmp = Join-Path $env:TEMP "pvz_autopilot_glove"; $userDir = Join-Path $tmp "userdir"
  New-Item -ItemType Directory -Force -Path $userDir | Out-Null
  $old = $env:APPDATA; $env:APPDATA = $userDir
  cmd.exe /c '"C:\Users\a a\Desktop\godot.exe" --headless --path "<项目路径>" -- --scenario=res://test/scenarios/probe_hand.gd --autopilot-max-seconds=300 > "<tmp>\ap_out.txt" 2> "<tmp>\ap_err.txt"'
  $env:APPDATA = $old
  ```

  存档被重定向到临时目录，**不会碰真实存档**（与 `run_autopilot.ps1` 同一套做法）。

## 推荐度与理由

**推荐**。理由：

- "选中态"与"生效态"分开，是这类"手上拿着东西"的通用做法：
  状态只在**组件内部**多一个成员，本体（`HandManager` / `PlantCell`）一行没改，
  通用搬运 API（`move_*`）原样复用 —— 硬约束 §1-1 / §1-2 都没破。
- 改完之后手套不再需要 `top_level` 位移那一套（植物压根没离开过格子），
  `carry_ori_z_index` / `CARRY_Z_INDEX_UP` 这些"记原值再还原"的坑一起消失。
- 探针能断言的东西变多了：旧流程断言"格子空了"（只能证明被摘走），
  新流程能断言"植物还在原格 + 有虚影 + 第二次点击才换格子"。

需要注意的坑：

1. **探针要赶在进关之前开模组**：`ModManager.set_mod_enabled()` 只补一次全局 `install()`，
   模组是在主游戏 `init_manager()` 里装载的 —— 进关之后再开开关，这一局里根本没有手套节点。
   `probe_hand` 现在自己开、自己还原（开关是持久化的，不还原会污染同目录的其它探针）。
2. **选中期间别动高亮**：`mouse_enter` / `mouse_exit` 里都要早退，
   否则光标一移开，选中的那株就不亮了（`be_shovel_look` 被 `be_shovel_look_end()` 撤掉）。
3. **取消不用放回植物**：旧流程"拿起"过，取消要 `_put_carry_plant_back()`；
   新流程植物从没离开过格子，取消只要收虚影（`_cancel_select()`）。
4. 探针跑批时的 `ObjectDB instances leaked at exit` 是无头中途掐对局的已知噪声，不是本次改动引入的。
