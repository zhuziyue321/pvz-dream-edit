# 2026-10-03 · 关卡与地图 · 新增「生成僵王」事件，5-10 流程改为五步

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次「某个单位/某件事要在流程某一刻发生」照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（用户自测）
> **验证方式**：免验证 + 已给出人工验证方法（代码改动由 linter 与静态检查兜底，实机交给用户）
> **补充自**：[2026-10-03\_关卡特判下沉.md](2026-10-03_关卡特判下沉.md) —— 同一批「排查特判」任务的第 2 项，本次是第 1 项（僵王关）

## 目标

`MainGameManager._spawn_zomboss_if_needed()` 整段是 5-10 的私货（锚定第 3 行、两个坐标魔数、重打血量规则），
把它搬成关卡时间轴事件，由 `adventure_05_10.run_flow()` 自己排。
同时按用户要求把 5-10 开局流程改成**僵尸预览 → 移回相机 → 生成僵王 → 准备-安放-植物 → 开战**五步。

## 步骤

1. **先确认只有 5-10 一个关卡用了 `is_zomboss_fight`** —— 这条决定了能不能直接删掉通用管理器里的自动生成：
   全仓库搜下来只有 `adventure_05_10.gd:37` 设了 `true`，可以放心搬。
2. 新建 `src/levels/core/timeline_event/level_timeline_event_spawn_zomboss.gd`：
   继承 `ResourceLevelTimelineEvent`，把生成逻辑整段搬进 `run()`，
   把原先写死的三样东西做成 `@export` 参数（`anchor_row_index` / `position_offset` / `repeat_hp`），
   再加一个 `settle_time`（放进去之后等几秒，等登场动画落位）。
3. `LevelPrefabs` 加一行式门面 `spawn_zomboss(anchor_row_index = 2, settle_time = 0.0)`。
4. `adventure_05_10.run_flow()` 改成五步；**去掉了原来的 `choose_card()`** ——
   本关 `card_mode = ConveyorBelt`，`can_choosed_card` 被 `init_para()` 压成 `false`，
   选卡事件会立刻返回，留着只是噪音。
5. 删掉 `MainGameManager` 的 `_spawn_zomboss_if_needed()` 与它在 `start_game()` 末尾的调用点；
   `_setup_zomboss_hp_bar()` 改名 `setup_zomboss_hp_bar()`（事件脚本要用，去掉下划线）。
6. 同步文档：[特殊关卡.md](../参考存档/特殊关卡.md)（开关表 + 开局流程 + 生成/血条两行）、
   [关卡时间轴.md](../参考存档/关卡时间轴.md)（事件清单加一行）、
   [关卡格式V2.md](../参考存档/关卡格式V2.md)（P2 标 ✅、分支点清单里划掉僵王那行）、
   `src/levels/core/level_data.gd` 里 `is_zomboss_fight` 的注释（原先指向那个已删函数）。

## 关键决策与理由

- **事件只留行为型参数，「这一刻播什么」由流程现场给** —— 这是 [关卡时间轴.md](../参考存档/关卡时间轴.md) 的既定口径
  （戴夫对话 / 教程数据都是这么做的），新事件照抄。
- **僵王排在「准备-安放-植物」之前，而不是开战之后** —— 让它踩着红字登场，对齐原版「从天而降」的观感；
  `start_battle()` 本身要 `await` 到打完，排在它之后没有意义。
- **保留 `is_zomboss_fight` 检查，但改成 `Log.error` 而不是静默 return** ——
  这个开关还管索敌（`component_detect` 靠它决定僵王能不能被打）。
  光排事件不开开关 = 僵王站那儿谁也打不到，必须让配置漂移吵出来，不能静默。
- **`repeat_hp` 默认取 `ZombossBoss.HP_MAX_REPEAT`，`<= 0` 表示一律用默认血量** ——
  以后要加一个血更厚的僵王关，直接传参就行，不用改事件脚本。
- **`settle_time` 默认 `0.0`**（不额外等待） —— 保持与原行为一致，需要等登场动画的关卡自己传。

## 踩坑

1. **新事件脚本带 `class_name`，被 `LevelPrefabs` 引用 —— 第一次启动 Godot 会报错**
   → 现象：`Identifier "LevelTimelineEventSpawnZomboss" not declared`。
   → 原因：带 `class_name` 的新脚本要进了全局类表才能被别处引用，本次运行是拿旧表跑的。
   → **正解**：**再启动一次 Godot** 就正常了（[关卡时间轴.md](../参考存档/关卡时间轴.md)
     与规范卡片 E-01 都记了这个坑）。不是代码写错了，别去改脚本。
2. **生成时机从「开战瞬间」变成了「开战之前」**
   → 影响：僵王现在会在「准备-安放-植物」红字期间就位，比原来早。
   → 判据：`zombie_manager.all_zombie_rows` 在流程事件运行时已经就绪（管理器在 `_ready` 里初始化完），
     所以锚点算得出来；如果哪天把这条事件排到管理器就绪之前，会走 `rows.is_empty()` 那条 `Log.error`。
3. **`_setup_zomboss_hp_bar` 是私有方法** —— 事件脚本在别的目录，按 GDScript 约定拿不到下划线方法。
   → **正解**：改名 `setup_zomboss_hp_bar()`（去掉下划线）。血条要挂 `level_info`，那段留在管理器里是合理的，
     只有「什么时候生成、站在哪、多少血」属于关卡。

## 给后来者的最简路径

关卡里要在**某一刻发生一件事**（生成一个东西 / 播一段动画 / 推一个状态）：

1. 在 `src/levels/core/timeline_event/` 新建一个脚本，继承 `ResourceLevelTimelineEvent`，
   `@export` 自己的参数，实现 `run(main_game)`。
2. `LevelPrefabs` 加一行式方法（`new()` 事件 → `_run(event, "备注")`）。
3. 关卡脚本 `run_flow()` 里 `await prefab.xxx()`。
4. 通用管理器里那段 `if 某开关: 做这件事` 删掉；只留事件脚本够不着的那部分（本例是挂血条）。
5. 文档：[关卡时间轴.md](../参考存档/关卡时间轴.md) 的事件清单加一行。**再启动一次 Godot**。

## 补充（2026-10-05）：第一步「僵尸预览」已去掉

补充自：[2026-10-03\_僵王关搬进关卡流程.md](2026-10-03_僵王关搬进关卡流程.md)（原文未改）。

僵王关（`adventure_05_10` / `minigame_20_zomboss_revenge`）的**出怪预览是空的** —— 本关不自然出怪
（`monster_mode = Null`，僵尸全由僵王投放），原版开局那段「看僵尸」一只都没有。

改法照本仓库「没有预览僵尸的关卡」那套口径（同 `minigame_02_bowling` / `adventure_04_05`）：

- `look_show_zombie = false` + `camera_init_x = MainGameCamera.CAM_POS_ORI.x`；
- `run_flow()` 里删掉 `show_zombie()` / `camera_back()` 两步，直接进 `spawn_zomboss()`。

> **只删 `show_zombie()` 不设 `camera_init_x` 会出事**：相机停在进关位（背景最左，只拍得见房子），
> 整段僵王登场都摆在屏幕外，直到 `main_game_start()` 才 snap 回来。

上面的「人工验证方法」第 2 条随之作废：**进关就停在草坪上、没有预览僵尸**；其余三条不变。
实机验证：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zomboss -Windowed`
→ `[ZOMBOSS] result=PASS failed=0`（改动后跑过）。
