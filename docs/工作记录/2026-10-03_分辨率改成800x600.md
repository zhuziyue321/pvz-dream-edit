# 2026-10-03 · 其它 · 设计分辨率从 1066x600 改成 800x600

> **任务类型**：其它（分辨率 / 布局适配）
> **推荐度**：**推荐**（同类任务照这个走：先定位 `world ↔ screen` 的换算，再按「必须改 / 不用改」两类筛）
> **耗时与成本**：约 4 轮对话；无头探针 + **未开游戏**（布局类改动最终要人工看一眼，方法见文末）
> **验证方式**：无头探针 `probe_start_menu_layout`（主菜单构图）、`probe_choose_level_layout`（选关网格）
>   + 冒烟 `boot_level` 已跑通；其余按文末清单人工目视
> **补充自**：无

## 目标

`project.godot` 的设计分辨率 / 窗口从 `1066x600` 改成原版的 `800x600`，且草坪 9 列、小推车、
顶栏卡槽都还在屏幕里（不是简单裁掉右边 266px）。

## 步骤

1. **先算出 `world ↔ screen` 的换算**（这一步不做，后面全是瞎猜）：
   主游戏 `Camera2D` 的 `anchor_mode = 0`（FixedTopLeft），`position.x` **就是可见区左边界**，
   所以 `screen_x = world_x - camera.position.x`。
   旧值 `-150` → 可见 world `-150..916`；地图 `map_front.tres` 草坪 `col_x 45..686 + 宽 78` → 右边界 764。
   ⇒ 800 宽下不挪相机就会吃掉最右两列，**相机必须往右移**。
2. 改 `project.godot` `window/size/viewport_width` → `800`。
3. 相机归位点 `-150 → 0`（`src/main/main_game_base.tscn` 的 `Camera2D.position` +
   `src/world/camera/main_game_camera.gd::move_back_ori` 两处必须同改，否则开局与「选卡结束」两处差 150px）。
   取 0 后可见 world `0..800`：草坪 `45..764`（左留 45、右留 36 当马路）、小推车（x=20）都在屏内；
   房子（world `-181..-32`）留屏幕外，交给失败流程 `mgm_lose_manager` 的 `move_to(-200, 0)` 去拍 —— 与原版一致。
4. 逐个筛「按 1066 硬摆」的位置，分成**必须改**与**不用改**（下面「关键决策」有清单）。
5. 同步测试基线：`test/autopilot.gd::HEADLESS_VIEWPORT` → `Vector2i(800, 600)`（无头假视口必须跟项目一致），
   4 个探针里的 `DAVE_CLICK_POS` 由 `(533,300)` → `(400,300)`（只是屏幕中心点，不改也能过）。
6. 同步文档口径：`docs/AI调试通道.md` 里两处 `1066x600` → `800x600`。

## 关键决策与理由

- **不做「窗口 800 但设计仍是 1066」的等比缩放方案** —— `stretch/aspect` 默认 `ignore` 会横向压扁 25%，
  `keep` 会上下留黑边；而仓库素材本身大多是 **800x600 原生**（`Almanac_IndexBack.jpg` 就是 800x600，
  `SelectorScreen_BG_*` 三段、`ShovelBank/SeedBank` 也都是按 800 时代画的）。所以「真 800x600」反而更贴素材。
- **相机取 0（world ≡ screen）而不是「保住房子可见」的 `-36`** —— 取 0 时草坪右侧留 36px 马路给僵尸入场，
  映射关系最简单（world 就是 screen，以后写死坐标不用再加减）；房子由失败相机平移负责露脸。
- **`zombie_create_global_pos = 950` 不动** —— 原版就是从屏幕外走进来，800 下离得更远而已，不影响玩法。
- **`ShowZombiePanel/2` 的 ±140 不动** —— 它是右锚 + `CanvasLayerBG follow_viewport`，
  位置永远跟着相机；`move_look_zombie` 保持 `120` 时，预演面板与僵尸相对相机的观感与 1066 时代完全一致。
- **顶栏 `CardSlotRoot.x: 150 → 70`** —— 顶栏宽 = 78（阳光计数左缝）+ 卡槽数×50 + 12 + 铲子 70 + 手套 70。
  满卡槽（商店买满 = 10 格）时右端 = `x + 730`，x=150 → 880 出屏（**手套点不到 = 功能坏**），x=70 → 正好 800。
  代价：选卡面板跟着左移 80（它的 x 是 `card_slot_norm.gd::move_card_slot_candidate` 里 tween 到 `position=(0,89)` 的，
  要留住原位置就得同时改编舞脚本，先不碰)。**这一条建议人工看一眼再定**。
- **`garden.tscn` 的 `Next`：硬摆 `798..858` → 改成右锚定 `offset_left=-62, offset_right=-2`** ——
  不必再为屏宽算坐标（同类硬摆位置以后都这么办）。
- **不改**：所有 `anchors_preset = 15/3/8`（全屏 / 角锚）的 UI、`day_suns_manager` 天降阳光 `50..750`
  （world≡screen 后正好落在草坪上）、小推车 / 进家判定 / 背景贴图 `x=-210`（1400x600 的底图仍盖满可见区）、
  `DetectComponentGlobal` 的 `1111x600` 检测矩形（放宽无副作用，收窄反而可能少检僵尸）。

## 踩坑

1. **`-150` 这类数字会散落在「场景」和「脚本」两处**：`Camera2D.position` 与 `move_back_ori` 必须一起改，
   只改一处 → 开局取景对、选卡结束回位就错（反之亦然）。→ **正解**：搜全仓库（含 `.tscn`）再动手，
   现在两处都提成了 `main_game_camera.gd` 里的 `CAM_POS_ORI` 常量，脚本侧只有一处。
2. **`.gd` 里搜 `1066` 搜不到问题** —— 视口宽只写在 `project.godot`，其余全是「按 1066 手摆的像素」，
   没有任何一处硬编码 `1066` 会报错，所以**必须靠算坐标 + 肉眼看**，不能靠编译/探针兜底。
3. **无头探针的假视口是独立数字**：`autopilot.gd::HEADLESS_VIEWPORT` 不跟着 `project.godot` 走，
   忘了改 → 无头下点击命中测试坐标体系与真机差 266px（报告全绿但真机点不到）。→ **正解**：改分辨率必改它。
4. **还有一类屏幕坐标写在 `.tscn` 的动画轨道里**（主菜单三段背景的 `BG_*:position` 末帧值），
   既不在脚本、也不在节点静态 `offset` 里 —— 按「节点属性」搜搜不到，只表现为运行期被屏幕边缘裁掉
   （详见文末「补充」）。→ **正解**：改分辨率时**必须**在 `.tscn` 里搜一遍 `values = [Vector2(` 这种动画关键帧。

## 给后来者的最简路径

1. 先算 `screen = world - camera.position.x`（`anchor_mode = 0` 时相机 x 就是可见区左边界）。
2. 拿地图 `col_x/col_width` 算出草坪世界区间，反推相机新值，保证「草坪 + 小推车」落在 `0..新宽度` 内。
3. 改 4 处：`project.godot` 视口宽 / `Camera2D.position` + `move_back_ori` / `autopilot.gd::HEADLESS_VIEWPORT` /
   排版类硬摆坐标（改成锚定，别改数字）。
4. 人工过一遍：主游戏开局（9 列草坪全见 + 顶栏右端不出屏）、选卡界面、僵尸预演、失败拍房子、各菜单页。

## 补充（同日）：主菜单墓碑等背景左移

上面第 5 条人工回归里，主菜单就是没过：右侧那块大墓碑（`SelectorScreen_BG_Right.png`，730x560）
被屏幕右边缘裁掉约 270px，连带挂在它上面的 10 个按钮一起出屏。

**根因**：三段背景的落点不在节点静态 `offset` 里，而在 `StartMenu` 的 Idle 动画轨道上：
`BG_Right:position` / `BG_Center:position` / `BG_Left:position` 的末帧值把「锚点自适应算出来的位置」
又写死成了 1066 时代的常数（`(340, 40)` / `(40, 250)`；1066/2-493 = 40 ✓、1066-726 = 340 ✓）。

**改法**：值改成 800 宽下的锚点解，锚点本身不动（`src/menus/start_menu/start_menu.tscn`）：

| 节点 | 锚点 | 旧末帧 x | 新末帧 x | 算式 |
| --- | --- | --- | --- | --- |
| `BG_Left`（左段：树 / 房子） | 左锚 | 0 | 0（不用改） | — |
| `BG_Center`（中段：草地） | 居中 | 40 | **-93** | 800/2 - 493 |
| `BG_Right`（墓碑 + 菜单按钮） | 右锚 | 340 | **74** | 800 - 726 |

`RESET` 动画里那条 `BG_Right:position` 也同步改成 74，免得编辑器重置时又跳回旧值。
云（`Cloud`）与用户名木牌（`WoodSign`）不用改：前者锚在容器中心、容器宽跟随视口（本来就会自适应），后者左上锚固定在左下角。

**验证**：新写探针 [test/scenarios/probe_start_menu_layout.gd](../../test/scenarios/probe_start_menu_layout.gd)
（`run_autopilot.ps1 -Scenario probe_start_menu_layout`，约 3 秒）断言两件事：

② 挂在墓碑上的 10 个按钮 `global_rect` 都在视口内。
结果 `[MENULAYOUT] result=PASS failed=0`，其中 `BG_Right/Menu/Button1` rect = `P(415,54) S(331,146)`
（改前会落在 681..1012，右边 212px 出屏）。

## 补充 2（同日）：冒险选关的关卡整体右移 35px

人工看选关界面时「关卡块整体偏左」。原因**不在锚点**，而在 `GridContainer` 的容器宽 ≠ 内容宽：

| 选关场景 | 网格 offset | 容器宽 | 内容宽（列宽×列数 + 分隔×间隔） | 结果 |
| --- | --- | --- | --- | --- |
| `02_adventure_choose_level` | ±393 | 786 | 104×5 + 49×4 = **716** | 内容偏左 35px ❌ |
| `03_mini_game` / `04_puzzle` | ±365 / +367 | 732 | 104×5 + 53×4 = **732** | 对称 ✓ 不用改 |
| `05_survival` | ±333 / +338 | 671 | 95×5 + 49×4 = **671** | 对称 ✓ 不用改 |

`GridContainer` **不会**把多余宽度分给列，多出来的 70px 全落在容器右侧：
容器本身居中（7..793），内容却只占 7..723 → 左留 7、右留 77。

**改法**：`adventure_choose_level.tscn` 的 5 个网格 offset 从 `±393` 改 `±358`（宽 716 = 内容宽）。
改后内容 42..758，左右各留 42。

**验证**：新探针 [test/scenarios/probe_choose_level_layout.gd](../../test/scenarios/probe_choose_level_layout.gd)
（`run_autopilot.ps1 -Scenario probe_choose_level_layout`，约 2 秒）
→ `[LEVELGRID] result=PASS failed=0`，`AllPage/GridContainer` rect = `P(42,123) S(716,260)`、
`ChooseLevelButton5` 落在 654..758。

> **给后来者的判断法**：判断居中是否真的对称，**不能只量容器的 rect**（容器居中 ≠ 内容居中），
> 要量「列宽之和 + 分隔之和」跟容器宽是否相等，或者直接量最左/最右按钮的 rect。
> 这条也已补进 [规范细则存档 S-04](../参考存档/规范细则存档.md)。

## 补充 3（同日）：开场僵尸预览右移 40px

「看僵尸」那段（相机 `move_look_zombie` = 120）的预览僵尸看着偏左。量了一下：

- 预览面板 `ShowZombiePanel` 挂在 `CanvasLayerBG`（`follow_viewport`）下，**层坐标 ≡ 世界坐标**，
  屏幕 x = 世界 x − 相机 x。右锚 `±140`（宽 280）→ 相机 120 时屏幕落在 **540..820**，
  左端只占屏幕宽度的 67.5%；1066 时代（面板 926..1206 → 屏幕 806..1086）是 75.6% → 相对偏左约 8%。
- 只右移 40（`offset` `-140/+140` → `-100/+180`）→ 屏幕 580..860，右端出屏 60px，
  随机分布的僵尸约 1/5 概率落在屏外（探针实测就抓到一只 x=822）。
- **最终取「右移 40 + 收窄到贴右边缘」**：`offset = -100 / +120`（宽 280 → 220），
  屏幕正好 **580..800** —— 既右移了 40，又一只都不出屏（僵尸密度略增，原版预览本来就是挤在一起的）。
  `ShowZombiePanel2`（蹦极那层）同步改，两层保持对齐。

验证：探针 [test/scenarios/probe_show_zombie.gd](../../test/scenarios/probe_show_zombie.gd)
（`run_autopilot.ps1 -Scenario probe_show_zombie`，约 6 秒）→ `[SHOWZOMBIE] result=PASS failed=0`，
`ShowZombiePanel` 屏幕 x 580..800，6 只僵尸落在 587..783。

> **给后来者**：量「跟着相机走的面板」的位置，用 `get_global_transform_with_canvas()`
> 直接取**屏幕坐标**最省事 —— 拿层坐标当屏幕坐标会差一个相机 x（本例差 120）。

## 补充 4（同日）：相机三个停靠点改成「按背景图算」

补充 3 之后又收到三条**几何硬要求**（用户给的验收口径）：

1. 初始相机左上角 ≡ 背景左上角
2. 「看僵尸」时相机右上角 ≡ 背景右上角
3. 相机归位后左上角 ≡ 背景左上角右侧 220px

背景贴图是 **1400×600**（`res://assets/image/background/*.jpg`，原版尺寸），
背景 `Sprite2D` 是 `centered = false` + `position = (-210, 0)`（`src/world/background/*.tscn` 四份都是这个值）
→ 背景占世界区间 **x ∈ [-210, 1190]**。视口 800×600、`anchor_mode = FixedTopLeft`
→ `camera.position.x` 就是可见区左上角的世界 x。于是：

| 停靠点                    | 算式                    | 值    | 可见区（world） |
| ---------------------- | --------------------- | ---- | ---------- |
| `CAM_POS_INIT`（进关）     | 背景左上角                 | -210 | -210..590  |
| `CAM_POS_LOOK_ZOMBIE`  | 背景右上角 − 视口宽            | 390  | 390..1190  |
| `CAM_POS_ORI`（归位）      | 背景左上角 + 220           | 10   | 10..810    |

**做法**：别再散落魔数，`src/world/camera/main_game_camera.gd` 里提三个基准常量
`BG_LEFT_X = -210` / `BG_WIDTH = 1400` / `VIEW_WIDTH = 800`，三个停靠点全部由它们算出；
换分辨率或换背景尺寸只改这三个。

同批改动：

- `src/main/main_game_base.tscn` 的 `Camera2D.position` 同步成 `-210`
  （并在 `MainGameCamera._ready()` 里以常量为准兜底 —— 场景与脚本两处不同步的坑见本文 §「踩坑」）；
- `mgm_lose_manager.gd` 失败拍房子的 `move_to(Vector2(-200, 0))` → `MainGameCamera.CAM_POS_INIT`；
- **新增 `snap_to()` + `main_game_start()` 里兜底归位**：调试通道 / 自动测试 / 关卡脚本会直接调
  `main_game_start()` 跳过选卡，那条路不走 `choose_card_finish()`，相机就一直停在 `-210`（只拍到房子），
  之前因为初始位置恰好等于归位点才没暴露。用 `snap_to`（瞬移、不播位移）而不是 `await move_back_ori()`，
  是为了不改变开战时（用 await 会把开战推迟一轮 2 秒位移）。

**副作用 + 已修（顺手一起改了）**：`ShowZombiePanel` 是**层坐标固定**的（`rect P(700,180) S(220,400)`，见补充 3），
屏幕 x = 层 x − 相机 x。相机「看僵尸」位从 120 → 390 之后，预览僵尸的屏幕位置从 **580..800（贴右）**
掉到 **310..530（屏幕中部）** —— 相机贴背景右边缘了，面板却还停在世界 700..920，离背景右边界（1190）差一大截。

正确算法是**反着推**：想要屏幕 S，就得要层坐标 `S + 相机x(=390)`，再换算成 offset（`层 = 800 + offset`，
因为是右锚）。目标屏幕 500..720（贴右且整只僵尸不出屏）→ 层 890..1110 →
`offset_left = -100 → +90`、`offset_right = +120 → +310`（宽度 220 不变）。
`ShowZombiePanel2`（蹦极那层）同步改，两层保持对齐 —— 见 `src/main/main_game_base.tscn`。

> **给后来者**：这里第一版我写错过（把「屏幕 500..720」直接当成层坐标去减，offset 写成 `-300/-80`，
> 真跑出来会飘到屏幕 x 110）。**面板是层坐标固定的，相机一动它就动** —— 定位置只能从目标屏幕位置反推层坐标。

**验证**：`probe_show_zombie` 带窗口 → `[SHOWZOMBIE] result=PASS failed=0`，相机 = `(390, 0)`，
面板屏幕 x 500..720，6 只僵尸屏幕 x **521.6..705.5**（改之前是 318..526）。
`probe_plant` 带窗口 → **FAIL**，但把归位值临时改回旧的 `0` 跑同样 FAIL
（教程关 1-1 逐步模式拦住种植，卡拿到手了但 `已种槽位=0`）—— **与本次改动无关**，别当本次引入的回归。
