## 1. 症状

架构优化收尾后开游戏：**植物不发射子弹、僵尸不啃植物**，但编译门禁 PASS、日志无任何报错。

## 2. 定位（未开游戏，全程静态比对）

1. 先把工作区改动按项分组（本轮共 7 项仍生效：生命周期改名 / 事件名常量化 / 实体解全局 / 子弹收口 / payload 校验 / 对话数据化 / 死资源清理）。
2. 按「会不会造成静默失效」排序，生命周期改名排第一 —— 它改的是**初始化链路**，断掉就是「没接线」，不报错。
3. 用 `git diff` 只看攻击组件目录的**函数签名行**，一眼看到 5 处 `func _ready()` 里原本的 `super()` 被删掉、改成的 `component_ready()` 里没有补回。

## 3. 根因（最关键的一条）

**`_ready()` 的 `super()` 是逐层级联的，`component_ready()` 由基类统一分派、只执行一次。**

```gdscript
# 改名前：每一层的 _ready 都会跑
func _ready() -> void:
	super()            # 子类 super → 父类 _ready → 祖类 _ready，每层都执行
	...自己的初始化

# 改名后：基类 _ready() 里只有一次 component_ready()，
# 虚调用落在「最派生的那个重写版本」，中间各层不执行
func _ready() -> void:          # ComponentNormBase
	if not is_enable_default: ...
	component_ready()          # ← 只调这一次
```

所以把 `_ready()` 改名为 `component_ready()` 时，**原样保留的 `super()` 不能删**。删了等于把父类整段初始化丢掉。

本例丢掉的是 `AttackComponentBase.component_ready()` → `detect_component_init()`，
那正是「把 `detect_component.signal_can_attack` 接到 `update_is_attack_factors`」的接线代码。
断掉后攻击状态永远收不到「有敌人可攻击」，`is_attack` 恒为 false —— 表现就是全体不攻击。

## 6. 踩坑

1. **改名类重构最容易丢的不是逻辑，是「级联」** —— `super()` 在原写法里承担了「跑完父类整条链」的职责，
   换成统一分派钩子后必须显式写成同名 `super()`，否则中间层整段消失。**grep 验收时不要只搜「有没有 component_ready」，要搜「父类有重写时子类有没有 super」**。
2. **两个 PowerShell 检查脚本给出过假结果，别直接采信**：
   - `Test-Path "res://..."` 恒为 false —— `res://` 是 Godot 虚拟路径，要先换成文件系统路径。
   - `git grep -h ... HEAD | Select-String` 组合返回空 —— `git grep` 本身正常（`-c` 能出数），管道组合有问题。**凡是「统计为 0」的结论，先换个写法复验再写进报告**（与 [架构优化四项清理](./2026-10-07_架构优化四项清理.md) §3 那条假阴性是同一类坑）。
3. **回退要回退到「项」的粒度**：本轮先后回退过「实体解全局」「HP 组件接入」两批都没解决问题，
   因为真正的元凶在第三批里。逐批回退不如**先把所有改动列成清单、按静默失效风险排序再逐项核验**。
