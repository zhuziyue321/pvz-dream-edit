## 目标

把 Z031 豌豆僵尸做成原版那样。原版口径（PVZ Wiki《Peashooter Zombie》）：

> Stat-wise, it is identical to a normal Zombie, but additionally fires peas **constantly** down its lane
> … they fire the peas **before they come on the screen**

可判定：① 僵尸照常往前走、碰到植物照常啃；② 没有植物时也恒定发射豌豆，豌豆是僵尸方、朝左、本行；
③ 头顶植物打得掉，掉了之后不再发射。

## 步骤

1. 先查 wiki 定口径（上面两句话 + 总耐久 270 / 头在 180 掉），再回仓库对照现状找缺口。
2. 发现三个问题（见「踩坑」1、2、3），逐个改：

   - `component_zombie_plant.gd` 的信号连接改到宿主 ready 之后。
3. `godot --headless --path . --import`（新增 `class_name` 必须跑一次，否则运行期找不到类型）→ 拿到新脚本的 `.uid` 写回 `.tscn`。
4. 扩 `probe_zom_botany`：新增「恒定发射」分支（组件类型 / 仍会啃咬 / 啃咬检测区必须是近身范围）。
5. 写一个一次性进关卡探针（跑完即删）验证 5 项行为 → 全 PASS；再把 `component_zombie_plant.gd` 改回旧写法反向验证一次，确认「头顶植物打不掉」这个 bug 是真的。

## 关键决策与理由

- **新增一个组件，而不是给 `component_attack_zom_botany.gd` 加开关** —— 两个行为的驱动源根本不同
  （啃咬由 `is_attack_res` 驱动，发射是恒定的），塞进一个组件只能靠 flag 分叉，读起来更乱；
  而且旧组件还被机枪 / 寒冰 / 三个投手 / 玉米炮共用，改它有回归风险。
- **继承 `AttackComponentZombieNorm` 而不是 `AttackComponentBulletBase`** —— 豌豆僵尸本体就是普通僵尸，
  啃咬才是它的「攻击」；反过来继承发射组件要把持续掉血 / `attack_once()` / 攻击力因子整段抄回来，抄得更多。
- **不重写 `owner_update_speed`** —— wiki 明确「被寒冰射手 / 冰瓜减速时它依旧按原频率开火」，
  减速只该影响啃咬速度。
- **头顶植物的 300 点耐久没动** —— 见「遗留」。

## 踩坑

1. **啃咬检测区被撑到 760 像素宽 → 僵尸停在几百像素外播啃咬动画**
   → `is_attack_res` 一为真就 `signal_change_is_attack(true)` → 移动组件 `IsAttack` 因素置位 → **僵尸停住**
   → **正解**：发射不该由 `is_attack_res` 驱动；检测区恢复成默认的近身那一小块（50×5），
   发射用自己的计时器。
2. **组件 `_ready()` 里读宿主的 `@onready` 成员永远是 `null`**
   → Godot **先跑子节点 `_ready()` 再跑父节点**，`character_base.gd` 的 `@onready var hp_component` 此刻还没赋值，
   而原写法用 `if is_instance_valid(...)` 判空 → **连接静默失败**，表现是「头顶植物怎么打都打不掉」
   → **正解**：`if owner.is_node_ready(): … else: owner.ready.connect(…)`。
   （用改回旧写法 + 探针反向验证过：确实是 `[NG] 头顶植物已消失`。）
3. **新增 `class_name` 脚本后必须跑一次 `godot --headless --path . --import`**
   → 否则运行期报 `Parse Error: Could not find type "Xxx" in the current scope`（编辑器扫描是全绿的，骗人）；
   `--import` 顺带生成 `.uid`，把它写回 `.tscn` 的 `ext_resource`（不写也能跑，但仓库约定带上）。
4. **探针里 `var x := expr` 会报 `Cannot infer the type`** —— 当 `expr` 来自无返回类型声明的函数
   （`create_norm_zombie` / `Global.main_game`）时，必须显式写类型：`var zombie: Zombie000Base = …`。
5. **`create_norm_zombie()` 的坐标是直接用传入值的，`y` 不会按行修正** —— 探针里想让僵尸啃到植物，
   必须按植物自己的 `global_position.y` 生成，否则啃咬检测区（只有 5 像素高）压根碰不到。
   另外别用「改 `position.x`」把僵尸挪过去：移动组件是靠 `_ground` 节点的位移反推的，瞬移会算出错误的修正量。

## 验证

- `godot --headless --path . --import` → 无报错，`AttackComponentZomBotanyPea` 已进全局类表。
- `probe_zom_botany` → `[ZOMBOTANY] result=PASS failed=0`。
- 一次性进关卡探针（冒险 1-1，`create_norm_zombie` 造 Z031，跑完即删）→ `[PEAZOMBIE] result=PASS failed=0`：
  - 头顶植物节点已拼出来；
  - 没有植物时也往前走（991.9 → 929.8）、恒定发射（场上 3 颗）、`is_attack` 仍为 false；
  - 豌豆阵营 = 僵尸方、方向 = 左、行号 = 0；
  - 打掉头顶植物后植物消失、不再发射；
  - 走到坚果墙跟前会停下来啃（`is_attack = true`）。
- 反向验证：把 `component_zombie_plant.gd` 改回旧写法 → 同一探针「头顶植物已消失」变 `[NG]`，确认坑 2 真实存在。

**人工验证方法**（开窗口，迷你游戏第 1 关「植物僵尸」）：

1. 豌豆僵尸**一进场就开始射豌豆**（还没碰到你的植物也在射），而且**一直在往前走**，不会站在原地；
2. 走到你的植物跟前会**停下来啃**（像普通僵尸一样），啃的时候头顶还在射；
3. 把头顶的豌豆射手打掉之后，它**不再射豌豆**，变回一只普通僵尸继续走；
4. 坚果僵尸依旧只是耐打、不射东西（这一轮没动它）。

## 遗留（没做的，留给下一轮）

- **耐久口径与 wiki 不一致**：wiki 说豌豆僵尸总耐久 **270**（与普通僵尸完全相同，头在 180 伤害时掉、掉了就不射），
  而仓库把「头顶植物耐久」统一映射成一类防具血量（默认 300），豌豆僵尸实际是 300 + 270 = 570。
  坚果 / 高坚果僵尸那 1100 / 2200 是**额外**护甲（wiki 口径 1370 / 2400），那一半是对的；
  错的是「非肉盾植物也给 300」。要改就得同时改 `ZombiePlantComponent` 的「头掉了」触发方式
  （现在靠 `signal_armor1_death`），**会影响全部 14 只**，所以这轮按最小改动范围没动。
