## 目标

仓库根下有个**不属于本仓库的独立 Godot 工程** `新建游戏项目/`（PVZ2 的 PAM 动画 → Godot
`AnimationPlayer` 的离线转换器，3124 个文件）：
① 把它加进 `.gitignore`；② 把里面的**菜问**动画搬进主项目；③ 做成 PVZ2 模组。

## 步骤

1. **先确认它有没有被 git 跟踪**再写忽略规则：`git ls-files -- 新建游戏项目` 返回 **0 行**
   ⇒ 直接加一行 `/新建游戏项目/` 即可，**不用** `git rm --cached`（与 `addons/todo_controller/config/config.tres`
   那种"已入库才要摘"的情况不同）。
2. **摸清素材与产物**：`texture/bonkchoy/` 48 张 png、`pvz2_anim/bonkchoy_reuse_pool.tscn`（4.6 MB，

   ⚠️ 生成的 `.tscn` 是**扁平结构**（没有按动画标签分容器），轨道路径直接是 `draw_slot_XX:*`
   ⇒ **自洽可用**，搬过来不用改节点树。
3. **落位（关键决策）**：贴图进 `assets/pvz2/bonkchoy/`（**不进模组目录**），

5. **搭植物**：`plant_bonkchoy.tscn` = 实例本体 `plant_base.tscn` + `Body` 下挂烘焙动画

   （`RectangleShape2D 240×80` 覆盖左右相邻格）+ `AttackCdTimer` + `AnimComponent` 换成空实现。

8. **写探针** `test/scenarios/probe_pvz2_mod.gd` 无头跑通（failed=0，零 stderr 脚本错误）。

## 关键决策与理由

- **贴图放 `assets/` 而不是模组目录** —— 因为 `ModManager._sync_builtin_mods` 的 `COPY_SKIP_SUFFIXES`
  跳过 `.import`，`user://` 下的 png 在导出包里没法导入；`assets/` 有 `more_armor` 的先例，
  且模组引用本体资源是边界规则允许的。
- **整个子工程加 `.gitignore`，只搬产物** —— 那是个 Godot **4.7** 的工程（主仓库是 4.5.1），
  带着 1048 个 `.import` + 2376 个 `.godot` 缓存，PAM 解析那套也不该进本体。
- **不接 AnimationTree，直接 `play()`** —— 烘焙产物本来就是「一段动画 = 一个动作」，
  硬套本体的 reanim 状态机反而要再发明一套映射。
- **植物 id 用 `&"pvz2_bonkchoy"` 字符串**，不在 `PlantIds` 里留槽位 —— 角色 id 已去编号化。

## 踩坑

1. **`AnimComponent` 找不到 `../AnimationTree` 报 Null** → 本体默认挂的是 `component_anim_norm.gd`（要 AnimationTree），
   本株不用状态机 → **正解**：在 `.tscn` 里把 `AnimComponent` 的 script 覆盖成 `component_anim_empty.gd`
   （沿用 `plant_wall_nut_bowling.tscn` 的做法）。
2. **`Unable to convert array index 0 from "NodePath" to "Object"`**（实例化时静默报，游戏照跑）→
   **在 `.tscn` 里覆盖一个「元素是节点的数组」属性时，节点头必须写 `node_paths=PackedStringArray("该属性")`**，
   否则 Godot 不把 `NodePath(...)` 解析成节点。根节点的 `node2d_detect_in_slope`
   与 `SleepComponent` 的 `sleep_influence_components` **两处都要写**（我只写了第一处，第二处又报了一次）。
   参照 `plant_tanglekelp.tscn` 的写法。
3. **`run_autopilot.ps1` 的 Godot 默认路径已失效**（指向 `Godot_v4.6.2-stable_win64.exe`）
   → 必须显式 `-Godot "C:\Users\a a\Desktop\godot.exe"`（`check_scripts.ps1` 里的路径是对的）。
4. **编辑器开着会让门禁第一关的 `--import` 跑不起来**（`out.txt 正由另一进程使用`）
   → 判据只看 `real compile errors = 0`；要跑完整导入得先关编辑器。
5. **探针 PASS ≠ 零 stderr** —— 上面第 1、2 条错误在 PASS 的同一轮里出现，
   必须单独 grep `ERROR|SCRIPT ERROR`（与 2026-10-10 那条同源）。

## 给后来者的最简路径

1. `git ls-files -- <目录>` 确认没人库 → `.gitignore` 加一行。
2. 贴图拷进 `assets/<模组>/<角色>/`；产物 `.tscn` 拷进 `mods_builtin/<模组>/<角色>/`，文本替换贴图路径。
3. 植物场景照 `plant_bonkchoy.tscn`：实例 `plant_base.tscn` → `Body` 下挂动画 → 换 `AnimComponent`
   为空实现 → 加 `DetectComponent` + 计时器；**所有数组属性都要补 `node_paths`**。
4. 入口照 `pvz2_mod.gd`：一张 `PlantRuntimeRecipe` + `PlantRuntimeKit`，图鉴自己登记自己摘。
5. 写探针，`run_autopilot.ps1 -Scenario xxx -Godot "C:\Users\a a\Desktop\godot.exe"` 跑，
   再 grep 一遍 stderr。

## 补充（2026-10-15 第二轮：手感、图层、收拳）

**改了什么**：出手间隔 1.4 → **0.35 秒**；每拳 20 → **直拳 15 / 上勾拳 35**（能一拳打死时自动换上勾拳）；
出拳段从**随机挑**改成**按目标方位挑朝向段**；**隐藏 PVZ2 的 12 件装扮**；修掉「出拳播完定格在半空」；
修掉「血条与卡片冷却遮罩被菜问盖住」。
探针 `probe_pvz2_mod` 从 6 步扩到 11 步（渲染 / 收拳 / 伤害 / 朝向 / 斩杀判定各成一步），`failed=0`
（stderr 只剩探针自己那句负面断言原本就会打的 2 行）。

**七段出拳怎么分工的（这次量出来的，重新烘焙前先看这里）**：7 段 = 2 种动作 × 2 个朝向 + 3 段本株不用的：

| 段 | 时长 | 主导位移 | 可见槽位 x 跨度 | 首帧 `a<0` 的槽位 | 归类 |
| --- | --- | --- | --- | --- | --- |
| `attack` | 0.333 s | 水平（dx 497） | [49 .. **497**] 往右伸 | 4/57 | **直拳·朝右** |
| `attack2` | 0.333 s | 水平（dx 434） | [**-108** .. 341] 往左伸 | **28/57** | **直拳·朝左** |
| `attack4` | 0.5 s | **垂直上挑**（上移 -251） | [40 .. **350**] 往右伸 | 4/57 | **上勾拳·朝右** |
| `attack5` | 0.5 s | **垂直上挑**（上移 -204） | [39 .. 349] | **28/57** | **上勾拳·朝左** |
| `attack3` | 0.667 s | 水平、dx 更大（604） | [-108 .. 497] 两侧都有 | 4/57 | 左右两连击，本株不用 |
| `attack6` / `attack7` | 1.667 s | 水平+下沉都很大（dx 573 / dy 422） | 73..573 / -185..324 | 4/57 | 击飞段，本株不用 |

（基准：三段 `idle` 都是 x ∈ [93, 247]、4/57 —— 那 4 个本来就是旋转件。）

**朝向怎么认的（两条独立证据，别凭感觉猜）**：
① 一段里**可见槽位的绘制坐标 x 跨度** —— 比待机的 [93, 247] 更往右 = 朝右、更往左 = 朝左；
② 变换矩阵**是否被镜像** —— `attack2` / `attack5` 有 28/57 个槽位的矩阵第一分量 `a < 0`（镜像过），
朝右段与待机段都只有那 4 个旋转件。
量法：对每段的 `draw_slot_*:transform` 轨道取各帧 `Transform2D` 的 6 个分量（第 5、6 个是 origin x / y），
配合 `draw_slot_*:visible` 轨道只统计当帧可见的槽位。

**逻辑因此改了**：出拳段不再随机挑（随机挑会有一半的拳朝着背后打），改成
`_is_target_on_left()`（取**最近**的那只目标）→ `_pick_punch_anim(是否上勾拳, 是否朝左)` 四段二选一。
顺带一提，出拳这下没有随机成分了，原来那处 `GameRng` 也就跟着删了。

**坑 1 · 烘焙产物用 `z_index` 编码绘制顺序 ⇒ 越层压住别人的 UI**
57 个槽位的 `z_index` 被写成它的序号（0~56）。同一 CanvasLayer 里 `z_index` 是**跨父节点**生效的，
所以整株植物占掉 57 层，把 0 层上的**血条**（`plant_base.tscn` 的 `HpComponent/HpControl`）和
**卡片冷却遮罩**（`card_base.tscn` 的 `ProgressBar`，它排在 `CardBg` 之后）一起盖住 ——
连卡上的阳光数字都被压过。**正解：57 处全部归零**。同一父节点下的部件本来就用**子节点顺序**表达先后，
与 z_index 等价，归零不改任何画面顺序（顺手也记进了 [渲染层级.md](../参考存档/渲染层级.md)）。

**坑 2 · `_play_idle()` 里的 `if _is_attack: return` 会把出拳段钉在最后一帧**
原来「检测框里还有敌人就不播待机」——出拳动画播完后没人接手，拳头停在空中直到下一拳才换动作。
**正解：收拳一律交给待机段**（去掉这个早退；`_is_attack` 只留着决定计时器到点要不要继续出拳）。

**坑 3 · 「能斩杀」不能写成「总血 ≤ 上勾拳伤害」**
僵尸的 `death_hp` 是**本体满血的 1/3**（普僵 270 → 89，见 `ComponentHpStageChange.component_ready()`），
总血掉到 35 那会儿它**早就判过死亡**了 —— `character_death` 一触发，检测框就不再认它
（`DetectComponent._judge_enemy_is_can_be_attack` 里那道 `enemy.is_death`），上勾拳会**永远不触发**。
**正解：按「这一拳打下去会不会死」算** —— `get_all_hp() - uppercut_damage <= death_hp`。
普僵的斩杀窗口因此是总血 ≤ 124（掉手之后、掉头死亡之前），这才真正打得出来。

**坑 4 · 探针里造僵尸，`lane` 必须在入树之前写**
`DetectComponent.component_ready()` 见到 `lane == -1` 会 `Log.error`（stderr 一行），
而探针 `add_child` 之前就写掉 `zombie.lane = choy.lane` 即可绕开；顺带一提，检测要求同行
（`is_lane`），lane 不一致时 `get_all_enemy_can_be_attacked()` 直接是空的。

**坑 5 · PVZ2 的装扮（服饰）也在同一份 PAM 里 ⇒ 菜问同时戴 12 件**
PVZ2 这套 PAM 把打扮用的**装扮和本体塞在同一时间轴**里，烘焙产物照单全收：菜问于是同时戴着
生日帽 / 水手装 / 围巾 / 腰带 / 花环 / 绷带… 本作不需要它们，已逐帧关掉。

可以拿来快速初筛，**但不能当唯一判据**。

⚠️ **第一版就栽在这里**：只按「非绿色 = 装扮」筛，`103x67` 因为 77% 是绿被当成「本体的一片叶子」放过，
于是玩家看到「**菜问还剩一条腰带**」。第二遍改成按绘制顺序核：把每段动画里可见槽位按索引排，
「未归入本体/特效」的那一撮在 17 段动画里始终只有同一批（+`103x67`）→ 这才把 12 件凑齐。

**做法与三个坑**：

1. 只关节点的默认 `visible` 没用 —— 动画的 `visible` 轨道会把它亮回来；必须**逐帧压掉轨道**。
   节点默认可见性一并关掉，是为了「还没 `play()` / 编辑器里预览」时也干净。
2. ⚠️ **贴图轨道是稀疏的**（只在贴图变化时打点，`attack` 里可见轨道 10 帧、贴图轨道只有 3 个键），
   按「第几个值」配可见性是错的 —— 第一版就这么写的，`plantfood_on2` 被多压了 17 条（会误伤特效槽位）。
   **正解：按 `"times"` 时间轴对齐**，逐帧取「该时刻生效的那张贴图」再决定压不压。
3. 复核写在同一支脚本里：改完再解析一遍，逐帧断言「亮着的必须是本体贴图」→ `装扮帧 = 0`。
   探针 `STEP6` 另外查两处真实表面：**场上这株**与**卡面**（卡面是取帧来的同一份动画数据）。
