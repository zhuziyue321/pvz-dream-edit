> **推荐度**：**推荐**（「角色 id 去编号」这类改造收尾时，照这条查遗漏、照这条定位无堆栈错误）
> **耗时与成本**：约 1 轮对话，未开窗口（编译门禁 PASS + 无头 `probe_tutorial` PASS + **反向对照复现**，已给人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（改动是三处资源取值，开一局有墓碑的夜晚关即可）
> **补充自**：[2026-10-14_角色id从编号改为字符串.md](2026-10-14_角色id从编号改为字符串.md)（本次就是给那次改造补漏）

## 目标

消掉运行时这条报错（每局进关卡出现若干次，没有堆栈、没有行号）：

```
ERROR: Cannot assign contents of "Array[int]" to "Array[StringName]".
   at: assign (core/variant/array.cpp:276)
```

## 步骤

1. **先排除「代码里某处 `.assign()`」** —— Godot 的报错来自 `Array::assign`，直觉是把 `Array[int]` 赋给了 `Array[StringName]` 变量，于是全仓（排除 `addons/` `test/`）列出所有 `.assign(` 调用共 79 处，逐个核对目标声明类型。
   ~~结论：一处都不是~~ → **放弃原因**：所有目标里只有 `zb_doctor_skill_state.gd:60` 的目标元素是 `StringName`，而它的源 `get_action_animations()` 全 7 个实现都返回 `Array[StringName]`，走不通。
2. **改查「资源里 overridden 的字段」** —— 全仓扫 `Array[int](`（`.tscn`/`.tres` 里 Godot 保存 typed array 一定会带这个标注），得到 15 处，其中 12 处是 `boundary_value_hp`（本来就是 `Array[int]`，没问题），剩下 3 处正是把 `Array[StringName]` 字段覆盖成了数字编号：

   | 场景 | 字段 | 声明类型 | 旧值 |
   | --- | --- | --- | --- |
   | `src/main/main_game_base.tscn` | `zombie_type_candidate_tombstone` | `Array[StringName]` | `Array[int]([1, 3, 5])` |
   | `src/items/tombstone.tscn` | `zombie_candidate_list` | `Array[StringName]` | `Array[int]([1, 3, 5])` |
   | `src/entities/character/zombie_boss/zombie_boss_doctor.tscn` | `zombie_types` | `Array[StringName]` | `Array[int]([1, 3, 4, 5, 6, 7, 8])` |

3. 按 `ZombieIds.LEGACY_INT_TO_ID` 的映射把三处翻译成字符串 id（`1→norm`、`3→cone`、`4→pole_vaulter`、`5→bucket`、`6→paper`、`7→screen_door`、`8→football`）。
4. 跑 `test/check_scripts.ps1`（PASS 0 error）与无头 `probe_tutorial`（PASS failed=0，输出里已无 `assign` 报错）。
5. **反向对照**：把 `main_game_base.tscn` 那行临时改回 `Array[int]([1, 3, 5])` 重跑同一探针 → 报错原样出现 3 次，确认这就是根因；再改回来复跑确认消失。

## 关键决策与理由

- **先扫 `Array[int](` 再扫代码** —— 因为 Godot 保存资源时**一定会**写出元素类型标注（写了 `Array[int]` 就一定 stored 成 typed int array），所以这一抓是全的、零遗漏；而代码侧的 `.assign(` 是运行时才可能命中，核对一遍成本高且本次结果是"都不是"。
- **必须做反向对照** —— 单跑一次 PASS 只能证明"改完之后没报错"，证明不了"报错就是它来的"。改回旧值复现 + 再改回消失，才敢说定位正确。
- **`godot --script` 不能用来验证** —— 它**不注册 autoload**（`Log`/`EventBus` 全是 `Identifier not found`，一堆脚本编译失败），要走 `test/run_autopilot.ps1 -Scenario ... -Godot "<真实路径>"`（这条与 2026-10-13 子弹那条记录的坑② 同源）。
- **`run_autopilot.ps1` 的 `-Godot` 默认值已失效**（还指着不存在的 `Godot_v4.6.2-stable_win64.exe`），必须显式传 `-Godot "C:\Users\a a\Desktop\godot.exe"`（2026-10-13 选卡那条记录里也踩过一次）。

## 踩坑

1. **现象**：运行时一行 `Error: Cannot assign contents of "Array[int]" to "Array[StringName]"` + `at: assign (core/variant/array.cpp:276)`，**没有**任何 `.gd` 堆栈行。
   → **原因**：这不是 GDScript 调 `assign()`，是**场景实例化**给脚本成员赋值时，`GDScriptInstance::set` 发现成员已是 typed `Array[StringName]`、新值是 `Array`，走的 `Array::assign` 分支；这条路径在 C++ 里，没有脚本栈。数字编号来自「角色 id 从 int 改成 StringName」那次改造的漏网之鱼 —— 批量脚本只处理了标量字段，**typed array 字段没在那轮被发现**。
   → **正解**：全仓搜 `Array[int](` 对照字段声明类型，把错位的改成字符串 id。
2. **现象**：编译门禁 PASS（`--import` 根本不 instantiate 节点），错误照样运行时报。
   → **原因**：--import 只走资源管线解析，**不会**实例化到足以触发成员赋值的程度。
   → **正解**：这类改动要靠「无头跑一个会进关卡的探针」验证，`Check_scripts.ps1` 只能证明"没改坏语法"。
3. **现象**：想用一次性脚本 `load()` + `instantiate()` 三个场景自证，输出里全是 `SCRIPT ERROR: Compile Error: Identifier not found: EventBus`。
   → **原因**：`godot --script` 自定义 MainLoop 不注册 autoload（见上面关键决策第 3 条）。
   → **正解**：直接用现有探针（`probe_tutorial` 会进 1-1，必然实例化 `main_game_base.tscn`）。

## 给后来者的最简路径

1. 报错形如 `Cannot assign contents of "Array[X]" to "Array[Y]"` 且没有 `.gd` 堆栈 → **别在代码里找 `.assign(`**，直接全仓扫资源里的 `Array[<类型>](`，逐条对照字段在 `.gd` 里的声明类型。
2. 改完用现有探针无头跑（`-Godot` 必须显式传真实路径），或用 `-Windowed` 开一局；想确认根因就把旧值改回去复现一次。
3. 「XX id 去编号」这类改造收尾，**必须**同时扫三类遗漏点：标量字段、`typed array` 字段、`Dictionary` 的键 —— 本次就是第二类。
