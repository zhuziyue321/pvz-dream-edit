## 关键决策与理由

- **先补「能证明能玩」的防线，再动死亡链** —— 批次 3（L-12 / L-13 / L-14 / U-31）全部落在角色与死亡管线上，而现有 118 个探针没有一条覆盖「打起来了」。顺序本身是结论，写进了 §6。
- **新的检查必须自证拦得住** —— 「写了检查但检查不报错」比没写更糟（H-09 的 `check_doc_facts.ps1` 就是因为漏了 assets 这一项，才能在文档写错的情况下一直 `PASS`）。所以本轮两条新检查各做了一次**注入 → FAIL → 还原**。
- **探针只认确定性事实** —— 掉落物（金币 / 阳光）有随机性，只打印不判定；「尸体离场」也归到诊断输出，判定只认「掉血」与「死亡信号 + `is_death`」。
- **`check_doc_facts.ps1` 的新检查用 `\uXXXX` 转义写中文** —— 但**纠正一处我写错的前提**：该文件其实**不是 ASCII-only**（文件里本就满是中文字段名如 `架构总览.md`，且能正常运行）；它实际是 **UTF-8 with BOM**，PS 5.1 才能正确读中文。所以转义只是「让正则贴着英文 `what` 标签更好读」，并非硬约束。若将来有人要把脚本改成无 BOM，那时才需要转义 —— 这是我先写错、后实测纠正的点。
- **H-11 只落地不销项** —— CI 文件没法在本地验证 runner 环境，按仓库文化「未验证的不声称可用」，条目留在 §3.5 并写明首推后的三步确认。

## 踩坑

1. **`_spawn_zombie()` 是协程** → 无头跑批直接 `Parse Error: Function "_spawn_zombie()" is a coroutine, so it must be called with "await"`，脚本整份加载失败，表现为「场景卡在开始菜单 180s 后被看门狗掐掉」→ **正解**：`var zombie := await _spawn_zombie(a, LANE)`；parse error 时看 `ap_err.txt`，不要只看报告。
2. **`cell.plant_in_cell.is_empty()` 永远为假** → 探针报「找到空的植物格子 …已占=9」（1-1 明明是空地）→ **原因**：`plant_in_cell` 在场景里就**预置了全部槽位键**（值恒为 `null`），任何格子都不 empty → **正解**：按槽位走安全读取口 `PlantCell.get_plant(place)`（与规范细则 S-06「字典读取一律用 `get()`」同源）。
3. **注入验证的还原必须可核对** → 用 PowerShell 就地改写 `bullet_registry.gd` 做注入，改完立刻用 `Copy-Item` 还原并 `git status --porcelain <file>` 确认干净（否则会把「为了验证而故意写坏的一行」带进交付）。
4. **跑批前先杀残留 Godot 进程**（沿用 H-08 的教训）→ 本轮全程带 `-KillStale`，未再遇到「传 A 跑 B」的陈旧输出。

## 补充：H-14① 接线检查器（同轮追加）

- **做了什么**：`tools/check_content_wiring.ps1` 把「新增一个角色要动哪几处」的纪律机械化（对应 `架构总览.md` §14 那张人读表）。遍历 `PlantIds.ALL` / `ZombieIds.ALL`，逐个校验「注册表数值表（`PLANT_INFO` / `ZOMBIE_INFO`）有条目 + 场景 `preload("res://...tscn")` 文件存在」，缺一项即 exit 1。健康树 `result=PASS checks=192`（`55` 植物 + `42` 僵尸，各 1 次条目校验 + 1 次场景校验）。
- **注入验证**：把 `plant_pea_shooter_single.tscn` 改名 → 报 `FAIL plant PEA_SHOOTER_SINGLE: scene missing`，改动已还原（`git status` 干净）。**没写检查就声称有检查 = 比没写更糟**（H-09 的教训）。
- **踩坑 / 边界**（写检查时先知道的，省得后人重判）：
  - **场景文件名不能从 id 反推**：`PUFF_SHROOM` 的 id 是 `puff_shroom`，但场景是 `plant_puff.tscn`。所以脚本**必须读数值表里实际的 preload 路径**，而不是拼 `plant_<id>.tscn`。
  - **已知例外 `WATER_BOWL`**：它在 `PlantIds.ALL` 里，却**故意不在 `PLANT_INFO`**——它是「模组的空槽位，场景/数据/卡片由 `water_bowl` 模组运行期注入」。脚本里把它显式放进 `$plantExceptions`，并在注释写清理由，否则会误报。
  - **僵尸 42 个 ALL id 全部在 `ZOMBIE_INFO` 中**（本轮实测 `missing-from-info` 为空），所以僵尸侧暂不需要例外列表；以后若新增「运行期注入」的僵尸，记得同步更新脚本的 `$zombieExceptions`。
  - **「动画目录存在」这一项本次没做**：动画目录命名与 id 非简单对应，硬写会产出假绿检查。等确认了约定（比如 `animation/character/<场景名>/`）再补，且补完必须做一次注入验证。
- **给后来者**：新增植物 / 僵尸后，除了跑 `check_scripts.ps1`，再跑 `tools/check_content_wiring.ps1`——它能拦住「加了 `ALL` 常量却忘在数值表登记 / 场景文件没提交」这类静默错位（编译门禁抓不到，因为 preload 路径是字符串）。
