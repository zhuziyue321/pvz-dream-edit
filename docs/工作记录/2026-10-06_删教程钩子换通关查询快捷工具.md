# 2026-10-06 · 其它 · 删除 `should_run_tutorial()`，换成两个「查通关记录」的快捷工具

> **任务类型**：其它
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（无头探针 `probe_tutorial` / `probe_tutorial_1_2` / `probe_tutorial_1_5` 全 PASS）
> **验证方式**：免验证（跑无头探针即可覆盖判定分支；教程画面无改动）
> **补充自**：无

## 目标

关卡脚本基类上的判定钩子 `should_run_tutorial(mg)` 删掉，改成关卡脚本**自己查通关记录**：

1. 一个「按关卡存档名查某一关有没有通关过」的快捷工具；
2. 一个「查本关有没有通关过」的快捷工具；
3. 原来靠 `should_run_tutorial()` 做判定的地方全部改用第 2 个，行为不能变。

## 步骤

1. **`GlobalGameState` 加唯一实现** `is_level_success(level_save_key)`：只有它读
   `curr_all_level_state_data[键]["IsSuccess"]`（顺手把空串键挡掉）。
   原先这处字典读取只有 `MainGameManager.is_curr_level_success()` 一家在用，
   再加关卡侧一个调用方就得复制一遍 —— 先把它沉到存档状态这一层，两边都是一句转发。
2. **`MainGameManager.is_curr_level_success()`** 改成转发上面那个，行为逐字不变。
3. **`MainGameManager.init_tutorial_manager()` 里两条分支合成一条**：
   `只播一次` 且 `本关已通关` → 不建 TutorialManager。原先「脚本关卡」和「老 .tres 关卡」
   是两条不同判据（前者调钩子、后者看 `only_first_playthrough`），合成后对现有全部关卡
   结果一致（脚本关的教程数据现在都是 null，走的本来就是「只播一次」那条）。
4. **`LevelScriptBase` 加两个快捷工具**（`#region 快捷工具：通关记录查询`），
   `is_curr_level_success()` 直接用本关自己的 `save_game_name`，**不依赖注入的 `_mg`**
   —— 关卡脚本本身就是 `game_para`，自己的存档名自己答得上来。
5. **调用点替换**：默认 `run_flow()`、1-1（`_mg.is_curr_level_success()` → `is_curr_level_success()`）、
   1-5、以及生成器 `test/scenarios/tool_level_tres_to_script.gd`（它生成的脚本里带着这句调用，
   不拔干净下次迁移 .tres 会生成编译不过的代码）。
6. 文档同步：`规范细则存档.md` 钩子清单、`新手教程.md`、`关卡时间轴.md`。

## 关键决策与理由

- **删钩子而不是留一个「默认实现」** —— 这个钩子的全部内容就是「读存档判 bool」，
  现在有现成的查询工具，留着它等于同一件事两处写法；覆写它反而绕远。
- **本关查询挂在 `LevelScriptBase` 而不是只留 `mg.is_curr_level_success()`** ——
  关卡脚本里写 `is_curr_level_success()` 不用先拿到 `_mg`（有的关卡脚本 `run_flow` 参数
  就叫 `_mg`，容易看混），而且这两个工具配对出现：查本关 = 查某一关把名字换成自己。
- **`only_first_playthrough` 的判定留在主管理器** —— 它是教程数据自己的字段，
  本体读它不算「认识具体关卡」；关卡脚本那侧的信号（数据 null）一律按「只播一次」处理。

## 踩坑

1. **1-1 的 `should_run_tutorial() -> true` 覆写删掉后，曾经靠它保底的「已通关也要建管理器」没有了**
   → 没关系：1-1 的教程事件本来就在 `if not is_curr_level_success():` 分支里，
   已通关的存档进关时那些事件根本不会跑到，不会空转（探针 STEP8 专门验这条）。
   → **做法**：把这条前提写进 `LevelScriptBase.is_curr_level_success()` 与 `新手教程.md` 的注释。
2. **改名／删函数的收尾要连生成器一起改** —— `tool_level_tres_to_script.gd` 会把
   `should_run_tutorial(mg)` 写进生成的关卡脚本；只 grep `src/` 会漏掉 `test/` 下这类模板串。
3. **并发编辑会污染探针结论** —— 本轮跑到一半时有别人在同仓库新增类
   （出现了 `LevelTimelineEventHint` 尚未进 class 缓存的 Parse Error），
   → **正解**：先确认报错点在不在自己的改动范围里（重 grep 自己的函数名 + 看文件 mtime），
   不在就等一会儿重跑，不要急着回滚自己的改动。

## 给后来者的最简路径

1. 先 grep 目标函数名的**全部**（含 `test/` 下的生成器模板串与 `docs/` 里的引用）。
2. 新能力只加一处实现（`GlobalGameState.is_level_success`），其余两处（主管理器 / 关卡脚本）转发。
3. 改动教程分支后跑三个无头探针：`probe_tutorial`、`probe_tutorial_1_2`、`probe_tutorial_1_5`。
4. 同步 `规范细则存档.md` 钩子清单 + `新手教程.md`；收尾在 `docs/工作记录/` 建一条。
