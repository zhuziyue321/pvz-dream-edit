## 关键决策与理由

- **钩子做成「怎么进场」而不是「出什么怪」**：`wave_spawn` 清单仍由通用波次按战力算出来，
  关卡脚本只换进场方式 —— 这样波次血量统计、提前刷新判定一行都不用改，
  也不给关卡脚本开「改出怪表」的后门（要改表就改 `zombie_refresh_types`）。
- **返回值必须是本波真正参战的僵尸**（空投蹦极自己也要算进去）：`zm_zombie_wave_manager`
  用它统计血量、挂掉血信号，漏了会让波次提前刷新。
- **类名跟着改** —— 验收口径是「搜 `BungiBlitzManager` 无残留」，只挪文件不改名会白留一处。

## 踩坑

1. **探针 `run_autopilot.ps1` 与其它 agent 抢同一个临时文件** → 现象：`The process cannot access
   the file because it is being used by another process`，且打屏的是**别人**的探针输出（我明明传的
   `probe_bungi_blitz`，看到的是 `probe_slot_machine`）。
   → 原因：脚本把输出固定写在 `%TEMP%\pvz_autopilot\ap_out.txt`，多 agent 并行必撞。
   → **正解**：自己直接起 Godot，指定独立的 `APPDATA` 与输出文件：
   `$env:APPDATA="$env:TEMP\xxx"; cmd.exe /c '"<godot>" --path "<proj>" -- --scenario=res://test/scenarios/<name>.gd > out.txt 2> err.txt'`。
2. **跑出来 `result=PASS failed=0` 但一条实机断言都没有** → 原因：`_boot()` 失败时探针直接
   `_finish()` 返回，失败路径没有 `_check`，失败数仍是 0。
   → **正解**：看总时长（只有 5 秒 = 根本没进关）+ err 文件，别只看 `result=PASS`。
3. **跑到一半整个项目编译不过**（`Could not find type "ZombieWaveSourceBase"`、
   `is_mouse_visibel_on_hammer not declared`）→ 原因：别的 agent 正在改 `zombie_manager.gd` /
   `main_game_manager.gd`，改到一半。→ **正解**：确认报错文件不是自己动的，等 45 秒重跑即可；
   不要去改别人的半成品。
4. **移动文件前必须关 Godot 编辑器**（§1-5）：本次用 `tasklist` 查出进程后请用户确认再结束。
   编辑器退出时可能回写它缓存的旧文件 —— 改完 `config.tres` 记得**再核对一次**。

  后者又把它减掉了，两者天然差一个 `body_correct.position.y`，这条断言怎么跑都是 NG。

  而降落只有约 2 秒，最多采到 3~4 个点，达不到断言要求的 4 个。
