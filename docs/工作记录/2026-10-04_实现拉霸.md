## 一句话目标

把迷你游戏第 3 关「拉霸」从旧的雪人赌博骨架改成原版 Slot Machine：没有僵尸、没有选卡，玩家花 25 阳光拉杆，转轮随机出图案，凑对拿阳光或免费植物，累计收集 2000 阳光过关。

## 关键决策

1. **卡槽模式用 `Null`，阳光自己管**：`CardMode.Norm` 是为正常植物卡槽设计的，拉霸关没有卡片；用 `Null` 避免空卡槽占位，自己在 UI 里画阳光标签并订阅 `add_sun_value` 事件。
2. **胜利条件用「累计收集阳光」而不是「余额 >= 目标」**：字符串 `ADVICE_SLOT_MACHINE_COLLECT_SUN` 写的是「收集{SCORE}点阳光即可过关」，所以 `SlotMachineUI` 维护 `_total_earned`（只统计拉杆奖励 + 向日葵产出），初始 2000 阳光只当本金不计入。
3. **植物图标先用种子包图集占位**：仓库里没有单独的拉霸转轮素材，`seeds.png` 里有太阳、钻石和 5 个彩色种子包底图；植物符号用彩底 + 中文标签，太阳/钻石直接用原图标。
4. **UI 代码动态构建，不建 `.tscn`**：新 UI 全是 `Control/TextureRect/Label/Button` 组合，用脚本 `_ready()` 现场创建，避免手动维护 UID 和场景引用。
5. **拉杆按钮做成透明 `Button` + 覆盖 `Label`**：`Button` 没有 `label_settings`，所以把按钮设透明无文字，文字交给同位置的 `Label` 显示。

## 踩坑

- **无**：这次改动比较独立，旧文件里的 `start_sun = 12810` / `card_mode = Coin` / `pre_choosed_card_list_zombie = [20]` 属于未完成的雪人赌博骨架，直接整体替换即可，不需要保留。
- **余额事件要自订阅**：因为卡槽模式为 `Null`，`CardSlotBattle` 没有订阅 `add_sun_value`；如果 `SlotMachineUI` 不订阅，向日葵产出的阳光点击后会「消失」。
- **`Button` 不支持 `label_settings`**：第一次写 `_pull_button.label_settings = ...` 会被运行时拒绝，改成透明按钮 + 独立 Label 后解决。
- **覆盖在按钮上的 `Label` 默认会拦截点击**：必须把拉杆文字的 `Label.mouse_filter` 设为 `Control.MOUSE_FILTER_IGNORE`，否则玩家点不到下面的透明按钮。

## 人工验证方法

1. 从主菜单 → 迷你游戏 → 第 1 行第 3 个「拉霸」进入关卡。
2. 确认：
   - 没有选卡、没有铲子、没有小推车、没有僵尸。
   - 屏幕左上显示「阳光：2000 已收集：0 / 2000」；中央偏左出现拉霸机 UI。
3. 点击拉霸机底部红色区域「拉杆 (-25阳光)」：
   - 三个转轮开始滚动，约 1 秒后依次停下。
   - 阳光减少 25。
4. 观察结果：
   - 两个太阳 → 阳光增加 100，已收集 +100，提示「两个图案相同！奖励阳光！」。
   - 三个太阳 → 阳光增加 500，已收集 +500，提示「阳光大奖！」。
   - 两个豌豆/向日葵/坚果/冰豆/大嘴 → 在随机空格子上种下 1 株对应植物，提示「两个图案相同！一株免费植物！」。
   - 三个相同植物 → 种下 3 株，提示「三个图案相同！三株免费植物！」。
   - 两个钻石 → 阳光增加 100，提示「两个图案相同！钻石！」。
   - 三个钻石 → 阳光增加 300，提示「钻石大奖！」。
   - 什么都没凑上 → 提示「再拉一次！」。
5. 重复拉杆或等待向日葵产阳光，直到「已收集」达到 2000；此时拉杆禁用，提示「目标达成！」，屏幕中央掉下奖杯。
6. 点击奖杯，进入通关结算。
