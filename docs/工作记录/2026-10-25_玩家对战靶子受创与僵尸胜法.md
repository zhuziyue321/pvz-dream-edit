# 2026-10-25_玩家对战靶子受创与僵尸胜法

> **本次任务**：给玩家对战模组的靶子僵尸接上受创三档换装（换手里的招牌），并把「僵尸进家 = 僵尸方赢」这条胜法做完
> **耗时 / 轮次**：1 轮（3 次探针运行），文档 + 探针一次跑通，没开窗口
> **推荐度**：推荐（两个坑都是下次一定会再踩的：动画轨道抢贴图、跳过选卡要等事件）

## 目标

1. `mods_builtin/player_battle/targetzombie/`：靶子僵尸按 DLC 口径「累计受创 60 / 110 / 160 换外观」，
   之前只有掉血没有换装；
2. `mods_builtin/player_battle/levels/player_battle_day.gd`：之前只有植物方胜法（击破 3 只靶子），
   僵尸方没有任何赢法 —— 补上「任意一只僵尸走进房子 = 僵尸方赢」。

## 最简路径（步骤）

1. **先确认 DLC 到底换的是哪张图**：`PVZ_DLC/_unpacked/properties/resources.xml` 里
   `<Image id="TARGET_1..3">` = `zombie_target_damage01~03.png`（手里那块招牌的三档破损）；
   `Zombie_target_body2.png` 在 DLC 本体里**没有任何引用**（exe 里也搜不到），不要凭空接它。
2. **换装不要换 `Target.texture`**：DLC 转换器把贴图写进了 idle 轨道，每 1.17 秒重播一次就写回完好那张。
   改法 = 动画面里在 `Target` 底下加三张覆盖精灵（`TargetDamage1~3`，`centered = false`，
   与完好图同尺寸 54×97，位置 / 旋转 / 缩放全跟着父节点），用 `sprite_appear` / `sprite_disappear` 开关。
3. **配置走本体组件**：`zombie_target.tscn` 里给 `HpStageChangeComponent` 写
   `boundary_value_hp = [140, 90, 40, 0]`（**剩余血量**，末项 0 = 死亡线）+ 三份
   `ResourceBodyChange`（只做「亮自己 / 收上一档」）。本体 `zombie_base.gd` 已经把
   `hp_component.signal_hp_loss` 接上了，脚本一行不用改。
4. **僵尸方胜法**：关卡 `is_zombie_can_home = true`，流程里 `EventBus.subscribe(ZOMBIE_GO_HOME)`
   记一笔 `_zombie_side_won`，并让 `wait_targets_defeated` 与 `_on_target_defeated` 认这个标记；
   收尾演出**不重复实现**，全交本体 `MgmLoseManager.on_zombie_go_home`（重开存档 + 暂停 + 红字）。
5. **补一条本体早退**（本次唯一本体改动）：`MgmLoseManager.on_zombie_go_home` 开头
   `if main_game_progress == GAME_OVER: return` —— 否则「场上还有僵尸时赢下来」会被随后进家的僵尸
   覆写成判负，`re_main_game()` 还会把通关存档冲掉。
6. **探针**：`test/scenarios/probe_player_battle_target_win.gd`（无头可跑，24 项断言，8.3 秒）。
7. 文档同步：[模组机制.md §6.11](../参考存档/模组机制.md) 的靶子僵尸行 / 胜负段 / 回归行。

## 弯路 / 踩坑（三段式）

- **试过**：进关卡后直接 `await mg.skip_choose_card_start_game()` 想跳过选卡。
- **因为**：调用时机比时间轴的选卡事件早（那会儿还在 `show_zombie()` 拉相机），
  `is_timeline_waiting_choose_card` 是 false，于是走进 `choosed_card_start_game()` 那条旁路，
  `signal_choose_card_finished` 白白发一次没人接；等时间轴真的开始等选卡时，那条信号已经过去了
  —— 一路空等到看门狗 180 秒收工（现象：`main_game_progress = 2`(PREPARE)、场上僵尸 0）。
- **结论**：先轮询 `mg.is_timeline_waiting_choose_card == true`，**再**跳过选卡。
  （顺带确认：`zombie_card` 的 `panel.finish_choose()` 只发默认卡面，不推进流程，别拿它当「开始战斗」。）

- **试过**：给 `Target` 直接换 `texture`（`ResourceBodyChange.sprite_change`）。
- **因为**：转换器把 `Zombie_body:texture` / `Target:texture` 都写成动画轨道，
  idle 段 `loop_mode = 1` 每秒多重播一次，换上去的贴图下一轮就被抹回完好那张。
- **结论**：换「挂在同一父节点底下的覆盖精灵」，动画不认这些节点，永远不打架；
  已加在动画面里并写清「重新转换要补回」。

## 推荐度与理由

推荐。两条经验能直接省掉一次看门狗超时和一个「换了但看不见」的灵异 bug。
另外记住：**单机双边的对战，僵尸方赢 = 玩家判负**（本体只有赢 / 输两个结果），
别自己再造一套胜利界面；关卡侧只需要记账 + 掐断对方的计数。

## 补充 / 评价（2026-10-25 · 靶子站位改到第 10 列）

- **补充**：靶子原来站在「最后一列右边缘 + 12px」（x=776），看着像站在第 9 列的右边；
  现改成 **第 10 列正中**（草坪 9 列之外那一列），并且**按身体而不是按原点**对齐 ——
  `TARGET_ZOMBIE_STAND_COLUMN = 10` + `TARGET_ZOMBIE_BODY_VISUAL_OFFSET_X = -19.5`
  ⇒ 原点 x=822.5，视觉包围盒 x=731~856（视口 800，约 44% 露在屏幕外）。
- **坑 1**：僵尸的身体是画在**原点左边**的，只按原点对齐会偏左近 20px（"看着在第 9 列"）。
  量法：把所有可见 `Sprite2D` 的 `get_rect()` 用 `global_transform` 变换后取并集，
  再用 `get_viewport().get_canvas_transform()` 换到屏幕坐标 —— 纯几何，无头可测。
- **坑 2**：摆到屏幕外之后最容易坏的是「还打不打得到」。探针在第 9 列直接
  `PlantCell.create_plant(PlantIds.PEA_SHOOTER_SINGLE)` 种一株，看靶子 1 秒内掉血
  （豌豆索敌带 1000px、子弹 `max_distance` 2000，够）。**改站位一定复跑这条**。
- **更省的做法**：以后要微调，只动 `player_battle_settings.gd` 那两个常量，别改关卡公式。
