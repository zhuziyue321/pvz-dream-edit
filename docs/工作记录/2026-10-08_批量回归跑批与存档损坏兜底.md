## 目标

架构评估列了 8 个升级点，先做「补网」的两条 —— 它们不改善玩法，但决定后面 6 条重构敢不敢动手：

1. **#5 回归基线**：把已有的行为探针批量跑起来并汇总 PASS / FAIL，失败非 0 退出，能接 CI。
2. **#3 存档安全**：堵住「解析失败 → 按空档处理 → 自动存档把空档写回」这条丢档链。

## 关键决策与理由

- **跑批器不做基线比对、不引测试框架** —— 先把「一键跑完 + 非 0 退出」这一步落地，
  成本最低且立刻可用；GUT / gdUnit4 迁移是另一件事，不该混在这一轮。
- **`_load_json` 改语义而不是新增第二个 API** —— 名字不变、调用点只有 2 处，
  一次性判 null 就够；留两套读档 API 迟早有人用错那个旧的。
- **损坏时「锁写」而不是「按空档继续」** —— 读档失败后 state 全是默认值，
  60 s 后的自动存档会把空档写回去；宁可本局不落盘，也不能丢档。
  保护是**一次性的**：每次 `load_global_game_data()` 开头重置，换用户 / 重开档自动解除。
- **坏档改名隔离而不是删除** —— 坏档里往往还有能救的字段，且玩家可能想自己看一眼。
- **隔离用「改名」而不是「留在原位」** —— 留在原位会被下一次 `_save_json` 当成旧档挪进 `.bak` 顶掉。
- **跑批器必须串行** —— `run_autopilot.ps1` 每次启动都重建同一个重定向用户目录
  `%TEMP%\pvz_autopilot\userdir`，并发会互相删档。已在脚本头写死这条约束。
- **跑批器不声称「能玩」** —— E-02 的反例就是「靠纯文本扫描断言的检查器给人全绿即通过的错觉」；
  脚本头与每次输出的结尾都写了「PASS 不代表能玩」。

## 踩坑

1. **PS 脚本输出字符串里的中文变乱码** → PowerShell 5.1 按 ANSI 读无 BOM 文件
   → **正解**：整文件**纯 ASCII**（含注释）。实测补充：注释里的中文**不会**导致解析失败
   （脚本照常执行），但 `Write-Host` 字符串里的中文会直接打出一串乱码，所以干脆全清。
2. **同一秒内的第二次坏档隔离把第一次的现场顶掉了** → `Time.get_unix_time_from_system()` 只有秒级精度，
   「主档坏 + .bak 也坏」这条路径会在同一秒内调两次隔离，算出同一个文件名
   → **正解**：改用 `Time.get_ticks_msec()`，再叠一层「重名就顺延序号」的循环。
   ⭐ **这个缺陷是新探针当场抓出来的**（断言「第二次坏档也被隔离」期望 ≥2 实际 1），
   说明「先写探针再写实现」反过来也成立：**先写实现再补探针，探针依然能抓出实现里的洞**。
3. **`DirAccess.copy_absolute()` 用于把 `.bak` 提升回主档** —— 复制而非改名，备份继续留一份。
   这一步失败不影响本次读取（数据已到手），只记 warn。
4. 探针里差点用裸 `print()` 报错 → 硬约束 §1-6 要求日志走 `Log.*`，但探针里没有 Log 上下文
   → **正解**：用 `a.log()`，并把 `_failed += 1` 一起打上，保证「造坏档失败」也算失败而不是静默通过。

## 给后来者的最简路径

1. 要跑回归：`powershell -ExecutionPolicy Bypass -File test/run_all_scenarios.ps1 -Filter 'probe_zomboss_*'`
   （`-ListOnly` 先看清单；全量 88 个约 30~60 分钟，日常用 `-Filter` 跑子集）。
2. 要写一个新探针：复制 `test/scenarios/probe_init.gd` 的骨架 —— `extends RefCounted` +
   `func run(a)` + 自己实现 `_check()` / `_finish()`，结尾固定打
   `a.log("[TAG] result=%s failed=%d" % ["PASS" if _failed == 0 else "FAIL", _failed])` + `a.quit_game()`。
3. 要动存档：记住读侧三条纪律 —— ① 区分 missing / broken ② 坏档隔离不删 ③ 损坏就锁写。
   改完跑 `probe_save_corrupt_guard` + `probe_garden_tool_save`。

## 人工验证方法（本轮未开窗口）

- **存档损坏提示**：启动游戏 → 退出 → 打开 `user://<用户名>/GlobalSaveGame.json`，
  把内容改成非法 JSON → 重新启动 → 控制台应出现「存档已损坏…已隔离为 …`.corrupt`」，
  且**金币 / 关卡进度不会变成 0 之后又被写盘消失**（原档还在 `.corrupt` 文件里）。
- **备份回退**：手动把 `GlobalSaveGame.json` 改坏、保留一份完好的 `.bak`，
  启动后进度应来自 `.bak`，控制台出现「主存档损坏，已回退到上一份备份」。
- **跑批器**：`-Filter 'probe_init,probe_hand'` 应输出 2 行 PASS 且 `exit 0`。
