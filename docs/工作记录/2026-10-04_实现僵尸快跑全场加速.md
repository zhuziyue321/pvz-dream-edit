
# 2026-10-04 · 新增内容 · 迷你游戏「僵尸快跑」补完全场加速（僵尸 2 倍速 + 植物 2 倍射速）

> **任务类型**：新增内容
> **推荐度**：**推荐**（下次要做「关卡级全场变速」照这个走）
> **耗时与成本**：约 4 轮对话，带窗口跑了 3 次探针 + 1 次 `--headless --import`
> **验证方式**：打开游戏实测（带窗口 `probe_zombie_nimble -Windowed`，`[NIMBLE] result=PASS`）+ `probe_hand` 回归
> **补充自**：无

## 目标

补完 `minigame_14_zombie_nimble.gd` 里 TODO 留下的两件事：本关**僵尸移动速度翻倍**、**植物攻击速度翻倍**。
判据：进本关僵尸明显跑得快、豌豆射手射速约翻倍，而**其它关卡速度照旧**。

## 步骤

1. **先摸清「改速度」的现成通道**（依据 [项目规范](../项目规范.md) §1 架构主线：能力在组件里）。
   已有 `Character000Base.update_speed_factor(值, E_Influence_Speed_Factor.X)` —— 一个乘法字典 + `signal_update_speed`，
   冰冻减速 / 黄油定身 / 啃大蒜都是照这个写的，到点恢复就是把因子写回 1.0。**照抄这套，不要另起炉灶。**
2. **关键发现：普僵的速度烤在动画里。** `MoveComponent.E_MoveMode.Ground` 是靠 `Body/BodyCorrect/_ground` 这个
   Sprite2D 在动画里的 x 位移反向推 `position.x` 的；`Speed` 模式才是数值驱动。
   → 想让普僵真的跑起来，**只能改动画播放速度**，也就是 `update_speed_factor`（它会顺带把 `parameters/TimeScale/scale` 乘上倍率）。
   `update_only_move_speed()` 那条路对普僵无效（只在 Speed 模式生效）。
3. 加一个枚举项 `E_Influence_Speed_Factor.LevelSpeed`，在 `level_data.gd` 加两个恒定倍率字段
   `speed_factor_zombie` / `speed_factor_plant`（**没有**动锤僵尸那套每波递增的 `speed_zombie_*`，TODO 里点名说别碰）。
4. 倍率下发点只有两处，且**都必须在 `add_child` 之后**（移动 / 攻击组件是在 `_ready` 里才连上 `signal_update_speed` 的）：
   - 僵尸：`ZombieManager.create_norm_zombie()`（注释里已声明「所有出战僵尸都要从这里生成」）
   - 植物：`PlantCell.create_plant()`
   下发动作统一收进 `ResourceLevelData.apply_speed_factor_to_zombie/plant()`，倍率 1.0 时直接 return，不给默认关卡白 emit 一次信号。
5. 关卡脚本 `_init()` 里写 `speed_factor_zombie = 2.0` / `speed_factor_plant = 2.0`，删掉 TODO 注释。
6. 写探针 `test/scenarios/probe_zombie_nimble.gd`：断言关卡字段 → 生成一只普僵读 `influence_speed_factors[LevelSpeed]` 并实测 2 秒位移
   → 种一棵豌豆射手读 `bullet_attack_cd_timer.wait_time`；**再拿 1-1 当倍率 1.0 的对照组**（这条最重要，能证明默认关卡没被改坏）。

## 关键决策与理由

- **用速度因子乘法，不用 `Engine.time_scale`** —— 后者会连 UI、音效、相机一起加速，不是「僵尸跑得快」。
- **倍率是「全场」而不是只改移动** —— Ground 模式下移动与动画是同一件事，拆不开；植物侧对称地一起提，
  只快一方难度直接失衡（僵尸 2 倍速而植物原速 = 必输）。
- **植物与僵尸分开两个字段** —— 方便以后只调一边（比如某关只想要植物快）。
- **没在 `Plant000Base` 基类统一连 `attack_component.owner_update_speed`** —— 各植物脚本本来就是自己连的
  （豌豆射手、寒冰射手、香蒲……都已连），动基类会牵连大嘴花那种自己实现了 `owner_update_speed` 的，风险大于收益。

## 踩坑

1. **探针第一次跑出「假 PASS」**：`[NIMBLE] result=PASS failed=0`，但僵尸 / 植物那几段断言一条都没执行。
   → 原因：`main_game_progress = 0`、`plant_cell_manager 为空` —— `zombie_manager.gd` 编译失败，管理器根本没建起来。
   → **正解**：断言跑不到时要**先怀疑脚本没编译过**，别信 `failed=0`。日志里那句「!! plant_cell_manager 为空」才是真信号。
2. **`TreeFood` / `TreeOfWisdom` 找不到类型、`bg_03_tree_of_wisdom.tscn` "does not exist"**（文件明明在）。
   → 原因：全局类缓存 `.godot/global_script_class_cache.cfg` 没刷新（踩坑表第 341 行那条）。
   → **正解**：先跑一次 `godot --headless --path . --import`。**这一刷还会把原本被它盖住的真正错误暴露出来**（见下一条）。
3. **`body_character.gd:137` 编译失败，连带 `character_base` / `zombie_base` / `plant_base` 全部「Failed to compile depended scripts」**（预存在，非本次引入）。
   → 原因：`invisible_before_alpha` 是 `Dictionary[Sprite2D, float]`，却塞了 `get_children()` 给的 `Node`；4.6 起这条检查变严。
   → **正解**：`invisible_before_alpha[child as Sprite2D] = ...`。**一处类型错误能瘫痪半个项目**，排查时先清 stderr 最上面那条。
4. **`var main_game := Global.main_game` 报「Cannot infer the type」**（我引入的）。
   → 原因：`MainGameManager` 因为上一条编译失败，类型拿不到。
   → **正解**：显式标注 `var main_game: MainGameManager = Global.main_game`。探针里的 `var zm := mg.zombie_manager` 同理。
5. **`AttackComponentBulletBase.owner_update_speed()` 原来只在计时器跑着时才改 `wait_time`**（既有行为）。
   → 后果：关卡倍率是在植物刚进场、**还没开始攻击**时下发的，这次倍率会被整个漏掉，攻击 CD 还是原值。
   → **正解**：把「折算剩余时间」和「更新 wait_time」拆成两件事，`wait_time` 无条件更新（`speed_product == 0` 仍然只暂停、提前 return）。
6. **`probe_plant` 报 FAIL，与本次改动无关**。日志显示「已种槽位=0」——种植根本没发生（1-1 教程拦了点击），
   而我的代码只在种植**成功之后**才执行；且 1-1 倍率是 1.0，`_apply_speed_factor` 直接 return，是彻底的 no-op。
   → **正解**：判定「是不是我改坏的」时，先确认改动路径有没有被执行到；再用覆盖同一条链路的 `probe_hand`（持卡/种植/铲子/取消）回归，它 PASS。
7. **残留的 Godot 进程会占住 `user://logs/godot.log`**，导致 `run_autopilot.ps1` 清理临时目录时 `Remove-Item` 失败、整条命令报错退出。
   → **正解**：换一个临时用户目录直起 Godot（`cmd /c 'set "APPDATA=<新目录>" && "<godot>" --path ... -- --scenario=...'`），别去杀进程（可能误杀用户的编辑器）。

## 给后来者的最简路径

1. 要「关卡级变速」就用 `ResourceLevelData.speed_factor_zombie` / `speed_factor_plant`，**不要**碰 `speed_zombie_*`（锤僵尸专用）。
2. 下发点就两个：`ZombieManager.create_norm_zombie()`、`PlantCell.create_plant()`，**都在 `add_child` 之后**。
3. 想让普僵跑起来只能走 `update_speed_factor`（Ground 模式速度在动画里，改数值没用）。
4. 验证一条命令：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_zombie_nimble -Windowed`，看 `[NIMBLE] result=PASS` 且两关的倍率 / 位移 / CD 都比得上。
