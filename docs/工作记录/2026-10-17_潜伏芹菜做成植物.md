## 1. 目标

上一轮已经把潜伏芹菜（Celery Stalker）的 PAM 动画接进模组（`.pam.bin` + `pam/pam_animator.gd`），
但场上**种不出来**：只有一段动画资源，没有植物场景、没有行为脚本、没登记进注册表。
本轮把它做成和菜问一样能上场的一株：**种下去 → 缩在地里 → 打背后 → 卡 / 图鉴 / 卸载全通**。

## 2. 做了什么

1. `mods_builtin/pvz2/celerystalker/celerystalker_plant.gd` —— 四段状态机（藏着 / 冒头 / 出拳 / 缩回）。
2. `celerystalker/plant_celerystalker.tscn` —— `plant_base.tscn` + `Body` 下挂 PAM 播放器
   + 左侧检测框（150×80，中心 -40）+ `ScanTimer`（0.1s）。
3. `celerystalker/celerystalker_recipe.gd` + `celerystalker_card_face.tscn` + `pam/pam_static_frame.gd`
   —— 卡面（**不能走通用取帧**，见 §4.2）。
4. `pvz2_mod.gd` 改成「一个 Kit 管一株」的数组：两株各一张配方、各一条图鉴、装 / 卸一起走。

6. 文档：`模组机制.md` §6.7 改成两只 + 新增 §6.7.2（玩法与卡面口径）、`运行期植物.md` §4 补
   「动画不是 `AnimationPlayer` 时卡面会假成功」、`mods_builtin/README.md` 那一行。

## 3. 动画 17 段各是什么（照着烘焙数据量的，不是猜的）

用几十行 python 读 `.pam.bin`，按「递归解析 sprite 时间轴 + 累计变换」算出**每段每帧的绘制包围盒**，
再对照画布 390×390（地面线 y≈240）：

| 状态 | 帧 | 判据 | 结论 |
|---|---|---|---|
| `idle` ~ `idle4` | 50 | 包围盒 y ∈ [69, 240]、x ∈ [136, 267] | 站在地上的整株待机 |
| `down` / `up` | 32 | 主体在 f12 前后从整株变/变回一小截，同时 x 撑到 [90, 329] | 缩回 / 冒出（扬土） |
| `idle_down` ~ `idle_down3` | 50 | y ∈ [165, 239]，只剩贴地一小截 | 缩在地里的待机 |
| `attack` | 8 | f4 起最左 x 从 136 → 89 | 朝左打一拳（**第 4 帧**命中） |
| `attack_loop` | 21 | 最左 x 到 -21（≈216 px 伸展），f1~9 / f10~18 两次 | 朝左连打两拳（**第 7、16 帧**） |
| `attack_end` | 18 | 包围盒几乎不动 | 收势，不造成伤害 |

`attack_special` / `plantfood*` / `water` 本株不用（菜问那株也只用了待机与出拳）。

## 4. 关键决策与理由

### 4.0 判据只有一个：左边有僵尸就起身 / 一直打，没有就低头

和仙人掌 `plant_cactus.gd` 那种「按条件起落」的状态机同一个路子：`_find_target()` 有 → 起身、
`attack` → `attack_loop` 循环打；没有 → `attack_end` → `down`。
**没有「打够几拳就收」的计数** —— 第一版加过 `max_punches = 4`，手感变成「明明左边还有僵尸，
它自己收势缩回去、再从头冒一轮」，与这条判据冲突，删掉了（探针里那条「打了不止 4 拳还停在出拳」
就是盯着这件事的回归）。

### 4.1 「僵尸不吃它」用关受击盒，不用受击状态位

僵尸挑「啃哪株」靠它自己 `DetectComponent` 的 Area2D（在身前，50×5）与植物受击盒重叠。
把 `hurt_box_component` 关掉（`monitorable = false`）之后**根本重叠不到**，也就不啃了。
另一条路「受击状态位」（`BeAttackStatusComponentPlant.init_be_attack_status` 改成僵尸掩码外的位，
地刺那样）是**一直生效**的 —— 本株冒头时必须能被啃（右边来的僵尸），所以不能用。

### 4.2 卡面：`build_card_face()` 会「假成功」

`PlantRuntimeRecipe.build_card_face()` 走 `AnimationFrameUtil.create_frame_node()`，那条路找
**`AnimationPlayer`** 再 `seek()`。PAM 播放器是自己在 `_draw()` 里画四边形，没有播放器节点 ——
`seek_frame()` 返回 false 只打一行 warn，然后照样把节点树剥成「能画的」，返回一棵**什么都画不出来**的树。
后果：卡面全空，手持报「卡片静态角色为空」拿不起来。

所以本株配方是 `PlantRuntimeRecipe` 的子类，只覆盖 `build_card_face()`，返回
`celerystalker_card_face.tscn`：`Node2D` 挂点 → `pam/pam_static_frame.gd`（`extends "pam_animator.gd"`，
`_process()` 顶成空实现，永远定格在 `idle` 第 0 帧）。
**为什么顶空 `_process` 而不是 `set_process(false)`**：卡面节点会被 `duplicate()` 复制到待选区种子包 /
出战场 / 手持 / 整列虚影，脚本级行为一定跟着复制，节点级开关不一定。

### 4.3 受击盒什么时候开：32 px 那条线

冒头过程（1.07 秒）受击盒一直关着 —— 这时僵尸就站在它头顶，开着就是「一冒头被啃」。
出拳期间每 0.1 秒按目标位置重判：目标走出 **32 px** 才开。
32 是量出来的：僵尸啃食框在身前、宽 50 且中心偏 -13 ⇒ 有 12 px 伸到自己身后；植物受击框半宽 20 px；
12 + 20 = 32。比这更近时两个框还叠着，开着等于「被目标回头啃」，伏击这层玩法直接没了。

### 4.4 只往左打

`attack` / `attack_loop` 的可视部件全部在左侧伸展，PVZ2 原版也是从背后下手；僵尸从右往左走，
「走到它背后」= 走到它左边。右边来的僵尸它打不到 —— 这是它的代价，也是受击盒要能开的理由。

### 4.5 命中帧走 `state_frame_changed`

`attack` 第 4 帧才伸手、`attack_loop` 第 7、16 帧各一次大伸展。按「播完打一次」会少打两拳、
按时间猜又会被帧率带偏；`pam_animator` 的 `state_frame_changed(state, frame)` 是现成的。

### 4.6 摆放

画布 390×390 以中心为原点、地面线在画布 y≈240 ⇒ `pivot_offset = (0, -45)` 把脚落到植物原点；
`scale = 0.55` 让整株 ≈ 72×94 px（格子 76×95）。

## 5. 踩坑

1. **探针里僵尸摆不动**：普僵是 `E_MoveMode.Ground` —— 位置由身体里那枚 `_ground` 精灵的位移
   **反向补偿**驱动（`MoveComponent._walk()`）。探针里没有关卡地面，给 `global_position` 赋值后
   两帧就被拽回几十像素（实测 -22 → 90），于是「僵尸走到左边」这一步永远测不出来。
   处理：先 `move_component.update_move_factor(true, E_MoveFactor.IsCharacter)` 把它定住，再摆位置。
   同一坑在菜问那段没暴露：那里赋值之后只隔 0.2 秒就打拳，误差还没把它带出检测框。
2. **`.tscn` 里 `index` 只用来改已有子节点的次序**：新加的 `ScanTimer` / `DetectComponent` 不写
   `index` 就是追加在末尾；要覆盖继承来的节点（`AnimComponent` / `SleepComponent`）才必须写。
3. **卡面「有子节点」不等于「画得出来」**：探针只查 `character_static.get_child_count() > 0`
   抓不到 §4.2 那个假成功。这次改成查「子树里那个节点是不是 PAM 定格节点、有没有解析到 bin」。

## 6. 给后来者的最简路径

1. 先确认动画齐了（`probe_pvz2_celery_anim` 那一步已经是现成的）。
2. **量出每段状态的含义**：解析 bin 算包围盒（`idle` = 整株 / `idle_down` = 贴地一小截 /
   `attack*` = 往哪边伸展、哪一帧伸到最远），别只看状态名猜。
3. 植物场景照 `plant_bonkchoy.tscn` 抄：`AnimComponent` 换 `component_anim_empty.gd`、
   `Body` 下挂动画、加检测框（模组植物一律**只铺自己够得到的范围**）、`node2d_detect_in_slope` 填
   `HurtBoxComponent/HurtBoxDetection` + `DetectComponent`。
4. 行为脚本继承 `Plant000Base`，初始化写 `ready_norm()` / `ready_show()` / `ready_norm_signal_connect()`，
   **不要重写 `_ready()`**（硬约束 1-3）。
5. 卡面：动画不是 `AnimationPlayer` 就覆盖 `build_card_face()`（照 `celerystalker_recipe.gd`）。
6. 注册：`pvz2_mod.gd` 里「一株一个 Kit」的数组写法，装完 `make_selectable()`，图鉴条目自己登记自己摘。
7. `check_scripts.ps1` 过了再 `run_autopilot.ps1 -Scenario probe_pvz2_mod`。
   ⚠️ 本机 `run_autopilot.ps1` 会被**开着的编辑器进程**挡住（`result=STALE_PROCESS`）——
   别 `-KillStale`（会杀掉编辑器），改成自己用一份独立临时目录跑：
   `$env:APPDATA=<tmp>\userdir; godot.exe --headless --path <项目> -- --scenario=res://test/scenarios/xxx.gd`。

## 7. 人工验证方法（画面类，机器只能证明「数据对」）

1. 开游戏 → 模组页面打开「PVZ2」→ 进任意关卡。
2. 选卡界面：菜问后面多一张**潜伏芹菜**，卡面是站着的芹菜（不该是空白，也不该是大嘴花的脸）。
3. 种在草地上：刚种下是**只露一小截**的缩地状态，僵尸从它身上走过去**不掉血**（它也不挡僵尸）。
4. 僵尸走过它的格心之后，它冒出来照着**后背**连打（拳头往左、每一拳都掉血）；
   **只要左边还有僵尸就一直打**，把那只僵尸打死 / 走远之后才收势缩回去。
5. 关注三点：比例（整株约 72×94 px，与豌豆射手差不多高）、站位（脚落在格子里，不悬空不下沉）、
   层次（不压住血条 / 卡片冷却遮罩）。
6. 反向验一次：让它正在打的时候来一只**从右边**的新僵尸 —— 这只应该能啃它（它打不到右边）。
