> **任务类型**：其它（一关专属机制收拢进关卡侧，硬约束 §1-8）
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 2 轮，带窗口实跑 `probe_zomboss` + 一次性迷你游戏 20 探针（多 agent 并行期间被并发跑批打断过多次）
> **验证方式**：打开游戏实测（`-Windowed`），冒险 5-10 = PASS、迷你游戏 20 = PASS
> **补充自**：[2026-10-03_僵王关搬进关卡流程.md](2026-10-03_僵王关搬进关卡流程.md)（那条把「生成僵王」搬进时间轴，本条接着清它的残留）

## 目标

僵王关（`adventure_05_10` / `minigame_20_zomboss_revenge`）主体已迁成时间轴事件，但本体还有两处残留：

1. 血条：`ui_zomboss_hp_bar.gd` 在 `src/ui/`、`SceneRegistry.ZOMBOSS_HP_BAR` 注册、`MainGameManager.setup_zomboss_hp_bar()` 负责挂 UI；
2. 索敌：`component_detect` 里有一条 `not main_game.game_para.is_zomboss_fight` 的关卡开关特例。

判据：`component_detect.gd` 与 `main_game_manager.gd` 内搜不到 `is_zomboss_fight` / `ZOMBOSS_HP_BAR`；两关的僵王出场 / 血条 / 掉血 / 击败流程实测正常。

## 步骤

1. **血条连 `.uid` 搬到关卡侧**：`src/ui/main_game_ui/ui_zomboss_hp_bar.gd` → `src/levels/core/zomboss/zomboss_hp_bar.gd`（`.uid` 原样带走，uid 不变），`src/ui/zomboss_hp_bar.tscn` → 同目录 `.tscn`（改 `ext_resource` 的脚本路径）。搬之前先确认 Godot 编辑器进程没在跑（§1-5）。
2. **创建与销毁一起搬**：血条 `bind_boss()` 里自己 `boss.boss_died.connect(queue_free)`，`_process()` 发现僵王已失效也 `queue_free()`；`LevelTimelineEventSpawnZomboss` 新增 `_spawn_hp_bar()` 自己 `instantiate()` 并挂到 `main_game.level_info`，本体删掉 `setup_zomboss_hp_bar()`。
3. **注册表条目评估后删除**：`SceneRegistry.ZOMBOSS_HP_BAR` 只服务僵王（且僵王关只有 2 关），删掉，改留一行注释指向关卡侧路径。
4. **索敌改成角色自己声明**：`ZombossBoss` 加 `is_range_detectable`（默认 `true`），`component_detect._try_zomboss_by_range()` 改为问僵王要这个声明，不再读 `game_para.is_zomboss_fight`。
5. 同步注释 / 文档：`level_data.gd` 的 `is_zomboss_fight` 注释（原来写着「本开关同时决定索敌组件认不认僵王」）、`scene_registry.gd` 僵王条目注释、`docs/参考存档/特殊关卡.md` 两张表。
6. 顺手修 `LevelRegistry._scan_dir()`：目录 `script/` 改名 `core/` 后跳过判断没跟着改，导致 `core/` 下 32 个基类 / 事件脚本被当成关卡登记；新增的关卡侧 `.gd` 也会中招。

## 关键决策与理由

- **血条放 `src/levels/core/zomboss/`** —— 「僵王关的 UI 归关卡」，`core/` 是关卡侧的基类 / 工具目录；顺手把 `core/` 从关卡扫描里排除，新文件就不会污染 `LevelRegistry.all_ids()`。
- **`is_zomboss_fight` 保留在关卡数据里**，由 spawn 事件做一致性校验 —— 它现在是纯声明（不自然出怪、胜利 = 打死僵王），删了等于把「本关是僵王关」这条事实从数据层抹掉；能不能打到僵王交给角色自己声明。
- **销毁挂在 `boss_died` 上而不是让事件去收尾** —— 事件跑完就返回了，血条要活到僵王死；「谁创建谁配套销毁」写在一个文件里最好读（血条自己收尾，创建方只管建）。

## 踩坑

1. **`SceneRegistry.ZOMBIE_BOSS` 的 `preload` 常量加载成空场景** → 僵王根本进不了场（探针 STEP1 `instantiate()` 返回 null、`spawn_zomboss` 事件报 `Failed to instantiate scene state of ""`）。
   同一进程里三条路径对比过：`SceneRegistry.ZOMBIE_BOSS`（常量）= `():<PackedScene>`（`get_path()` 为空，instantiate = null）／`SceneRegistry.get("ZOMBIE_BOSS")` = 完好的场景／`load("res://...zombie_boss.tscn")` = 完好的场景；注册表里其它 10 个常量（含 `ZOMBOSS_BALL`）全部正常，只有僵王这个（50 张 reanim 贴图 + 23 段动画，全场最大）中招。
   → **正解**：写成 `var ZOMBIE_BOSS: PackedScene = load(...)`（与同文件 `TOMBSTONE` / `TROPHY` / `SUN` 一致），改完探针全程 PASS。**autoload 脚本里别用 `const ... = preload()` 引大场景**，症状是「加载成功但内容为空」，而且不会打任何编译错误。
2. **多 agent 并行时探针会假失败** —— 别人正在改 `zombie_manager`（`ZombieWaveSourceBase` 还没进全局类缓存）时，整项目编译不过，探针 STEP1 必挂；别人跑 `godot --import` 时资源缓存被重写也会连坐。
   → **正解**：先跑一次 `godot --headless --path . --import` 确认能过，再用**独立的 `APPDATA` / 输出文件**跑自己的探针（别共用 `%TEMP%\pvz_autopilot`，会撞文件锁）；看到 `Parse Error` 先怀疑并发，不要急着改自己的代码。
3. **判断「是不是我改坏的」要撤改动复测** —— 把 `zombie_boss.gd` 新增的那一行临时删掉再测，空场景现象依旧，才敢判定是既有问题。

## 给后来者的最简路径

1. 血条：`ui_*.gd` + `.tscn` + `.uid` 三件套一起搬到 `src/levels/core/<玩法>/`，`.tscn` 里的 `ext_resource` 路径改掉，创建与销毁都写进关卡侧（事件建、血条自己随 boss 死亡 `queue_free`）。
2. 注册表里只服务这一玩法的条目删掉，留注释指向新路径。
3. 组件里的关卡开关特例 → 换成角色自己的声明字段（如 `is_range_detectable`），组件只问角色。
4. 验证：`powershell -ExecutionPolicy Bypass -File test\run_autopilot.ps1 -Scenario probe_zomboss -Windowed` → `[ZOMBOSS] result=PASS`。
