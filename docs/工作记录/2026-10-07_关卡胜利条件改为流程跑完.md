# 2026-10-07 · 关卡与地图 · 胜利条件从「战斗打完」改成「关卡流程跑完」

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次同类任务照这个走）
> **耗时与成本**：约 1 轮对话，未开游戏（编译门禁 PASS，已给人工验证方法）
> **验证方式**：免验证 + 已给出人工验证方法（改的是胜利判定链路，必须进关打完一局才看得出来）
> **补充自**：无

## 目标

- 战斗完成（最后一波清完 / 罐子全砸开 / 僵王倒下后清场）**不再判胜**；
- `run_flow()` 跑完**强制胜利并给奖杯**；
- `run_flow()` 内也能主动调用胜利，并且**给物品**（本关奖励 / 解锁道具）。

## 步骤

1. **先摸清 `create_trophy` 的调用方**（`search_content "CREATE_TROPHY"`），把 8 个推送点分成两类：
   - **战斗完成**：`zombie_manager` 三处（魅惑清场 / 全灭 / 僵王 `_try_finish_wave`）、
     `plant_cell_manager` 的「罐子全砸开」→ **改成新事件 `battle_finished`**；
   - **玩法自己判胜**：`beghouled_manager` / `zombiquarium_manager` / `minigame_07_seeing_stars` /
     `minigame_03_slot_machine` / `gim_brain`（我是僵尸的脑子全吃掉）→ **保留 `create_trophy`**。
2. `ConstEventName` 加 `BATTLE_FINISHED`（payload `[Vector2]`）+ payload 签名表补一行。
3. `MgmRewardManager`：加 `on_battle_finished()`（只切下一轮）、`force_win_on_flow_finished()`（流程跑完强制判胜）、
   `win_with_trophy()` / `win_with_item()`（两条胜利入口 + `_try_start_win()` 防重入），
   原 `create_trophy()` 里「抛奖杯」那段抽成 `_spawn_trophy()`，解锁道具 / 首次通关奖励的掉落顺序原样保留。
4. `LevelTimelineManager` 在 `run_flow()` / 老事件数组跑完后调 `force_win_on_flow_finished()`。
5. `LevelScriptBase` 加 `win_with_trophy()` / `win_with_item()` 两个流程方法（`glo_pos` 留空 = 掉在本轮清场的位置）。
6. 同步文档：`docs/参考存档/关卡时间轴.md` 新增「胜利条件 = 关卡流程跑完」一节 + 开战结束条件那行改口径；
   `docs/参考存档/特殊关卡.md` 僵王死亡那条、`docs/参考存档/项目目录说明.md` 清场快捷键那条各改一句。

## 关键决策与理由

- **战斗完成必须还留一条事件（而不是直接删掉推送）** —— 多轮关卡（砸罐子 `adventure_04_05`，
  `game_round = 3` + `is_one_shot_flow`）的切轮就挂在「本轮打完」上：`start_battle` 事件结束后会
  `await wait_until(curr_game_round > from_round)`，切不掉就永远卡在那一批。
  只把「判胜」摘掉、保留「切下一轮」，多轮关一行都不用改。
- **`force_win_on_flow_finished()` 不 await** —— 胜利线里要等玩家点开奖励 / 点开奖杯，最后还会 `change_scene`；
  挂在关卡流程的协程上会让 `MainGameManager` 一直卡在 `_ready()`，且切场景时协程正好醒在已释放的对象上。
  与原来「清场推事件、结算子管理器自己跑」的形态一致。
- **`is_win_started` 与 `is_win_settled` 要分开** —— 胜利流程是异步的（掉奖励 → 等点开 → 结算），
  中途 `win_main_game()` 会被回调进来；只用一个标志会把自己挡在门外（第一版就写成了这样，见踩坑 1）。
- **保留 `create_trophy` 这个名字与行为** —— 玩法自己判胜的 5 个关卡、`test/scenarios/probe_*.gd` 里
  `reward_manager.create_trophy(...)` 的直调、以及 `MainGameManager` 的注释都指着它，改名要动一片。
- **跳过判胜的场合**：已经判过胜 / 已经结算 / 已经失败（`main_game_progress == GAME_OVER`）/
  还有下一轮 —— 否则观星超时、水族馆宠物全死这类失败流程会被「流程跑完」误判成通关。

## 踩坑

1. **一个标志挡住了自己的结算** —— 最初只在 `win_main_game()` 开头判 `is_win_started` 就 return，
   而 `win_with_trophy()` 一进来就把 `is_win_started` 置真，于是「掉奖励 → 等点开 → 结算」最后那步
   `win_main_game()` 被自己挡掉，玩家点了奖励却永远不切场景。
   → **正解**：`is_win_started`（胜利流程已启动，挡重复判胜）与 `is_win_settled`（已结算，挡重复写存档 / 切场景）分开。
2. **别把「玩法判胜」的推送点一起改成 `battle_finished`** —— 我是僵尸（`puzzle_zombie_*`）的
   `monster_mode = Null`，`is_end_wave` 永远为假，`start_battle()` 不会返回，流程压根跑不完；
   它的胜利只能靠 `gim_brain` 推 `create_trophy`。改了就是十关都通不了关。
3. **流程跑完就能赢 ≠ 流程跑完一定赢** —— 失败流程（僵尸进家 / 观星超时 / 水族馆全饿死）都会把
   `main_game_progress` 置 `GAME_OVER`，强制判胜前必须先挡这一条。

## 给后来者的最简路径

1. 改「战斗完成」的推送点：`CREATE_TROPHY` → `BATTLE_FINISHED`（先分清哪几个推送点是「玩法判胜」，那些别动）。
2. `MgmRewardManager` 加 `on_battle_finished()`（只切轮）与 `force_win_on_flow_finished()`（流程跑完判胜），
   两个标志分开用。
3. `LevelTimelineManager` 流程跑完调一次（**不 await**）；`LevelScriptBase` 暴露 `win_with_trophy()` / `win_with_item()`。
4. 跑 `powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`，再进一关打完看奖杯 / 奖励是否正常。

## 补充 3（2026-10-07 续：把「首次通关才给」的判据摆到关卡脚本里）

**起因**：读 1-1 只看到 `level_complete_drop_plant = P002SunFlower` 和末尾一句
`win_on_level_complete()`，「到底什么时候才给向日葵」的判据藏在
`MgmRewardManager.drop_adventure_reward_on_level_complete()` 里，关卡脚本上看不见。

**改动**：把分支显式写进关卡脚本（冒险 53 个关卡脚本末尾统一换成这一段）：

```gdscript
	## 通关掉落：首次通关掉本关奖励（见 _init 里的 level_complete_drop_*），已通关过只出奖杯
	if is_curr_level_success():
		win_with_trophy_only()
	else:
		win_on_level_complete()
```

- `LevelScriptBase.win_with_trophy_only()`（新，非协程）：只掉奖杯，给「已通关过」分支；
- `MgmRewardManager.start_trophy_only()`（新）：与 `start_win_on_level_complete()` 同一套判据
  （已判胜 / 已结算 / 已失败），跳过「掉本关奖励 / 解锁道具」两步直接 `_spawn_trophy()`。

**行为不变**：`win_on_level_complete()` 内部仍会再判一次「首次通关」，两条分支合起来
= 首次通关掉奖励、重打掉奖杯，与改之前完全一致；判据只是从「只有本体知道」变成「关卡里也写明白了」。

**本次验证**：编译门禁 PASS（`real compile errors = 0`），未开游戏。
