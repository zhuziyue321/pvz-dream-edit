## 目标

控制台（`CanvasLayerConsole`）原本把 11 个开关**硬编码**在场景 + 脚本 + `ConfigService` 三处，
加一项要动三个文件，模组完全没地方挂自己的调试开关。
改成**条目是数据**：谁都能往注册表登记一条，面板只负责渲染；模组可在自己的入口脚本里加一行就多一个开关。

## 步骤

1. 先读 `canvas_layer_control.gd` + `control_canvas_layer.tscn` + `config_service.gd` + [模组机制.md](../参考存档/模组机制.md)，
   确认现状是「11 个 CheckBox + 11 个 `_on_check_box_N_toggled` + 11 个字段 × load/save」。
2. 新建 `src/ui/console/console_entry.gd`（条目数据 + 链式配置 + 三种形态）。
3. 新建 `src/core/autoload/console_registry.gd`（注册表），挂到 `Global/Registry` 下（`global.tscn` 加节点、`global.gd` 加 `@onready`），
   与其它 registry 的取法保持一致（`Global.console_registry`）。
4. 新建 `src/ui/console/console_builtin_entries.gd`，把 11 条内置开关一条一行搬过去（分「自动 / 显示 / 调试」三组）。
5. 重写 `canvas_layer_control.gd`：只剩「按分组造控件 / 写回条目 / 读回控件」；`control_canvas_layer.tscn` 删掉 11 个 CheckBox 与其连接，
   换成一个 `ScrollContainer` + 空 `VBoxContainer`（条目多了能滚）。
6. `ConfigService` 加 `console_values` 通用键值区（整包读写，落在 config.ini 的 `[console]` 段），
   配 `ConsoleEntry.bind_config()` —— 新增持久化开关不用再改 `ConfigService`。
7. `ModBase` 加 `register_console_entries()` 钩子；`ModManager` 在 `install()` 后调它、关模组时 `unregister_source()` 整组撤销，
   并给每个模组自动在「模组」组放一个开 / 关开关（不用改 `.tres`）。
8. 写无头探针 `test/scenarios/probe_console_registry.gd` 验「可扩展性本身」。
9. 文档：新建 [控制台.md](../参考存档/控制台.md)，在两个索引 + `AGENTS.md` 路由表 + `模组机制.md` §四 + `架构总览.md` 登记。

## 关键决策与理由

- **条目是数据，面板只做渲染** —— 因为加一项要动三处的根因是「面板认识具体选项」；反过来「面板只认 `ConsoleEntry`」，
  加一项就只剩「登记一条」这一个动作。
- **注册表挂 `Global/Registry` 而不是新增 autoload** —— 与 `CharacterRegistry` / `BulletRegistry` 的取法一致
  （`Global.xxx_registry`），不增加第 10 个 autoload。
- **内置条目单独一个文件** —— 注册表与面板都不该认识「自动收集阳光」这种具体选项，加 / 删内置项只改这一处。
- **内置条目的读写一律写进 lambda** —— `ConsoleRegistry` 挂在 `Global` 下，它的 `_ready()` 跑在 `Global` 的 `@onready`
  之前，那时 `Global.config_service` 还是 null；写进 lambda 才是「取值时才读」。
- **持久化两条线**（绑已有字段 / `bind_config()` 通用键值区）—— 本体老字段的行为与存档位置完全不变，
  新增项与模组项走整包读写的 `console_values`，不用给 `ConfigService` 加字段。
- **`ConsoleBuiltinEntries._add()` 里写字面量 `&"builtin"` 而不是 `ConsoleRegistry.SOURCE_BUILTIN`** ——
  避免「注册表 → 内置条目 → 注册表」形成全局类的循环引用。

## 踩坑

1. **`Node.find_children()` 默认 `owned=true`，运行时 `add_child()` 的控件一个都找不到**
   → 现象：探针里面板控件数全是 0，但注册表条目数是对的
   → **正解**：第 4 个参数传 `false`（`find_children("*", "CheckBox", true, false)`）。
2. **`CheckBox` 也是 `Button`**，`find_children("*", "Button")` 会把 15 个勾选框一起算进来
   → 现象：「按钮应为 1 实际 16」
   → **正解**：按类型查完再排除 `not (node is CheckBox)`。
3. 探针自己漏给临时按钮写 `.set_category("探针")`，条目落进默认组「通用」，按组查就少一条
   → **正解**：不写分组的条目一律落 `ConsoleRegistry.CATEGORY_DEFAULT`，写探针断言时别默认它进了你那组。

## 给后来者的最简路径

1. 加一个**本体**开关 → 只在 `src/ui/console/console_builtin_entries.gd` 对应 `_register_*_entries()` 里加一段
   `ConsoleEntry.create_toggle(...).bind(...)`（要持久化且是新项就用 `bind_config()`）。
2. 加一个**模组**开关 → 在该模组的 `ModBase` 子类里重写 `register_console_entries(registry)`，`registry.register_entry(ConsoleEntry.create_toggle(...).bind_config("模组前缀.键名", false))`。
3. 跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_console_registry`（无头，秒级）+ `test/check_scripts.ps1`。
4. **不要**再去 `control_canvas_layer.tscn` 里加 CheckBox、也不要给 `ConfigService` 加字段 —— 那是改造前的老路。
