# 2026-10-13 · 其它 · 选卡界面植物排序：普通植物在最前且顺序固定，调试 / 模组的追加在最后，页数按总数算

## 目标

选卡界面（待选卡槽 `CardSlotCandidate`）的植物排列满足三条：

1. **普通植物在最前面，顺序固定** —— 装不装模组、开不开调试模式，前 48 株的页与格位都不变；
2. **调试模式植物与模组新增植物追加在后面** —— 它们彼此的先后无所谓；
3. **页数按植物总数算**（每页 48 格）。

## 步骤

1. 先量清现状再动手（`AllCards` 源目录 48 + 4：PlantCards 48 株普通植物，PlantCards2 就是那 4 株调试植物；
   待选网格模板 48 个占位 ⇒ 正好「第 1 页 = 普通植物，第 2 页 = 调试植物」）。
   ~~一开始以为是图鉴（`src/almanac/plant_page.gd`）要排序~~ → **放弃原因**：图鉴没有分页，且它按 `curr_plant`
   （解锁顺序）遍历，新植物天然在最后，不需要改。带「页数」的只有待选卡槽。
2. 在 `card_slot_candidate.gd` 加 `_build_ordered_plant_types()`：先按源目录顺序取普通植物，再把
   「调试模式专属」（`ConstPlantUnlock.DEBUG_MODE_PLANT_TYPES`）+「运行期注册的」（= 模组新增）追加到末尾。
3. 加 `_create_card_pages()`：**页数 = ceil(卡片总数 / 每页格数)** 一次算出来再建页，替掉原来
   「循环里填满了才顺带建下一页」的写法；格位下标改用**排列序号** `i % 每页格数`，不再用 `card_id`。
   容器字典仍按 `card_id` 登记（禁选 / 预选 / 重选上次卡片都按 `card_id` 找卡位，不能动）。
4. 模仿者页复用同一套顺序（它本来就跟普通植物页一一对应）。
5. 水盆模组 `_install_card()` 从「插在花盆卡后面」改成**追加到源目录末尾**（两处注释 + 模组页面说明同步改）。
6. 探针 `probe_water_bowl` 的 STEP2 断言跟着改：原来是「紧挨花盆 + 落在第 1 页」，现在按新规矩判
   「排在普通植物之后 + 页码 = 顺序下标 / 每页格数」。

## 关键决策与理由

- **排序放在消费侧（待选卡槽），不靠插入方自觉** —— 因为卡的编号是按源目录节点顺序算的
  （`AllCards.rebuild()`），插在中间会让后面每一株普通植物的 `card_id` 挪一格，最后一株被挤到下一页；
  本体不认识任何模组，没法要求模组一定插在末尾，只能自己排一次。
- **「是不是模组新增」用 `CharacterRegistry.is_runtime_plant()` 判**（新增的实例方法） ——
  本体只能认「走了 `register_runtime_plant()` 的」这一类，与 `register_runtime_plant` / `clear_runtime_plant`
  同一 region，语义自洽。
- **格位下标与 `card_id` 解耦** —— `card_id` 是「卡在源目录里的编号」，会被插入打乱；
  排列序号才是「摆在第几页第几格」。两者各管一件事，别混用。

## 踩坑

1. `CharacterRegistry.PlantInfo.has(...)` 编译不过（`Parse Error: Could not resolve external class member "PlantInfo"`，
   连带 13 条 `Failed to compile depended scripts`） → **类常量**引用撞了循环依赖（待选卡槽 → CharacterRegistry →
   数据表 → …）→ **正解**：改成实例方法 `Global.character_registry.is_runtime_plant()`，方法调用不触发常量解析。
   ⚠️ 判定方法：门禁输出里出现 `Could not resolve external class member` 基本就是这一类，先怀疑类常量引用。
2. `run_autopilot.ps1` 的 Godot 路径默认值指向已不存在的 `Godot_v4.6.2-stable_win64.exe` → 无头跑批直接
   `'...' is not recognized`，stdout 0 行 → **正解**：显式传 `-Godot 'C:\Users\a a\Desktop\godot.exe'`
   （`check_scripts.ps1` 的默认值已修，autopilot 这个还没修）。
3. `probe_card_lock` 有一条**既有失败**「商店生成 9 个植物卡商品 ← 10」，与本次改动无关
   （`row_upgrade_third` 里除了动态生成的 9 个紫卡 / 模仿者商品，还挂着一个静态的坚果包扎术商品）。

## 给后来者的最简路径

1. 要排顺序 → 在消费侧写一次「普通项 + 追加项」的显式排序，别改插入方。
2. 要分页 → 页数按总数 `ceili()` 一次算出来建页，格位用排列序号而不是源编号。
3. 判「这是不是模组加的」 → 走注册表实例方法，不要引用注册表的**类常量**。
4. 改完跑：门禁 + `probe_water_bowl` + `probe_bowling_debug_mode`。

## 人工验证方法（未开游戏，6 条）

1. 默认（不开调试、不装模组）进任意关卡选卡：第 1 页 48 格，页码显示 `1/1`，翻不到第 2 页。
2. 控制台勾上「调试模式」：第 2 页出现 4 株（三保龄球 + 反向双发），页码 `1/2`，第 1 页内容不变。
3. 装上「水盆」模组：水盆出现在**第 2 页**（第 1 页 48 格仍全是普通植物），页码 `1/2`。
4. 调试模式 + 水盆同开：第 2 页是「水盆 + 4 株调试植物」共 5 张，第 1 页不变。
5. 第 1 页最后一格仍是原版最后一株（玉米加农炮），没有被新植物挤到第 2 页。
6. 模仿者页的页序 / 格位与普通植物页完全一致（点模仿者 → 逐页对照）。
