## 目标

把迷你游戏第 1 关「植物僵尸」与第 17 关「植物僵尸 2」做到可交付：
消掉第 17 关文件头那条 `TODO(植物僵尸 2) 逐个确认 Z033Squash / Z034Jalapeno / Z035Gatling / Z039Pumpkin(高坚果)`，

可判定：两关都能进、能选卡、能打完；第 17 关出齐原版的 6 只植物僵尸；`probe_zom_botany` 仍 PASS。

## 步骤

   且「除了窝瓜僵尸，其余植物僵尸都有鸭子圈版本」。
2. 对照仓库现状找缺口：缺**高坚果僵尸**（此前用南瓜僵尸顶替）；第 1 关背景写成夜晚；第 17 关波数 20（应为 30）。
3. 新增高坚果僵尸（照 [植物僵尸.md](../参考存档/植物僵尸.md) §6 的四步走）：
   枚举 `Z044TallNutZombie` → `ZomBotanyConfig` 加一条（耐久 2200 / 战力 4 / 权重 2000，取 wiki 数值）
   → `ZombieInfo` 加一条 → 新建 `zombie_tall_nut.tscn`（继承 `zombie_norm.tscn`，只改 `zombie_type` 与 `max_hp_armor1`）。
4. 改关卡：第 1 关 `FrontNight` → `FrontDay` 并删掉多余的 `is_day_sun = true`；第 17 关 `start_battle(20)` → `30`、出怪表加高坚果僵尸。
5. 窝瓜僵尸 `ZombieRowType` 改 `Land`（它没有鸭子圈版本，不能出现在水面行）。
6. 写一次性实机探针进关卡跑一遍 → 顺带查出另外两个坑（见「踩坑」1、2）。
7. 扩 `probe_zom_botany`（14 只 / 高坚果耐久 / 窝瓜只走陆地行），删一次性探针。
8. 同步 [植物僵尸.md](../参考存档/植物僵尸.md)：加「两关怎么摆」一节、14 只清单、三个坑。

## 关键决策与理由

- **新增高坚果僵尸，而不是把南瓜僵尸改名为高坚果** —— 南瓜僵尸已经有自己的场景 / 贴图 / 出怪权重，
  改它是改旧内容；新增只是加一条配置 + 一个继承场景，两关都能各取所需。
- **耐久取 2200** —— wiki 高坚果僵尸总耐久 2470，是坚果僵尸（1100）的两倍档，和「高坚果植物耐久是坚果墙两倍」同比例。
- **两关出怪表不动（保留 13 / 12 只加料僵尸）** —— 上一轮记录明确把「植物僵尸关能出这 13 只」当目标，
  裁掉等于推翻它；原版口径写进文档 §2，想严格对齐照文档一行就能裁。
- **第 1 关背景改白天** —— 原版 ZomBotany 就是白天；此前 `FrontNight + is_day_sun = true` 是「夜晚底图配天降阳光」，自相矛盾。
- **不在泳池关出怪表里写 Z011Duckytube** —— 表外类型会被 `init_para()` 过滤（见踩坑 2）。

## 踩坑

1. **`card_mode = ConstLevelData.E_CardMode.Null` 会把关卡压成「一张卡都带不进去」**
   → `_apply_card_mode_constraints()`：`card_mode != Norm` 且 `can_choosed_card` → 强制 `can_choosed_card = false`，
   而本关又没有预选卡 → 玩家零植物 → 关卡没法打（第 1 关一直就是这个状态）
   → **正解**：删掉这行，卡槽模式走默认值 `Norm`。
2. **泳池关出怪表写 `Z011Duckytube` 会被静默过滤**
   → `init_para()` 按 `whitelist_refresh_zombie_types_with_zombie_row_type[地图默认行类型]` 过滤，游泳圈僵尸不在陆地白名单里，
   只在日志里留一行 `warning: 出怪刷新列表中 ZombieDuckytube 不在当前场景可以自然刷怪列表`
   → **正解**：不写它；水面行由两栖（`Both`）僵尸顶上，入水自动套鸭子圈（`body_change_on_pool`）。
   （顺带：`minigame_16_last_stand` 的出怪表里也有 Z011，同样会被滤掉 —— 未改，留给该关的收尾。）
3. **一次性探针被别的进程抢输出** —— `run_autopilot.ps1` 把输出写到固定临时文件 `pvz_autopilot/ap_out.txt`，
   同时有另一个 agent 在跑 Godot（无头模式: false），读回来的是**别人那次**的报告（场景名都对不上）
   → **正解**：直接用 `cmd.exe /c '"<godot>" --headless --path "<项目>" -- --scenario=... > 自己的文件 2> 自己的文件'` 跑，
   路径带空格时用**单引号包整条**（PowerShell 单引号串里的双引号原样给 cmd）。
4. **探针里 `_check(label, got, want)` 与 `_check(label, ok, detail)` 两种签名混用** → `bool == String` 运行时报错，
   而报错发生在 `await` 之后就直接被看门狗超时吞掉（看不到 FAIL 行，只看到 120s 超时）
   → **正解**：统一成 `_check(label, ok: bool, detail := "")`（照 `probe_zombie_drop_chocolate.gd` 的写法）。
5. **`ZombieManager` 上没有 `zombie_choose_row_system` 属性**（它在 `ZombieWaveCreateManager` 下，`@onready %ZombieChooseRowSystem`）
   → **正解**：`zombie_manager.get_node_or_null("ZombieWaveManager/ZombieWaveCreateManager/ZombieChooseRowSystem")`。

## 补充 / 评价（2026-10-05）

**来自**：[2026-10-05\_豌豆僵尸对齐原版行为.md](2026-10-05_豌豆僵尸对齐原版行为.md)

- 本记录第 7 步「扩 `probe_zom_botany`」当时只锁了**场景属性**，没锁行为 ——
  结果漏了两个只有进关卡才暴露的坑，都在续作里补掉了：
  1. 发射挂在 `is_attack_res` 上 + 检测区撑到 760 像素宽 → 僵尸**停在几百像素外啃空气**（原版是照常走 + 恒定发射）；
  2. `ZombiePlantComponent` 在 `_ready()` 里连 `hp_component` 的信号 —— 宿主 `@onready` 还没赋值，
     **静默失败**，头顶植物怎么打都打不掉。
- **对本记录的评价不变（推荐）**：关卡设置那部分（白天 / 波数 / 出怪表 / `card_mode`）结论仍然成立。
  但「跑静态探针 PASS」不等于「能玩」，后续同类任务**应该**再补一个进关卡的一次性探针。
