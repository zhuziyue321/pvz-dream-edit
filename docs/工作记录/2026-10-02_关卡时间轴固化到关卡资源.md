# 2026-10-02 · 关卡与地图 · 关卡时间轴固化到关卡资源（先做多轮特殊关）

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（下次给其它关配时间轴照这个走）
> **耗时与成本**：约 1 轮对话，开了游戏（带窗口跑 4-5 实机 + 无头跑数据探针）
> **验证方式**：打开游戏实测（冒险 4-5 三批砸罐子实机）+ 新增数据探针自动校验 15 关等价
> **补充自**：无

## 目标

把「只有代码里生成、编辑器里看不见」的默认关卡时间轴，写成 `.tres` 资源挂到具体关卡上，
让流程在编辑器里**可见可调**；先覆盖多轮特殊关（砸罐子 / 我是僵尸无尽 / 生存模式）。

## 步骤

1. 确认现状：`ResourceLevelTimelineData` / `ResourceLevelTimelineEvent` / `LevelTimelineManager`
   已经落地，但**没有任何关卡真的配了 `timeline`**，100 多关全部走 `build_default_timeline()`。
2. 按关卡族定时间轴资源（放 `src/levels/timeline/<模式>/`）：
   - `mode_adventure/adventure_04_05_timeline.tres`（3 批砸罐子，独占一份）
   - `mode_puzzle/puzzle_pot_common_timeline.tres`（砸罐子通用，18 / 19 / 20 共用）
   - `mode_puzzle/puzzle_zombie_10_timeline.tres`（我是僵尸无尽）
   - `mode_survival/survival_flag_common_timeline.tres`（生存模式通用，06 ~ 15 共用）
3. 手写 4 份 `.tres`（**不用 Godot 重新保存关卡资源**：那样会丢掉文件里 `;` 开头的原版考据注释）。
   事件里的说明一律写进 `note` 字段（编辑器可见、不会被保存冲掉）。
4. 挂到 15 个关卡资源：手改冒险 4-5，其余 14 个用一次性 PowerShell 脚本批量插入
   （`load_steps + 1`、加 `ext_resource`、在 `[resource]` 段首行后写 `timeline = ExtResource(...)`），跑完删脚本。
5. 写数据探针 `test/scenarios/probe_timeline_data.gd`（无头可跑）：逐关比较「固化轴」与
   「把 `timeline` 置空后 `build_default_timeline()`」的事件序列。
6. 带窗口跑 `probe_4_5_flow` 实机验证三批砸罐子。

## 关键决策与理由

- **共用 vs 每关一份**：流程完全相同的关卡族（10 个生存关、3 个砸罐子无尽关）共用一份资源文件，
  靠文件名后缀 `common` 标明，共用文件头注释写「某关要单独改就复制一份再改」——
  每关一份会产生 10 份逐字重复的文件，改一处要改 10 次。
- **轴写的是「一轮」的流程，不是整关**：`start_curr_round_game()` 每轮重跑一遍时间轴，
  所以轮内写 2 步、跑 3 轮就是 6 步。写轴前先想清楚「这一步是每轮都有还是只在第一轮」
  （只在首轮用 `is_first_round_only`）。
- **只写本关真实生效的步骤**：默认轴为了通用带了一堆按开关跳过的步骤，固化到具体关卡时该删就删。
  4-5 最后就是轮内 2 步（戴夫对话 → 开战），删掉了戴夫推销 / 教程 / 红线三个在本关空转的步骤。
  生存 / 解谜那 3 份目前仍是「与默认轴逐条一致」的保守版（空转步骤留着 + `note` 标注）——
  它们没有对应的实机探针，先求零风险，后续要精简照 4-5 的做法来即可。
- **手改 `.tres` 而不是用 Godot 保存**：Godot 重新序列化会丢掉关卡文件里大量 `;` 原版考据注释。
- **新增文件不写 `uid`**：引用方一律用 `path`（与 `data/tutorial/*.tres` 一致），
  Godot 之后补 uid 也不影响加载。

## 踩坑

1. **把时序偶发当成因果（误判，已澄清）**
   → 现象：第一版精简轴（4-5 轮内 2 步）跑 `probe_4_5_flow`，第一次点戴夫对话就报
   `Parent node is busy adding/removing children, remove_child() can't be called at this time`，
   stdout 只有 40 行进程就没了；摘掉 `timeline` 用默认轴跑同一探针则三批全过（45 秒）。
   → 误判：据此认定「省掉空转步骤改变了戴夫对话的起始时机」→ 不敢精简，改成忠实固化。
   → 澄清：那条 ERROR **挂轴 / 不挂轴、精简 / 不精简都会报**，是既有缺陷且不影响流程走完；
   后来把 4-5 改回精简版连跑两次都正常（45.0s / 44.9s，三批 25 罐数据一致）。
   那次中断判定为**偶发**（新资源首次被 Godot 导入那一次）。
   → **教训**：单次实机失败先复跑确认再下结论，别拿一次现象当因果写进文档。
2. **等价性不能靠读代码推**：15 个关卡的开关（展示僵尸 / 可选卡 / 出怪模式 / 红字）各不相同，
   手写的序列很容易漏一条。→ 正解：写纯数据探针自动比对（探针直接 `load` 资源，不用切场景，无头几秒跑完）。
3. **改 `.tres` 时 Godot 编辑器开着**：编辑器可能把内存里的旧版本写回磁盘。
   → 正解：批量改之前先关编辑器；这次是在编辑器运行时改的，改完用探针重读磁盘确认落盘。

## 给后来者的最简路径

1. 复制 `src/levels/timeline/` 下同族的那份 `.tres`，改名（如 `adventure_01_05_timeline.tres`）。
2. 先在代码里确认这关的默认轴长什么样：临时打印 `ResourceLevelData.build_default_timeline()` 的事件序列照抄，
   再**删掉本关确定空转的步骤**（戴夫推销 / 教程 / 红线，判定见 [关卡时间轴.md](../参考存档/关卡时间轴.md)）。
   写的是「一轮」的流程，多轮关每轮重跑一遍。
3. 关卡 `.tres` 加三处：`load_steps + 1`、一条 `ext_resource` 指向新文件、`[resource]` 段里 `timeline = ExtResource("N_tl")`。
4. 把新关卡路径加进 `test/scenarios/probe_timeline_data.gd` 的 `LEVEL_PATHS`；
   刻意精简过的（不与默认轴等价）再往 `CUSTOM_EXPECT` 里写死期望的轮内序列。
   然后 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_timeline_data`，
   看到 `[TIMELINEDATA] result=PASS` 才算过。
5. 触达具体关卡玩法时再带窗口跑一次对应探针（`-Windowed`），**失败先复跑一次再下结论**（见踩坑 1）。

- 4 份已固化 `.tres` 全部改成「`sub_resource.script` 指向事件脚本」，数组类型用基类脚本。
- 探针：`probe_timeline_data` 的 4-5 期望序列改成 8 事件；`probe_timeline`（1-4）期望 8 步。

- `probe_4_5_flow`（带窗口）：三批全过 45.5s，第 3 批 25 罐 / 占列 4-8 / 绿罐 3，日志里能看到

- 两条设计原则（已写进 [参考存档/关卡时间轴.md](../参考存档/关卡时间轴.md)）：

- **补充**：本记录的「用默认轴批量生成固化轴」这条路径漏了一类**生成时与运行时不一致的开关**。

  于是 **1-10 / 2-10 / 3-10 / 4-10 / 5-5 / 5-10 / minigame_05_column 这 7 关的固化轴上带了一条

  修法见 [卡片与选卡流程.md](../参考存档/卡片与选卡流程.md)——`is_no_choose_permission()` 增加第 0 条
  `not can_choosed_card`，并给 `CardManager.card_slot_disappear_choose()` 判空。
- **评价**：数据等价探针（`probe_timeline_data`）在这条路上**查不出这类问题**——

- **更省的做法**：批量生成固化轴之后，**每种卡槽模式（Norm / 传送带 / 金币卡槽）各挑一关
  带窗口或无头实机跑一遍**，确认能走到 `MAIN_GAME`；只看数据探针不够。
