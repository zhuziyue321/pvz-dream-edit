
# 2026-10-06 · 其它 · 僵尸迷阵的「点两株交换」改成原版口径的「按住拖到相邻株」

> **任务类型**：其它
> **推荐度**：**推荐**（下次做「拖动类玩法」照这个走）
> **耗时与成本**：约 2 轮对话，跑了无头探针 `probe_beghouled` + `probe_beghouled_twist`（未开窗口，已给人工验证方法）
> **验证方式**：免验证（无头探针已用**合成鼠标事件**走完真实链路）+ 已给出人工验证方法
> **补充自**：无（同类首例）

## 目标

僵尸迷阵（迷你 05）原来是「点第一株选中 → 点相邻第二株交换」，改成原版 Beghouled 的**按住一株不放、把光标拖到相邻株上**就交换；
点一下不再有任何反应。09 关「旋风」是点一下旋转 2×2，不能跟着变成拖动。

## 步骤

1. **先定口径再动手**：原版是「按住 + 移动光标」（不是点两下）—— GameFAQs 攻略原话
   「Swap two plants by pressing on one plant then hold while you move your cursor to where you want to switch with」
   （<https://gamefaqs.gamespot.com/boards/961689-plants-vs-zombies/56448845>）。
   常量 `DRAG_SWAP_RATIO` 的文件头把这句原话抄进去，口径就不会再被后人改回去。
2. `BeghouledManager`（`src/levels/core/beghouled/`，05 / 09 共用）：
   - `_connect_board_cells()` 加一条 `cell.button.button_down.connect(_on_press_cell.bind(cell))`，并 `set_process(true)`；
   - `_on_press_cell()` 记起点格子 + 按下时的光标位置（`cell.get_local_mouse_position()`），并亮高亮框；
   - `_process()` 每帧：左键没按着了 → 最后再判一次后收摊；拖过 `DRAG_SWAP_RATIO`（半格）→ `_check_drag_swap()`；
   - 删掉 `selected_cell` / `_select_cell` / `_is_adjacent`，`_clear_select()` 改名 `_cancel_drag()`（顺手清 `_drag_from_cell`）；
   - 基类 `_on_click_cell()` 留成**空钩子**：09 旋风关要覆盖它做点击旋转。
3. 09 关 `minigame_09_beghouled_twist_manager.gd`：覆盖 `_on_press_cell()` 为空（拖动链不启动）+ `_clear_select` → `_cancel_drag`。
4. 探针（关键）：给 `AutopilotInput` / `autopilot.gd` 加 `drag()` / `drag_plant_cell()`，
   `probe_beghouled` 的 STEP3 改成 **合成真实鼠标事件**（warp → down → 中途 4 帧移动 → up），
   不再直接 `_on_click_cell()`；再加 STEP3.1 断言「单击不交换」。
5. 同步文档：`docs/参考存档/特殊关卡.md` 两条（05 的玩法口径 + 拖动手感条目、09 的「本关覆盖掉拖动」说明）。

## 关键决策与理由

- **按下用 `Button.button_down`，不用 `_input` / `_unhandled_input`** —— 格子 Button 会把鼠标事件消费掉
  （`hammer.gd` 的注释已经踩过：点在 HUD 控件上的点击到不了 `_unhandled_input`），只有 Button 自己的信号收得到。
  顺带保证「按下点必须在草坪上」：从卡槽卡片上按着拖进草坪不会误触交换。
- **松手用 `Input.is_mouse_button_pressed()` 轮询，不接 `button_up`** —— 光标拖出草坪 / 拖到 HUD 上松手时，
  那个 `button_up` 不一定送到起点那个 Button；问输入状态最稳。拖动之外 `_process` 立刻 return，不是常驻开销。
- **阈值取「半格」而不是「拖进目标格」** —— 更跟手，且玩家能在松手前把光标拖回原格取消这一次。
- **位移用格子的 `get_local_mouse_position()` 比，不用全局坐标** —— 起点与当前都在同一格的局部空间里，
  不受画布变换 / 相机影响；阈值 `cell.size` 也是同一空间。
- **只认上下左右相邻一格，空格 / 弹坑换不动** —— 与原版一致（盘面上只有植物能换）。

## 踩坑

1. **探针里 `:=` 从 Variant 推断类型 → 编译报错**（`The variable type is being inferred from a Variant value …
   Warning treated as error`）：`_plant_cell_center()` 取不到格子时返回 `null`，调用处写 `var c := ...` 就炸；
   `var drag_ok := await a.drag_plant_cell(...)` 同理（探针的 `a` 是无类型的）。
   → **正解**：这两处显式标类型（`var c: Variant` / `var drag_ok: bool`）。本仓库把告警当错误，探针里接无类型返回值一律显式写。
2. ~~想让被拖的植物跟着光标走（原版有这个表现）~~ → **放弃**：植物节点在格子容器里，`position` 被自己的组件与
   啃咬检测用着，改它风险大且难以在本仓验证；退化成「起点格高亮」—— 交互是原版口径，表现层不做。

## 给后来者的最简路径

1. 定口径（wiki / 攻略原话）→ 写进常量的文件头注释。
2. 按下接 `cell.button.button_down`，拖动判位移（格子局部坐标 + 半格阈值），松手用 `Input.is_mouse_button_pressed()` 兜底。
3. 基类把「单击」留成空钩子给点击类子类覆盖，子类再覆盖「按下」切断拖动链。
4. 探针用 `a.drag_plant_cell(r1,c1,r2,c2)` 走真实事件（已加进 `AutopilotInput`），别直接调管理器的私有方法。

**人工验证方法**（无头探针跑不了手感）：打开游戏 → 迷你游戏第 5 关「僵尸迷阵」→
① 按住任意一株往相邻株方向拖过半格 → 两株立刻换位（凑不成连线会自己换回）；
② 松手前把光标拖回原格 → 不交换；③ 单击一株 → 只有高亮、不交换；
④ 迷你游戏第 9 关「旋风」点一下仍是旋转 2×2，拖动它不会交换。
