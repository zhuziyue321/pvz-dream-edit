## 目标

改模组 `mods_builtin/more_armor/` 的**铜桶**：除下列两处外与铁桶完全一致 ——
① 随时间获得易伤，**只对防具有效**；② 贴图变成铜锈色。

## 步骤

1. 先读 [防具.md](../参考存档/防具.md) 定落点：伤害沿防具链走，本体只拿「防具没吃掉的那部分」，
   ⇒ **「只放大防具」只能做在防具自己吃的那一步**（`ArmorComponent.absorb_damage()`），
   也就是写一层模组自己的防具子类，本体一行都不用动。
2. 新增 `mods_builtin/more_armor/armor_copper_bucket.gd`（`extends ArmorComponent`）：
   `_process` 累计在场时间 → 氧化进度 0→1 → 易伤倍率 1.0→2.0（30 秒到底）；
   `absorb_damage()` 只放大「按剩余伤害扣 + 溢出下传」那一类，并**把下传量夹回原始伤害**。
3. 改 `zombie_copper_bucket.gd`：血量 800 → **1100（对齐铁桶）**；`build_runtime_parts()` 里
   先把本体那层基类防具换成铜桶那层（`_equip_copper_armor()`），再 `super()` 走公共装配，
   最后按氧化进度染三张桶精灵（头上 / 被吸走 / 掉地上）。
4. 同步三处：`more_armor_mod.gd` 模组页面文案、`probe_more_armor_mod.gd`（800→1100 + 铜桶专属 6 条断言）、
   [模组机制.md §6.3](../参考存档/模组机制.md) 与 [防具.md](../参考存档/防具.md) 的那句备注。
5. 门禁 + 探针：`check_scripts.ps1`（0 error）→ `probe_more_armor_mod`（PASS failed=0）→
   `probe_mod_page`（PASS failed=0）。

## 关键决策与理由

- **易伤长在防具组件里，不长在僵尸脚本里** —— 宿主拿不到「这一层吃了多少伤害」的判断权，
  硬做只能去改本体结算；做在防具里则完全符合「防具存在时的效果由防具自己定义」。
- **放大后必须把下传量夹回原始伤害**（`mini(passed, remain - absorbed)`）——
  否则防具一破，多出来的伤害会溢到本体；更隐蔽的是 `break_armor()` 也走伤害管线，
  磁力菇吸个桶会直接啃掉僵尸本体几百血。
- **固定伤害（保龄球 / 锤子）与原样下传（穿透二类）不放大** —— 那几条的口径是「打多少就是多少」，
  放大会改掉原版那张分配表。判据写在 `get_absorb_rule()` 的返回上，不用认模式。
- **换一层防具而不是 `set_script()`** —— 运行期换脚本会把场景里配好的类别 / 铁器 / 音效清回默认值
  （`ZombieRuntimeRecipe._apply_script()` 那条注释就是这事），所以先抄配置 → 摘掉旧层 → `add_armor()` 挂新的。
- **颜色走 `modulate` 的 lerp，不做新美术** —— 仓库里没有铜锈色的桶贴图，用「铜色 × 铜锈色」乘法染色，
  顺带让颜色本身成为「还剩多少血（有多脆）」的视觉提示。
- **血量 800 → 1100**：需求写的是「其余与铁桶相同」，铜桶的弱化改由氧化承担；
  出怪战力 / 权重 / 阳光（3 / 1600 / 100）**没动** —— 那是模组自己的稀有度阶梯，不是「铜桶是什么」。

## 踩坑

1. **探针里 `协程函数(a)` 不 await → 那一段断言凭空消失且不报错** ——
   `_check_copper_extra(a)` 里有 `await a.frames(20)`，调用处没写 `await`，
   它在第一个 await 处挂起，而 `run()` 继续跑完直接 `quit_game()` ⇒
   第一次跑出来「PASS failed=0」但铜桶那 5 条断言一条都没打印。**现象：探针 PASS 而断言数对不上。**
   **正解**：调用协程一律 `await`；写新探针时顺手核对「打印的断言条数 = 自己写的条数」。
2. **探针读模组防具上的成员不能标类型** —— 防具的静态类型是基类 `ArmorComponent`，
   上面没有「氧化进度 / 易伤倍率」，标了类型编译不过。改成 `var armor = hp.get_all_armors()[0]`
   （`=` 推断为 Variant；写成 `:=` 才会推断成静态类型）。
3. **关卡之外打伤害只能打「不会打破防具」的量** —— 防具一破就走掉落，掉落物要挂到 `zombie_manager` 下，
   关卡外会报 Nil（[防具.md](../参考存档/防具.md) §6）。本次打 100（防具 1100）刚好绕开。
4. `run_autopilot.ps1` 的默认 Godot 路径已失效 —— 必须显式传 `-Godot "C:\Users\a a\Desktop\godot.exe"`。

## 给后来者的最简路径

1. 要「只影响防具的效果」→ 在模组里写 `extends ArmorComponent` 的子类，重写 `absorb_damage()`；
   放大伤害时**务必把下传量夹回原始伤害**。
2. 换防具走 `add_armor(armor_type, max_hp, armor_class, 模组防具脚本, priority)`，
   旧那层的 `armor_type / armor_class / absorb_priority / sfx_be_attack / iron_node` 先抄下来再搬。
3. 外观（染色 / 换贴图）归宿主僵尸脚本，进度向防具组件要，宿主不自己存一份。
4. 收尾：门禁 + `probe_more_armor_mod`（**核对断言条数**）+ 同步模组页文案与两份机制文档。

1. 主菜单 → 选项 → 控制台 → 模组 → 打开「更多的防具」，看右侧文案是否写着铜桶 1100 / ×2.0 / 30 秒。
