# 2026-10-12 · 排查调试 · 联机时客户端的僵尸迷阵滑动只动自己的盘面

> **任务类型**：排查调试
> **推荐度**：**推荐**（下次给「某一种玩法补联机」照这个走）
> **耗时与成本**：约 1 轮对话 / 未开游戏 / 无需人工介入
> **验证方式**：免验证 + 已给出人工验证方法（见最简路径第 4 条）
> **补充自**：无

## 目标

联机（房主 + 客户端）打迷你游戏 05「僵尸迷阵」时，客户端拖植物做三消要真正作用到**主机那一局**，
并且两端的盘面保持一致（不能各跑各的）。

## 步骤

1. 先确认「滑动」走的是哪条输入链：`BeghouledManager._on_press_cell`（`PlantCell.button` 的
   `button_down`）→ `_process` 每帧轮询 `Input.is_mouse_button_pressed` → `_check_drag_swap` → `_try_swap`。
   全链路搜 `rpc / is_host / 联机 / 同步` **零命中** —— 它压根没过 `GlobalUtils.player_action_gate`。
2. 确认为什么「自己换一下」不行：盘面只有主机那一份。客户端换的是自己的盘面，
   主机毫无变化 ⇒ 客户端的盘面与主机越走越远（`NetplayStateSync._align_plants` 只按
   `entity_id` 对齐，**不纠正格子与类型**，岔开了收不回来）。
3. 于是按「主机权威」的既有套路补一条命令：
   - 本体加通用操作 `GlobalUtils.E_PlayerAction.SwapCell`（payload `[PlantCell, PlantCell]`）；
   - 本体加通用落地口 `ConstEventName.MAIN_GAME_SWAP_CELL`（payload `[行A, 列A, 行B, 列B]`），
     与 `MAIN_GAME_CLICK_SHOVEL` 同款，模组只推事件，**不需要认识三消**（硬约束 §1-8）；
   - `NetplayCommand.OP_SWAP_CELL` + `NetplayBattleSync._replay_swap_cell()` 推那条事件；
   - `BeghouledManager` 把一次交换拆成 `_try_swap`（发起，过上报口）与 `_do_swap`（执行，被事件驱动）。
4. 补「两端得有同一份盘面」这个前提：三消的摆场 / 补位 / 重排原先走**全局随机**与共享的
   `GameRng`。给 `RandomPicker.get_random_item()` 加了可选 `rng` 参数，三消改持一条
   **本关私有随机流** `_board_rng`（种子取 `GameRng.get_seed()`），不挤占共享序列。
5. 顺手补 `BeghouledManager._drop_one_sun()` 的 `GlobalUtils.sun_spawn_gate`
   （原先漏了 ⇒ 客户端一次消除会掉两份阳光）。
6. `test/check_scripts.ps1` → `real compile errors = 0`。

## 关键决策与理由

- **本体 / 模组两侧都只写「两格互换」，不写玩法名** —— 一关专属玩法归关卡脚本（硬约束 §1-8）；
  这样模组新增一条命令只多一个枚举值 + 一支 `match`，不必认识 `BeghouledManager`。
- **用事件落地而不是让模组去找三消管理器** —— 与 `_replay_click_shovel()` 推
  `MAIN_GAME_CLICK_SHOVEL` 同一套写法；模组按名字找关卡侧节点等于把一次性玩法写进模组。
- **客户端被接管后本地一笔不动** —— 它从没自己改过盘面，所以只是按顺序重放主机**接受下来**的
  那些交换；主机拒掉的那一笔不会下发，两端依旧一致（不必再加"请求中"的锁）。
- **私有随机流而不是共用 `GameRng`** —— `GameRng` 是全项目共享序列，僵尸那一族也在抽，
  谁多抽一次后面全串位，且**没有任何报错**（出怪那条线已经踩过）。
- ~~让 `NetplayStateSync._align_plants` 变成"格子 / 类型"全权纠偏，客户端纯镜像~~
  → **放弃原因**：快照（unreliable）会比 `battle_op`（reliable）先到 ⇒ 客户端先被快照搬一次、
  再被 op 重放一次 ⇒ **二次交换**。改成两端重放同一串就没有这个竞态。

## 踩坑

1. 现象：客户端拖了没反应 / 换回去 / 后面棋盘全乱 → 滑动没过 `player_action_gate`，
   主机那一局毫无变化，而快照层不纠正格子与类型 → **正解**：把滑动做成一条命令上行，
   同时让两端的盘面同源（私有随机流）。
2. 现象：客户端一次消除掉两份阳光 → `BeghouledManager._drop_one_sun()` 漏了 `sun_spawn_gate`
   （文档里写着"宝石迷阵已收归主机"，代码没接） → **正解**：补上闸门判断。
3. 现象：`_do_swap` 里再调 `submit_player_action` 会递归 → **正解**：执行口不再问上报口，
   「发起」与「执行」必须是两个函数。

## 给后来者的最简路径

1. 本体：`GlobalUtils.E_PlayerAction` 加一个值 + `ConstEventName` 加一条事件（登记 payload 签名）。
2. 模组：`NetplayCommand` 加 `OP_*`（含 `op_from_action` / `args_from_action` 两支 match），
   `NetplayBattleSync._execute_inner` 加一支 match 推那条事件。
3. 玩法侧：把操作拆成「发起（过 `submit_player_action`）」+「执行（订阅那条事件）」两个函数；
   凡是影响盘面的随机，改成**本关私有可播种流**（种子取 `GameRng.get_seed()`）。
4. 人工验证（未开游戏）：用 `test/run_netplay_pair.ps1` 起一对，房主与客户端都进迷你游戏 05；
   客户端拖一次 → 房主那一局的对应两株也要换位置、配对进度 +1、消除的阳光只在主机下发后出现一次。
