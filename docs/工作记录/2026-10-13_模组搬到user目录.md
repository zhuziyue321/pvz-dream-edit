
# 2026-10-13 · 其它 · 模组运行时搬到 `user://mods`，仓库里只留安装源与 autoload

> **任务类型**：其它（目录迁移 / 运行时加载方式改造）
> **推荐度**：**推荐**（「把运行时文件从 `res://` 挪到 `user://`」照这个走：**先探测引擎能力 → 再决定改造量**，别凭猜）
> **耗时与成本**：约 6 轮对话；**未开游戏窗口**，用无头探针 + 编译门禁验证
> **验证方式**：编译门禁 PASS（`real compile errors = 0`）+ 无头运行时三轮验证（7 个模组全部实例化、指纹同步三种状态全对）
> **补充自**：无

## 目标

把模组**运行时**从 `res://src/mods/` 挪到 **`user://mods/`**（玩家能直接改自己那份、能放自己的模组），
同时保证① 编译门禁仍然覆盖得到 ② 本体对 `ModIds` / `ModConfig` 的编译期引用不断 ③ 五个现役模组行为不变。

可判定：`ModManager` 从 `user://mods/` 装载并打印「已装载模组」；`test/check_scripts.ps1` 结果 PASS。

## 步骤

1. **先探测引擎能力，再决定改造量**（这一步决定了后面 80% 的工作量，别省）：
   写临时探针 `test/tmp_*.gd` + `--script` 驱动脚本，实测 `user://` 下 `.gd` / `.tscn` 的加载边界。
2. 把探测结论摆给用户，确认搬迁范围（三个选项：只搬数据 / 搬模组不含框架 / **含框架一起搬**），用户选了含框架。
3. 物理移动：`src/mods/` 下的 `mod_base.gd` / `mod_ids.gd` / `mod_config.gd` + 五个模组目录 → 新建 `mods_builtin/`（连 `.uid` 一起搬）。
4. `.tscn` 的 `ext_resource` 与脚本里的 `preload` 全改**相对路径** —— 这样同一份文件在 `res://mods_builtin/` 和 `user://mods/` 下都自洽。
5. 去掉模组脚本的 `class_name`，`extends ModBase` → `extends "../mod_base.gd"`，互相引用改 `const X := preload("x.gd")`。
6. 删掉指向这些类的类型标注（`var m: ModBase` / `-> NetplaySession` / `as Xxx`）。
7. 断 `preload` 环：`hammer_mod.gd` ⇄ `hand_component_hammer_mod.gd` 互引 → 抽出 `hammer_settings.gd`（与原来的 `glove_settings.gd` 同款处理）。
8. 修 9 个引用了模组类的探针（补 `preload` 常量）。
9. 同步文档：`src/mods/README.md` 重写、新建 `mods_builtin/README.md`、`AGENTS.md` §6 表、`docs/README.md` §3、`模组机制.md` §2.0 / §四 / §五，以及 62 处路径引用批量替换。
10. 把「手写 `BUILTIN_MODS_VERSION`」换成**安装源内容指纹**（见下「关键决策」）。

## 关键决策与理由

- **`src/mods/` 只留 `mod_manager.gd`** —— autoload 脚本必须是 `res://` 资源，搬不走；其余（基类 / id 表 / 五个模组）全进 `mods_builtin/`。
- **新建 `mods_builtin/` 当安装源** —— `user://` 是运行时目录，仓库里的文件不会自己跑过去。它在 `res://` 与 `user://` 下都能自洽编译，等于「一份源码两处可用」。
- **`mod_ids.gd` / `mod_config.gd` 保留 `class_name`**，其余模组脚本去掉 —— 前两者是本体 ↔ 模组的契约，`adventure_04_06.gd`、`data/mods/mod_config.tres` 要按名字编译引用；保留它们的 `class_name`，**这两处引用点一行都不用改**。
- **同步判定用「安装源内容指纹」而不是手写版本号** —— 版本号方案一天内踩了三次（我自己两次、另一个 agent 一次）：忘了 +1 就静默跑旧代码。改成算 `res://mods_builtin` 每个文件的 `FileAccess.get_sha256()` 汇总，全自动；且指纹算的是**安装源**那一侧，玩家改 `user://mods/` 不会让指纹变化，改动不会被冲掉。

## 踩坑

1. **`user://` 下脚本的 `class_name` 不注册为全局类**（实测 Godot 4.6.2）
   → 现象：`extends ModBase` / `var m: ModBase` 一律 Parse Error "Could not find base class"。
   → **正解**：`extends "../mod_base.gd"`（相对路径）+ 跨文件引用一律 `const X := preload("x.gd")`。
2. **`Script.instance_has()` 对 `user://` 脚本恒为 `false`**
   → 现象：5 个模组全部报「不是 ModBase 子类」，但基链打印出来明明白白是 `user://mods/mod_base.gd`。
   → 原因：`user://` 路径的脚本**不走资源缓存**，`load()` 每次都是新对象，指针比不上（实测 `load("user://x.gd") == load("C:/绝对路径")` 为 `false`）。
   → **正解**：沿 `get_base_script()` 基链**比 `resource_path`**（`ModManager._extends_mod_base()`）。
3. **批量删类型标注的正则跨行吃掉了换行**
   → 现象：`Parse Error: Expected a newline after "match" statement`。
   → 原因：`:\s*(Name)\b` 里的 `\s*` 会跨行匹配，把 `match state:` 的换行和下一行的 `NetplaySession.` 一起吃掉，变成 `match state.E_State.Idle:`。
   → **正解**：逐行处理、`:` 后只允许空格；改完用「`match` 关键字行 `:` 必须在行尾」复核一遍。
4. **`:=` 推断失败一片**（`Cannot infer the type of "xxx" variable`）
   → 原因：宿主变量失去类型后，`mod.xxx()` / `_session.xxx()` 返回 Variant。
   → **正解**：显式标注（`var others: Array = ...`）或退回 `var x = ...`。这类错**一次只报文件里第一条**，要反复跑门禁才能捞干净。
5. **`preload` 跨 `res://` → `user://` 其实是可行的**，第一次测成失败是假象
   → 原因：`--script` 模式下脚本先于 autoload 编译，那时 `user://mods/` 还没被同步出来。
   → **正解**：验证「依赖同步结果」的行为必须放到 `_process()` 里跑（`_initialize()` 太早）。
6. **`cd` 在每次命令里不一定生效**（PowerShell 会话似乎会重置）
   → 现象：相对路径被解析到仓库根，报「找不到路径的一部分」；`Get-Content` 不带 `-Encoding UTF8` 还会把中文读成乱码。
   → **正解**：脚本一律用**绝对路径**，读写中文文件显式 `[System.Text.UTF8Encoding]::new($false)`。

## 给后来者的最简路径

1. **先写临时探针把引擎边界测清楚**（`class_name` 注不注册、`.tscn` 相对路径行不行、`preload` 能不能跨、`instance_has` 准不准），再动手搬。
2. 移动文件 → 改相对路径 → 去 `class_name` → 补 `preload` 常量 → 删类型标注（**逐行**、别用跨行正则）。
3. 互相 `preload` 的环，用「抽第三个文件」断（`glove_settings.gd` / `hammer_settings.gd` 是现成样板）。
4. 判断「某实例是不是某基类」用 `get_base_script()` 基链比路径，**不要**用 `instance_has()`。
5. 同步机制直接上**内容指纹**，别用手写版本号。
6. 反复跑 `test/check_scripts.ps1` 直到 PASS（类型推断错误一次只报一条，要迭代几轮）。
