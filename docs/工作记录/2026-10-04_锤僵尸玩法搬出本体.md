# 2026-10-04 · 其它 · 锤僵尸玩法搬出本体（迷你游戏 15 + 冒险 2-5 共用一条规则）

> **任务类型**：其它
> **推荐度**：**推荐**（下次「本体里有 6 处散落的 `if is_xxx` 分支要收」照这个走）
> **耗时与成本**：约 1 轮对话，带窗口跑新探针 `probe_hammer_zombie`（27 断言全过）
> **验证方式**：打开游戏实测（带窗口探针，`[HAMMER] result=PASS failed=0`，含通关出奖杯与失败流程）
> **补充自**：[2026-10-04\_僵尸迷阵三消整包搬出本体.md](2026-10-04_僵尸迷阵三消整包搬出本体.md)（那次给了「本体只留一个通用口子」的思路）、[2026-10-04\_排山倒海整列种植收进关卡脚本.md](2026-10-04_排山倒海整列种植收进关卡脚本.md)（同类的「散落分支收拢」）

## 目标

锤僵尸玩法只有 2 关（`minigame_15_hammer_zombie` / `adventure_02_05`），本体里却有 6 个文件各留一条分支：
`zm_hammer_zombie_manager`（常驻主场景）、`main_game_manager`（鼠标显隐）、`mgm_lose_manager`（失败收锤）、
`gim_other`（生成锤子）、`coin.gd` / `trophy.gd`（UI 分支）。

目标：**把这两关共用的部分收成一条规则 / 一个事件入口**，本体不再出现 `is_hammer` / `HammerZombie`，
且行为一字不改（锤子、锤击、通关奖杯、失败、金币鼠标都要与现状一致）。

## 步骤

1. 先关 Godot（硬约束 §1-5）。
2. **判断能不能走「规则层」**：这两关侵入本体的其实是**两样本体不必认识的东西** ——
   ① 一个跟着鼠标走的**自定义光标**（系统鼠标什么时候该露出来）② 一个**出怪器**（本关怎么出怪）。
   于是把它们做成两个通用入口，而不是在本体里加第 7 个分支。
3. 新增两条通用职衔：
   - `MainGameManager.set_custom_cursor_mode()` + `bind_custom_cursor_hover()`：**通用开关**。
     本体只管「系统鼠标什么时候该露出来」（EventBus `set_keep_system_cursor_visible` 管「面板打开期间保持可见」），
     信号连接也不再按关卡挑 —— 一律连上，处理函数第一行判断开关，非自定义光标关卡等于什么都不做。
   - `ZombieWaveSourceBase` + `ZombieManager.set_wave_source()`：**注入口子**。
     出怪器实现 `init_source()` / `start_first_wave()`，波次进展靠 `signal_wave_refresh` 通知回来。
4. 新增 `src/levels/script/level_rule_hammer_zombie.gd`（`LevelRuleHammerZombie.install(mg)`），
   两关各自的 `init_level_items()` 里调一次，装上：锤子（挂 `canvas_layer_temp`）+ 打开自定义光标开关 +
   把出怪器挂到 `ZombieManager` 下并注入。场景走 `SceneRegistry.HAMMER / HAMMER_ZOMBIE_SOURCE`（§1-4）。
5. 出怪器不再常驻：新建 `zm_hammer_zombie_manager.tscn`（脚本 + Timer），主场景 `main_game_base.tscn`
   里的 `HammerZombieManager` 节点和那条 `ext_resource` 一起删（`load_steps` 91→90）。
   `monster_mode = HammerZombie` **保留** —— 它是数据层开关（关卡数据 / 文档 / 探针都在读），
   只是 `ZombieManager` 那个分支里不再出现具体类名，改成用注入进来的基类。
6. 删掉 `ResourceLevelData.is_hammer`（玩法开关字段，与观星 / 三消那两次同口径），两关脚本里那行也删。
7. UI 侧与失败判定：
   - `coin.gd`：改成 `bind_custom_cursor_hover(button)`；
   - `trophy.gd`：改成 `on_cursor_ui_hover_enter()`（顺手删掉已经没人用的 `main_game` 字段）；
   - `mgm_lose_manager.gd`：**整段删掉** —— 见下面「关键决策」第 2 条。
8. 探针：`probe_tmp_2_5.gd` 改从 `canvas_layer_temp` 找锤子（不再走 `gim_other.hammer`）；
   `probe_night.gd` / `probe_levels.gd` 去掉对 `is_hammer` 的读法；
   新增 `probe_hammer_zombie.gd`，一次跑两关 + 失败流程。

## 关键决策与理由

- **本体留「开关 / 注入口子」，不留玩法字段**：一关专属玩法各有各的接入需求，
  一个「自定义光标开关」+ 一个「出怪器注入口子」就够，本体不需要知道任何玩法名（硬约束 §1-8）。
  这也是照 [三消那次](2026-10-04_僵尸迷阵三消整包搬出本体.md)「本体给的必须是回调口子」的思路做的。
- **失败判定那段代码可以直接删，不必替换成任何东西**：`Hammer` 自己订阅了 `main_game_progress_update`，
  而 `MgmLoseManager.on_zombie_go_home()` 第一件事就是切 `GAME_OVER` —— 那时锤子已经把自己停用了，
  后面那句 `hammer.set_is_used(false)` 是重复调用。删完之后**用探针实测过**
  （强制僵尸进家 → `GAME_OVER` + `hammer.is_used == false`），不是靠推理。
- **注入放在 `init_level_items()`，不用 `register_level_init_callback()`**：出怪器必须排在
  `ZombieManager.init_manager()` **之前**注入（管理器初始化时就要用它），而那个回调是排在所有子管理器**之后**的。
  用哪个取决于「要不要赶在子管理器初始化之前」。
- **出怪器拿不到 `%FlagProgressBar`**：运行期 `instantiate()` 出来的节点没有场景 owner，
  于是把旗帜进度条作为 `init_source()` 的参数由 `ZombieManager` 转交 —— 顺手让依赖显式化。
- **2 秒入场延迟跟着出怪器走**：原来写在 `ZombieManager.start_game()` 里，现在挪成
  `HammerZombieManager.FIRST_WAVE_DELAY`，本玩法自己的节奏不用再动本体。

## 踩坑

1. **跑批的报告被别的进程串了** —— `run_autopilot.ps1` 的输出文件 `ap_out.txt` 是所有人共用的，多 agent 并行时会
   「The process cannot access the file」并读到别人的报告（本次第一次跑拿到的竟是 `probe_column_mode` 的结论）。
   → **正解**：自己建独立 user 目录 + 独立输出文件跑 Godot
   （`$env:APPDATA = <自己的临时目录>; ... -- --scenario=... > <自己的 out.txt>`）；
   拿到报告先看 `场景脚本:` 那一行是不是自己的（[Agent协作协议](../Agent协作协议.md) §4）。
2. **探针里推 `EventBus "test_death_all_zombie"` 出不来奖杯** —— `character_death_disappear()` 是
   **直接消失**，不走死亡信号，`ZombieManager._on_zombie_dead()` 根本不会被调用。
   → **正解**：要验结算就走正常死亡（`zombie.be_attack_to_death()`）。
3. **不停出怪就永远清不干净场**（`curr_zombie_num` 一直是 1，奖杯出不来）—— 出怪器每小组都在自己起 Timer。
   → **正解**：先 `wave_source.get_node("HammerZombieTimer").stop()`，再杀僵尸、轮询几次等奖杯。
4. **首次通关不出奖杯**（日志「掉落本关首次通关奖励…代替奖杯」）→ **正解**：探针里先把该关存档写成已通关
   （迷你游戏 15 的存档键是关卡脚本里写死的老值 `102_0_0002`，别用运行时拼出来的那个）。

## 给后来者的最简路径

1. 先看侵入点属于**几样本体不必认识的能力**（本项目已有两个例子：自定义光标、出怪器），
   能抽象就把它们做成**开关 / 注入口子**，本体一个玩法名都别出现。
2. 共用的那几条搬到 `src/levels/script/level_rule_<玩法>.gd`，关卡脚本在 `init_level_items()` 里调一次
   （注意：目录名 `script` 会被 `LevelRegistry._scan_dir()` 跳过，不会被当成关卡）。
3. 需要实例化的节点做成 `.tscn` 并登记 `SceneRegistry`，不要再常驻主场景。
4. 删掉关卡数据上的玩法开关字段，同步改探针（探针改找不到原先的取法时，**补一条反向断言**：验「注入的那口子」）。
5. 「某段代码是不是真的冗余」用探针实测判定，别只靠读代码推理。
6. 最后 `--headless --import` 刷一次全局类缓存，再带窗口跑探针（多个 agent 同时干活时，用独立 user 目录 + 独立输出文件）。
