# 2026-10-24_多场战斗拼接进度条

> **本次任务**：给关卡进度条加一个「多场战斗拼起来」的工具 —— 多轮关卡（生存 5 轮 / 砸罐子 3 批）不再每轮从 0 重来
> **耗时 / 轮次**：约 1 轮（读进度条三层结构 → 新数据源 → 探针 → 文档）；无头探针实跑 2 次
> **推荐度**：推荐（数据源层加一个子类就够，没动控制器 / 进度条节点 / 出怪侧）

## 目标

默认口径 `LevelProgressBattleProvider` 只认「本场战斗」：出怪侧每切一轮就把进度归零、并置一次
「收起全部旗帜」请求 → 进度条回 0、旗帜全趴下，玩家看不出「五轮里打到第几成了」。
要的是：**N 场按等分拼成一条**，切轮进度连着走、已升起的旗留着。

## 最简路径（步骤）

1. **确认分层**：`LevelProgressBarController`（每帧问数据源 → 写 `FlagProgressBar`）/
   `LevelProgressProvider`（口径）/ `ZombieManager.get_battle_progress()`（战斗进度本体）。
   换口径只需要换数据源 —— 控制器、进度条节点、出怪侧都不用动。
2. **新数据源**：`LevelProgressChainedBattleProvider extends LevelProgressBattleProvider`，只改四处：
   `get_progress()` 折进第几场、`get_flag_num()` 乘场次数、`take_flag_raise_index()` 加偏移、
   `take_flag_reset()` 取走并丢弃。
3. **自动挂上**：`_pick_provider()` 在 `game_para.game_round > 1` 时返回它（关卡不用写代码）；
   关卡脚本 `create_progress_provider()` 仍然优先。
4. **探针**：`probe_progress_chain` 起生存 1（5 轮），改 `curr_game_round` 验 40% / 80% 两档、旗帜 5 面、收旗被吞。
5. **回归**：`probe_level_progress_bar`（单轮 1-3 + 僵王 5-10）必须仍 PASS。

## 关键点

- **轮次在 `MainGameManager.curr_game_round`**；`ResourceLevelData` 上只有总轮数 `game_round`。
  数据源第一版读 `game_para.curr_game_round` → 运行期 `Invalid access ... on Resource(survival_flag_01_day.gd)`，
  探针里表现为「切场进度还是 0」。
- **切轮要吞掉「收旗」请求**：底层每轮都发一次，留着它就把前几场的旗全收下了，拼接的意义没了。
- **切轮瞬间 `is_battle_started()` 会变 false**：不兜这一下，进度条会在两轮之间闪一下消失。
- 段数按**场次等分**（不按波数加权）：现有关卡每轮波数相同，不预留假接口。
- 无尽（`game_round == -1`）与单轮关：`get_battle_count() == 1`，行为与原口径逐字等价。

## 推荐度与理由

推荐。**价值在「只加数据源」**：口径变化被 `LevelProgressProvider` 挡住，控制器与出怪侧一行没改，
以后「按波数加权」「某轮单独换口径」都能在同一个位置继续加。
**给后来者的坑**：① 轮次字段在管理器上不在关卡配置上；② 拼接模式必须吞掉每轮的收旗请求；
③ 切轮有一帧 `is_battle_started()` 为 false，进度条可见性要兜。
