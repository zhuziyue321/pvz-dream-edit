## 2. 四项各自的现行约定

### 2.1 戴夫对话：一律 `.tres`，不要在关卡脚本里 new

**关键发现**：`data/dave/dialog/` 下 11 个 `.tres` **早就建好了**（含 `adventure_05_05_opening` 的 11 句 detail），
但 `src/levels` 里**零引用** —— 之前那次任务只生成了数据、没接线，于是关卡脚本里又硬编码了一份等价内容。
所以这一步不是「造数据」，是**删掉重复实现 + 接线**，风险极低。

写法：

```gdscript
const DAVE_OPENING := preload("res://data/dave/dialog/adventure_05_05_opening.tres")
...
await dave_dialog(DAVE_OPENING)
```

`preload` 一个带 `script_class` 的 `.tres` 能被推断出 `CrazyDaveDialogResource`，直接传给
`dave_dialog(dialog_resource: CrazyDaveDialogResource)` 编译得过（本轮已验证）。
`adventure_02_05` 原本缺 `.tres`，按同目录既有格式补了一组（6 句 detail + 1 个 dialog）。

### 2.2 事件名：`ConstEventName.XXX`

`EventBus` 是**动态信号**实现（`subscribe` 时才 `add_user_signal`），所以事件名拼错**不报编译错误**，
只是运行期静默失效。37 个常量按语义分了 5 组（阳光/卡槽、掉落物、战斗效果、关卡流程、设置调试）。

`MainGameCamera.SHAKE_EVENT` 是**有意保留的例外**：相机自己声明自己消费的事件，与全局玩法事件不同族。
`CrazyDaveDialogDetailResource.on_talk_event` 本来就是数据层配置的变量事件名，保持变量。

### 2.3 实体取主场景：三个基类各一份访问器

- `Character000Base.get_main_game()` / `Bullet000Base.get_main_game()` —— 直接返回
- `ComponentNormBase.get_main_game()` —— 内部 `owner as Character000Base` 再问宿主

**为什么不改成注入**：真正注入要动 `init_plant()` / `init_zombie()` 的参数链路，26 个文件、触达所有僵尸与子弹的行为，
收益/风险比不划算。访问器把「实体拿主场景」收敛到 **3 处定义**，将来要改注入只改这 3 处，是同方向的最小步。

两个**不继承** `ComponentNormBase` 的特殊类要单独处理：
`zombie_drop_base.gd`（extends Node2D）用它持有的 `zombie` 变量；
`jackson_manager.gd`（extends Node）自己加了一份转问 `owner` 的访问器。
`z_b_001_doctor_skill_base.gd`（extends Node）用它的 `doctor` 变量。

### 2.4 判定死资源：必须按**路径**判定，不能按文件名

`animation/character/zombie/zombie_boss/` 23 个 `.tres`：
按文件名在 `src` 里搜会 **23/23 全命中**，但全是误报 —— 命中的是

## 3. 踩坑（最重要的一条）

### ⚠️ PowerShell `Select-String -Path "src/**/*.gd"` 有假阴性

`**` 在 Windows PowerShell 的 `-Path` 上**不会递归到深层子目录**，只匹配到有限层级。
本轮因此得出过两个**完全错误**的结论：

| 指标 | 假阴性结果 | 真实值 |
|---|---|---|
| EventBus 调用点 | 8 push / 7 subscribe（→ 误判「基础设施未兑现」） | **109 处 / 37 个事件名** |
| `Global.main_game` | 42 处 | **60 文件 155+ 处** |
| `_process` 回调 | 10 个 | **53 个** |

**正解**：`Get-ChildItem -Path src -Filter *.gd -Recurse -File | Select-String -Pattern ...`
（`Get-ChildItem -Recurse` 负责递归，`Select-String` 只负责匹配）。
或者直接用 ripgrep。**凡是「全仓统计」结论，先用两个方法交叉验证再写进报告。**

顺带：`Measure-Object -Line` 统计的是**非空行**，`(Get-Content $f).Count` 是**总行**，
两者差约 20% —— 文档里写行数必须标口径，本轮已把 §15.1 全部按「总行」重测并注明。
