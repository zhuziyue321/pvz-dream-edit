## 关键决策与理由

- **只转「机制说明」，保留「流程与踩坑」** —— 工作记录的价值是"这次怎么干的、踩了什么"，
  照抄进参考存档会让两份都变臃肿；机制部分搬走后，原记录顶部留一个指针即可。
- **不删任何记录文件** —— 仓库规范明确"发现过时就在顶部加 `已过时`，不要删"；删了就查不到当初为什么那么做。
- **「已过时」与「已固化」分开措辞** —— 前者是"做法错了/被取代"，后者是"文档体系自身的一次变迁，结论已固化"；
  混用会让后来者误以为要改用别的做法。
- **批量改 md 用脚本而不是逐条编辑** —— 30 个文件 × 同一种插入，脚本 1 次跑完；
  但必须先解决编码与换行（见踩坑 1）。
- **僵王节是本次最大的一处过时**：活跃参考文档 `特殊关卡.md` 还停在 2026-10-05 的
  `ZombossBoss`（独立 Node2D）+ `is_zomboss_fight` + `spawn_zomboss()` 事件，
  而代码在 2026-10-06 已整套换成 `ZB000Base` / `ZB001Doctor` + `boss_*` 字段。
  这类"文档停在上一版"比"记录过时"更危险，必须优先订正。

## 踩坑

1. **批量改 md 的两个陷阱**（本次用 PowerShell 脚本处理 30 个文件）
   → ① 无 BOM 的 UTF-8 `.ps1` 在 PowerShell 5.1 下**可能被按 ANSI 解析导致中文乱码** —— 本次实测正常，
   但动手前先跑一个只 `Write-Output "中文"` 的脚本验一次，别直接拿正式脚本试；
   ② 写回时若统一用 `Environment.NewLine`，会把 LF 文件整份变成 CRLF，git 里显示为全量改动 ——
   **正解**：`ReadAllText` 判原换行风格（`Contains("`r`n")`），`[System.IO.File]::WriteAllText` +
   `UTF8Encoding($false)` 原样写回。
2. **改完发现 git 里整份文件被标记为全量改动**（本次 31 份 × 约 60 行全删全加，实际只加了 2 行）
   → 原因：这些 md 在**索引里是 LF、工作副本是 CRLF**，而它们的 `attr` 没让 git 做行尾转换，
   于是每行都因行尾 CR 显示为改动（跟本次改动无关，但会把 diff 冲成一团看不清）
   → **正解**：改完跑一遍归一化 —— `git ls-files --eol -- <文件>` 读出索引的 `i/lf` 或 `i/crlf`，
   再把工作副本按它统一（本次 31 份全是 `i/lf`，统一成 LF 后 diff 从 2404/2339 降到真实的 291/112）。
   **判定用 `git diff --ignore-cr-at-eol --numstat`**：只剩真实改动行数，说明内容没被写坏。
3. **判断"过时"不能看标题，要拿文档里的符号去 `src/` 里 grep** —— 本次靠
   `ZombossBoss` / `is_zomboss_fight` / `POOL_LATE` / `_build_opening_script()` / `LevelPrefabs` / `TutorialManager`
   零命中，才确认那一整节是过时的；光看"僵王博士已实现"这行字完全看不出来。
4. **替换旧符号前先确认新名字是什么，不要照抄旧记录** —— 例如僵王的出生点常量，
   10-06 记录里写"出生点 1030→-240"，而代码里现在是 `ZB000Base.FIXED_SPAWN_POSITION = Vector2(-80, 0)`；
   血量也不是旧文档写的"重打 60000"，而是 5-10 / 迷你 20 各自 `boss_hp`（40000 / 60000）。
5. **索引表按行追加标记要防重复** —— 脚本里先判 `Contains("机制→")` / `Contains("**已过时**")` 再插，
   否则重跑一次会把标记叠两遍（本次因为要补跑一次才加了这道判据）。

## 给后来者的最简路径

1. **找过时**：把候选文档里的类名 / 字段名 / 路径拿到 `src/` 里 grep，零命中 = 过时；
   被后续记录点名推翻的（索引里带 `已过时`）也一并处理。
2. **转存档**：同一主题的几条记录合并成 `docs/参考存档/<主题>.md`，带 `<!-- AGENT-DOC: archive -->` 首行 +
   「触发条件 / 读完你能 / 强制级别 / 关联」元信息块；只写机制，不抄流程。
3. **登记**：参考存档 README §1 一行 + `docs/README.md` §2.2 份数 + 根 `AGENTS.md` §2 路由一行（若值得路由）。
4. **标源**：源记录顶部插「已归档 / 已过时 / 已固化」块（写明失效原因 + 替代做法），索引行同步加标记；**不删文件**。
5. **批量**：30 份以上的同构改动写一次性脚本（注意踩坑 1 的编码与换行），跑完删掉脚本。
