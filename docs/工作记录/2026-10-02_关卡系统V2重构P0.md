# 2026-10-02 · 关卡与地图 · 关卡格式 V2 重构 P0：版本字段 + 存档键显式化 + 关卡注册表

> **任务类型**：关卡与地图
> **推荐度**：**推荐**（V2 的四条通道设计与 P0 落地路径都验证过了，后续 P1–P4 照它走）
> **耗时与成本**：约 3 轮对话 / 未开游戏（全程无头探针）+ 冒烟探针
> **验证方式**：免验证（只加字段 + 新增静态类，不改任何运行时分支）+ 跑了 `probe_save_key` / `boot_level` 无头冒烟
> **补充自**：无

## 目标

设计一套「脚本驱动的高度自定义 × 数据驱动的简便复用」的关卡格式，并落地 P0：
`format_version` 版本字段、`save_key` 存档键显式化、`LevelRegistry` 关卡注册表。
**硬要求**：V1 关卡行为零变化，玩家存档一个都不能丢。

2. **跟用户收敛方向** —— 抛出 A/B/C/D 四条路线对比表，用 `ask_followup_question` 拿到三个关键决策：三层都要做且要考虑玩家自制关、加 version 兼容并迁移 1-4 作示例、数值用 `.tres` 流程用 `.gd`。
3. **先测技术风险再定设计** —— 外部 `.gd` 能否加载是 P2 的地基，写 `probe_ext_script_load.gd` 实测三种加载方式 × 两个目录，全部 OK 才把 `level_script` 写进设计。

5. **建注册表** —— 新建 `src/levels/core/level_registry.gd`（静态类，不占 autoload）。
6. **dump 而非推算** —— `tool_dump_save_keys.gd` 真跑 4 个选关场景，从按钮上读权威 `save_game_name`。
7. ~~**写回 + 同进程回读校验**~~ → **放弃原因**：同进程内资源仍被场景引用，`CACHE_MODE_REPLACE` 顶不掉缓存实例，回读拿到默认值，误判成"写入失败"。
8. **拆分** —— 写回工具 `tool_write_save_keys.gd` 只管写，回读挪到独立进程 `probe_save_key.gd`。
9. **修 `.tres` 属性顺序坑** —— 见踩坑 1，字段必须排在 `script =` 之后。
10. **验证** —— `probe_save_key` 全 PASS + `boot_level` 冒烟 + 与备份逐行比对确认只多两行。

## 关键决策与理由

- **注册表 id = 文件名 basename**，不维护 95 行大表 —— 因为自制关卡的 level_id 本来就是文件名（`custom_choose_level.gd`），内置关与自制关共用一套规则；且扫目录自动登记，加一个 `.tres` 就自动进表。
- **注册表不做 autoload** —— 项目已有 9 个 autoload，[项目规范.md §1](../项目规范.md) 提到过 autoload 初始化顺序故障，静态类零风险。
- **存档键必须 dump 不能推算** —— 它来自选关场景遍历节点的顺序（`choose_level.gd:31`），推算错了玩家老存档直接丢失，这是不可逆事故。
- **迁移工具走文本级按行改写，不用 `ResourceSaver`** —— 关卡 `.tres` 里有大量 `;` 开头的原版考据注释，Godot 重新保存会全部冲掉。
- **先测外部 `.gd` 加载再定 P2 设计** —— 如果导出版加载不了，整个逃逸层要换成别的形态，先测能省掉返工。
- **编排层（控制流事件）必须存在，不能只做逃逸层** —— 玩家自制关卡不便要求写代码。

## 踩坑

1. **`.tres` 属性按顺序设置，插错位置被静默忽略** —— 写回后 `format_version` / `save_key` 文件里明明有，加载回来却是默认值，且不报错。
   → 原因：字段插在 `[resource]` 之后、`script = ExtResource(...)` **之前**，那时资源还没挂脚本。
   → **正解**：插入位置必须在 `script =` 那一行之后。
2. **static 方法名撞内建方法** —— `LevelRegistry.get_path()` 报 `Invalid call to function 'get_path' in base 'GDScript'. Expected 0 argument(s)`。
   → 原因：`Resource` / `Script` 有内建 `get_path()`，同名 static func 被解析成内建方法。
   → **正解**：改名 `get_level_path()`，`has()` 同理改 `has_level()`。
3. **新建带 `class_name` 的脚本不是立即可用** —— 报 `Identifier "LevelRegistry" not declared`。
   → 原因：全局类表是上一次启动的快照。
   → **正解**：新建后先随便跑一次引擎再写引用它的代码。
4. **同进程回读刚写的文件拿到旧值** —— 见步骤 7。
   → **正解**：回读另起一个进程。
5. **探针是 `RefCounted`，没有 `get_tree()`** —— 用 `a.get_tree()`。
6. **`GDScript` 没有 `is_valid()`** —— 动态编译后判断能否实例化要用 `can_instantiate()`。

## 给后来者的最简路径

1. 先读 [关卡格式V2.md](../参考存档/关卡格式V2.md) 拿规格，别重新设计。
2. 加 V2 字段时：给安全默认值 + 在 `set_choose_level()` / `init_para()` 里做「留空回退旧逻辑」的兼容分支。
3. 要批量改关卡 `.tres`：**一律文本级按行改写**，新增字段排在 `script =` 之后；改前先备份，改后与备份逐行比对。
4. 校验脚本**单独起进程**跑，不要在写文件的那个进程里回读。
5. 验证三件套：`probe_save_key`（数据正确性）+ `boot_level`（冒烟）+ 与备份逐行 diff（确认没有多余改动）。
