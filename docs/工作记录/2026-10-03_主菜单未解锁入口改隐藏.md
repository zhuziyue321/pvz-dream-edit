# 2026-10-03 · 其它 · 主菜单未解锁入口：图鉴 / 商店改隐藏，模式按钮仍置灰

> **任务类型**：其它（UI 表现对齐原版）
> **推荐度**：**推荐**（下次动主菜单解锁表现照这个走）
> **耗时与成本**：约 2 轮对话，跑了无头探针（画面建议人工看一眼）
> **验证方式**：跑了无头探针 `probe_start_menu_unlock`（PASS）+ 回归 `probe_start_menu_layout`（PASS）
> **补充自**：[2026-10-03_2-4掉大图鉴与图鉴解锁.md](2026-10-03_2-4掉大图鉴与图鉴解锁.md)（该记录第 4 步的"置灰 + 点击弹提示"本次已改为"直接隐藏"）

## 目标

主界面上"按进度解锁的东西"不该是「显示了、点了才提示未解锁」，而应该**没解锁就不显示**。
范围由用户拍板：**图鉴 / 商店**（属于"拿到才有的道具"）未解锁时直接隐藏；
**迷你游戏 / 解谜 / 生存**（属于"玩法列表"）维持原样置灰 + 点击提示。

## 步骤

1. 先摸清现状（`src/menus/start_menu/start_menu_root.gd`）：`MODE_BUTTON_PATHS` 三个模式按钮置灰；
   图鉴走 `_apply_almanac_lock_state()` 置灰 + 点击弹提示；**商店连置灰都没有**，只能点了才知道没解锁。
2. 范围有歧义（"等"包不包括模式按钮）→ 用 `ask_followup_question` 一次问清，用户选"图鉴 / 商店隐藏，模式按钮保持置灰"。
   **这一步别省**：隐藏 vs 置灰是两套相反的表现，猜错了要返工。
3. 改 `start_menu_root.gd`：
   - 加 `SHOP_BUTTON_PATH`，把 `_apply_almanac_lock_state()` 换成 `_apply_item_lock_state()`
     + 通用 `_apply_unlock_visible(path, unlocked)`（`button.visible = unlocked`）；
   - 加 `_is_shop_enterable()`（与 `_is_almanac_enterable()` 同口径，都要认 `config_service.open_all_level`）；
   - 两个 `_on_item_button_*_pressed()` 里的 `show_lock_tip(...)` 删掉，只留 `if not ...: return` 兜底。
4. 新探针 `test/scenarios/probe_start_menu_unlock.gd`：改 `curr_all_level_state_data` 后直接调
   `menu._update_mode_lock_state()` 复算，逐个门槛（0 / 13 / 14 / 23 / 24 / 22 / 50）核对可见性与颜色。
5. 文档同步 `docs/参考存档/选关界面与解锁.md`：新增「主菜单两类未解锁入口：模式置灰、道具隐藏」小节，
   并改掉「图鉴解锁」小节里过时的置灰描述。
6. ~~以为改完就完事~~ → 用户实测"新档还是显示" → 追加切换用户刷新：`User.user_session_switched`
   信号 + `StartMenuRoot.refresh_for_current_user()`，探针补 STEP5（真实走一遍建档 → 点 OK）。
7. 顺手修"建了新档却没生效"：新建用户后列表不会自动选中它（`add_user` 只加进列表、不切当前用户），
   玩家直接点「好」等于切回旧档。`PanelCreateNewUser.new_user_created` → `User._on_new_user_created()`
   把选中项切到新用户。
8. 用户再提"花园的逻辑不对" → 花园也纳入同一套：加 `GARDEN_BUTTON_PATH` + `_is_garden_enterable()`
   （5-5），`_apply_item_lock_state()` 三件一起隐藏。原文档写的是"主菜单进花园不做限制"，
   属于旧口径，一并改掉。

## 关键决策与理由

- **只隐藏道具类、模式仍置灰** —— 原版 PVZ 就是这么分的：图鉴 / 商店是"戴夫把东西给你之后才出现在草坪上"，
  模式按钮要让玩家看见"后面还有内容"（与选关界面 `ChooseLevelButton.lock_choose_level_button()` 同口径）。
- **用 `visible` 而不是调 `disabled` / 挪走** —— 隐藏后按钮收不到点击，不需要额外拦截；
  道具栏三个按钮是绝对坐标，隐藏中间一个不会挤动花园按钮。
- **商店判定补 `open_all_level`** —— 原来 `_on_item_button_3_pressed()` 直接查 `is_shop_unlocked()`，
  控制台"开放所有关卡"对它无效；统一走 `_is_shop_enterable()` 后两边一致。

## 踩坑

1. **`show_lock_tip()` 不能整个删** —— 模式按钮的 `_try_enter_mode()` 还在用，只删道具那两处。
2. **既有探针 `probe_start_menu_layout` 不会因隐藏而失败** —— 它对 `TextureButton2/3` 只取
   `get_global_rect()`，隐藏的 Control 仍然有 rect，PASS 不受影响（已实测确认）。
3. **改完用户仍报"新档还是显示图鉴商店"—— 真凶不是隐藏逻辑，是切换用户不刷新主菜单** →
   `User._on_button_ok_pressed()` 只做「存旧档 → `set_current_user` → `reload_session_for_current_user`」
   就 `visible = false`，**开始菜单场景不重建**，`_update_mode_lock_state()` 也就不会再跑一次，
   表现沿用上一个用户的存档（该用户已通关到 3-4，图鉴 14 / 商店 24 都解锁，所以三个图标全在）。
   **正解**：`User` 加 `user_session_switched` 信号（在 reload **之后**发出，不能挂在
   `UserManager.signal_users_update` 上 —— 那个是在 `set_current_user` 里、新存档还没加载时发的），
   `StartMenuRoot._ready()` 连到 `refresh_for_current_user()` 重算解锁 + 花园图标。
   **排查手法**：写个只读诊断探针跑**真实存档**（`& godot --headless --path <项目> -- --scenario=...`，
   不重定向 APPDATA），打出 `curr_user_name` / `get_max_success_adventure_level()` / 各按钮 `visible`，
   一眼就能区分「逻辑错了」还是「存档本来就有进度」。
4. **跑批读到上一次的残留输出** —— `run_autopilot.ps1` 的输出文件在 `%TEMP%\pvz_autopilot\`，
   被残留的 Godot 进程占着时 `Remove-Item` 是 `SilentlyContinue`，于是 `Get-Content` 读到旧内容，
   看起来像"指定的探针没跑、跑了别的探针"。**下次**：跑批前先
   `Get-Process | ? {$_.ProcessName -like '*godot*'}` 清残留，或直接调用 Godot 读控制台输出。

## 给后来者的最简路径

1. `src/menus/start_menu/start_menu_root.gd`：要加新的"隐藏型"入口 → 加 `XXX_BUTTON_PATH` 常量，
   在 `_apply_item_lock_state()` 里补一行 `_apply_unlock_visible(XXX_BUTTON_PATH, _is_xxx_enterable())`。
2. 判定函数统一形如 `_is_xxx_enterable()`：`open_all_level` 优先放行，否则查 `GlobalGameState.is_xxx_unlocked()`。
3. 跑 `powershell -ExecutionPolicy Bypass -File test\run_autopilot.ps1 -Scenario probe_start_menu_unlock`
   核对门槛（探针里 `_mark_cleared(state, N)` + 手动调 `menu._update_mode_lock_state()`，不用真打关）。
