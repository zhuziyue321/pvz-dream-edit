# 2026-10-23_植物僵尸外观移植

> **本次任务**：把原版 6 只植物僵尸的头从「植物部件 PNG 拼的静态图」换成原版那套（挂那颗植物的 reanim、播 `anim_idle` / `anim_head_idle`）。
> **耗时 / 轮次**：一次任务、约十几轮；**未开窗口实测**（编译门禁 + `probe_zom_botany` 通过），视觉需要人工看一眼。
> **推荐度**：推荐（做法可复制到任何「僵尸头上挂植物」的场合）。

## 目标

原版 `Zombie::Zombie()` 里 `ZOMBIE_*_HEAD` 分支给僵尸挂的是**那颗植物的整套 reanim**：

| 僵尸 | reanim + 动画 | 挂点 | 原版 attach（offset / rot / scale） |
| --- | --- | --- | --- |
| 豌豆 | `REANIM_PEASHOOTER` + `anim_head_idle` | `anim_head1` | 65, -5 / 0.2 / -1, 1 |
| 坚果 | `REANIM_WALLNUT` + `anim_idle` | `Zombie_body` | 50, 0 / 0.2 / -0.8, 0.8 |
| 高坚果 | `REANIM_TALLNUT` + `anim_idle` | `Zombie_body` | 37, 0 / 0.2 / -0.8, 0.8 |
| 辣椒 | `REANIM_JALAPENO` + `anim_idle` | `Zombie_body` | 55, -5 / 0.2 / -1, 1 |
| 机枪 | `REANIM_GATLINGPEA` + `anim_head_idle` | `anim_head1` | 65, -5 / 0.2 / -1, 1 |
| 窝瓜 | `REANIM_SQUASH` + `anim_idle` | `anim_head1` | 55, -15 / 0.2 / -0.75, 0.75 |

（行号基准 `../PvZ-Portable-main/src/Lawn/Zombie.cpp` 的 707–851 行。）

本仓库没有 reanim 播放器，但**植物自己的 idle 动作已经从 reanim 转成了 Godot 动画资源**（`animation/character/plant/**`），
所以「移植外观」= 让僵尸头实例化一个**只含视觉部件 + 一个 AnimationPlayer** 的小场景，直接播那套动画。

## 最简路径（步骤）

1. 先确认目标植物的 idle 动画**轨道路径**：`Select-String -Path <anim>.tres -Pattern 'path = NodePath'`。
   路径前缀决定头场景的节点层级（多数是 `Body/BodyCorrect/...`；窝瓜的 `squash_idle.tres` 是 `Body/...`）。
2. 建 `plant_head_<植物>.tscn`：节点层级**照抄植物场景**（`Body/BodyCorrect/...`，但 `BodyCorrect` 的
   格子修正写 `(0, 0)`），尾部 `AnimationPlayer` 不写 `root_node`，库只放一条
   `{ &"Head_Idle": ExtResource(<植物 idle .tres>) }`。
   **不要复制动画** —— 直接引用植物那份，植物改了僵尸头跟着改。
3. 摆位**照抄原版** `Zombie.cpp` 707–851 行的 `AttachReanim`：配 `attach.to_body`（挂 `Zombie_body` 还是
   `Anim_head1`）+ `offset` / `rotation` / `scale`（含镜像负号）。头场景的根 = **植物原点**，
   组件只把根设成这三个数，**不要**自己算「贴图中心对居中」或做缩放归一化（见下面弯路）。
4. 配置表 `ZomBotanyConfig` 里把 `head_scene` 指过去；有原版裂纹图的再补 `head_body_path`
   （坚果 `Anim_face`、高坚果 `Anim_idle`）；整颗植物替换头的三只补 `hide_tie`。
5. 探针补断言：**轨道路径逐条能解析到节点**（值轨查节点、方法轨跳过）、原版 6 只都有 `head_scene`、
   `head_body_path` 指得到 `Sprite2D`。
6. 跑 `test/check_scripts.ps1` + `probe_zom_botany`；视觉仍需开窗口看一眼（见下）。

## 弯路 / 踩坑（三段式）

- **试过**：把整份植物场景（`plant_wall_nut.tscn`）实例化当僵尸头，再想办法关掉它的脚本 / 组件。
- **因为**：植物场景带 `plant_base` 的 `_ready()`（格子、光照、睡眠…），一实例化就跑一整套逻辑，还会接管输入。
- **结论**：只抄**视觉子树**（几个 `Sprite2D` + 节点层级），动画走共享 `.tres`，脚本一个都不要。

- **试过**：直接照抄原版 `attach.offset` 塞进 `position`、`attach.rotation` 塞进 `rotation`，
  头场景里还留着植物场景那份 `BodyCorrect(-43,-67)` 格子修正。结果**巨大错位**。
- **因为**：`BodyCorrect` 是「植物 reanim → 格子锚点」的修正，只对种在格子里的植物成立；
  原版 attach 摆的是**植物 reanim 原点**。另外 `PvzpScaleRotateTransformMatrix(rad)` 的线性部分是
  `R(-rad)·S`，和 Godot 的 `R(θ)·S` 差一个符号（0.2 rad ≈ 11.5°，乘上 ~65px 的偏移就是十几像素）。
- **结论**：头场景的 `BodyCorrect` 一律写 `(0, 0)`（部件坐标不动），`rotation = -attach.rotation`，
  `position` 原样不加半贴图。改完用 headless 量「植物主体中心 vs 僵尸头贴图中心」（只算变换，不用渲染）：
  豌豆 (-3.1, +4.7)、机枪 (+0.7, +6.1) 直接对上；坚果 / 高坚果 / 辣椒挂 body 轨道、窝瓜本来就偏高，
  剩下那点 y 差是原版布局本身的（它们不是「头贴头中心」），别再当 bug 去调。

- **试过**：以为原版轨道 `(x,y)` 是贴图中心（`ReanimBltMatrix` 里那句 `m02 - scale*width*0.5` 看着像），
  于是给 `position` 补半个贴图。
- **因为**：`DrawTrack` 里先给矩阵预乘了 `T(+cel/2)`，`ReanimBltMatrix` 再减 `scale*cel/2`，两者相消 ——
  `(x,y)` 就是**左上角**，和本仓库 `centered = false` 的节点原点一致。
- **结论**：`position = attach.offset`，不加不减；补半张贴图反而再偏半个头。

- **试过**：在头场景里加一层 `HeadCorrect`，把植物主体贴图「归一化成屏幕 1:1」并对齐到僵尸头贴图中心，
  以为这样就能沿用旧静态头的 `head_scale = 0.5` 且位置不变。
- **因为**：静态头那套「贴图中心对贴图中心」是本仓库自己调的近似，和原版 `AttachReanim` 的
  「植物原点 + (65,-5) / 0.2 rad / 镜像」完全是两套坐标，肉眼一对就偏（用户第一轮反馈就是「头的偏移有问题」）。
- **结论**：删掉 `HeadCorrect`，头场景根改成植物原点、层级照抄植物场景（`Body/BodyCorrect/...`），
  摆位改成配置里的原版 `attach`。**凡是原版有数值的，一律照抄，不要自己换算对齐。**

- **试过**：给新头场景也复制一份动画（像 2026-10-19 的豌豆头那样把 `Head_Idle` 搬进场景）。
- **因为**：机枪的 idle 有 57 KB、辣椒 35 KB，6 份拷贝之后植物那边改动画这里不会跟。
- **结论**：改用 `AnimationPlayer.root_node` 指到对齐节点，直接引用植物的 `.tres`；
  代价是节点名不能随意改（改名 = 轨道全断），因此补了「轨道逐条能解析」的探针断言。

- **试过**：探针里顺便断言「所有轨道都能解析」（包括方法轨）。
- **因为**：豌豆的 `Head_Attack` 方法轨**故意**写的是植物场景的 `NodePath("AttackComponent")`，
  头挂到僵尸身上后由 `_bind_head_attack_shoot_track()` 运行期重定向。
- **结论**：值轨才查节点，方法轨跳过；否则豌豆必红。

- **踩到**：`probe_zom_botany` 原来断言「头场景必须有带 `_shoot_bullet` 方法轨的 `Head_Attack`」。
  新加的 5 个只搬了 idle，一加就失败。
- **结论**：改成「配了 `Head_Attack` 才要求方法轨」，没配视为通过（发射仍是冷却到点直接发）。

## 推荐度与理由

推荐：这条路子把「原版 reanim 外观」落到本仓库已有的动画资产上，不用新素材、不用写 reanim 播放器；
以后任何「X 头上长着 Y」的外挂部件都照这个套路（视觉子树 + 共享动画 + `root_node` 对齐节点）。

需要注意：

- 对齐只保证「主体贴图中心 = 僵尸头贴图中心、大小 = `head_scale`」，**好不好看要开窗口看**
  （尤其窝瓜，原版 attach 是 `55,-15`、0.75 缩放，本仓库沿用静态头那套 0.5 口径）；
- 原版坚果 / 高坚果 / 辣椒挂 body、不跟着摇头，本仓库统一挂头节点（位置大小一致，只是跟着晃）；
- 8 只扩展（寒冰 / 火炬 / 磁力菇 / 南瓜 / 卷心菜 / 玉米炮 / 西瓜 / 冰瓜）仍是静态 PNG。

## 补充 / 评价（事后追加，见 §5）

**补充（同日第二轮，用户反馈「坚果 / 高坚果 / 辣椒靠下、窝瓜靠上、机枪 / 豌豆有微小差别」）**：
上面那段「剩下那点 y 差是原版布局本身的、别再当 bug 去调」**是错的**，收回了。

- 漏掉的是原版 `Reanimation::GetAttachmentOverlayMatrix()` 里的**基准姿态除法**：
  它算的是 `僵尸overlay · 轨道(当前帧) · 轨道(基准帧)⁻¹`，基准帧由 `aBodyReanim->mFrameBasePose = 0`
  指定（`NO_BASE_POSE = -2`，写 0 就是第 0 帧）→ 挂点轨道**第 0 帧自带的平移 / 缩放不参与**。
  之前只比了「植物主体中心 vs 僵尸头贴图中心」，那个口径看不出这一步。
- 本仓库动画资源写的是绝对姿态，直接 `anchor.add_child(plant_head)` 会多乘一次 `轨道(0)`：
  挂 `Zombie_body` 的三只多带 `(28.9, 33.8)` + 0.8 缩放（偏低 ~34px），挂 `Anim_head1` 的三只
  多带 `(6.7, 8.8)` + 0.8 缩放（偏低 9~12px），六只还统一小 20% —— 正好对上用户的三条反馈。
- 修法：`ZombiePlantComponent._attach_head_to_original_track()` 在挂点与植物头之间垫一层
  `AttachBasePoseInverse`（= `轨道(0)⁻¹`，从僵尸 `AnimationPlayer` 的 `Zombie_walk` 第 0 帧读）。
  **没有**去改 `attach` 里的原版数值 —— 那些数是照抄 `Zombie.cpp` 的，错的是本仓库的挂接方式。
- 教训：涉及「原版 reanim 挂接 / 叠加矩阵」的地方，光看最终位置对不对不够，
  要把 `Attachment` / `GetAttachmentOverlayMatrix` / `Reanimator` 的矩阵乘序完整对一遍；
  另外「各图层动画第 0 帧都是同一份基准姿态」是本仓库动画资源的既有约定，读基准姿态不用区分图层。

**补充（同日第三轮，用户反馈「窝瓜偏高，窝瓜和辣椒没有摆动」）**：

- **窝瓜偏高** 是**动画资源里藏着的格子修正**：`animation/character/plant/squash/squash_idle.tres`
  比植物场景内联的 `Squash_idle` 多一条 `Body:position:y = -45`（老层级 `Body/...` 时期的残留），
  idle 一播整颗头就抬高 45px。该 `.tres` **只有窝瓜头场景引用**（植物用的是场景内联动画，路径是
  `Body/BodyCorrect/...`），已删掉这条轨道。删后 `Body = (0,0)`，`Squash_body` 起伏 ±6px 照常。
- **量过的数据**（无头 Godot 实跑，后面再遇到「没摆动 / 大小不对」可以直接比照）：
  · 六只头的 `Head_Idle` 在引擎里都真的在动：辣椒 ±1.4px + 茎转 7°（原版 reanim 帧 5~11 本来就这么小，
    `Jalapeno.reanim` 的 `Jalapeno_body` 就是 17.1/10.4 → 16.5/12.3），窝瓜 12px 起伏，坚果 4px。
  · 挂点轨道自己摆得很大：`zombie_walk` 里 `Anim_head1` posΔ(26.7,15.9) rotΔ0.49、
    `Zombie_body` posΔ(15.0,8.8) rotΔ0.35 —— 所以「头不跟僵尸晃」在矩阵上不该发生。
  · 结论：位置类问题先查「资源里有没有藏偏移」，摆动类问题先量动画资源本身，再怀疑挂接。

**补充（同日 2026-10-24，用户反馈「辣椒 / 窝瓜僵尸身体完全没有动」）**：

- 这是**僵尸脚本继承错了基类**，不是植物头的问题。
  `zombie_norm.tscn` 的动画状态机转换用了 `walk_status == 1/2`、`idle_status == 1/2`、
  `death_status == 1/2/3`，且 `advance_expression_base_node = NodePath("..")`（读僵尸脚本上的属性）；
  这些 `@export` 是 `Zombie001Norm`（`zombie_norm.gd`）定义的。
- `zombie_squash.gd` / `zombie_jalapeno.gd` 当时写的是 `extends Zombie000Base` —— 脚本上**根本不存在**
  `walk_status` 等属性 → `advance_expression` 解析失败、判定为假 → 子状态机卡在 `Start`、无动画在播 → 身体冻住。
- 为什么只有这两只：豌豆 / 坚果 / 高坚果 / 机枪没有自己的脚本，直接用 `zombie_norm.gd`（`Zombie001Norm`），
  所以正常。**改法**：把这两个脚本的 `extends Zombie000Base` 改成 `extends Zombie001Norm`
  （它们本来就是「普通僵尸身体 + 植物头」，本就该归到 `Zombie001Norm`；它 `ready_norm()` 里的
  `_random_anim_status()` 正好负责把 `walk_status` 等设成 1/2，让状态机跳出 `Start`）。
  两个脚本里自定义的 `init_random_speed` / `ready_norm_signal_connect` / `ready_norm` / `_physics_process`
  在 `Zombie001Norm` 里都没定义，不会冲突。编译门禁 `real compile errors = 0`。
- 教训：凡是继承 `zombie_norm.tscn`（共用那套带 `walk_status` 状态机的 AnimationTree）的僵尸脚本，
  **必须**继承 `Zombie001Norm`（或在其上再加属性），否则状态机表达式会读不到字段而冻住整具身体。
