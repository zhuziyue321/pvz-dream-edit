# 2026-10-16 · 玩法 / 关卡入口 · 冒险模式去掉选关界面，按进度只能打下一关

> **任务类型**：其它（菜单流程 / 玩法入口）
> **推荐度**：**推荐**（同类活「删掉一层中间界面、把它的职责收进后台」可照这条走：工作量不在删，在把旧界面隐式依赖的口径重新落实）
> **耗时与成本**：约 1 轮对话；**未开游戏**；无头探针 4 次（1 条新的 + 3 条受影响的）
> **验证方式**：编译门禁 PASS（118 个 scenarios）+ 新探针 `probe_adventure_next_level` PASS
>   + `probe_unlock` / `probe_adventure_reward` / `probe_netplay_session` PASS
> **补充自**：[2026-10-16_主菜单冒险模式按钮关卡号.md](2026-10-16_主菜单冒险模式按钮关卡号.md)
>   （同一块木牌：那条只做了「显示关卡号」，这条把「点它进哪一关」也定下来）

## 目标

移除冒险模式的选关界面（原版那张 5 页 × 10 关的地图），改为**按进度只能打下一关**：
进冒险模式直接进「已通关最大序号 + 1」，通关后回主菜单（木牌上就是下一关，再点一次就进）。

## 最简路径（步骤）

1. 先摸清「进哪一关」这条链：`start_menu_root.gd::_on_button_1_pressed` → 3 秒过场 → 选关场景；
   通关后 `mgm_reward_manager.gd::win_main_game()` 又走 `get_scene_path(game_para.game_mode, StartMenu)` 回选关页。
   **全仓搜 `ChooseLevelAdventure` 确认入口只有这两处**（其余都是把它当 mode 值用）。
2. 进关参数放在进度持有者身上：`GlobalGameState.get_curr_adventure_level_to_play()` +
   `build_curr_adventure_level_para()`；序号 → 关卡 id 的正向映射放注册表
   （`LevelRegistry.get_adventure_level_id()`，与已有的 `_parse_adventure_level()` 互为逆运算）。
3. 主菜单改成直接进关：过场播完 `StartMenuRoot._start_adventure_level()` 取参数 + 切到 `game_sences`
   （与旧选关页点按钮后做的事完全一样）。
4. 注册表摘掉 `ChooseLevelAdventure` 的场景槽位（**枚举值保留**），删场景文件；
   `choose_level.gd` 里冒险模式专用的那一段（`calc_open_level_num()` 的 `return 1`）摘掉。
5. 通关后的回退**不用改代码**：`get_scene_path(mode, StartMenu)` 的 fallback 正好接住
   —— 只补了一句注释说明「这是常态，不是兜底」。
6. 联机模组的退关场景（`choose_level_scene_of_mode()`）补上「认不出选关页就回主菜单」，
   否则冒险关里「退出房间」会把玩家扣在关卡里。
7. 收拾探针：9 条用「主菜单 → 选关页 → 第一关」进关的 `_goto_level` 改成「点木牌 → 等 `main_game`」；
   3 条「通关后回选关页」的断言改成回主菜单；2 条只有冒险选关页才有对象的探针（网格布局 / x-10 纸条图标）删除。
8. 新探针 `probe_adventure_next_level` 钉住：新档→1-1 / 通关 1-1 后→1-2 / 全通后停在 5-10 /
   木牌号 == 实际进的那一关 / 三个抽查关的**存档键写死**对照。
9. 跑 `test/check_scripts.ps1` + 上述探针，更新 `docs/参考存档/选关界面与解锁.md`。

## 关键决策与理由

- **「进哪一关」收进 `GlobalGameState`**（不写在主菜单里）：它是进度的持有者
  （`get_max_success_adventure_level()`），而主菜单木牌上的关卡号本来就用同一个函数
  （`ConstUnlockLevel.get_adventure_button_level`）—— 一份进度两个出口对不上，就会出现
  「木牌写 1-2 却进了 1-1」。
- **进关参数照旧走 `set_choose_level()`，页码 / 关卡号一个都不改**：1-2 起的老关卡是 V1
  （`save_key` 为空），存档键 `"101_<页码>_<4 位关卡号>"` 是**现场拼**出来的。
  改口径不报错、不崩溃，只会静默把玩家的通关进度挪位（护栏见 `probe_level_registry_order`）。
- **删场景 ≠ 删枚举**：`MainScenes.ChooseLevelAdventure` 现在是「冒险模式」的 id，
  存档键与 `ResourceLevelData.game_mode` 都按它的**数值**存 —— 枚举定义处补了注释钉住这点。
- **通关后回主菜单**（而不是自动进下一关）：主菜单木牌本来就是「显示当前关卡号 + 点它开打」，
  与原版「关卡结束 → 回地图」的顺序一致，改动面也最小。
- **`open_all_level` 不再管冒险模式**：没有列表就没有「开放关卡」可言；控制台 tooltip 改了措辞，
  指路已有的「通关所有冒险关卡」。要跳关还有它。

## 弯路 / 踩坑（三段式）

- **试过**：直接拿 `LevelRegistry.get_adventure_level_data(n)`（现成的「序号 → 关卡实例」）当进关参数。
- **因为**：那个函数的注释写明它返回的是**专供查声明的共享副本**（`_data_by_adventure_level` 缓存），
  拿它当 `game_para` 会被 `init_para()` 就地改字段、把缓存污染掉。
- **结论**：加正向映射 `get_adventure_level_id()`，走 `get_level()`（对脚本关卡是 `new()` 一份新实例）。

- **试过**：连着跑几条探针时复用同一个 `%TEMP%` 用户目录（自己手搓启动命令，绕开 `run_autopilot.ps1`）。
- **因为**：`run_autopilot.ps1` 每次都会**删掉并重建**它的 userdir，而手搓命令没有 ——
  前一条探针留下的存档（36 株植物）被后一条读到，`probe_netplay_session` 报了两条**假 NG**
  （“默认存档下判定无选卡权”失败，因为它读到的根本不是默认存档）。
- **结论**：每条探针用**独立**的 user 目录（或干脆走 `run_autopilot.ps1`，它自己会清）；
  看到「与本次改动无关的 NG」先怀疑存档串了。

- **试过**：探针里连续两次调「进关入口」，拿前后两次的 `game_para` 做断言。
- **因为**：进关会真的切场景（`GlobalUtils.change_scene` 是延迟调用），第一次调用之后主菜单节点已经没了，
  第二次拿不到菜单（探针里那条「（前置）主菜单在场上」就是这么红的）。
- **结论**：需要多次验入口的探针，每次调用前先回主菜单；纯换算的断言放到最后，不碰场景。

## 推荐度与理由

**推荐**。这类「删掉中间层界面、职责收进后台」的活，工作量不在删，而在三件事：
① 找齐**所有**入口（本例只有「主菜单进」与「通关回」两处，靠全仓搜枚举名确认，别靠感觉）；
② 把原界面**隐式依赖的口径**（按钮顺序 → 页码 / 关卡号 → 存档键）在后台重新落实并写清注释；
③ 收拾挂在旧界面上的探针（本次 11 条受影响 + 2 条删除）。
第 ② 点最容易漏 —— 漏了不报错，只是玩家的进度错位。

## 遗留

- 挂在冒险选关按钮上的**看点图标 / 关卡名 / 页码 / 页面背景**随界面一起消失（原版是地图上的装饰），
  没有补替代位置。
- `ChooseLevelAdventure` 在 `MainScenesMap` 里**没有槽位是故意的**（注释已写明）：
  任何 `get_scene_path(ChooseLevelAdventure)` 都会走 fallback 回主菜单。
- ⚠️ **导出包方向待观察**：`LevelRegistry` 扫目录在导出包里可能扫不到关卡
  （`script_export_mode` 会把 `.gd` 变成 `.gdc`，`_scan_dir()` 只认 `.gd`，
  联机模组里已为这种包留过「id 失败再用路径」的兜底）。冒险模式现在**没有**「选关页硬挂 ExtResource」
  那层保险，进关完全依赖注册表。本仓未做过导出实测；真出问题优先查这里。
