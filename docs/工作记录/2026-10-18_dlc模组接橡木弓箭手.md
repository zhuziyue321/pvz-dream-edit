# 2026-10-18_dlc模组接橡木弓箭手

> **本次任务**：把 DLC 的「橡木弓箭手」（OakArcher）接成能种的本行直线射手
> **耗时 / 轮次**：约 6 轮；**未开游戏实测**（ Godot 编辑器被他人占用，见踩坑 ）
> **推荐度**：可用（结构照抄现役 7 株 DLC 植物；摆放 / 卡面为静态估算，待运行期探针回填）

## 目标
在 `mods_builtin/dlc/` 再接一株能种的植物「橡木弓箭手」：有卡、能种、能射箭、有图鉴、有探针；关模组全撤。

## 最简路径（步骤）
1. 读 [DLC植物导入.md](../../参考存档/DLC植物导入.md) 八步流程；动画段在 `mods_builtin/dlc/animation/character/plant/OakArcher/`（idle / shooting / reload / blink / idle_empty），本株只用 idle + shooting + blink。
2. 取 wiki 数值：`api.php?action=parse&page=Oak%20Archer&prop=wikitext` → 阳光 200 / 冷却 7.5s / 伤害 80（带问号，暴击 160 未实现）/ 射程 1x9 / 攻击间隔 4.25s。
3. 量 `AnimLib` 在动画场景里的索引：数 `parent="."` 的直接子节点，`AnimLib` 是第 18 个 → 覆盖时 `index="17"`。`shooting` 长 0.9167s（< attack_cd 4.25，安全）。
4. 出箭时机：解析 `OakArcher_shooting.tres`，持弓手 `Oak_archer_arm1_2` 的 rotation 在 t≈0.17s 到 -2.142 拉满 → `shoot_delay = 0.17`。
5. 摆放：解析 idle 首帧各部件 `position/scale` + PNG 尺寸合并包围盒 ≈ x[-32.7,111.9] y[-43.0,79.5]，底边由 `Oak_archer_body`（95×107×0.93）主导 → `position = (-39.6, -79.5)`（内容底边落在原点）。⚠️ 有几个部件（arrow2 / arm_back / eyebrows）贴图走动画 texture 轨道，静态量会漏，**以运行期 `get_content_rect()` 为准**。
6. 建文件：`oakarcher/bullet_oakarcher_arrow.tscn`（继承本体 `bullet_cactus.tscn`，直线箭，80 伤害 / speed 260 / 0.6 缩放）、`oakarcher/oakarcher_plant.gd`（自挂 DetectComponent + 双计时器，`IsActivateLane=true` / `Direction=RIGHT`）、`oakarcher/plant_oakarcher.tscn`（检测框 9 格 = 684×60）。
7. 接进 `dlc_mod.gd`：常量 / `_build_oakarcher_recipe()` / `_register_oakarcher_almanac_entry()` / install 数组 / uninstall / 描述 / 详情面板。
8. 写探针 `test/scenarios/probe_dlc_oakarcher.gd`（对齐豌豆射手底边 + 战斗零件 + 箭矢字段 + 卸载）。

## 弯路 / 踩坑（三段式）
- **试过**：直接 `powershell > out.txt` 重定向跑 godot 探针。
- **因为**：godot 是 GUI 子系统二进制，PowerShell 重定向给不了真实文件句柄 → 输出 0 字节（假空）。
- **结论**：跑探针必须走 `test/run_autopilot.ps1 -Scenario <name>`（内部用 `cmd.exe /c ... > file` 拿真实句柄）。
- **试过**：跑 `run_autopilot.ps1` 实测摆放。
- **因为**：返回 `STALE_PROCESS` —— 有 Godot 编辑器窗口开着（`kingcactus_spike.tscn`，未保存），且同时有并发 agent 的无头 godot 在跑；**不能 `-KillStale`**（可能是用户编辑器 / 丢未保存工作）。
- **结论**：本次**未开游戏**；摆放 / 卡面落点是静态估算，需在 Godot 空闲后跑一次 `probe_dlc_oakarcher`，按 STEP5 打印的 `[INFO] rect=` 回填 `plant_oakarcher.tscn` 的 `position` 与 `dlc_mod.gd` 的 `OAK_ARCHER_CARD_FACE_POSITION`。
- **试过**：跑 `test/check_scripts.ps1` 编译门禁。
- **因为**：`--import` 主门禁 **real compile errors = 0**（本株文件全过）；但第二道 scenarios 编译 FAIL，报错全是**并发 agent 正在加的新植物**（`_build_glowshroom_recipe` / `_build_shrinkingviolet_recipe` / `_register_shrinkingviolet_almanac_entry` 未定义、`beeshooter` 的 `CanAttackZombieStatus` 拼写），**没有一条出自橡木弓箭手文件**。
- **结论**：共享的 `dlc_mod.gd` 正被多人同时编辑、处于「调用了但函数还没写」的中间态；门禁要等并发 agent 把自己那几株补完才转绿。**不要**去替别人实现/删他们的函数（会踩 [Agent协作协议.md](../Agent协作协议.md) 的所有权分区）。

## 推荐度与理由
推荐照此结构再接 DLC 植物：本体 `plant_base.tscn` + DLC 动画节点（覆盖 AnimLib 库）+ DetectComponent + 冷却/出弹双计时器，子弹能复用本体基类就复用（直线→`bullet_cactus`、抛物线→`bullet_parabola_base`）。后来者注意：① `AnimLib` 的 `index` 必须按动画场景实际子节点数数；② 摆放必须运行期 `get_content_rect()` 量，静态估算会漏 texture 轨道部件；③ 本仓正多 agent 并发改 `dlc_mod.gd`，改前先 `search_content` 看当前 install 数组与函数是否齐全，改后编译门禁的 scenarios  FAIL 很可能来自他人中间态，先甄别再决定管不管。
