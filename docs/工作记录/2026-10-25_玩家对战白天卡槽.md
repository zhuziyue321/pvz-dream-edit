## 弯路 / 踩坑（三段式）

- **试过**：重写 `zombie_card_mod.gd` 时只顾着改文案，把 `const ModBase := preload("res://src/mods/mod_base.gd")` 弄丢了。
- **因为**：`create_detail_control()` 里用了 `ModBase.create_detail_label(...)`；
  模组脚本在 `user://` 下不能裸写 `ModBase`（没有全局类名）。
- **结论**：编译门禁第二关能抓到（`Parse Error: Identifier "ModBase" not declared`）——
  **重写模组入口文件时先找一遍 `const ModBase`**。

- **试过**：僵尸卡槽的脑子计数 Label 复用本体卡槽的偏移（`-101..14`，贴左端脑区）。
- **因为**：底图翻了，脑区在**右端**；本体那套偏移把数字画在左端空白上。
- **结论**：场景里 Label 偏移直接按「内容原点 (12,10) + 右端脑区中心 ≈ 351」算好写进
  `.tscn`（`282..397`），别指望继承。

- **试过**：给 `CardSlotBattle` 子类节点在**代码里**补 `Marker2DSunTarget` 并标 `unique_name_in_owner`。
- **因为**：基类 `@onready var marker_2d_sun_target = %Marker2DSunTarget`；
  代码建的节点没有 owner，`%` 解析不到，@onready 每次实例化报一条 Node not found。
- **结论**：卡槽做成**场景**（`.tscn`），unique name / 节点路径全由场景解决；
  场景里脚本用**相对路径** `path="zombie_card_battle_slot.gd"`（先例 `glove/glove_slot.tscn`），
  跟模组加载根走；占位剪影等**本体**贴图写绝对 `res://pak/...`（模组可用本体的一切）。

- **试过**：`setup()` 里把 `sun_value = start_brains` 放在 `set_cards()` **之后**。
- **因为**：`set_cards()` 末尾那遍 `main_game_refresh_card()` 会拿 `sun_value` 判每张卡
  够不够阳光 —— 那一刻它还是 Nil，游戏里炸 `Invalid operands 'Nil' and 'int' in '>='`
  （本体不炸是因为 `init_card_slot_battle()` **先**给阳光**再**发牌，顺序是隐含契约）。
- **结论**：给 `CardSlotBattle` 装阳光必须排在 `set_cards()` 之前；
  凡是复用本体「初始化 → 发卡」链路的自建卡槽，都照本体 init 的字段顺序来。

### 追加一：选僵尸卡面板（同日第二轮）

- **做了**：`zombie_card_choose_panel.gd` + `.tscn` —— 植物待选区右面贴一条选僵尸卡面板
  （一行五张、一页五行），卡从候选容器池取（`SceneRegistry.acquire_candidate_container()`，
  池支持同一身份多份借出，与本体待选区的敌人页不冲突）；点卡选进反向卡槽（上限六张）、
  再点退回后面前移；收尾挂 `signal_choose_card_finished`：收面板，一张没选才发默认六张。
- **踩坑两个**：
  1. 本体待选区按存档解锁名单点亮候选容器，但僵尸卡是调试特性、存档里没人解锁过 ——
     面板**不做解锁门槛**（全亮），模组本身就是开关；
  2. 卡的点击路由不看 `card_context`，只看 `is_main_game`（见 `Card._on_button_pressed`）——
     池里出来的卡（Catalog 语境）在选卡阶段照样发 `signal_card_click`，无需切语境；
     但面板的选中处理必须**自判进度**（只在 CHOOSE / RE_CHOOSE 响应），
     否则 PREPARE 阶段点槽里的卡会被误退回。

- **试过**：`slot.setup(bank_tex, tex, [], start_brains)` —— 裸 `[]` 传给
  `references: Array[ResourceCardReference]` 参数。
- **因为**：无类型空数组字面量**不会**在调用点自动转成类型化数组，
  运行期炸 `Invalid type in function 'setup' … does not have the same element type`。
- **结论**：给参数写**类型化默认值**（`references: Array[ResourceCardReference] = []`），
  「传空」的场景直接省参；凡是「空数组也要传」的接口都这么留口子。

### 追加二：出场/收场动画 + 去翻页（同日第三轮）

- **做了**：反向卡槽与选卡面板都改成**阶段驱动**的 0.2s 平移（订阅
  `MAIN_GAME_PROGRESS_UPDATE`，与本体 `move_card_slot_battle/candidate` 同拍同速）：
  卡槽初始停在屏幕上方外（y=-100）、面板停在下方外（y=615），选卡/重选阶段滑入，
  其余阶段滑出；`finish_choose()` 不再管隐藏（滑出交给阶段事件，免得和进度两处打架）。
  面板去掉上一页/下一页按钮与页码，改单页 + `ScrollContainer`（27 张 6 行 445px，
  内容区 461px 装得下；以后卡多了滚动条自然兜底）。
- **注意**：动画 tween 要存引用、新动画先 `kill()` 旧的 —— 两个 tween 抢同一个
  `position:y` 会抖；`Tween.tween_property(self, "position:y", …)` 只动 y、保住接线摆好的 x。

- **试过**：候选容器从池里取出后直接 `grid.add_child(container)`。
- **因为**：池取出的容器**还挂在池存放节点下**（`CardCandidatePoolStorage`），
  裸 `add_child` 炸 `already has a parent`（本体待选区取件后用的是
  `container.reparent(占位格, false)`，见 `CardSlotCandidate._build_plant_page_slots`）。
- **结论**：**候选容器池的取件方一律 `reparent()` 挂进目标格**（判空父再 `add_child`），
  别裸 `add_child`。

- **试过**：卡槽/面板只订阅 `MAIN_GAME_PROGRESS_UPDATE` 等选卡阶段的滑入事件。
- **因为**：主游戏 `_ready` **一进来**就把进度推到 `CHOOSE_CARD`（`MainGameManager._ready`
  在 `init_manager()` 之前），而这两块是 `init_manager()` 装模组时才建的 ——
  阶段事件**早就发过了**，没人再发第二次，节点永远停在屏幕外的初始位（「僵尸卡槽没有出现」）。
- **结论**：**订阅完必须按当前阶段对一次表**（`_on_main_game_progress_update(_curr_progress())`）；
  且接线要**先摆位再 `add_child`** —— 否则 `_ready` 里的对表滑入会被随后的 position 赋值摁回屏幕外。
  任何「进场动画靠事件驱动、节点又是 init 中途装上去」的 UI 都适用这条。

- **试过**：出场也挂在 `MAIN_GAME_PROGRESS_UPDATE` 的选卡阶段上（订阅后按当前阶段对表）。
- **因为**：进度枚举在主游戏 `_ready` 一进来就是 `CHOOSE_CARD`，而植物卡槽/待选区实际是
  **选卡事件**（`enter_choose_card_progress` → `appear_choose`，开场相机平移完之后）才滑入 ——
  跟进度走整体**出早了**约 2 秒；且进度事件之后不会再发一次。
- **结论**：**出场跟拍** —— `_process` 里盯着本体待选区的 y（隐藏位 600，低于 595 = 开始滑入）
  就跟着滑， latch 后 `set_process(false)`；**收场仍走进度事件**（选卡收尾推 PREPARE，
  与本体待选区滑出同拍）。跳过选卡的局（PREPARE/MAIN_GAME 时才建）在 `_ready` 直接就位。
  「进场时机跟某个本体动画走、又没有对应事件」的 UI 都用这招。

### 追加六：**12 槽合一**（同日第七轮，用户拍板「和联机类似，看似两个卡槽，实则存储是一个 12 槽」）

> 用户口径：与联机的合并卡表同一套思想 —— 眼前左右两条银行，存储是**一个** 12 格出战卡槽
> （前 6 格植物、后 6 格僵尸 / 僵王，「卡槽第几格」是整槽口径）。
> 货币**保持分池**（植物花阳光 / 僵尸花脑子 150，不随阳光涨）；**对战没有 1~0 快捷键**。

- **本体加的三个通用口子**（`card_slot_battle.gd`，照联机「本体只加口子」的先例，不带对战字样）：
  ① `card_type_blocks` / `block_sizes`（分块：每类卡进自己那块第一个空位，取消只清自己那格，
  空位留在原地 —— 块与块互不挤占）；② `currency_of_card` / `on_card_cost`（分池：每张卡判钱 /
  扣钱问哪个池）；③ `shortcuts_enabled`（整槽不发快捷键）。外加全链路**空位容忍**
  （`curr_cards` 允许 null：sun setter / refresh / set_cards / 下一轮 / 紫卡价 / 判负 /
  指针找卡 / 存选卡 / 断连接 / 测试零冷却，约 10 处 null guard）；分块银行的空位**恒显示**
  （收走空格会把卡挤得跟底图对不上）。
- **模组侧**：`zombie_card_battle_slot` 从「第二张 CardSlotBattle（独立存储）」降级成**纯外观银行视图**
  （底图 + 脑子计数 + 占位格 6~11 的宿主，占位格由接线从本体槽挪进去、槽的 `cards_placeholder`
  后 6 格指向它）；接线 `zombie_card_pvp_wiring` 改配槽（分块 / 分池 / 快捷键）+ 挪占位格；
  选卡面板改走 `free_index_in_block(1)` / `put_card_at` / `take_out_card`；关卡
  `max_choosed_card_num = 12`。分池的钱账（脑子）记在接线 `_brains`，扣脑子后刷计数 +
  重判僵尸卡。
- **为什么能合一**：「我是僵尸」关本来就是僵尸卡直接进本体出战卡槽（`puzzle_zombie_XX`
  `start_sun=150`）—— 合一只是把这个既有模式扩成混装。放置 / 扣费 / 判够不够全走既有链路
  （`click_cell` → `signal_card_use_end` → 槽 `card_use_end`，判钱由槽 `judge_sun_enough` 推给卡），
  口子只动「问哪个池 / 扣哪笔」。
- **踩坑两个**：
  1. 银行场景里留着旧的 `CardPlaceholder_ori` 模板（旧发卡流程要复制它）—— 占位格挪进来后
     卡住 7 个孩子，探针抓出「6 格变成 7」。**场景转纯宿主时记得把模板节点一起摘掉**。
  2. 探针里 `slot.block_sizes == [6, 6] as Array[int]` 被 GDScript 解析歪（实参判成 Array）——

### 追加八：选卡面板里「墓碑 ↔ 旗帜」对调显示位置

> 用户口径：在选卡界面里把产脑光墓碑和旗帜僵尸**换个位置**。

- **为什么需要单独做一步**：面板的显示顺序 = `AllCards.zombie_card_ids` 的登记顺序
  （= `all_cards.tscn` 的节点顺序 + 运行期插卡）。墓碑由 `ZombieRuntimeKit` 插进源目录**末尾**
  （`zombie_runtime_card._install_card()` 追加在最后一个容器），所以它永远排在最后；
  旗帜僵尸是本体第 2 张（`norm 0 / flag 1 / cone 2 …`）。
- **改法**：不碰 `AllCards` 的编号（那会牵动卡槽格子换算、僵王 id 接续），
  只在这一面排显示顺序：`_build_grid()` 先收集成 `types: Array[StringName]`，
  再按 `zombie_card_settings.gd` 的 `PLAYER_BATTLE_SWAP_CARDS = [墓碑 id, ZombieIds.FLAG]`
  对调两项，然后才建格。任一张不在表里（玩家对战模组没开、墓碑没装）就不换。
  （**同日追加九已把「对调」换成通用的 `PLAYER_BATTLE_MOVE_AFTER`**，见文末。）
- **边界**：僵尸卡模组与玩家对战模组之间**没有依赖**，所以墓碑那边只能按 **id 字面量**认识
  （`zombie_card_vsgravestone`，前缀 `zombie_card_` 是历史原因，见 `player_battle_settings.gd`）；
  除「显示排序」外仍不给它开任何特判。
- **验证**：`check_scripts.ps1` PASS（real compile errors = 0）。没开窗口，人工看一眼：
  进「玩家对战：白天」选卡 → 面板第 2 格是墓碑、旗帜挪到僵王前面那一格（原来墓碑的位置）。

### 追加九：伴舞放开可选 + 顺序规则通用化

> 用户口径：**在舞王后插入伴舞**，**把旗帜移动到海豚后**。

- **伴舞放开**：`ZombieIds.DANCER` 从 `PLAYER_BATTLE_EXCLUDED_ZOMBIES` 移出。它在
  `all_cards.tscn` 里本来就排在舞王后面（`jackson 8 / dancer 9`），所以「插到舞王后」
  **不用额外挪位** —— 一放开就自然落在那里。剩下不给选的只有单个雪橇车队员 / 鸭子救生圈。
- **顺手补的一处（别漏）**：伴舞不在 `PLAYER_BATTLE_ZOMBIE_COOLDOWNS` 里就会吃到注册表的
  **0 冷却**（`zombie_info_data.gd` 的 CoolTime 是「我是僵尸」口径，全 0）→ 无限放。
  按同批「wiki 没登记」的先例填 **30 s** 并标待核实。花费仍走注册表的 50（对战表没这张卡）。
- **「对调」换成通用规则**：`PLAYER_BATTLE_SWAP_CARDS`（两项互换算）换成
  `PLAYER_BATTLE_MOVE_AFTER = [[要挪的卡, 挪到谁的后面], …]`，面板侧 `_apply_display_moves()`
  逐条「摘出来 → 插到目标后面」。现在的两条：墓碑 → 普僵后（等价于原来那个「和旗帜对调」的位置），
  旗帜 → 海豚骑士后。要挪的卡或目标卡不在列表里就跳过。
- **探针**：`probe_player_battle_mod` 的排除项改成只剩雪橇单车 + 鸭子救生圈，
  另加三条顺序断言（墓碑紧跟普僵 / 伴舞紧跟舞王 / 旗帜紧跟海豚骑士）。
- **验证**：`check_scripts.ps1` PASS（real compile errors = 0）。
  ⚠️ **运行期探针没跑**：`run_autopilot.ps1` 检测到已有 Godot 进程（pid 26932）占着共享输出，
  按规矩不杀。人工看一眼：进「玩家对战：白天」选卡 → 一行五张依次是
  普僵 / 墓碑 / 路障 / 撑杆 / 铁桶 … 舞王 后面紧跟**伴舞**，海豚骑士 后面紧跟**旗帜**。
