## 1. 这是什么

植物僵尸 = **普通僵尸的身子 + 一颗植物顶替了它的头**（原版就是僵尸头上长着植物，不是额外挂一棵在头顶上方）：

1. 那颗植物有**自己的耐久** —— 玩家先把它打掉，才轮到僵尸本体；
2. 那颗植物**会用原植物的能力攻击玩家的植物**（豌豆僵尸射豌豆、投手僵尸投掷…）。

原版 ZomBotany 是**迷你游戏**（不是冒险模式关卡），本仓库对应两关，见 §4：

| 关 | 文件 | 原版场景 | 原版旗帜 |
| --- | --- | --- | --- |
| 迷你游戏第 1 关「植物僵尸」 | `src/levels/mode_minigame/minigame_01_zom_botany.gd` | 白天前院 | 2 面（20 波） |
| 迷你游戏第 17 关「植物僵尸 2」 | `src/levels/mode_minigame/minigame_17_zom_botany_2.gd` | 泳池 | 3 面（30 波） |

（选关界面顺序与原版 1 / 17 号位一致；早期文件名里的 `06` 只是迁移时的编号，不代表顺序，
见 [选关界面与解锁.md](选关界面与解锁.md)。）

## 2. 数据在哪：ZomBotanyConfig

**`src/entities/character/components/zombie_plant_component/zom_botany_config.gd`**（全 static，和 `BulletCampConfig` 同风格）

14 只的差异**全是数据**：贴图 / 耐久 / 出怪战力与权重。全部集中在 `C_ZOM_BOTANY_INFO`：

| 字段 | 含义 |
| --- | --- |
| `zombie_type` / `plant_type` | 僵尸类型 / 取代僵尸头的那颗植物对应的植物类型 |
| `plant_hp` | 那颗植物的耐久。**0 = 没有独立耐久**（原版豌豆 / 窝瓜 / 机枪僵尸：总耐久就是僵尸本体 270，植物头只在 2/3 血时掉落，是纯表现）；坚果 / 南瓜 1100、高坚果 2200、火爆辣椒 230；本仓库扩展的 8 只用 300 |
| `head_offset` / `head_scale` | 相对**僵尸头贴图中心**的微调偏移（默认 `Vector2.ZERO`）与植物整体缩放 |
| `sprites` | 植物头的贴图（**只放头、不放茎**；按数组顺序绘制，越靠后越上层） |
| `head_scene` | 动画版植物头场景（可选，**优先于** `sprites`）：根 = 植物原点，实例化后播根下 `AnimationPlayer` 的 `Head_Idle`。**原版 6 只都配了**（`plant_head_*.tscn`），扩展的 8 只仍是拼静态 PNG（见 §3.2） |
| `attach` | **原版 attach 参数**（`HeadAttach`）：`to_body` 选挂点轨道（`Zombie_body` / `Anim_head1`，也就是图层）+ `offset` / `rotation` / `scale`（含镜像负号）。原版 6 只全部照抄 `Zombie.cpp`，静态头不用（见 §3.2.1） |
| `head_body_path` | 动画头里「主体贴图」的**节点路径**（相对头场景根）：受损裂纹换的是它。静态头换的是 `sprites[0]`，动画头的贴图由动画资源自己设，只能按路径找节点。目前只有坚果（`Body/BodyCorrect/Anim_face`）/ 高坚果（`Body/BodyCorrect/Anim_idle`）配了 |
| `hide_tie` | 隐藏僵尸领带（原版 `ReanimShowPrefix("Zombie_tie", RENDER_GROUP_HIDDEN)`）：坚果 / 高坚果 / 辣椒僵尸的头是**整颗植物**，领带会从植物底下露出来 |
| `power` / `weight` | 出怪战力与初始权重（**只有这里一份**，见 §4） |

> `head_offset` / `head_scale` 的语义在 2026-10-16 的「换头」改造里变过一次：
> 早先是「相对 `Body/BodyCorrect` 的挂点 + 头顶那棵完整植物的缩放」，现在是
> 「相对僵尸头贴图中心的微调 + 植物显示出来的最终大小」——
> **僵尸头节点自身的缩放（0.798）由组件抵消掉**，配置里写多少就是屏幕上多大，不用自己乘系数。

> `C_ZOM_BOTANY_INFO` 是 `static var` + `_static_init()`，**不能写成 const** ——
> GDScript 的 const 初始值里不允许 `new` 内部类实例（报 `isn't a constant expression`）。

> **原版口径**（2026-10-23 按 wiki 重核）：PvZ1 的 ZomBotany 只出**豌豆僵尸 + 坚果僵尸**两只，
> ZomBotany 2 = 这两只 + **窝瓜 / 火爆辣椒 / 机枪 / 高坚果**（PVZ Wiki ZomBotany zombies），就这 6 只。
> 本仓库多做的那 8 只（寒冰 / 火炬 / 磁力菇 / 南瓜 / 卷心菜 / 玉米炮 / 西瓜 / 冰瓜）是**加料**，
> wiki 明说寒冰射手僵尸 *"does not appear in the first Plants vs. Zombies"*，所以它们的耐久 / 战力 / 权重
> 是本仓库自己定的，**不要**拿它们当原版数据用。
>
> **耐久口径**：原版只给「总耐久」——总耐久 = 僵尸本体 270（`zombie_base.tscn` 的 `HpComponent.max_hp`）
> + 头顶植物那层耐久，所以 `plant_hp = 总耐久 − 270`。豌豆 / 窝瓜 / 机枪的总耐久就是 270，
> 那颗植物头**不是**一层血量（原文 `loses its … head at 180` 是本体血量的 2/3，纯表现），
> 因此 `plant_hp = 0` → 场景里 `ArmorComponent.max_hp = 0`，按 `ArmorComponent` 的约定「0 = 这不是一件防具」，
> 不打血、不显示血条、植物头也永远不会消失（原版那一下「头掉」本仓库没做，见 §8）。
> 高坚果僵尸 wiki 页自相矛盾（信息框 `health = 2470`，正文写 2670 / 2400），取**信息框** 2470。
>
> **当前出怪表**（关 1 = 2026-10-05，关 2 = 2026-10-23 起，两关都已对齐原版）：
> 关 1 只出 `豌豆僵尸 + 坚果僵尸` 两只；关 2 出 `豌豆 / 坚果 / 窝瓜 / 火爆辣椒 / 机枪 / 高坚果` 六只。
> **两关都不出普僵**，旗帜波也不补旗子僵尸（见 §4 的 `spawn_plain_zombie_extra`）—— 那 8 只扩展已移除。
> 想加料：把类型加回对应关卡脚本（`minigame_01_zom_botany.gd` / `minigame_17_zom_botany_2.gd`）的
> `zombie_list` 即可，不需要动其它文件，数据都还在 `ZomBotanyConfig`。

## 3. 行为骨架

### 3.1 攻击：`AttackComponentZomBotany`

**`src/entities/character/components/attack_behavior_component/component_attack_zom_botany.gd`**

> **为什么不直接用植物的 `AttackComponentBulletBase` / `...PultBase`**：
> 那两个组件的 `_on_bullet_attack_cd_timer_timeout()` 只是给 `AnimationTree` 打一个 `ONE_SHOT_REQUEST_FIRE`，
> **真正发射是攻击动画里的 `_shoot_bullet()` 方法调用轨道**。僵尸的攻击动画是「啃咬」，没有这条轨道 ——
> 直接套用会出现「冷却一直在走、一颗子弹都不出」。
> 所以这里改成冷却到点直接发射，再用 Tween 让头顶植物做个「发射」的小动作代替动画。
> **豌豆僵尸例外**（2026-10-19）：它的动画头里搬了植物的 `Head_Attack`（连「吐出豌豆」的方法轨一起），
> 计时器只负责起播动画，真正的发射由那条方法轨回调 `_shoot_bullet()`（见 §3.2）。

要点：

- `burst_num` / `burst_interval`：连发（机枪僵尸 4）。
- `attack_once()` 是**空实现**（2026-10-25 加）：僵尸共享的 `Zombie_eat` 动画在啃咬帧会调这个方法，
  而这条路上的植物僵尸本来就不啃植物（下面 §3.1 末段的口径）。留空只为接住方法轨，否则一进啃咬状态就每口刷一次
  「方法不存在」；**不要**在这里补啃咬伤害，那属于另一套逻辑（`AttackComponentZombieNorm`）。
- `bullet_direction` 默认 `Vector2.LEFT`：**不能**用 `detect_component.ray_area_direction` ——
  它按检测区的 `rotation` 算，僵尸的啃咬检测区 `rotation` 是 0（等于朝右），拿来用子弹会往僵尸身后飞。
- 子弹阵营由 `AttackComponentBulletBase.get_bullet_camp()` 决定（owner 是僵尸 → 僵尸方子弹，打玩家的植物），
  所以这些僵尸和玩家植物**共用同一份子弹场景**，见 [子弹说明](子弹说明.md) §3。
- 玉米加农炮僵尸走 `component_attack_zom_botany_cob_cannon.gd`：玉米炮子弹不发 `init_bullet`，
  要 `init_cannon(目标位置)`，且爆炸框的 mask 要按阵营切（见 `bullet_cob_cannon.gd`）。

#### 豌豆僵尸不在这条路上：`AttackComponentZomBotanyPea`

**`src/entities/character/components/attack_behavior_component/component_attack_zom_botany_pea.gd`**

原版口径（PVZ Wiki《Peashooter Zombie》）：

> Stat-wise, it is identical to a normal Zombie, but additionally fires peas **constantly** down its lane
> … they fire the peas **before they come on the screen**

也就是**两件事同时成立**，只做一件都不对：

1. 它**照常走、照常啃植物** —— 啃咬开关还是 `is_attack_res`，走到植物跟前才停；
2. 豌豆**恒定**发射 —— 不要求检测区里有植物，进场（甚至还没进屏）就开始射。

`AttackComponentZomBotany` 做不到这两点：它把发射挂在 `is_attack_res` 上，而 `is_attack_res` 一为真
就会 `signal_change_is_attack(true)` → 移动组件的 `IsAttack` 因素置位 → **僵尸停住**；
为了让检测区「够得着」又把它撑到 760 像素宽，结果僵尸停在离植物几百像素的地方播啃咬动画 ——
既不走也不啃，还只在有植物时才射。

所以豌豆僵尸改成：继承 `AttackComponentZombieNorm`（啃咬整套照搬，一个字不用改）+ 自带一个
只受「组件启用 / 头顶植物还在」约束的发射计时器。

> **2026-10-24 校正**：上面这句「不重写 `owner_update_speed`」只对一半 ——
> **减速**（寒冰射手 / 冰瓜）确实不影响发射频率，但**完全定住**（寒冰菇冰冻停滞 / 玉米投手黄油）
> 时原版 `mPhaseCounter` 不递减、同样不开火。现在组件重写了 `owner_update_speed()`：
> `speed_product == 0` 时 `bullet_attack_cd_timer.paused = true`（保留剩余时间），
> 与 `AttackComponentBulletBase` / 大嘴花 chew_timer 同款处理；减速档不停表。

> 机枪僵尸 / 寒冰射手僵尸目前还在旧组件上（会停在检测区边缘），想一并对齐原版就照这份抄一遍。

**发射点照原版实时取头部轨道（2026-10-24）**：原版 `Zombie::UpdateZombiePeaHead()`
（`Zombie.cpp` 第 2338-2339 行；机枪 `UpdateZombieGatlingHead()` 2458-2459 同公式）每次发射都读
`anim_head1` 轨道的**当前帧**变换再加偏移：

```cpp
aOriginX = mPosX + aTransform.mTransX - 9.0f;
aOriginY = mPosY + aTransform.mTransY + 6.0f - mAltitude;
```

但 `mPos` **不是脚底**，是僵尸**头顶**（碰撞框 `mZombieRect = Rect(36, 0, 42, 115)` 从 mPos 往下
115 到脚底）；而 reanim 的绘制原点也不在 mPos 上 —— `DrawZombieWithParts()` 里
`SetPosition(mImageOffsetX + 15 + 30 - 30s, mImageOffsetY + mBodyY - 8 + 120 - 120s)`，
普通僵尸 `s = 1`、`mImageOffset = 0`、`mBodyY = 0` → **reanim 原点 = mPos + (15, -8)**。

两条式子一起整理就得到仓库口径（`Anim_head1` 节点的 `position` 就是原版 `mTrans`，
reanim 文件第 0 帧 `x=6.7 y=8.8` 与 Godot 侧动画值逐字节一致）：

```text
发射点 = mPos + mTrans + (-9, +6)
       = (头贴图左上角 − (15, -8)) + (-9, +6)
       = 头贴图左上角 + (-24, +14)      ← C_SHOOT_OFFSET
```

`mAltitude` 在两式里各出现一次（发射点 `- mAltitude`、`mBodyY = -mAltitude`），**正好抵消**；
跳跃高度体现在头节点自身的世界位置上，不用再减。

**算法收到一处**：`ZombiePlantComponent.get_head_shoot_global_position()` 读 `Anim_head1` 的
`global_position` 加这个偏移（读不到头轨道就返回调用方给的兜底）。为什么放这儿 —— 这些僵尸的「嘴」
本来就是**头顶那颗植物头**的属性，只算一份，改常量不会漏改另一处：

- 豌豆僵尸（`component_attack_zom_botany_pea.gd`）直接调它；
- 机枪 / 寒冰射手僵尸（`component_attack_zom_botany.gd`）经 `AttackComponentBulletBase` 新增的
  可覆写入口 `get_shoot_global_position(index)` 调它，场景里把 `shoot_from_head_track` 打开
  （原版同公式，机枪 `Zombie.cpp` 2458-2459）；
- 仓库扩展的**投手类**（卷心菜 / 西瓜 / 冰瓜）原版 ZomBotany 没有，没有可照抄的口径，
  继续用场景里的 `Marker2D` 静态坐标（`shoot_from_head_track` 默认关）。

**不要退回读场景里 `Marker2D` 的静态坐标**：原先写死的 `(0, -38)` 换算到世界坐标是僵尸头顶
上方 40 多像素（头贴图本身在 `y ≈ -112`），而头在动画里还晃 ±10 像素 —— 表现就是「豌豆从头顶
飞出去、和嘴对不上」，也就是 2026-10-24 用户反馈的「子弹有偏移」。直线弹（豌豆 / 机枪 / 寒冰）
现在只把 `Marker2D` 当「读不到头轨道」时的兜底，场景里已改成与静态头姿态对齐的
`(1.9, 17.96)`（= `(25.9, 3.96) + (-24, +14)`）；投手类则仍以它为发射口、位置按投掷口手动摆。
`body` 被水平镜像（**非魅惑原因**，如模组自定义朝向）时偏移取反：判据用
`body.global_transform.x.x < 0`，**不能**用 `global_scale.x`（`scale.x = -1` 分解出来可能是 `(1, -1)`）。

**魅惑态单独一档（2026-10-24 补，原版 `DO_FIX_BUGS` 分支）**：`UpdateZombiePeaHead()` /
`UpdateZombieGatlingHead()` 对 `mMindControlled` 的吐豆僵尸做两件事（两个参照项目口径一致）：

1. 发射点在普通口径上再 `aOriginX += 90.0f * mScaleZombie`（豌豆僵尸是普通僵尸，s = 1）——
   即相对头贴图左上角 `(-24 + 90, +14) = (66, +14)`，仓库常量 `C_SHOOT_OFFSET_HYPNO`；
2. 改发**植物方**豌豆（`PROJECTILE_PEA`，不带 `MOTION_BACKWARS`）→ **朝右飞**，打右边还没被魅惑的同类。

仓库侧：`is_hypno` 时 `get_head_shoot_global_position()` 直接返回头轨道 + `C_SHOOT_OFFSET_HYPNO`
（不再走镜像取反——魅惑在仓库里同样靠 body 水平镜像实现，两条路只选与原版数值一致的那条）；
方向由 `component_attack_zom_botany_pea.gd` 的 `_get_bullet_direction()` 翻成 `Vector2.RIGHT`；
阵营不用管 —— `BulletCampConfig.get_owner_camp()` 已随 `is_hypno` 翻成植物方。
回归断言见 `test/scenarios/probe_zom_botany_pea_shoot.gd`。

### 3.2.1 原版 6 只的动画头：直接复用植物自己的 idle 动画 + 原版 attach 参数

2026-10-23 起，原版 6 只（豌豆 / 坚果 / 窝瓜 / 辣椒 / 机枪 / 高坚果）的头不再是「拿植物部件 PNG 拼的静态图」，
而是 `plant_head_<植物>.tscn` —— **原版僵尸外观就是这么长的**：原版 `Zombie` 构造函数里给
`ZOMBIE_*_HEAD` 挂的就是**那颗植物的整套 reanim**，播 `anim_idle` / `anim_head_idle`：

| 僵尸 | 原版挂的 reanim + 动画 | 本仓库头场景 | 复用的动画资源 | 原版挂点 + attach（offset / rot / scale） |

| 坚果 | `REANIM_WALLNUT` + `anim_idle` | `plant_head_wall_nut.tscn` | `animation/.../wall_nut/wallnut_idle.tres` | `Zombie_body`，50,0 / 0.2 / -0.8,0.8 |
| 高坚果 | `REANIM_TALLNUT` + `anim_idle` | `plant_head_tall_nut.tscn` | `tallnut_idle.tres` | `Zombie_body`，37,0 / 0.2 / -0.8,0.8 |
| 窝瓜 | `REANIM_SQUASH` + `anim_idle` | `plant_head_squash.tscn` | `squash_idle.tres` | `anim_head1`，55,-15 / 0.2 / -0.75,0.75 |
| 火爆辣椒 | `REANIM_JALAPENO` + `anim_idle` | `plant_head_jalapeno.tscn` | `jalapeno_idle.tres` | `Zombie_body`，55,-5 / 0.2 / -1,1 |

（attach 数值来自 `../PvZ-Portable-main/src/Lawn/Zombie.cpp` 的 707–851 行，照抄，**不要自己调**。）

**摆放 = 原版 attach：挂点轨道本身就是「图层」**

- 挂 `Body/BodyCorrect/Anim_head/Anim_head1`（`attach.to_body = false`）：跟着走路摇头 / 啃咬点头；
- 挂 `Body/BodyCorrect/Zombie_body`（`attach.to_body = true`）：跟身体走、**不**跟头，且作为身体贴图的
  子节点画在身体**之上**。原版坚果 / 高坚果 / 辣椒就是这么挂的。

头场景的根 = **植物 reanim 的原点**（= 原版 attach 摆的那个点），组件把根摆到
`attach.offset / rotation / scale` 上 —— 原版对「植物 reanim 原点」的那三个数，直接搬。所以：

1. **节点层级/名字照抄植物场景，但格子修正要清零**：层级仍是 `Body/BodyCorrect/...`（窝瓜那套
   `squash_idle.tres` 的轨道路径是 `Body/...`，所以它的 `Body` 直接顶替 `BodyCorrect` 的位置），
   可是植物场景里 `BodyCorrect` 那个 `(-4x, -6x)` 是**「植物 reanim → 格子锚点」的修正**，
   只对种在格子里的植物成立。头场景必须把它写成 `(0, 0)`，否则整颗头会跟着偏几十 px
   （2026-10-23 就是这么偏的：带着 `BodyCorrect` 时豌豆头偏 (+41, -41)）。
   部件自身的坐标**不要动**，那是 reanim 原始坐标，动了动画轨道会对不上；
   ⚠️ 同样的修正也可能**藏在动画里**：窝瓜的 `squash_idle.tres` 原来多一条
   `Body:position:y = -45`（老场景留在动画资源里的格子修正），idle 一播整颗头就抬高 45px
   —— 2026-10-23 第二轮「窝瓜偏高」就是它，已删除。头场景的根必须**只**是 reanim 原点；
2. **摆位必须扣掉挂点轨道的「基准姿态」**（2026-10-23 第二轮返工，用户反馈「坚果 / 高坚果 / 辣椒靠下、
   窝瓜靠上、机枪 / 豌豆有微小差别」就是漏了这一步）：
   原版 `Reanimation::GetAttachmentOverlayMatrix()` 算的是
   `僵尸overlay · 轨道(当前帧) · 轨道(基准帧)⁻¹`，基准帧由 `aBodyReanim->mFrameBasePose = 0` 指定
   （`NO_BASE_POSE = -2`，写 `0` 就是第 0 帧，**不是**「没有基准」）。
   即轨道第 0 帧自带的平移 / 缩放**不参与**：植物原点正好落在 `attach.offset`（僵尸 reanim 坐标系），
   植物只再乘一次 `attach.scale`。
   本仓库的动画资源写的是**绝对姿态**（每个图层时间 0 = reanim 第 0 帧），直接挂到轨道节点下会多乘一次
   `轨道(0)`：挂 `Zombie_body` 的三只多带 `(28.9, 33.8)` + 0.8 缩放（偏低 ~34px），
   挂 `Anim_head1` 的三只多带 `(6.7, 8.8)` + 0.8 缩放（偏低 9~12px），六只还统统小 20%。
   组件 `_attach_head_to_original_track()` 在挂点与植物头之间垫一层 `AttachBasePoseInverse`
   （= `轨道(0)⁻¹`，从僵尸 `AnimationPlayer` 的 `Zombie_walk` 第 0 帧读出来）来抵消；
   **不要**改成直接 `anchor.add_child(plant_head)`，也不要把这段差值手调进 `attach`；
3. `AnimationPlayer` **不写 `root_node`**（默认就是父节点 = 场景根 `PlantHead`），
   `Body/BodyCorrect/...` 刚好解得开。漏写/写错只会刷 `Node not found: Body/BodyCorrect/...`，
   表现是「植物某个部件不动」；
4. 后 5 个场景**不复制动画**，直接引用植物自己的 `.tres`（植物那边改了动画，僵尸头跟着改）；
5. **`rotation` 要取负**（`-attach.rotation`）：原版 `PvzpScaleRotateTransformMatrix(rad)` 的线性部分
   是 `[[cos·sx, sin·sy], [-sin·sx, cos·sy]]` = `R(-rad)·S`，Godot 的 `rotation` 是 `R(θ)·S`；
6. **`position` 不要加减半个贴图**：原版轨道 `(x,y)` 就是贴图左上角（`DrawTrack` 预乘 `T(+cel/2)`、
   `ReanimBltMatrix` 再减 `scale*cel/2`，相消），本仓库 `centered = false` 的节点原点也是左上角。

> 动画头的**受损裂纹**不能再用 `sprites[0]`（贴图由动画资源自己设），改按 `head_body_path` 找节点换图：
> 坚果换 `Body/BodyCorrect/Anim_face`、高坚果换 `Body/BodyCorrect/Anim_idle`。
> 这两个节点的 idle 动画**没有** `texture` 轨道，换上去不会被打回去。
> 以后给别的植物做裂纹素材，先确认它的 idle 动画不驱动 `texture`，再在配置里补 `head_body_path`。

> 原版那三只用整颗植物替换头的（坚果 / 高坚果 / 辣椒）还额外 `hide_tie`：僵尸领带是
> `Body/BodyCorrect/Zombie_tie`（外层容器，内层贴图的 visible 会被 `_random_sprit_appear()` 随机改），
> 不关就会从坚果底下露出来。

**豌豆僵尸的动画头**在 `plant_head_pea_shooter.tscn`：节点层级、贴图、`Head_Idle` / `Head_Attack` 轨道全部从
`plant_pea_shooter_single.tscn` **原样搬过来**（轨道路径前缀保持 `Body/BodyCorrect/`），
所以它和玩家种下的豌豆射手是同一套动画。几条不显然的约定，改这个场景前先看：

- 根 `PlantHead` 的原点 = 植物 reanim 原点（`BodyCorrect` 的格子修正已清零），摆位交给配置里的
  `attach`（65,-5 / 0.2 / -1,1）—— **不要**再在场景里加「居中 / 归一化」层，
  也不要把植物场景那份 `BodyCorrect(-43,-67)` 抄回来；
- 头场景里必须有一个直接叫 `AnimationPlayer` 的子节点、库里要有 `Head_Idle` 与 `Head_Attack` ——
  组件按名字取（`ZombiePlantComponent.C_HEAD_ANIM_PLAYER_NAME`），缺了只会打 error，
  那颗头就停在静止姿势（不会自动退回 `sprites`）；
- **发射由动画驱动**：`Head_Attack` 里那条 `_shoot_bullet` 方法轨原本写的是 `NodePath("AttackComponent")`
  （植物场景里攻击组件就在根下），头挂到僵尸身上后路径对不上。组件实例化时**复制一份 `Head_Attack`**、
  把这条轨重定向到僵尸自己的 `AttackComponent`（共享资源不能就地改，否则所有僵尸互相覆盖），
  再按植物的 **3 倍速**播（`AnimationTree` 里 `TimeScale 2 = 3.0`，不照抄头会慢三拍）；
  豌豆就在方法轨那一帧打出去（约 0.3s），播完自动回 `Head_Idle`。
  绑不上方法轨时 `play_head_attack_anim()` 返回 false，攻击组件退回「直接发射 + Tween 后坐」，
  不会变成「只演动画、一颗都不射」。

藏僵尸头的三种写法，只有最后一种能用（这一处最容易踩）：

| 做法 | 结果 |
| --- | --- |
| 改 `Anim_head1.visible` | **动画里有 `Anim_head/Anim_head1:visible` 这条 track**（死亡动画把它设成 false），下一帧就被还原 |
| 隐藏外层 `Anim_head` | `visible` 是**继承**的 —— 植物就挂在这个头节点下面，等于把植物一起关掉 |
| `Anim_head1.self_modulate.a = 0` ✅ | `self_modulate` 只影响本节点自身的绘制、不牵连子节点，也没有动画 track 会覆盖它 |

> 隐藏清单与 `ResourceBodyChange`（僵尸「掉头」那套，见 `zombie_norm.tscn` 的 `Resource_b4qrn`）
> 用的是**同一组节点路径** —— 那套改的也是**外层容器**，所以不会被动画还原，这边照抄同一份判断。

**为什么挂在头节点下、而不是 `Body/BodyCorrect` 下**：僵尸走路的摇头 / 啃咬时的点头，
全是动画里那条 track 在驱动**头节点**的 `position / rotation / scale`；
挂进头节点，植物才跟着一起动，而不是钉死在身体上。
挂点 = 头贴图中心（`centered = false` 时就是 `texture.get_size() / 2`）＋ `head_offset` 微调，
头节点自身的缩放与初始倾斜由组件抵消（见 §2 的字段说明）。

**朝向：植物头做了水平翻转（`plant_head.scale.x` 取负）**。植物贴图一律朝右，僵尸却朝左走
（房子在左、豌豆也朝左飞），不翻就是「背对着行进方向」；翻 `plant_head` 的 x 缩放后，
各张贴图的 `offset` 跟着一起镜像，整颗植物是一张水平镜像图 —— `head_offset` / 贴图偏移的
调参值都在上一层（僵尸头节点）坐标系里，不受翻转影响，不用重调。

> 顺带一个好处：黄油等「糊脸」效果本来也是挂在 `Anim_head/Anim_head1` 上的（`ZombieButterUtil`），
> 换头之后它会正好糊在植物头上，不用另做适配。

> 「防具掉光就把植物藏起来」这一步**不在本组件里** —— 它属于那件防具自己的效果，
> 写在 `ArmorComponentPlantHead.on_armor_break()`（见 §3.3 与 [防具.md](防具.md)），
> 那里藏的正是本组件建出来的 `plant_head`。
>
> 历史坑（写法已改，教训留着）：**组件的 `component_ready()` 里读不到宿主的 `@onready` 成员** ——
> Godot 先跑子节点 `_ready()` 再跑父节点，`hp_component` 此刻还是 `null`，
> `if is_instance_valid(zombie.hp_component)` 会判空跳过，连接**静默失败**，
> 表现是「那棵植物怎么打都打不掉」（静态探针查不出来，只有进关卡打一下才发现）。
> 现在改成由**防具组件**按类型找 `ZombiePlantComponent`（`owner.get_node_or_null()`），
> 谁也不依赖宿主的 `@onready` 时序。
>
> 同源的时序坑（2026-10-16 换头时踩到）：**换头也不能写在 `component_ready()` 里** ——
> 宿主 `Zombie001Norm.ready_norm()` 里还有一步随机外观 `_random_sprit_appear()`，
> 会把舌头 / 头发**随机**设成 `visible`，把刚藏好的又打开（表现是「有的僵尸还顶着头发」）。
> 现在改成挂 `owner.ready`（宿主整个 `_ready()` 走完才执行，`CONNECT_ONE_SHOT`）。

### 3.3 耐久：走一层 `ArmorComponentPlantHead`

头顶植物的耐久 = 挂在同一角色下那件**一类防具**的血量（`ArmorComponentPlantHead`），
不是组件自己存的一份（伤害先扣防具再扣本体、血条显示都是 `HpComponent` 现成的，
自己另存一份会和它各演化各的，K-01）。详见 [防具.md](防具.md)。

场景里必须写：

```gdscript
[node name="ArmorComponent" type="Node2D" parent="."]
script = ExtResource("9_armor")   ## component_armor_plant_head.gd
armor_type = 9                    ## ConstArmor.E_ArmorType.PlantHead
armor_class = 1
max_hp = 230                      ## 植物头耐久 = 原版总耐久 − 270；**0 = 原版没有这层耐久**
```

> `max_hp = 0` 不是「配漏了」：`ArmorComponent` 的约定就是这个数（`component_ready()` 直接 return、
> `is_alive()` 恒 false、不参与伤害结算、不显示血条）。原版豌豆 / 窝瓜 / 机枪僵尸就是这种形态 ——
> 头顶植物只是换皮，僵尸本体 270 打完就死。**配置表里的 `plant_hp` 与场景的 `max_hp` 必须一致**，
> `probe_zom_botany` 会逐只对表（§7）。

打光之后由那个防具组件自己把植物藏起来（`on_armor_break()`），
`ZombiePlantComponent` 与豌豆 / 磁力的攻击组件按类型取它、连它的 `signal_armor_death`。

| 僵尸 | 脚本 | 触发方式 |
| --- | --- | --- |
| 窝瓜僵尸 | `zombie_squash.gd` | 连 `attack_component.signal_change_is_attack`，碰到植物 → 对**目标那一格的所有植物**各 1800 穿透伤害（原版 `SquishAllInSquare`）→ `character_death_disappear()` |

| 火炬僵尸 | `zombie_torchwood.gd` | 场景里加 `Area2DUpBullet`（mask=8，只接植物方子弹），`area_entered` 时升级；**只升级 `bullet_camp == Plant` 的豌豆** |
| 磁力菇僵尸 | `zombie_magnet_shroom.gd` | 自带 Timer（15s），扫描本行 P032MagnetShroom 并吸走；头顶植物掉了就停 |
| 高坚果僵尸 | 无（纯肉盾） | 只有耐久 2200，没有速度 / 攻击加成（原版同） |

#### 踩坑：脚本用 `%` 引用自己加的节点，场景里必须勾「场景唯一名」

火炬僵尸在场景里新增了 `Area2DUpBullet`，脚本用 `@onready var area_2d_up_bullet: Area2D = %Area2DUpBullet` 取它。
**只写 `[node name="Area2DUpBullet" ...]` 不够**，还必须补一行 `unique_name_in_owner = true`：

```gdscript
[node name="Area2DUpBullet" type="Area2D" parent="." index="13"]
unique_name_in_owner = true
collision_layer = 0
collision_mask = 8
```

漏了这一行的表现：`@implicit_ready()` 报 `Node not found: "%Area2DUpBullet"`，变量是 `null`，
随后 `ready_norm_signal_connect()` 连信号时空指针 —— 僵尸**进场瞬间就把关卡流程打断**
（`zm_zombie_show_in_start.create_show_zombie`），而不是延迟到豌豆飞过来才炸。

- **为什么容易漏**：纯手写 `.tscn` 时在编辑器里看不到那个「%」勾选项，
  而仓库里同类写法（`zombie_zamboni.tscn` 的 `Smoke`、`zombie_digger.tscn` 的 `ZombieQuestionmark`）都带着这一行。
- **容易一起踩的**：`%` 与 `$` 别混用 —— `%` 要勾唯一名，`$` 要写对路径；本仓库两者都在用，
  改一处引用时先看原场景用的是哪一种。

| `spawn_plain_zombie_extra` | `false`（旗帜波不补旗子僵尸 / 普僵，残差也不补普僵） | `false`（同左） |
| `zombie_multy`（出怪倍率） | `1`（**原版不乘倍率**，见下注） | `1`（同左） |
| 选卡 | 自由选卡（`card_mode` 保持默认 `Norm`） | 同上 |

> `spawn_plain_zombie_extra` 是 `ResourceLevelData` 上的总开关（`LevelScriptBase` 继承它，关卡脚本 `_init()` 直接赋值），
> 由 `zm_zombie_wave_create_manager.get_curr_wave_zombie_list()` 消费。**原版依据**：`Board::InitZombieWaves`
> 里旗帜波那段对 `GAMEMODE_CHALLENGE_WAR_AND_PEAS` / `_2` 特判跳过「补普僵 + 旗子僵尸」，
> 所以这两关整关只有出怪表里的植物僵尸。**关 2 出怪表里再写一个 `ZombieIds.NORM` 就会把这条绕过去** —— 别加。
>
> `zombie_multy` 同理必须保持 `1`：原版 `Board::PickZombieWaves()` 那几条点数倍率
> （COLUMN ×6、保龄 / 小麻烦 ×4、MiniBoss / 暴雨夜 ×3、铲子 / 蹦极 / 传送门 / 隐形 ×2）
> **都不含** WAR_AND_PEAS / `_2`，这两关的波次点数就是 `aWave/3+1`（大波 ×2.5、大波普僵段不触发）。
> 关 1 据此：第 1 波 1 点 = 1 只豌豆僵尸，第 10 波（大波）`int(4×2.5)=10` 点，第 20 波 7 点；
> 关 2（30 波）：第 30 波 `30/3+1=11` 点。**别为「加料」调高它** —— 2026-10-24 之前这里是 `10`，
> 每波出怪数是原版的 10 倍（第 1 波就 10 只豌豆僵尸），用户实机反馈「植物僵尸明显过多」，
> 已改回 `1`（两份本机 C++ 参照交叉验证：倍率分支确实不含这两个模式）。
> `probe_zom_botany` 锁住了这三个开关的值（见 §7）。

> **首次允许波次**（2026-10-23 加）：`ZomBotanyInfo.first_allowed_wave`（**1 起算**，与关卡波数同口径），
> 原版 `ZombieDefinition.mFirstAllowedWave` —— 豌豆 / 坚果 = 1，窝瓜 / 辣椒 / 机枪 / 高坚果 = 10
> （`Board::PickZombieType()` 里 `theWaveIndex + 1 < mFirstAllowedWave` 就跳过）。
> 由 `ZombieWaveCreateManager._apply_first_allowed_wave(wave)` 在**每波取列表前**开关随机池：
> `RandomPicker.update_item_weight()` 不接受 0 权重，所以只能整项 `add_item` / `remove_item`。
> 本表之外的僵尸（普僵 / 路障 …）默认第 1 波起就允许，行为不变。

三个踩过的坑，改这两关时别再踩：

1. **`card_mode` 不要写 `Null`** —— `_apply_card_mode_constraints()` 会把它压成 `can_choosed_card = false`，
   而关卡又没有预选卡，结果是**一张植物都带不进去**（第 1 关以前就是这么坏的，只能眼看着僵尸进家）。
2. **泳池关的出怪表不要写 `Z011Duckytube`** —— 它不在泳池场景的自然刷怪白名单里，`init_para()` 会把它滤掉
   并打 `warning: 出怪刷新列表中 ZombieDuckytube 不在当前场景可以自然刷怪列表`。
   水面行由**两栖**（`ZombieRowType.Both`）僵尸顶上，它们入水会自己套上鸭子圈。
3. **窝瓜僵尸的行类型是 `Land`** —— 原版「除了窝瓜僵尸，其余植物僵尸都有鸭子圈版本」，
   写成 `Both` 会让水面行刷出一只没有鸭子圈却在水上走的窝瓜僵尸。
4. **`game_BG` 与 `game_sences` 是两条独立的线，必须成对写** —— `game_BG` 只换背景**贴图**，
   地图几何 / 水道 / 小推车类型全部由 `game_sences` 反查的默认地图决定
   （`MainGameBack → map_pool.tres`，见 [地图实现](地图实现.md) §一）。
   第 1 关曾写成 `MainGameBack` + `FrontDay`，结果前院底图上凭空出现两条水道和 6 台小推车
   （其中 2 台是水路 `PoolCleaner`），底图与玩法对不上；已改回 `MainGameFront`。

## 5. 出怪：战力与权重只在配置表

`zm_zombie_wave_create_manager.gd` 的 `zombie_power` / `zombie_weights_ori` 两张表**没有**这 14 只，
改由 `get_zombie_power()` / `get_zombie_weight()` 先查 `ZomBotanyConfig`，查不到再回落两张表。

理由：14 只各写一份会让两张表翻倍，且和 `zom_botany_config.gd` 各演化各的。
（`update_zombie_refresh_types()` 遇到 power ≤ 0 会跳过并打 warn，所以忘了配的表现是「这只永远不出」而不是崩。）

**原版 6 只的战力 / 权重取自各僵尸信息框的 `wave point cost` / `weight`**（2026-10-23 对齐，
与普通僵尸表同口径：普僵 1 / 4000、路障 2 / 4000）：

| 僵尸 | power（wave point cost） | weight |
| --- | --- | --- |
| 豌豆僵尸 | 1 | 4000 |
| 坚果僵尸 | 4 | 3000 |
| 窝瓜僵尸 | 3 | 2000 |
| 火爆辣椒僵尸 | 3 | 1000 |
| 机枪僵尸 | 3 | 2000 |
| 高坚果僵尸 | 4 | 2000 |

扩展的 8 只没有原版数据（wiki 只有二代页面），`power` / `weight` 是本仓库按「投手系更贵、炮系最贵」定的。

**踩坑（2026-10-05）**：本文件里凡是「按出怪表遍历」的循环都必须走 `get_zombie_power()` / `get_zombie_weight()`，
**不能裸写 `zombie_power[type]` / `zombie_weights[type]`** —— 裸索引遇到 Z031+ 直接抛
`Invalid access to property or key '31' on a base object of type 'Dictionary'`。
`update_curr_zombie_weight_upper_limit()` 当年漏改，表现是「出怪表含植物僵尸的关卡开第一波就崩」
（`curr_wave` 初值 -1，首波 wave == 0 正好走那一段）。
现已抽成 `calculate_all_zombie_weight()`，口径与 `update_zombie_refresh_types()` 一致：power ≤ 0 跳过、权重走同一取值函数。

## 6. 新增一只植物僵尸的步骤

1. `ZombieIds`（`src/core/consts/zombie_ids.gd`）加一个 id 常量（如 `&"zom_botany_pea"`）；
   2026-10-14 起僵尸编号已改成字符串 id，**没有编号段了**，不用再挑号、也不会撞段。
2. `ZomBotanyConfig.C_ZOM_BOTANY_INFO` 加一条（**那颗植物的头**的贴图、耐久、战力、权重；
   `sprites` 只放头、不放茎，位置默认「贴图中心对僵尸头中心」，不合适再给 `head_offset` / `head_scale`）。
   想要动画头就再给一个 `head_scene` + `attach`，它优先于 `sprites`。**照 §3.2.1 的路子**：
   照 `plant_head_wall_nut.tscn` 把植物场景的部件节点抄成 `Body/BodyCorrect/...`（根 = 植物原点），
   动画库直接引用植物自己的 idle `.tres`（`AnimationPlayer` 不写 `root_node`），
   摆位照抄原版的 `attach.to_body / offset / rotation / scale`。
3. `CharacterRegistry.ZombieInfo` 加一条（名字 / 场景 / `ZombieRowType`）。
4. 新建场景：**继承 `zombie_norm.tscn`**，只改这几处：

   ```gdscript
   [node name="Zombie044XxxZombie" instance=ExtResource("1_base")]
   zombie_type = 44                       ## 1) 类型

   [node name="ArmorComponent" type="Node2D" parent="."]
   script = ExtResource("9_armor")        ## 2) component_armor_plant_head.gd
   armor_type = 9
   armor_class = 1
   max_hp = 230                           ## 头顶植物耐久 = 原版总耐久 − 270；0 = 没有这层耐久

   [node name="AttackComponent" parent="." index="6" node_paths=PackedStringArray("markers_2d_bullet")]
   script = ExtResource("4_atk")          ## 3) 发射类才换：component_attack_zom_botany.gd
   attack_cd = 1.5
   attack_bullet_type = 1
   markers_2d_bullet = [NodePath("../Body/BodyCorrect/Marker2D")]

   ## ⚠️ 节点头那句 node_paths 不能省！markers_2d_bullet 是 Array[Marker2D]，
   ## 场景里存的是 NodePath，只有声明了 node_paths 引擎才会在 instantiate 时把路径解析成节点；
   ## 漏写会在实例化时直接报
   ##   "Unable to convert array index 0 from 'NodePath' to 'Object'"，
   ## 表现是关卡开场 create_show_zombie() 一崩，整个流程断在展示僵尸那一步。
   ## （zombie_pea_shooter / snow_pea / gatling / cabbage_pult / melon_pult / winter_melon / cob_cannon
   ##  七份场景都踩过这个坑，已修；同类坑见 probe_zom_botany 的「发射点已解析成 Marker2D」断言。）

   [node name="BulletAttackCdTimer" type="Timer" parent="AttackComponent" index="1"]
   ## 豌豆类（直线弹，原版有 (mTransX-9, mTransY+6) 口径）由组件按头部轨道实时算：
   ##   在 AttackComponent 上加 `shoot_from_head_track = true` 即复用 `ZombiePlantComponent` 的同一公式，
   ##   Marker2D 只当「读不到头轨道」时的兜底（位置 = 静态头 position + (-24, +14)）；

   [node name="ZombiePlantComponent" type="Node2D" parent="." index="13"]
   script = ExtResource("2_plant")
   ```

   发射类还要把检测区改大（默认是贴身啃咬那一小块）：`AttackComponent/DetectComponent/Area2d`

## 8. 已知边界

- **原版 6 只已经是原版外观**（2026-10-23）：头 = 那颗植物自己的 idle 动画（reanim 转出来的那套
  `.tres`），不再是拼出来的静态 PNG，见 §3.2.1。**扩展的 8 只**仍是拿植物部件 PNG 拼的静态图
  （位置与大小靠 §2 的 `head_offset` / `head_scale`，默认「贴图中心对贴图中心」），
  只给了一个 3% 缩放循环当待机呼吸（`_start_static_head_idle()`）—— 那是「别完全静止」的近似，
  不是原版 reanim。
- 僵尸本体沿用普通僵尸的动画：挂点与图层按原版 —— 豌豆 / 窝瓜 / 机枪的头挂 `Anim_head1`（跟着摇头 / 点头），
  坚果 / 高坚果 / 辣椒挂 `Zombie_body`（跟身体走、画在身体之上），见 §3.2.1。
  豌豆僵尸的头另有 `Head_Attack`（张嘴 / 发射），**但没接待机眨眼**
  （`Anim_blink` 在场景里是隐藏的，原植物靠 `BlinkComponent` 换贴图，这里没搬；
  攻击时那套 `Idle_shoot_blink` 是 `Head_Attack` 自带的，有）；其余 5 只原版只有 idle，
  没有眨眼（同样是 `BlinkComponent` 那套没搬）。
- 其余走 `AttackComponentZomBotany` 的植物僵尸，发射时仍是 Tween 的「向后一顿再弹回」（§3.1）——
  它们的动画头只搬了 idle，原版那套 `anim_shooting`（机枪 4 连发时头会抖）没搬；
  想要的话照豌豆的 `Head_Attack` 路子再补一条带方法轨的攻击动画。
- **死亡掉出来的头**：2026-10-23 起换成植物头（`ZombiePlantComponent._replace_drop_head()` 把
  `Body/NodeDrop/Node2D_Head_Drop/Head_Drop` 里的普僵头部件隐藏、补一张植物头主体贴图）。
  弹跳 / 旋转仍由掉落节点自己驱动，位置取 `head_offset` —— 只是「掉的是哪颗头」对了，
  不是原版那套掉头 reanim。
- **僵尸豌豆没有专属贴图**：原版 `PROJECTILE_ZOMBIE_PEA` 用的就是玩家那张 `IMAGE_PROJECTILEPEA`
  （`Projectile::Draw` 里两者同一个分支，没有染色），差别只在 `MOTION_BACKWARDS`（往左飞）。
  所以本仓库复用玩家 `pea` 子弹**是对的**，不要为了「僵尸专属」再造一套贴图。
- **受损裂纹**只做了坚果 / 高坚果（有 `Wallnut_cracked1/2.png`、`Tallnut_cracked1/2.png` 原图）；
  其余植物头没有对应的裂纹素材，配置表 `cracked_sprites` 留空 = 不换图。
- 磁力菇僵尸只在玩家**种了磁力菇**时才有实际作用（原版就是这样）。
