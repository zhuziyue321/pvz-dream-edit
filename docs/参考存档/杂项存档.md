## 铁器

铁器有两种：`IronNode` 和 `IronNodeArmor`，`IronNodeArmor` 从 `IronNode` 继承。

铁器是从 Body 中复制出来的新节点，默认隐藏；当铁器被磁力菇吸走时，重新复制一份新铁器、位置不变，替原来的那份被吸走。

## 角色本体（植物 / 僵尸）

角色根节点只处理基础属性、动画、body 相关，以及少量与本体高度耦合、不好拆分的特殊功能（土豆类准备、大嘴花攻击、魅惑），
其余能力一律交给组件（攻击 / 攻击检测 / 移动 / 睡眠等基础组件）。

- 继承出来的植物与僵尸**不重写 `_ready()`**：角色根节点按初始化类型分派，子类重写对应的 `init_*()`。
- 角色被 `add_child()` 加进节点树之前，先用 `init_*()` 给行、初始化类型等参数赋值。
- 创建僵尸统一走 `ZombieManager.create_norm_zombie()`。
- 部分主游戏全局数据（植物格子、僵尸行等）放在单例 `MainGameDate` 里，每次加载主游戏场景时由对应子管理器更新赋值。

### 组件信号连接

为避免信号漫天飞，角色及其组件的信号连接按下面的规则走：

- 角色类本身的 `Timer` 的 `timeout` 可以在编辑器里直接连；**组件自身的 Timer 必须连到该组件本体节点**。
- 存在依赖关系的组件可以由父组件连子组件的信号，例：攻击组件（父）← 攻击检测组件（子）。
- 影响角色速度的组件：把该组件挂到角色根节点的属性上，在角色的信号连接函数里连。
- 影响其它组件启用 / 禁用的组件（睡眠、胆小）：在发起方的属性里声明被影响的组件，在角色的信号连接函数里连。
- 除以上情况，其余自定义信号都由角色本体在对应的初始化函数里连接。

**正常出战（Norm）的角色死亡必须走血量组件掉血死亡，禁止直接删除角色。**

## 全局事件总线（EventBus）的订阅回收

`src/core/autoload/event_bus.gd` 常驻不销毁，而订阅者大多是**每关重建**的管理器
（`zombie_manager` / `main_game_manager` / `card_manager` …）。
所以「订阅了不退订」在这里不是小隐患，而是**连接表与元数据表单调膨胀**。

三条约定：

1. **订阅者自己退订**：节点级订阅者在 `_exit_tree()` 里 `EventBus.unsubscribe`。
   现成的写法看 `zombie_boss.gd::_exit_tree()`。
2. **不要在清理僵尸连接时加 `is_instance_valid` 保护** —— 这类连接的对象本来就已释放，
   加了判断它们**永远断不掉**（2026-10-05 修的就是这个逻辑反转，见 [工作记录](../工作记录/2026-10-05_系统排查重要漏洞与修复.md)）。
3. **对象已释放的连接取不到 `instance_id`**，元数据 `_event_metadata` 只能靠「连接表 ↔ 元数据表」对账回收
   （`EventBus._prune_orphan_metadata()`，每次 `push_event` 末尾跑一次）。

> 排查手感：玩久了越来越卡、事件推送变慢，先看 `EventBus.get_subscription_counts()` 里有没有该事件
> 的订阅数随关卡数一起涨。

## 存档范围

当前存档只实现了**植物数据**与**僵尸波次**两部分。

### 存档写入的三条铁律

`src/core/autoload/save_service.gd` 是唯一的存档出口，写它的时候守住三条：

1. **不要「读档 → 改一个键 → 写回」**。
   `_load_json()` 在文件损坏 / JSON 解析失败时返回 `{}`，此时写回的字典**只剩那一个键**，
   金币 / 关卡进度 / 花园 / 已解锁植物会被整体抹掉。
   `save_selected_cards()` 就是这个坑（2026-10-05 修），现在直接调 `save_now()` 写全量。
   要加新字段，往 `save_now()` 的字段表里加一行。
2. **写入必须原子**：`_save_json()` 走「写 `.tmp` → 旧档挪成 `.bak` → rename 替换 → 失败还原 `.bak`」。
   直接 `FileAccess.open(path, WRITE)` 覆盖，写入中途崩溃会留下截断的坏档，再叠加第 1 条就是整档丢失。
3. **读回来的数字一律 `int()` 归一化**。JSON 没有整数类型，枚举读回来是 float，
   `Array.has(int)` / 按枚举取值因此对不上 —— 这个坑已经踩过三次
   （花园工具 `normalize_garden_data_numbers()`、`curr_zombie`、`curr_plant`），
   `selected_cards` 是 2026-10-05 补上的第四个。新增存档字段时照抄 `_normalize_selected_cards()` 的写法。

> `_load_json()` 解析失败时**必须出声**（现在是 `Log.error`）：静默返回 `{}` 会让上层把残档当空档写回。

## 取动画的某一帧当图片（AnimationFrameUtil）

角色 / 物件场景都是「base 节点树 + `AnimationPlayer` + `Animation` 资源」，要在 UI 里摆一个**静态形象**
（商店图标这类）时，不要去 `assets/reanim/` 里挑单张部件图拼 —— 那通常只有零件（蜗牛只有壳、小推车只有车身）。
统一走工具 [`AnimationFrameUtil`](../../../src/core/utils/animation_frame_util.gd)（`src/core/utils/`）：

| 想要什么                | 调哪个                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| 一张图片（`Texture2D`）   | `await AnimationFrameUtil.create_frame_texture(scene, &"动画名", 帧号, 尺寸, 留白)`                       |
| 一个静态形象节点（挂进 2D 场景）  | `AnimationFrameUtil.create_frame_node(scene, &"动画名", 帧号)`                                      |
| 场景里连代码都不想写          | 摆一个 `TextureRect` 挂 [`AnimationFrameIcon`](../../../src/ui/animation_frame_icon.gd)，填 `scene` / `anim_name` / `frame` |

- **动画名**是 `AnimationLibrary` 里的键（`&"PoolCleaner_land_static"` / `&"RoofCleaner"` / `&"Stinky_idle"`），不是资源文件名。
- 取帧靠 `play + seek(时间, true) + stop(true)`：`stop(true)` 才保留姿态，写成 `stop()` 会退回第 0 帧。
- 工具会先**剥离脚本**再定格，所以角色自带的 `_ready` / `_process` 不会在离屏容器里跑起来
  （小推车的 `_process` 会自己往前开，不剥离就会看到它跑掉）。

已经在用的地方：商店的水路 / 屋顶小推车（`goods_pool_cleaner.tscn` / `goods_roof_cleaner.tscn`）、蜗牛
（`GoodsGardenTool.FRAME_ICON_*`）。回归探针：`test/scenarios/probe_animation_frame.gd`。
