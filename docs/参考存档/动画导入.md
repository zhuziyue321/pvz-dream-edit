# 动画导入（四条路线怎么选、怎么走）

> **[面向 AI Agent]** ｜ **触发条件**：要给一只植物 / 僵尸 / 物件接动画；要动 `animation/` 下的资源；要把 PVZ2 的 PAM 素材搬进来；发现「动画能播但不换图」「播完 `animation_finished` 连发」这类问题
> **读完你能**：① 按「素材形态 + 帧数量级」挑出该走哪条路线；② 知道每条路线的命令 / 参数 / 产物落位；③ 知道动画挂进角色后必须满足的 AnimationTree 结构与 `uid` 规矩；④ 知道模组里的动画素材为什么不能 `preload("res://assets/...")`
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：小帧数素材硬塞 Animation 资源 → 几 MB 的 `.tscn` 加导入卡顿；参考项目的轨道整段照搬 → 播放时 `node not found` 刷屏；换路由工具时覆盖掉本仓 `uid` → 引用它的场景全部失效
> **关联**：仓库入口 [../../AGENTS.md](../../AGENTS.md) ｜ 动画目录指针 [../../animation/AGENTS.md](../../animation/AGENTS.md) ｜ 挂点 [创建新角色.md](创建新角色.md) ｜ 模组素材读取 [模组机制.md](模组机制.md) ｜ 层级 [渲染层级.md](渲染层级.md) ｜ 逐次记录 [../工作记录/2026-10-15_PVZ2模组菜问.md](../工作记录/2026-10-15_PVZ2模组菜问.md) · [../工作记录/2026-10-17_潜伏芹菜动画导入.md](../工作记录/2026-10-17_潜伏芹菜动画导入.md)

## 1. 先选路线

判据只有一个：**节点数 × 帧数 = 关键帧总量**。Godot 的 `Animation` 资源每个部件的每条轨道都要逐帧写 key，几十万 key 就不该走资源路线了。

| 素材形态 | 路线 | 产物 | 运行时怎么播 | 先例 |
|---|---|---|---|---|
| 原版 PVZ1 `.reanim` + 逐部件图 | **A** 编辑器插件转换（插件已移出仓库，见 §2） | `animation/**/*.tres`（一段 = 一个 `Animation`） | 每部件一个 `Sprite2D` + `AnimationTree` 状态机 | 全仓现役动画 |
| 别处已烘好的 Godot 动画资源 | **B** 整段移植脚本 | 保留本仓 `uid` 的 `.tres` | 同 A | 僵王博士 23 段 |
| PVZ2 `.PAM`，帧数中等（几千 key 级） | **C** 外部转换器 → 节点树（**已停用**，2026-10-23） | 一个几 MB 的 `*_anim.tscn` | `AnimationPlayer.play()`，不接 Tree | 曾用于菜问 `bonkchoy`，重写时已并入路线 D |
| PVZ2 `.PAM`，帧数上千（几百帧 × 几十部件） | **D** 离线烘 `.pam.bin` | 一个 bin + 一张图集（或 N 张碎图） | `Node2D._draw()` 自己画四边形 | 模组 `pam/` 的五株（`celerystalker` / `firepeashooter` / `peapod` / `bonkchoy` / `goopeashooter`） |

> 数量级体感：菜问 283 帧烘成 4.8 MB `.tscn`（`tools/bake_pvz2_assets.py` 之后同一个 PAM 只占 319 KB `.pam.bin` + 一张图集）；
> 潜伏芹菜 549 帧 × 平均几十个部件，换成动画资源要几十万关键帧 ⇒ 只能走 D。
> **结论：只要帧数过百就一律走 D**，C 那条路只在「段数极少、部件极少」时才划算。

现役家底（2026-10-17 实测）：`animation/` 下 482 个 `.tres` + 15 个 `.res`（`.res` 是二进制存储的同类型资源，内容格式一样），原版拆出的逐部件 PNG 在 `pak/reanim/`（1801 张）。**规模数字的唯一权威口径见 [架构总览.md](../../架构总览.md) §15。**

## 2. 路线 A：原版 reanim → `animation/*.tres`

> **前置：插件已不在本仓库**（2026-10-18 移除 `addons/R2Ga_PVZ/`，`project.godot` 启用项也已摘掉）。
> 需要走这条路时先从 [上游仓库](https://github.com/hsk-dream/PVZ_reanim2godot_animation) 取回 `addons/R2Ga_PVZ/`（含 `PVZ_reanim2godot_animation_x86_x64.exe`）并在「项目设置 → 插件」启用；也可以直接用 exe 命令行跑第 3 步的参数，不开面板。
>
> **2026-10-24 补充：新版 R2Ga 是 C++ 重写版，可执行文件在仓库外** `..\PVZ_reanim2godot_animation_cpp.exe`
> （相对仓库根，即桌面下，**是 exe 文件不是目录**）。用法 `PVZ_reanim2godot_animation_cpp.exe <reanim> <anim res:// 路径> <图片 res:// 路径> -om anim_tres`，
> 其余参数跑 `--help`；旧版 `PVZ_reanim2godot_animation_x86_x64.exe` 的 `<reanim> <动画目录> <图片目录> auto` 只作对照。
>
> **已知坑（2026-10-24 实测，都是转智慧树 51 档踩出来的）**：
> 1. **一次最多约 49 段动画**（实测 48 段正常、50 段 0xC0000005 崩溃），段数多的 reanim 要拆批转再合并命名；
> 2. **产物写在输入文件所在目录**，不是命令行的动画输出目录（实测误往 `pak/reanim/` 写过 `Stinky*.tres`，记得清掉）；
> 3. 缺图（如 `IMAGE_REANIM_TREE_BG` 在 pak 里没有 PNG）或**重名轨道**都会崩/并轨，转前先修净；
> 4. 产物里的 `ext_resource` 路径是 **PascalCase**（`Tree01.png`），pak 里可能是小写带尾下划线（`tree6_.png`），转完要改名对应上。
>
> 完整复现步骤与"单帧定妆"压缩口径见 [禅境花园.md](禅境花园.md) §6.1。

1. 编辑器里打开插件面板：`addons/R2Ga_PVZ`（面板 `ui/main_panel.tscn`，三个路径输入 + 一个运行按钮）。
2. 三个输入：`.reanim` 文件、**动画输出目录**（`res://animation/character/<plant|zombie>/<角色>/`）、**图片输出目录**（`res://pak/reanim/...`）。
3. 点运行 → 插件 `OS.execute` 调 `PVZ_reanim2godot_animation_x86_x64.exe`，参数固定为
   `<reanim 文件> <动画输出目录> <图片输出目录> auto`（见 `ui/main_panel.gd::_on_run_exe`）。
4. 产物：每段动画一个 `.tres`；每部件一张 PNG。
5. **精简轨道**（原版转换产物偏「全」）：
   - 僵尸的胳膊 / 头 `visible` 轨道、植物的眨眼 `visible` 轨道，由代码控制更省事；
   - 推荐做法：把要代码隐藏的节点**挂到一个新的 `Node2D` 父节点下**，代码控父节点的显隐，**动画文件不动**；
   - 真的要删轨道再用 `anim_player_refactor` 插件（它只认英文菜单，见 [项目目录说明.md](项目目录说明.md) 的插件一节）。
6. **动画由工具生成，不建议手改**；确需调整先确认这段 `.tres` 没被多个角色共用。唯一例外是僵王那批（走路线 B 移植的全量版），**不要**用转换工具重新生成覆盖掉。

> **DLC 模组**走的是路线 A，但输出目录在 `mods_builtin/dlc/`（`animation/` + `reanim/` 各一份，保持模组自包含）。
> 转换完之后「怎么接成一株能种的植物」（覆盖 `AnimLib` 的库、量摆放、抛射 / 紫卡、探针）见 [DLC植物导入.md](DLC植物导入.md)，本文不重复。

## 3. 路线 B：整段移植别处已有的动画资源

工具：`tools/port_zomboss_animations.py`（默认**预演**只打印计划，`--apply` 才真写）。

它存在的四个理由，也就是四条硬规则：

| 规则 | 为什么 |
|---|---|
| **保留本仓 `.tres` 的 `uid`，只替换 `[resource]` 主体** | 场景用 `uid://` 引用这些 `.tres`，保 uid ⇒ `.tscn` 一行都不用改 |
| **剔除来源资源里 `Anim_*` 节点的轨道** | 那是来源项目自己的 `AnimationPlayer` 节点（僵王来源有 23 个），本仓场景没有这些节点，照搬会一直报 `node not found` |
| **贴图 `uid` 以贴图自己的 `.import` 为准** | 拿到才写，否则会写回来源项目的旧 uid |
| **缺贴图只报 `[NG]`，绝不退化成别的文件** | 曾经退化成 `Zombie_boss_neck_.png`（黑白蒙版），脖子整块显示成蒙版 —— 这种「能跑但画面错」比报错难查得多 |

- `xxx.jpg` + `xxx_.png` 这种 **原版彩色图 + 黑白蒙版**对，先 `powershell -ExecutionPolicy Bypass -File tools/merge_alpha.ps1 -Name pak/reanim/<不含扩展名> -Out assets_custom/reanim/<名字>.png` 烘成单张 RGBA PNG **放进 `assets_custom/`**，再跑移植脚本（转完的 `ext_resource` 要指向 `assets_custom/`，不能留在 `pak/`）。
- 产出统一 **UTF-8 无 BOM + LF**：Godot 的文本资源解析器不认 BOM。

## 4. 路线 C：PAM → 节点树 + `AnimationPlayer`（帧数中等）

素材来源是仓库**外**的独立转换工程（PAM → Godot），只搬产物，工程本身进 `.gitignore`。

1. 产物形态：扁平节点树 `draw_slot_XX` + 一个 `AnimationPlayer`，轨道路径直接是 `draw_slot_XX:*` ⇒ **自洽**，搬进来不用改节点树。
2. 贴图与 `*_anim.tscn` 放**同一个模组目录**（旧先例 `mods_builtin/pvz2/bonkchoy/`：48 张 png + 4.8 MB tscn，2026-10-23 已废弃，换成路线 D）；`.tscn` 里的贴图用 `res://` 绝对路径引用，同目录的 `.tscn` / 脚本写相对路径也行（相对路径按**场景所在目录**解析，见 §6.3）。
   ⚠️ 模组可以被拷到 `user://mods/`，那时 `.tscn` 里的 `res://` 绝对路径会指到「另一份」——
   跨模组的脚本一律按 `ModManager.get_mod_asset_path()` 在运行时取（先例 `mods_builtin/pvz2/pam_bridge.gd`）。
3. `.import` 不要复制，让 Godot 自己生成。
4. **不接 `AnimationTree`**：产物本来就是「一段动画 = 一个动作」，硬套状态机要再发明一套映射。做法是把 `AnimComponent` 的脚本覆盖成 `component_anim_empty.gd` —— 本体默认挂 `component_anim_norm.gd`，它会去找 `../AnimationTree`，找不到直接报 Null。
5. 位置 / 缩放按贴图**内容包围盒**算（菜问：`position = (-77,-101)`、`scale = 0.45`），别照着原版帧尺寸硬填。
6. 动画结束用 `animation_finished` 接下一段（如出拳 → 待机三段接龙）。

## 5. 路线 D：PAM → `.pam.bin` + 运行时自绘（帧数上千）

**本仓不在运行时解析 `.PAM`**，先离线烘成自包含二进制，运行时零解析开销。

1. 备料：`.PAM` + 图集。**现在的口径**（2026-10-23 起）是解包资源 `..\2代解包资源`：
   - `.PAM` → json 用 `tools/pam2json.py`（纯 Python，可批量；不再需要 PopStudio 手工点）；
   - 图集矩形表：`PROPERTIES/RESOURCES.RTON` 用 `tools/rton2json.py` 转成 JSON（`ax/ay/aw/ah` + `parent`），
     **必须**给 `bake_pam_bin.py --atlas-id`（同名 image 在 768 / 1536 两组里各有一份矩形，数值差一倍）；
   - 一键重烘：`python tools/bake_pvz2_assets.py`（五株全烘，清单在文件头）。贴图有两种形态，按手上素材二选一：
   - **图集**（五株现在都是）：图集矩形表 + 1536 图集 PNG（**绘制尺寸仍取 PAM 名义尺寸**，换分辨率只影响清晰度）；
   - **碎图**（毒液豌豆 `goopeashooter/`）：一个部件一张 PNG，文件名 = PAM `image[].name` 的 `|` 前一半
     （如 `goopeashooter_30x24.png`）。**碎图边长普遍比逻辑尺寸大 1.28 倍左右**（导出自带 padding），
     烘焙时 `src_rect` 取整张 PNG、`draw_size` 仍取 PAM 的 `size` —— 两者搞反画面会整体放大 28%。
2. 烘焙：
   ```
   # 图集模式
   python tools/bake_pam_bin.py --json <x.PAM.pam.json> --resources <RESOURCES*.json> ^
       --atlas <图集.png> --atlas-dst res://.../<角色>_atlas.png ^
       --out res://.../<角色>.pam.bin --texture-path res://.../<角色>_atlas.png

   # 碎图模式（不需要 --resources / --atlas；--texture-res 是写进 bin 的路径前缀）
   python tools/bake_pam_bin.py --json <x.PAM.pam.json> --texture-dir <碎图目录> ^
       --texture-res res://.../<角色> --out res://.../<角色>.pam.bin
   ```
   - `--check-only` 只校验不写盘；脚本会打印 image / 帧 / 状态 / 实例总数、**相邻帧完全相同占比**，
     再**回读自检**（逐帧比 `index/resource/anim_frame/color/xform`；占比 > 50% 直接判失败）。
   - 格式 `PAM2 v1`，与运行时 `mods_builtin/pam/runtime/pam_binary_reader.gd` 一一对应；改格式两边一起改。
   - 两种模式运行时都吃：`_bind_textures` 见只有一张贴图就整张复用，多张就按 `part_name` 精确匹配文件名。
3. 落位：`<角色>.pam.bin` + 贴图（图集一张 / 碎图 N 张）。**不再需要 `*_anim.tscn`**：
   角色场景里放一个**空的 Node2D** 作挂点，由调用方的桥脚本（先例 `mods_builtin/pvz2/pam_bridge.gd`）
   在 `character_ready()` 里挂播放器脚本并塞 `binary_path` / `hidden_parts` / `texture_override`
   （跨模组不能写死 `res://` 路径，理由见 §4 与 [模组机制.md](./模组机制.md) §6.7.0）。
   **捣不清哪个部件是装扮**就离线合成一帧对比（`python tools/render_pam_bin.py --bin ... --texture-dir ... --state idle --frame 5 --out a.png`，
   加 `--hide <部件名>` 再出一张）：装扮名（`custom_01` 这种）在时间轴上**每段都在用**，光看名字和用法判断不出来。
4. 导出：`.bin` **不是资源文件**，`export_filter="all_resources"` 不会带它，必须靠 `export_presets.cfg` 的 `include_filter`（已有 `*.pam.bin`）。
5. 运行时约定（改 `pam_animator.gd` 前必看）：
   - 用 `Node2D._draw()` 按帧画四边形，不建节点树、不生成动画资源；
   - `.bin` 按**路径静态缓存共享**，否则场上 20 株就解析 20 份；
   - PAM 的 `change.transform` 是**部分更新**：6 元 = 完整矩阵，**3 元 = `(旋转弧度, x, y)`**，2 元 = 只改平移；一律当 6 元会打包长度对不上、旋转件被打飞；
   - 非循环状态播完要**只发一次** `animation_finished`（时间轴判据 + `_finished_emitted` 幂等），别用「前后帧号相等」判结束（那样每帧都发）；
   - 贴图按 `part_name` 精确匹配，匹配不上就 `Log.error` + 不画，**不拿别的图顶上**。
6. **烘焙侧：每帧快照必须是拷贝**（踩过的坑，见 §8 第一行）。`append/remove/change` 压平时间轴时，
   若把 `active` 里那个实例 dict 直接放进帧列表，后续帧的 `change` 会**就地改掉历史帧**，
   烘出来的 bin 相邻帧大量重复 —— 运行时帧号照走、画面却冻住几秒再突然跳一下。
   判据只看工具打印的「相邻帧完全相同占比」：正常动画是个位数百分比，接近 100% 就是这个坑
   （`tools/bake_pam_bin.py` 已改成 `snapshot()` 拷贝并把这个比例纳入自检；参考工程
   `tmp/Core/pam_instance_state.gd` 的 `snapshot()` 本来就是拷贝）。

## 6. 四条路线共同的收尾

1. **`uid` 与路径**：`res://` 绝对路径 + 带 `.uid` 一起移动 / 改名（[../项目规范.md](../项目规范.md)）。
2. **模组里的动画素材**：贴图与脚本 / 场景放同一个模组目录（模组自包含，先例 `mods_builtin/pvz2/bonkchoy/`）；脚本里取自己的贴图走 `ModManager.load_mod_asset(mod_id, rel_path)`，拼路径前缀走 `ModManager.get_mod_root(mod_id)`。原因：模组有两个加载根（`user://mods/` 优先，`res://mods_builtin/` 兜底），`user://` 下的图片**不走引擎导入管线**，`load()` 拿不到 Texture2D，`load_mod_asset()` 会退回 `Image.load_from_file()` 并按路径缓存。
3. **`.tscn` 的 `ext_resource` 路径**：相对路径合法，但按**场景所在目录**解析 —— 跨目录引用写 `res://` 绝对路径最省事。曾经把 `pam/pam_animator.gd` 写进 `celerystalker/` 下的场景，被解析成 `celerystalker/pam/...`，直接 `referenced non-existent resource`。
4. **临时素材目录加 `.gdignore`**：`tmp/` 这种放上万个 PVZ2 素材的目录会让编辑器反复导入（要重新看见素材就删掉该文件）。
5. **探针**：先过 `test/check_scripts.ps1`（编译门禁），再 `test/run_autopilot.ps1 -Scenario <probe_xxx> -Windowed`。现成可抄的：`probe_pvz2_mod`（路线 C）、`probe_pvz2_celery_anim`（路线 D：数据 / 贴图绑定 / 状态帧数 / 装扮 / 循环与单次 / 缓存共享）、`probe_animation_frame`（取帧）。
6. **画面只能开窗口看**：比例、站位原点、图层（会不会压住血条 / 卡片冷却遮罩）。

## 7. 附带：取动画某一帧当图片（UI 图标）

动画不是导入，但常和导入一起做（商店图标、图鉴头像）。

- `src/core/utils/animation_frame_util.gd`（`AnimationFrameUtil`）：`create_frame_texture(scene, anim_name, frame, size, margin)`（异步离屏渲染）/ `create_frame_node(scene, anim_name, frame)`（同步定格）。
- `src/ui/animation_frame_icon.gd`（`AnimationFrameIcon extends TextureRect`）：场景里摆好节点、填三个导出量，零代码。
- 三个必须：定格用 `play + seek(t, true) + stop(true)`（写成 `stop()` 会退回第 0 帧）；实例化后先递归 `set_script(null)`（否则角色的 `_process` / `_ready` 会在离屏容器里跑起来）；seek 前**摘掉 `AnimationTree`**（它每帧覆盖姿态）。

## 8. 常见故障对照

| 症状 | 多半是 |
|---|---|
| 动画**整段冻住几秒、零件一换又突然跳一下**（帧号在走、画面不动） | 烘焙时帧快照没拷贝（`flatten_frames` 把 `active` 的实例 dict 直接放进帧列表，后续 `change` 改写了历史帧）。看工具打印的「相邻帧完全相同占比」，正常个位数、这个坑接近 100% |
| 播放时刷 `node not found: Anim_xxx` | 路线 B 没剔除来源项目的 `Anim_*` 节点轨道 |
| 动画「只动位置、不换图」 | 用了精简版轨道（只有 `visible` + 变换），缺 `texture` / `self_modulate` |
| `AnimComponentNorm` 报 Warn 且动画不同步 | `AnimationTree` 不是「树根混合树 + `TimeScale` + `StateMachine`」结构（见 `component_anim_norm.gd` 顶部注释） |
| `AnimationPlayer` 找不到 `../AnimationTree` 为 Null | 路线 C 没把 `AnimComponent` 换成 `component_anim_empty.gd` |
| `animation_finished` 每帧连发 | 用「前后帧号相等」判结束；改成时间轴判据 + 幂等标志 |
| 导出后 `.pam.bin` 缺失 | 没进 `include_filter` |
| 贴图整块变黑白蒙版 | 用了 `xxx_.png` 蒙版而不是合成后的 `xxx.png`（先 `merge_alpha.ps1`） |
| `.tres` 解析失败 / 打开报错 | 文件被写成了带 BOM 的 UTF-8 |
| 场上多株同角色内存暴涨 | `.bin` 没做按路径静态缓存 |
| 整株不画、`Log` 刷「贴图不存在」 | bin 里写的是烘焙机的临时路径（`res://texture/...` 那种）—— 搬进模组后要**重烘一遍**，别只拷 bin |
