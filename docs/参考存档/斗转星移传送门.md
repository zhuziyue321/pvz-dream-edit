## 一、开关与组成

| 项 | 位置 | 说明 |

| 管理器 | `src/managers/portal_manager.gd`（`PortalManager`） | 挂在主场景 `Manager` 下（`main_game_base.tscn`，已设 `unique_name_in_owner`，主游戏用 `%PortalManager` 取） |

| 提示条 | `TutorialAdviceUI.ensure_level_hint(main_game)` | 原版 `DisplayAdviceAgain("[ADVICE_PORTAL_RELOCATING]")`，文案「传送门重置中……」 |

门贴图分辨率不一，按目标高度归一（`DOOR_HEIGHT = 120`），不用逐张调 scale。

## 二、关卡配置（原版是**传送带关**，不是选卡关）

原版 `Challenge::HasConveyorBeltSeedBank` 对本关返回 true，传送带卡池与权重写死在 `Challenge.cpp:1564-1579`：

| 植物 | 权重 |
|---|---|
| 豌豆射手 | 25 |
| 双发射手 | 20 |
| 火炬树桩 | 10 |
| 仙人掌 | 15 |
| 坚果 | 15 |
| 樱桃炸弹 | 15 |

- 传送带出卡间隔 = 普通传送带的 **1.5 倍（更慢）**（`aConveyorSpeedMultiplier = 1.5`）。
  ⚠️ 方向陷阱：原版这个数是「**间隔**倍数」，仓库 `create_new_card_speed` 是「**速度**倍率」→ 取倒数 `1.0 / 1.5`。
- 起始阳光 50、夜晚场地（仓库 `is_day = false` 即夜晚，蘑菇不睡觉）、不天降阳光、出怪倍率 ×2、首波 2 秒（`mZombieCountDown = 200` tick）。
- 出怪白名单：普 / 铁桶 / 橄榄球 / 气球（`Challenge.cpp:2338-2344`）。

## 三、摆门规则（原版固定位置，不随机）

原版 `Challenge::PortalStart` 写死四扇门（列, 行）：

| 门 | 列 | 行 |
|---|---|---|
| 方形 | 2 | 0（最上一行） |
| 方形 | 9 | 1 |
| 圆形 | 9 | 3 |
| 圆形 | 2 | 4（最下一行） |

- **配对 = 同类型的另一扇**（原版 `GetOtherPortal` 按类型配对，不是按位置）。
- 第 10 列（`gridX = 9`）在仓库地图里只有 9 列 → 当作「草坪右缘的虚拟列」，
  中心取 `col_x[last] + col_width[last]`（原版该列中心 = 760，仓库 = 764，差 4px）。
- 绘制锚点（原版 `GridItem::OpenPortal`）：圆门 (格中心-46, 行地面-65)、方门 (格中心-50, 行地面-40)。
- `z_index = lane * 50 + 20`（插在植物行 `lane*50+10` 与僵尸行 `lane*50+30` 之间）。

## 四、换位规则

- **首次 90 秒、之后每 60 秒**（原版 `mChallengeStateCounter = 9000` tick，换位后重置 6000 tick）。
- 每次**只动一扇**门：在四扇打开的门里等概率随机挑一扇。
- 新落点候选（原版 `Challenge::MoveAPortal`）：10 列 × N 行里
  ① 该格没有打开的门 ② **与搭档门的列、行都不同**（原版是 `&&` 不是 `||`）→ 再均匀随机挑一个。
- 表现：旧门淡出消失（`Portal.close_portal`）、新门在目标格淡入（`Portal.open_portal`），开门播传送门音效。
- 换位前 5 秒弹提示条「传送门重置中……」（原版计数剩 500 tick 时 `DisplayAdviceAgain`）。
- 关卡结束 / 奖杯落下后不再换位（原版 `HasLevelAwardDropped`）。

## 五、传送判定与配套逻辑

原版 `Challenge::UpdatePortal` 每物理帧对**每扇打开的门**遍历全部僵尸 / 子弹 / 推车，判「**x 落在窗口里 + 行号一致**」。
原版的三套窗口不一样，**别统一**（换算成「相对格中心」的偏移）：

| 对象 | 窗口中心 | 半宽 | 原版写法 |
|---|---|---|---|
| 僵尸 | 格中心 **-15** | 45 | `gridX*80+25` |
| 子弹（仅直线） | 格中心 **+15** | 40 | `gridX*80+55` |
| 小推车（已启动） | 格中心 **-15** | 20 | `gridX*80+25`，推车参考点 `mPosX+45` |

各自传送时要配套做的事：

| 对象 | 传送时要做的事 | 漏做的后果 |
|---|---|---|
| 僵尸 | `lane = 出口行` → `curr_zombie_row_type` 更新 → `signal_lane_update.emit()`（僵尸管理器挪 `all_zombies_2d`）→ `reparent(新行节点)` → 落点 = **出口格左缘**（原版 `mX = otherGridX*80 - diffX`，仓库僵尸原点即受击框中心，diffX≈0）、y = 新行地面 | 不发 `signal_lane_update` 会留下悬空引用；y 不对齐会悬空/入土 |
| 子弹 | `lane = 出口行` → `z_index = lane*50+45` → 落点 = **出口格中心 +20**、y 平移行差（原版 `mY += 行差*100`，仓库按地图实际行距算）→ `start_pos = position`（重置最大射程基准） | 不重置 `start_pos` 会被当「超过最大射程」立刻销毁 |
| 小推车 | `lane = 出口行` → `z_index = lane*50+40` → 落点 = 出口门 x（格中心-15）、y = 新行地面 | 推车留在旧行会顶错方向 |

- **方向不变**：僵尸的 `direction_x_root`、子弹的 `direction` 都不动，走出出口门后继续原方向走 / 飞。
- **出口记忆**（原版 `mLastPortalX`）：记下「从哪一列的门出来的」，同一列的门不会再把它吸回去，换别的列仍然能传。
- **只有直线子弹过门**（原版只传 `MOTION_STRAIGHT`）：仓库对应 `BulletLinear000Base`；抛物线 / 追踪子弹不过门。
- **被魅惑的僵尸不传**（与原版有差，见第七节）：`signal_lane_update` 会把魅惑僵尸挪回 `all_zombies_2d`，
  而魅惑僵尸死亡时只清 `all_zombies_be_hypno`，会留下悬空引用。

## 六、出怪行权重与隔门索敌

| 机制 | 原版 | 仓库落点 |
|---|---|---|
| 每行出怪权重 | `Challenge::PortalCombatRowSpawnWeight`：离小推车太近（门链距离 < 5）→ **0.01**；这行有门 → **1.0**；其它行 → **0.2** | `PortalManager.get_row_spawn_weights()` → 选行处传入（`zm_zombie_wave_create_manager.gd` 的 `_get_row_spawn_weights()`，非本关返回空数组 = 默认权重） |
| 隔门索敌 | `Challenge::CanTargetZombieWithPortals`：豌豆 / 双发 / 仙人掌能隔着传送门打到**门另一行**的僵尸（最多穿 3 道门） | `PortalManager.find_target_through_portal()` + `DetectComponent.allow_target_through_portal`（植物场景里打开）；检测组件定时重查（僵尸从门里出来不会触发 `area_entered`） |

隔门索敌的判定（原版口径）：从植物所在格出发，向右找本行最近的门；该门搭档所在行、搭档门右边到下一个门（或草坪右缘）之间的僵尸，
就是这株植物能打到的目标。**子弹自己会穿门**，所以只要植物肯开火，子弹就能打到门那一边。

## 七、与原版的差异（明确记录）

1. **魅惑僵尸不过门**：原版不区分，魅惑僵尸也会被传送；仓库因为 `all_zombies_2d` / `all_zombies_be_hypno`
   的清理不对称（会留悬空引用）而排除，传送魅惑僵尸的风险大于收益。
2. **配对时机**：原版 `GetOtherPortal` 只看「类型相同且没死」，换位后那约 1 秒里新门会先配上**正在消失的旧门**
   （原版的一个小 bug）。仓库按意图修正为「配对 = 另一扇**打开**的同型门」。
3. **小推车落点的 y**：原版 `mPosY` 写的是相对位移（`(出口行-本行)*100`），仓库改成新行地面的绝对 y。
4. **门的动画**：原版用 `Portal_Square.reanim` / `Portal_Circle.reanim` 的 `anim_appear` / `anim_pulse` / `anim_disappear`，
   仓库用 Tween 近似（方门交替闪烁、圆门中心慢转 + 呼吸）；`pak/reanim/` 里**有**这两个 reanim，要还原可走动画转换流程。
5. **传送带间隔**：仓库底数是 5 秒（原版 4 秒），只保证「本关 = 普通传送带 × 1.5」的比例一致，绝对时长有差。
