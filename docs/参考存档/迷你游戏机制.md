## 1. 拉霸（第 3 关，Slot Machine）

关卡脚本 `src/levels/mode_minigame/minigame_03_slot_machine.gd`，UI `src/levels/mode_minigame/minigame_03_slot_machine_ui.gd`，进度条数据源 `src/levels/mode_minigame/minigame_03_slot_machine_progress_provider.gd`（三者都是本关专属，跟着关卡脚本同目录）。

**口径 = 原版**（2026-10-24 按本机原版 C++ 参照重做；之前那版是自创玩法：累计收集 + 中间大面板 + 均等随机，已作废）：

- **机器排在屏幕左上角**（原版 `SeedBank::Draw` / `Board::GetSeedPacketPositionX` / `Challenge::SlotMachineGetHandleRect`）：
  阳光银行底图 `pak/images/SunBank.png` 画在 (0,0)、阳光数值黑字画在 (34,78) 居中；
  **3 个种子包当转轮**（`pak/images/seeds.png` 50x70 一帧一个，x = index*59+247、y = 8），初始 = 向日葵 / 豌豆 / 寒冰豆；
  覆盖层 `pak/images/SlotMachine_Overlay.png` 画在 (189,-2)，盖在转轮上（它自带三个透明窗口洞，位置 62 / 121 / 180 × 19，各 42x42）；
  拉杆三块 `pak/reanim/SlotMachine_base/shaft/ball.png` 按 reanim 轨摆（reanim 本仓没转成场景 → 用贴图 + Tween 复现 pull/return，先例 `src/items/mini_game/portal.gd`），拉杆点热区 (473,0,55,80)。
- **没有僵尸、没有选卡、没有卡槽**：`monster_mode = Null`、`can_choosed_card = false`、`card_mode = E_CardMode.Null`、`is_shovel = false`、`is_lawn_mover = false`。
- **本金 50 阳光**（原版 `Board::InitLevel` 的 else 分支）；**过关看「当前余额」不是「累计收集」**：余额（0~2000 截断）到 2000 判胜掉奖杯（原版 `Challenge::UpdateSlotMachine`）。
- **一次拉杆 25 阳光**（原版 `TakeSunMoney(25)`）；三个转轮**同时**开转，各 300 帧，每秒翻转 5 → 2 次（曲线域 400：`flips = 6 - 4*(400-countdown)/400`），全部停稳后结算。
- **符号权重**（原版 `SeedPacket::PickNextSlotMachineSeed`）：向日葵 / 豌豆 / 寒冰豆 / 坚果 / 太阳各 100、钻石 30；**豌豆权重随场上豌豆数 200→100**（满 5 株取 100，场上豌豆越多越不容易再出豌豆）；**第 3 个转轮**与前两轮「即将出现」的符号一致时权重 x1.5（钻石除外）。
- **结算奖励**（原版 `Challenge::UpdateSlotMachine`）：两个相同 = 1 钻石（=100 阳光）/ 4 颗太阳（=100）/ 1 株免费植物；三个相同 = 5 钻石（=500）/ 20 颗太阳（=500）/ 3 株免费植物。
  太阳币走本体 `SunSpawner.pop_up`；钻石币是 UI 层自绘的掉落物（`pak/reanim/Diamond.png`），点它走 `add_sun_value` 入账；免费植物 = `CardManager.create_temp_card` 掉一张临时卡（25 秒后消失），玩家点起来自己找地方种。
- **阳光自己管**：`card_mode = Null` 时 `CardSlotBattle` 不订阅 `add_sun_value`，UI 必须自己订阅，否则向日葵产的阳光点了会"消失"。
- **不出怪也要 `await mg.main_game_start()`**：它同时负责切主游戏 BGM 与把阶段推进到 MAIN_GAME，少了这一句整关停在选卡曲上。
- **提示走本体提示条**（`TutorialAdviceUI.ensure_level_hint`）：开场「拉动手柄就有新的种子！」→ 结果提示（6 种文案）→ 待机「收集2000点阳光即可过关」/「再拉一次！」（阳光 1900 起发「就要成功了！」）。
- **进度条**：本关专属数据源 `SlotMachineProgressProvider`（进度 = 阳光 / 2000），在 `create_progress_provider()` 返回；**UI 判胜后会被关卡流程收走，所以数据源要缓存最后读到的阳光**（过关那一下进度条要显示 100%，不能跟着 UI 归零）。
- UI 是脚本 `_ready()` 现场创建的 `Control/TextureRect/Label/Button` 组合，**没有 `.tscn`**（省 UID 与场景引用维护）。

坑：
- `Button` **不支持 `label_settings`**（运行时拒绝）→ 拉杆热区做成透明 `Button`（`StyleBoxEmpty` 覆盖各态），数字标签单独用 `Label`。
- 盖在按钮上的 `Label` 默认**拦截点击** → 必须设 `mouse_filter = Control.MOUSE_FILTER_IGNORE`（本关所有装饰件都设 IGNORE：机器区域不挡草坪点击，与原版一致）。
- 转轮是「当前包 + 下一个包」两块贴图上下叠着滚（`position.y = -70*进度` 与 `+70`）；**停稳后要把「下一个包」藏起来**（原版倒计时 <= 0 时只画当前包）。
- 倒计时走完但这一格没翻完时**要再给一帧**（原版 `SeedPacket::Update`：`else if (mSlotMachineCountDown == 0) mSlotMachineCountDown = 1;`），否则会停在半格。
- 存档键沿用改名前的 `102_1_0021`，**不跟着文件名序号改**（改了会让玩家已通关记录错位）。
- 奖杯（`mgm_reward_manager.gd`）没被点开、过期自动消失时，`gain_loot` 里的 `wait_unlock_drop_closed(new_drop)` 会拿**已释放对象**去调 → 报 "previously freed" 并把结算一起带崩（已加 `is_instance_valid` 兜底）。

## 2. 种子雨（第 4 关，Seed Rain）

本体侧只留两个**不带玩法判断**的通用口子，`card_manager.gd` 里搜不到任何 `is_seed_rain`：

- `card_manager.add_card_front_node(node)` —— 往卡片前景层挂节点（临时卡片本来就挂这一层）。
- `create_temp_card(para)` —— 造卡。

关卡脚本 `minigame_04_seed_rain.gd` 自己 `preload` 现成的 `card_slot_seed_rain.tscn`（出卡概率 / 固定顺序 / 下落 tween 本来就在这卡槽里，由关卡数据字段喂参），在 `run_flow()` 里开战前 start、打完 pause；卡槽用 `is_instance_valid` 兜底只建一次（多轮关卡 `run_flow()` 会重跑）。

- **起停挂在 `run_flow()` 的时序上，不要用 EventBus 订阅进度** —— 关卡脚本是 `Resource`（不是 Node），订阅了没有可靠退订时机，换关后回调会残留并污染别的关卡。
- **创建时机放 `run_flow()` 而不是 `init_level_items()`** —— 后者给的 `item_root` 在背景层且 `process_mode = ALWAYS`（树暂停时照样跑），种子卡会在玩家暂停 / 切轮摆场时继续掉；卡片前景层是 `INHERIT`，语义才对。
- 覆写 `run_flow()` 时形参一律写 `mg`：改叫 `_mg` 会遮蔽基类 `LevelScriptBase` 的同名字段（`SHADOWED_VARIABLE_BASE_CLASS`），
  照抄基类的下划线写法又会写出未定义的 `mg`；本关用不上 `mg` 时**签名照抄 + 加一行 `@warning_ignore("unused_parameter")`**
  按掉 Godot 的 `UNUSED_PARAMETER`（模板见 `src/levels/mode_adventure/adventure_01_03.gd` 的 `run_flow` 上方两行注释）。

## 3. 隐形战争（第 6 关，Invisi-ghoul）

**渲染侧（这部分的坑是通用的，不只这一关）**：

- 隐形**必须合成进 `body.modulate`**：`animation/character/**` 里每个身体部件都带 `self_modulate` 轨道、逐帧写回 `Color(1,1,1,1)`，改 `self_modulate` 会被动画盖掉（第一版就是这么写的，跑起来必然失效）。`BodyCharacter` 已有 `E_ChangeColors` 合成机制，加一个 `Invisible` 枚举项即可，还能与受击闪白 / 冰冻染色相乘互不覆盖。
- **影子一起隐**（线索清单里没有影子，留着等于送答案）。
- 现形钩子：`Character000Base.be_ice_freeze()` / `_on_ice_freeze_timer_timeout()`（冰冻 / 解冻）、`ZombieButterUtil.be_butter()` / `on_butter_timer_timeout()`（黄油）。**只有"冰冻"和"黄油"现形，冰冻减速不现形**。
- 冰冻 + 黄油叠加时，若解冻先到会把还在黄油定身中的僵尸重新隐形 → 解冻回调里先看黄油计时器还在不在走。
- 掉落防具 / 死亡爆炸粒子 / 入水水花 / 洗冰车冰道**不用特殊处理**：它们本来就 `reparent` 出僵尸本体（`ZombieDropBase.acitvate_it()` → 僵尸行；`SwimBoxComponent.appear_splash()`；`IceRoad` → 背景层），自动不受隐形影响。代价：挂在贴图下的粒子（洗冰车受损烟雾）会跟着隐形，可接受。

**开关怎么喂进来（已改过一版）**：
早期加的是 `ResourceLevelData.is_invisible_zombie` 字段 + `ZombieManager.create_norm_zombie` 里一行赋值 —— **已删除**（§1-8 一关专属机制不进本体）。现在关卡脚本覆写 `get_zombie_init_para_extra()` 返回 `{ E_ZInitAttr.IsInvisible: true }`，管理器只做 `zombie_init_para.merge(game_para.get_zombie_init_para_extra(), true)`。

配套：`is_day = false`（底图仍是白天泳池，但要让冰蘑菇落地就能用；`is_day` 在仓库里只影响蘑菇睡觉）。

**开局几波最下行不出怪（2026-10-24 补齐）**：原版 `Board.cpp` 的条件是
`INVISIGHOUL && mCurrentWave <= 3 && aRow == 5` → 该行权重归零。本作**不**在波次管理器里写「隐形战争」分支，
走通用能力：关卡脚本覆写 `before_wave_spawn()` → `create_manager.set_banned_spawn_rows([最下行])`，
波次过了就 `clear_banned_spawn_rows()`；选行系统用 `banned_lanes` 把权重归零，**兜底选行也会避开**
（只有所有可出怪行都被禁时才忽略，避免整波停刷）。探针：`probe_invisi_ghoul_rows`。

> 注意：原版 C++ 注释写「前 3 波」，但条件是 `<= 3`（0 起算 = 第 1~4 波）。按代码实现。

## 4. 僵尸快跑（第 14 关）—— 关卡级全场变速

`ResourceLevelData` 上有两个**通用**恒定倍率字段：`speed_factor_zombie` / `speed_factor_plant`（本关都写 2.0），走 `Character000Base.update_speed_factor(值, E_Influence_Speed_Factor.LevelSpeed)` 这套乘法字典（冰冻减速 / 黄油定身 / 大蒜换行都是这么写的），下发动作收在 `ResourceLevelData.apply_speed_factor_to_zombie/plant()`，倍率 1.0 时直接 return（不给默认关卡白 emit 一次信号）。

- **关键前提：普僵的速度烤在动画里。** `MoveComponent.E_MoveMode.Ground` 靠 `Body/BodyCorrect/_ground` 这个 Sprite2D 在动画里的 x 位移反向推 `position.x`（`Speed` 模式才是数值驱动）⇒ 想让普僵真跑起来**只能改动画播放速度**，也就是 `update_speed_factor`（它顺带把 `parameters/TimeScale/scale` 乘上倍率）。`update_only_move_speed()` 对普僵无效。
- **动画与移速要分开时用 `MoveComponent.ground_speed_scale`**（2026-10-24 新增，默认 1.0）：它只放大 / 缩小 `_ground` 推出来的**位移**，不动动画播放（吃植物动画不会跟着变快）。给「原版里移动比动画快得多」的角色用 —— 目前只有读报僵尸暴走（`ArmorComponentNewspaper`，1.5 倍 → 实测普僵的 3.07 倍，对齐原版 `0.90 : 0.30`）。速度实测见 `probe_zombie_speed`。
- 下发点只有两处，且**都必须在 `add_child` 之后**（移动 / 攻击组件在 `_ready()` 里才连 `signal_update_speed`）：`ZombieManager.create_norm_zombie()` 与 `PlantCell.create_plant()`。
- **不要碰 `speed_zombie_*`**（那是锤僵尸关每波递增的专用字段）。
- 别用 `Engine.time_scale`（会连 UI / 音效 / 相机一起加速）。
- 植物射速：`AttackComponentBulletBase.owner_update_speed()` 里「折算剩余时间」与「更新 `wait_time`」要拆开，**`wait_time` 无条件更新** —— 关卡倍率是在植物刚进场、还没开始攻击时下发的，旧的"只在计时器跑着时才改"会让倍率被整个漏掉。

## 5. 坚不可摧（第 16 关，Last Stand）—— 布阵阶段与禁选卡

**布阵阶段是一个时间轴事件**，不是本体开关：`src/levels/core/timeline_event/level_timeline_event_wait_battle_start.gd`

1. `await main_game.allow_lawn_operation()` —— 它已经是「推进到 MAIN_GAME + 出战卡槽进场 + 不出怪 + 不天降阳光」，正是布阵阶段需要的（原本是教程用的）。
2. 挂按钮 `lets_rock_button.tscn`（`SceneRegistry.LETS_ROCK_BUTTON`，文案取 `lawn_strings` 的 `[LETS_ROCK_BUTTON]`）。
3. **不要用 `await button.pressed`** —— 关卡中途被销毁时那个 await 永远不返回（协程泄漏）；改成按钮自带 `player_pressed` 标志（**不能叫 `is_pressed`**，会遮住 `BaseButton` 同名方法报 SHADOWED_VARIABLE_BASE_CLASS）+ 基类 `wait_until()` 轮询。

**禁选卡**：关卡数据字段 `banned_plant_types_in_choose_card`（`level_data.gd:250`），由 `CardSlotNorm.init_card_slot_norm()` 转调 `CardSlotCandidate.set_plant_card_banned()`，普通页与模仿者页各一份容器。
表现是**整张卡不出现**而不是置灰：`Card.set_card_disable()` 的灰化只在 MAIN_GAME 阶段判 `is_can_click`，选卡阶段点击不检查它。

**每波补阳光**写在关卡脚本里（只有这一关要）：挂 `zombie_wave_manager.signal_wave_refresh`，用 `curr_wave > 0` 跳过开局那一波（5000 是本钱）。

坑：`max_wave` 是「开战」事件才写进关卡数据的，布阵阶段读到的还是默认值 30 —— 断言总波数要挪到点完按钮之后。

## 6. 蹦蹦舞会（第 19 关，Pogo Party）

- 出怪表**只写 `Z019Pogo`**（原版是 "purely Pogo Zombies outside of flag waves"）。想让某种僵尸占绝对多数时，**先试收窄 `zombie_refresh_types`**，不要为它去改 `ResourceLevelData` / `ZombieWaveCreateManager` 加权重覆盖。
- `zombie_multy = 4` 是刻意的：波次战力上限 = `int(波数/3 + 1) * zombie_multy`，而蹦蹦僵尸战力恰好是 **4** ⇒ 非旗帜波的战力预算刚好是整数只蹦蹦，凑不出余额去补普僵，真能"一只别的都没有"。**挑 `zombie_multy` 时看能不能让「战力预算 ÷ 该僵尸战力」整除。**
  ⚠️ 这是**全仓唯一一处**刻意偏离原版倍率的关（原版 POGO_PARTY 实际 ×1）—— 其余关卡一律按 [僵尸波次.md](僵尸波次.md) 「模式倍率」表填，由 `probe_wave_points` 锁死；想加料先看那张表，别在这里发明新倍率。
- `game_BGM` 改 `Roof`（本关是仅有的两个播屋顶曲的小游戏之一）、开战时传 `first_wave_time = 55.0`、删掉误配的 `is_bungi`。
- **旗帜波不要写严格断言**：`get_curr_wave_zombie_list()` 在战力余额已经买不起出怪表里任何一只时会用普僵补齐余数（原版从空权重表落到 0 号普僵，所有关卡都这样），严格断言只留给非旗帜波；大波本身还固定掺 `min(波数/3+1, 8)` 只普僵（见 [僵尸波次.md](僵尸波次.md) 的「一波怎么凑出来」）。

## 7. 通用：波次构成怎么验

出怪表改完别真刷波等几十秒，直接调纯列表计算逐波核对：

```gdscript
zombie_wave_create_manager.create_curr_wave_zombie_list(wave, is_big)
```

它是纯计算、秒出结果、不依赖随机（`probe_pogo_party` / `probe_last_stand` 就是这么写的）。
