# 关卡进度条 —— 控制器 + 数据源

> **[面向 AI Agent]** ｜ **触发条件**：要改关卡右下角那条进度条（`FlagProgressBar`）的**显示口径** —— 让它代表别的东西，或新增一种口径
> **读完你能**：知道进度条由谁驱动、换口径该改哪个文件、僵王关为什么显示的是血量
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：可能在出怪侧（波次管理器 / 出怪器）里直接写进度条，改动扩散到不该碰的地方
> **关联**：[僵尸波次.md](僵尸波次.md) ｜ [特殊关卡.md](特殊关卡.md)（僵王战）｜ 硬约束 [../项目规范.md](../项目规范.md) §1-8

---

## 1. 一句话结构

```
LevelProgressBarController（常驻 main_game_base.tscn，%LevelProgressBarController）
        │  每帧：问进度 → 写 FlagProgressBar → 问旗帜
        └── LevelProgressProvider（数据源：进度条代表什么）
                ├── LevelProgressBattleProvider  默认：战斗进度（波次）
                ├── ZombossProgressProvider      僵王关：僵王血量百分比
                └── 关卡脚本自己给的（覆写 LevelScriptBase.create_progress_provider()）
                        ├── BeghouledProgressProvider       僵尸迷阵：配对次数 / 75
                        ├── ZombiquariumProgressProvider    僵尸水族馆：阳光 / 1000
                        └── SeeingStarsProgressProvider     观星：已种轮廓点 / 轮廓点总数
```

**进度条节点只认控制器一个写方**。出怪侧（`ZombieWaveManager` / 关卡注入的 `ZombieWaveSourceBase`）
只负责**算**自己的战斗进度，由 `ZombieManager` 的「波次进度」区统一转发给数据源，谁都不碰 UI。

## 2. 三个文件各管什么

| 文件 | 职责 |
| --- | --- |
| `src/ui/main_game_ui/ui_level_progress_provider.gd` | 数据源基类：每帧被问「进度多少 / 显不显示 / 几面旗 / 要不要升旗 / 要不要收旗」 |
| `src/ui/main_game_ui/ui_level_progress_battle_provider.gd` | 默认口径：转发 `ZombieManager.get_battle_progress()` 等五个查询 |
| `src/ui/main_game_ui/ui_level_progress_bar_controller.gd` | 挑数据源、每帧写进度条、建 / 收旗帜、关卡整体开关 `set_enabled()` |
| `src/ui/main_game_ui/ui_flag_progress_bar.gd` | 纯显示：真实值 `real_value` + 追赶值 `chase_value`（每秒 10 单位平滑） |

数据源是 `RefCounted`，`controller` 字段在 `set_provider()` 时注入，数据源靠它拿 `main_game`。

## 3. 默认口径：战斗进度

出怪侧各算各的（百分比本体在它们自己身上，数据源每帧读一次）：

| 出怪侧 | 进度怎么算 |
| --- | --- |
| `ZombieWaveManager` | `battle_progress` = 本波起点（`curr_wave % 每轮波数 × 每波占比`）+ 本波每秒推进量（定时器每 1 秒累加） |
| `HammerZombieManager`（锤僵尸出怪器） | `battle_progress` = 已出场小组数 × 每小组占比 |

控制器每帧从 `ZombieManager` 取（内部按 `wave_source != null` 转发给出怪器）：

```gdscript
get_battle_progress()          ## 0~100
is_battle_started()            ## 开第一波之前进度条不显示
get_battle_flag_num()          ## 旗帜数 = max_wave_one_round / 10（0 = 不画旗）
take_battle_flag_raise_index() ## 取走「本帧要升旗」的下标，取完清掉
take_battle_flag_reset()       ## 取走「全部收旗」（多轮游戏切新一轮）
```

- **旗帜**：数据源报的数量变了，控制器才 `create_flag(n)` 重建一次；`n = 0` 等价于清掉上一批（僵王战就是这样）。
  所以 `apply_max_wave()` 改波数后旗帜会自动跟着变，出怪侧不用再通知 UI。
- **多轮游戏**：出怪侧把进度归零 + 置一次「收旗」请求，控制器读到就 `down_all_flags()`。

## 4. 换口径：关卡脚本一句话

`LevelScriptBase` 上有一个可覆写的钩子，返回一个数据源实例即可（`main_game.init_manager()` 时装上）：

```gdscript
func create_progress_provider() -> LevelProgressProvider:
	return MyProvider.new()      ## 返回 null（默认）= 走下面的自动挑选
```

运行期也能换（关卡流程打到一半换口径）：

```gdscript
mg.level_progress_controller.set_provider(MyProvider.new())
```

自动挑选顺序（`LevelProgressBarController._pick_provider()`）：

1. 关卡脚本 `create_progress_provider()` 给的非空实例；
2. 关卡数据 `has_boss()` → `ZombossProgressProvider`（僵王战）；
3. 其它 → `LevelProgressBattleProvider`。

> 一关专属的口径写在关卡脚本里（硬约束 §1-8）；被 ≥2~3 关复用的口径才上浮成本体里的数据源类
> （`ZombossProgressProvider` 就是因为冒险 5-10 与迷你游戏 20 都用）。

## 5. 僵王关：血量百分比

`ZombossProgressProvider`（`src/levels/core/zomboss/`，与僵王其它代码同侧）每帧读
`ZombieManager.get_living_bosses()[0].hp_component`：`curr_hp / max_hp × 100`。

- 满血 = 100，打死 = 0；**僵王没出场 / 已死亡 / 已离场 → 进度条自动隐藏**（不会留一条孤儿进度条）。
- 僵王战没有波次，`get_flag_num()` 返回 0 → 进度条上不画旗帜。
- 原来那条独立的 `ZombossHpBar`（独立 UI，由僵王创建 / 销毁）已经删掉：它和关卡进度条本来就摆在
  同一块位置，统一由控制器驱动后不需要两份。

## 6. 僵尸迷阵：配对次数 / 75

`BeghouledProgressProvider`（`src/levels/mode_minigame/minigame_05_beghouled_progress_provider.gd`）每帧读
`BeghouledManager.match_num`：`配对次数 / ConstBeghouled.TARGET_MATCH_NUM(75) × 100`。

- 本关原版没有波次（无限波），`get_flag_num()` 返回 0 → 进度条上不画旗帜。
- **只有玩法进行中才显示**（`is_running` 且 `main_game_progress == MAIN_GAME`）：
  开战前（展示僵尸 / 铺盘）与通关结算后都藏起来，不留一条 0% 的孤儿进度条。
- 三消管理器建得比数据源晚（数据源在控制器 `setup()` 时装上，管理器在关卡初始化回调里建），
  所以由关卡脚本建好管理器后 `bind_manager()` 补一次（见 `minigame_05_beghouled._init_beghouled`）。

> 这条口径替代了原来的「本关整条关掉进度条」（`level_progress_controller.set_enabled(false)`）；
> `set_enabled()` 现在是**没有对应口径的关卡**才用的总闸。

## 7. 僵尸水族馆：阳光 / 1000

`ZombiquariumProgressProvider`（`src/zombiquarium/`，与水族馆其它代码同侧）每帧读
`ZombiquariumManager.get_sun_value()`：`当前阳光 / ConstZombiquarium.TROPHY_SUN_COST(1000) × 100`。

- 本关不计波次，`get_flag_num()` 返回 0 → 进度条上不画旗帜。
- **只有玩法进行中才显示**（`ZombiquariumManager.is_running` 且 `main_game_progress == MAIN_GAME`）：
  水族馆挂上来之前、通关 / 判负之后都藏起来，不留一条 0% 的孤儿进度条。
- 玩法本体比数据源建得晚（水族馆是 `run_flow()` 里才实例化的），由关卡脚本挂好之后
  `bind_manager()` 补一次（同三消那条口径，见 `minigame_08_zombie_aquarium.run_flow`）。
- **进度会退**：买僵尸要花 100 阳光，进度条会跟着往回掉 —— 这是真实的现金减少，
  刚好和「奖杯卡什么时候能点」同步，玩家看着这一条就知道离通关还差多少。

## 8. 观星：已种轮廓点 / 轮廓点总数

`SeeingStarsProgressProvider`（`src/levels/mode_minigame/`，与观星其它代码同侧）每帧读关卡脚本上的
`star_cells` 与 `get_unplanted_num()`：`(总数 - 未种数) / 总数 × 100`。

- **进度条只代表种植进度，不画旗帜**：`get_flag_num()` 返回 0、`take_flag_raise_index()` 返回 -1，
  进度条上不出现旗帜（口径同僵王战 / 僵尸迷阵）。本关的 4 面旗帜只是「没种满就判负」的倒计时，
  归波次管，不占进度条 —— 画上去反而会被误读成「进度跟波次有关」。
- 显示时机沿用战斗口径（继承 `LevelProgressBattleProvider`）：开第一波之后才显示。
- 轮廓点一个都没有（自制关卡没配 `STAR_CELLS`）→ 进度条隐藏，不留 0% 孤儿条。
