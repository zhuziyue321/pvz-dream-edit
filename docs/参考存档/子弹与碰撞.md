## 子弹类型

子弹分为4类: 直线\抛物线\追踪子弹\ 其他（加农炮）

### 直线

直线型 非穿透性攻击 子弹在碰撞到屋顶斜坡时判断是否破碎

### 抛物线

抛物线子弹使用贝塞尔曲线控制子弹弹道,根据目标僵尸位置确定终点位置,可以跟随僵尸移动,僵尸移动超出一定限制,固定最终落点

### 追踪子弹

追踪子弹根据贝塞尔曲线每帧更新移动方向

### 加农炮子弹

加农炮子弹继承Node2D节点,与子弹基类无继承关系

### 检测过滤

检测碰撞时会同时检测角色受击状态  
若可以检测者可以检测到目标受击状态,发射可以攻击信号  
若不能攻击,连接僵尸状态改变信号,僵尸状态改变时,重新判断是否可以攻击

植物（枚举与状态现在由受击状态组件 `BeAttackStatusComponentPlant` 持有，脚本 `res://src/entities/character/components/be_attack_status_component/component_be_attack_status_plant.gd`；植物本体通过只读属性 `curr_be_attack_status` 转发，检测组件的读取方式不变）:

```gd
enum E_BeAttackStatusPlant{
	IsNorm = 1,		## 正常
	IsFloat = 2,	## 悬浮
	IsDown = 4, 	## 地刺
	IsShort = 8, 	## 低矮植物（僵尸方直线子弹的检测过滤；植物僵尸做之前未使用）
}
```

僵尸:

```
enum E_BeAttackStatusZombie{
	IsNorm = 1,		## 正常
	IsJump = 2,		## 跳跃
	IsDownPool = 4,		## 水下
	IsSky = 8,			## 空中
	IsDownGround = 16,	## 地下
	IsJumpInPool = 32,	## 跳入泳池,该状态无法被高建国拦截
}
```

> 「可以攻击的敌人状态」掩码（`can_attack_plant_status` / `can_attack_zombie_status`）现已由可攻击状态掩码组件 `CanAttackStatusComponent` 持有  
> （脚本 `res://src/entities/character/components/can_attack_status_component/component_can_attack_status.gd`）：  
> 攻击检测、跳跃、炸弹、子弹、溅射、窝瓜等攻击来源各自挂载该组件，由组件内 `can_attack(enemy)` 判定；  
> 未在场景中配置该组件时，按该攻击来源的历史默认掩码在运行期创建。

## 碰撞层说明

- layer 1 World : 世界层，房子区域\泳池碰撞\屋顶斜坡
- layer 2 PlantHurtBoxDetecttion : 植物层，植物所在层
- layer 3 ZombieHurtBoxDetecttion : 僵尸层，僵尸本体所在层（**魅惑僵尸也在这层**，敌我改由归属阵营判断）
- layer 4 BulletFromPlant : 植物子弹所在层，
- layer 5 ~~ZombieHurtBoxDetecttionOnAttack~~ : **已废弃**（原「僵尸攻击时前移 20px 的额外检测框」层，现改名 Deprecated_OnAttackDetection）
  - 僵尸攻击时**不再前移受击框**：窝瓜 / 大嘴花 / 缠绕海草原本靠这一层多拿到 20px 的提前量，现在一律只检测
    layer 3（`DetectComponent` 的 `is_detect_attack` 已随该层一并删除），行为回归「范围内有僵尸就触发」
- layer 6 ~~ZombieHurtBoxDetecttionBeHypnotized~~ : **已废弃**（原魅惑僵尸检测层，现改名 Deprecated_BeHypnotizedDetection）
- layer 7 Bowling : 保龄球子弹层，撑杆跳僵尸可以检测到该层跳跃，
- layer 8 BulletFromZombie : 僵尸子弹区域所在层（投石车僵尸的篮球、将来的植物僵尸子弹）
  - 阵营与层的映射现由 `src/entities/bullet/bullet_camp_config.gd` 集中管理，见 [子弹说明](子弹说明.md) §3；
    场景里不要再手改 `Area2DAttack` 的层来表达阵营
- layer 9 PlantHurtBoxReal: 植物真实受击区域
- layer 10 ZombieHurtBoxReal: 僵尸真实受击区域（**魅惑僵尸也在这层**，敌我改由归属阵营判断）
- layer 11 ~~ZombieHurtBoxRealBeHypnotized~~ : **已废弃**（原魅惑僵尸真实受击层，现改名 Deprecated_BeHypnotizedReal）
- layer 12 ItemDetect:道具检测层(梯子、脑子等)
- layer 13 ItemReal: 道具真实层

### 受击层简化说明（layer 5 / 6 / 11 已废弃）

受击层现为 **4 个**：layer 2/3（植物 / 僵尸索敌框）、layer 9/10（植物 / 僵尸真实受击框）。
层只回答「我是植物还是僵尸、是索敌框还是伤害框」；
**敌我（含魅惑）与「僵尸是否在啃食」都不再靠层区分**，前者改由归属阵营判断：

- `BulletCampConfig.get_owner_camp(character)`：角色的**归属阵营**，魅惑僵尸算**植物方**（它是玩家的人）
- `BulletCampConfig.is_enemy(camp, character)`：用归属阵营比较，魅惑僵尸因此是僵尸方的敌人、植物方的自己人
- 因为魅惑僵尸与普通僵尸同层，僵尸方的 mask 必须把敌方层写全：`ZombieEnemy = 2+4`（检测）/ `256+512`（真实），
  再由 `DetectComponent._judge_enemy_is_can_be_attack` 与子弹命中处的 `is_enemy` 把非魅惑的同伴过滤掉

魅惑不再切层也带来一个副作用：周围已经重叠着的检测组件收不到 `area_entered`，
所以 `Character000Base.be_hypno()` 会 `EventBus.push_event("character_be_hypno")`，
所有 `DetectComponent` 订阅后把 `need_judge` 置真，下一帧重新判定敌我。

「僵尸攻击时前移受击框」也已删除：原来每个僵尸额外挂一个 `HurtBoxDetectionOnAttack`（layer 5），
攻击时把 `position.x` 改成 `-20`（前移 20px），只在窝瓜 / 大嘴花 / 缠绕海草配置了 `is_detect_attack` 时生效。
这个前移既不符合原版（原版僵尸受击框不随啃食状态变化），又会连带影响屋顶斜坡判定 ——
`node2d_detect_in_slope` 的补偿节点列表里就含这个框，它前移会让斜坡判定的采样点跟着动。
所以整框连同 layer 5 一并删除，上述三种植物回归「范围内有僵尸就触发」。

#### 废弃层的位必须手动清掉

删层不等于删干净：**`BulletCampConfig.apply_camp_collision()` 会把场景里「不属于任何阵营基础层」的位当成
有意义的额外层原样保留**（`extra_mask = collision_mask & ~C_AllCampMaskBits`，而 `C_AllCampMaskBits` 只有 `512|256`）。

也就是说，只要某个 `.tscn` 的 `collision_mask` 里还留着 `16`（layer 5）/`32`（layer 6）/`1024`（layer 11），
运行时切阵营时这些位会被**永久带走**，谁也说不清它们还在检测什么。

改动碰撞层后自查：全仓库 `collision_mask` / `collision_layer` 的取值里不应再出现 `16` / `32` / `1024` 这三个位。
2026-10-05 清理掉的 7 处残留（都是 `+16`）：

| 场景 | 原值 | 现值 | 分解 |
| --- | --- | --- | --- |
| `plant_chomper.tscn` DetectComponent/Area2D | 20 | 4 | L3 |
| `plant_potato_mine.tscn` Area2DBomb | 20 | 4 | L3 |
| `plant_cherry_bomb.tscn` Area2DBomb | 2068 | 2052 | L3 + L12 |
| `plant_doom_shroom.tscn` Area2DBomb | 2068 | 2052 | L3 + L12 |
| `bullet_cob_cannon.tscn` Area2DBomb | 2068 | 2052 | L3 + L12 |
| `bullet_bowling_bomb.tscn` Area2DBomb | 4116 | 4100 | L3 + L13 |
| `items/mini_game/hammer.tscn` Area2D | 20 | 4 | L3 |

当时这些位**没有造成实际误伤**（已无任何节点的 `collision_layer` 带 16），只是死配置；
但留着就会误导后来者，且 `apply_camp_collision` 会把它当「有意义的额外层」一直传下去。
