## 一个坑：跨画布层时 z_index 不起作用

同一棵树里决定先后顺序的是 `CanvasLayer.layer`，**层内的**才轮到 `z_index` 和树序；

一个 layer 100 的节点永远画在 layer 6 的节点之上，后者就算写 `z_index = 2000` 也压不过去

（掉落物 / 战利品写 `z_index = 2000` 也只在它自己那层里有效，仍然排在 UI 层之下）。

所以要「某个画面元素必须压在某

个元素之上 / 之下」，只有两条路：

1. 调 `CanvasLayer.layer`（粗粒度，跨层的唯一手段）
2. 把两者放进**同一个** CanvasLayer，再靠树序 / `z_index` 排（参照 `present.tscn`：

   `PickUpGlow` 排在 `TextureButton` 之前 —— 本体才不会被自己的光糊掉）

通关掉落的收尾表演就是按这个排的（见 `src/fx/other_effect/canvas_layer_white_screen.gd` 文件头）：

- 发光组 `PickupAwardLight` 挂在 `CanvasLayerDropItem` 的**第一个子节点**：跟掉落物同层，

  且排在掉落容器之前，掉落物本体画在光之上
- 白屏单独占 layer 100：最上层，把 UI 也一起吃掉，最后才变白、才切场景

## 一个坑：同层内 z_index 是**跨父节点**生效的，别拿它给「同一棵树的部件」编顺序

同一 CanvasLayer 里，`z_index` 比树序**优先**，而且**不限于兄弟之间** —— 一个 `z_index = 30` 的深层子节点，
照样画在 `z_index = 0` 的另一棵子树之上。所以「同一父节点下的部件谁在前谁在后」应该靠
**子节点顺序**表达（等 z_index 时按树序画），不要调 z_index。

反例（已修，且该产物 2026-10-23 随 PVZ2 重写一起废弃 —— 菜问改走 PAM 路线，一个 `Node2D`
在 `_draw()` 里画，压根没有节点层级可言）：PVZ2 烘焙动画 `mods_builtin/pvz2/bonkchoy/bonkchoy_anim.tscn`
把 57 个 `draw_slot_*` 的绘制顺序写成了 `z_index = 0 ~ 56`，于是整株植物占掉 57 层：

- 植物自己的**血条**（`plant_base.tscn` 的 `HpComponent/HpControl`，0 层，靠 `HpComponent` 排在
  `Body` 之后才压住身体）被顶到下面，看不见；
- 卡片上的**冷却遮罩**（`card_base.tscn` 的 `ProgressBar`，0 层，排在 `CardBg` 之后）同样被盖住；
- 连卡面的阳光数字（`CardBg/Cost`）也会被压过。

正解：这些部件的 `z_index` **全部归零**，先后交给子节点顺序 —— 画面顺序与原来一致，层级不再外溢。
凡是「外部工具烘焙出来的动画 `.tscn`」，都值得检查一遍它有没有把顺序写进 `z_index`。
