## 传送带关卡（冒险模式）

每个大区的**第 5 关与第 10 关**（1-5/1-10、2-5/2-10、3-5/3-10、4-5/4-10、5-5/5-10）是「关卡自己发牌」的关卡，  
**2-5 是锤僵尸关、4-5 是砸罐子关**（各见下一节与「砸罐子关」一节），**其余都是传送带关**，  
关卡资源写 `card_mode = 2`（`ConstLevelData.E_CardMode.ConveyorBelt`）。  
`ResourceLevelData._apply_card_mode_constraints()` 会自动把 `can_choosed_card`、`is_day_sun` 关掉；  
传送带卡片免费（`card.gd::card_init_conveyor_belt()` 把 `sun_cost` 置 0），所以关卡不需要天降阳光。

传送带刷什么卡由关卡资源的 `all_card_plant_type_probability` 随机池决定  
（`card_order_plant` 可指定开局前几张的顺序，`create_new_card_speed` 调生成速度，见 `card_slot_conveyor_belt.gd`）。  
**运行期改出卡间隔**：关卡脚本调 `card_manager.set_conveyor_card_interval_scale(x)`（倍率，`0.5` = 间隔减半）  
或 `card_manager.set_conveyor_card_interval(秒)`（直接指定）；倍率以关卡初始化算出的原始间隔为基准，  
重复设同一个倍率不会叠加，非法值（≤0 / NaN）只告警并忽略。  
僵王关（冒险 5-10、迷你游戏「僵尸博士的复仇」）在 `run_flow()` 开战前设了 `0.5`，boss 战期间出卡间隔减半。  
x-10 的卡池约定为**该区主题植物（+ 豌豆射手 / 坚果），且不含产阳光植物**（传送带卡片免费、且不天降阳光，给产阳光植物没有意义）：  
1-10 = 除向日葵外的全部白天植物；2-10 = 除阳光菇外的全部夜晚蘑菇（**纯蘑菇卡池**，不含豌豆射手 / 坚果）；  
3-10 / 4-10（后院 / 浓雾）额外带睡莲，5-10（屋顶）带花盆与投手类。

各关实际卡池（`all_card_plant_type_probability` 的 key，权重统一 2）：

| 关卡   | 卡池（`CharacterRegistry.PlantType` 编号）                            |
| ---- | --------------------------------------------------------------- |
| 1-10 | 白天植物（除向日葵）                                                      |
| 2-10 | 夜晚蘑菇（除阳光菇）                                                      |
| 3-10 | 莲叶17 / 三线19 / 水草20 / 辣椒21 / 地刺22 / 火炬树桩23 / 高坚果24               |
| 4-10 | 莲叶17 / 海蘑菇25 / 仙人掌27 / 裂荚29 / 杨桃30 / 南瓜头31 / 磁力菇32（雷雨夜浓雾，无 BGM） |
| 5-5  | 花盆34 / 南瓜头31 / 大嘴花7 / 樱桃炸弹3（蹦极闪电战，见下一节）                         |
| 5-10 | 屋顶植物 + 花盆 + 投手类                                                 |

调整传送带关卡时同步改关卡资源与本表。

## 蹦极闪电战（冒险模式 5-5）

**蹦极闪电战 = 本关不直接出怪，僵尸全部由蹦极僵尸「空投」进场。**

| 波次             | 来的是什么                                                       |
| -------------- | ----------------------------------------------------------- |
| 正常波次           | **空投僵尸的蹦极僵尸** `Z026BungiDrop`：把一只僵尸吊在绳子上放到场上                |
| 大波（旗帜波 / 最后一波） | 本波照常空投，**另外**再来一批**偷植物**的蹦极僵尸 `Z021Bungi`（`is_bungi` 的大波空投） |

5-5 是屋顶传送带关，卡池是「花盆 / 南瓜头 / 大嘴花 / 樱桃炸弹」：花盆开种植位、大嘴花输出、  
南瓜头保护、樱桃炸弹救场，被偷了就从传送带立刻补。

**只有 5-5 这一关用**，所以开关不在关卡资源上（本体已经没有 `is_bungi_blitz` 字段），  
玩法整段写在关卡脚本里：

| 位置                                                          | 职责                                                            |
| ----------------------------------------------------------- | ------------------------------------------------------------- |
| `src/levels/mode_adventure/adventure_05_05.gd`                | `init_level_items()` 里建出空投管理器；覆写 `create_wave_zombies()` 把本波僵尸换成空投进场 |
| `src/levels/mode_adventure/adventure_05_05_bungi_blitz.gd`    | 空投本体（`Adventure0505BungiBlitz`）：挑落点 → 建真僵尸 → 建吊它的 `Z026BungiDrop` |
| `LevelScriptBase.create_wave_zombies()`                       | **通用**钩子：波次管理器每波都来问一次「这批僵尸怎么进场」，默认是走进来     |
| `ZombieWaveCreateManager.create_norm_wave_zombies()`          | **通用**进场：僵尸从场地边缘走进来（退化路径也走它）                     |

`zombie_refresh_types` 仍然决定**空投哪些僵尸**（战力上限、权重那一套完全不变），变的是进场方式。  
大波的偷植物蹦极僵尸还是 `is_bungi` + `range_num_bungi`，与空投相互独立。

实现落位：

- `src/entities/character/zombie/zombie_bungi_drop.gd`（`Z026BungiDrop`）+ `src/entities/character/zombie/zombie_bungi_drop.tscn`  
  —— 继承蹦极僵尸的场景与脚本，改六件事：
  1. **没有靶子**：空投落点本来就随机，不需要给玩家提示，`BungeeTarget` 直接隐藏。
  2. **每帧画面都相同**：它更像一段投放动画而不是僵尸，画面从头到尾就是一张静态图。  
     两个动画资源都放在 `animation/character/zombie/zombie_bungi/` 下，都是原版  
     `zombie_bungi_raise.tres` 的**最后一帧**（抱着东西的姿态）抽出来的单帧动画：
     - `Zombie_bungi_drop_static.tres`：降落 / 落地等（drop / idle 两态），无方法轨
     - `Zombie_bungi_raise_static.tres`：起飞（raise 态），同一帧 + `raise_start` 方法轨，  
       靠它把投放完的蹦极僵尸撤走  
       子场景重写了 `AnimationPlayer.libraries` 与 `AnimationTree.tree_root`（状态名沿用父场景）。  
       绳子在 `ready_norm()` 里就挂到 `body2` 上，否则全程看不见绳子。  
       落地那一态（`is_grab`）在普通蹦极这里是「抓取」，空投**没有这一态**——  
       状态机直接从 idle 跳到起飞，不做「伸手抓」也不做「松手抬起」。
  3. **没有前后摇**：`drop_start_delay` / `grab_start_delay`（父类 `Zombie021Bungi` 的导出变量，  
     普通蹦极都是 2 秒：等靶子落地、落地后停顿）在子场景里都设成 0，  
     进场就开始降落、落地就开始起飞，整段约 1.3 秒。
  4. **不被索敌**：父类的 `enable_hurt_box_on_drop()`（降落途中启用受击框）在空投里重写成空实现，  
     受击框全程 `monitorable = false`，任何索敌 / 子弹都检测不到它。
  5. **怀里僵尸的运动（核心，其余都围着它转）**：把它当成「t=0 时刻凭空生成」的僵尸，  
     空投只是让这次生成看起来合理，所以降落过程（t<0）是一条**直上直下、y 随时间正比例**  
     的直线（补间不设缓动），t=0 时横纵坐标跟「凭空生成」完全重合：
     - 横向：`BungiContainer` 在本体偏右 42，`ready_norm()` 里把蹦极整体左挪到  
       「绳子末端正好在落点正上方」，之后 x 恒定不变，落地那一刻不会横向跳；
     - 纵向：降落终点抬高容器的那点高度（父类新增的 `landing_offset_y`），本体停在半空、  
       绳子末端正好停在地面上，僵尸的脚才落在地面而不是陷进地里；
     - 本体还要在基准上再偏 `perch_offset`（默认 `(-17, -60)`，x 正 = 往右、y 正 = 往下，纯观感），  
       这只挪本体，僵尸走位会反向补回来，路径不受影响。  
       怀里的僵尸 `z_index` 抬到蹦极之上（放下时还原），否则会被蹦极的身体挡住。  
       **被抱着的僵尸夹在中间图层**：身体留在行内 z，僵尸 +1，抱着它的「手 / 小臂」  
       （`Zombie_bungi_*_lower2` / `*_hand2`，四个节点）单独抬到 +2——它们是本体内部的节点，  
       相对 z 压不住同行的另一只僵尸，所以用绝对 z（`z_as_relative = false`，  
       与火爆辣椒火焰同源的写法），节点本身不挪（挪了动画轨道取不到）。  
       还差一点就用导出变量 `carry_offset` 微调。
  6. **蹦极的贴图整体下移 10px**（`body_texture_offset_y`，含挂在身上的绳子）：  
     抱着看觉得偏上；只改 `Sprite2D.offset`（动画轨道不打 offset，不会被覆盖），  
     `BungiContainer`（Node2D，没有贴图）不动，所以挂点 / 落点完全不受影响。
  7. **落地不偷植物**，而是把吊着的僵尸放下来（重写 `bungi_plant_cell()`）。  
     被吊着时禁用受击 / 移动 / 攻击组件，并把速度系数压到 0  
     （`E_Influence_Speed_Factor.BungiCarry`，与黄油 / 冰冻同一套口径），落地才恢复：  
     只禁用移动组件它只是不平移，走路动画还在播，看着像自己在半空里走下来，  
     **下落全程它应该一动不动，只有整只僵尸跟着绳子往下走**；  
     本体只跟着绳子改坐标，  
     **不改父子关系**（僵尸动画轨道按 `Body/BodyCorrect/...` 取节点，把 `Body` 挪走会让移动动画失效）。  
     被打下来或被保护伞摊开时也先把僵尸丢下去，避免本波僵尸凭空消失。
- `src/levels/mode_adventure/adventure_05_05_bungi_blitz.gd`（`Adventure0505BungiBlitz`，由关卡脚本
  在 `init_level_items()` 里创建，挂在背景物品层）  
  —— 每波按原版战力算出僵尸清单后，为每只僵尸挑一个空投落点（随机植物格子，最靠左两列不投，  
  免得贴脸房子），先建真僵尸再建吊它的空投蹦极僵尸。真僵尸计入本波血量与僵尸数，  
  所以波次血量统计和提前刷新判定都不用改。
- `adventure_05_05.gd` 覆写 `create_wave_zombies()` 接住本波出怪；本体那条分支已于
  2026-10-04 删掉 —— 通用波次代码不再认识这个玩法（硬约束 §1-8）。

5-5 的取值（`adventure_05_05.gd`）：`is_bungi = true`（大波偷植物）+ 空投走本关自己的脚本。


## 僵王关（冒险模式 5-10「夜屋顶 Night Roof」）

**5-10 是冒险模式最后一关，也是僵王博士（Dr. Zomboss）那一战** —— 原版把它放在一个独立的
第 6 个场景**夜屋顶（Night Roof）**：场地几何与白天屋顶完全一致，只是整张背景换成了夜色版
（`background6boss.jpg`，1080×440，与 `background5.jpg` 的房型 / 车道位置像素对齐）。

地图层三件套（改任一件都要记得另外两件，详见 [地图实现.md](./地图实现.md#232-夜屋顶僵王关的底图与背景子场景)）：

| 层 | 取值 | 位置 |
| --- | --- | --- |
| 地图数据 | `map_boss.tres` | 关卡自己的 `map_data`（`adventure_05_10.gd` 里 `preload` 指定），**不在 `DEFAULT_MAP_PATHS` 里** |
| 背景枚举 | `ConstLevelData.GameBg.Boss` → `background6boss.jpg` | `ConstLevelData.GameBgTextureMap` |
| 背景子场景 | `main_game_bg_boss.tscn` | `ResourceMapData.map_bg_scene`（多挂一个 `Background6GameoverMask`） |

关卡资源（`adventure_05_10.gd`）的关键开关：

| 开关 | 取值 | 说明 |
| --- | --- | --- |
| `game_sences` | `2`（`MainGameRoof`） | 只决定加载哪份主游戏场景（三份其实是同一个文件）；地图另走下面的 `map_data` |
| `map_data` | `map_boss.tres` | 夜屋顶图，**不再复用 `map_roof`**（几何相同，但背景子场景不同） |
| `game_BG` | `5`（`GameBg.Boss`） | 夜屋顶底图；下标与 `MainGameHome.door_downs` / `door_masks` 一一对应 |
| `game_BGM` | `6`（`GameBGM.Boss`） | `brainiac_maniac.mp3`（Brainiac Maniac，只给 5-10 与僵王复仇用） |
| `is_day` / `is_day_sun` | `false` / `false` | 夜晚；不出天降阳光（阳光只能靠传送带塞给的花盆外的途径，本关实际没有阳光产出） |
| `card_mode` | `2`（`ConveyorBelt`） | 传送带关：`can_choosed_card` 被 `init_para()` 强制 `false`，**没有普通选卡界面** |
| `look_show_zombie` | `false` | **出怪预览为空**：本关不自然出怪，原版开局那段「看僵尸」一只不出，连带「镜头右移看僵尸」也不跑（`camera_init_x` 直接停在归位位，别再给玩家拍房子） |
| `is_zomboss_fight` | `true` | 僵王关：胜利条件从「打完最后一波」变成「打死僵王」（原名 `is_boss`）；**僵王由下面的流程事件放进场**，不再由主管理器开战时自动 spawn |
| `monster_mode` | `0`（`Null`） | 本关不自然出怪，僵尸全部由僵王放出来 |
| `run_flow()` 开头 | `await plant_flower_pot_columns(4)` | 夜屋顶是裸屋顶：流程第一步沿整列铺出左侧 4 列花盆（走「系统种植」事件），少了花盆屋顶上什么都种不下；多轮 / 切轮会再铺一次（格子里已有花盆则跳过） |

**开局流程**（`adventure_05_10.run_flow()`，从上往下读就是这一关的开局顺序）：

```gdscript
await spawn_zomboss()    ## 生成僵尸博士（没有僵尸预览，见下）
await wait(3.0)          ## 等登场动画落位
await init_lawn_mover()  ## 初始化小推车
await ready_set_plant()  ## 准备-安放-植物
await start_battle()     ## 开战
```

> **没有僵尸预览**：本关不自然出怪（`monster_mode = Null`，僵尸全由僵王投放），
> 原版开局那段「看僵尸」的内容也是空的 —— 所以 `look_show_zombie = false`，
> 流程里不写 `show_zombie()` / `camera_back()` 那两步（出了预览僵尸就是倒退），
> 相机由 `camera_init_x = MainGameCamera.CAM_POS_ORI.x` 一进关就停在归位位。
> 迷你游戏「僵王复仇」同口径。
>
> 「生成僵王」排在**开战之前**，好让它踩着「准备-安放-植物」的红字登场（原版僵王是从天而降的）。
> 想让它晚一点露面，就给这条事件加 `settle_time`（等登场动画落位）或把它挪到 `start_battle()` 之前更靠后。
> ⚠️ 本关 `card_mode = ConveyorBelt`，`can_choosed_card` 被 `init_para()` 压成 `false`，
> 所以流程里**没有 `choose_card()`** —— 写了也会立刻返回（见「传送带关卡」那一节）。

场地本身（与 `map_roof` 逐格一致，**不要单独改**）：

- 5 行 × 9 列全 `Roof`（裸屋顶）、5 行全 `Land` 陆地行、`have_slope = true`
- 每行一台屋顶清洁车（`lawn_mover_type = 2`），与白天屋顶同样配置
- 阶梯 `col_dy = [99,84,63,45,17,0,0,0,0]`、`zombie_create_global_pos` 与进家位置同 `map_roof`

可操作草坪的阶段藏起来、悬停能点的 UI 露出来、打开菜单期间保持可见），
锤子不再自己 `set_mouse_mode`。

**砸僵尸掉阳光**：`hammer.gd` 里 `can_sun`（开关）/ `pred_sun`（概率，当前 10%）/ `sun_value`（面值 25），  
砸死僵尸时按 `pred_sun` 判定，命中则在该僵尸头顶一次掉 3 个阳光并做抛物线飘落。

## 砸罐子关（冒险模式 4-5「Vasebreaker」）

**4-5 是第四大关第 5 关，也是原版唯一一个出现在冒险模式里的解谜关**：原版把它放在**夜晚前院**  
（不是本区的浓雾后院），草坪上没有自然出怪、没有旗帜，植物与僵尸全部由罐子开出。  
玩家点罐子把它砸开（`HandComponentNull.click_cell()` → `ScaryPot.open_pot_be_hammar()`），  
砸完一批并打光僵尸后戴夫再摆下一批，一共**三批**，通关奖励裂荚射手（`ConstPlantUnlock` 第 35 关）。

关卡资源（`adventure_04_05.tres`）的关键开关：

| 开关                         | 取值                                      | 说明                                                                         |
| -------------------------- | --------------------------------------- | -------------------------------------------------------------------------- |
| `game_sences`              | `0`（`MainGameFront`）                    | 夜晚前院 `map_front.tres`（5 行 9 列），**不是**本区 4-x 用的 `map_pool.tres`             |

| `monster_mode`             | `0`（`E_MonsterMode.Null`）               | 无自然出怪、无旗帜；`zombie_refresh_types` 只作记录，不参与刷怪                                |
| `card_mode`                | `0`（`Null`）+ `can_choosed_card = false` | 没有出战卡槽：植物全靠罐子里开出的临时卡（`ScaryPot.open_plant()`）                              |
| `is_pot_mode` / `pot_mode` | `true` / `1`（`E_PotMode.Fixd`）          | 固定生成模式，罐子里装什么写死在关卡资源里                                                      |
| `pot_col_range`            | 第 1 批 `(6, 9)`                          | 罐子摆在最后 **3 列 × 5 行 = 15 个格子**（第 2 / 3 批由 `pot_config_on_round` 改成 4 / 5 列） |

| `is_lawn_mover`            | `true`（默认值，不写）                          | 与解谜模式的砸罐子不同，**这一关有小推车**（原版同样如此）                                            |


**三批罐子一批比一批难，占的列也一批比一批多**：`pot_config_on_round`（`Array[Dictionary]`，  
下标 0 = 第 1 批）按轮次覆盖 `plant_pot` / `random_pot_plant` / `zombie_pot` / `random_pot_zombie`  
以及 `pot_col_range`（本批占的列）/ `pot_hint_num`（本批戴夫提示罐个数）；  
`PlantCellManager.start_next_game_plant_cell_manager_update()` 在每轮摆罐子之前先调  
`ResourceLevelData.apply_pot_config_on_round()` 换配置，再按新的列数  
`init_plant_cell_row_on_zombie_row_type()` 重算候选格子，最后 `cerate_pot()`。

| 批次 | 占列       | 罐子数 | 神秘罐里的植物            | 神秘罐里的僵尸                 | 戴夫提示罐（绿罐）  |
| -- | -------- | --- | ------------------ | ----------------------- | ---------- |
| 1  | 6~8（3 列） | 15  | 豌豆 ×9、窝瓜 ×2        | 普僵 ×3、小丑 ×1             | 0 个（全是棕色罐） |
| 2  | 5~8（4 列） | 20  | 豌豆 ×7、寒冰 ×5、窝瓜 ×1  | 普僵 ×4、铁桶 ×2、橄榄球 ×1      | 2 个        |
| 3  | 4~8（5 列） | 25  | 豌豆 ×6、寒冰 ×6、魅惑菇 ×4 | 普僵 ×4、铁桶 ×2、小丑 ×2、舞王 ×1 | 3 个        |

> **罐子内容一律写在 `random_pot_plant` / `random_pot_zombie`（棕色神秘罐）里，  
> 再用 `pot_hint_num` 挑几个换成绿罐**：这样第 1 批就是全棕色（玩家完全不知道哪个是植物），  
> 后面几批才有戴夫点名的绿罐。直接写 `plant_pot`（绿罐）/ `zombie_pot`（僵尸罐）会提前泄底。

> **每批都要刚好填满本批的格子数（列数 × 行数）**：固定模式摆完配置里的罐子后，  
> 剩下的格子会被**结果随机罐子**填满（`PlantCellManager.create_all_pot_on_fixed_mode()`），  
> 而结果随机罐子是从**全僵尸白名单**里开怪的，会把原版没有的僵尸（冰车 / 海豚…）放出来。  
> 配置罐子数量时先数格子，别指望「少写几个让草坪空着」。
>
> **第 1 批要写在顶层字段上**：`init_para()` → `_init_pot_mode_fixed()` 只读顶层那四个字典，  
> `pot_config_on_round` 是「换轮次时覆盖」而不是「第 1 轮的数据源」。  
> 只写 `pot_config_on_round` 不写顶层字段的话，第 1 批会退化成一整片结果随机罐子  
> （实测会开出冰车）。

**切换批次时清空场地与卡片**（原版 4-5 每批从空草坪重新开始）：  
罐子模式下 `PlantCellManager.start_next_game_plant_cell_manager_update()` 无条件  
清掉上一批种下的植物，并兜底清掉没砸开的罐子（`clear_all_pot()`，正常流程罐子已经砸光）；  
（早先有个 `is_save_plant_on_pot_mode` 开关可以「跨批次保留植物」，没有关卡在用，已删）  
`CardManager.start_next_game_card_manager_update()` 在罐子模式下调 `clear_all_temp_cards()`  
清掉上一批罐子里开出来还没用完的临时卡片（手上正拿着的那张例外，避免手持物悬空引用）。

> **重玩 / 读档时第 1 批不能被后面几批顶掉**：`apply_pot_config_on_round()` 改的就是顶层那几个字段，  
> 而顶层字段同时是第 1 批的数据源（`init_para()` 只读顶层字段），  
> 所以 `init_para()` 里先 `reset_pot_config_first_round()` 再 `snapshot_pot_config_first_round()`，  
> 每次切轮也都从第 1 批的原始配置（`pot_config_first_round`）出发逐层覆盖。  
> 少了这一步，同一进程里第二次进本关看到的「第 1 批」会变成上次玩到的那一批。

**砸罐子关不按批次存档（每次进关都从第 1 批开始）**：罐子不进存档、植物每批都会被清掉，  
多轮存档里没有任何可恢复的进度，  
只有「第 N 批已经打完」这个轮次——读档 = 一进关就跳到第 N+1 批，玩家以为自己什么都没干就到第 3 批了。  
原版同理：砸罐子关退出就是从头砸。所以冒险 4-5 配 `is_save_multi_round_data = false`：

| 位置                                                 | 行为                                                                                    |
| -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `ResourceLevelData._maybe_load_multi_round_save()` | `is_save_multi_round_data = false` 时不加载存档（`save_game_data_main_game` 保持 null）         |
| `MainGameManager._ready()`                         | 多轮且 `is_save_multi_round_data = false` → 先 `re_main_game()` 删掉历史存档文件、清掉选关界面的「第 N 轮」标记 |
| `MainGameManager.start_next_round_game()`          | `is_save_multi_round_data = false` 时切轮不写存档                                            |

> 需要「接着上一轮玩」的多轮关卡（例如自然出怪的多轮关）保持默认 `true` 即可，别改。  
> 新增多轮关卡时先想清楚：本关有没有可恢复的进度？没有就把这个开关关掉。

**戴夫提示罐 = 绿色植物罐**：`pot_hint_num` 配置本批有几个罐子「明牌」。摆好罐子后  
`PlantCellManager.create_pot_hint()` 从本批**装着植物**的棕色神秘罐里挑出几个，  
调 `ScaryPot.set_hint_plant_pot()` 把它们的**外观换成绿色植物罐**（`E_PotType.Plant`）：  
玩家一眼就知道那几个是植物，但仍然看不出是哪一种，砸开才知道。  
第 1 批 0 个（**全是棕色罐**）、第 2 批 2 个绿罐、第 3 批 3 个绿罐。  
（别做成「显示罐内虚影」——那样连具体植物都泄底了，原版只露颜色。）

**多轮砸罐子不能把罐子摆在已有植物 / 已有罐子的格子上**：  
`PlantCellManager.filter_can_create_pot_plant_cell()` 在摆罐子前把这两类格子筛掉。

**戴夫一共说三段话**（原版 4-5：开场介绍 → 砸完第 1 批 → 砸完第 2 批）：

| 时机        | 落位                                                                           | 台词来源                                             |
| --------- | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| 关卡开场      | `run_flow()` 里 `await dave_dialog(_build_dave_dialog_1())`            | `data/strings/lawn_strings.txt` 的 `CRAZY_DAVE_2500~2502` |
| 第 2 批罐子之前 | `await dave_dialog(_build_dave_dialog_2())`                          | `CRAZY_DAVE_2700~2704`                           |
| 第 3 批罐子之前 | `await dave_dialog(_build_dave_dialog_3())`                          | `CRAZY_DAVE_2800~2802`                           |

三段对话都在 `adventure_04_05.gd` 里现场构造（各一个 `_build_dave_dialog_N()`），
不再走 `crazy_dave_dialog` / `crazy_dave_dialog_next_round` 按轮次取 —— 本关流程是
`is_one_shot_flow`（整关只跑一遍），三批罐子写在同一段 `run_flow()` 里，

### 花瓶终结者 `puzzle_pot_01..10`

`pot_mode = 1`（`E_PotMode.Fixd`）：罐子里装什么写死在关卡资源里，罐子数**必须刚好填满本批格子**
（填满后多余的格子会被「结果随机罐子」补上，那种罐子从全僵尸白名单开怪，会放出原版没有的僵尸）。
原版每排罐子数 5 / 6 / 7 不等，对应 `pot_col_range`（**结束列最大 9，超过会被夹成 9**）：

| 每排罐子数 | `pot_col_range` | 罐子总数（× 5 行） |
| ----- | --------------- | ---------- |
| 5     | `(4, 9)`        | 25         |
| 6     | `(3, 9)`        | 30         |
| 7     | `(2, 9)`        | 35         |

> **踩坑**：`PcmPotUtil.init_plant_cell_row_on_zombie_row_type()` 里
> `if pot_col_range.y > row_col.y: pot_col_range.y = row_col.y`（前院 `row_col = (5, 9)`），
> 所以写 `(4, 10)` 会被悄悄夹成 `(4, 9)` = 4 列 = 20 个格子，
> 而配置里写了 25 个罐子 → `_init_pot_mode_fixed()` 的 `assert(pot_num <= num_pot_candidate)` 直接崩。
> **结束列一律写 9，往左挪起始列来加宽。**

`pot_hint_num`：摆好罐子后有几个「装着植物的棕色罐」换成绿色植物罐（戴夫提示）。
原版 **第 1 / 2 关是 0 个（全是棕色罐），第 3 关起每关 2 个**。

### 僵尸公敌 `puzzle_zombie_01..10`

`is_zombie_mode = true`：玩家用阳光放僵尸去啃掉每行尽头的脑子（`GimBrain`）。
阳光**只能靠啃向日葵获得**（夜晚不掉阳光，且向日葵在僵尸模式下不自行产阳光），
**开局 `start_sun = 50`**（原版：阳光不够放最便宜的僵尸就判负）。

- `pre_choosed_card_list_zombie`：本关可用的僵尸（阳光费用见 `CharacterRegistry.ZombieInfo.SunCost`）；
  同时把 `max_choosed_card_num` 设成这个个数（覆盖存档卡槽数），卡槽就不会留出一排空槽，也不会挤掉多余的僵尸卡。
- `plant_col_on_zombie_mode`：植物占**最左边**几列（本仓库 1~4 列逐关变密）；
  `plant_cell_col_j = 4` + `is_bowling_stripe = true` 画出放置红线，僵尸只能放在红线右侧。
- `all_plants_weight_on_zombie_mode`：纸板植物的随机权重（**向日葵权重给到 6**，否则可能全场没有阳光来源）；

#### 失败条件

原版我是僵尸**不靠僵尸进家判负**（`is_zombie_can_home` 被 `_apply_zombie_mode_rules()` 强制关闭，
僵尸走到脑子那儿是吃掉脑子，不是进家）。唯一的失败方式是：

> 场上没有僵尸，且阳光不足以放下任何一只僵尸（最便宜的僵尸 50 阳光）。
> 失败提示 = `lawn_strings.txt` 的 `[I_ZOMBIE_DEATH_MESSAGE]`「你失去了所有的僵尸！」

实现在 `MgmLoseManager`（`src/managers/main_game_manager/mgm_lose_manager.gd`）：
`is_zombie_mode` 关卡起一个 1 秒轮询计时器，满足「主游戏阶段 + `curr_zombie_num == 0` +
可用阳光 < 本关最便宜僵尸的价格」就走与僵尸进家同一套失败流程（重开存档 + `losemusic` + 红字）。

- **为什么用轮询而不是只挂 `signal_curr_zombie_num_change`**：草坪上可能还躺着没捡的阳光
  （`Sun.exist_time = 10` 秒后自行消失），捡起来也许刚好够再放一只僵尸，此时判负会很冤；
  轮询把「草坪上没捡的阳光」算进可用阳光，等它消失后再判。
- **不判负的后果**：阳光只来自啃食向日葵，没有僵尸就再也产不出阳光，玩家会永久卡死在关卡里。

### 解锁与「无尽关」

- 模式解锁仍是 `ConstUnlockLevel.PUZZLE_UNLOCK_ADVENTURE_LEVEL = 36`（冒险 4-6 掉礼盒），
  首批开放 3 关，之后通关一关解锁下一关，见 [选关界面与解锁.md](选关界面与解锁.md)。
- 每页第 10 关是**无尽关**（`game_round = -1`）：`ChooseLevel.update_lock_level()` 对
  `game_round == -1` 直接 return，**无尽关默认开放、不占开放名额**（与原版一致）。

## 全面冻结（迷你游戏「Bobsled Bonanza」，第 13 关）

**一句话规则**：开局四条地面路线上已经结着**永久冰面**（冰面盖住的格子不能种植），
雪橇队沿冰面滑进来、洗冰车一边开一边把冰铺长；**冰面被融掉的那一行只出洗冰车**，等冰铺回来才有雪橇队。

| 项       | 值                                                                                                     |
| ------- | ----------------------------------------------------------------------------------------------------- |
| 场地      | 泳池（`GameBg.Pool`，6 行 × 9 列；中间两条是水面行，**不铺冰**）                                                         |
| 开局冰道    | 四条地面行各 1 条，从最右列往左铺 `PRESET_ICE_ROAD_CELL_NUM = 4` 格                                                   |

   调动画 / 调数值时用它，不必先跳进第 8 关。

## 僵尸迷阵（迷你游戏「Beghouled」，第 5 关）

**本关不是「种植物守家」，是三消**：草坪开局已被系统铺满植物（最右一列留空给僵尸入场），
玩家**按住一株植物往相邻株上拖**，两株换位后凑成三个及以上同类连线即可消除，累计 **75 次配对**通关（不是打完波次）。

| 项      | 值                                                | 落点                                                     |
| ------ | ------------------------------------------------ | ------------------------------------------------------ |
| 棋盘     | 全部行 ×（总列数 − 1）列                                  | `BeghouledManager.board_row_num / board_col_num`        |
| 开局植物   | 豌豆射手 / 坚果 / 寒冰射手 / 小喷菇 / 星星果 / 磁力菇（六种）          | `ConstBeghouled.BASE_PLANT_TYPES`                       |
| 阳光奖励   | 3 连 25 / 4 连 50 / 5 连及以上 100（一次交换造成多组时**各自掉**）   | `ConstBeghouled.get_sun_by_chain_len()`                 |
| 升级     | 豌豆射手→双重射手 1000、小喷菇→大喷菇 500、坚果→高坚果 250           | `ConstBeghouled.UPGRADE_LIST`                           |
| 重置植物   | 100 阳光                                           | `ConstBeghouled.SHUFFLE_SUN`                            |
| 填一个弹坑  | 200 阳光                                           | `ConstBeghouled.CRATER_FILL_SUN`                        |

规则要点：

- **操作是「按住不放再拖」，不是点两下**（原版口径：GameFAQs 攻略原话「Swap two plants by pressing
  on one plant then hold while you move your cursor to where you want to switch with」，
  <https://gamefaqs.gamespot.com/boards/961689-plants-vs-zombies/56448845>）：
  格子的 `Button.button_down`（`_on_press_cell`）记下起点与按下时的光标位置，
  `_process` 每帧比位移 —— 拖过 `DRAG_SWAP_RATIO`（半格）就认这一下，朝四个邻格之一发起交换；
  松手时再判一次（整段拖动在一帧内甩完时前面的帧赶不上），没拖够就当没动过，**单击不做事**
  （`_on_click_cell` 在基类是空钩子，留给 09 关「旋风」覆盖成「点一下旋转 2×2」）。
  只认上下左右相邻的一格，空格 / 弹坑换不动。
- **消除的阳光掉在被消掉的那些格子上，玩家点了才进账**（不是「配对完立刻进计数器」）：
  `_drop_match_sun()` 把奖励按 `ConstBeghouled.SUN_UNIT_VALUE`（25）拆成几颗，沿连线均匀选格子，
  再由 `_drop_one_sun()` 用 `SceneRegistry.SUN` 建一颗（弹起来再落下，同 `CreateSunComponent`）。
  拆开的理由：`Sun` 会按面值缩放，单颗 100 的贴图会大得离谱。开了「自动收集阳光」的档仍然是落地即进账。
- **下落**：同一列里上方的植物往下补空位，顶部空出来的格子长新植物；弹坑留在原地不动，且**挡住**上方植物的下落。
- **弹坑**：棋盘上的植物不是被三消消掉的（= 被僵尸啃掉），就原地留一个**永久**弹坑
  （`PlantCell.create_crater_permanent()`，不花阳光填就一直在，靠 `DoomShroomCrater.init_crater()` 的新增 `duration` 参数实现）。
- **交换用的是手套那套搬运 API**（`glove_take_plant` / `glove_put_plant`）：植物实例与血量等状态跟着走，不是「销毁再种」。
- **没有小推车 / 钉耙**（一只僵尸进屋就输）、**没有卡片与铲子**（`can_choosed_card=false` / `is_shovel=false`）；
  夜晚但蘑菇不睡觉（`is_day = false`）、不天降阳光（`is_day_sun = false`）。
- **不走时间轴的「开战」事件**：结束条件是配对次数，由 `BeghouledManager.start_beghouled()` 开战并 `await signal_beghouled_win`，
  达标后自己推 `create_trophy`。波数给 100（原版无限波的近似），**且必须是 10 的倍数**（进度条的旗帜数 = `max_wave / 10`）。
- **关卡进度条换成本关口径：配对次数 / 75**（原版没有波次旗帜）：`create_progress_provider()` 返回
  `BeghouledProgressProvider`（`src/levels/mode_minigame/minigame_05_beghouled_progress_provider.gd`），每帧读 `BeghouledManager.match_num`，
  不画旗帜、只在玩法进行中显示。见 [关卡进度条.md](关卡进度条.md) §6。
- **摆场要 `await`**：`setup_board()` 内部要等两帧让格子槽位空出来，关卡脚本不 await 会和 `main_game_start()` 抢跑（棋盘会整个空掉）。
- **没步可走就免费重排**（`_ensure_board_playable()`：无连线 + 有步可走，两样缺一就 `_shuffle_plants()`）：
  开口摆场后、每次连锁结算收尾、买完升级换场后，三处同一个口径 —— 玩家不该为了「买了一下升级」再掏 100 阳光洗牌。
- **重排之前要先停一拍给提示**（自定义，非 wiki 口径）：判出死局后先用**教程那条屏幕下方的提示条**
  （`TutorialAdviceUI.ensure_level_hint()`，与关卡脚本 `hint()` 同一个实例）打出
  `ConstBeghouled.NO_MOVE_TIP_TEXT`（「没有配对的植物了！」），等 `NO_MOVE_TIP_WAIT`（4 秒）才真正 `_shuffle_plants()`，
  免得盘面毫无征兆地整盘变脸。这 4 秒里 `is_resolving` / `_is_replacing` 保持为真（`_can_operate()` 挡住玩家点击），
  所以**三处调用方一律 `await _ensure_board_playable()`**；等待期间关卡若已结束（失败 / 通关）就直接返回、不再动棋盘。

**植物升级**（买了之后场上所有 `from` 换成 `to`，后续补位长出来的也是 `to`）：

- **换场有空隙**：`_replace_all_plants()` 要先 `character_death_disappear()`（queue_free）再等两帧才能种新的，
  这两帧里棋盘是半空的。整段用 `_is_replacing` 锁住（`_can_operate()` 一并挡住点击 / 洗牌 / 填坑 / 再买一档），
  换完才解锁 —— 否则玩家在这个空档点一次交换，`_resolve_board()` 会跟 `create_plant()` 抢同一个格子。
- **「这是我自己拿走的」标志也跟着延长到换场结束**（`_self_removing` 在重新种完之后才解开）：
  死亡回调万一延后一帧落到空档里，会被 `_on_plant_free` 当成「被僵尸啃掉」，原地留下一个不该有的弹坑。
- **随机池同步换**：`plant_pool` 删掉 `from`、加入 `to`；之后 `_collapse_all()` 顶部补位、`try_fill_crater()` 填坑都用新池。
- **玩家能按的东西全在出战卡槽里，底部按钮条已经没有**（`beghouled_ui.gd` 只剩进度文字 + 居中提示语）：
  同一种操作不该有两个入口，买升级 / 刷新 / 填坑统一走卡槽。
- **出战卡槽五格全是本关自己的种子包**（`LevelScriptBase.create_custom_seed_packet()`，见
  [卡槽与传送带.md](卡槽与传送带.md) §5）：三档升级（卡面用升级**后**的植物，1000 / 500 / 250）
  + 100 阳光「刷新盘面」（卡面 = `seeds.png` 裁出的第 5 个种子包整图 `SeedPacket_Beghouled_Refresh.png`）
  + 200 阳光「填坑」（卡面 = `seeds.png` 裁出的第 4 个种子包整图 `SeedPacket_Beghouled_Fill.png`）；
  这两张的整卡贴图由关卡脚本建卡后 `ConstBeghouled.set_packet_face()` 换上（换背景贴图 + 清掉模板角色形象），
  上面不再叠任何东西（第 9 关「旋风」共用同一套卡面，见下文）。
  升级**买过一档就永久置灰**（`card.set_card_disabled_forever()`）；
  填坑卡**没有坑时置灰**（`card.set_card_blocked()` + 管理器的 `crater_num_changed` 信号，坑出现又点亮）。

代码落点（**全部在 `src/levels/` 侧，本体不认识本玩法**，硬约束 §1-8）：
关卡 `src/levels/mode_minigame/minigame_05_beghouled.gd`（属性 + 流程 + 创建并持有管理器）、
玩法 `src/levels/core/beghouled/beghouled_manager.gd`、数值 `const_beghouled.gd`、
界面 `beghouled_ui.gd`（纯代码建节点：一行进度 + 一排按钮，按钮数 = 升级档数 + 2）
—— 这三个与 09 关共用，所以放 `core/beghouled/`，不挂某一关的名字；
进度条数据源 `src/levels/mode_minigame/minigame_05_beghouled_progress_provider.gd`（只有本关用）。

接入方式：**管理器由关卡脚本自己 new()**，本体只给一个通用口子 ——
`init_level_items()` 里 `mg.register_level_init_callback(...)`，主游戏跑完所有子管理器
`init_manager()` 之后回调它（要读格子、要给进度条数据源绑三消管理器，都得等那时候）。

`beghouled_manager` 字段。

探针：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_beghouled`
→ `[BEGHOULED] result=PASS`（摆场 / **用合成鼠标事件按住拖过去做三消**（`a.drag_plant_cell`）/ 单击不交换 /
