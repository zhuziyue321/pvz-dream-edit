## 1. 一句话机制

通关本周目的 5-10 → **周目 +1** → 冒险进度「回到 1-1」，
**已解锁的一切（植物 / 金币 / 商店已购 / 图鉴 / 花园 / 紫卡 / 各分支模式）全部保留**（经典 New Game+）。
周目数**没有上限**，可继续三周目、四周目……

**二周目起，这一关换用自己的一套关卡脚本**（`adventure_XX_YY_round2.gd`，见 §6），
与一周目版的差异三条：**普通关多 10 波**、**开局锁定前 3 个随机卡槽**、**1-1 ~ 1-3 直接给满 5 行草皮**。

## 2. 两条进度口径（★ 最容易搞混的地方）

| 口径 | 函数 | 谁在读 | 二周目下的值 |
| --- | --- | --- | --- |
| **历史最高**（跨周目） | `GlobalGameState.get_max_success_adventure_level()` | **所有解锁门**：铲子 / 图鉴 / 花园 / 商店 / 商店扩展 / 紫卡 / 迷你 / 解谜 / 生存，外加手套与锤子模组、主菜单「冒险模式已开打」判定 | 一直停在 **50**（**「全部继承」就靠它**） |
| **本周目进度** | `GlobalGameState.get_adventure_round_cleared_level()` | **只决定「该打哪一关」**：主菜单木牌上的关卡号、`get_curr_adventure_level_to_play()` → `build_curr_adventure_level_para()` | 进二周目回到 **0**（又从 1-1 开打） |

两条口径为什么必须分开（两个方向都试过、都会坏）：

- 让「本周目进度」也去驱动解锁门 → 二周目一进档，商店 / 图鉴 / 迷你游戏全变回未解锁，等于把玩家的东西清空；
- 让「该打哪一关」挂在历史最高上 → 二周目一进档直接又被丢回 5-10（历史最高还是 50）。

> 一句话：**解锁看历史，打关看本周目。**

## 3. 周目存在哪、怎么记

| 项 | 落点 |
| --- | --- |
| 周目字段 | `GlobalGameState.curr_adventure_round`（1 = 首周目，无上限）；默认常量 `DEFAULT_ADVENTURE_ROUND` |
| 落盘 | `save_service.save_now()` 写 `"curr_adventure_round"`；读档 `data.get("curr_adventure_round", DEFAULT_ADVENTURE_ROUND)`。**老存档没有这个键 = 周目 1，不用进 `_migrate_save_data()`** |
| 每关记录 | 关卡记录里多一个键 `"Round"`（常量 `GlobalGameState.LEVEL_STATE_DATA_ROUND_KEY`）= 这一关是第几周目通过的；**没有这个键的记录一律当周目 1**（老存档、迷你 / 解谜 / 生存的记录都不带这个键） |
| 谁写 | 真通关：`MgmSaveManager.update_level_state_data_success()`（**只给冒险模式的记录写**）；调试：`GlobalGameState.success_all_adventure_level()`（写当前周目） |
| 谁读 | `GlobalGameState.get_round_on_level_state_data(记录)`（静态小工具，兼容老存档） |
| **周目 → 关卡脚本** | `LevelRegistry.get_adventure_level_id(关卡序号, 周目)`（周目 ≥ 2 且变体存在 → 返回 `_round2` 那份）；唯一消费方 `GlobalGameState.build_adventure_level_para()` |

★ **存档键里不含周目**：`101_0_0001` 这类键在哪个周目都是同一份，靠记录里的 `Round` 区分。
**二周目脚本与正本共用同一个存档键**（键由 `set_choose_level()` 按序号拼，与加载哪个文件无关）——
换键等于改掉「10 关一页、按钮序号 == 关卡序号」那条老口径，会静默挪移所有人的进度
（见 [选关界面与解锁.md](选关界面与解锁.md) 那张表下面的警告）。

## 4. 「进度清零」是算出来的，不是删出来的

`get_adventure_round_cleared_level()` = 所有冒险记录里 `IsSuccess` 且 `Round >= curr_adventure_round` 的最大关卡序号。

进二周目**只把 `curr_adventure_round` +1，一条记录都不删**，于是：

- 本周目进度自然归零（老记录的 `Round` 小于当前周目）；
- 迷你 / 解谜 / 生存的进度不受影响（它们的存档键根本不是冒险模式的）；
- `save_service._build_curr_plant()` 按历史记录重建植物 → 植物一株都不丢；
- 老存档（记录不带 `Round`）在一周目照旧算作已通关，进二周目才归零。

反过来，如果真去删记录：植物重建不出来、商店 / 图鉴 / 花园的解锁门一并对不上，而且**没有任何报错**。

## 5. 什么时候 +1

唯一入口：`MgmRewardManager.win_main_game()` 写完通关存档之后（调用 `GlobalGameState.advance_adventure_round()`）：

1. 先按「**本关是不是冒险模式 5-10**」挡一道（`_get_curr_adventure_level() == ADVENTURE_FINAL_ADVENTURE_LEVEL`）——迷你 / 解谜 / 生存通关不会碰周目；
2. `advance_adventure_round()` 自己再核一遍「**本周目 1-1 ~ 5-10 都通了**」——所以重打 5-10、调试把存档写成半通都不会误进（**幂等**：不满足就返回 false、什么都不做）；
3. 位置在跳商店 / 图鉴判定**之前**：首次通关 5-10 仍照原样先进商店（`shop_expand_stage` 2→3），商店那两跳与「进不进下一周目」各管各的。

> 通关记录（`Round`）是**进周目之前**写的：所以 5-10 那一笔带的是**旧周目**的号，这正是「本周目全通」的最后一个条件。

## 6. 二周目的玩法差异：换一套关卡脚本

二周目**不是一个绕开关卡的开关**，而是**每一关都有自己的第二套脚本**：

| 项 | 落点 |
| --- | --- |
| 二周目脚本 | `src/levels/mode_adventure/adventure_XX_YY_round2.gd`，50 关各一份（与正本同目录、同结构：`_init()` 属性 + `run_flow()` 流程） |
| 文件名规则 | 正本的 id + 后缀 `_round2`（常量 `LevelRegistry.ROUND_VARIANT_SUFFIX`）。**没有变体文件就回退正本**，所以只有想改的关才需要建 |
| 路由 | `LevelRegistry.get_adventure_level_id(关卡序号, 周目)`：`周目 >= DEFAULT_ADVENTURE_ROUND + 1` 且变体存在 → 返回变体 id |
| 触发时机 | `GlobalGameState.build_adventure_level_para()` 把 `curr_adventure_round` 传进去。**进关的路只有这一条会带上周目**（联机 / 自制关 / 探针各自 `set_choose_level()`，它们走的是已拼好的参数，不是序号） |
| 三周目及以后 | 沿用同一份 `_round2` 变体（周目无上限，但差异只有这一套） |

### 6.1 变体**不算「一关」**（注册表侧，动它之前先读这条）

`LevelRegistry` 扫目录时把 `*_round2.gd` 单独登记进 `_round_variant_path_by_id`，
**不进 `_path_by_id` / `_mode_by_id`**，因此：

- `get_level("adventure_01_01_round2")` 取得到（路由要用）；
- `ids_by_mode(ChooseLevelAdventure)` / `all_ids()` **不含**它 —— 冒险关仍然恰好 50 个、
  第 n 个 id 仍然严格等于 `adventure_<大关>_<小关>`（护栏 `test/scenarios/probe_level_registry_order.gd`）。

> 混进去会怎样：那两条「50 关 + 顺序 == 序号」的断言会立刻炸，将来若给冒险建选关页，
> 二周目副本还会当成两关出现 —— 这类错**不报错、只错位**，所以单独放一张表。

### 6.2 差异一：普通关多 10 波

写在各自 `run_flow()` 里的 `await start_battle(...)` 上（波数本来就是开战事件带进运行期的，不是字段）。

| 关 | 一周目 | 二周目 |
| --- | --- | --- |
| 普通关（10 / 20 波） | 10 / 20 | **20 / 30** |
| 1-1（教程关） | 4 | **10** |
| 4-5 砸罐子（三段各 10） | 10 ×3 | 不变 |
| 5-5 蹦极闪电战 | 20 | 不变 |
| 5-10 僵王关 | `-1`（默认 30） | 不变 |
| 3-4 / 3-7 / 3-9 / 3-10 / 5-4 / 5-7 / 5-9（`-1`，默认 30） | `-1` | 不变 |

### 6.3 差异二：开局锁定前 3 个随机卡槽

变体在 `_init()` 里写 `locked_random_card_num = 3`（字段在 `src/levels/core/level_data.gd`）。

- `_resolve_locked_random_cards()` 在 `init_para()` 里（排在 `_resolve_adventure_locked_cards()` **之后**）
  从 `GlobalGameState.curr_plant` 里 `GameRng.shuffle()` 后取前 3 株，写进 `prechosen_cards`；
- 入槽与锁定**全部复用** `CardSlotNorm.init_pre_choosed_card()`：预选卡从第 0 槽顺序填、点不动、选卡阶段取消不了，
  玩家只能编辑第 4 个槽起的部分 —— **UI 侧零改动**；
- 随机走 `GameRng`（可播种），联机 / 回放 / 回归能复现同一组卡。

三条边界（踩了就变成「整关跳过选卡」或塞进禁选植物，见 `_resolve_locked_random_cards()` 注释）：

1. **不置 `is_locked_card_slot`** —— 置了 `is_no_choose_permission()` 就返回 true，选卡界面根本不出现；
2. **至少留 1 个槽**（N 夹到 `卡槽数 - 1`），否则预选卡填满卡槽，同样退化成跳过选卡；
3. **剔除 `banned_plant_types_in_choose_card`** —— 禁选是在卡位生成之后才生效，预选这条路绕不过它。

> `refresh_pre_choosed_card_on_card_slot_change()`（夜晚关戴夫卖卡槽扩充）会把它一起重算。

### 6.4 差异三：1-1 ~ 1-3 满 5 行草皮

变体文件里把 `map_data` 直接写成满草皮图 `res://data/map/map_front.tres`
（正本分别是 `map_front_1row.tres` / `map_front_5row.tres`）。
1-4 起本来就是满草皮（不指定 `map_data`，走 `game_sences` 默认图）；5-10 是僵王关 `map_boss`，不受影响。

> **正本上的 `map_data_from_second_round` 字段仍然留着**：它是「变体缺失时回退正本」的兜底
> （`resolve_map_data()` 按 `is_from_second_round()` 换图，只有 1-1 / 1-2 / 1-3 填了它）。
> 变体都在时它不会被触发 —— 别再往它上面加新差异，新差异写变体脚本。

### 6.5 想再加一条周目差异该往哪儿写

改**变体脚本**（`adventure_XX_YY_round2.gd`）：内容型参数归关卡（`_init()` 里声明），
流程类差异归 `run_flow()`。**不要**在业务代码里按周目分支，也**不要**去改一周目的正本。
需要一个新的「服务多关」的字段就在 `src/levels/core/level_data.gd` 加（像 `locked_random_card_num` 那样，默认值保证不动现有行为）。

## 7. 玩家看到的（主菜单木牌）

- **关卡号**：`StartMenuRoot._apply_adventure_button_state()` 读**本周目进度** → 二周目进档显示 `1-1`；
- **周目标记**：同一块木牌上的 `BG_Right/Menu/Button1/LevelText/RoundText`（`_apply_adventure_round_text()`）——**一周目不显示**（玩家看不到「周目」这回事），二周目起显示 `2周目`；挂在 `LevelText` 下，所以「还没开打冒险模式」时随关卡号一起隐藏；
- **木牌贴图**换不换看**历史最高**（`ConstUnlockLevel.is_adventure_started()`）：二周目**不会**退回「开始冒险模式」那块木牌；
- 关卡内部没有「第二轮开始」的过场演出（原版也没有），差异只体现在**关卡本身**（波数 / 锁卡槽 / 草皮）；
- 通关 5-10 后回主菜单（首次那一遍会先进商店），木牌上就是下一周目的 `1-1` + `N周目`。

## 8. 怎么快速验证

**无头回归**：

- `-Scenario probe_level_registry_order`：注册表侧护栏 —— 冒险关仍恰好 50 个、第 n 位 == 第 n 关、
  **50 关都有变体且变体不进 `ids_by_mode`**、按周目取脚本（周目 2 拿变体 / 周目 1 拿正本）；
- `-Scenario probe_adventure_next_level`：二周目点木牌**真的进** `adventure_01_01_round2.gd`
  （进关脚本按周目算）、存档键仍 `101_0_0001`、地图是满草皮 `map_front`；
- `-Scenario probe_adventure_round`：周目字段默认值 / 老档兼容、两条口径分家、解锁门全保留、
  `advance` 的前置与幂等、木牌文案、1-1 ~ 1-3 换图且不泄漏到 1-4 与 5-10、端到端通关 5-10 后进第 2 周目并落盘。

**手里打**（不用真打完 50 关）：

1. 主菜单按 `Ctrl+D` 再按 `1`（通关所有冒险关卡）——写的是**当前周目**的通关，木牌随即显示 `5-10`；
2. 点木牌进 5-10，按 `Ctrl+D` 再按 `0`（立刻通关本关）→ 首次通关会先进商店，从商店退出来就是主菜单；
3. 木牌应显示 `1-1` + `2周目`；点它进的应是 1-1（`adventure_01_01_round2.gd`），
   草坪**满 5 行**、教程之后**10 波**、**前 3 个卡槽已被随机 3 株植物占住**（选卡界面只能编辑后面的槽）。

## 9. 坑

1. **别用 `get_max_success_adventure_level()` 算「该打哪一关」** —— 二周目会直接跳回 5-10。
2. **别在进二周目时「清进度」** —— 见 §4，清了就是植物 / 商店 / 图鉴一并对不上，而且不报错。
3. **`Round` 键只给冒险模式写**（`update_level_state_data_success()` 里按 `get_adventure_level_on_save_game_name() > 0` 判）：给别的模式也写不会立刻出错，但以后谁按 `Round` 过滤别的模式就会踩到。
4. **一周目里「历史最高 50」与「木牌显示 1-1」不可能同时成立**：周目 1 时所有老记录（没有 `Round` 键）都算本周目已通过。可达的「木牌显示 1-1」只有两种：新档（木牌整块不显示关卡号）与二周目起（本周目进度 0）。写断言时别造这个组合。
5. **`get_adventure_button_level()` 的「夹到 5-10」现在只剩兜底作用**：正常流程下「本周目全通」的那一瞬就会被 `advance_adventure_round()` 接手，夹取只在调试写档 / 同一帧的中间态生效。
6. **「二周目关卡」= `adventure_XX_YY_round2.gd`，不是正本**：改了 `adventure_01_01.gd` 只管一周目；
   二周目要改就去改变体（**两套脚本，双份维护** —— 一周目改了 bug 记得同步 50 份变体里的对应那几关）。
7. **变体不要写进 `ids_by_mode` / 不要给变体另立存档键** —— 前者会打破「冒险关恰好 50 关」的护栏，后者会静默挪移玩家进度（见 §3）。
8. **`locked_random_card_num` 别设 ≥ 卡槽数**（会退化成跳过整个选卡界面），也别在变体里置 `is_locked_card_slot`。
