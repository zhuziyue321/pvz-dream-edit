# 僵尸波次（开局延迟）

`ZombieManager.start_game()` 决定**第一波什么时候开始**：

| 出怪模式 / 关卡 | 第一波时机 |
|----|----|
| 普通出怪（`E_MonsterMode.Norm`） | 开局后等 `ResourceLevelData.first_wave_delay` 秒（默认 `20.0`，逐关可在 `.tres` 里覆盖），再刷第一波（`start_next_wave()` + 起进度计时器） |
| 锤僵尸模式（`E_MonsterMode.HammerZombie`） | 固定等 2 秒 —— 延迟写在出怪器自己身上（`HammerZombieManager.FIRST_WAVE_DELAY`），出怪器由本关的玩法规则注入 `ZombieManager.set_wave_source()`，本体不认识具体实现 |
| 教学演出排在开战之前时 | **不开波**：教学是关卡流程里的一段，开战前不会调 `start_game()`，僵尸一律等开战才出场（原版 1-2 在教学途中就出僵尸，当前实现不这么做） |

`first_wave_delay` 只影响第一波；后续波次仍由 `ZombieWaveRefreshManager`
（正常刷新 / 残半刷新 / 全死亡刷新）按原节奏推进。写自动化测试时注意：等待开波的超时要大于本值，
见 `test/scenarios/probe_night.gd::_wait_wave_start()`。

## 僵尸波次（波长与刷新节奏）

**波长** = 相邻两波僵尸刷新的间隔秒数。实现全在 `ZombieWaveRefreshManager`
（`src/managers/zombie_manager/zm_zombie_wave_refresh_manager.gd`），参数一律是 `@export`，改节奏不用动逻辑：

| 参数 | 值 | 原版含义 |
|----|----|----|
| `time_min_wave` | `6.0` | **最短波长** 6 秒：提前刷新最早也要等到本波开始 6 秒后 |
| `norm_refresh_time_range_in_half_refresh` | `25.0 ~ 31.0` | **最长波长** 25 + rand(0,6) 秒：普通波 / 旗帜波到点必刷新 |
| `norm_refresh_time_range_in_total_refresh` | `45.0` | **旗前波**（W9 / W19…）拖满 45 秒激活，或全场僵尸死完立即激活 |
| `refresh_threshold_range` | `0.5 ~ 0.65` | **残半刷新**比例：本波僵尸剩余总血量低于该比例时激活刷新 |
| `refresh_vacuum_time` | `2.0` | **刷新真空**：激活刷新后还要过 2 秒才真正刷出下一波（最短/最长波长已含这 2 秒） |

三条刷新路径：

- **正常刷新**：`WaveNormRefreshTimer` 到点（25~31 秒，旗前波 45 秒）→ 直接刷新。
- **残半刷新**（普通波 / 旗帜波）：本波僵尸掉血到阈值以下 → `_trigger_refresh()`。
- **全死亡刷新**（旗前波）：全场僵尸死完 → `_trigger_refresh()`。

`_trigger_refresh()` 先等 `refresh_vacuum_time` 再刷新，且**不会**让波长短于 `time_min_wave`；
多个触发同时堆积时用 `_is_trigger_valid()` 按波次去重，避免同波刷两次或被上一波的迟到触发提前开下一波。

大波（旗帜波）额外延迟：红字「一大波僵尸正在接近」出现后 **7.45 秒**才刷出僵尸
（`UIRemindWord.TIME_ZOMBIE_APPROACH`），所以旗前波拖满 = 45 + 7.45 = **52.45 秒**。

> 注意：玩家清怪快时残半 / 全死亡提前刷新会让波长贴近 6 秒下限，这是原版行为，不是 bug。
> 想改节奏只改上面这张表的 `@export` 参数（或逐关调 `zombie_multy` 出怪倍率）。

## 出怪强度与密度（调关卡难度看这里）

出怪强度一律按**原版公式**算（`ZombieWaveCreateManager.calculate_wave_power_limit()`）：
本波总战力 = `int(波数 / 3) + 1`，大波再 `× 2.5` 向下取整，最后乘关卡的 `zombie_multy` 出怪倍率。

**`zombie_multy` 一律 1**：原版没有「出怪倍率」这个旋钮，之前收尾关（1-10 / 2-10 / 3-10 / 4-10 / 5-9）
写成 2 会让大波战力翻倍（30 波关末波从 25 点变 50 点），密度明显超出原版，现已全部归 1。
唯一例外是 `adventure_05_10.tres = 3`：5-10 是原版 Zomboss 关的替代实现，本次未改。
要调难度仍只改关卡资源里的 `zombie_multy`，不提供全局削弱倍率。

出怪数量的两个下限：每波预算至少 `1`（`calculate_wave_power_limit()` 末尾 `max(1, …)`，防止某一波一只都不出）、
单波只数上限 `max_zombies_per_wave = 50`。

### 入场错开（同波僵尸不挤成一团）

原版一波僵尸是**陆续进场**的，不是同时从场外同一点涌入。本仓库在
`ZombieWaveCreateManager.wave_create_zombie()` 里按本波序号把生成点往场外错开：

| 参数 | 值 | 含义 |
|----|----|----|
| `spawn_gap_x` | `25.0` | 同波内每只僵尸往场外多挪 25 像素（约 0.6 秒的行进时间） |
| `spawn_gap_x_max` | `400.0` | 错开的总跨度上限，防止波末僵尸离场太远、把清场时间拖得过长 |

珊瑚僵尸 / 蹦极僵尸走 `spawn_index = -1`，不参与错开。

## 开局僵尸预览（选卡前的镜头右移）

关卡开场（戴夫对话 / 开场教学演出之后、选卡之前）镜头右移，草坪右侧站着一队僵尸，告诉玩家本关会来什么。
实现在 `ZombieShowInStart`（`src/managers/zombie_manager/zm_zombie_show_in_start.gd`）：
时间轴的「展示僵尸」事件调 `create_prepare_show_zombies()` 生成，
`main_game_start()` 里 `delete_prepare_show_zombies()` 删除（`look_show_zombie = false` 的关卡不放）。

**数量规则（对齐原版）**：原版预览的是本关「出怪池」的一份快照 —— 池里每个条目出一只，
而池是按权重重复列出的，所以预览里普僵占多数，总数 1-1 是 5、多数关卡约 10、x-10 大波关 15。

| 参数 | 值 | 含义 |
|----|----|----|
| `show_zombie_extra_num` | `5` | 展示总数 = 出怪类型数 + 5（再夹进范围） |
| `show_zombie_num_range` | `(5, 15)` | 展示总数上下限；类型数超过上限时按类型数取，保证每种都露脸 |
| `exclude_show_zombie_types` | `[Z002Flag]` | 旗帜僵尸不预览：原版出怪池里没有旗帜，它是大波时才单独加进波次的 |

分配方式：先给每种出怪类型 1 只（预览的作用就是让玩家看清本关有哪些僵尸），
剩下的名额按出怪权重抽样补足（用的是 `ZombieWaveCreateManager.zombie_choose_random_pool` 那一池），
所以权重高的普僵 / 路障会多出几只。`is_bungi = true` 的关卡额外补 1 只蹦极
（挂在 `ShowZombiePanel2`，不按 y 轴排序渲染）。
