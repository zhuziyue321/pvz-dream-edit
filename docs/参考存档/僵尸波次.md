# 僵尸波次（开局延迟）

`ZombieManager.start_game()` 决定**第一波什么时候开始**。

**首波时间写在关卡流程那一句开战上**（`LevelScriptBase.start_battle()` 的第 4 个位置参数，
GDScript 不支持具名实参，必须占满前三个位置：波数 / 出怪表 / 超时）：

```gdscript
await start_battle(10, zombie_list, 0.0, 36.0)   ## 1-2：36 秒
await start_battle(20, [], 0.0, 1.0)             ## 迷你 boss：1 秒（无出怪表用空数组占位）
```

参数 `-1` = 不覆盖，用关卡数据的 `ResourceLevelData.first_wave_delay`（**兜底默认 18 秒**，
即原版 `ZOMBIE_COUNTDOWN_FIRST_WAVE = 1800` tick）。落到运行期的链路：
`start_battle()` 造 `LevelTimelineEventStartBattle` → `_apply_battle_para()` 写回 `game_para.first_wave_delay`
→ 紧接着的 `main_game_start()` 里 `ZombieManager.start_game()` 现读该值。

> 表格「首波」列的数值就是 `start_battle()` 第 4 个位置参数（参数名 `first_wave_time`）的取值；本仓库 GDScript 不支持具名实参，实际用位置参数传入（占满前三个：波数 / 出怪表 / 超时）。

| 关卡 | 原版依据 | 首波 |
|---|---|---|
| 冒险普通关 / 一般挑战 | `Board::InitZombieWaves` → `ZOMBIE_COUNTDOWN_FIRST_WAVE` 1800 | **18 秒**（不传参数，用关卡数据默认值） |
| 首次冒险 1-2 | 同函数 `mLevel == 2` → `ZOMBIE_COUNTDOWN * 2` = 3600 | `first_wave_time = 36.0`（二周目变体不翻倍） |
| 冒险 1-10 / 2-10 / 3-10（迷你 boss） | `Challenge::StartLevel` 的 `IsMiniBossLevel()` → 100 | `first_wave_time = 1.0` |
| 冒险 1-5、迷你 02 / 18（坚果保龄球） | `IsWallnutBowlingLevel()` → 200 | `first_wave_time = 2.0` |
| 冒险 3-5（含二周目）、迷你 10（小僵尸大麻烦） | `IsLittleTroubleLevel()` → 200 | `first_wave_time = 2.0` |
| 冒险 4-10（暴雨夜） | `IsStormyNightLevel()` → 200 | `first_wave_time = 2.0` |
| 冒险 5-5（蹦极闪电战） | `IsBungeeBlitzLevel()` → 200 | `first_wave_time = 2.0` |
| 迷你 06 Invisighoul / 迷你 11 传送门之战 | `GAMEMODE_CHALLENGE_INVISIGHOUL` / `PortalStart()` → 200 | `first_wave_time = 2.0` |
| 迷你 12 排山倒海 | `GAMEMODE_CHALLENGE_COLUMN` → 2400 | `first_wave_time = 24.0` |
| 迷你 13 雪橇狂欢 | `GAMEMODE_CHALLENGE_BOBSLED_BONANZA` → 4500 | `first_wave_time = 45.0` |
| 迷你 16 坚不可摧 | 点「开始战斗！」后 `mZombieCountDown = 10` | `first_wave_time = 0.1` |
| 迷你 19 蹦蹦舞会 | `GAMEMODE_CHALLENGE_POGO_PARTY` → 5500 | `first_wave_time = 55.0` |
| 冒险 5-10 / 迷你 20（僵王） | `IsFinalBossLevel()` 不在首波特判里 | 18 秒（默认） |
| 迷你 05 / 09（僵尸迷阵） | 原版 200，但本仓库不出自然波（不走 `start_battle`） | 无 |
| 冒险 2-5、迷你 15（锤僵尸） | `IsWhackAZombieLevel()` → 200 | 2 秒，写在出怪器 `HammerZombieManager.FIRST_WAVE_DELAY` 上，不读 `first_wave_time` |
| 生存模式第 2 轮起 | `IsSurvivalMode() && mSurvivalStage > 0` → `ZOMBIE_COUNTDOWN_RANGE` 600 | 6 秒（`ZombieManager.SURVIVAL_NEXT_ROUND_FIRST_WAVE_DELAY`，优先级高于关卡值） |
| 教学演出排在开战之前时 | —— | **不开波**：教学是关卡流程里的一段，开战前不会调 `start_game()`（原版 1-2 在教学途中就出僵尸，当前实现不这么做） |

`first_wave_delay` / `first_wave_time` 只影响第一波；后续波次仍由 `ZombieWaveRefreshManager`
（正常刷新 / 残半刷新 / 全死亡刷新）按原节奏推进。写自动化测试时注意：等待开波的超时要大于本值，
见 `test/scenarios/probe_night.gd::_wait_wave_start()`。

## 僵尸波次（波长与刷新节奏）

**波长** = 相邻两波僵尸刷新的间隔秒数。实现全在 `ZombieWaveRefreshManager`
（`src/managers/zombie_manager/zm_zombie_wave_refresh_manager.gd`），参数一律是 `@export`，改节奏不用动逻辑：

| 参数 | 值 | 原版含义 |
|----|----|----|
| `time_min_wave` | `6.0` | **最短波长** 6 秒：提前刷新最早也要等到本波开始 6 秒后 |
| `norm_refresh_time_range_in_half_refresh` | `25.0 ~ 31.0` | **最长波长** 25 + rand(0,6) 秒：普通波 / 旗帜波到点必刷新（关卡可用 `wave_norm_time_range` 覆盖，见下） |
| `norm_refresh_time_range_in_total_refresh` | `45.0` | **旗前波**（W9 / W19…）拖满 45 秒激活，或全场僵尸死完立即激活 |
| `refresh_threshold_range` | `0.5 ~ 0.65` | **残半刷新**比例：本波僵尸剩余总血量低于该比例时激活刷新 |
| `refresh_vacuum_time` | `2.0` | **刷新真空**：激活刷新后还要过 2 秒才真正刷出下一波（最短/最长波长已含这 2 秒） |

取值口径对齐原版的**整数 tick**（`TICKS_PER_SECOND = 100`）：`_random_norm_refresh_time()` 把区间换算成
tick 数后 `randi_range`，所以默认区间取到的是 **25.00 ~ 30.99 秒**（原版 `2500 + Rand(600)` 是 0~599 tick），
端点相同的区间（旗前波 45 秒 / 下面三关的 7.5 秒）直接取该值、不消耗随机数。

**短波长的关卡**：原版在 `SpawnZombieWave()` 之后对「小僵尸大麻烦」（`IsLittleTroubleLevel`：
小游戏 `GAMEMODE_CHALLENGE_LITTLE_TROUBLE` + **冒险 `mLevel == 25` 即 3-5**）、「排山倒海」
（`GAMEMODE_CHALLENGE_COLUMN`）、「坚不可摧」（`GAMEMODE_CHALLENGE_LAST_STAND`）
写死 `mZombieCountDown = 750` tick = **7.5 秒**。本仓库用关卡数据字段覆盖：

| 字段 | 默认 | 说明 |
|----|----|----|
| `ResourceLevelData.wave_norm_time_range` | `(25.0, 31.0)` | 普通波 / 旗帜波波长区间；下面 5 个脚本在 `_init()` 里写 `Vector2(7.5, 7.5)`，由 `ZombieWaveRefreshManager.apply_wave_norm_time_range()` 在初始化时应用 |

覆盖为 `Vector2(7.5, 7.5)` 的脚本：`minigame_10_mini_zombie`、`minigame_12_column`、
`minigame_16_last_stand`、`adventure_03_05`、`adventure_03_05_round2`（冒险 3-5 是原版
`IsLittleTroubleLevel` 的冒险分支，二周目同口径）。旗前波的 45 秒不受本字段影响。

三条刷新路径：

- **正常刷新**：`WaveNormRefreshTimer` 到点（25~31 秒，旗前波 45 秒，短波长关卡 7.5 秒）→ 直接刷新。
- **残半刷新**（普通波 / 旗帜波）：本波僵尸掉血到阈值以下 → `_trigger_refresh()`。
- **全死亡刷新**（旗前波）：全场僵尸死完 → `_trigger_refresh()`。

`_trigger_refresh()` 先等 `refresh_vacuum_time` 再刷新，且**不会**让波长短于 `time_min_wave`；
多个触发同时堆积时用 `_is_trigger_valid()` 按波次去重，避免同波刷两次或被上一波的迟到触发提前开下一波。

大波（旗帜波）额外延迟：红字「一大波僵尸正在接近」出现后 **7.45 秒**才刷出僵尸
（`UIRemindWord.TIME_ZOMBIE_APPROACH`），所以旗前波拖满 = 45 + 7.45 = **52.45 秒**。

> 注意：玩家清怪快时残半 / 全死亡提前刷新会让波长贴近 6 秒下限，这是原版行为，不是 bug。
> 想改节奏只改上面这张表的 `@export` 参数（或逐关调 `zombie_multy` 出怪倍率）。

## 出怪强度与密度（调关卡难度看这里）

出怪强度一律按**原版公式**算（`ZombieWaveCreateManager.calculate_wave_power_limit()`）：
本波总战力 = `int(波数 / 3) + 1`，大波再 `× 2.5` 向下取整，最后乘关卡的 `zombie_multy` 出怪倍率。

**`zombie_multy` 一律 1**：原版没有「出怪倍率」这个旋钮，之前收尾关（1-10 / 2-10 / 3-10 / 4-10 / 5-9）
写成 2 会让大波战力翻倍（30 波关末波从 25 点变 50 点），密度明显超出原版，现已全部归 1。
唯一例外是 `adventure_05_10.tres = 3`：5-10 是原版 Zomboss 关的替代实现，本次未改。
要调难度仍只改关卡资源里的 `zombie_multy`，不提供全局削弱倍率。

出怪数量的两个下限：每波预算至少 `1`（`calculate_wave_power_limit()` 末尾 `max(1, …)`，防止某一波一只都不出）、
单波只数上限 `max_zombies_per_wave = 50`（原版 `MAX_ZOMBIES_IN_WAVE`）。

### 一波怎么凑出来（对齐原版 `Board::PickZombieWaves()`）

原文基准：`../PvZ-Portable-main/src/Lawn/Board.cpp:534-768`（`PickZombieWaves` / `PickZombieType` /
`PutInMissingZombies`）+ `src/Lawn/Zombie.cpp:80-113`（`gZombieDefs[]`）。
实现全在 `ZombieWaveCreateManager.get_curr_wave_zombie_list()`，五条规则：

| 规则 | 原版 | 本仓库落点 |
| - | - | - |
| **大波先普僵后旗帜** | 先放 `aPlainZombiesNum = min(本波点数, 8)` 只普僵，再放 1 只旗帜僵尸 | `get_curr_wave_zombie_list()` 大波分支（`calculate_base_wave_points()` 算本波点数） |
| **大波普僵数不是一律 8** | 第 10 波 4 只、第 20 波 7 只、第 30 波起封顶 8 只（点数 = `波数 / 3 + 1`） | 同上，`mini(点数, 8)`；改它要连带改 `probe_pogo_party` 的期望 |
| **买不起的类型先排除再抽** | `PickZombieType()` 里 `theZombiePoints < mZombieValue` 直接跳过，再按权重抽 | `pick_zombie_within_power(剩余点数)`；一只都买不起时退回「用普僵补余额」（原版这时会从空权重表落到 0 号普僵） |
| **最后一波补齐本关全部种类** | `PutInMissingZombies()`：冒险关最后一波把本波还没出现过的类型各补一只（雪人除外） | `_put_in_missing_zombies()`，**只对冒险模式**生效 |
| **首次允许波次** | `mFirstAllowedWave`：`波次下标 + 1 < 该值` 的类型不进随机池 | 注册表 `ZOMBIE_FIRST_ALLOWED_WAVE`（撑杆 / 铁门 / 橄榄球 / 舞王 = 5，潜水 / 冰车 / 雪橇 / 海豚 / 小丑 / 气球 / 矿工 / 跳跳 / 扶梯 / 投篮 = 10，伽刚特尔 = 15，普僵 / 路障 / 铁桶 / 读报 = 1） |
| **二周目点数更高** | 已通关冒险后 `aZombiePoints = 波数 * 2 / 5 + 1`（1-5 例外，仍走首周目公式） | `calculate_base_wave_points()` 里的 `is_second_round_adventure()`；大波普僵数跟着它走 |
| **新登场僵尸必定露面** | `GetIntroducedZombieType()`：本关 `mStartingLevel` 匹配的类型必定出现在**中间波**（每轮波数 / 2）与**最后一波**，矿工 / 气球提前到第 7 波起 | `get_introduced_zombie_type()` + `is_introduced_zombie_wave()`；注册表 `ZOMBIE_STARTING_LEVEL`（1-3 路障、1-6 撑杆、1-8 铁桶、2-1 读报、2-3 铁门、2-6 橄榄球、2-8 舞王、3-3 潜水、3-6 冰车、3-8 海豚、4-1 小丑、4-3 气球、4-6 矿工、4-8 跳跳、5-1 蹦极、5-3 扶梯、5-6 投篮、5-8 巨人） |

「新登场僵尸」只认**本关出怪表里也有**的类型 —— 原版那几条排除就自动成立：鸭子圈（原版显式跳过，3-1 表里本来没有）、
蹦极（本仓库走 `is_bungi` 的大波空投，不进出怪表）、雪人（不进自然池）。它**不受「首次允许波次」约束**，
这正是原版「新僵尸提前来一只给你看」的设计（例：5-8 第 11 波必有 1 只巨人，虽然巨人首次允许波次是 15）。

**权重在冒险模式里是恒定的**：原版 `PickZombieType()` 的权重衰减（普僵 ×1/10、路障 ×1/4）只在
**生存模式**按已完成旗帜数生效，冒险模式直接用 `mPickWeight` 原值。本仓库此前那套
「普僵 `4000-(波-5)*180`、路障 `4000-(波-5)*150` 随波衰减」没有原版依据，已删除 ——
所以后期波次会回到「普僵 / 路障仍是主体」，与原版一致。要调难度请调 `zombie_multy` 或出怪密度倍率。

`首次允许波次`、`新登场僵尸`、`最后一波补齐` 只对**冒险模式**（`game_mode == ChooseLevelAdventure`）生效：
小游戏 / 生存 / 我是僵尸在原版里各自另写一套出怪规则（原版还专门豁免了蹦蹦舞会 / 全面冻结 /
蹦极闪电战），本仓库这些关卡的出怪表已经按各自规则写好，再套一层会让波数少的关卡前几波空场
（例：蹦蹦舞会的出怪表只有蹦蹦，首次允许波次是 10）。植物僵尸那几个「第 10 波起」的类型不受此限，
任何模式都生效（原版 ZomBotany 硬规则）。

### 为什么不改「开局预生成全波次表」

原版在 `Board::InitZombieWaves()` 里一次性算完整关的 `mZombiesInWave[][]`，刷怪时只是把当前波搬上场；
本仓库是**逐波现算**。两者对出怪**构成**没有可观察差异（每波只算一次、按顺序推进），
真正会变的只有下面这些「按当时局势才成立」的钩子，而它们恰恰是本仓库比原版多出来的玩法：

- `before_wave_spawn`：关卡按局势改出怪密度（例：全面冻结融冰后普僵变多）；
- `set_banned_spawn_rows`：隐形关前几波禁最下行；

预生成要在开战时就把 30 波的类型全定死，上面两条只能失效或退化成"重算该波"（等于没预生成）。
所以**刻意保留逐波现算**。若哪天真要预生成，先改造这两个钩子的时序，别只改出怪管理器。


### 入场错开（同波僵尸不挤成一团）

原版一波僵尸是**陆续进场**的，不是同时从场外同一点涌入。本仓库在
`ZombieWaveCreateManager.wave_create_zombie()` 里按本波序号把生成点往场外错开：

| 参数 | 值 | 含义 |
|----|----|----|
| `spawn_gap_x` | `25.0` | 同波内每只僵尸往场外多挪 25 像素（约 0.6 秒的行进时间） |
| `spawn_gap_x_max` | `400.0` | 错开的总跨度上限，防止波末僵尸离场太远、把清场时间拖得过长 |

珊瑚僵尸 / 蹦极僵尸走 `spawn_index = -1`，不参与错开。

## 开局僵尸预览（选卡前的镜头右移）

关卡开场（戴夫对话 / 开场教学演出之后、选卡之前）镜头右移，草坪右侧站着一队僵尸，告诉玩家本关会来什么。
实现在 `ZombieShowInStart`（`src/managers/zombie_manager/zm_zombie_show_in_start.gd`）：
时间轴的「展示僵尸」事件调 `create_prepare_show_zombies()` 生成，
`main_game_start()` 里 `delete_prepare_show_zombies()` 删除（`look_show_zombie = false` 的关卡不放）。

规则整体对齐原版 `CutScene::PlaceStreetZombies()` / `PlaceAZombie()`
（`../re-plants-vs-zombies-main/Lawn/CutScene.cpp`）：

**数量**：原版统计**全波次出怪表**里每种僵尸出现了几次（`aZombieTypeCount`），再按
`预览数 = clamp(条目数 × 容量 ÷ 总条目数, 1, 条目数)` 分配（容量 = `aPreviewCapacity`，默认 10，
小僵尸大麻烦 15；原版暴雨夜冒险 / 迷你 boss 为 18，本仓库暂无这两类关卡）。

本仓库没有预生成的全波次出怪表（每波按战力上限运行时随机），所以用出怪权重折算条目数：
`条目数 = clamp(round(权重 ÷ spawn_count_weight_unit), 1, 容量)`（普僵 4000 → 4 条）。

| 参数 | 值 | 含义 |
|----|----|----|
| `preview_capacity` | `10` | 预览容量（原版 `aPreviewCapacity`） |
| `preview_capacity_mini_zombie` | `15` | 小僵尸大麻烦的容量（用关卡 `get_zombie_init_para_extra()` 的 `IsMiniZombie` 判定） |
| `spawn_count_weight_unit` | `1000.0` | 权重 → 出怪表条目数的换算单位 |
| `preview_grid` | `(5, 5)` | 预览占位网格（原版 5x5） |
| `exclude_show_zombie_types` | `[Z002Flag]` | 旗帜僵尸不预览：原版出怪池里没有旗帜，它是大波时才单独加进波次的 |

特殊规则（原版同款）：蹦极 / 雪橇每种最多 1 只；泳池关必定预览一只鸭子僵尸（出怪表里没有也补）；
雪人只在暴雨夜、雪橇只在雪橇狂欢关预览 —— 本仓库出怪表按关卡配，这两类不会出现在别关，等价于原版判断。
