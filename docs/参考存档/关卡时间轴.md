## 关卡时间轴（关卡流程 = 一条事件轴）

> ⚠️ **本文记录的是关卡脚本化之前的写法**（关卡 = `.tres` + 挂一条 `timeline` 事件轴）。
> 现在关卡 = 一个 `.gd`（属性写 `_init()`、流程写 `run_flow()`，见 `LevelScriptBase`），
> 老 `.tres` 关卡只剩 `LevelTimelineManager` 里的兼容分支。
> 文中提到的 `tool_inline_*.gd` / `probe_timeline*.gd` **已随老时间轴资源一并删除**，
> 别再照着跑；开场流程改由 `probe_tutorial` / `probe_4_5_flow` 覆盖。
>
> **2026-10-05：`LevelPrefabs` 门面已拆掉** —— 原来那层 `prefab.xxx()` 转发并进了
> `LevelScriptBase`，流程方法与 `init_level_items` / `is_curr_level_success` 这些**平级**：
> 关卡脚本里直接写 `await show_zombie()`，不再有 `prefab.` 前缀（正文里若还有就是漏改）。
>
> **2026-10-06：判定钩子 `should_run_tutorial()` 已删** —— 教程「播不播」不再靠覆写钩子，
> 关卡脚本自己查通关记录：`LevelScriptBase.is_curr_level_success()`（本关）/
> `is_level_success(关卡存档名)`（别的一关）。

**关卡流程就是一条时间轴**：戴夫对话 / 选卡 / 开战 / 清场……都是轴上的一个事件，  
**上一个事件结束（await 到它的完成条件）才开下一个**。

**一种事件 = 一个脚本**：每种事件有自己的资源脚本（继承 `ResourceLevelTimelineEvent`），
脚本 `@export` 出来的字段就是**这个事件的参数**，脚本实现的 `run(main_game)` 就是**这个事件的行为**。
执行器（`LevelTimelineManager`）**不认识任何具体事件类型**，只按数组顺序 `await event.run(main_game)`。

**每个关卡文件里都有一条显式时间轴**：全部 94 个关卡（冒险 53 / 解谜 20 / 生存 15 / 小游戏 6）
都把时间轴连同它的事件写进了自己的 `.tres`（`[sub_resource]` 段 + `timeline = SubResource(...)`）——
**一个关卡 = 一个文件**，编辑器里可见可调，复制 / 分享关卡文件就带齐全部配置。
`ResourceLevelData.build_default_timeline()` 保留着，只当「新关卡留空 `timeline`」时的等价兜底：
留空就按关卡开关生成一条一样的轴，老关卡 / 手搓的新关卡不用先配轴就能跑。

**轴里只写本关真实生效的步骤**：条件不满足时 `run()` 直接 return 的事件（空转步骤）不生成 ——
留着只会让人误以为本关有这一步。判据就是各事件脚本 `run()` 的提前返回条件，
做成关卡上的三个方法（`ResourceLevelData`）：

| 事件                      | 本关一定空转（不生成）的判据                                                        |
| ----------------------- | ---------------------------------------------------------------- |
| 戴夫推销 `DaveSell`        | 商店已解锁 / 非冒险模式 / 冒险关卡序号 < 2-2 / `can_choosed_card` 为 false（见 `is_dave_sell_possible()`） |
| 戴夫对话 `DaveDialog`      | 本关一轮都没有对话（`has_dave_dialog_on_any_round()` 为 false：字段空）                        |
| 保龄球红线 `BowlingStripe` | `is_bowling_stripe` 为 false（红线节点只在保龄球关创建）                                 |

运行时才定的条件（商店是否已解锁、卡槽是否已满、金币够不够、对话是否只在首次通关播）
**不算空转**，事件照旧留在轴上，由 `run()` 自己判断。

| 文件                                                                                           | 职责                                       |
| -------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `src/levels/core/level_timeline_data.gd`（`ResourceLevelTimelineData`）   | 时间轴本体：`events` 数组 + `is_one_shot`      |
| `src/levels/core/level_timeline_event.gd`（`ResourceLevelTimelineEvent`） | 事件**基类**：通用字段 + 等待工具                                |
| `src/levels/core/timeline_event/*.gd`                                   | **每种事件一个脚本**（参数 + 行为，见下表）             |

| `src/managers/level_timeline_manager.gd`（`LevelTimelineManager`）                          | 执行器：按下标 `await` 每个事件的 `run()`，不分派类型      |

**没有集中的事件类型枚举**：事件的身份就是**事件脚本的类名**（`LevelTimelineEventDaveDialog` …），
中文说明写在事件脚本自己的注释里、调试看关卡文件里这条事件填的 `note`。
以前 `ConstLevelData.E_LevelEventType` + `LevelEventTypeNameMap` 那一套（只服务于日志）已删除 ——
加一种事件不用再去中枢登记。

> 直接当参数传给 `start_battle(20, [1, 3, 5])`，`_init()` 里不再预置这两个字段 ——
> 翻 `run_flow()` 就能一眼看出本关几波、出哪些僵尸（`src/levels/mode_*/` 下所有关卡脚本都是这个写法）。
> 代价：**预览僵尸（`show_zombie`）跑在开战之前**，它按关卡数据上的默认出怪表生成，
> 所以本关出怪表与默认表差别大时，预览里的僵尸会和实际波次不完全一致。

**加一种事件 = 新建一个脚本 + 基类加一个同名方法**：继承 `ResourceLevelTimelineEvent`，
`@export` 自己的参数、实现 `run()`，再在 `LevelScriptBase` 上加一个包它的同名方法
（`new()` 出事件 → 填参数 → `await _run_event(event, "备注")`）。
执行器、枚举分发、通用事件资源都不用动，也不用去任何地方登记事件类型。

**新增脚本后要先跑一次 Godot**：带 `class_name` 的新脚本要进了全局类表才能被 `LevelScriptBase` 引用，
下一次 Godot 启动前引用它会报 `Identifier "Xxx" not declared`（见 [规范细则存档 E-01](规范细则存档.md) 的同类坑）。

**「这一刻播什么」由流程现场给，事件只留行为型参数**：
戴夫对话这类**关卡内容**现在由 `run_flow()` 现场构造并当参数传进去 ——
`await dave_dialog(_build_dave_dialog())`，
流程一眼就看出这一句在播什么，不用回头翻 `_init()` 里的字段赋值。
（关卡脚本迁移自 `.tres`，构造代码原样搬进了同文件的 `_build_*()` 方法里，见各关卡脚本末尾。）
**不传时才回落到关卡字段**（`crazy_dave_dialog` / `crazy_dave_dialog_next_round`），
老 `.tres` 关卡与没改过的脚本照旧。
事件上只留流程参数（`wait_time`、`timeout` 这类）与「流程传进来的内容」。

**教学演出同样内联在关卡脚本里**（2026-10-06 起）：提示台词直接写在 `run_flow()` 的那段教学里，
没有教程数据资源 —— `ResourceTutorialData / ResourceTutorialStep`、`TutorialManager`、
关卡字段 `tutorial_data`、`has_tutorial()` 一并删除，也不再有「本关有教程」的声明。

**对话（含每句台词）也内联在关卡脚本里**：由 `_build_dave_dialog()` 现场构造，
不再引用 `data/dave/dialog/*.tres` + `dialog_detail/*.tres`。
改台词直接改关卡脚本里那一段。关卡脚本同样不再给 `crazy_dave_dialog` 字段赋值，
也不需要任何「本关有对话」的声明 ——「有对话就不推销」由关卡脚本自己避开
（2-2 ~ 3-4 里没对话的关才写 `await dave_sell_card_slot()`）。
多轮关卡（4-5）三批对话各一个方法（`_build_dave_dialog_1/2/3`），由 run_flow 按批传，
不再走 `crazy_dave_dialog_next_round` 按轮次取。
对话原文件**保留没删**：`dialog_detail/store/*` 还被商店那边用着（且这些文件 git 未跟踪，无备份）。

**开战的结束条件写在脚本里**（`LevelTimelineEventStartBattle._is_battle_finished()`），不在事件上配：

- 砸罐子（`is_pot_mode`）：罐子全砸开（`curr_pot_num == 0`）+ 场上僵尸清空
- 出怪关：最后一波刷完（`is_end_wave`）+ 场上僵尸清空（清场那一刻原流程推 `create_trophy`）

`timeout` 是兜底秒数（`<= 0` 一直等，砸罐子这种要等玩家自己砸完的就是一直等）。

**开波只开一次**：第一波由开战（`main_game_start()` → `ZombieManager.start_game()`）统一开，
由 `ZombieManager.is_first_wave_started` 兜底只开一次（多轮切轮时重置）。
流程里没有「不等开战先开第一波」的事件了 —— 要提前出怪就把 `start_battle()` 提前。

**两种跑法**（时间轴的 `is_one_shot`）：

- `false`（默认）：**每轮重跑一遍**，一轮 = 这条轴，轮与轮之间由 `MainGameManager` 摆场
  （生存模式 10 轮就是这种）。
- `true`：**整关只跑一遍**，一条轴把整关都写进去，跨轮继续往下跑
  （砸罐子 4-5 的三批：批与批之间用 `ClearField` 事件摆下一批）。
  这时 `MainGameManager.start_curr_round_game()` 会跳过摆场和重跑，交给轴上的清场事件。

事件上有三个通用开关：`is_enabled`（关掉 = 把这一步从轴上摘掉）、
`is_first_round_only`（多轮关卡只在第一轮跑）、`note`（编辑器备注，不参与运行）。

**不配时间轴也能跑**：`ResourceLevelData.timeline` 留空时，`build_default_timeline()`  
按关卡现有开关（`look_show_zombie` / `can_choosed_card` / `is_show_ready_set_plant` …）生成一条  
**等价的默认时间轴**（`is_one_shot = false`，每轮重跑）：  
`戴夫推销 → 戴夫对话 → 开场教程 → 保龄球红线 → 展示僵尸 → 选卡 → 准备安放植物 → 开战`。  
所以一百多个老关卡一个字段都不用改就照旧跑。

**怎么改一关的流程**：在关卡资源的 `timeline` 里挂一条 `ResourceLevelTimelineData`，  
按想要的顺序摆事件（每个 `sub_resource` 的 `script` 指向对应事件脚本）即可。

## 已固化到关卡资源上的时间轴（**内联**在关卡 `.tres` 里）

13 个多轮特殊关已经把时间轴**内联**进关卡自己的 `.tres`：`timeline` 字段是一个 `SubResource`，
它和它的事件都是关卡文件里的 `[sub_resource]` 段，编辑器里展开 `timeline` 就能改。

**一个关卡 = 一个文件**（为了自定义关卡）：复制 / 分享一个关卡 `.tres` 就带齐全部配置，
也不用担心改一关时波及同族的其它关（生存 10 关各自一份副本，不再共用一份时间轴文件）。

| 关卡文件                                                          | 事件数 | 事件序列                                                                        |
| ------------------------------------------------------------- | --- | --------------------------------------------------------------------------- |
| `mode_adventure/adventure_04_05.tres`                         | 8   | 戴夫对话 → 开战 → 戴夫对话 → **清场** → 开战 → 戴夫对话 → **清场** → 开战（`is_one_shot = true`，整关跑一遍） |
| `mode_puzzle/puzzle_pot_10.tres`（花瓶终结者无尽）                     | 1   | 开战（`is_one_shot = false`，无尽每轮重跑一遍）                                              |
| `mode_puzzle/puzzle_zombie_10.tres`                           | 6   | 同上（本关红线真的会画：`is_bowling_stripe = true`）                                      |
| `mode_survival/survival_flag_06_day.tres` … `15_roof.tres`（10 关各一份） | 8   | 戴夫推销 → 戴夫对话 → 教程 → 红线 → 展示僵尸 → 选卡 → 准备安放植物 → 开战（每轮重跑）                        |

4-5 是这套设计的样板：**一条轴把整关三批都写全**，
`is_one_shot = true` 让它跨批次继续跑（不会被切轮重启），
批与批之间的「摆下一批」是显式的**清场事件**，不再藏在 `MainGameManager` 里。

固化时的几条约定（照抄现有文件即可）：

- **只写本关真实生效的步骤**。默认轴为了通用会带一堆按关卡开关跳过的步骤，
  固化到具体关卡上时**该删就删**，轴要能一眼看出这关在干什么。
  ⚠️ 但删除前先确认这一步在本关**真的**空转：戴夫推销（非冒险模式直接 `return`）、
  开场教程（没教程数据）、保龄球红线（`is_bowling_stripe = false`）这几步对砸罐子 / 生存关都是空转；
  「戴夫对话」在本关有对话（`has_dave_dialog_on_any_round()`，或对话在 run_flow 里现场给）时
  **不**是空转，别删（4-5 三批对话就靠它）。
- 删不掉 / 不想删的步骤就保留，在 `note` 里标「本关空转」—— 生存关那 8 步目前就是这种保守版，
  与 `build_default_timeline()` 逐条一致，行为零风险（生存模式的多轮本次没动）。
- **一关一份，内联进关卡文件**（不再建共用的时间轴 `.tres`）。同族的关（10 个生存关、
  3 个砸罐子无尽关）各自持有一份副本，改哪关都不影响别人。
