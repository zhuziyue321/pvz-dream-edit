### <span style="background-color:rgb(255, 238, 173)">身体(Body):</span>

- 僵尸身体,将僵尸的精灵节点全都放在`BodyCorrect`节点下,移动`BodyCorrect`节点,修正位置,Body节点位置默认为(0,0),在修改角色大小时,不需要移动Body位置

### <span style="background-color:rgb(255, 238, 173)">临界值组件(CriticalValueComponent):</span>

- 默认临界值取 `DeathBoundary` —— 跟随角色自身的死亡临界值 `hp_component.death_hp`（僵尸由 `HpStageChangeComponent` 写成 `boundary_value_hp` 的最后一项，默认本体满血的 1/3，也就是原版"掉头"那一下）
- **小推车规则（原版）**：本体血量到临界值以下（= 已掉头）或已进入死亡流程的僵尸**不触发小推车**，落点在 `lawn_mower.gd::start_trigger_filter()`
- 改成 `Ratio` / `Fixed` 自定义临界值时**必须**高于 `death_hp`，否则僵尸先死、永远进不了临界值，组件 `_ready` 会提示一次；也只有这类配置下"自动掉血"才有掉血窗口（默认 `DeathBoundary` 进临界值与死亡是同一刻）
- 查询接口：`is_below_critical()` / `is_hp_below_critical(hp)` / `get_critical_value()`；宿主转发只读属性 `is_below_critical_value`
- 事件：`signal_below_critical`（进入）/ `signal_drain_hp`（每次掉血）/ `signal_leave_critical`（回到临界值之上）；状态由宿主把 `hp_component.signal_hp_loss` 连到 `on_hp_loss()` 同步，需要额外响应时在 `ready_norm_signal_connect()` 里连（K-05 第 6 条）
- 掉血走血量组件公开接口 `Hp_loss()`（`AttackMode.Real`，不播放受击音效），死亡与掉手\掉头仍按正常流程，禁止绕过血量组件
- 默认已挂在 `zombie_base.tscn`，所有僵尸继承；不需要的僵尸在自己场景里删掉该节点或关掉 `is_drain_hp` 即可（K-01 可独立增删）

### <span style="background-color:rgb(255, 238, 173)">丢车保护（小推车触发后本行不出怪）:</span>

- **机制（原版）**：某行的小推车被触发（= 玩家丢车）后，该行在一段时间内**不再被选为出怪行**，给玩家补防的窗口；全局默认开启，不分关卡与模式
- 链路：`LawnMover._start_mower()` → `EventBus.push_event("lawn_mover_triggered", [lane])` → `ZombieChooseRowSystem.on_lawn_mover_triggered()`
  - `_start_mower()` 是**唯一入口**，子类（泳池清洁器 / 屋顶清洁器）重写的是 `_do_start_mower()`，所以三种推车都自带保护；新增推车类型时不要另起入口
- 保护时长：`ZombieChooseRowSystem.mower_protect_time`（默认 15 秒，`<= 0` 关闭保护）；剩余时间存 `lane_protect_time_left`，由该系统自己的 `_process(delta)` 递减（跟随游戏时间，暂停时不流逝）
- 选行过滤：`calculate_smooth_weights()` 把保护中的行权重直接归零；`select_spawn_row()` 的兜底分支同样跳过保护中的行
- **兜底的兜底**：所有能出怪的行都在保护中时（例如全场丢车），忽略保护再选一次 —— 保护只负责让行「少出怪」，不能让整波停刷
- 只影响**后续波次的选行**：当前波已经生成、正在场上走的僵尸不受影响（波次是在波次开始时一次性生成并定行的）；蹦极僵尸按植物格子选目标，也不走选行
