## 0. 判等标准（先看这一节，否则后面全读错）

**以「视觉 / 逻辑相同」为判等标准**，不要求两边的数字或代码结构长得一样。三条换算规则：

| 情况 | 换算方式 |
| - | - |
| 时间类 | 原版固定 **100 tick/秒**（`SexyAppBase.cpp` 里 `mFrameTime = 10`），所以 `tick ÷ 100 = 秒`；例：`mLaunchRate = 150` = 1.5 秒 |
| 速率类 | 原版「每 N tick 一次 × M 点」→ 先折成**每秒**再比；例：`4 点 / 4 tick` = 100 点/秒 |
| 随机幅度 | 比**相对量**不比绝对值；例：`RandRangeFloat(0.23, 0.37)` 均值 0.3 → 相对区间 0.77~1.23 |
| 串联计时器 | 原版「一个计数器同时管冻结 + 减速」→ 本作两个计时器串联时，本作的**第二个时长 = 原版总时长 − 冻结时长** |

判等不通过、但**两条路径实现方式不同**的（例：冰车压地刺），在 §5 单列，不算偏差。

## 2. 逻辑逐项对照

### 2.1 更新驱动

原版：所有角色在 `Board::Update()` 里逐 tick 调 `Update()`，状态推进靠 `mStateCountdown` / `mPhaseCounter` 递减。
本作：每个角色 `_physics_process()` / `_process()` + 组件，动画用 `AnimationTree` 状态机（转换条件写 `is_xxx` 布尔或由脚本 `request_anim_state()` 点名）。

→ **不等价的地方**：本作没有全局 tick，计时用 `Timer` / `delta`。所以凡是"第 N tick 发生"的原版细节（动画帧对齐、`mShootingCounter` 倒计时）在本作表现为"第 N 秒"或"动画方法轨事件"，判等时看**表现是否一致**，不看帧号。

### 2.2 索敌

- 原版植物：`GetRectOverlap(攻击矩形, 僵尸矩形) >= -extraRange`，权重 `-zombieRect.mX`（**最靠前**优先）；僵尸是否同行靠 `mRow` 比对，巨人 / 僵王特判跨行。
- 原版僵尸：`GetZombieAttackRect()` 与植物矩形重叠 **≥ 20** 才咬；格子内"该吃谁"由 `GetTopPlantAt(TOPPLANT_EATING_ORDER)` 决定：**南瓜 → 普通 → 底层（花盆 / 睡莲）**。
- 本作：`DetectComponent` 的一组 `Area2D` 检测框 + `CanAttackStatusComponent` 位掩码 + 归属阵营过滤；"该吃谁"由 `DetectTargetStrategy.get_first_be_hit_plant_in_cell()` 决定：**Shell（南瓜）→ Norm → Imitater → Down → Float**。
- 原版那一堆 `if seedType == ...` 的白名单（矿工只咬未出土土豆雷、撑杆跳过、跳跳跳过…）在本作拆成三条路：**掩码**（`can_attack_plant_status` / `can_attack_zombie_status`）、**检测组件开关**（`is_attack_ladder_plant` / `is_ignore_ladder`）、**角色脚本重写**（窝瓜进入 look 就 `hurt_box_component.disable_component()`）。

> 多出来的 `Imitater` / `Float` 两档是**有意扩展**（模组友好），原版只有 3 档；对原版 49 种植物不产生行为差异。

### 2.3 攻击 / 发射

| | 原版 | 本作 |
| - | - | - |
| 节奏 | `mLaunchCounter` 每 tick 减 `mLaunchRate`，到 0 触发 | `BulletAttackCdTimer`（`attack_cd` 秒）→ `request_one_shot()` |
| 出弹时机 | `UpdateShooting()` 在动画帧上 `Fire()` | 动画方法轨 `on_anim_event("shoot")` → `shoot_burst()` |
| 首发延迟 | `RandRangeInt(0, mLaunchRate)`（豌豆 0~1.5 秒） | `randf_range(0, wait_time / 3)`（0~0.5 秒） |
| 连发 | 写死在各 `Fire()` 分支 / 动画里 | `burst_num` / `burst_extra_num` 字段 |

典型值：豌豆 `mLaunchRate = 150` ↔ `attack_cd = 1.5`；向日葵 `2500` tick ↔ `create_time_range_other = (23.5, 25)`、首发 `(3, 12.5)`、25 阳光。

### 2.4 啃食

原版（`Zombie.cpp:6859`、`7099`）：`mZombieAge % TICKS_BETWEEN_EATS(4) == 0` 时咬一口 `DAMAGE_PER_EAT(4)`，被冻时周期翻倍 → **100 点/秒**；未出土的土豆雷可以啃，撑杆 / 跳跳有跳过分支，倭瓜 look / 花盆睡莲无敌期**不扣血**。

本作（`component_attack_zombie_norm.gd`）：每 `EAT_SETTLE_FRAME_INTERVAL(8)` 帧把这段时间累积的伤害一次结算（`settle_eat_damage()`，含零头累加）→ 同样 **100 点/秒**；"不该扣血"的植物由**掩码 / 自己重写 `process_damage()` / 关受击框**表达。

### 2.5 伤害与防具分层

原版：`TakeDamage()` 严格分层「飞行层 → 二类防具 → 一类防具 → 本体」，剩余伤害往下传；`damageFlags` 位掩码决定是否闪白 / 是否播受击音 / 是否穿透防具。
本作：`DamageSystem.apply()` 三段（① 写包 → ② 加工：防具链 + 本体 + 修饰器 → ③ 应用），防具是**节点**可叠加，原版 `ShieldType` / `HelmType` 两个固定槽 → `ArmorComponent` + `E_ArmorClass`。

口径一致的细节（易踩）：
- 一类防具（路障 / 铁桶 / 头盔）**吃满伤害时仍然上减速**；二类防具（铁门 / 报纸 / 梯子）**全挡住时不减速** → 本作 `ArmorComponent.is_immune_slow() == (armor_class == Armor2)`，与原版一致。
- 保龄球 / 锤子打本体是固定值（`ConstDamage.BOWLING_*` / `HAMMER_ARMOR1`），不是"剩余伤害"。

### 2.6 掉手 / 掉头 / 死亡

原版固定：本体 < **2/3** 掉手、< **1/3** 掉头（`Zombie.cpp:3909`）。本作 `HpStageChangeComponent` 默认算出来的阈值同样是 `max_hp*2/3-1` / `max_hp*1/3-1`，但可在场景里覆盖（坚果 / 南瓜头也走同一组件）。

### 2.7 移动

原版：`mVelX` 由 `PickRandomSpeed()` 给（普通僵尸 `0.23~0.37` px/tick）；**有 `"_ground"` 轨道时改用动画轨道速度**（`Zombie.cpp:4127`）。
本作：`MoveComponent` 两种模式 —— `Ground`（照抄上面那条：由动画 `_ground` 轨道带动，速度因子同时缩放动画）与 `Speed`（`ori_speed` px/s）。普通僵尸走 `Ground`，气球 / 投石车 / 矿工 / 跳跳 / 冰车走 `Speed`，与原版分支对应。
个体差异：原版 ±23%，本作 `zombie_base.tscn` 覆盖成 `random_speed_range = (0.77, 1.23)`（2026-10-23 对齐，均值仍 1.0）。

### 2.8 控制时长

| 控制 | 原版（tick） | 本作（秒） |
| - | - | - |
| 寒冰减速（雪豆 / 冰瓜） | `ApplyChill(false)` = 1000 | `time_be_decelerated = 10.0` |
| 完全冻结 | 陆地 `Rand(400,600)`、水中 300 | `ZombieManager.ICE_TRAP_FREEZE_LAND = (4,6)`、`ICE_TRAP_FREEZE_POOL = 3` |
| 冰冻附带的减速 | `ApplyChill(true)` = 2000（**从冰冻那一刻起算**） | `ICE_CHILL_TOTAL = 20`，实际下发 `20 − 冻结时长` |
| 黄油定身 | 400 | `be_butter()` 默认 4 |
| 冰冻减速系数 | `CHILLED_SPEED_FACTOR = 0.4` | `be_ice_decelerate()` 写死 `0.5`（**保留差异，见 §4**） |

## 4. 偏差与处置

### 4.1 2026-10-23 已按原版口径校准

| 项 | 改前 | 改后 | 落点 |
| - | - | - | - |
| 啃食字段名 | `..._per_min`（误称，单位其实是 HP/秒） | `init_attack_value_per_sec` / `curr_attack_value_per_sec`（旧名留了一个转发属性给第三方模组） | `component_attack_zombie_norm.gd` |
| 啃食结算零头 | 每次 `int()` 截断 → 实际 97.5 点/秒 | 零头累加 → 平均正好 100 点/秒 | `settle_eat_damage()` |
| 寒冰减速 | 3 秒 | 10 秒 | `bullet_pea_snow.gd/.tscn`、`bullet_winter_melon.gd/.tscn`、`spatter_component_winter_melon.gd` |
| 寒冰菇 | 冻结 3 秒 + 解冻后减速 5 秒 | 陆地 4~6 秒随机 / 水中 3 秒；减速总时长 20 秒（解冻后即剩余值） | `component_bomb_ice.gd`、`ZombieManager.ice_all_zombie()` |
| 僵尸速度个体差异 | `random_speed_range = (0.9, 1.1)` | `zombie_base.tscn` 覆盖成 `(0.77, 1.23)`（原版 ±23%） | `zombie_base.tscn` |

> `ice_all_zombie()` 的第二参语义随之变成「减速**总**时长（从冰冻那一刻起算）」，传 `0` = 解冻后不减速；调用方（探针 / 模组）要传 `冻结时长 + 想要的解冻后时长`。

### 4.2 仍然保留的差异（有意，别顺手"修"）

| 项 | 原版 | 本作 | 为什么留着 |
| - | - | - | - |
| 冰冻减速系数 | 0.4 | 0.5 | 0.5 是仓库内多处口径（黄油 / 冰瓜 / 僵王共用）；改动会连带所有减速玩法，且 0.4 vs 0.5 肉眼难分 |
| 植物首发延迟 | 0~1.5 秒 | 0~0.5 秒 | 手感更跟手；对总 DPS 无影响 |
| 植物速度因子 | 无随机 | `random_speed_range` 默认 ±10% | 只用来让同屏多株不同步（攻速 / 产阳光错峰），原版也有"首发随机"，视觉等价 |
| 可吃优先级 | 3 档 | 5 档（多 Imitater / Float） | 模组扩展位，对原版植物行为无影响 |
| 保护期植物 | `EatPlant()` 里集中判断（倭瓜 look、花盆 / 睡莲无敌…） | 各角色自己关受击框 / 掩码 | 架构约束（本体不认识具体植物，硬约束 §1-8） |

**注意（改这两处会踩的坑）**：

- 地刺 / 钢地刺的伤害**不再由动画方法轨触发**：`_attack_once()` 现在留空，改由 `_deal_damage()` 按 `attack_hit_times` 结算。若以后用工具重导动画，方法轨仍指 `_attack_once`，语义不变（空实现），不会双结算。
- 撑杆跳只加兜底不改算法：跳跃期间的 `jump_compensate_distance` 逻辑未动，多株植物叠放时的落点仍可能和原版差几十像素（视觉等价，见 §4.2）。

### 4.4 第三轮校准（2026-10-24，已改代码 + 探针实测）

**移动速度的测量口径（先读这条，别再静态读动画轨道）**

Ground 模式的位移来自动画里 `_ground` 的 x 轨道，直接拿「位移 / 时长」算会**漏掉循环回绕**：
walk 动画末尾有 `MoveComponent._walking_start` 的方法轨，回绕帧会复位 `_previous_ground_global_x`
而**跳掉**那一帧的回绕位移，所以「位移 / 时长」就是真实速度；但轨道中途有停顿段，
**必须按运行时平均量测**（`test/scenarios/probe_zombie_speed.gd`，把 `InitRandomSpeed` 压成 1.0）。

| 项 | 原版 | 本作实测 | 处置 |
| - | - | - | - |
| 普通僵尸 | 0.23~0.37 px/tick = 23~37 px/s | **14.2 px/s** | **未改**：整体移速约为原版一半，属全局调参（牵动波次节奏 / 小推车 / 手感），单列未解决项 |
| 读报僵尸暴走 | 0.89~0.91 px/tick，是普僵均值的 **3 倍** | 改前 29.0 px/s = 普僵的 **2.04 倍** | 已改：`ArmorComponentNewspaper.on_armor_break()` 设 `MoveComponent.ground_speed_scale = 1.5` → 43.5 px/s = **3.07 倍** |
| 舞王 / 伴舞 | 0.45 px/tick = 45 px/s，是普僵的 1.5 倍 | `_ground` 28.6 px / 1.667 s × `speed_scale 1.3` = 22.3 px/s = 普僵的 **1.57 倍** | **不改**：相对倍率已对齐（绝对值和普僵一样受全局移速影响） |

为什么报纸用 `ground_speed_scale` 而不是去抬 `paper_gasp` 的 `TimeScale`：TimeScale 会把**吃植物动画**
一起放大（内层 eat 还有一份 2.0，叠起来会到 12 倍），而原版只是移动快、动画只快 ~1.7 倍
（`StartWalkAnim(20)` vs 常速 12）。`ground_speed_scale` 只放大位移、不动动画，正好对上。

**同轮修掉的两处行为差异**

- **冰瓜的减速判据**（原 L-21）：原版 `TakeShieldDamage()` **不调** `ApplyChill()`，所以二类防具
  （铁门 / 报纸 / 梯子）还举着时不吃减速；本作寒冰豌豆早就判了 `is_slow_immune`，冰瓜的**直击 + 溅射
  两处都没判**。已补成同一条判据，判定放在伤害结算**之后**（这一发把门打掉时，防具已经 `is_alive() == false`，
  会正常上减速 —— 与原版「剩余伤害传到本体」一致）。实测见 `test/scenarios/probe_winter_melon_slow.gd`。
- **隐形战争前几波最下行不出怪**（原 L-33）：原版 `Board.cpp` 的条件是
  `INVISIGHOUL && mCurrentWave <= 3 && aRow == 5`（0 起算 ⇒ 第 1~4 波；C++ 注释写「前 3 波」但代码是 `<= 3`，
  以代码为准）。本作新增关卡级行限制 `set_banned_spawn_rows()`，关卡脚本在 `before_wave_spawn()` 里按波设置 / 清空。
  实测见 `test/scenarios/probe_invisi_ghoul_rows.gd`。

**同轮修掉的数值差异**

- **僵尸迷阵级联阳光**（原 L-32）：原版 `BeghouledScore()` 的 `aNumSuns = 连线株数 - 2 (+2 若 ≥5 连)
  + mBeghouledMatchesThisMove`，clamp 1..5，每颗 25；同一次移动（含级联）里第 2 组起每组多一颗。
  已按此改 `ConstBeghouled.get_sun_by_chain_len(chain_len, matches_this_move)`，并在 `_resolve_matches()`
  里跨级联累计组数。实测：`probe_beghouled` 新增 STEP2.6 公式断言。

**仍然保留 / 已知边界**

- `zombie_paper.tscn` 的 `AnimationPlayer.speed_scale = 5.0` 是死值（被 AnimationTree 接管时不生效），别拿它当倍率。
- **全局移速偏慢**（普僵 14.2 vs 原版 23~37）：要动就是全角色的 `AnimationTree TimeScale` 或动画轨道，
  影响所有关卡节奏，**需单开一轮并开游戏**，别顺手改。

## 5. 实现路径不同但视觉等价（不算偏差）

1. **冰车 / 投石车 vs 地刺**：原版 `CanTargetPlant()` 允许车类压地刺；本作车的 `can_attack_plant_status` 不含地刺位，改由**地刺主动扎 + `EFFECT_CALTROP` 便条**，车在 `process_damage()` 里翻译成"自己爆 + 载具反伤"。玩家看到的结果一致（车爆、地刺在）。
2. **巨人跨行 / 僵王跨行**：原版特判 `mZombieType`；本作由检测框几何覆盖范围决定，不写同行限制。
3. **梯子**：原版塞在 `CanTargetPlant()` + `EatPlant()`；本作用 `LadderComponent` + 植物 `signal_ladder_update` + `is_ignore_ladder`（只有巨人和冰车忽略梯子）。
   > **2026-10-24 复查：这条不再算「视觉等价」** —— 原版梯子是**让僵尸爬上去继续吃**（`EatPlant()` 见梯子即 `HEIGHT_UP_LADDER`），
   > 本作是**让植物免被普通僵尸吃**（`component_detect.gd:339-343`），语义相反，详见 §4.5 #2（待实机确认后再定性）。
