# 伤害系统

## 0. 一句话

一次伤害 = **一个「效果包」走完三段**。全场只有一个入口 `DamageSystem.apply(info)`：

```
  ① 伤害方写包          ② 受击方加工包                          ③ 系统应用包
  ├ 子弹 / 炸弹 / 僵尸   ──> ②-a 防具链（外层先说话，就地吸收）──> 按 effects 逐项施加
  └ DamageInfo.effects     ②-b 目标.process_damage()               （通用效果在这里生效）
                           ②-c 修饰器链
```

| 段 | 谁做 | 做什么 |
| - | - | - |
| ① 写包 | 伤害方（子弹 / 植物 / 僵尸 / 关卡脚本） | 往 `info.effects` 里塞"我要施加什么" |
| ② 加工包 | **受击方自己**：**先**身上的每一层防具（`ArmorComponent.process_damage()`，外层 → 内层）**再**本体（`Character000Base.process_damage()`），最后修饰器链 | 翻译**系统不认**的特殊效果；可改值、可整包取消。**防具链这一步同时把防具自己的血扣了**（吸收，见 §4.2） |
| ③ 应用包 | `DamageSystem` | 只处理自己认得的**通用效果**（伤害 / 减速 / 冰冻 / 黄油）；此时 `info.amount` 已是"走完防具剩下的" |

> **② 的顺序是"谁在外面谁先说话"**：防具挂在外层、最先挨打，所以也最先拿到包
> （谁先挨打谁先吸收，顺序都是「二类 → 一类 → 本体」）。顺序由 `DamageSystem.apply()` 保证，
> **不依赖**角色子类记得先调 `super()` —— 见 §4.2 与 [防具.md](防具.md) §3。

**所有伤害都必须经过 `apply()`**。绕过它直接调 `hp_component.hp_loss()` 等于绕过 ② 加工与应用 —— 不报错，而且**防具一滴血都不会掉**（吸收在 ②-a 的防具 `process_damage()` 里），只是将来加的功能也在这里失效。

> 2026-10 前本系统是「发起 → 修饰器链 → 结算」两段，附加效果只能挂修饰器组件。
> 现在改成三段式 + 效果包：伤害之外还能带减速 / 冰冻，且**某个角色专属的规则**（地刺秒杀洗冰车）由那个角色自己翻译，不进系统。
> 2026-10-16 起 ② 再分两步：**防具链先加工**（`ArmorComponent.process_damage()`）**再本体**
> （`Character000Base.process_damage()`）—— 以前防具只在 ③ 结算层分血，没有对包表态的机会。
> 2026-10-16 起 ③ 也不再遍历防具：**防具的吸收（扣血）并入它自己的 ② 加工环节** —— 每层就地扣血、
> 把 `info.amount` 改成"剩下的"交给下一层，③ 只拿剩下的打本体。

## 2. 两个枚举：模式决定「怎么算」，来源只做标记

```gdscript
ConstDamage.E_DamageMode   # 参与分配分支：Norm / Penetration / Real / BowlingFront / BowlingSide / Hammer
ConstDamage.E_DamageCause  # 只做语义标记：Bullet / Spatter / Bomb / Eat / Hammer / Freeze / Burn / Drain / Crush / Death / Script
```

- **`E_DamageMode` 决定伤害在三层血之间怎么分**，实现分两处：**防具**吃多少 / 往下传多少在 `ArmorComponent.get_absorb_rule()`（防具在自己 ② 的 `process_damage()` 里随手扣血），**本体**吃多少在 `HpComponentZombie.get_body_damage()`（植物只有本体血，用基类 `HpComponent.hp_loss()`）。
    
  **加一种模式必须同步在这两处加分支** —— 漏了就是静默不掉血（不报错，症状是「这个技能打人没伤害」）。
- **`E_DamageCause` 不参与任何结算分支**，只用于：反伤/免疫只对某种来源生效、联机对账、统计与成就。
    
  不要用 `cause` 当结算分支。

`E_DamageMode` 原先挂在 `BulletRegistry.AttackMode` 名下（子弹注册表里放伤害类型，名不副实），现已迁到 `ConstDamage`；**值与旧枚举一一对应**（0~5），存量 `.tscn` 存的是 int，**不需要改任何场景文件**。

## 3. 效果包：一次伤害 = 一张字典

```gdscript
info.effects   ## Dictionary，key = ConstDamage.EFFECT_*（效果）/ ConstDamage.KEY_*（元信息）
```

**包里只有这一张字典**。`DamageInfo` 上的具名字段（`amount` / `mode` / `cause` / `target` /
`attacker` / `source` / `is_instant_kill` / `is_drop_on_death` / `is_drop_2` / `trigger_sfx` /
`final_amount`）**全是它的代理访问器** —— `info.mode = x` 等价于 `info.effects[ConstDamage.KEY_MODE] = x`。

之所以做成代理而不是留一撮独立字段：**字典是唯一真源**，否则两处各存一份必然漂移。
好处是全仓几十处 `info.amount = x` / `info.attacker = self` / `be_attacked_bullet(20, ...)` 一行都不用改；
代价是字典里混进了两类 key，所以靠前缀区分（见下）。

### 两类 key：`EFFECT_*` 是效果，`KEY_*`（值带 `meta_` 前缀）是元信息

| 档 | 常量 | 字典里的值 | 谁消费 |
| - | - | - | - |
| **效果** | `ConstDamage.EFFECT_*` | `damage` / `slow` / `freeze` / `butter` / `caltrop` / `vehicle_backlash` | 系统（通用）/ 受击方（特殊） |
| **元信息** | `ConstDamage.KEY_*` | `meta_mode` / `meta_cause` / `meta_target` / `meta_attacker` / `meta_source` / `meta_instant_kill` / `meta_drop_on_death` / `meta_drop_2` / `meta_sfx` / `meta_final_amount` | **没人消费**，只是随包走一段路 |

元信息那几个（谁打谁、怎么算、掉不掉东西）**不是效果** —— 系统不施加、受击方不翻译，
只是伤害包走到 ③ 之前必须带着的上下文。加 `meta_` 前缀是为了：调试打印时能一眼把上下文和效果
分开（`ConstDamage.META_KEYS` 就是干这个的），也免得将来某个效果也叫 `source` 时撞 key 还**静默失效**。

> ⚠️ 别在包里手写 `meta_*` 字符串：一律走 `ConstDamage.KEY_*` 常量，或干脆用更好读的具名字段。
> 同一项不要一会儿用具名字段、一会儿用 `effects[...]`。

### 效果分两类

| 类型 | 谁处理 | 含义 |
| - | - | - |
| **通用效果** | `DamageSystem` 在 ③ 亲自施加 | 所有角色一视同仁：伤害 / 减速 / 冰冻 / 黄油 |
| **特殊效果** | **受击方**在 ② 自己翻译，系统不认也不碰 | 发起方写给受击方的一张「便条」：只对某类角色有意义 |

**为什么留特殊效果这一档**：把「洗冰车被地刺秒杀」写进系统，系统就得认识"洗冰车"和"地刺" —— 那是硬约束 §1-8 明令禁止的。交给受击方自己翻译，系统从头到尾不知道世界上有洗冰车。

### 当前登记的效果

| 效果 | key | 值格式 | 谁处理 |
| - | - | - | - |
| 伤害 | `EFFECT_DAMAGE` | `int`（分配方式看 `mode`） | 系统 |
| 减速 | `EFFECT_SLOW` | `{time:float, factor:float}` | 系统 → `be_slow()` |
| 完全冰冻 | `EFFECT_FREEZE` | `{time:float, after_slow:float}` | 系统 → `be_ice_freeze(t, s, 0)` |
| 黄油定身 | `EFFECT_BUTTER` | `float`（秒） | 系统 → `Zombie000Base.be_butter()`（植物没有这回事，静默跳过） |
| 地刺扎 | `EFFECT_CALTROP` | `true` | **受击方**：洗冰车 / 投石车 → 秒杀 + 载具反伤，巨人 → 整包取消，其余（**含雪橇车小队**）→ 当没看见 |
| 载具反伤 | `EFFECT_VEHICLE_BACKLASH` | `true` | **受击方**：洗冰车 / 投石车被地刺类扎到时，反过来对**发起者**打一下**0 伤害**并塞这张条；地刺 → 直接报废，钢地刺 → 按自己的 `vehicle_backlash_damage` 掉一截血 |

> **载具反伤是「0 伤害 + 便条」**：车压根不知道扎它的是地刺还是钢地刺，它只负责**照 `info.attacker` 打回去**，
> 打多狠由**受击方**在 ② 加工阶段自己写进 `effects[EFFECT_DAMAGE]`（地刺置 `is_instant_kill` 直接报废，
> 钢地刺把 `amount` 填成自己的受损值）。
>
> 这样做的好处是**受损数值一律落在字典里**、由受击方填，车这边一个数字都没有，也不认识任何一种地刺
> （硬约束 §1-8）。
>
> 前提：发起方写包时**必须填 `info.attacker`** —— 没写它车就没得可打，整条反伤链不会发生。
>
> 0 伤害包只有在受击方把它"加工"成非零（或秒杀）之后才会真的结算；没人翻译它就是一个什么都不发生的空包。

### 秒杀：`is_instant_kill`

```gdscript
info.is_instant_kill = true      ## 直接把目标清空到死
info.with_instant_kill()         ## 链式写法（默认 true）
```

**不看伤害值、不看伤害模式、不走防具的吸收规则** —— 防具层与本体一并清零，必然致死。

为什么要这个字段，而不是老写法「把 `amount` 抬到 `get_all_hp()` + `E_DamageMode.Real`」：

| 老写法的毛病 | 说明 |
| - | - |
| 仍要过吸收规则 | 减伤 / 固定吸收的防具（模组里那些矿石桶）会让它**打不死**；本意是"必死"，结果取决于防具表 |
| `Real` 语义不对 | `Real` 只跳过**二类**防具，一类防具照样吃伤害，不是"无视一切" |
| 血量是加工时读的 | ② 阶段读到的血量，到 ③ 真正结算时可能已经变了（残血流失、另一发子弹先落地） |

秒杀**不是绕过管线**：加工阶段、修饰器链、死亡流程、亡语、掉落、伤害事件照常走一遍，只是不再拿 `amount` 当"要扣多少"。
修饰器与 `process_damage()` 把它改回 `false` 就是「免疫秒杀」的标准写法。

⚠️ 秒杀仍然需要一个伤害效果（`DamageInfo.create()` 一定会带上），`amount` 写 0 也无妨 —— 系统靠 `EFFECT_DAMAGE` 认领这次结算，靠 `is_instant_kill` 决定怎么扣。

当前用它的地方：地刺扎（洗冰车 / 投石车 在 ② 里把便条翻译成秒杀）、`be_attack_to_death()`（大保龄球 / 锤子秒杀）、`HpComponent.hp_loss_to_death()`（铲除 / 死亡消失 / 强制致死）。

### 效果的读写

```gdscript
info.set_effect(name, value)      ## 塞一个（链式，已存在则覆盖）
info.get_effect(name, default)    ## 取一个（不会自动塞默认值）
info.has_effect(name)             ## 有没有（不看值：值为 0 / false 也算有）
info.remove_effect(name)          ## 移除一个（链式）—— 受击方"否决"一个效果的标准写法
```

## 4. 三段式：一段一段说清

### ① 伤害方写包

发起方只管**声明要施加什么**，不管后果：

```gdscript
## 地刺：伤害 + 一张"我是地刺"的便条
var info := DamageInfo.create(zombie, attack_value,
	ConstDamage.E_DamageMode.Real, ConstDamage.E_DamageCause.Bullet)
info.set_effect(ConstDamage.EFFECT_CALTROP, true)
var result := zombie.apply_damage(info)
```

### ② 受击方加工包（三步，顺序固定）

`DamageSystem` 在施加前依次调三个地方，**任何一步返回 false = 整包取消**（本体与更内层不再掉血、控制也不上）：

| 步 | 调谁 | 做什么 | 取消时 `cancel_reason` |
| - | - | - | - |
| ②-a | 身上每一层防具：`ArmorComponent.process_damage(info)`（按 `armor_list`，外层 → 内层） | 翻译防具的特殊效果、改包 / 取消；**并就地扣掉本层该吃的血**，把 `info.amount` 改成"走完本层剩下的" | `Armor` |
| ②-b | 受击方本体：`Character000Base.process_damage(info)` | 翻译本体的特殊效果、改包 / 取消 | `Target` |
| ②-c | 修饰器链（`DamageModifierComponent` / `DamageModifier`，按 priority 降序） | 改值 / 免疫 / 取消 | `Modifier` |

**为什么防具排在前面**：防具是最外层、最先挨打的东西，所以也最先拿到包、最先吸收 —— 顺序都是
「二类防具 → 一类防具 → 本体」同一个方向（谁在外面谁先说话）。顺序由管线强制，
不靠角色子类记得先调 `super()`；已经破掉的防具不参与（见 [防具.md](防具.md) §3）。

> ⚠️ **吸收在 ②-a 就发生，取消的只是"更内层与本体"**：靠里的防具 / 本体 / 修饰器 `return false`
> 不会退还外层已经扣掉的防具血。要"整包取消连防具也不掉血"，让**最外层**的防具 `return false`。
>
> 正因为如此，**取消时返回的 `DamageResult` 也带血量快照**（`DamageResult.canceled_with_hp()`）：
> `hp_loss` 反映的是外层**已经扣掉**的血，而不是 0 —— 否则调用方会以为"这次伤害一点没造成"
> （只有 `NoTarget` / `NoHpComponent` 那两处拿不到血量，才用不带宽带的 `canceled()`）。

特殊效果在这里被翻译成具体后果 —— 同一张便条，不同角色 / 不同防具翻译出不同结果（见 §9）。

### ③ 系统应用包

`DamageSystem` 按 `EFFECT_APPLY_ORDER` 的固定顺序逐个施加**自己认得**的效果，**一个都没施加成 = 这次没生效**。

顺序是显式定的（字典遍历顺序不稳定）：**伤害先结**（打死了就不再上控制），控制类随后。

此时 `info.amount` 已经是**走完防具剩下的**（防具的吸收在 ②-a 就完成了）：通用效果里的「伤害」
拿它打本体 —— 僵尸侧本体吃多少由 `HpComponentZombie.get_body_damage()` 决定
（保龄球 / 锤子那几个模式是固定值，与传进来的剩余量无关）。

> 已经死了的角色不再上控制类效果 —— 给死人挂减速，计时器回调会去改一个已 `queue_free` 的节点。

## 5. 角色侧的四个函数

`Character000Base`（`src/entities/character/character_base.gd`）：

| 函数                              | 谁调                      | 说明                                                                                           |
| ------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------- |
| `apply_damage(info)`            | **业务代码**                | ① 的入口，内部转 `DamageSystem.apply()`                                                              |
| `process_damage_armors(info)`   | **只由 `DamageSystem` 调** | ②-a：转发给血量组件，僵尸逐层问 `armor_list`（植物没有防具，基类直接放行）。**防具的吸收也在这步完成**（各层就地扣血并改写 `info.amount`）。子类一般**不需要**重写                                                            |
| `process_damage(info)`          | **只由 `DamageSystem` 调** | ②-b 加工阶段：翻译特殊效果、可改 `amount` / `mode` / `effects`；**默认返回 true**，重写时**应该** `return super(info)` |
| `take_damage(info)`             | **只由 `DamageSystem` 调** | ③ 末端，转 `hp_component.hp_loss(info)`；子类一般不重写，要重写**必须** `return super(info)`                 |

> 想改「挨打前这次伤害长什么样」只有两个落点：**属于一层防具的**写 `ArmorComponent.process_damage()`
> （②-a），**属于角色本体的**写 `Character000Base.process_damage()`（②-b）。两者都在 ②，纪律同 §5 下面三条。

加工阶段的三条纪律：

1. **不要在这里触发新的伤害**（嵌套 `apply()` 有重入保护，但那是防栈溢出不是正确用法）。要加伤害就改 `info.amount`，让系统去施加。
2. **除了防具自己的吸收，不要在这里改血量** —— 本体血量归 ③ `hp_loss()`；防具在 ②-a 就地扣自己的血是唯一例外（它属于防具自己那层的结算）。
3. **表现（动画 / 特效）放 ③ 末端 `take_damage()`，不要放 ②** —— ② 之后还可能被修饰器取消，那时动画已经切了却没掉血，留下"车还在跑却是散架姿势"这类视觉 bug。防具的掉血信号 / 音效同理，由 `notify_hp_loss()` 在 ③ 末端统一补发。

另有 `be_hit_light()`（受击闪白光一次），给**不走 `be_attacked_bullet()` 的发起方**（地刺自己写包那条路）复用这份表现，免得去碰别人的 `body` 节点。

语义入口（`be_attacked_bullet` / `be_zombie_eat` / `be_bomb` / `be_ice_freeze` / `be_squash` / `be_attack_to_death` …）现在**只负责组装 `DamageInfo`**，不再各自调血量组件。它们保留原签名，老调用点一行都不用改。

## 7. 造一次伤害（新代码怎么写）

```gdscript
## 推荐：走角色的语义入口（老入口，不用自己拼 DamageInfo）
zombie.be_attacked_bullet(20, ConstDamage.E_DamageMode.Norm, true, true, self)

## 带附加效果 / 没有合适语义入口时：自己组装，走 apply_damage()
var info := DamageInfo.create(zombie, 20, ConstDamage.E_DamageMode.Norm, ConstDamage.E_DamageCause.Script)
info.attacker = self                                              ## 谁打的（可空）
info.source = self                                                ## 伤害载体（可空）
info.trigger_sfx = false                                          ## 残血流失一类"非受击"掉血要关掉
info.set_effect(ConstDamage.EFFECT_SLOW, {time = 5.0, factor = 0.5}) ## 附带减速
var result := zombie.apply_damage(info)
if result.is_applied and result.is_lethal:
	... ## 这次打死了
```

`apply()` 会保证：目标为空 / 已释放 → 返回未生效（`NoTarget`）不报错；伤害值被加工成 ≤0 且包里只有伤害 → 取消（`ZeroAmount`），**不会倒扣血**。

`result.applied_effects` 列出**系统实际施加了**哪些通用效果 —— 只看 `is_applied` 分不清"掉了血"和"只上了个减速"。

### 角色攻击力（`Character000Base.attack_value`）怎么流到子弹

子弹伤害的**三级优先**（只在「发射类攻击」这条路上生效，`E_InitParasAttr.AttackValue` 就是这条链的出口）：

| 级 | 字段 | 配在哪 | 说明 |
| - | - | - | - |
| 1 | `AttackComponentBulletBase.attack_value_bullet` | 攻击组件 | 组件级覆盖（> 0 生效），给「同一组件发射不同伤害的子弹」用 |
| 2 | `Character000Base.attack_value` | 角色（植物 / 僵尸共用） | 角色自己的攻击力（> 0 生效） |
| 3 | 子弹场景自己的 `attack_value` | 子弹 `.tscn` | 都不设（前两者 ≤ 0）时沿用，**默认行为不变** |

取值入口是 `AttackComponentBulletBase.get_shoot_attack_value()`（豌豆僵尸组件 `AttackComponentZomBotanyPea` 继承自啃咬组件、没有组件级字段，本地有一份同语义的 `_get_shoot_attack_value()`）。
取值经 `get_bullet_paras()` 写进 `E_InitParasAttr.AttackValue`，由 `Bullet000NormBase.init_bullet()` 应用（只有 > 0 才覆盖子弹自身的值）。

> 啃食类持续伤害**不走这条链**：僵尸啃植物的每秒伤害在 `AttackComponentZombieNorm.init_attack_value_per_sec`（单位 HP/秒，
> 大嘴花的啃咬伤害在角色攻击力 `attack_value` 上（吞小体型僵尸是秒杀，不看伤害值）—— 它们各自直接把数值写进 `DamageInfo`。
>
> **非发射类攻击也读同一个 `attack_value`**：地刺 / 钢地刺（扎）、忧郁菇（烟雾）、
> 火爆辣椒（整行）、倭瓜（压扁）、寒冰菇（全场伤害 + 冰冻）都是「植物读自己的 `attack_value` 写包」，
> 数值配在各自的植物 `.tscn` 里，`ConstDamage` **不再存任何植物专属伤害值**（见下表）。

## 8. 加一种通用效果（所有角色都吃的那种）

两处，其余代码一行不用动：

1. `ConstDamage` 加一个 `const EFFECT_XXX := &"xxx"`（**用 `StringName`**，别用裸字符串拼 key —— 拼错了不报错，只是静默失效）
2. `DamageSystem._register_effect_handlers()` 登记一个处理函数，并把它加进 `EFFECT_APPLY_ORDER`

```gdscript
## 处理函数签名：返回 true = 真的施加了（会写进 DamageResult.applied_effects）
func _apply_effect_xxx(info: DamageInfo, target: Character000Base) -> bool:
	var v: float = info.get_effect(ConstDamage.EFFECT_XXX, 0.0)
	if v <= 0.0:
		return false
	target.be_xxx(v)
	return true
```

## 9. 加一种「只对某个角色有意义」的规则 → 走特殊效果

**不要**写进系统。发起方写便条，受击方自己翻译：

```gdscript
## ① 发起方（地刺）：塞一张便条，不关心后果
info.set_effect(ConstDamage.EFFECT_CALTROP, true)

## ② 洗冰车：翻译成秒杀
func process_damage(info: DamageInfo) -> bool:
	if info.has_effect(ConstDamage.EFFECT_CALTROP):
		info.is_instant_kill = true   ## 直接清空，不看伤害值 / 不看防具规则
	return super(info)

## ② 巨人：翻译成整包取消（免疫）
func process_damage(info: DamageInfo) -> bool:
	if info.has_effect(ConstDamage.EFFECT_CALTROP):
		return false
	return super(info)
```

**没重写的角色不受影响** —— 它不认识这张便条，包里的伤害照常结算（普僵被地刺扎 = 掉 20 血）。

当前 `EFFECT_CALTROP` 的翻译一览：

| 角色                     | 翻译结果               |
| ---------------------- | ------------------ |
| 洗冰车 `zamboni`         | 秒杀 + 报废（死亡 + 报废动画）   |
| 投石车 `catapult`        | 秒杀 + 报废（死亡 + 报废动画）   |
| 雪橇车小队 `bobsled`      | **不认识 → 正常挨伤害**（无特殊互动） |
| 巨人 `gargantuar`        | 整包取消（一点血不掉）       |
| 其余僵尸                   | 不认识 → 只挨包里的伤害     |

> **这张便条从哪儿发出**：地刺 / 钢地刺的**主动攻击**（`_attack_once()`，每 0.75 秒扎一次检测区里的敌人），
> 不是"被压扁后的反击"。洗冰车 / 投石车刻意**不压**地刺 —— 它们的碾压检测 `can_attack_plant_status`
> 不勾「地刺」位（4），原因见 `AttackComponentZombieZamboni` 文件头；勾上就会变成
> "车爆了、地刺也塌了"。地刺那条"被压扁时反扎"的路现在只有巨人会走到，而巨人自己取消了整包。

### 9.1 如果这条规则属于**一层防具** → 写 `ArmorComponent.process_damage()`

同一套道理：规则跟着"谁挨打"走。防具挂在外层，所以 ② 里它**比本体先**拿到包
（管线顺序 ②-a 防具链 → ②-b 本体 → ②-c 修饰器）：

```gdscript
## 一层"只对爆炸免疫"的防具
extends ArmorComponent

func process_damage(info: DamageInfo) -> bool:
	if info.cause == ConstDamage.E_DamageCause.Bomb:
		return false          ## 整包取消
	return super(info)        ## ⚠️ 放行时必须 super()：吸收（扣本层血）就在父类这一步
```

返回 false 时 `DamageResult.cancel_reason` 是 `E_CancelReason.Armor`，与本体取消的 `Target`、
修饰器取消的 `Modifier` **分开**——排查"到底是谁把这次伤害挡下来的"时一眼能看出来。

> ⚠️ 重写 `process_damage()` 后**放行时一定要 `return super(info)`**，否则本层防具永远不掉血
> （旧实现里吸收在 ③、不在 `process_damage()`，所以只 `return true` 也照样掉血 —— 现在不行了）。
>
> ⚠️ 只影响**本层吃掉多少**的规则走 `get_absorb_rule()`（由父类 `process_damage()` 调用，
> 只管自己这一层；改包则会连带影响更内层防具与本体）—— 对比见 [防具.md](防具.md) §4。

## 10. 加一种伤害修饰（免疫 / 反伤 / 加成 / 护盾）

组件版（**推荐**）：写一个继承 `DamageModifierComponent` 的脚本，重写 `modify(info)`，挂到角色场景根节点下即可 —— 注册/注销/启用禁用全自动，角色被禁用时自动失效。

```gdscript
func modify(info: DamageInfo) -> bool:
	if info.cause == ConstDamage.E_DamageCause.Bomb:
		info.amount = 0        ## 免疫爆炸
		return false           ## true = 继续，false = 取消这次伤害
	return true
```

裸修饰器（`DamageModifier` 子类）用 `DamageSystem.register_modifier()` / `unregister_modifier()` 手动管理生命周期，**切关要记得注销**，否则会残留失效引用。

### 防具加工 / 本体加工 / 修饰器：什么时候用哪个

三者都在 ② 阶段跑（顺序：②-a 防具 `process_damage()` → ②-b 本体 `process_damage()` →
②-c 修饰器），区别在**这条规则属于谁**：

| | 防具 `process_damage()` | 本体 `process_damage()` | 修饰器组件 |
| - | - | - | - |
| 规则属于 | **某一层防具**（铁门挡减速、矿石桶易伤） | **这个角色自己**（洗冰车怕地刺） | **可插拔的通用规则**（护盾 / 免疫 / 加成） |
| 参与条件 | 那层防具还活着（破了就不参与，见 §9.1） | 角色还能挨打 | 组件启用期间 |
| 作用范围 | 改这**一次**的包（要限定就自己判 `info.target` / `info.cause`）；**本层吸收也在这里发生** | 改这**一次**的包 | 全局：对所有目标生效 |
| 加规则要动 | 防具脚本 | 角色脚本 | 挂个组件，角色脚本不动 |

> ⚠️ **修饰器排在防具之后（②-c），看到的是已经被防具削过的 `info.amount`**：所以「按比例减伤 / 加伤」
> 这类修饰器只作用到**打本体那部分**，不影响防具那一层。想连防具一起吃比例，得写防具自己的
> `absorb_damage()`（见 [防具.md](防具.md) §4）。

三条纪律：

1. `modify()` 里**不要再调 `DamageSystem.apply()`**（嵌套伤害）。管线有重入保护（跳过修饰器 + 记一条 `Log.error`），但那只是防栈溢出，不是正确用法。
2. 修饰器是**全局**的：想只对某类角色生效，自己判 `info.target`。
3. **目前本体没有任何内置修饰器** —— 改前改后行为完全一致，接口是给扩展预留的。

## 11. 死亡流程（没变，只说清谁触发）

`curr_hp <= death_hp` 的 setter → `signal_hp_component_death` → `character_death()`（角色侧）→ 植物 `queue_free()` / 僵尸播倒下动画 → 掉落由 `drop_item_component` 连死亡信号。

伤害管线**不处理死亡表现**，只在 `DamageResult.is_lethal` 里回一句「这次打死了没有」。
  
`is_lethal` 的口径是**本次造成的死亡**（原本已死的目标再被打，`is_lethal` 为 false）。

秒杀类效果（地刺扎洗冰车）走的是**正常死亡流程**：开 `info.is_instant_kill`（让结算层直接清空）即可，死亡 / 亡语 / 掉落全按正常死亡走一遍 —— **不要**在加工阶段直接改 `hp_component`，那条路会绕过管线。

| 地刺强令对方 `character.be_caltrop()`                      | 地刺塞 `EFFECT_CALTROP` 便条，各僵尸自己翻译（`be_caltrop()` 已全删）          |
| `info.amount` 是独立字段                                  | `amount` 是 `effects[EFFECT_DAMAGE]` 的**代理**（字典是唯一真源）           |
| "秒杀" = `amount = get_all_hp()` + `Real` 模式             | `info.is_instant_kill = true`（不看伤害值与吸收规则，防具与本体一起清空）     |
| `info` 的 mode / cause / target / attacker / source / 秒杀 / 掉落 / 音效 是独立字段 | 全部收进 `effects`（`ConstDamage.KEY_*`，值带 `meta_` 前缀），具名字段降级为**代理访问器**（写法一行没变） |

`attack_value`（子弹 / 炸弹的数值字段名）**没改**：它是 `.tscn` 里的 `@export`，改名会让存量场景失效。

## 13. 别踩的坑

- **别绕过管线**：`hp_component.hp_loss()` 是末端不是入口。真要直接改血量（联机快照、读档、包扎）用的是 `curr_hp` 赋值 + 信号，那不是伤害。
- **别在系统里认识具体角色**：写「地刺秒杀洗冰车」这种规则前先问它是不是只对一种角色有意义 —— 是就走特殊效果（§9），让那个角色自己翻译。
- **别在 `modify()` / `process_damage()` / 防具 `process_damage()` 里触发伤害**（见 §10）。
- **防具能改包就别绕道**：想让某层防具免疫 / 改值 / 整包取消 → 写 `ArmorComponent.process_damage()`
  （②-a，**整个包**）；只想改「本层吃掉多少」才写 `get_absorb_rule()`（**只自己这层**）。
  重写 `process_damage()` 放行时**必须 `return super(info)`**，否则那层防具永远不掉血。
  **不要**自己动 `curr_hp` —— 扣血由父类 `process_damage()` 里那次 `absorb_damage()` 做。
- **效果 key 一律用 `StringName` 常量**，别用裸字符串 —— 拼错了不报错，症状是「效果没生效」，极难查。包里一个通用效果都没施加成会返回 `NoEffect`，可以据此自检。
- **别把表现写进加工阶段**（见 §5 第 3 条）。
- **加伤害模式记得改 `ArmorComponent.get_absorb_rule()` 与 `HpComponentZombie.get_body_damage()` 两处 match**（见 §2），否则静默不掉血。
- **要"必死"就用 `is_instant_kill`**，别再把伤害值抬到血量上限 —— 那条路仍要过防具的吸收规则，碰上减伤防具就打不死（见 §3 的秒杀小节）。
- `be_ice_freeze()` 第三个参数 `damage` 默认 0（只冻不打，伤害由发起方给）—— 系统施加 `EFFECT_FREEZE` 时同样**显式传 0**，否则伤害会跟包里的 `EFFECT_DAMAGE` 双算。
- **联机**：客户端血量由主机快照下发，`DAMAGE_APPLIED` 事件是**观测用**的，订阅方不要在里面改血量（会被下一次快照覆盖）。
