# 防具（ArmorComponent）

> **[面向 AI Agent]** ｜ **触发条件**：要给角色加 / 改一层防具，改防具的伤害分配，或做「防具存在时的特殊效果」
> **读完你能**：知道防具挂在哪、怎么挂、伤害怎么沿着防具链走、六种 `E_DamageMode` 各自扣多少、特殊效果写在哪、改坏了跑哪个探针
> **强制级别**：**参考** ｜ **不读的风险**：把防具的数值写回 `HpComponent` 的固定槽位（已删除），编译就过不去
> **关联**：伤害管线 [伤害系统.md](伤害系统.md) ｜ 结算方 `HpComponentZombie` ｜ 枚举 `ConstArmor` ｜ 探针 `test/scenarios/probe_armor_component.gd`

## 1. 一句话

**防具 = 挂在同一角色下的 `ArmorComponent` 节点，挂几层就有几层，同类可以叠加。**
`HpComponentZombie` 在 `component_ready()` 里**自动收集角色根目录下的所有本类节点**并排好挨打顺序，
没有任何注册表、不需要宿主登记；把节点删掉角色照常运行，只是少一层防具。

```
src/entities/character/components/armor_component/
├── component_armor.gd              ## 基类：血量 / 破损外观 / 掉落 / 音效 / 铁器 / 效果钩子
├── component_armor_balloon.gd      ## 气球：存在时浮空，破了落地
├── component_armor_newspaper.gd    ## 报纸：破了暴走（提速 + 怒吼）
└── component_armor_plant_head.gd   ## 植物僵尸头顶植物：破了把它藏起来
src/core/consts/const_armor.gd      ## ConstArmor：类别 / 类型 / 吸收规则三个枚举
```

### 为什么不再是 `HpComponent` 上的两个槽位

重写前防具是 `HpComponentZombie` 的 `max_hp_armor1/2` 两个变量 + `HpStageChangeComponent` 的
`body_change_armor1/2` 两个数组（2026-10 之前的实现）：

- 一个角色**最多一层一类 + 一层二类**，"同一个僵尸戴两个路障"只能去血量表里再开一列；
- 防具自带的效果（铁门挡减速、气球浮空、报纸破防暴走）无处安放，只能散在僵尸子类里
  `if zombie_type == ...`，而本体不该认识任何具体僵尸（硬约束 §1-8）；
- 防具的「血量 / 外观 / 掉落 / 音效」四份状态分居两个组件，改一处要两边对表。

现在这四份状态都在 `ArmorComponent` 里，宿主不复制一份（K-01）。

## 2. 给一个角色加防具（两步）

1. 角色根节点下加一个 `Node2D`，挂 `component_armor.gd`（要特殊效果就挂它的子类）；
2. 检查器里填：

| 属性                  | 含义                                                       |
| ------------------- | -------------------------------------------------------- |
| `armor_type`        | 类型标识（`ConstArmor.E_ArmorType`），**只用于按类型查找**，不参与结算        |
| `armor_class`       | 类别：`Armor1`（头顶那件）/ `Armor2`（举在身前那件）。**二类在外、先挨打**         |
| `absorb_priority`   | 同类之间的挨打顺序，**数值越大越外层**。叠加同类防具时用它排先后                       |
| `max_hp`            | 本层血量（`0` = 这不是一件防具）                                      |
| `sfx_be_attack`     | 受击音效                                                     |
| `iron_node`         | 铁器节点；填了磁力菇就能把它吸走（非铁器防具留空）                                |
| `boundary_value_hp` | 破损临界值，留空时按 `max_hp` 自动切三段（2/3、1/3、0）                     |
| `body_change`       | 每到一个临界值要做的外观改变（换纹理 / 显隐精灵 / 掉落），与上面**一一对应**             |

`.tscn` 里长这样（路障，`zombie_cone.tscn`）：

```gdscript
[node name="ArmorComponent" type="Node2D" parent="."]
script = ExtResource("9_armor")
armor_type = 1
armor_class = 1
max_hp = 370
sfx_be_attack = 1
body_change = Array[ExtResource("4_tdg5j")]([SubResource(...), SubResource(...), SubResource(...)])
```

**运行期挂防具（热注册僵尸那条路）**：不用改任何 `.tscn`，在脚本里重写
`Zombie000Base.build_runtime_parts()` 并调 `add_armor()` —— 详见
[僵尸热注册.md](僵尸热注册.md) §2 / §5（`add_armor()` 内部会补一次 `HpComponentZombie.collect_armors()`，
少了这一步那一层**不参与伤害结算且没有任何报错**）。

⚠️ **Node 类型导出的路径是相对本节点解析的**（与 `ResourceBodyChange` 一样）：
防具节点是根的直接子节点，所以铁器要写 `NodePath("../Body/BodyCorrect/IronNode")`，
**不是** 根节点上那份 `"Body/BodyCorrect/IronNode"`。

## 3. 伤害怎么沿防具链走

`HpComponentZombie.hp_loss()` 按 `armor_list` 顺序（**二类 → 一类**，同类按 `absorb_priority`
从大到小，再相同按节点顺序）逐层调用 `ArmorComponent.absorb_damage(mode, remain)`，
每层吃多少、往下传多少由 `ArmorComponent.get_absorb_rule(mode)` 决定，走完防具还剩多少打本体。

默认规则表（= 重写前六个分支的原样翻译）：

| 模式             | 二类防具                    | 一类防具        | 本体              |
| -------------- | ----------------------- | ----------- | --------------- |
| `Norm`         | 溢出扣                     | 溢出扣         | 剩余伤害            |
| `Penetration`  | 照扣但**不消耗**伤害（啃食 / 爆炸）   | 溢出扣         | 剩余伤害            |
| `Real`         | **跳过**（地刺 / 寒冰菇 / 残血流失） | 溢出扣         | 剩余伤害            |
| `BowlingFront` | 扣 400，不往下传              | 扣 800，不往下传  | 固定 1800         |
| `BowlingSide`  | 扣 1800，继续传 1800         | 扣 800，不往下传  | 固定 1800         |
| `Hammer`       | **跳过**                  | 扣 900，不往下传  | 清空（`curr_hp`）   |

> **新增一种 `ConstDamage.E_DamageMode` 要改两处**：
> `ArmorComponent.get_absorb_rule()` 与 `HpComponentZombie.get_body_damage()`。
> 漏了就是**静默不掉血**（没有任何报错）。

### 打掉一整层防具

```gdscript
## 磁力菇吸铁器 / 气球被门框挤破 / 梯子搭到植物上
var armor := zombie.get_armor(ConstArmor.E_ArmorType.Ladder)
zombie.break_armor(armor, false, false)
```

⚠️ **走 `break_armor()`，不要直接给 `curr_hp` 赋 0**：它内部用「从最外层到目标层的血量之和」
当伤害值走一次 `Norm`，沿链溢出刚好把那几层扣光、不碰更内层与本体，同时照样触发
破损信号 / 外观 / 掉落 / 联机事件。直接赋值只是数字变了。

## 4. 防具存在时的特殊效果（由防具组件自己定义）

基类 `ArmorComponent` 留了两类钩子，**重写哪个防具的哪个钩子，就是哪件防具自己说了算**，
本体与僵尸子类都不需要认识它：

| 钩子                          | 何时调用                          | 用来做什么                   |
| --------------------------- | ----------------------------- | ----------------------- |
| `on_armor_equip()`          | 角色 ready 之后一次（见 `Zombie000Base.ready_norm()`） | 存在期间持续有效的东西（浮空、免疫…）    |
| `on_armor_break()`          | 本层血归零时一次（掉落表现已走完）             | 破防才触发的东西（报纸暴走、气球落地…）   |
| `is_immune_slow()`          | 被寒冰豌豆 / 冰冻查询时                 | 默认：**二类防具挡减速**（原版口径）    |
| `is_immune_butter()`        | 被黄油查询时                        | 默认 `false`             |
| `get_iron_node()`           | 磁力菇找铁器时                       | 默认返回 `iron_node`        |

消费方只问宿主，宿主只做转发（K-01）：

```gdscript
zombie.is_slow_immune      ## HpComponentZombie.is_immune_slow() → 逐层问防具
zombie.is_butter_immune
zombie.get_armor(ConstArmor.E_ArmorType.X)      ## 按类型取一件
zombie.get_magnet_armor()                       ## 取最外层还没被吸走的铁器防具
```

## 5. 已迁移的现存防具

| 防具            | 类别  | 血量    | 脚本                            | 备注            |
| ------------- | --- | ----- | ----------------------------- | ------------- |
| 路障            | 一类  | 370   | `component_armor.gd`          |               |
| 铁桶            | 一类  | 1100  | `component_armor.gd`          | 铁器（磁力菇可吸）     |
| 橄榄球头盔         | 一类  | 1400  | `component_armor.gd`          | 铁器            |
| 矿工镐           | 一类  | 100   | `component_armor.gd`          | 另有 `IronItem` |
| 铁门            | 二类  | 1100  | `component_armor.gd`          | 铁器 + 挡减速      |
| 报纸            | 二类  | 150   | `component_armor_newspaper.gd` | 挡减速 + 破防暴走    |
| 梯子            | 二类  | 500   | `component_armor.gd`          | 铁器 + 挡减速      |
| 气球            | 一类  | 20    | `component_armor_balloon.gd`  | 浮空 / 破防落地     |
| 14 只植物僵尸头顶植物  | 一类  | 300 / 1100 / 2200 | `component_armor_plant_head.gd` | 详见 [植物僵尸.md](植物僵尸.md) |

铁器**道具**（跳跳棒 / 小丑盒 / 矿工镐）不是防具，仍在 `Zombie000Base.iron_type = IronItem`
+ `iron_node` 上，由子类重写 `loss_iron_item()`；磁力菇先找铁器防具、再找铁器道具。

> 原版之外加的防具（铜桶 / 钻石桶 / 下界合金桶）**不在本表** —— 它们在模组
> `mods_builtin/more_armor/` 里，靠热注册 + `build_runtime_parts()` 装到铁桶僵尸的骨架上
> （见 [模组机制.md](模组机制.md) §6.3）。要改它们的数值去模组里改，本体不认识这三件。
>
> 其中**铜桶自带一层防具脚本**（`armor_copper_bucket.gd`，本文件的子类）：它随时间氧化、
> 涨易伤倍率，且**只放大本层防具吃掉的那部分伤害**（放大出来的伤害不往下传，所以不啃本体）
> ——「防具自己决定自己挨多少打」这条照样成立，本文件一行都不用改。

## 6. 回归

```powershell
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_armor_component
```

`test/scenarios/probe_armor_component.gd` 锁死三件事：各场景的防具节点能被收集到（类别 / 血量对得上）、
四种典型模式的分配没被改坏、同类防具能叠加（`absorb_priority` 决定谁先挨打）。

> ⚠️ 它**进了一个普通白天关**才打伤害：防具破损掉落的掉落物要挂到 `zombie_manager` 下，
> 关卡之外实例化僵尸打伤害会报 `Nil`（不是防具的问题，本体掉手那条路同样如此）。

## 7. 联机

僵尸渲染快照里那两个 3 位防具阶段槽（bit 3~5、6~8）**不再是「一类 / 二类」**，
改成**按 `armor_list` 下标的前两层** —— 两端场景同源 ⇒ 下标一致，对号入座；超过两层的部分不进快照
（`netplay_state_sync.gd` 的 `RENDER_Z_ARMOR_SLOT0_SHIFT` / `RENDER_Z_ARMOR_SLOT1_SHIFT`）。
客户端侧由 `ArmorComponent.apply_stage_from_snapshot()` 照阶段号补演破损外观。
