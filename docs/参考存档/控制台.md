# 控制台（可扩展的调试开关面板）

> **[面向 AI Agent]** ｜ **触发条件**：要加 / 改本体的一个调试开关；或要弄清楚**模组**入口在哪（入口页最后一个「模组」按钮 → 模组页面）

> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：照老写法去场景里加第 12 个 CheckBox；或给模组写 `register_console_entries()`（这个钩子已经删了）

## 一、控制台是什么

主菜单 →「选项」→「控制台」（游戏内：暂停菜单 →「控制台」）那一层
（`CanvasLayerConsole`）。它装的是**调试 / 偏好开关**，
不是给玩家看的正经设置项（正经设置项在 `ConfigService` 里有各自的字段与信号）。

> 那个按钮 2026-10-11 从「选项设置」改名为「控制台」（主菜单：选项 → 控制台）；
> 游戏内那份 2026-10-12 同样改名并独占一行（原先「查看图鉴」占左半、「选项设置」占右半，
> 「查看图鉴」已移除：游戏内看图鉴改由主菜单进入）。

2026-10-08 之前它是**硬编码**的：场景里手写 11 个 CheckBox，脚本里 11 个 `_on_check_box_N_toggled`，
`ConfigService` 里 11 个字段 + load / save 各 11 行。加一项要动三处，模组完全没地方挂。
现在**条目是数据**：谁都能往注册表里登记一条，面板只负责把它变成控件。

面板本身是**分页**的（2026-10-09 起），没有滚动条：

```
打开控制台 ──▶ 入口页（每个分组一个按钮 + 一个「模组」按钮）──点某个分组──▶ 该分组的那一页
                    ▲────────────────── 底部「返回」───────────────┘
                    │
                    └──点「模组」──▶ 模组页面（盖在控制台上，关掉它回到入口页）
```

入口页列出注册表里的**每一个分组**，分组页只放这一组的控件；新登记一个新分组 →
入口页自动多一个按钮、面板自动多一页，什么都不用改。

入口页最后那个「模组」按钮是**场景里挂出来的**：`CanvasLayerConsole.mod_page_path`（`@export NodePath`）
填了才有（现在只有主菜单那份填了 `StartMenuOptionDialog/Button4/ModPage`）；游戏内那份没填，
就没有这个按钮。**没挂就什么都不用改**。

一句话判据：

> **加一项 = 往 `ConsoleRegistry` 登记一条 `ConsoleEntry`**，面板 / 场景 / `ConfigService` 都不用改。

## 二、四件套

| 文件                                                    | 类                        | 作用                                          |
| ----------------------------------------------------- | ------------------------ | ------------------------------------------- |
| `src/ui/console/console_entry.gd`                     | `ConsoleEntry`           | **一条条目**（数据）：id / 分组 / 形态 / 读写回调              |
| `src/core/autoload/console_registry.gd`               | `ConsoleRegistry`        | 注册表（`Global.console_registry`）：登记 / 撤销 / 查询 / `entries_changed` |
| `src/ui/console/console_builtin_entries.gd`           | `ConsoleBuiltinEntries`  | 本体内置的 12 条（自动 3 / 显示 7 / 调试 2 三组）              |
| `src/ui/ui_main_game_menu/canvas_layer_control.gd`    | `CanvasLayerConsole`     | 面板：打开时把条目渲染成控件，改动时写回条目，事件来了读回控件（入口页的「模组」按钮由 `@export mod_page_path` 决定有没有） |
| `src/ui/console/console_entry_control.gd`             | `ConsoleEntryControl`    | **条目 → 控件的渲染器**（控制台与[模组页面](模组机制.md#七模组页面左列表--右详情)共用）      |

> 渲染为什么不在面板里写死：模组页面也要显示模组自己的那一批开关（联机的目标 / 开启房间 / 状态…），
> 与其抄第二遍，两边共用 `ConsoleEntryControl`（一个实例造一堆控件、`refresh()` 一次刷全部值）。

场景 `src/ui/control_canvas_layer.tscn` 里**只剩**标题（`OptionBG/Label`）、一个空容器
（`OptionBG/PageRoot`）和关闭按钮 —— 页面与控件全是运行时造的。
页面 = `VBoxContainer`，都在 `build_console_panel()` 时一次造齐（分页只切 `visible`，翻页不用重建），
切 API 是 `show_page(page)`。

数据流：

```
登记方（本体；探针 / 调试脚本也可临时登记）──register_entry()──▶ ConsoleRegistry ──get_categories()/get_entries()──▶ CanvasLayerConsole
                                              │                                                    │
                                              └──entries_changed──（面板开着就重建）──────────────────┘
用户点控件 ──▶ entry.set_value() ──▶ ConfigService 字段 或 ConfigService.console_values（关控制台时存盘）
```

## 三、加一项的三条路径

### 3.1 本体的内置开关 → 改 `ConsoleBuiltinEntries`

一条一行，写进对应的 `_register_*_entries()`：

```gdscript
_add(registry, ConsoleEntry.create_toggle(&"my_option", "我的选项")
	.set_tooltip("鼠标悬停时显示的说明")
	.set_category(ConsoleBuiltinEntries.CATEGORY_DISPLAY)
	.set_order(80)
	.bind(func() -> bool: return Global.config_service.my_option,
		func(value: bool) -> void: Global.config_service.my_option = value))
```

⚠️ **不要在登记时读 `Global.config_service`** —— `ConsoleRegistry` 挂在 `Global` 下，它的 `_ready()`
跑在 `Global` 的 `@onready` 之前，那时 `Global.config_service` 还是 null。一律写进 lambda（取值时才读）。

### 3.2 「ModBase.register_console_entries()」已经撤了：模组的界面去**模组页面**

2026-10-11 起模组**不再**往控制台挂条目（历史写法 `ModBase.register_console_entries()` 与
`ModManager` 给每个模组放的 `mod_switch_*` 开关都已删除）—— 模组的列表 / 开关 / 详情统一在
**模组页面**（主菜单 → 选项 → 控制台 →「模组」，见 [模组机制.md](模组机制.md#七模组页面左列表--右详情)）：

```gdscript
## 模组页面右侧那一块：显示什么、能改什么全由模组决定
func create_detail_control() -> Control:
	var box := VBoxContainer.new()
	var builder := ConsoleEntryControl.new()   ## 一个实例能造一堆控件，refresh() 一次刷全部值
	box.add_child(builder.create_control(
		ConsoleEntry.create_toggle(&"glove_free_move", "手套无视冷却")
			.bind_config("glove.free_move", false)))
	return box
```

想复用五种形态就用 `ConsoleEntry` + `ConsoleEntryControl`（面板与模组页面共用同一个渲染器，见 §一），
**不必**也不应该再 `register_entry()` 进注册表。

### 3.3 运行期临时加 → 直接调注册表

探针 / 调试脚本可以在任何时候 `Global.console_registry.register_entry(...)`；
面板下次打开（或正开着就立刻）会重建，新条目就出现了。
（`test/scenarios/probe_console_registry.gd` 就是这么验的。）

## 四、五种形态（`ConsoleEntry.E_Kind`）

| 形态      | 工厂                                                          | 需要绑什么                    | 面板上的样子        |
| ------- | ----------------------------------------------------------- | ------------------------ | ------------- |
| Toggle  | `create_toggle(id, text)`                                   | `bind()` 或 `bind_config()` | CheckBox      |
| Button  | `create_button(id, text, action)`                           | 无（点一次跑一次 `action`）         | Button        |
| Slider  | `create_slider(id, text, min, max, step)`                   | `bind()` 或 `bind_config()` | 名字 + HSlider + 数值 |
| Text    | `create_text(id, text, default)`                            | `bind()` 或 `bind_config()` | 名字 + LineEdit |
| Readout | `create_readout(id, text, getter)`                          | 只绑取值（没有 setter，改不了）       | 名字 + 值（Label） |

**Text**（要填一段文字，如联机的 `地址:端口`）：`set_placeholder()` 设浅色提示，
**回车或输入框失焦时**才写回条目 —— 面板回写值时会跳过**正在获得焦点**的输入框，免得把打到一半的文字顶掉。

**Readout**（要显示一段随时在变的文字，如联机的连接状态）：只读，**值变了由登记方自己通知面板**：

```gdscript
## 登记
registry.register_entry(ConsoleEntry.create_readout(&"xxx_status", "状态", _status_text).set_category("xxx"))
## 自己内部状态一变就喊一声（面板不一定开着，关着就什么都不做）
func _on_state_changed() -> void:
	Global.console_registry.request_refresh()
```

`ConsoleRegistry.request_refresh()` 发 `values_changed`，面板收到就把值重读一遍（不重建控件）；
比起重建整个面板，这条路径便宜得多，也允许值频繁变。

把「输入框 + 三个按钮 + 一行状态」凑齐的例子见 [联机模组.md](联机模组.md) §七
（2026-10-11 起它不再登记进注册表，而是直接由 `create_detail_control()` 搬到**模组页面**上显示）。

配置方法都是链式的：`set_tooltip()` `set_category()` `set_order()` `set_source()` `set_placeholder()` `set_enabled_getter()`
（最后一个返回 false 时控件置灰，例如「只在关卡内才可用」）。

## 五、持久化：两条线，都不用改 `ConfigService`

| 场景                       | 用法                                       | 落在哪                                            |
| ------------------------ | ---------------------------------------- | ---------------------------------------------- |
| 本体已有的正式字段（如 `open_all_level`） | `.bind(getter, setter)` 直接绑字段            | `config.ini` 的 `[user_control]`（老位置，行为不变）       |
| 新增项（本体）                  | `.bind_config("前缀.键名", 默认值)`              | `ConfigService.console_values` → `config.ini` 的 `[console]` 段 |
| **模组的设置**                 | `.bind(getter, setter)` 里读写 `ModManager.get/set_mod_value()` | **模组存档文件** `user://<用户名>/mod_config.ini`（与模组开关同一份，见 [模组机制.md](模组机制.md#21-模组存档文件user用户名mod_configini)） |

`console_values` 是**整包读写**的通用键值区：加一个持久化开关不需要给 `ConfigService` 加字段，
也不用补 load / save 各一行。键名建议带前缀避免撞键。
存盘时机与原来一致：**关掉控制台时** `save_config()`。

> **模组的设置不进这条线**（2026-10-11）：`bind_config()` 落在 `config.ini`，与模组开关不在一份文件里；
> 模组要持久化就用 `ModManager.set_mod_value()`（存进模组存档文件，帧末自动落盘）。

## 六、模组开关 → 已搬到**模组页面**（控制台里没有「模组」那一组了）

2026-10-11 之前 `ModManager` 会给每个模组在「模组」组里放一个开关；现在那组**整个撤了** ——
开 / 关模组去**模组页面**：主菜单 → 选项 → 控制台 → 入口页最后那个「模组」按钮
（见 [模组机制.md](模组机制.md#七模组页面左列表--右详情)），
点一下就 `ModManager.set_mod_enabled()`（**直接存进模组存档文件**，下次启动照旧）。

> 因此控制台的分组只剩本体那三组（自动 / 显示 / 调试）；
> `probe_console_registry` 里有一条**反断言**：控制台里出现「模组」条目即 FAIL。

生效范围（与 `ModManager` 的装载时机一致）：

- 打开：立刻补一次 `install()`；
- 关闭：立刻 `uninstall()`，但**已经装进当前这一局主游戏的节点要下一局才消失**；
- 开关与设置都落在 `user://<用户名>/mod_config.ini`（`data/mods/mod_config.tres` 只是播种用的工程默认）。

## 七、验证

改动较小 → **免验证**（判定见 [验证流程.md](../验证流程.md) §1）。

要验证就跑无头探针（不用开窗口）：

```powershell
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_console_registry
```

它验的是「可扩展性本身」：内置 12 条在不在、分组齐不齐（只有本体那三组，没有「模组」）、
内置项有没有真写到 `ConfigService`、运行期登记三种形态后面板会不会立刻多出对应控件、
撤销登记方后条目与控件有没有一起消失。模组那一侧的回归跑 `-Scenario probe_mod_page`。

> 探针数「条目带来的控件」时会跳过面板自己造的翻页按钮（入口页的分组按钮 / 分组页的「返回」，
> 都带 meta `CanvasLayerConsole.NAV_META`）—— 它们的数量跟着分组数变，不跟条目走。

人工看一眼（画面类改动建议做一次）：
- 游戏内：进任意关卡 → 暂停 → 控制台，应先停在**入口页**（每个分组一个按钮），
  点进去才看到该组的开关；**整屏没有滚动条**，关掉控制台后重进仍在；又回到了入口页。
  这一份没挂模组页面，**入口页不该有「模组」按钮**。
- 主菜单：选项 → 控制台（按钮已改名为「控制台」）→ 入口页最后多点一下「模组」→
  模组页面盖在上面（左列模组 / 右侧详情）；关掉它回到控制台入口页。

## 八、历史

- 2026-10-08 之前：11 个 CheckBox 硬编码在 `control_canvas_layer.tscn` + 11 个 `_on_check_box_N_toggled`。
- 2026-10-08 改成数据驱动（`ConsoleRegistry` + `ConsoleEntry`），并给 `ModBase` 加了
  `register_console_entries()` 钩子；顺带修掉「开放所有关卡」的 tooltip 抄了上一条的文案。
- 分组顺序 = 条目第一次登记的顺序，组内按 `order` → id 排序，保证每次打开顺序一致。
- 2026-10-09 去掉 `ScrollContainer`，改成**分页**：入口页 + 每个分组一页，`ScrollContainer` 换成

  探针里给按钮统计加了 `NAV_META` 过滤，免得翻页按钮随分组数变化干扰增量断言。

- 2026-10-11 **模组页面搬进控制台**：主菜单「选项」面板里原来那个单独的「模组」按钮撤掉，

  下面两行位置不动。图鉴入口只剩主菜单那一个。
