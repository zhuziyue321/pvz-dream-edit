## 一、一张图由什么决定

```
关卡资源 src/levels/**/*.tres   (ResourceLevelData)
  ├ game_sences : MainSceneRegistry.MainScenes   ← 选默认地图（不再选场景文件）
  ├ map_data    : ResourceMapData                ← 可选覆盖；留空则按 game_sences 取默认图
  ├ game_BG     : ConstLevelData.GameBg          ← 背景贴图（白天/黑夜/泳池/浓雾/屋顶）
  └ 玩法参数：出怪、卡槽、罐子、我是僵尸 …
        │
        │  ResourceLevelData.resolve_map_data()              (level_data.gd:305)
        ▼
  MainSceneRegistry.DEFAULT_MAP_PATHS[game_sences]             (main_scene_registry.gd:50)
        │  延迟 load（map_data.gd 反向引用了 MainScenes 枚举，preload 会循环依赖）
        ▼
  data/map/map_front.tres       5 行 × 9 列  草地（白天 / 夜晚）
  data/map/map_pool.tres        6 行 × 9 列  泳池 / 浓雾
  data/map/map_roof.tres        5 行 × 9 列  屋顶（带斜面）
  data/map/map_front_1row.tres  5 行 × 9 列  草地（1-1 专用，只有中间 1 行有草皮）
  data/map/map_front_5row.tres  5 行 × 9 列  草地（1-2 / 1-3 专用，只有中间 3 行有草皮）
  data/map/map_boss.tres        5 行 × 9 列  夜屋顶（5-10 僵王关专用，几何同屋顶）
        │  全部由唯一的主游戏场景加载
        ▼
  src/main/main_game_base.tscn
     ├ 管理器、UI、相机、各 CanvasLayer
     ├ CanvasLayerBG/Background：背景贴图 + 房子 + 常驻的 RoofSlope（非屋顶地图会被释放）
     └ 空的 PlantCellsRoot / ZombiesRoot（都在场景原点）
```

`MainSceneRegistry.MainScenesMap` 里五个主游戏枚举**全部指向同一份场景**
（[main_scene_registry.gd:28](../../src/core/autoload/main_scene_registry.gd#L28)）。
`game_sences` 现在的唯一作用就是反查默认地图，它不再决定加载哪个 `.tscn`。

## 二、数据格式

### 2.1 `ResourceMapData` —— 一张图

[data/map/map_data.gd](../../data/map/map_data.gd)

| 字段 | 类型 | 含义 |
|---|---|---|
| `game_sences` | `MainSceneRegistry.MainScenes` | 反查默认地图用（关卡没覆盖 `map_data` 时）；**不再决定加载哪个场景** |
| `display_name` | `String` | 备注名，只用于日志 |
| `map_bg_script` | `GDScript` | 本地图的**背景动画脚本**（`MapBgAnimBase` 子类），见 [§四.5](#45-背景动画脚本mapbganimbase) |
| `have_slope` | `bool` | 是否有屋顶斜面（**逻辑侧**，不进动画脚本） |
| `zombie_go_home_panel` | `Rect2` | 僵尸进家面板 `PanelZombieGoHome` 的矩形（房门位置每张图不同） |
| `zombie_go_home_marker` | `Vector2` | 僵尸进家落点 `Marker2DZombieGoHome` 的局部坐标 |
| `col_x` | `PackedFloat32Array` | 每列左边缘 x（长度 = 列数） |
| `col_width` | `PackedFloat32Array` | 每列格子宽（长度 = 列数） |
| `rows` | `Array[ResourceMapRowData]` | 每行定义（长度 = 行数） |

> 前四个字段是「场景合并」后从 5 份 `.tscn` 里搬过来的美术 / 装配参数：
> `map_bg_script` 走表现，`have_slope` 与进家位置走逻辑，两者互不掺。

方法：

- `get_row_num()` / `get_col_num()`
- `get_cell_rect(row, col)` —— 格子矩形，公式见下
- `get_default_zombie_row_type()` —— 全行同类型则返回该类型，水陆混合返回 `Both`
- `is_valid()` —— 校验：行数、列数 > 0；`col_x` 与 `col_width` 等长；行非空；`row_height > 0`。失败写 `Log.error`

```gdscript
# 第 row 行第 col 列的格子矩形（坐标相对 PlantCellsRoot，后者在场景原点）
x = col_x[col] + row_data.get_col_dx(col)
y = row_data.row_y + row_data.get_col_dy(col)
w = col_width[col]
h = row_data.row_height
```

### 2.2 `ResourceMapRowData` —— 一行

[data/map/map_row_data.gd](../../data/map/map_row_data.gd)

| 字段 | 默认 | 含义 |
|---|---|---|
| `plant_cell_type` | `Grass` | 该行格子地形（Grass / Pool / Roof / **Unsodded 无草皮**），逐格复制 |
| `zombie_row_type` | `Land` | 该行僵尸行类型（Land / Pool / Both / **None 不出怪**） |
| `row_y` | 0 | **行节点的平地基准 y**（不是第 0 列格子的绝对 y，见第七节） |
| `row_height` | 96 | 该行格子高 |
| `col_dx` | — | 逐列额外 x 偏移；缺省 / 越界当 0 |
| `col_dy` | — | 逐列额外 y 偏移（屋顶阶梯）；缺省 / 越界当 0 |
| `zombie_create_global_pos` | (950, 0) | 该行僵尸生成点，全局坐标（僵尸原点在脚部） |
| `have_lawn_mover` | true | 该行**是否配备**小推车（false = 该行没有小推车，如没铺草皮的行） |
| `lawn_mover_type` | 0 | 该行小推车类型（`GIM_LawnMover.E_LawnMoverType`：0 草坪 / 1 泳池 / 2 屋顶） |
| `have_rake` | false | 该行是否有钉耙（见下） |

**`have_rake`：钉耙落哪一行**（生成逻辑在 `src/managers/game_item_manager/gim_rake.gd`）

- **放不放**：`GlobalGameState.rake_use_num > 0`（钉耙是商店商品，$200 买一次管 3 关，
  见 [选关界面与解锁.md](./选关界面与解锁.md)）；砸罐子这类没有自然刷怪的玩法不放。
- **放哪一行**：取所有 `have_rake = true` 的行；一行都没标时兜底到**正中间那条陆地行**
  （原版放在「第一只僵尸出现的那一行」，本仓库没有拖拽换行的交互，先用地图数据 + 中间行兜底）。
- **放在哪一列**：固定**从右数第 2 列**（原版 wiki：*the second column (from the right)*），
  x = `col_x[col] + col_width[col] / 2 + get_col_dx(col)`，
  y = `zombie_create_global_pos.y + get_col_dy(col)`（脚部基准，屋顶斜面用 `col_dy`）。
- **触发**：同行僵尸踩上去 → 1800 点穿透伤害（除巨人类与高坚果僵尸外当场击杀）→ 把手弹起 → 钉耙消失；
  本关放过钉耙就在通关结算时消耗一次使用次数（原版没踩到也算用掉）。

### 2.2.1 「没铺草皮」的行：三个开关一起关

原版冒险模式一周目是**逐步铺草皮**的（wiki：`Day` 条目 —— 1-1 只有 1 行草皮，1-2 / 1-3 有 3 行，1-4 起 5 行）。
没铺草皮的行在玩法上是「三不」：**不能种植物、不自然出怪、没有小推车**。三个开关各管一段：

| 想要的效果 | 数据 | 实现 |
|---|---|---|
| 不能种植物 | `plant_cell_type = Unsodded` | `PlantCell.init_condition()` 把地形条件置 0，任何植物的种植条件与之相与都为 0（不能改用 `can_common_plant`，它会被 `_update_state_plant()` 按特殊状态重算） |
| 不出怪（行仍在） | `zombie_row_type = None` | `ZombieChooseRowSystem` 给该行三种权重都是 0；选行兜底分支也会跳过这些行 |
| 没有小推车 | `have_lawn_mover = false` | `GIM_LawnMover` 用 `all_lane_have_lawn_mover` 记录，生成与补充（含读档）都跳过该行 |

> `ResourceMapData.get_default_zombie_row_type()` 会**忽略 None 行**再判水陆。
> 否则「1 行草地 + 3 行 None」会被判成 `Both`，水陆僵尸全进自然刷怪白名单。

`get_col_dx(col)` / `get_col_dy(col)` 对负数和越界都返回 0，所以数组可以只写前几列。

#### 2.3.1 前院「未铺草皮」底图与草皮叠加

原版冒险模式一周目是**逐步铺草皮**（1-1 只 1 行、1-2/1-3 三行、1-4 起满 5 行）。
这几张前院图用两张贴图叠出这种效果，由 `ResourceMapData` 上两个可选字段驱动
（`BackgroundManager.init_sod_overlay()` 在 `init_background()` 里装配，见 [§4.0](#40-背景管理器--backgroundmanager)）：

| 字段 | 作用 |
|---|---|
| `bg_base_texture` | 非空时**替换**按 `game_BG` 选出的背景贴图（1-1~1-3 用它指向 `background1unsodded.jpg` 无草皮底图）；留空则继续按 `game_BG` 取（`map_front` / 泳池 / 屋顶图都留空） |
| `bg_sod_overlay` | 非空时按地图里 `Grass` 行与列边界算出的矩形，在底图上叠加草皮条（`sod1row.png` / `sod3row.png`）；只盖标记成 `Grass` 的行，未铺草皮的 `Unsodded` 行不盖 |

组合结果（与玩法上的「几行草皮」一一对应）：

| 关卡 | 地图数据 | 底图 | 草皮叠加 | 视觉 |
|---|---|---|---|---|
| 1-1 | `map_front_1row` | `background1unsodded` | `sod1row`（覆盖索引 2） | 未铺草皮底图 + 中间 1 行草皮 |
| 1-2 / 1-3 | `map_front_5row` | `background1unsodded` | `sod3row`（覆盖索引 1/2/3） | 未铺草皮底图 + 中间 3 行草皮 |
| 1-4 起 | `map_front` | ——（按 `game_BG` 取 `background1`） | 无 | 满 5 行草皮 |

> 草皮叠加的矩形由 `map_data` 的 `Grass` 行（`row_y` / `row_height`）与列边界（`col_x` / `col_width`）
> 算出，与 `PlantCellManager` 生成的格子几何完全一致，所以草皮正好盖住没铺草皮底图上的对应车道。
> 叠加节点挂在 `Background`（`CanvasLayerBG`，layer -10）下，天然位于格子（layer 0）之下。

## 三、关卡如何拿到地图

`ResourceLevelData` 上有两个相关字段（[level_data.gd:25-32](../../src/levels/core/level_data.gd#L25-L32)）：

```gdscript
@export var game_sences: MainSceneRegistry.MainScenes = MainSceneRegistry.MainScenes.MainGameFront
## 留空时按 game_sences 取场景默认地图
@export var map_data: ResourceMapData
```

`resolve_map_data()` 的优先级（[level_data.gd:253](../../src/levels/core/level_data.gd#L253)）：

1. `map_data` 已经非空 → 原样保留（**关卡覆盖优先**）；
2. 否则按 `game_sences` 查 `MainSceneRegistry.DEFAULT_MAP_PATHS`，`load()` 后缓存；
3. 都没拿到 → `Log.error("关卡 %s 没有可用的地图数据…")`。

**调用时机**：主游戏 `MainGameManager._enter_tree()` → `set_game_para()` → `game_para.resolve_map_data()`
（[main_game_manager.gd:142-156](../../src/managers/main_game_manager.gd#L142-L156)），
在 `_ready()` 调 `init_manager()` 之前完成。各子管理器（格子 / 僵尸行 / 小推车）在 `_ready` /
`init_manager` 里才读 `map_data`，所以顺序没问题。`ResourceLevelData.init_para()` 也会再调一次
（幂等），用于出怪白名单。

> **现状**：绝大多数关卡不写 `map_data`，地图按 `game_sences` 取场景默认图（前院 / 泳池 / 屋顶三选一）。
> 夜晚草坪 / 浓雾泳池 / 生存和自定义关卡都复用这三张图。
> **要用特殊地图的关卡在自己身上直接指定 `map_data`** —— 目前有四关这么做：
> 冒险 **1-1 → `map_front_1row.tres`（5 行，只有中间 1 行有草皮）**、
> **1-2 / 1-3 → `map_front_5row.tres`（5 行，只有中间 3 行有草皮）**（两张新图目前复用前院白天贴图，

> 冒险 **5-10 → `map_boss.tres`（5 行全屋顶，[夜屋顶](#232-夜屋顶僵王关的底图与背景子场景)）**，

> 几何仍与 `map_roof` 完全相同。
>
> ⚠️ **不要为某一关往 `MainSceneRegistry.MainScenes` 里加枚举值**。这三个槽位曾叫
> `MainGameFront1Row` / `MainGameFront5Row` / `MainGameBoss`，已删除：它们指向的是同一份主游戏场景，
> 只为「选一张不同的地图」而存在，属于把关卡差异顶到全局枚举上。场景枚举只描述「主游戏用哪份场景」，

### 4.0 背景管理器 —— `BackgroundManager`

[background_manager.gd](../../src/managers/background_manager.gd)

`init_background()` 先做一件事：**按 `map_data.map_bg_scene` 实例化对应地图的背景子场景**（含背景贴图宿主 `Background`、房子 `Home`、屋顶 `RoofSlope`、僵尸进家面板 / 落点），挂到 `CanvasLayerBG` 下，并取出 `background` / `home` 引用；再依次做：

1. 背景贴图：`ConstLevelData.GameBgTextureMap[game_para.game_BG]`（白天 / 黑夜 / 泳池 / 浓雾 / 屋顶）。
2. 房门：`home.init_home(game_BG)` 打开对应背景的门内部图与遮罩；`is_zombie_can_home = false` 时禁用房子。
3. **表现**：按 `map_data.map_bg_script` 挂一份地图动画脚本（[§4.5](#45-背景动画脚本mapbganimbase)）。
4. **逻辑**：`init_map_bg_logic()` —— 按 `map_data.have_slope` 从背景子场景里取 `RoofSlope`
   （仅屋顶子场景带它，其它地图子场景没有，缺失即跳过），并按 `zombie_go_home_panel` / `zombie_go_home_marker`
   从子场景里取出僵尸进家面板 / 落点后摆放（数值由 `map_data` 决定，数据驱动）。

> **背景必须永远在 `CanvasLayerBG` 的最底下**：背景子场景是**运行期** `add_child` 进来的，
> 而画布层的绘制顺序就是子节点顺序 —— 直接 `add_child` 会排在末尾，把场景里原有的兄弟节点
> （`GameItemsInBg`，**保龄球红线**就挂在它下面，`z_index` 同为 0）整片盖住，表现为「红线不见了」。
> 所以 `init_background()` 挂完立刻 `move_child(bg_instance, 0)`。
> 回归探针：`test/scenarios/probe_bowling_redline.gd`（`[BOWLINGSTRIPE] result=PASS`）。
>
> **红线的出现时机与节点显隐是两回事**：`init_item()` 里就把红线左右两边的格子打好
> 「不可种植 / 不可走僵尸」标记（`set_bowling_no_plant()` / `set_bowling_no_zombie()`），
> 但节点本身先 `visible = false`，等戴夫念到「我们去玩保龄球！」（`on_talk_event = show_bowling_stripe`）
> 才画出来；没有这段对话的场合由 `MainGameManager` 在预览僵尸前调
> `GameItemManager.gim_other.show_bowling_stripe()` 兜底显示。

### 4.1 植物格子 —— `PlantCellManager`

## 五、坐标与索引约定（**改地图前必读**）

1. **行号 = 一切的行索引**：`PlantCell.row_col.x`、`Zombie000Base.lane`、`all_zombie_rows`、
   `all_zombies_2d`、`all_ice_roads`、小推车 `lane`、子弹 `lane` 全部同一套（0 = 最上一行）。
2. **列号 0 = 最左列**：等于 `all_plant_cells[row]` 的下标。关卡数据里的 `plant_cell_pos` 是
   **1 基、从左到右**（`plant_cell_pos.y - 1` 才是列下标）。
3. **不再依赖 RTL 镜像**：格子与行节点都在原点，每个格子的 `position` / `size` 是显式正坐标，
   所以 `get_rect()` 的局部坐标 == 地图数据坐标。历史上那套
   「行节点 `layout_direction = 3` + 负 `offset_*` + 靠 RTL 落到屏幕内」的做法已随手摆地图一起废弃。
4. **屏幕坐标 ≠ `get_global_rect()`**：关卡有 `Camera2D`（位置 120,0，入场时还会移动）。
   实测 `canvas_origin = (-120, 0)`，即 `screen_x ≈ rect.x - 120`。
   要点格子 / 判断鼠标压住哪个控件，一律用 `get_global_transform_with_canvas()`
   （见 [项目规范.md](../项目规范.md) 的 S-03，以及 [AI调试通道.md](../AI调试通道.md) 第六节）。
5. **渲染层次**（`main_game_base.tscn`）：

   | 层 | 节点 | 内容 |
   |---|---|---|
   | -10 | `CanvasLayerBG` | 背景图、房子、展示僵尸面板 |
   | 0（默认画布） | `PlantCellsRoot` / `ZombiesRoot` / `LawnMovers` / `Bullets` / `Bombs` / `BrainOnZombieMode` | 格子、僵尸行、小推车、子弹、炸弹、阳光 |

   | 6 | `CanvasLayerDropItem` | 金币等掉落、`CoinBankLabel` |

   | 20 | `CanvasLayerTemp` | 手持物、`RealShovel` |
   | 30 | `CanvasLayerEffect` | 全屏特效（冰、毁灭菇） |
   | 50 | `CanvasLayerUI` | UI |
   | 60 | `CanvasLayerAlmanac` / `CanvasLayerConsole`（`CanvasLayerUI` 子层） | 图鉴 / 控制台 |

6. **同一层内按 `z_index = 行号 * 50 + 槽位` 排序**（全部由代码在运行时赋值，场景里写的会被覆盖）：

   | 槽位 | 内容 | 赋值处 |

## 六、行类型（Land / Pool / Both）

「这行是不是水」的事实现在只有**两份**数据（旧实现里还有第三份场景表
`MainSceneRegistry.ZombieRowTypewithMainScenesMap`，已随迁移删除）：

| # | 数据 | 位置 |
|---|---|---|
| 1 | 每行 `plant_cell_type`（Grass / Pool / Roof），生成时复制到每个格子 | `ResourceMapRowData.plant_cell_type` |

- 出怪选行权重（[zm_zombie_choose_row_system.gd:43](../../src/managers/zombie_manager/zm_zombie_choose_row_system.gd#L43)）

> 水陆混合的图（泳池 / 浓雾）整体算 `Both`。改图时这一条要自己保证。

## 七、屋顶特化

- **格子是阶梯摆放的**：`col_dy = [99,84,63,45,17,0,0,0,0]`（5 行相同），第 6 列起贴平。
  `row_y`（88/173/259/343/430）是**行节点的平地基准 y**，第 0 列格子的绝对 y 是 `row_y + col_dy[0]`。
- 斜面节点常驻在唯一主场景里：[main_game_base.tscn](../../src/main/main_game_base.tscn) 的
  `CanvasLayerBG/Background/RoofSlope`（position `(420, 0)`，子节点 `Slope` 为
  [slope.tscn](../../src/world/background/slope.tscn) 实例，position `(-210, 0)`），
  `SegmentShape2D a=(0,122) b=(460,0)`（约 14.9°），5 个 `Area2DReal` 对应 5 行。
  非屋顶地图由 `BackgroundManager.init_slope()` 直接 `queue_free()`，免得斜面碰撞体留在场景里；
  引用由 `main_game.main_game_slope` 持有（不再靠场景里的 NodePath 导出）。
- `MainGameSlope.get_all_slope_y(x)`（[main_game_slope.gd:14](../../src/world/background/main_game_slope.gd#L14)）
  按 x 取相对 y：僵尸入场落位（`zombie_base.gd:204`）、僵尸放置虚影
  （`hand_component_character.gd:260`）、抛物线子弹影子、玉米加农炮都查它。
- `GlobalUtils.update_plant_cell_slope_y()` / `…_array()`（[global_utils.gd:8-25](../../src/core/autoload/global_utils.gd#L8-L25)）
  用 `plant_cell.slope_step_y`（由 `PlantCellManager` 按 `get_col_dy` 赋值）把检测面
  **从阶梯位置反向补偿回 `row_y` 水平基准**。非屋顶地图 `slope_step_y` 恒为 0，等于空操作。
- ⚠️ **不要用 `plant_cell.position.y` 代替 `slope_step_y`**：数据驱动之后 `position.y` 是格子的
  **绝对 y**（含 `row_y`），拿它当阶梯偏移会把整行高度减到检测框的本地坐标上，受击框被抬走，
  僵尸会直接穿过植物不啃。消费点在 [plant_base.gd:119](../../src/entities/character/plant/plant_base.gd#L119)、
  `scary_pot.gd:74`、`ladder.gd:14`、`brain_on_zombie_mode.gd:27`。

## 八、新增 / 改造一张地图的步骤

1. **做数据**：复制最接近的 `map_*.tres`，在编辑器里改成目标几何；
   或者复制旧的手摆场景后用一次性工具导出（见第九节）。
2. **保证矩形**：每行列数一致，`col_x` / `col_width` 长度 = 列数，`rows` 长度 = 行数。
3. **逐行填**：`plant_cell_type`、`zombie_row_type`、`row_y`、`row_height`、
   `zombie_create_global_pos`（y 对准该行脚部）、`have_lawn_mover`、`lawn_mover_type`、`have_rake`。
   要做「没铺草皮的行」就按 §2.2.1 把三个开关一起关。
4. **屋顶**：逐行填 `col_dy`；`row_y` 写**行节点 y**，不要写第 0 列格子的绝对 y；
   并勾上 `have_slope = true`（否则 `RoofSlope` 会被释放）。
5. **表现**：填 `map_bg_script`（指向一张 `MapBgAnimBase` 子类）。
   复用 `map_bg_anim_front` / `map_bg_anim_roof` 就不必写新脚本；要有新表现就按
   [§4.5](#45-背景动画脚本mapbganimbase) 加一份子类，**不要**往 `BackgroundManager` 里加分支。
6. **进家位置**：按目标背景图的房门填 `zombie_go_home_panel` / `zombie_go_home_marker`
   （前院 `Rect2(92,0,200,600)` / `(72,424)`；泳池 `Rect2(50,-19,200,600)` / `(72,424)`；
   屋顶与夜屋顶 `Rect2(-5,-304,204,491)` / `(117,448)`）。
7. **注册**：只有在 `MainSceneRegistry` 里新增枚举时才需要补 `MainScenesMap` 与 `DEFAULT_MAP_PATHS`；
   **不要再新增主游戏场景文件** —— 六个 `MainScenes` 已经全部指向 `main_game_base.tscn`。
   地图专属的静态表现节点走「新增一份 `src/world/background/main_game_bg_<地图>.tscn` 背景子场景」，
   并在本资源里登记 `map_bg_scene` 指向它（见 [§四.0](#40-背景管理器--backgroundmanager)）；
   新增时直接复制最接近的现有背景子场景改即可，无需动宿主场景。
   如果这张新地图还配了**新的 `GameBg` 枚举成员**，必须同步把 `MainGameHome.door_downs` /
   `door_masks` 补到同样长（下标与 `GameBg` 一一对应），见 [§2.3.2](#232-夜屋顶僵王关的底图与背景子场景)。
8. **关卡指向**：关卡资源的 `game_sences` 选默认地图；要特殊地图就直接在关卡里指定 `map_data`。
9. **进关卡看日志**：`validate_map_consistency()` 无 error 即通过。
10. **跑探针**：见第九节。

> 小推车类型不用单独维护：它跟着 `map_data.rows[].lawn_mover_type`，行数也由数据决定。

## 十、已知坑

- **屋顶 `row_y` 必须是「行节点的 y」而不是第 0 列格子的 y**：`slope_step_y` 按 `col_dy`
  把检测面反向补偿回 `row_y`。写错会让整行错约 99px，植物 / 僵尸检测框不重叠 → **互相不索敌**
  （平地地图 `col_dy[0] = 0`，所以只有屋顶会犯）。
- **不要写死行数**：行数取自 `zombie_manager.all_zombie_rows.size()`（出怪选行系统曾写死 6 行，
  5 行地图的兜底分支会返回越界行号）。
- **僵尸行节点统一用 `Node2D`**：`Panel + clip_children` 会把该行僵尸裁剪在面板矩形内。
- **关卡 `.tres` 里不要写 `属性 = null`**：nil 赋值对带类型的脚本属性等于没写（回落默认值），
  看起来像「关掉了小推车 / 选卡」，实际是默认值；要显式写值。
- **存档按 `row_col` 作数组下标**（[plant_cell_manager.gd:604-613](../../src/managers/plant_cell_manager/plant_cell_manager.gd#L604-L613)），
  所以列号方向与行列顺序属于**存档格式的一部分**：改 `row_col` 语义、改列数或调整列顺序会让老存档整体错位 / 镜像。
- **`plant_cell.size` 必须在 `add_child` 之前设**：`PlantCell._ready` 会按当时的尺寸记录各容器节点
  初始位置，之后再改尺寸不会重算这些基准。
