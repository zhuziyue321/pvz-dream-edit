# 资源注册表（AssetRegistry）—— 图片 / 音频 / 字体 / 场景的统一取用口

> **[面向 AI Agent]** ｜ **触发条件**：要在一个 `.gd` 里**取任何资源**（贴图 / 音频 / 字体 / `.tscn` / `.tres`）之前  
> **读完你能**：知道该调哪个方法、缓存是什么语义、运行期（模组 / 自制关卡）怎么注册自己的素材；不会再写出裸 `load("res://pak/...")` 或无人管理的 `preload`  
> **强制级别**：**参考**（不读不打回，但裸 `load` 会被评审问「为什么不用 AssetRegistry」） ｜ **不读的风险**：同一个贴图被多个脚本各加载一份、音效表在启动时全部常驻内存、模组素材没地方登记  
> **关联**：硬约束 [../项目规范.md](../项目规范.md) §1-4 / §1-5 ｜ 模组素材根 [模组机制.md](模组机制.md) ｜ 场景类型映射 [../../src/core/autoload/scene_registry.gd](../../src/core/autoload/scene_registry.gd)

---

## 1. 它解决什么

改造前「取资源」有三套写法同时存在：

| 旧写法 | 代表位置 | 问题 |
|---|---|---|
| 各注册表里 `preload` 好塞进 const 字典 | `SceneRegistry` / `LootRegistry` / `SoundManager` | const 注定常驻；想要「运行期换绑 / 模组替换」无门 |
| 业务脚本里裸 `load("res://pak/...")` | 背景图、BGM、字体 | 同一个文件被加载多次，改路径时全文搜不到 |
| `.tscn` 的 `ext_resource` | 动画 / 字体 / 贴图 | **这条不用改**（见 §6 边界） |

现在统一为：**所有代码取资源都经 `AssetRegistry`**（`src/core/resource/asset_registry.gd`，`class_name AssetRegistry`，纯 static，**不是 autoload**）。

## 2. API 速查

| 想要 | 调 |
|---|---|
| 贴图 | `AssetRegistry.get_texture(key)` → `Texture2D` |
| 音频 | `AssetRegistry.get_audio(key)` → `AudioStream` |
| 字体 | `AssetRegistry.get_font(key)` → `Font` |
| 场景模板 | `AssetRegistry.get_scene(key)` → `PackedScene` |
| 场景实例 | `AssetRegistry.instantiate(key)` → `Node`（**只创建，不入树**） |
| 任意资源 | `AssetRegistry.get_resource(key)` → `Resource` |
| 预热 | `AssetRegistry.prefetch([key1, key2])` |
| 运行期登记路径 | `AssetRegistry.register(&"我的贴图", "res://mods/.../x.png")` |
| 运行期登记内存资源 | `AssetRegistry.register_asset(&"我的贴图", tex)` |
| 撤销 / 查询 | `unregister(id)` / `has(id)` / `get_path(id)` |
| 缓存维护 | `is_cached(key)` / `uncache(key)` / `clear_cache()` / `clear_all()` / `reload(key)` / `get_stats()` |

失败语义统一：**取不到 / 类型不符 → `Log.error` + 返回 `null`**，调用方照旧判空（与 `BulletRegistry.get_bullet_scenes` 同款）。

## 3. 三种 key，混用不冲突

```gdscript
## 1) 绝对路径：最常见，硬约束 §1-5 要求写全 res://
var tex := AssetRegistry.get_texture("res://pak/images/Taco.png")

## 2) 逻辑 id：自己登记一个短名字，业务代码只认 id
AssetRegistry.register(&"loot_taco", "res://pak/images/Taco.png")
var taco := AssetRegistry.get_texture(&"loot_taco")

## 3) 内存资源：模组现生成、没有磁盘路径的素材
AssetRegistry.register_asset(&"mod_logo", some_texture)
```

- 缓存 key 是**解析后的路径**：同一个文件用 id 和路径各取一次，只加载一份。
- `register()` 要求路径形如 `res://...` / `user://...`，否则直接 `Log.error` 不登记。
- 重复 `register()` 同一 id = 覆盖登记（缓存里已有的旧资源不主动丢弃，需要时 `uncache(old_path)`）。

---

## 4. 缓存语义（容易踩）

- 缓存是 **static、进程级**：不随场景切换清空，跨关卡复用。
- 只是「从缓存字典里摘引用」，被场景节点持有着的资源不会真的释放；要回收内存调 `clear_cache()`（id 表与内存资源保留），全清调 `clear_all()`（主要给测试）。
- 没有容量上限 / LRU：这个仓库的资源基本是「整章都要用」，做淘汰反而增加抖动。真需要时在 `_cache` 上加。
- `reload(key)` 用于改完素材后热重载（先 `uncache` 再取）。

## 6. 边界：这几类**不用**改

1. **`.tscn` 的 `ext_resource`**：场景数据绑定，不是代码取用；改了反而破坏编辑器里的资源依赖。
2. **`data/**/*.tres` 里的 `ExtResource`**：同上，数据驱动。
3. **角色 / 子弹 / 掉落物注册表内部的场景登记**：它们本身就是「类型 → 场景」的**唯一入口**（硬约束 §1-4）。登记值可以是路径或 `AssetRegistry.get_scene` 的结果，但**业务代码不允许再绕开注册表直接取**。
4. **`mods_builtin/` 里的模组素材**：走 `ModManager.load_mod_asset(mod_id, rel_path)`（双源解析 `user://mods/` 优先），它有自己的 `_asset_cache`；模组往本体登记资源时用 `AssetRegistry.register`。

---

## 7. GDScript 的两个硬坑（本次踩过）

1. `const` 的初始值必须是常量表达式 → `const X := AssetRegistry.get_scene(...)` **编译不过**。
   改写后按取用点选声明：实例方法用 `var`；只有 static 函数取用才用 `static var`。
2. `static` 函数只能访问 `static` 成员 → 把 const 改 `var` 后，原来在 static 函数里读它的地方会报
   `Cannot access non-static variable "X" from the static function`。看到这条就把那个成员改成 `static var`。

编译门禁能抓这两类（`test/check_scripts.ps1`，含 `test/scenarios/*.gd`）。
