# AI 查 wiki 避坑

> **[面向 AI Agent]** ｜ **触发条件**：要从 PVZ wiki（`wiki.pvz1.com` / `plantsvszombies.fandom.com`）取数值、机制、关卡数据**并写进代码**之前
>   
> **读完你能**：① 按可信度分级选对数据源；② 识别 12 类常见坑（版本混淆、改版污染、表格错位、单位不一致、抓取静默失败…）；③ 走「查 → 交叉验证 → 落位 → 写来源注释」的流程落地数据
>   
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：把二代 / 改版 / 社区误编辑的数值当成**原版一代**数据写进常量，错误会静默扩散到解锁进度、血量、伤害、关卡表，且任何静态检查都抓不到（数据错误 ≠ 代码错误，只能打开游戏看对不对）
>   
> **关联**：仓库入口 [../AGENTS.md](../../AGENTS.md) ｜ 文档地图 [README.md](../README.md) ｜ 常量落位 [../src/core/consts/readme.md](../../src/core/consts/readme.md) ｜ 验证 [验证流程.md](../验证流程.md)

> **本仓库复刻的是：原版《植物大战僵尸》一代（PC，冒险模式 50 关）。**
>   
> 一切 wiki 数据只有在确认「一代原版」身份后才可落地。

## 0. 速查表：症状 → 坑 → 做法

| #  | 症状 / 触发场景                                  | 坑                                        | 正确做法                                                        |
| -- | ------------------------------------------ | ---------------------------------------- | ----------------------------------------------------------- |
| 1  | 页面里出现"阳光消耗 100 / 冷却 5 秒"但和记忆不符             | **版本混淆**（一代 / 二代 / GOTY 年度版 / 手机版 / 主机版） | 先确认页面属于一代；本仓库只认**一代 PC 原版**                                 |
| 2  | 数值在两个 wiki 上不一样                            | **多站口径不同**，且各自可能错                        | 交叉验证（§2），取不到一致就标"待核实"，不要猜一个                                 |
| 3  | 查到"杂交版 / 自制植物 / Last Stand / 花园战争"         | **改版与 fanmade 污染**                       | 看 URL 与页面分类；含 `Fanmade`、`PvZ2`、`Modded` 一律丢弃                |
| 4  | 抓回来的正文里混着"Plants / Zombies / Community"导航词 | **页面框架污染**（侧栏、面包屑、推荐卡、广告）                | 用 §3 的 raw / API 接口取纯 wikitext                              |
| 5  | 表格按"第 N 行第 M 列"读出来的值和表头对不上                 | **rowspan / colspan / 脚注上标 / 图片占位**导致错位  | 按表头逐格匹配，不按行列序号；空单元格 ≠ 0                                     |
| 6  | 按中文名"寒冰射手"搜不到页面                            | **译名不统一**                                | 用**英文原名**定位（Snow Pea），再回仓库 `CharacterRegistry` 对枚举          |
| 7  | 关卡序号对不上（"3-4" 写成 3.4 / 304）                | **序号口径**不统一                              | 本仓库口径：`(区域-1)*10 + 小关号`，`3-4` = **34**，见 `ConstUnlockLevel` |
| 8  | 伤害 / 血量数值量级差一倍                             | **单位不统一**（内部值 vs 表现值、HP 点数 vs 豌豆颗数）      | 落地时注释写明单位与换算依据                                              |
| 9  | wiki 与实机表现不符                               | **wiki 本身过时 / 编辑错误**                     | 以解包数据或实机录像为准（§2 分级 A 级）                                     |
| 10 | 抓取返回空 / 登录墙 / 只有 JS 壳                      | **抓取静默失败 → AI 幻觉补齐**                     | 没拿到正文就**不得下结论**，换路径或明确报告"查不到"                               |
| 11 | 想从 wiki 下载图鉴图 / 动画帧当素材                     | **版权风险**（原版素材已因版权移出本仓库）                  | 只引用数值与机制描述，不下载原版美术 / 音频                                     |
| 12 | 数值被写进业务脚本、来源无从追溯                           | **落位与溯源缺失**                              | 常量放 `src/core/consts/`，来源 URL 写进头部注释（§5）                     |
| 13 | 要给关卡补戴夫台词，wiki 上只查得到英文                     | **中文台词没有权威 wiki 源**                      | 英文原文取 wiki.gg 关卡页 / `Plants_vs._Zombies/Dialogue` 的 Dialogue 段；中文按游戏中文版语音转写（如喜马拉雅语录贴）并与英文逐句对应，存疑的词写 `待核实` 注释 |

## 1. 查之前：先确认三件事

1. **我要查的是什么**：数值（伤害 / 血量 / 阳光 / 冷却）/ 机制（触发条件、优先级）/ 关卡表（解锁、出怪、铺草皮）。
2. **单位是什么**：写下来，落地时一并写进注释。
3. **仓库里是不是已经有了**：先 `grep` 一遍（`src/core/consts/`、`data/`、`data/almanac/almanac_data.json`）。
     
   **仓库已有数据是第一顺位**，wiki 只用于补齐与核验 —— 已有数据与 wiki 冲突时，不要直接改代码，先向用户确认。

---

## 2. 数据源可信度分级

| 级别    | 来源                                     | 用法                           |
| ----- | -------------------------------------- | ---------------------------- |
| **A** | PAK 解包数据、原版实机录像 / 实测                   | 可直接落地，冲突时以它为准                |
| **B** | `wiki.pvz1.com`（中文，一代专精）               | 可落地，建议再找一个来源交叉验证             |
| **C** | `plantsvszombies.fandom.com`（英文，覆盖全系列） | 落地前**必须**确认页面是一代原版，非改版 / 非二代 |
| **D** | 百科、自媒体、视频文案、**AI 自身记忆**                | 只能当搜索线索，**禁止**直接落地           |

> **禁止凭记忆写数值。** AI 记忆里的 PVZ 数据（血量、冷却、解锁关）与 wiki / 原版常有偏差，不查就写等同编造。

## 3. 取正文：别抓渲染后的页面

推荐接口（返回纯 wikitext，避开导航 / 广告 / 推荐卡）：

| 站点                           | 取正文方式                                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| `wiki.pvz1.com`（DokuWiki）    | `https://wiki.pvz1.com/doku.php?id=<页面>&do=export_raw`                                           |
| `plantsvszombies.fandom.com` | `https://plantsvszombies.fandom.com/wiki/<页面>?action=raw`                                        |
| Fandom 搜索                    | `https://plantsvszombies.fandom.com/api.php?action=query&list=search&srsearch=<关键词>&format=json` |

注意：

- **pvz1 中文页面 URL 需百分号编码**：`教程:植物图鉴` → `教程%3A植物图鉴`（冒号是 `%3A`）。直接拼中文 + 冒号会跳到搜索页或 404。
- **页面不存在不等于数据不存在**：Fandom 常有重定向与"该内容在 XX 页"的合并页，先搜索再下结论。
- **抓取失败要如实报告**，不要用记忆补齐（坑 #10）。

## 4. 判定「这是一代原版吗」

落地前逐条过一遍，任一不满足即丢弃该页面：

- [ ] 站点 / 分类指向一代：Fandom 页面无 `Category:Plants (Plants vs. Zombies 2)` 之类二代分类；pvz1 wiki 页面不在"自制 / 改版"命名空间。
- [ ] 无 fanmade / modded 标记（URL 或页面模板含 `Fanmade`、`Modded`、`Fan-Made`）。
- [ ] 页面形态是一代：冒险模式 50 关、白天 / 夜晚 / 泳池 / 浓雾 / 屋顶五场景、无"植物能量 / 叶绿素 / 世界地图"。
- [ ] 数值与已落地的 A/B 级来源不冲突；冲突时按 §2 以高级别为准。

## 5. 落地规范（写完要能溯源）

1. **落位**：数值与关卡表放 `src/core/consts/`（见 [../src/core/consts/readme.md](../../src/core/consts/readme.md)），机制类写进对应资源 / 组件，**禁止**把 wiki 数值散落在业务脚本里。
2. **写来源注释**：在文件头或常量上方写清 `## 数据来源: <站点>(<URL>)`，必要时补一句口径说明（单位、版本、关卡序号算法）。
3. **有疑必标**：无法交叉验证的写 `## 待核实: <疑问>`，不要用看起来确定的数值掩盖不确定。
4. **要不要验证**：改动较小 / 确定不会出问题 → 免验证；否则**打开游戏实测**（判定见 [验证流程.md](../验证流程.md) §1）。
5. **触达玩法行为** → 按 [验证流程.md](../验证流程.md) 人工回归清单在真窗口里确认（数据错误只有跑起来才看得出来）。

**正例**（本仓库已有，照此格式）：

```gdscript
## 冒险模式进度解锁常量(植物以外的解锁:模式、花园、铲子、金钱、商店、商店扩展)
## 冒险模式 50 关的关卡序号: 1-1 = 1 …… 5-10 = 50(即 (区域-1)*10 + 小关号)
## 数据来源: PVZ Wiki(https://plantsvszombies.fandom.com/wiki/Money 、
## https://plantsvszombies.fandom.com/wiki/Crazy_Dave%27s_Twiddydinkies)

## 铲子解锁: 通关冒险模式 1-4 后疯狂戴夫把铲子交给玩家,1-1 ~ 1-4 期间没有铲子
const SHOVEL_UNLOCK_ADVENTURE_LEVEL := 4
```

（摘自 `src/core/consts/const_unlock_level.gd`）

同类先例：`src/core/consts/const_plant_unlock.gd`（植物解锁进度）、`docs/参考存档/地图实现.md` §2.2.1（草皮铺放行，引用 wiki `Day` 条目）。

**反例**：

```gdscript
# 反例 1：来源不明、单位不明、版本不明
const ZOMBIE_HP := 270

# 反例 2：把二代 / 改版数值当一代
const SUN_COST := 100  ## 冷知识:这是二代数值

# 反例 3：数值藏在业务脚本里
func _on_hit() -> void:
	hp -= 20  ## wiki 说豌豆伤害 20(哪来的? 什么单位? 谁写的?)
```
