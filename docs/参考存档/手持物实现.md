# 手持物（组件化）实现

> **[面向 AI Agent]** ｜ **触发条件**：新增手持物（卡片、铲子、锤子、手套）之前
> **读完你能**：走「枚举 + 组件脚本 + 挂节点」三步扩展，明确**不改** `HandManager`
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：按旧实现去改 `HandManager` 加 `match` 分支，违反红线第 7 条
> **关联**：仓库入口 [../AGENTS.md](../../AGENTS.md) ｜ 文档地图 [README.md](../README.md)

手持物 = 玩家用鼠标"拿在手上"的东西：**植物/僵尸卡片**、**铲子**（后续的锤子、手套同属此类）。
本文说明它的组件化结构、事件时序，以及"新增一个手持物要改哪里"。

> 旧实现是 `HandManager` + `hm_character.gd` / `hm_item.gd` / `hm_null.gd` 三个平行类，
> 靠 `match` 硬编码派发；现改为**手持物组件机制**，`HandManager` 只做注册与派发。

## 一、文件与节点

| 文件 | 类 | 作用 |
|---|---|---|
| `src/managers/hand_manager/hand_manager.gd` | `HandManager` | 调度器：注册组件、派发事件、手持⇄空手切换、界面统一刷新 |
| `src/managers/hand_manager/component/hand_component_base.gd` | `HandComponentBase` | 手持物组件基类（抽象） |
| `.../component/hand_component_null.gd` | `HandComponentNull` | 空手（兜底）：花盆提示、敲罐子 |
| `.../component/hand_component_character.gd` | `HandComponentCharacter` | 手持卡片：美术、虚影、种植、紫卡提示（**只做通用校验**，不含任何玩法分支） |
| `.../component/hand_component_shovel.gd` | `HandComponentShovel` | 手持铲子：跟随、高亮、铲除、铲子界面 |
| `.../component/hand_component_glove.gd` | `HandComponentGlove` | 手持手套：搬运场上的植物（不铲除不重种）、高亮、手套界面 |
| `.../component/hand_component_hammer.gd` | `HandComponentHammer` | 手持锤子：拿起 / 放下锤子美术（锤僵尸玩法的两关专用，默认禁用，见 §六） |

节点结构（都在 `src/main/main_game_base.tscn`）：

```
MainGame
├── Manager/HandManager            (手持物调度器)
│   ├── HM_Null      (Node2D + HandComponentNull)
│   ├── HM_Character (Node2D + HandComponentCharacter)
│   ├── HM_Item      (Node2D + HandComponentShovel)
│   ├── HM_Glove     (Node2D + HandComponentGlove)
│   └── HM_Hammer    (Node2D + HandComponentHammer)
├── CanvasLayerCardSlot/CardSlotRoot/CardSlotContainer/ShovelContainer
│   ├── UIShovel                   (铲子槽，图标由铲子组件控制显隐)
│   └── UIGlove                    (手套槽，紧贴铲子右侧，不占卡牌槽)
└── CanvasLayerTemp (layer 20, follow_viewport_enabled)
    ├── TemporaryCharacter         (手持卡片美术的挂载点)
    ├── RealShovel                 (跟随鼠标的真铲子)
    ├── RealGlove                  (跟随鼠标的真手套)
    └── RealHammer                 (跟随鼠标的真锤子，锤僵尸玩法专用，见 §六)
```

**为什么组件是 `Node2D`**：复用 `ComponentNormBase` 的启停机制（`is_enabling` + `E_IsEnableFactor`），
所以和角色组件一样是 `Node2D`。**为什么美术不挂在组件下**：手持物必须画在卡槽之上、
且跟随画布变换（有关卡相机），所以可视节点留在 `CanvasLayerTemp`，组件只引用它们。

## 二、组件机制

`HandComponentBase extends ComponentNormBase`，生命周期函数**只有当前手持组件会收到**：

| 函数 | 何时调用 | 约定 |
|---|---|---|
| `_ready_component()` | 注册时调一次（重写这里，**不要重写 `_ready`**） | 读关卡参数、订阅自己触发的事件 |
| `get_hand_component_type()` | 注册时 | 抽象方法，子类必须返回自己的 `E_HandComponentType` |
| `enter_hand(payload)` | 切到本组件 | 返回 `false` = 拒绝手持，管理器退回空手 |
| `exit_hand()` | 切走本组件 | **必须幂等**（可能没 enter 就被调、也可能连调两次） |
| `hand_process()` | 每帧 | 跟随鼠标之类 |
| `mouse_enter/exit/click_cell(cell)` | 格子的 `cell_mouse_enter/exit/click_cell` 信号 | `click_cell` 返回 `true` = 这次点击用完了手持物（回空手） |
| `refresh_ui()` | 手持切换 / 启停变化 / 游戏阶段变化 | 收敛**自己那部分界面**的显隐 |

`HandManager` 对外接口：

```gdscript
hand_manager.take_hand(HandComponentBase.E_HandComponentType.Shovel)   # 拿到手上，返回是否成功
hand_manager.drop_hand()                                              # 放回空手
hand_manager.change_hand_component_enable(类型, true/false)            # 启用/禁用一个手持物
hand_manager.get_curr_hand_type() / is_holding_hand() / curr_plant_cell
hand_manager.get_hand_component(类型)                                  # 取组件本体
```

关键点：

1. **`curr_hand_component` 永远非空**——空手就是一个组件（`HandComponentNull`），
   所以派发路径上没有 `if 状态 == X` 的分支，也没有 `match`。
2. **组件被禁用就不能手持**：`take_hand` 会检查 `is_enabling`。
   铲子组件在 `_ready_component()` 里把自己禁用，条件由 `is_can_has_shovel()` 单点决定：

```gdscript
change_is_enabling(is_can_has_shovel(), E_IsEnableFactor.HandItem)

func is_can_has_shovel() -> bool:
	return game_para.is_shovel and Global.global_game_state.is_shovel_unlocked()
```

   两个条件缺一不可：**关卡参数**（`level_data.gd::is_shovel`，如 `minigame_101_small_gambling`
   这种不放植物的关卡）+ **全局解锁进度**（`ConstUnlockLevel.SHOVEL_UNLOCK_ADVENTURE_LEVEL = 4`，
   即通关冒险模式 1-4 后戴夫才把铲子交给玩家；1-1 ~ 1-4 卡槽不出现铲子）。
   解锁进度是从 `curr_all_level_state_data` 的通关记录推导的（`GlobalGameState.get_max_success_adventure_level()`），
   **不单独落库存档**，所以老存档、手改存档都自动生效。
   探针覆盖见 `-Scenario probe_hand` 第 0 节。
3. **非游玩阶段自动放手**：`HandManager` 订阅 `main_game_progress_update`，
   阶段不是 `MAIN_GAME` 就 `drop_hand()` + 刷新界面（轮次切换、游戏结束都不会残留手持物）。
4. **「空闲手持物」可以被关卡换掉**：`HandManager.set_idle_hand_type(类型)` 指定「放下手持物 /
   进入可操作草坪的阶段时回到哪个手持物」，默认是空手。锤僵尸那两关用它把**锤子变成自己的空手**
   （见 §六），所以那两关进 MAIN_GAME 锤子自动在手上、种完植物也回到锤子。
   空闲手持物**不算「手持中」**（`is_holding_hand()` 为 false），右键取消对它无效。

## 三、一次「点卡 → 种植」的时序

```
Card.Button.pressed
  → EventBus "main_game_click_card"          (card.gd::_on_button_pressed)
  → HandComponentCharacter._on_click_card    (组件自己订阅)
  → hand_manager.take_hand(Character, card)
       ├─ 旧手持物 exit_hand()               (同组件重复进入 = 重置)
       ├─ enter_hand(card)：造手持美术 + 格子虚影 + 紫卡闪烁
       ├─ refresh_all_hand_ui()              (各组件刷新自己的界面)
       └─ 若鼠标已在某格，补发一次 mouse_enter（Godot 不会重发 hover）
  → SoundManager.play_other_SFX("seedlift")

鼠标移动：HandManager._process → 组件 hand_process() → 美术 global_position = 鼠标

鼠标进/出格子：PlantCell 信号 → HandManager 派发 → 组件算虚影/高亮

格子 Button.pressed
  → PlantCell.click_cell 信号 → HandManager._on_click_cell
  → 组件 click_cell(cell)
       ├─ 种不下去：返回 false（播放 buzzer，手持物留在手上）
       └─ 种植成功：create_plant() → curr_card.signal_card_use_end → 返回 true
  → HandManager.drop_hand() → 回到空手

右键 / 左键点空白：HandManager._input → 播放 tap2 → drop_hand()
```

虚影规则（`_update_cell_shadow`）：植物走 `plant_condition.judge_is_can_plant`；
僵尸走行类型（`zombie_row_type`）与 `can_common_zombie`；通过则虚影 `modulate.a = 0.5`
并吸附到该格 `plant_container_node.global_position`。

**手持组件只做通用校验**：能不能种一律问格子（`judge_is_can_plant` / 行类型 / `can_common_zombie`），
组件里**没有任何玩法分支**。

「点一格种一整列」这种一关专属玩法不在这里 —— 它写在关卡脚本
[`minigame_12_column.gd`](../../src/levels/mode_minigame/minigame_12_column.gd) 里（硬约束 §1-8）：
关卡自己在 `init_level_items()` 里接格子的 `signal_plant_create` / `cell_mouse_enter` / `cell_mouse_exit`，
① 种下一株后同列其它可种的行补同一种；② 悬停时自己造、自己清理整列虚影（挂
`MainGameManager.canvas_layer_temp`，与手持组件的格子虚影同层）。
原来的 `is_mode_column`（关卡数据字段 + 手持组件里的 6 处分支）已整体删除，
详见 [特殊关卡.md](特殊关卡.md#迷你游戏-12-排山倒海column-like-you-see-em)。

## 四、铲子

拿取：`UIShovel/Button.pressed → EventBus "main_game_click_shovel" → 组件._on_click_shovel → take_hand(Shovel)`。

- 跟随：`RealShovel` 自己 `_process` 跟鼠标（`change_is_using(true/false)`）。
- 高亮：`mouse_enter` 取该格"将被铲除的植物"（多个植物时按鼠标 y 三分法选 Float/Norm/Shell），
  调用 `be_shovel_look()`（`z_index + 10` + 变黑）；`hand_process` 里随鼠标切换。
- 铲除：`click_cell` → `be_shovel_kill()`（先关亡语再死亡）→ 返回 `true` → 回空手。
  空格子返回 `false`，铲子留在手上。
- **界面归属**：卡槽铲子的显隐**只由铲子组件决定**（`refresh_ui`）：

```gdscript
var is_slot_visible := is_enabling and is_in_play        # 关卡有铲子 + 游玩阶段
ui_shovel.refresh_shovel_ui(is_slot_visible, is_slot_visible and not is_curr_hand())
```

  `UIShovel.refresh_shovel_ui(卡槽是否显示, 图标是否显示)`：卡槽本体（背景+按钮）
  在游玩阶段常显，铲子图标拿了就消失（屏幕上只剩跟随鼠标的那把）。

> `CardManager` 不再直接改 `ui_shovel.visible`。它在阶段/关卡参数上的判断已由
> 「组件的启用状态 + 主游戏阶段」取代。

## 五、手套

> **★ 当前功能已隐藏**：`ConstFeatureSwitch.GLOVE_ENABLED = false`，手套整条链路关闭
> （卡槽按钮 / G 快捷键 / 搬运交互 / 解锁判定 / 4-6 戴夫赠礼对话）。
> 实现方式见 [工作记录 2026-10-04](../../docs/工作记录/2026-10-04_隐藏关卡内手套功能.md)；改回 `true` 即完整恢复。
> 下面正文描述的是**开启时**的行为，代码与场景节点都保留未删。

拿取：`UIGlove/Button.pressed` 或快捷键 **G**（`ShortcutKeys_Glove`）→ EventBus `"main_game_click_glove"`
→ `HandComponentGlove._on_click_glove` → `take_hand(Glove)`。

- **获取时机（与铲子同一套口径）**：**通关冒险 4-5（关卡序号 35）后戴夫把手套交给玩家，4-6 起卡槽才出现手套**
  —— 4-6 是矿工僵尸首次登场的关卡，矿工从后排钻出，玩家第一次需要挪动已种下的植物，赠送即教学。
  所以 `is_can_has_glove()` 与铲子一样是**两个条件**：关卡参数 `game_para.is_shovel` +
  `Global.global_game_state.is_glove_unlocked()`（常量 `ConstUnlockLevel.GLOVE_UNLOCK_ADVENTURE_LEVEL`，
  与铲子的 1-4 同理由通关记录推导，不落库存档）。
- **赠礼演出**：4-6 开场戴夫举着手套讲用法（8 句，第 5 句举起手套、末句发疯收尾），
  资源在 `data/dave/dialog/adventure_04_06_glove.tres`，
  手上举的手套是 `src/dave/hand_item/hand_glove.tscn`；
  关卡资源上勾了 `dave_dialog_only_first_playthrough`，重玩已通关的 4-6 不再播。
- **交互**：手上没植物 → 点格子拿起（`click_cell` 返回 `false`，手套留在手上）；
  手上有植物 → 点目标格子放下，**成功才返回 `true` 回空手**；目标非法（不可种植 / 槽位被占）播 `buzzer` 且保持手持。
- **跟随**：`RealGlove` 自己 `_process` 跟鼠标；拿起植物后收起手套图标，改由植物跟随鼠标
  （`hand_process()`：`plant.global_position = temporary_character.get_global_mouse_position() - carry_offset`）。
- **取消 / 右键 / 退出**：`exit_hand()` → `_put_carry_plant_back()` 放回来源格子并还原 `z_index`（幂等）。

> **★ 状态保持的关键**：搬运期间**不把植物摘出场景树**，只把 `CanvasItem.top_level` 打开做视觉位移。
> 一旦 `remove_child` 脱离场景树，`Timer` 与 `_process` 会停 —— 攻击、产阳光、动画全部中断。
> `top_level` 的效果是「视觉上脱离父级变换，逻辑上仍是场景树的成员」。

格子侧 API 集中在 `src/items/plant_cell.gd` 的 `#region 手套搬运`：

| 函数 | 作用 |
|---|---|
| `glove_get_carry_plant()` | 按鼠标位置取本格子可搬运的植物（与铲子的选取规则一致） |
| `glove_take_plant(plant)` | 从本格子摘除：清槽位、结束高亮、断开死亡回调；底部植物（花盆 / 睡莲）额外把 Norm / Shell 容器搬回格子并还原地形 |
| `glove_get_put_place(plant)` | 植物放进格子时应占的槽位（模仿者走 `Imitater` 槽） |
| `glove_judge_can_put(plant)` | 与种植条件同源：格子无特殊状态 + 地形符合 + 槽位为空 |
| `glove_put_plant(plant, place)` | 放入：先无条件 `remove_child` 再 `add_child`、关 `top_level`、更新 `plant_cell / row_col / lane`、重连死亡回调 |

四个必须遵守的约定：

1. **不发 `signal_plant_create` / `signal_plant_free`**：搬运不改变场上植物总数，
   发了会让 `PlantCellManager` 的植物统计与教程判定错乱。
2. **`z_index` 是相对父级的值**（行层级 `row * 50 + 10` 挂在行节点上，植物自身多为 0），
   所以拿起时记原值再 `+ CARRY_Z_INDEX_UP`，放回时**原样还原**，**不能按行重算**（南瓜壳等自带偏移）。
3. **必须在 `glove_take_plant()` 之前记录 `plant.global_position`**：摘除后节点成孤儿，
   `global_position` 会退化成局部坐标，`carry_offset` 会算错（植物飞离鼠标）。
4. **玉米加农炮占两个格子**，只搬其中一株会破坏它的双格结构，`_can_take_plant()` 直接拒绝。

界面归属与铲子同规则：`refresh_ui()` 只让「组件启用 + 可操作草坪阶段」显示卡槽，
图标只在**不在手上**时显示（拿着时只留背景）。

## 六、新增一个手持物（现役例子：锤子）

四步走（锤子就是照这四步落地的，可直接照抄）：

1. `HandComponentBase.E_HandComponentType` 加一个枚举值（锤子 = `Hammer`，加在**末尾**，别插中间）。
2. 写 `hand_component_hammer.gd`：

```gdscript
extends HandComponentBase
class_name HandComponentHammer

## 跟随鼠标的真锤子（挂在 CanvasLayerTemp 下，与真铲子 / 真手套同层）
@onready var real_hammer: Hammer = %RealHammer

func get_hand_component_type() -> E_HandComponentType:
	return E_HandComponentType.Hammer

func _ready_component() -> void:
	## 是否可用由本玩法的规则决定 —— 不要为此在 ResourceLevelData 上加 `is_xxx` 开关：
	## 只有少数几关用到的手持物，默认禁用，由那几关的玩法规则启用
	change_is_enabling(false, E_IsEnableFactor.HandItem)

func enter_hand(_payload: Variant = null) -> bool:
	if is_instance_valid(real_hammer):
		real_hammer.set_is_used(true)
	return true

func exit_hand() -> void:
	if is_instance_valid(real_hammer):
		real_hammer.set_is_used(false)

func click_cell(_plant_cell: PlantCell) -> bool:
	## 锤子不靠点格子挥（它跟着鼠标，点屏幕任意非 UI 处都挥，见 hammer.gd），永远留在手上
	return false
```

3. 在 `HandManager` 下加一个 `Node2D`（`HM_Hammer`）挂这个脚本，美术 `RealHammer` 挂在 `CanvasLayerTemp` 下。
4. 由玩法规则启用，并设成那几关的**空闲手持物**（取代空手，见 §二 关键点 4）：

```gdscript
## src/levels/core/hammer_zombie/level_rule_hammer_zombie.gd（迷你游戏 15 / 冒险 2-5 两关共用）
mg.register_level_init_callback(func() -> void:
	mg.hand_manager.change_hand_component_enable(HandComponentBase.E_HandComponentType.Hammer, true)
	mg.hand_manager.set_idle_hand_type(HandComponentBase.E_HandComponentType.Hammer)
)
```

> 启用必须排在 `HandManager.init_manager()` 注册组件**之后**：关卡脚本的 `init_level_items()`
> 跑在它之前，那时直接调 `change_hand_component_enable()` 拿不到组件（静默失效），
> 所以走 `register_level_init_callback()`（该回调排在所有子管理器初始化之后）。

**不需要改 `HandManager`**（它没有任何手持物相关的分支）。

## 七、本次重构修掉的问题

| # | 旧实现的问题 | 现在 |
|---|---|---|
| 1 | `if click_card_column:` 把方法当条件（Callable 恒为真）→ **每次点卡都创建柱子虚影**，而清理被 `if is_mode_column` 挡住 → 非柱子关卡每点一次卡泄漏 5~6 个节点 | 创建改为 `if is_mode_column:`，清理无条件执行 |
| 2 | 点到不能种的格子会**静默丢卡**（`click_cell` 后无条件回空手） | `click_cell` 返回 `bool`，只有成功才回空手；失败播 `buzzer` |
| 3 | 拿着铲子再点一次铲子 → `Item→Item` 自转换触发 `exit_status()` → `ui_shovel_appear()` → **卡槽又出现一把铲子** | 界面显隐由组件 `refresh_ui()` 单点决定：拿着时图标必隐藏 |
| 4 | 轮次切换/游戏结束时手持物**冻结在屏幕中间盖住选卡面板** | 阶段不是 `MAIN_GAME` 时自动 `drop_hand()` |
| 5 | 铲子切换目标前不结束旧高亮；漏发 `mouse_exit` 时植物永久变黑/压层 | `mouse_enter` 先 `_clear_shovel_look()`；`exit_hand` 也清 |
| 6 | 子处理器全程无空值保护，只靠"状态==X 则数据一定在"的隐性契约 | 每个组件自己守边界（`is_instance_valid`），`exit_hand` 幂等 |
| 7 | 新增手持物要改 `HandManager` 的 5 处 `match` | 加枚举 + 加组件 + 加节点，`HandManager` 不动 |
| 8 | 关卡没有铲子这件事由 `CardManager` 和 `HM_Item` 各记一份 | 由组件从 `game_para` 读，单一真身 |
| 9 | 铲子从第一关就能用（原版是通关 1-4 后获得） | 额外叠加 `GlobalGameState.is_shovel_unlocked()`，未通关 1-4 时卡槽不出现铲子 |

改动较小 / 确定不会出问题 → **免验证**（判定见 [验证流程.md](../验证流程.md) §1）。

要验证就**打开游戏**（带窗口）跑探针，见 [AI调试通道.md](../AI调试通道.md)，报告自带 `[HAND] result=PASS`：

```powershell
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_hand -Windowed
```

`probe_hand.gd` 覆盖：**铲子解锁进度**（未通关 1-4 组件被禁用且卡槽隐藏，通关 1-4 后组件启用且卡槽出现）
→ 组件注册与初始状态 → 点卡手持 → **反复点卡节点不堆积**（问题 1 回归）
→ 种植成功扣阳光并回空手 → 点不能种的格子仍手持（问题 2）→ 右键取消

> 再调用 `change_is_enabling(is_can_has_shovel(), HandItem)` 让组件重算——
