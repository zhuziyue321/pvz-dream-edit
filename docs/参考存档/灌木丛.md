## 1. 机制口径与数据来源

> 来源：<https://pvz-dlc-edition.fandom.com/wiki/Woods>（`Camp` / `Forest` 都重定向到它）
> "Bushes spawn in this level, **preventing most plants from attacking zombies who walk
> through them**. Plants like **Beeshooter** are meant to counter this, and **exploding
> insta-kill plants can also counter bushes, being able to destroy them**. **Zombies can
> spawn from the bushes during ambushes, particularly during the final wave.** Also, if a
> **Lawn Mower collides with a bush, it will explode**, destroying only the zombies in front
> of that bush, making **Wood Chipper** necessary to shred the bushes and reach the end
> of the lawn."

落在本仓库的取舍（**各关的灌木数量 / 列区间维基没给，做成关卡自配**）：

| 项 | 取值 | 出处 |
| --- | --- | --- |
| 数量 | `init_bush_num`（关卡自配，默认 0） | 自定 |
| 位置 | 先长草坪右侧三分之二（9 列里的第 4~9 列），满了才轮到左三列 | 沿用墓碑规则（保守：障碍挡在右边） |
| 藏僵尸 | 受击状态位 `IsInBush = 128` | 本仓机制 |
| 摧毁 | 爆杀类 / 小推车撞上 | 维基 |
| 出怪 | 只在**最终波**，每丛灌木各放一只 | 维基 |

## 2. 实现清单

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 开关 | `ResourceLevelData.is_have_bush` / `init_bush_num` | 与墓碑同款；开局时（`MainGameManager.main_game_start()`）按数量生成 |
| 实体 | `src/items/bush.gd` + `bush.tscn`（`Bush extends Node2D`） | 挂在 `PlantCell` 下，占一格（`E_SpecialStatePlant.IsBush` → 不能种普通植物） |
| 生成 / 登记 | `src/managers/plant_cell_manager/bush_manager.gd`（`BushManager`） | 结构与 `TombStoneManager` 同款：只维护「该位置有没有灌木」的二维表，实例列表放 `PlantCellManager.bush_list` |
| 注册 | `SceneRegistry.BUSH`、`ConstEventName.CREATE_BUSH`（payload 签名已登记） | 主场景 `main_game_base.tscn` 的 `Manager/PlantCellManager/BushManager` 节点订阅该事件 |
| 藏僵尸 | `bush.gd` 的 `%Area2DHide` 进出 → `zombie.curr_be_attack_status = IsInBush` | 僵尸照常前进 / 啃植物，只是**大多数植物打不到它** |
| 摧毁 ① 爆杀 | `component_bomb_norm._bomb_all_enemy()` 里新增 `area_owner is Bush` 分支 | 灌木与梯子**共用 L12 道具层**，炸弹的 `Area2DBomb` 掩码是 2048+4，所以**没有一个炸弹场景需要改** |
| 摧毁 ② 辣椒 | `plant_cell_manager.jalapeno_bomb_item_lane()` 里加清灌木 | 火爆辣椒不走物理，走 `JALAPENO_BOMB_ITEM_LANE` 事件（原来只清冰道 / 梯子） |
| 摧毁 ③ 推车 | `lawn_mower._on_lane_bush_enter()` | DLC 口径：撞上就自爆，**只炸灌木前方（x 更大的一侧）的僵尸**，推车自己也没了 |
| 出怪 | `zm_zombie_wave_manager.call_bush_create_zombie()` | 最终波每丛灌木各放一只，种类取 `zombie_type_candidate_bush` |

## 3. 藏僵尸的判定链（想改豁免清单先看这里）

单一插入点是 `CanAttackStatusComponent.can_attack(enemy)`：位不匹配就判「打不到」。
灌木只是把僵尸的受击状态位换成 `128`，**没有任何攻击代码被改过** —— 默认掩码 `1` 的
攻击来源天然落空。想让某种攻击打到灌木里的僵尸，把 `128` 勾进它的掩码即可：

| 来源 | 掩码 | 场景 | 说明 |
| --- | --- | --- | --- |
| 普通植物 / 子弹 | `1`（默认） | —— | 打不到（DLC 里灌木的主要价值就在这） |
| 蜂射手 BeeShooter | `129` | `mods_builtin/dlc/beeshooter/plant_beeshooter.tscn` | DLC 官方指定的唯一反制手段 |
| 樱桃 / 毁灭菇 / 柠檬榴弹 | `191` | 各 `plant_*.tscn` | 爆杀克制灌木（连带把灌木也炸掉） |
| 火爆辣椒 | —— | —— | 它杀僵尸**不判** `can_attack`（走 `JALAPENO_BOMB_LANE_ZOMBIE` 事件），灌木里的僵尸照杀 |

`63 → 191` 的改动只影响新增的 128 位，跳跃 / 水下 / 空中 / 地下 / 跳入泳池几位原样保留。

推车**不在**豁免清单里（推车不是攻击判定，是撞上就爆）—— 这正是 DLC 让 Wood Chipper
成为必需品的原因。

## 5. 素材状态（PopStudio）

灌木的 DLC 素材是加密的 `.reanim.compiled`，**必须 PopStudio 解**（`_xml_in` → `_xml_out`）：

| 文件 | 状态 |
| --- | --- |
| `reanim/bushes3/4/5.reanim.compiled` | 🟡 已放进 `PVZ_DLC/_popstudio_in/reanim/`，**等你用 PopStudio 转 .reanim 到 `_xml_out/`** |
| `reanim/Bushes_charred.reanim.compiled` | 🟡 同上（灌木被烧焦的那帧） |
| `particles/BushesParticles.xml.compiled` | ✅ 已转出 `_particles_xml/BushesParticles.xml.compiled.xml`（碎屑粒子，用的是 `IMAGE_REANIM_BUSH_PARTICLE*`） |
| `particles/Zombie_bushes.xml.compiled` | ✅ 已转出 |

转完后由 converter 落到这三个路径（**灌木代码按路径存在与否自动取舍，缺哪张就用剩下的**）：

```
pak/images/woods_bush1.png
pak/images/woods_bush2.png

```

⚠️ 贴图没到位之前灌木**只是不出图**（`[Bush] 灌木贴图还没导入` 的日志），占位 / 藏僵尸 /
被炸 / 被撞的逻辑照常 —— 这是有意的：不等美术也能先把玩法跑通。

## 6. 验证

```powershell
# 灌木丛：场景契约 + 开局长灌木 + 藏僵尸 + 爆杀摧毁 + 推车撞灌木 + 灌木出怪
powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_bush
```

**人工肉眼验收**：把任意冒险关临时改成
`scene_name = SceneSettingRegistry.SCENE_WOODS` + `map_data = preload("res://data/map/map_woods.tres")`
+ `init_bush_num = 3` + `is_have_bush = true` 进关：

- 草坪右侧长出几丛灌木，灌木那一格种不下植物（卡片是灰的）；
- 僵尸走到灌木里时会被灌木挡住视线、**豌豆打不到它**，走出灌木后又照常挨打（用蜂射手就能打到）；
- 往灌木旁边丢一颗樱桃炸弹，灌木连着里头的僵尸一起没了；
- 让僵尸踩到小推车，推车冲出去撞到灌木就当场爆炸（只清掉灌木右边那几只）；
- 最终波每丛灌木会各冒出一只僵尸。
