## 1. 结构：一页一个背景，翻页不重建

| 元素 | 落点 | 说明 |
| --- | --- | --- |
| 背景页枚举 | `E_GardenBgType`（温室 / 蘑菇园 / 水族馆 / `TreeBg` 智慧树） | 智慧树是**第四页**，不是摆在花园角落 |

## 1.1 成长与需求：4 阶 + 真实时间戳（2026-10-24 对齐 `ZenGarden.cpp`）

主体在 `src/entities/character/components/garden/component_garden.gd`（`GardenComponent`）：

- **4 阶**：`Sprout / Small / Medium / Full`（原版 `PottedPlantAge`）。旧存档的 `Large(3)` / `Perfect(4)` 在读档归一化时并到 `Full(3)`；旧 `Perfect` 额外当成"今天已照顾过"，免得满级植物一读档就停产。
- **满级不再降级**：杀虫剂 / 留声机是满级植物的**日常需求**（原版 `PlantFulfillNeed`：掉 1 金，水生 / 夜行再 +2 金），不再是"Large → Perfect"的成长步骤。
- **需求每帧按真实时间戳算**（原版 `GetPlantsNeed`）：浇过水 15 秒内不要水（最小间隔 3 秒）→ 浇水次数 < `feedings_per_grow`(3~5) 要水 → 非满级要肥 → 满级按"跨 1 小时 + 跨自然日"刷新药 / 留声机。夜行植物在阳光房里不需要照顾；水生植物永远不要水（满级走药 / 留声机，非满级只在水族馆要肥料）。
- **产币**只在 `Full` 且"今天被照顾过"（`is_need_fulfilled_today()`：距上次满足 < 1 小时，或同一自然日）时跑：间隔 `RandRangeInt(1800, counterMax)` 帧（代码里换成秒），`counterMax` 随"距上次满足的分钟数"从 3000（5 分钟）线性涨到 15000（30 分钟）；金/银 = `Rand(1000) + curve(5→30 分钟, 0→80) < 100`。
- **巧克力**：`can_have_chocolate()` = 满级 + 今天已照顾 + 当前不嗨；喂完把下一次产币压到 1 秒（原版 `mLaunchCounter = 60`），嗨 300 秒。喂不上时道具不扣（`GardenItem05Chocolate` 会把刚扣的那块退回）。
- **物种入手即定**：`curr_plant_species`（原版 `mSeedType`）在花盆入队时就写死 —— 商店"金盏花幼苗"= 金盏花，僵尸 / 关卡礼包 = `GlobalGameState.pick_random_garden_plant_species()`（排除金盏花 / 花盆 / 幼苗 / 模仿者）。发芽期只画通用幼苗，苗→小时才换成该物种（`GardenComponent.up_growth_stage`）。
- **首进花园的戴夫教程**：进园后戴夫讲三句（介绍花园 → 讲水壶 → 送金盏花，见 `GardenManager.FIRST_VISIT_TUTORIAL_TEXTS`），**讲的同时就把 2 株金盏花放进待放置队列**（一次性标记 `is_first_visit_garden_plant_granted`）。本仓库没有通用教程状态机，所以只落"台词 + 送礼"这条结果，不做原版锁按钮 / 引导箭头。
- **盆口深色**：原版 `SetImageOverride("Pot_top", IMAGE_REANIM_POT_TOP_DARK)` 用一层 `Pot_top_dark` 叠加精灵实现（`GardenFlowerPot.plant_change_pot_top_dark`）—— 动画每帧覆写 `Pot_top` 的贴图与 transform，直接改贴图会被盖回去，叠加层在 `_process` 里同步 transform。规则：**只有"要浇水"是普通色**，刚浇过 / 有肥药留声机需求 / 今天已照顾都是深色。
- **满园判定**（`GlobalGardenState.has_empty_garden_cell`）只统计**阳光房** 32 格，对齐原版 `IsZenGardenFull`；蘑菇园 / 水族馆空着不代表"花园还有位置"。
- **空闲淡出**：鼠标 50 秒不动把工具栏 / 翻页 / 商店 / 菜单滑出屏幕，动一下鼠标滑回（`GardenManager._set_idle_faded`，原版 `STATECHALLENGE_ZEN_FADING` 的 3000 帧）。

## 2. 园艺工具：买断型 vs 消耗型

| 类型 | 工具 | 判定 / 库存 |
| --- | --- | --- |
| **买断型** | 黄金水壶、留声机、园艺手套、蜗牛 | `GlobalGameState.is_garden_tool_bought(...)`，买了永久有 |
| **消耗型** | 肥料、杀虫剂、巧克力、树肥料 | 库存字典，上限 `ConstShop.TOOL_MAX_OWN_NUM`（20）；树肥料例外：最多 10 袋 |

**依赖品**（没买解锁物就整件藏起来）：巧克力要有蜗牛、树肥料要有智慧树 —— 与 `drop_garden_plant` 的 `is_garden_unlocked()` 同一套写法。

### 2.1 显隐刷新（改这里最容易漏）

- `garden_manager._refresh_garden_tool_visible()`：**双向**刷新 —— 可用就 `visible = true`，不可用就按钮与道具一起藏（早期版本只会 `continue` 跳过可用项、从不设真，于是「买了手套回到花园没有按钮」）。
- 刷新点必须在 `_update_back_from_store()`（从商店回来的回归入口）里补一次，只留在 `_ready()` 不够。
- **别动道具本体的 `visible`**：`ItemBase` 用 `visible` 表达「是否被激活」（`activete_it()` 真 / `deactivate_it()` 假 / `_ready()` 假），反向设真会让道具凭空出现在 `(0,0)` 并跟着鼠标跑。

### 2.2 水壶两态（基础款 / 黄金款）

`src/garden/item/garden_item_01_wateringcan.gd`：

- 五张「普通 / 黄金」对照常量表（壶身贴图 / 按钮图标 / 浇水动画名 / 检测矩形尺寸 / 矩形偏移 / 一次最多几株）+ `is_gold()`（查是否买了 `GoldWateringCan`）+ `refresh_visual()`。
- **范围口径对齐原版 `Board::IsPlantInGoldWateringCanRange`**：黄金水壶是**矩形** `160×160`、相对鼠标 `x∈[-70,+90]`（中心偏右 10px）、`y∈[-80,+80]`，**范围里有几株浇几株**（`MAX_PLANT_NUM[gold] = -1` 表示不限）；基础水壶退化成 `1×1` 的点、一次 1 株。动画分别是 `ZenGarden_wateringcan_water` / `ALL_ANIMS`。
- 2026-10-24 之前这里是「圆半径 62 + 最近 4 株」的拟合值，现已换成原版的矩形 + 不限株数。
- **场景文件默认值按基础款写**（贴图 / 半径 / 准星全按没买的状态），升级只在 `refresh_visual()` 里做 —— 这样任何没调刷新的入口（探针、以后新加的场景）默认都是正确的基础款。
- 动画名走常量表，不改动画资源：`animation/` 是工具生成的，两套动画本来就在库里。

## 3. 蜗牛（`src/garden/stinky.gd`）

行为常量全在文件顶部（速度 / 清醒时长 / 爬行范围 / 拾取距离）。几条**反直觉但必须照做**的：

| 结论 | 为什么 |
| --- | --- |
| 撞边界要**强制掉头**（`wanted_direction = -direction`） | 旧写法撞边界时传的还是原朝向，`_start_turn` 收到相同朝向不翻面 ⇒ 「播 0.58s 转身动画 → 爬一帧被夹回 → 再播」无限循环 |
| 清醒 / 加速计时**挪到转身判断之前** | `if is_sleep or _is_turning: return` 会把倒计时和翻身绑死，每转一次身冻结一次清醒时间 |
| 追钱加**朝向死区** `DIRECTION_DEAD_ZONE` | `to_coin.x >= 0.0` 在钱的正下方会在 0 附近抖动，导致左右反复转身 |
| 单步位移 `minf(speed * delta, to_coin.length())` | 免得在钱底下左右来回蹭 |
| `sleep()` 里清 `is_turn` | 状态机里转身只连回爬行、不连睡眠，睡着时挂着转身动画会卡住 |
| 朝向映射 `body.scale.x = float(-direction)` | **素材默认朝左**（`stinky.tscn` 里头 x≈3.6、尾 x≈57.9），不翻面就是「往右走朝左」 |
| 纵向漫游**常驻在分支外**，追钱只改横向 | 写在「没钱闲逛」的 `else` 里时，花园里几乎总有钱 ⇒ 纵向被拉到条带顶边钉死，一路横线爬 |
| `_idle_turn_cd` 在 `_ready()` 里给随机初值 | 初值 0 会让蜗牛一醒就在原地翻个身（也会掩盖边界掉头的 bug） |
| 动画倍速跟位移倍速同源（抽 `get_move_speed_scale()`） | 原来只接了巧克力倍速，追钱时位移翻倍而爬行动画不变 ⇒ 脚下打滑 |

**已被推翻的一条**：曾加过 `REACH_UP_DISTANCE`（只收地面往上 100px 内的钱，防"隔空取物"），代价是上面两排的钱蜗牛理都不理。
现在改成「爬行范围覆盖整个花园 + 钳进范围后仍离得远才算够不着」，判据统一成一个，**不再需要高度魔数**。
教训：限制"够不着"之前，先想能不能让它够得着。

### 3.1 原版口径（2026-10-24 对齐 `ZenGarden.cpp` 的 `AddStinky` / `StinkyPickGoal` / `StinkyUpdate`）

| 项 | 原版 | 本仓库 |
| --- | --- | --- |
| 一次清醒多久 | 180 秒（`ShouldStinkyBeAwake`: now - 购买时间 < 180） | `WAKE_TIME = 180`（倒计时表达同一件事） |
| 巧克力 | 3600 秒（`IsStinkyHighOnChocolate`），动画倍速 6→12 | `CHOCOLATE_TIME = 3600`，`get_move_speed_scale()` ×2 |
| 位置持久化 | `mStinkyPosX / mStinkyPosY` 存盘，下次进来接着爬 | `garden_data["stinky_pos"]`（`GardenManager.STINKY_POS_SAVE_KEY`）：进花园恢复、`save_curr_page_data()` 写回 |
| 选目标权重 | 金 -40 / 钻 -80；离上一目标 < 5px 再 -20；快消失的币按 `mDisappearCounter` 再 -0~-40 | 四条都实现了，后两条见 `Stinky._find_nearest_coin` + `Coin.get_exist_seconds` |
| 没钱时漫游 | 权重网格：有植物的格子 `2000 - abs(Δy)`、空格子 1，目标 y = 格子像素 y + 80 | `Stinky._pick_wander_target_y`（`plant_cells` 由 `GardenManager._refresh_stinky_visible` 注入当前页） |

| 爬行速度 | `GetTrackVelocity("_ground") * 15`（`Stinky.reanim` 轨道推出来约 32.2 px/s） | `CRAWL_SPEED = 32.2`（推导过程写在常量注释里） |

## 4. 掉钱落点

- `DIM_Coin` 曾配 `drop_to_ground_y = 505` + `drop_x_clamp`，把所有钱强制送到屏幕最下面那条地面（当初是为了让地面上的蜗牛够得着）。**已删除**（`dim_coin.gd` 的 `drop_to_ground_y` / `drop_x_range` / `drop_x_clamp` 与 `_calc_target_position()`）。
- 现在钱按调用方给的相对偏移**就地落下**（默认 ±50 横移、往下 80~90）⇒ 花园里的钱落在**产出它的植物旁边**（花盆那一行）。战斗场景走同一份代码，别顺手改默认偏移。
- 蜗牛 `move_range` 扩到 `Rect2(30, 130, 745, 460)`（罩住三种背景的全部植物格子；温室格子 y 110~492、蘑菇园 232~579、水族馆 119~549，钱的落点比格子中心再低约 25）。
- `CHASE_SPEED_SCALE` 追钱倍率 **3**（不是 2）：26×2=52 px/s 爬最远 440px 要 8.5 秒，而钱只存在 10 秒，几乎必掉。
- 出生点只在**第一次**（存档里没有 `stinky_pos`）用固定点：水平正中、竖直中心往下 150px（800×600 下即 (400, 450)）再钳进爬行范围 —— 范围扩到整个花园后随机出生会把蜗牛扔到架子上悬着。之后按存档位置恢复（原版 `mStinkyPosX / mStinkyPosY`）。

改蜗牛捡不到钱时按这个顺序查：`move_range`（爬得到哪）→ `PICK_COIN_DISTANCE`（多近算捡到，现为 12）→ `CHASE_SPEED_SCALE`（追不追得上）→ `Coin.coin_exist_time`（钱还在不在，10 秒）。

## 5. 战斗侧：僵尸掉巧克力

- 链路：`DropItemComponent.drop_chocolate()`（三重门槛：组件启用 + 已买蜗牛 + 库存未满 + 概率）→ `EventBus "create_chocolate"` → `DropItemManager` **转接**并 `get_clamp_drop_position()` → `DIM_Chocolate` 实例化（`src/items/drop/chocolate.tscn`）。
- 转接放在管理器是因为只有它有 `get_clamp_drop_position()`（画布有偏移，直接拿视口尺寸夹会掉到屏幕外）。
- 概率 **0.48%**（原版 `Board::DropLoot` 的万分比表：`aChocolateChance = aPottedPlantChance + 36`，基础档 (12+36)/10000；冒险重打 +72 / 无尽 +9 的档位本仓库未区分）。花园植物同一张表取 12/10000 = **0.12%**。
- 掉落条件对齐原版 `CanDropPottedPlantLoot` / `CanDropChocolate`：花园植物要**已通关冒险**（`Goods.is_adventure_finished()`）+ 主花园没满；巧克力持有到 **10 块**就不再掉（`CHOCOLATE_DROP_MAX_OWN_NUM`）。**商店侧持有上限仍是 20**（原版 "max of twenty"），这两个数不是一回事。
- 关卡结算另按 **15%** 掉一盆花园植物（原版 `Challenge.cpp` 的 `aHit < 15`，见 `DropItemManager.try_drop_garden_plant_award`）；本关解锁道具礼包 `is_garden_plant = false` 不变 —— 那是"解锁物"，不是盆栽。
- 新掉落物的通用套路：`src/items/xxx.gd` + `src/items/drop/xxx.tscn`（照 `coin.gd` 抄 `launch()` 与淡出）→ 加 `dim_xxx.gd`（只管实例化）→ `DropItemManager` 转接事件 → `SceneRegistry` 登记场景 → `main_game_base.tscn` 补 `DIM_*` 与 `AllDrop*` 两个节点。

## 6. 智慧树（第四页）

- **2026-10-24 起按原版 `Challenge::TreeOfWisdom*`（`../PvZ-Portable-main`）逐条对齐**，

  每次翻页都会重建页面节点，所以状态从「等待嘟囔」重新开始（与原版 `TreeOfWisdomInit` 一致）。
- **视觉走原版 51 档动画，且带帧间运动**（2026-10-24 修订）：`animation/garden/tree_of_wisdom/treeofWisdom_grow1..51.tres`
  由 [tools/gen_tree_wisdom_anims.py](../../tools/gen_tree_wisdom_anims.py) 直接从 `pak/reanim/treeofWisdom.reanim`（XML）逐帧生成；
  档位进场按 `clamp(height, 1, 50)`（原版 `TreeOfWisdomInit`）、长高按 `clamp(height, 1, 51)`（原版 `TreeOfWisdomGrow`）。
  **长高时会真的播这段动画**：按原版 `PlayReanim(..., 8.0f)` 的 8 帧/秒（素材本身 12fps ⇒ `speed_scale = 8 × step ≈ 0.67`），
  一档 5~10 帧播 0.5~0.8 秒 —— 玩家看到的"拉伸"就是它（先拉长再收回定妆姿态）；进场则 `seek(length)` + `pause()` 直接定在最后一帧。
  `TreeOfWisdom._build_tree_anim_layer()` 从动画轨道里**反推节点集合与绘制顺序**（并集按大档位先扫），动态建 Sprite2D + AnimationPlayer。
  兜底：产物缺失/读取失败时退回 `ConstTreeOfWisdom.TREE_STAGES` 的 10 档静态图（`Trunk` + `RootOverlay`）。
- 坐标口径：reanim 的 `x/y` 是**贴图左上角**（原版 `Reanimation::DrawTrack` 里先 `+cel/2` 抵掉 Sexy 的中心绘制），
  所以 Sprite2D 必须 `centered = false`；`kx/ky` 是角度（度）⇒ `rotation = deg2rad(kx)`、`skew = deg2rad(ky - kx)`。
- `Trunk` 精灵即使不显示也会设贴图（兜底与 10 档静态图要用）；**点击判定用原版固定矩形**。
- **肥料落点 = 原版 `TreeOfWisdomFertilize` 的 (340,300)**，但袋子节点要先减掉 `tree_food.tscn` 里 `Body` 的 `(-40,-46)` ——
  那个偏移是**手持**时让袋子居中在光标上用的，不减掉整袋就偏左上 40×46 像素（"肥料动画有偏移"就是这么来的）。
- **喂食互斥**：`TreeOfWisdom.is_growing()` 为真（刚长高的弹跳里）时不给再喂（原版 `TreeOfWisdomCanFeed`），
  扣库存发生在通过这道判定之后。
- 音效：袋子落下播 `fertilizer`、树长高播 `plantgrow`（原版 `FOLEY_FERTILIZER` / `FOLEY_PLANTGROW`）。
- 喂完动画之前翻页 / 进商店 / 离开花园：原版 `TreeOfWisdomLeave` 会把这一袋照样算上，
  本仓库在 `TreeFood.use_it` 里发现树已失效时直接写存档，不会白扣一袋。

### 6.1 51 档视觉的转换（2026-10-24 已完成，下面是复现步骤）

- **工具**：新版 R2Ga 是 C++ 重写版，可执行文件在**仓库外** `..\PVZ_reanim2godot_animation_cpp.exe`（注意是 **exe 文件**不是目录），
  用法 `PVZ_reanim2godot_animation_cpp.exe <reanim> <anim_res://路径> <图片res://路径> -om anim_tres`，其余参数 `--help`。
  **旧版 `PVZ_reanim2godot_animation_x86_x64.exe`（v3.1_dev）转这个 reanim 会直接 0xC0000005 崩溃**（无任何输出），别用。
- **坑 1：一次最多约 49 段动画**。直接转 52 段（`anim_start` + 51 段 grow）新版也崩：实测 48 段 grow 正常、50 段崩。
  做法：把源拆成两批（`grow1..26` 带 `anim_start` / `grow27..51`），各转一次，再把产物文件名统一回 `treeofWisdom_growN.tres`。
- **坑 2：产物写在输入文件同目录**（不是命令行的 `anim_res://` 目录）。所以把裁剪后的 `.reanim` 放进 `animation/garden/tree_of_wisdom/` 再转，
  转完删掉中间 `.reanim`。
- **坑 3：源里 `bg` 轨道引用的 `IMAGE_REANIM_TREE_BG` 在 `pak/reanim` 里没有对应 PNG**，带上它也会崩；本页不需要天空图（背景页自带），转之前把 `bg` 轨道删掉。
- **坑 4：重名轨道**。`leaf1..4` / `bunch1..3` 在源里重复出现（同名不同实例），转之前给重名追加 `_dupN` 后缀，否则多个图层会被并成一条轨道。
- **坑 5：产物里的贴图路径是 PascalCase**（`Tree01.png` / `Tree_grass.png`），pak 里实际是小写且部分带尾下划线（`tree6_.png` / `tree_grass_.png`）。
  转完必须把 `ext_resource` 的 path 改成磁盘上的真实文件名，否则运行期贴图全丢。
  带尾下划线的那些更要注意：`tree6_` / `tree_grass_` 是**黑白蒙版**，正确目标是 `assets_custom/reanim/tree6.png`
  一类烘焙产物（[M-04](./规范细则存档.md#m-04-alpha-蒙版必须离线烘焙)），直引蒙版就是整块黑白剪影。
- **不要再做"单帧定妆"压缩**（2026-10-24 修订）：压成单帧会把施肥时的**拉伸动画**一起压掉（R2Ga 产物每档 ~280KB / 共 14MB）。
  现在的做法是 `tools/gen_tree_wisdom_anims.py` 直接读 reanim 的 XML：按 `anim_growN` 标记轨道切区间、展开继承语义（`<t/>` 不改、
  `<f>-1</f>` 隐藏、省略 `<f>` 默认可见）、**只在"值真的变了"的帧写关键帧**（线性插值下与逐帧写等价）——
  结果同样是 3.4MB，但运动保留。用法：`python tools/gen_tree_wisdom_anims.py`（体检）/ `--write`（覆盖 51 个 `.tres`）/ `--check-tex`（贴图映射交叉核对）。
  想让长高"看得见拉伸"，**必须**让它按 8 帧/秒播而不是 `seek(length)` —— 这是 2026-10-24 用户反馈里补的第二处。
- **两个只会体现在画面上、编译/探针都不报的坑**（2026-10-24 第三轮，用户反馈"新贴图从左上角平移过来"）：
  1. **隐藏期的坐标不能照抄**。半路出场的部件在 reanim 里"出场帧之前"根本没有坐标，展开继承语义得到的是 `(0,0)`；
     照抄成关键帧，Godot 就会从 `(0,0)` 线性插值到出场坐标 —— 看起来就是新贴图从左上角滑进来。
     正确做法：`visible == false` 的那段一律用**出场那一帧的姿态**顶住，并在出场帧再钉一个关键帧（否则运动仍会提前开始）。
  2. **`visible` 轨道在 Godot 里也走插值**。`false@t0 → true@t1` 会在**中点**就翻成 `true`（不是 t1），
     比坐标到位早半段，同样表现为"滑入"。做法跟 R2Ga 一致：在切换前一帧再放一次旧值，把跳变压进 1 帧内
     （不要指望 `interp = 0`，nearest 也是按中点取近）。
- 复现时**别手改 reanim**：裁剪/命名是 R2Ga 那条路的预处理，XML 直出这条路不需要；仓库里最终只留 51 个 `.tres` + `ConstTreeOfWisdom` 的兜底表。
- **彩蛋（智慧树输入码 mustache / future / daisies / dance / pinata / trickedout）明确不做**：每个码对应的是战斗侧全局效果层（胡子贴图覆写 / 草坪长雏菊 / 僵尸跳舞 / 掉糖 / 未来画风 / 小推车换皮），本仓库没有这些资源；这是**判定不做**，不是待办，别再挂回 TODO 清单。

## 7. 800×600 适配（贴图与坐标）

### 7.1 背景贴图与 48 个格子

`assets/image/garden/` 里曾有 1066×600 的 `*_New.png` 与原版 800×600 的 `*.jpg` 两套。实测关系是**1:1 居中放置 + 左右各补 133px**（`1066 - 800 = 266`），不是缩放：

| 背景 | 横向裁剪偏移 `dx` | ZNCC |
| --- | --- | --- |
| 温室 | 133 | 0.987 |
| 蘑菇园 | 133 | 0.996 |
| 水族馆 | 130 | 0.69（峰值较平缓） |

改法：`x_800 = x_1066 - dx`（**平移，不是缩放**），`y` 不变；格子保持 75×75 不跟着缩（缩了点击区会变成 56×75 的扁矩形）。

- 工具：`powershell -ExecutionPolicy Bypass -File tools\image_crop_offset.ps1 -Source <1066图> -Target <800图>`（高通滤波 + ZNCC）。
- **别用平均灰度差（MAD）判断两套图是不是缩放关系**：跨来源素材整体亮度差异很大，MAD 会被低频差异带偏（本例"拉伸假设" MAD 37.94 完胜"平移假设" 134.80，但结论是错的，按缩放改完植物全部错位）。判据是**峰值 ZNCC > 0.9 且两侧快速衰减**。
- 改完务必生成「坐标叠加预览图」（在目标贴图上按新坐标画格子 rect）目视确认，比开游戏更快更准；贴图 `ext_resource` 的 uid 要和目标 `.import` 一致。
- 已知残留：蘑菇园 8 个格子在原坐标下就与画面土坑有 ±50px 的手摆误差；水族馆 ZNCC 0.69，目视觉得偏可单独微调 `dx`。

## 8. 存档坑：JSON 读回是 float

`is_garden_tool_bought()` 用 `Array.has(int(tool_type))`，而 `JSON.parse_string` 把数字一律读成 float（存档里是 `4.0`），`Array.has()` 认不出来 ⇒ **买断型工具读档后全部丢失**（商店能再买一次、花园工具栏空了）。

- 修法两边都做：读取侧逐个 `int()` 比（老存档救得回来）+ `SaveService` 读档后 `GlobalGameState.normalize_garden_data_numbers()` 归一化（新存档不再越存越浮点）。
- 通用规则：凡是存档里的 **int 数组 / int 字典值**，读取侧一律 `int()` 容错，别信 `Array.has()`。（`curr_plant` / `curr_zombie` 早就有这个转换，唯独 `bought_garden_tools` 漏了。）
- 探针里读盘断言也要用同样的 `int()` 容错比较，别把「读盘方式」的坑当成产品 bug。

### 8.1 同一个坑的植物版：植物类型也要 read-time 迁移（2026-10-14 角色 id 去编号那一轮漏了）

角色 id 从 int 编号改成 `StringName`（`PlantIds`）之后，**老存档花园里每株植物的 `curr_plant_type` 还是数字编号**，
JSON 读回来还是 float ⇒ 进花园 `_add_new_plant()` 第一行就崩：

```
Trying to assign value of type 'float' to a variable of type 'StringName'
plant_cell_garden.gd:81 @ _add_new_plant() ← garden_bg_page ← garden_manager.init_new_page()
```

同一份植物数据里还有 `curr_growth_stage` / `curr_need_item` / `curr_water_time` / `max_water_time` /
`curr_plant_condition` 这些 int 字段，同样是 float ⇒ 类型错紧跟着来了第二个。

- **别只改读取那一处**，`garden_data` 里所有的植物都要一起洗干净：`SaveService.load_global_game_data()`
  读档后调 `GlobalGameState.normalize_garden_plant_cell_data()`（本体在 `global_garden_state.gd`），
  遍历「背景 → 页 → 格子」+ 顶层 `WheelBarrow` 那株，把 `curr_plant_type` 走 `PlantIds.from_legacy()`
  迁成 id、把 int 字段 `int()` 回来。
- 读取侧（`PlantCellGarden._add_new_plant()` / `GardenComponent.init_garden_component()`）仍保留 `from_legacy()`
  与 `int()` 兜底：不是每次重建植物都绕得回读档那条路（换背景页、独轮车、手套都在传这份字典）。
- **独轮车那株不在「背景 → 页 → 格子」三层结构里**（直接挂在 `garden_data["WheelBarrow"]`），
  做遍历式迁移时很容易只覆盖到格子里的植物 —— 键名现在收在 `GardenManager.WHEEL_BARROW_SAVE_KEY`。
- 迁移到一半的植物（编号不在 `LEGACY_INT_TO_ID` 里 / 模组植物没装）会让 `get_plant_info()` 返回 null，
  往下 `.place_plant_in_cell` 就炸 ⇒ 读不出来时**留一个空格子 + 打一条 Log.error**，不要硬往下走。

### 8.2 2026-10-24 新增的花园存档键（需求模型换成时间戳 + 物种队列）

| 键 | 含义 | 老存档兼容 |
| --- | --- | --- |
| `curr_plant_species` | 入手时定下的物种（原版 `mSeedType`） | 缺失 → 苗→小时兜底随机 |
| `times_fed` / `feedings_per_grow` | 已浇水次数 / 长一阶要浇几次 | 缺失 → 读旧键 `curr_water_time` / `max_water_time` |
