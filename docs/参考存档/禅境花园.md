## 1. 结构：一页一个背景，翻页不重建

| 元素 | 落点 | 说明 |
| --- | --- | --- |
| 背景页枚举 | `E_GardenBgType`（温室 / 蘑菇园 / 水族馆 / `TreeBg` 智慧树） | 智慧树是**第四页**，不是摆在花园角落 |
| 页面场景 | `src/garden/bg_0N_*.tscn`（`BgPageScenes` 里登记） | 翻页是切 `visible`，节点不重建 |
| 每页格子数 | `PLANT_CELL_NUM_PER_PAGE` | **智慧树页写 0**：不种植物，「花园是否已满」自动不受它影响 |
| 工具栏 | `src/garden/garden.tscn` 的 `PanelUI`（8~9 个 75px 槽） | 加第 9 个按钮时把 8 个槽的 `custom_minimum_size` 一起改小（见 §7.2） |
| 蜗牛 | `src/garden/stinky.gd`（行为常量全在文件顶部） | 节点在 `garden.tscn` 里，翻页不重建 |

蜗牛节点在 `garden.tscn` 里、翻页不重建 ⇒ 任何「按背景页各配一套参数」的想法都会落空，参数必须是全局唯一的（蜗牛爬行范围就是这么定的，见 §4）。

## 2. 园艺工具：买断型 vs 消耗型

| 类型 | 工具 | 判定 / 库存 |
| --- | --- | --- |
| **买断型** | 黄金水壶、留声机、园艺手套、蜗牛 | `GlobalGameState.is_garden_tool_bought(...)`，买了永久有 |
| **消耗型** | 肥料、杀虫剂、巧克力、树肥料 | 库存字典，上限 `ConstShop.TOOL_MAX_OWN_NUM`（20）；树肥料例外：最多 10 袋 |

**依赖品**（没买解锁物就整件藏起来）：巧克力要有蜗牛、树肥料要有智慧树 —— 与 `drop_garden_plant` 的 `is_garden_unlocked()` 同一套写法。

### 2.1 显隐刷新（改这里最容易漏）

- `garden_manager._refresh_garden_tool_visible()`：**双向**刷新 —— 可用就 `visible = true`，不可用就按钮与道具一起藏（早期版本只会 `continue` 跳过可用项、从不设真，于是「买了手套回到花园没有按钮」）。
- 刷新点必须在 `_update_back_from_store()`（从商店回来的回归入口）里补一次，只留在 `_ready()` 不够。
- **别动道具本体的 `visible`**：`ItemBase` 用 `visible` 表达「是否被激活」（`activete_it()` 真 / `deactivate_it()` 假 / `_ready()` 假），反向设真会让道具凭空出现在 `(0,0)` 并跟着鼠标跑。

### 2.2 水壶两态（基础款 / 黄金款）

`src/garden/item/garden_item_01_wateringcan.gd`：

- 四张「普通 / 黄金」对照常量表（壶身贴图 / 按钮图标 / 浇水动画名 / 检测半径 / 一次最多几株）+ `is_gold()`（查是否买了 `GoldWateringCan`）+ `refresh_visual()`。
- 基础款：点检测（半径 0.1）、一次 1 株、动画 `ZenGarden_wateringcan_water`；黄金款：半径 62、按离光标最近取 4 株、动画 `ALL_ANIMS`。
- **场景文件默认值按基础款写**（贴图 / 半径 / 准星全按没买的状态），升级只在 `refresh_visual()` 里做 —— 这样任何没调刷新的入口（探针、以后新加的场景）默认都是正确的基础款。
- 动画名走常量表，不改动画资源：`animation/` 是工具生成的，两套动画本来就在库里。

## 3. 蜗牛（`src/garden/stinky.gd`）

行为常量全在文件顶部（速度 / 清醒时长 / 爬行范围 / 拾取距离）。几条**反直觉但必须照做**的：

| 结论 | 为什么 |
| --- | --- |
| 撞边界要**强制掉头**（`wanted_direction = -direction`） | 旧写法撞边界时传的还是原朝向，`_start_turn` 收到相同朝向不翻面 ⇒ 「播 0.58s 转身动画 → 爬一帧被夹回 → 再播」无限循环 |
| 清醒 / 加速计时**挪到转身判断之前** | `if is_sleep or _is_turning: return` 会把倒计时和翻身绑死，每转一次身冻结一次清醒时间 |
| 追钱加**朝向死区** `DIRECTION_DEAD_ZONE` | `to_coin.x >= 0.0` 在钱的正下方会在 0 附近抖动，导致左右反复转身 |
| 单步位移 `minf(speed * delta, to_coin.length())` | 免得在钱底下左右来回蹭 |
| `sleep()` 里清 `is_turn` | 状态机里转身只连回爬行、不连睡眠，睡着时挂着转身动画会卡住 |
| 朝向映射 `body.scale.x = float(-direction)` | **素材默认朝左**（`stinky.tscn` 里头 x≈3.6、尾 x≈57.9），不翻面就是「往右走朝左」 |
| 纵向漫游**常驻在分支外**，追钱只改横向 | 写在「没钱闲逛」的 `else` 里时，花园里几乎总有钱 ⇒ 纵向被拉到条带顶边钉死，一路横线爬 |
| `_idle_turn_cd` 在 `_ready()` 里给随机初值 | 初值 0 会让蜗牛一醒就在原地翻个身（也会掩盖边界掉头的 bug） |
| 动画倍速跟位移倍速同源（抽 `get_move_speed_scale()`） | 原来只接了巧克力倍速，追钱时位移翻倍而爬行动画不变 ⇒ 脚下打滑 |

**已被推翻的一条**：曾加过 `REACH_UP_DISTANCE`（只收地面往上 100px 内的钱，防"隔空取物"），代价是上面两排的钱蜗牛理都不理。
现在改成「爬行范围覆盖整个花园 + 钳进范围后仍离得远才算够不着」，判据统一成一个，**不再需要高度魔数**。
教训：限制"够不着"之前，先想能不能让它够得着。

## 4. 掉钱落点

- `DIM_Coin` 曾配 `drop_to_ground_y = 505` + `drop_x_clamp`，把所有钱强制送到屏幕最下面那条地面（当初是为了让地面上的蜗牛够得着）。**已删除**（`dim_coin.gd` 的 `drop_to_ground_y` / `drop_x_range` / `drop_x_clamp` 与 `_calc_target_position()`）。
- 现在钱按调用方给的相对偏移**就地落下**（默认 ±50 横移、往下 80~90）⇒ 花园里的钱落在**产出它的植物旁边**（花盆那一行）。战斗场景走同一份代码，别顺手改默认偏移。
- 蜗牛 `move_range` 扩到 `Rect2(30, 130, 745, 460)`（罩住三种背景的全部植物格子；温室格子 y 110~492、蘑菇园 232~579、水族馆 119~549，钱的落点比格子中心再低约 25）。
- `CHASE_SPEED_SCALE` 追钱倍率 **3**（不是 2）：26×2=52 px/s 爬最远 440px 要 8.5 秒，而钱只存在 10 秒，几乎必掉。
- 出生点**固定**在水平正中、竖直中心往下 150px（800×600 下即 (400, 450)）再钳进爬行范围 —— 范围扩到整个花园后随机出生会把蜗牛扔到架子上悬着。

改蜗牛捡不到钱时按这个顺序查：`move_range`（爬得到哪）→ `PICK_COIN_DISTANCE`（多近算捡到，现为 12）→ `CHASE_SPEED_SCALE`（追不追得上）→ `Coin.coin_exist_time`（钱还在不在，10 秒）。

## 5. 战斗侧：僵尸掉巧克力

- 链路：`DropItemComponent.drop_chocolate()`（三重门槛：组件启用 + 已买蜗牛 + 库存未满 + 概率）→ `EventBus "create_chocolate"` → `DropItemManager` **转接**并 `get_clamp_drop_position()` → `DIM_Chocolate` 实例化（`src/items/drop/chocolate.tscn`）。
- 转接放在管理器是因为只有它有 `get_clamp_drop_position()`（画布有偏移，直接拿视口尺寸夹会掉到屏幕外）。
- 概率 **2%**（原版只说"随机掉"没给数，代码里标了 `待核实`；介于花园植物 0.4% 与金币 30% 之间）。
- 库存上限沿用 20（原版是攒够 10 块不再出现，与商店判定分叉，差异写在注释里）。
- 新掉落物的通用套路：`src/items/xxx.gd` + `src/items/drop/xxx.tscn`（照 `coin.gd` 抄 `launch()` 与淡出）→ 加 `dim_xxx.gd`（只管实例化）→ `DropItemManager` 转接事件 → `SceneRegistry` 登记场景 → `main_game_base.tscn` 补 `DIM_*` 与 `AllDrop*` 两个节点。

## 6. 智慧树（第四页）

- 商店第四页第二行第一格，$2500 一袋，最多囤 10 袋；**买树白送 5 袋**；一袋长一英尺；100 / 500 / 1000 英尺是里程碑。
- 高度与台词存 `garden_data["tree_of_wisdom_height"]`；台词取 `data/strings/lawn_strings.txt` 的 `TREE_OF_WISDOM_*`，常量表在 `src/core/consts/const_tree_of_wisdom.gd`。

## 7. 800×600 适配（贴图与坐标）

### 7.1 背景贴图与 48 个格子

`assets/image/garden/` 里曾有 1066×600 的 `*_New.png` 与原版 800×600 的 `*.jpg` 两套。实测关系是**1:1 居中放置 + 左右各补 133px**（`1066 - 800 = 266`），不是缩放：

| 背景 | 横向裁剪偏移 `dx` | ZNCC |
| --- | --- | --- |
| 温室 | 133 | 0.987 |
| 蘑菇园 | 133 | 0.996 |
| 水族馆 | 130 | 0.69（峰值较平缓） |

改法：`x_800 = x_1066 - dx`（**平移，不是缩放**），`y` 不变；格子保持 75×75 不跟着缩（缩了点击区会变成 56×75 的扁矩形）。

- 工具：`powershell -ExecutionPolicy Bypass -File tools\image_crop_offset.ps1 -Source <1066图> -Target <800图>`（高通滤波 + ZNCC）。
- **别用平均灰度差（MAD）判断两套图是不是缩放关系**：跨来源素材整体亮度差异很大，MAD 会被低频差异带偏（本例"拉伸假设" MAD 37.94 完胜"平移假设" 134.80，但结论是错的，按缩放改完植物全部错位）。判据是**峰值 ZNCC > 0.9 且两侧快速衰减**。
- 改完务必生成「坐标叠加预览图」（在目标贴图上按新坐标画格子 rect）目视确认，比开游戏更快更准；贴图 `ext_resource` 的 uid 要和目标 `.import` 一致。
- 已知残留：蘑菇园 8 个格子在原坐标下就与画面土坑有 ±50px 的手摆误差；水族馆 ZNCC 0.69，目视觉得偏可单独微调 `dx`。

### 7.2 顶部 UI 重排（组合件要按总宽算）

| 元素 | 1066 时代 | 800 时代 | 说明 |
| --- | --- | --- | --- |
| `PanelUI` 工具条 | `184..778` | `25..619` | 右边缘让出翻页组 |
| `Next` 翻页按钮 | `798..858` | `639..699` | 右锚按**组合总宽** 161 算（按钮 60 + 间距 10 + 页码 91） |
| 页码 `Label` | `868..959` | `709..800` | 是 `Next` 的**子节点**，改父节点偏移即可 |
| `StoreEnterKey` 商店 | `982..1061` | `716..795`，y `80..122` | 下移 21px 避开页码 |
| `ReturnStartMenu` 主菜单 | `976..1066` | `0..90`，y `560..600` | 右上角被占满，移到左下角 |

`Next` 是「箭头按钮 + 右侧两行页码」的组合，`PanelUI` 是「容器 + 8 个 75×75 子按钮」的组合（容器宽 594 是子按钮撑出来的）—— 改这类组合的锚点必须按**组合总宽**算，且改完要把所有子节点的屏幕矩形都画出来看一眼。

## 8. 存档坑：JSON 读回是 float

`is_garden_tool_bought()` 用 `Array.has(int(tool_type))`，而 `JSON.parse_string` 把数字一律读成 float（存档里是 `4.0`），`Array.has()` 认不出来 ⇒ **买断型工具读档后全部丢失**（商店能再买一次、花园工具栏空了）。

- 修法两边都做：读取侧逐个 `int()` 比（老存档救得回来）+ `SaveService` 读档后 `GlobalGameState.normalize_garden_data_numbers()` 归一化（新存档不再越存越浮点）。
- 通用规则：凡是存档里的 **int 数组 / int 字典值**，读取侧一律 `int()` 容错，别信 `Array.has()`。（`curr_plant` / `curr_zombie` 早就有这个转换，唯独 `bought_garden_tools` 漏了。）
- 探针里读盘断言也要用同样的 `int()` 容错比较，别把「读盘方式」的坑当成产品 bug。
