# 动画封装（驱动源 + 本地控制 / 包分发控制）

> **[面向 AI Agent]** ｜ **触发条件**：要给角色加 / 改动画控制；要把某株植物从「改 `is_xxx` 字段让动画树自己推导」改成「代码点名切状态」；要接联机动画同步；发现「客户端动画不动 / 发了等于没发 / 动画被本地逻辑抢回去」
>   
> **读完你能**：① 知道所有角色（植物 / 僵尸 / 僵王 / 花园僵尸）的动画只有 `AnimComponentBase` 一个入口；② 知道单人走 `request_state()` / `request_one_shot()`，客户端走 `take_over()` + `apply_anim_*()`；③ 知道迁一株植物到「代码控制」要改哪两处（脚本 + `.tscn` 的 transition）；④ 知道新植物的初始状态怎么配（`norm_anim_state` / `show_anim_state`）
>   
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：绕过组件直接抓 `AnimationTree` / `AnimationPlayer` → 宿主结构一改就静默失同步；客户端 `play()` 完下一帧被状态机换回去 → "发了等于没发"
>

## 1. 一句话

**动画只有一层封装：`AnimComponentBase`（挂在角色的 `%AnimComponent` 上）。**
 
它内部有「驱动源」开关：

| 场景      | 驱动源      | 谁决定播哪条                     | API                                                                      |
| ------- | -------- | -------------------------- | ------------------------------------------------------------------------ |
| 单人 / 主机 | `LOCAL`  | 角色自己的代码（植物字段 / 攻击组件 / 状态机） | `request_state()`、`request_one_shot()`                                   |
| 联机客户端   | `REMOTE` | 主机下发的包（动画下标 + 相位）          | `take_over()`、`apply_anim_index()`、`apply_anim_phase()`、`apply_packet()` |

植物、僵尸、僵王、花园僵尸都挂同一个 `character_base.tscn`，所以**这一层对全体角色同时生效**，不需要各写一套。

```
Character000Base.anim_component : AnimComponentBase
        │
        ├─ LOCAL  ── request_state() / request_one_shot() ──▶ 角色自己的逻辑
        └─ REMOTE ── apply_anim_index() / apply_anim_phase() ─▶ 包分发方（联机模组）
```

## 2. API 一览

### 2.1 本地驱动（单人）

| 方法                                                               | 用途                           |
| ---------------------------------------------------------------- | ---------------------------- |
| `request_state(state)`                                           | 显式点名切状态机的状态（植物 / 僵尸脚本用）      |
| `request_one_shot(param)`                                        | 播一次 OneShot（攻击组件、磁力菇这类一次性动作） |
| `cancel_one_shot(param)`                                         | 撤掉正在播的 OneShot（淡出）           |
| `update_anim_speed_scale(scale)` / `owner_update_speed(product)` | 速度                           |
| `find_state_by_suffix(suffix)`                                   | 按后缀找状态名（`*_sleep` / `*_idle` / `*_idle_aquarium`） |

植物侧有转发入口（`Plant000Base`）：`request_anim_state()` / `request_anim_one_shot()`。

### 2.2 远端驱动（客户端）

| 方法                                            | 用途                                                       |
| --------------------------------------------- | -------------------------------------------------------- |
| `take_over()`                                 | 冻结本地驱动源（`AnimComponentNorm` 关树），幂等                       |
| `release()`                                   | 交还本地驱动（重连 / 退出房间后恢复角色自己的动画逻辑）                            |
| `apply_anim_index(index)`                     | 按动画下标切播（下标 = `AnimationPlayer.get_animation_list()` 的序号） |
| `apply_anim_phase(position)`                  | 把播放头拉到指定秒数（偏差 > `PHASE_RESYNC_EPS` 才拉）                   |
| `apply_packet(index, position, speed_scale)`  | 上面两件事 + 可选速度，一次应用                                        |
| `snapshot()`                                  | 采集：`{name, index, position}`（主机侧一步取齐）                    |
| `anim_index_of(name)` / `anim_name_at(index)` | 名字 ↔ 下标                                                  |
| `get_animation_player()`                      | 播放器访问器（**唯一**允许拿播放器的地方）                                  |

### 2.3 通用只读

`update_current_anim()` → `anim_name_now` / `anim_position_now`。
 
动画树驱动时 `AnimationPlayer.current_animation` **恒为空**，问名字只能问组件。

### 2.4 表现接口（视觉与逻辑分离的落点）

业务代码要表达"看起来怎样"时走这两个入口，不去抓节点：

| 入口 | 用途 |
| --- | --- |
| `signal anim_event(event)` + `on_anim_event(event)` | **动画方法轨的唯一调用点**：动画资源只认这一个方法、带一个事件名，逻辑侧订阅信号；动画里不再出现 `_shoot_bullet` 这类玩法方法名 |
| `apply_visual(op)` | 视觉操作：`VISUAL_TINT`（`color`）/ `VISUAL_Z`（`offset`，**增量**）/ `VISUAL_PART_VISIBLE`（`part` + `visible`）/ `VISUAL_SWAP_TEXTURE`（`part` + `texture`） |

- 颜色走 `Body` 的合成色（与受击闪白 / 冰冻染色相乘），**不改部件 `self_modulate`** —— 动画轨每帧写回。
- 层级记的是**偏移量**，旧的 `z_index += 10` 写法照样能并存。
- 部件按名字在 `Body` 子树里找，找不到只报一次 WARN。
- 回归：`probe_anim_component` 的「表现接口」段（事件转发 + 四种操作各改一次并还原）。

#### 迁移状态（2026-10-23）

| 方法族 | 状态 | 接线位置 |
| --- | --- | --- |
| `_shoot_bullet` / `_shoot_bullet_2`（开火） | ✅ 已迁（20 个 `.tres` / 23 条轨） | `AttackComponentBase._on_anim_event()` → `_shoot_bullet()` / `_shoot_bullet_2()` |
| `attack_once` / `_attack_once`（近战、菇类、磁力菇） | ⬜ 待迁 | 目标节点各异（植物脚本 / 检测组件），要一族一族接 |
| `bomb_once` / `_fire_end` / `plant_*` 这类一次性动作 | ⬜ 待迁 | 同上 |
| 僵王 `notify_skill_event` / `request_trophy` / `hurt_enable` | ⬜ 待迁 | 与状态机时序（`action_delta`）绑在一起，单独一批 |

- 同一角色可能挂多个攻击组件（投石车 `AttackComponent` / `AttackComponent2`）：只让**第一个**接管的组件处理事件（`ANIM_EVENT_OWNER_META`），一次动画不会发两份子弹。
- 再迁一族用现成模板：`tools/migrate_anim_shoot_events.gd`（改 `METHOD_EVENTS` 与目标节点名，跑一遍 headless 即可；二进制 `.res` 不动，未迁的轨照样能工作）。

## 3. 单人：植物代码怎么控制动画

**所有原版植物的「播哪条」都已由脚本点名**：`.tscn` 里不再有靠 `is_xxx` 表达式自动推进的状态转换
（57 个植物场景中，27 个带状态机的已全部处理；其余是纯 OneShot 角色，本来就没有状态机）。

### 3.1 迁一株 / 新增一株要动两处

1. `.tscn` 里把转换改成「能被 `travel()` 走、但不会自动推进」：
   ```
   advance_mode = 1                         # ENABLED
   advance_condition = &"__manual_travel"   # 从不置 true 的条件名 ⇒ 自动推进永不触发
   ```
   并删掉原来的 `advance_expression`。
2. 脚本里在**所有**该切换的地方调 `request_anim_state()`。

> ⚠️ 改 `.tscn` 时按 `(from, to)` 精确匹配，别按命名猜：大嘴花的啃咬状态叫 **`Bite`**，磁力菇是 **`Magnetshroom_*`**（小写 s）。

### 3.2 已迁移清单（原版植物）

| 组   | 植物                                     | 状态切换点                                                                                          |
| --- | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 地刺类 | 地刺、钢地刺                                 | 检测到敌人 ⇄ 回待机                                                                                    |
| 攻击类 | 窝瓜（左/右看）、玉米加农炮（开火/充能）、磁力菇（吸附/冷却结束）     | 脚本自己的信号 / 计时器                                                                                  |
| 啃咬类 | 大嘴花（Bite / chew / swallow / idle）      | `change_is_attack`、计时器、动画轨回调                                                                   |
| 生长类 | 阳光菇（grow）、土豆雷（rise）、小喷菇（scared）        | 成长计时器 / 准备计时器 / 害怕组件                                                                           |
| 姿态类 | 仙人掌（rise / lower）、保护伞（block）           | 攻击状态变化 / 撞击事件                                                                                  |
| 睡眠类 | 毁灭菇、大喷菇、忧郁菇、魅惑菇、冰菇、磁力菇、小喷菇、胆小菇、海蘑菇、阳光菇 | **基类统一**：`signal_is_sleep` / `signal_not_is_sleep` → `*_sleep` / `*_idle`（冰菇展示态走 `_idle_only`） |
| 出场类 | 三叶草、樱桃炸弹、咖啡豆、墓碑吞噬者、模仿者、辣椒、毁灭菇         | `norm_anim_state`（出战即播的一次性动画）                                                                |
| 水族类 | 海蘑菇、缠绕海草                                | 花园态 `*_idle_aquarium`（`is_garden_aquarium`）                                                     |
| 死条件 | 坚果 `is_face`、花盆 `is_water`              | 字段不存在、条件恒假，表达式已一并清掉                                                                          |

### 3.3 启动时的初始状态

`Start → *` 的边同样是手动 travel，初始状态由 `Plant000Base._apply_initial_anim_state()` 选：

| 顺序 | 判据 | 结果 |
|---|---|---|
| 1 | `is_sleeping` | `*_sleep` |
| 2 | `is_show`（展示体） | `show_anim_state` → `*_idle_only` → `*_idle` |
| 3 | 花园态 + `is_garden_aquarium` | `*_idle_aquarium` → `*_idle` |
| 4 | 出战 | `norm_anim_state` → `*_idle` |

两个 `@export`（配在植物 `.tscn` 根节点上）：

| 字段 | 用途 | 已配置 |
|---|---|---|
| `norm_anim_state` | 出战初始状态 / 一次性出场动画 | 三叶草、樱桃炸弹、咖啡豆、毁灭菇、墓碑吞噬者、模仿者、辣椒、土豆雷、魅惑菇、胆小菇、小喷菇、海蘑菇 |
| `show_anim_state` | 展示体的特殊形态 | 阳光菇（成长形态）、土豆雷（已升起） |

- **毁灭菇**额外覆盖 `_after_anim_wake()`：白天被唤醒后直接切 `DoomShroom_explode`（原来靠 `not is_idle` 在醒来后自动触发）。
- 新植物如果不配这两个字段，默认走 `*_idle`；**状态机里没有 `*_idle` 的植物必须配**，否则会停在 `Start`（完全没动画）。
- 回归探针会对 27 株植物的展示体断言「已离开 `Start`」，漏配会立刻暴露。

### 3.4 三种写法（踩过）

| 写法                                            | 自动推进              | `travel()`         |
| --------------------------------------------- | ----------------- | ------------------ |
| 只删 advance 属性（默认 `advance_mode = 0` DISABLED） | 否                 | 部分版本下**不走**（转换被跳过） |
| `advance_mode = 1` + 空 `advance_condition`    | **每帧自动推进**（等于没接管） | 走                  |
| `advance_mode = 1` + 恒假条件（本文写法）               | 否                 | 走                  |

⚠️ `request_state()` 内部对「已经在目标状态」做了短路：重复 travel 会把该状态从头重播，而调用方常常是每帧都会触发的检测信号。
 
⚠️ `travel()` 有 xfade，**调用后要等过渡结束**才读 `get_current_node()`（0.2 秒的过渡，等 3 帧读到的还是旧状态）。
⚠️ 转换是 `switch_mode = 2`（At End）时，`travel()` 要等当前动画播完才生效（钢地刺回待机就是这种）。

## 4. 客户端：包怎么驱动动画

协议维持现状：**动画下标（1 字节）+ 相位（量化进 `z_render` / `p_render`）**，不下发动画名、不下发速度。

```
主机：character.anim_component.snapshot()  →  index / position  → 快照
客户端：component.apply_anim_index(idx) + component.apply_anim_phase(pos)
```

- 下标两端天然对齐：两端实例化的是同一份 `.tscn`，动画列表与插入顺序一致 ⇒ **不需要"名字 → 编号"映射表**。
- `ANIM_NONE = 255` 是占位：拿不到 / 越界时不接管。
- `PHASE_NONE` 是相位占位：主机没在播 ⇒ 客户端**不动**播放头（发 0 会被误当成"拉回第一帧"）。
- 速度差靠相位硬拉抹平：远端驱动下 `owner_update_speed()` 直接返回（树已停，写它无效）。
- 僵王是例外：死亡是编排式流程，`apply_packet` 只保证播对动画，撑不起 `start_death_remain()` ⇒ 仍走 `zb_death` 触发的本地流程。

## 5. 硬约定（写代码前先看）

1. 动画树结构固定：`AnimationNodeBlendTree` → `TimeScale` → `StateMachine`。结构不对 `AnimComponentNorm` 只报**一次** WARN 然后静默退出同步。
2. 组件里取宿主节点走 `Character000Base.host_node_of(owner, ^"X")`，不要写 `$"../X"` —— 宿主多包一层就静默取 null。
3. **不要在组件外递归找 `AnimationPlayer`**：那是组件内部知识，需要就用 `get_animation_player()`。
4. 不要改 `Sprite2D.self_modulate`：动画轨道每帧会写回，改颜色走 `body.modulate`。
5. 植物的 `animation_finished` 没人用（只有僵尸的移动组件订阅）；"射完回 idle"靠 OneShot 的 fade_out 与状态机条件。
6. `request_state()` 的状态名写错会打 WARN，不写就静默不动 —— 迁移时以场景里的状态名为准。
7. 状态机不是 `tree_root`：树根是 `AnimationNodeBlendTree`，状态机是它下面名为 `StateMachine` 的节点（`_state_machine_root()` 负责取）。
