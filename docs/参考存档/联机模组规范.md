三条顶层约定（用户需求原文，本文逐条展开）：

1. **有房间机制** —— 见 §一；
2. **所有关卡都由房主打开 / 退出** —— 见 §二；

## 一、房间机制

### 1.1 房间是什么

- **一个房间 = 一个 ENet 主机进程（peer id 恒为 1）+ 若干客户端**，屋里同一时刻只打一关（合作共守一块草坪）。
- 会话 `NetplaySession` 挂在 `SceneTree.root`（节点名固定 `NetplaySession`），**跨场景存活**：双方得先在主菜单连上，再一起进关卡。挂 `MainGameManager` 下会跟着关卡一起被销毁。
- **房间不是存档的一部分、不跨进程持久化**：进程一退房间就没了；目标地址 `netplay.target` 存在 `ConfigService` 的控制台键值区，那只是"上次连哪儿"的便利值。

### 1.2 房间状态（房主侧是唯一权威）

| 状态 | 谁维护 | 说明 |
|---|---|---|
| `role` / `state` / `local_peer_id` | 本机 | `None/Host/Client` + `Idle→Hosting/Connecting→Connected→Failed` |
| 成员表 | 由 `peer_connected` / `peer_disconnected` 维护 | **不发全量名单快照**，成员变化只发信号（`peer_joined` / `peer_left`） |
| `room_level_id` / `_room_level_key` | 房主写入，下行给全屋 | 屋里正在打的这一关（空 = 房主还在菜单） |
| `room_seed` | 房主每开一关换一颗 | 两端 `GameRng` 同一颗种子，抽奖型随机才对得上 |
| `ready_peers` | 各自主张 → 房主记账 → 转告全屋 | 选卡阶段的准备状态，每局开局清一次 |

### 1.3 生命周期

```
Idle ──开启房间──▶ Hosting ──有人进来──▶ Connected
Idle ──加入房间──▶ Connecting ──▶ Connected / Failed
```

- **房主断线（`server_disconnected`）⇒ 房间解散**，客户端回 `Idle` 并**留在当前画面**（不要替玩家乱跳场景）。
- **不做房主迁移**（v1 定死）：关卡的权威状态只在房主那一局里，换主等于重做整局的事实来源；要做就等阶段四有状态下行之后再说。
- 某个客户端掉线：房主把它从 `ready_peers` 摘掉、继续打，房间不散。

### 1.4 三类消息与方向（写新 RPC 前先归类）

| 类 | 方向 | 谁能发 | 例子 |
|---|---|---|---|
| **上行（请求 / 主张）** | client → host | 任何人 | `receive_command`（操作请求）、`report_ready`、`card_selection` |
| **下行（事实 / 指令）** | host → all | **只有房主** | `enter_level`、`leave_level`、`level_result`、`battle_op`、`sync_battle_seed` |
| **协商** | any ↔ any（经主机转发） | 任何人 | `card_selection`、`_card_selection_refresh_asked` |

规则（写新 RPC 时逐条对）：

1. 凡是**改变局面事实 / 房间方位**的，只能房主下行；客户端发来的一律丢弃并 `Log.warn`。
2. 下行 RPC **一律**校验 `multiplayer.get_remote_sender_id() == SERVER_PEER_ID`。
3. **不要**把"事实"塞进命令表上行 —— 命令是"客户端 → 主机"的上行，进关 / 退关是"主机 → 客户端"的下行，方向相反，混在一起会让重放逻辑多一层"这条要不要在本地跑"的分支。
4. 房间内部**不走 `ConstEventName`**（边界规则 3）：自己的连线用 `NetplaySession` 的信号。

### 1.5 加入 / 掉线 / 后加入

- 上限：`NetplaySession.MAX_PLAYERS`（现 4 = **客户端数**，含房主共 5；合作共守先按 2 人 + 余量设的）。
- **后加入的人**：房主在 `_on_peer_connected()` 里补发**当前关卡键值 + 房间种子**，把他直接拉进同一关 —— 不然新来的人只能自己在菜单里猜是哪一关。
- 没有"加入中"的中间态：连上就算进屋；不在关里就待在自己当前场景。

### 1.6 界面

- 现状：**房间界面就是控制台「联机」一栏**（目标 `地址:端口` 输入框 + 开启房间 / 加入房间 + 状态 / 最近一条 / 房间关卡），见 [控制台.md](控制台.md)。
- 正式 UI 之后再落成场景（照 `glove_slot.tscn` 的方式）。**在那之前不要为了联机去改本体面板** —— 本体不认识联机（边界规则 1）。

## 二、所有关卡都由房主打开 / 退出

### 2.1 规则（四条）

1. **只有房主能决定进哪一关、什么时候退**：`request_enter_level()` / `request_leave_level()` 一律用 `is_host()` 挡住，客户端喊了静默返回。
2. 客户端收到的进 / 退关指令**只认房主**（`sender == SERVER_PEER_ID`），其余丢弃并 `Log.warn`。
3. **客户端不得自行开关卡**（进关已拦住，退关仍待办，见 §2.5）。
4. 房主换关 = **退 + 进**，不需要额外协议；中途那次多余的"退"会被紧随的"进"盖掉。

### 2.2 进关

```
房主 MainGameManager.init_manager()
  → ModManager.install_mods_to_main_game() → NetplayMod.install_to_main_game(mg)
      → NetplaySession.request_enter_level(_level_key_of(mg.game_para))   ← 只有 is_host() 时成立
          → enter_level.rpc(level_key)
客户端 NetplayMod._on_level_enter_requested()
  → LevelRegistry 取关 → para.set_choose_level(三件套) → Global.game_para = para
  → GlobalUtils.change_scene(MainScenesMap[para.game_sences])
```

进关键值（`NetplayMod._level_key_of()`）:

| 字段 | 用途 |
|---|---|
| `id` | `LevelRegistry` 的 id（**首选**） |
| `path` | 铺底：有的导出包里 `LevelRegistry` 扫不到内置关卡，客房按 id 找不到时退回路径，**仍要**过 `is_level_script()` 白名单 |
| `mode` / `page` / `level_id` | 选关三件套 —— `save_game_name` 就是靠它拼出来的，不补齐会把通关存档写到默认键上 |

**本机没有这一关 ⇒ 留在原地 + `Log.error`**，不猜、不进主菜单、不静默回菜单。

### 2.3 退关

- 触发点：房主的 `MainGameManager` 节点退场（`tree_exited`）⇒ `request_leave_level()` ⇒ `leave_level.rpc()`。
  选它当触发点的理由：结算退出 / 暂停菜单退出 / 失败退出**都会销毁这一局**，一个 `tree_exited` 全覆盖，不必逐条出口登记。
- 客户端退回**进关时那一关所属的选关页**：`ResourceLevelData.game_mode` 存的就是 `MainSceneRegistry.MainScenes.ChooseLevel*`，不需要维护对照表；认不出（还要过一遍 `path.contains("choose_level")` 保险）就**留在原地**。
- 连续换关时旧节点的 `tree_exited` 也会响一次，会被紧随的"进"盖掉，不会闪过一个多余画面。

### 2.4 通关以房主为准

- 存档层已经按房主走（`MgmSaveManager.level_success_write_gate`）：房主照旧写并下发裁决 `level_result`；客户端**只有房主裁决过这一关才写**。
- 表现层（结算画面 / 失败演出）在阶段四之前仍是各跑各的 —— 裁决口保证的是**存档进度**跟着房主，不等于表现也跟着房主。

### 2.5 现状差距（待办，按优先级）

| 约定 | 现状 | 待办 |
|---|---|---|
| 客户端不得自行**进**关 | ✅ 已做：本体留了 `GlobalUtils.enter_level_gate`，模组占住后客户端点选关页的关卡**进不去**（控制台「最近一条」提示"由房主选关"）。房主 / 未连线一律放行 | 有正式 UI 时把选关按钮置灰（现在是点了没反应 + 一行提示） |
| 客户端不得自行**退**关 | 客户端退出关卡不通知任何人，房主与同伴都不知道 | 退关入口按角色分流：客户端的"退出"= 退出房间 / 断开连接，**不是**把大家带走。<br>⚠️ 难点：换关时客户端的旧 `MainGameManager` 也会 `tree_exited`，与"自己退出"分不开，要先有"正在被房主拉去下一关"的状态位才做得干净 |
| 无房主时的行为 | 房主在菜单里时客房自由逛菜单 | 保持（房间只决定"打哪一关"，不接管菜单） |
| 新增退出路径 | 只兜了 `tree_exited` | 将来出现"不销毁 `MainGameManager` 的退出"时要补触发点 |

## 三、进关之后：战斗域走联机，其余本地

### 3.1 一句口诀

> **会改变胜负 / 场上实体与数值的 ⇒ 战斗域（主机权威）；只改变"我看到什么"的 ⇒ 本地。**

### 3.2 战斗域（唯一走联机的部分）

> 玩家这边的操作**只有一个出口**：本体所有玩家操作入口都先过 `GlobalUtils.player_action_gate`
> （见 §3.5），由 `NetplayActionGateway` 翻译成命令、`NetplayBattleSync` 发出去。
> 不要再为某一种操作另开一个上行口。

| 项 | 通道 | 现状 |
|---|---|---|
| 选卡（谁带哪张 / 不重复 / 准备 / 开始） | 协商 + 房主收工 | ✅ `NetplayCardSync` / `NetplayReadyFlow` |
| 场上植物（种 / 铲） | `click_card` / `click_shovel` / `click_cell` 上行 → 主机跑成 → `battle_op` 下行重放 | ✅ 操作层已通 |
| 僵尸（波次时机 / 出怪类型 / 出怪行） | **波次时机与演出**由主机下发 `wave_next`；**出怪本身不下发** —— 客户端一个僵尸都不自己造，场上的僵尸全部由快照按 `entity_id` 补种（客户端**彻底没有出怪逻辑**，不再依赖 `GameRng` 同源） | ✅ 已通（实现见 [联机模组.md](联机模组.md) §4.7） |
| 传送带出卡 | **出哪一张由主机下发** `card_spawn`（带 `ResourceCardReference.to_dict()`）；客户端闸门恒 false，一张都不自己抽。★ 只管传送带 —— 种子雨是一关专属玩法，不接管（§1-8） | ✅ 已通（实现见 [联机模组.md](联机模组.md) §4.12） |
| 阳光（天降 / 拾取） | 天降 **`sun_spawn` 下行**（编号 / 值 / 起点 / 落点）；拾取 `pick_sun` **带实体编号**上行 → 主机摘掉同一颗 → 下行重放 | ✅ **五处生成点全部**已收归主机（天降 / 植物生产 / 水族馆 / 宝石迷阵 / 锤子）+ 拾取按编号对齐（实现见 [联机模组.md](联机模组.md) §4.8）<br>⚠️ 别找"僵尸掉落的阳光"：不存在，`DropItemComponent` 只掉金币 / 花园植物 / 巧克力 |
| 掉落物（金币 / 巧克力） | 由主机下发 `drop_item`（编号 / 种类 / 起点 / 落点）；拾取 `pick_drop` 带编号上行 → 主机收走同一枚 → 下行重放 | ✅ 已通（实现见 [联机模组.md](联机模组.md) §4.10）<br>⚠️ 礼包 `Present`（解锁道具 / 战利品 / 关卡结算线）**不拦**：时机由关卡数据决定，拾取要写存档与触发结算 |
| 卡槽冷却 / 阳光总量 | 下行（阶段四快照） | ⏸ 待做 |
| 小推车 / 场上机关 | 由僵尸与格子事件驱动 ⇒ 属战斗域 | ⏸ 随阶段四 |
| 通关 / 失败 | 房主裁决下行 | ✅ 存档层 |

### 3.3 本地域（各跑各的，不上行也不下行）

- **关卡外的一切**：主菜单 / 选关页 / 存档选择 / 账号 / 商店 / 图鉴 / 成就 / 禅境花园 / 智慧树。
- **关卡内的非战斗 UI**：暂停弹窗、菜单按钮、提示条、教程演出、进度条表现、镜头、音效与 BGM、动画与粒子。
- **存档读写**（除了房主裁决下来的那一次通关写档）。
- **输入的手感层**：按下到主机回话之间的本地表现（预测 / 回滚属阶段四）。
- **控制台与调试开关**。

> 判定不清的：**先当本地**，等阶段四统一收编 —— 提前把表现层接进命令表只会让同步表膨胀且难拆。

### 3.4 三步判定法（新增一条机制时）

1. 它会不会让**两端的胜负**不一样？会 ⇒ 战斗域。
2. 它会不会改变**场上的实体集合 / 血量 / 数值**？会 ⇒ 战斗域。
3. 只影响画面 / 声音 / 个人 UI？⇒ **本地域**（默认答案）。

### 3.5 落到代码：战斗域的三个必做动作

0. **本体侧先把它接进统一上报口**：在 `GlobalUtils.E_PlayerAction` 加一个值，
   在那个操作的入口处调一行 `GlobalUtils.submit_player_action(那一种操作, [相关对象])`
   （返回 true 就 `return`，本地不再跑）。**这是唯一需要动本体的地方** ——
   不要再为它新开一个 `xxx_gate`（那种口越多，漏装的机会越多，见 [联机模组.md](联机模组.md) §4.6）。
1. 在 `NetplayCommand` 加一个 op + 参数（**只放可序列化标量**：int / float / String / Vector2i；
   对象一律换成下标 / 类型 id），并在 `op_from_action()` / `args_from_action()` 里登记那一种操作。
   `NetplayActionGateway` 不用改 —— 它按操作种类查表，**新增一种操作它自动就认**。
2. 在 `NetplayBattleSync.execute()` 的**唯一重放表**里加一支，且**尽量推本体的同一条事件 / 入口**：

   ```gdscript
   EventBus.push_event(ConstEventName.MAIN_GAME_CLICK_CARD, [card])   # 好的写法
   mg.hand_manager._on_click_cell(cell)                               # 好的写法（同一枚入口）
   ```

   **不要**替本体抄一份逻辑 —— 推同一个事件就还是本体的同一条链路，音效、生命周期、冷却与阳光校验全都不用模组再抄一遍。

### 3.6 边界纪律

- **本地域代码不得依赖远端数据**：不要出现"等对端回话才继续"的本地流程（选卡"准备"那种**等待人**不算，**等待数据**才算）。
- **战斗域的判定只在主机上跑**：客户端上行的是请求，主机跑不动（冷却 / 阳光不够 / 下标对不上）就当这一下没发生，两端都不记这一笔。
- **表现随机不要换 `GameRng`**（眨眼、断肢弹道、音效、花园、砸罐摆位）：不同步也不影响胜负，换成共享随机反而占用种子序列。
- 两端**只做主机那一份局面**，不要"各跑各的、事后对齐" —— 那是阶段四的做法，得先有稳定网络 id 与纠偏。

## 四、验收清单（人工，双实例）

开两个实例（各用一份 APPDATA，免得 `netplay.target` 与存档互相覆盖），往 `data/mods/mod_config.tres` 的 `enabled_mods` 加 `&"netplay"`，各自在游戏内打开控制台（暂停菜单 → 控制台 → 「联机」栏）：

1. 一端开房间、一端加入 → 「状态」显示已连接、房里 2 人，「最近一条」出现 `玩家 N 已加入`。
2. 房主从选关页进任意一关 → 客户端被**自动拉进同一关**（不用在客端点任何东西），客端日志有 `跟房主进 [...]`。
3. 房主退关 → 客户端退回**同一选关页**。
4. 客户端点选关页的关卡**进不去**；房主进关后客端被自动拉进同一关。
   **两端在同一刻开同一波、出同一批怪、落在同一行**（看日志里的波次号与场上僵尸）。
   天降的阳光两端同一颗；捡一颗两端一起没。
   **客户端这一侧的僵尸位置 / 血量跟着主机走**（被每帧快照拉齐）—— 客户端自己打死一只、
   主机那边没死时，下一帧它应该"复活"回去，这正是快照在起作用。
5. 双方选卡不能选重；撞车时 **peer id 大的一方让**。
6. 客户端点卡片 / 铲子 / 捡阳光 → 主机回到话之后两端场上一致（现在有半个 RTT 的延迟，属已知项）。
7. 房主打通一关 → 两端存档都解锁；客户端自己打通不算数。
8. 第三人中途加入 → 被拉进当前关、拿到同一颗种子。
9. 房主进程强退 → 客户端回「未连接」，房间解散。

交付前照例跑编译门禁：`powershell -ExecutionPolicy Bypass -File test/check_scripts.ps1`（要 `real compile errors = 0`）。
