## 1. 脚本继承关系

```
Node2D
└── Bullet000Base
    ├── Bullet000NormBase              ← 大多数「标准子弹」从这里开始
    │   ├── BulletLinear000Base        直线
    │   ├── Bullet000ParabolaBase      抛物线（贝塞尔）
    │   └── Bullet000TrackBase         追踪（含无敌人时跟鼠标等）
    └── Bullet016CobCannon（示例）     ← 特殊弹：只继承最薄基类
```

- **`Bullet000Base`**：Body、影子、`bullet_type`、阵营等，体积最小。
- **`Bullet000NormBase`**：受击 `Area2D`、击中特效、`speed` / `direction`、`init_bullet`、通用碰撞与 `attack_once`。
- **三种运动基类**：在 `_physics_process` 里调用各自 **`$MovementComponent`** 的 `physics_process_bullet_move`。
- **特殊类（如玉米炮）**：直接继承 **`Bullet000Base`**，不经过 `NormBase`，通常也没有通用 `MovementComponent`，用独立流程（如 `init_cannon`、Tween、炸弹组件）。

## 2. 初始化（`init_bullet`）

标准子弹在发射后应调用 **`Bullet000NormBase.init_bullet(字典)`**。常用键见枚举 **`E_InitParasAttr`**，例如：

| 键                               | 含义                 |
| ------------------------------- | ------------------ |
| `Position` / `Direction`        | 起始位置与方向            |
| `BulletLane` / `IsActivateLane` | 行与是否按行过滤命中         |
| `Enemy`                         | 抛物线 / 追踪可选目标       |
| `EnemyGloPos`                   | 抛物线：敌人已消失时仍用于落点的位置 |

追踪弹会在 `init_bullet` 里设置 **`detect_component_global`**；发射流程须保证先 `init_bullet` 再依赖 `_ready` 里的全局检测，避免空引用。

## 3. 子弹阵营（植物 / 僵尸）

一份子弹场景要能被**双方**复用（植物发射打僵尸、**植物僵尸**发射打玩家植物），
阵营不能写死在场景里 —— 相关常量集中在 **`src/entities/bullet/bullet_camp_config.gd`**（`BulletCampConfig`，全 static）：

| 项                                                     | 植物方（`CharacterType.Plant`）        | 僵尸方（`CharacterType.Zombie`）                                     |
| ----------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------- |
| `Area2DAttack.collision_layer`                        | 8（layer4 `BulletFromPlant`）       | 128（layer8 `BulletFromZombie`）                                    |
| `Area2DAttack.collision_mask`                         | 512（layer10 僵尸真实受击框）             | 256 + 1024（layer9 植物真实框 + layer11 魅惑僵尸真实框）                        |
| 敌人                                                    | `Zombie000Base`                  | `Plant000Base`（魅惑僵尸也算，它受击框在 layer11）                              |
| 索敌前后优先级                                                | x 更小（更靠近房子）优先                    | x 更大（更靠近僵尸出生侧）优先                                                 |

**阵营怎么定**

1. 场景里的 `bullet_camp` 只是**默认值**；
2. 发射方在 `get_bullet_paras()` 里填 **`E_InitParasAttr.BulletCamp`** —— `AttackComponentBulletBase.get_bullet_camp()`
   直接用 `BulletCampConfig.get_camp_of_character(owner)` 推导（owner 是僵尸 → 僵尸方子弹）；
3. `Bullet000NormBase.init_bullet()` 应用阵营：`apply_bullet_camp()` → `BulletCampConfig.apply_camp_collision()`。

**额外层不会丢**：`apply_camp_collision()` 会先把场景里配置的位按 `~C_AllCampLayerBits` / `~C_AllCampMaskBits` 剥离，
不属于阵营基础层的位（直线子弹的 layer1 World 判斜坡、保龄球的 layer7 Bowling 供撑杆跳检测）原样保留再并回去。

**溅射**：`SpatterComponent` 在 `_ready` 里从所属子弹读一次阵营并同步 `Area2DSpatter` 的层；
对外方法统一叫 **`spatter_all_area_enemy()`**（旧名 `spatter_all_area_zombie()` 保留为转发）。

**已知边界**：全局检测组件（`main_game_base.tscn` 的 `DetectComponentGlobal`）仍是**植物视角**（只检测僵尸层），
所以僵尸方的**追踪**子弹暂时索不到植物 —— 真要做僵尸方追踪子弹，先补一个僵尸视角的全局检测组件。
投手 / 直线类不受影响，它们的目标来自发射方自己的 `DetectComponent`。

**已在用这套机制的**：植物僵尸（Z031–Z044，见 [植物僵尸.md](植物僵尸.md)）——
豌豆僵尸射的就是 `bullet_pea.tscn`，靠 `BulletCamp = Zombie` 变成打植物的子弹。

## 4. 移动组件（脚本路径：`src/entities/bullet/component/movement/`）

| 脚本                       | 作用                                                                               |
| ------------------------ | -------------------------------------------------------------------------------- |
| `BulletMovementBase`     | `_ready` 时把 `owner` 当作子弹根节点（`Bullet000Base`）。                                    |
| `BulletMovementLinear`   | 按 `direction * speed` 推进（根节点本地 `position`）。                                      |
| `BulletMovementParabola` | 贝塞尔落点；根节点 `_ready` 时调 `parabola_movement_ready`；可保护伞弹开重置。                        |
| `BulletMovementTrack`    | `reset_track_movement` 切换追敌 / 鼠标 / 无目标减速；每帧由根节点调用 `physics_process_bullet_move`。 |

约定：**根节点**统一在 `_physics_process` 里调用移动组件，移动组件**不**单独启用全局 `_physics_process` 抢顺序，便于先移动再判距离销毁等。

## 5. 特殊子弹示例：玉米炮

| 项目 | 内容                                                                                                                  |
| -- | ------------------------------------------------------------------------------------------------------------------- |
| 场景 | `bullet_cob_cannon.tscn`                                                                                        |
| 脚本 | `src/entities/bullet/bullet_cob_cannon.gd` → `extends Bullet000Base`                                                 |
| 特点 | 使用 **`init_cannon(世界坐标)`**；动画与落地逻辑写在脚本内；爆炸由 **`BombComponent`** 等子节点处理，不走通用 `init_bullet` + `MovementComponent` 管线。 |

新增类似「演出型 / 炮击型」子弹时，若与标准碰撞、移动差异大，可沿用：**只继承 `Bullet000Base`**，场景中补齐脚本里 `@onready` / `%` 引用的节点。

## 6. 新增一种标准子弹的推荐步骤

1. 在 `src/entities/bullet/` 使用 **`bullet_linear_base`** / **`bullet_parabola_base`** / **`bullet_track_base`** 之一作为新场景父模板，保持 **`MovementComponent` 子节点脚本类型**与运动方式一致。
2. 在 `src/entities/bullet/` 新建脚本 **`extends`** 继承对应父类子弹。
3. 在 `BulletRegistry` 注册，同步 **`BulletType`** 与资源引用。
4. **不用为僵尸方复制一份场景**：阵营由发射方在 `init_bullet` 时传入（见 §3），碰撞层会自动切换。
   场景里**不要**再手改 `Area2DAttack` 的 `collision_layer` / `collision_mask` 去表达阵营 —— 那会被 `apply_camp_collision()` 覆盖，
   只把「非阵营」的额外层（World / Bowling）留在场景里即可。

> 回归探针：`test/scenarios/probe_bullet_camp.gd`（锁死「同场景 / 两阵营 / 两组碰撞层」+ 额外层不丢），
> `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_bullet_camp`。
