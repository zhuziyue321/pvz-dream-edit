# 运行期植物（模组 / 运行期新增一株植物）

> **[面向 AI Agent]** ｜ **触发条件**：要在**运行期**（模组 / 控制台 / 自制关卡）新增一株植物，或改「登记 / 卡片 / 卡面 / 解锁」这条链路
> **读完你能**：知道新增一株植物要填什么、装 / 卸由谁管、卡片与卡面的四个坑收在哪、底部植物怎么声明自己的地形位
> **强制级别**：**参考** ｜ **不读的风险**：把「新增植物」的样板代码再抄一遍到模组里（登记顺序、取帧时机、撤销顺序，三个坑都藏在里面）
> **关联**：僵尸那一侧 [僵尸热注册.md](僵尸热注册.md) ｜ 注册表 `CharacterRegistry` ｜ 配方 `PlantRuntimeRecipe` ｜ 装 / 卸 `PlantRuntimeKit` ｜ 地形位 `PlantConditionBits` ｜ 模组 [模组机制.md](模组机制.md)

---

## 1. 一句话

**运行期新增一株植物 = 填一张 `PlantRuntimeRecipe`，交给 `PlantRuntimeKit.install()` 一键装。**
装的四件事（登记进注册表 / 插卡 / 画卡面 / 解锁）与卸的反向四步都在 Kit 里，模组不用碰。

内置的 48 株植物是「一个 `.tscn` + `PlantInfoData.PLANT_INFO` 一行」—— 那是**编译期**的事。
运行期走不了这条路：`PLANT_INFO` 是 `const` 表（写不进去），本体也不能 `preload` 模组的场景
（本体不 import 模组，硬约束 §1）。

```
src/entities/character/plant/plant_runtime_recipe.gd   ## PlantRuntimeRecipe：这株植物是什么
src/entities/character/plant/plant_runtime_kit.gd       ## PlantRuntimeKit：装 / 卸（登记 + 卡片 + 卡面 + 解锁）
src/core/autoload/character_registry.gd                 ## 热注册入口 / 撤销 / 条件位查询
src/core/consts/plant_condition_bits.gd                 ## PlantConditionBits：地形位的名字
src/entities/character/plant/plant_down_base.gd         ## 底部植物：own_condition_bit（我给格子加哪个位）
```

## 2. 两步装一株植物

### 第 1 步：植物场景 + 脚本（跟内置植物一样写）

场景根节点继承 `Plant000Base`（底部容器类继承 `Plant000DownBase`），脚本照
[创建新角色.md](创建新角色.md) 挂组件。这一步与内置植物**没有任何区别** ——
「运行期新增」只是注册方式不同，不是写法不同。

### 第 2 步：填配方 + 装

```gdscript
var recipe := PlantRuntimeRecipe.new()
recipe.plant_type = &"my_mod_plant"     ## 留空由注册表分配 `runtime_plant_1`
recipe.plant_name = &"MyPlant"
recipe.plant_scene = preload("my_plant.tscn")
recipe.cool_time = 7.5
recipe.sun_cost = 25
recipe.condition_bits = PlantConditionBits.GRASS | PlantConditionBits.ROOF
recipe.place_in_cell = CharacterRegistry.PlacePlantInCell.Down
recipe.card_face_anim = &"MyPlant_idle"  ## 卡面从这一帧动画里取
recipe.card_face_fallback_plant = PlantIds.FLOWER_POT  ## 取不到就借这张卡的脸

var kit := PlantRuntimeKit.new()
kit.install(recipe)        ## 失败返回 false（配方不合法 / id 撞了内置植物）
## ★ 还想让玩家在选卡界面里挑到它：装完之后自己登记一页（见 §6）
var choose_page := AllCards.register_plant_choose_page([kit.recipe.plant_type])
```

卸载：`AllCards.unregister_plant_choose_page(choose_page)` → `kit.uninstall()`
（Kit 负责摘卡 → 清注册表 → 撤解锁；选卡页归模组所有，Kit 不代撤）。
一局一局的解锁会丢（读档按存档重建 `curr_plant`），所以每局开局补一次 `kit.unlock()`。

## 3. id：本体不必再留空槽位

植物 id 改成 StringName 之后（2026-10-13），**没有编号段这回事了**：

- 配方里 `plant_type` 留 `PlantIds.NULL` → 注册表自动分配 `runtime_plant_1`、`runtime_plant_2` …；
- 手动指定 → 不能撞内置植物已用的 id（`PlantIds` 里有就拒绝，见 `register_runtime_plant()`）；
  建议带模组自己的前缀（如 `&"more_armor_copper_bucket"`）；
- 想知道某株是不是运行期注册的：`CharacterRegistry.is_runtime_plant(id)`（`is_runtime_zombie()` 的对照）。

> `PlantIds.WATER_BOWL` 那个「空槽位」是编号时代的产物（水盆现在挂在 DLC 植物模组里，
> 沿用该 id 只为兼容探针与老存档，纯历史原因）——
> 新模组不要再让本体加常量，自己起 id 就行。

## 4. 卡片与卡面：四个坑都收在 `PlantRuntimeKit` 里

这四件事以前写在模组里（水盆 1.0 就是），每只新植物都要重踩一遍：

| 坑 | Kit 里的处理 |
| --- | --- |
| 插卡后不 `AllCards.rebuild()` → 新卡没有编号、选卡界面认不出 | `_install_card()` 末尾统一重排 |
| 插在源目录**中间**会把它后面每张卡的编号挪一格 | 一律追加到**最后一个**容器（`PlantCards2`）的末尾 |
| 取帧要往 `tree.root` 挂临时容器，`_ready()` 里挂不进去（"Parent node is busy setting up children"） | 卡先挂进目录与编号，**卡面推到帧末**再画（`_build_card_face.call_deferred()`） |
| 取帧拿到的是整株（血条 / 组件容器那批 UI 也在，脚本已被剥掉、visible 停在 true） | 剥影子 + 默认只留 `Body` 那一枝（`card_face_body_only`，与手摆卡面的成分一致） |
| 借脸时把源卡的 `CharacterStatic` **整块**搬过来 → 卡内挂点 (24,30) 叠成两份 | `_borrow_card_face()` 只复制源卡 `CharacterStatic` **下面的那株植物** |

卡面取不到帧时按 `card_face_fallback_plant` 借一张现成卡的脸 ——
**卡面一空，手持会直接报「卡片静态角色为空」拿不起来**，所以这条兜底别省。

⚠️ 借脸的口径（2026-10-17 踩坑，明日方舟精英化「种子包贴图偏移」）：
卡面的挂点属于**卡自己的** `CharacterStatic`（`card.tscn` 里 `position = (24, 30)`），
所以借来的只能是它下面的植物那一枝。把 `CharacterStatic` 整块搬过去会带一份挂点，
两份叠在一起 → 卡面 / 待选区种子包 / 出战卡槽整块往右下歪，手持还会按
`get_child(0).scale = Vector2.ONE` 把「包装节点」当植物还原，尺寸也不对。
判据：卡面子树必须与手摆原版卡同构（`CharacterStatic → PlantXXX → Body`）。

⚠️ **动画不是 `AnimationPlayer` 的植物，通用取帧会「假成功」**（2026-10-17 踩坑，PVZ2 潜伏芹菜）：
`build_card_face()` 走 `AnimationFrameUtil`，而那条路是按 `AnimationPlayer` 找帧的
（`find_animation_player()` → `seek()`）。自己 `_draw()` 画四边形的播放器（如 PAM 路线的
`mods_builtin/pam/runtime/pam_animator.gd`）没有播放器节点 —— 取帧**不报错**，返回的是一棵
什么都画不出来的树：卡面全空，手持还会报「卡片静态角色为空」拿不起来。
这类植物的做法是**在配方子类里覆盖 `build_card_face()`**，直接给自己的一帧定格节点
（先例：`mods_builtin/pvz2/<植物>/<植物>_recipe.gd` 调 `pam_bridge.gd` 的 `create_static_frame()`，
定格渲染器在 `mods_builtin/pam/runtime/pam_static_frame.gd`）。
判据：卡面上 `character_static.get_child_count() > 0` **不等于**画得出来，要看那棵子树里有没有真的能画的东西。

## 5. 地形位：`PlantConditionBits`

`ResourcePlantCondition.plant_condition` 是位掩码，每一位 = 一种能落地的地形。
位值写在 `PlantConditionBits`（`src/core/consts/plant_condition_bits.gd`），
代码里一律按名字取：`PlantConditionBits.GRASS | PlantConditionBits.ROOF`。

⚠️ 加一位要改两处：常量表 + `condition_plant_base.gd` 的 `@export_flags`
（那串字符串是编辑器里的勾选项）。

两种「加位」的场景：

| 想干什么 | 走这个口子 |
| --- | --- |
| 新增的**底部植物**自己声明「我给格子加哪个位」 | 场景里写 `own_condition_bit`（见 `Plant000DownBase`），种下 / 死亡时由 `PlantCell.down_plant_change_condition()` 按它改地形 |
| 让**已有的植物**认这个新位（如水生植物能种进水盆） | `CharacterRegistry.add_runtime_plant_condition_bit(plant_type, bit)`（在现有条件上按位或，换的是**副本**）；撤用 `clear_runtime_plant_condition()` |
| 反查「哪些植物认这个位」 | `CharacterRegistry.collect_plant_types_by_condition(bits)`（按位查，别在模组里写死「海蘑菇 / 缠绕海草」） |

## 5.1 同格叠层（豌豆荚这类「同格再种一次 = 叠一层」）

本体只留口子，不认识任何具体植物：

| 位置 | 做什么 |
| --- | --- |
| `Plant000Base.max_stack_layers` / `can_stack_up()` / `try_stack_up()` | 叠层植物在场景里配最多几层，并重写后两个方法；普通植物默认 1 层、不支持 |
| `ResourcePlantCondition.judge_is_can_plant()` | 目标位置已有植物时，**同种 + 还能叠**才放行（手持虚影走的也是这一条） |
| `PlantCell.create_plant()` | 同种 + `try_stack_up()` 成功 → **不新建第二株**，直接返回已有那株 |
| 存档 | 层数是植物自己的状态，叠层植物覆盖 `gat_save_game_data_plant()` / `load_game_data_plant()` 保存与恢复 |

先例：`mods_builtin/pvz2/peapod/peapod_plant.gd`（最多 5 层，攻击按层数连发）。
⚠️ 叠层只叠「层数」，**不会**自动加血量 / 加受击框 —— 要加得自己在 `try_stack_up()` 里做。

## 6. 解锁 / 撤销解锁 / **进选卡界面（按页登记）**

`GlobalGameState.unlock_plant()` / `lock_plant()` 成对 —— Kit 自己会调。
`lock_plant()` 除了从 `curr_plant` 里摘掉，还会把「上次选卡」里的条目一并清掉
（不清的话「重选上次卡片」会点到一个不存在的卡位，调试模式那批植物也是这个规矩）。

**★ 解锁 ≠ 可选**：想让它出现在选卡界面里，还要**自己登记一页选卡** ——
`install_to_main_game()` / `unlock()` 都代替不了它：

```gdscript
func install() -> void:
	if not _kit.install(_build_recipe()):
		return
	## ← 少了这一行：注册成功、解锁成功，选卡界面里就是没有它
	_choose_page = AllCards.register_plant_choose_page([PlantIds.NULL, _kit.recipe.plant_type])
```

`register_plant_choose_page(plant_types)` 的参数就是**这一页的排版**：数组下标 = 格位，
`PlantIds.NULL`（`&""`）留空一格，同一页里按你给的顺序排；页序 = 登记顺序，接在原版植物页之后。
返回页句柄，关模组时 `AllCards.unregister_plant_choose_page(handle)` 撤掉。
一页装不下（超过网格模板的 48 格）时，超出的部分顺延到你这一页的下一页。
一株一页也可以，多株排一页也可以 —— **本体不替你重排**。

- **为什么要有这道门禁**：模组注册的植物未必都想给玩家挑（只给关卡脚本 / 传送带发货的也有），
  以前「注册 + 解锁」就等于可选，两件事分不开；
- **没登记会怎样**：待选区**连它的卡位都不造**（`CardSlotCandidate` 按原版页 + 登记的页建容器），
  已解锁也点不亮 —— 但卡牌目录里仍有它，`CardSlotNorm` 的「重选上次卡片」会跳过这类条目；
- **撤销**：页归模组所有，`uninstall()` 不代撤；忘了撤也不会崩（页里指不到的卡会被跳过）；
- **调试模式那四株不走这条路**：`GlobalGameState._sync_debug_mode_plants()` 只把它们并进 /
  撤出 `curr_plant`（已解锁名单），**不登记页** —— 所以选卡界面里看不到它们。
- **如果它是某个已有植物的「副本」**（换皮 / 换数值，例如明日方舟模组的精英化），
  别给它登记页（会另开一格）；用 `AllCards.set_plant_choose_replacement(原版, 副本)`
  让它顶掉原植物那一格（见 [卡片与选卡流程.md](卡片与选卡流程.md) 的「原位替换」一节）。
- 完整机制与消费侧口径见 [卡片与选卡流程.md](卡片与选卡流程.md)。

## 7. 与僵尸热注册对照

| | 僵尸 | 植物 |
| --- | --- | --- |
| 配方 | `ZombieRuntimeRecipe`（本体 + 脚本） | `PlantRuntimeRecipe`（场景 + 数值 + 卡面） |
| 注册 | `CharacterRegistry.register_runtime_zombie()` | `CharacterRegistry.register_runtime_plant_recipe()` |
| 实例化 | `instantiate_zombie()`（配方现场组装，**没有场景文件**） | 照旧 `PlantScenes.instantiate()`（有场景文件） |
| 装 / 卸助手 | 没有（注册即用） | `PlantRuntimeKit`（还有卡片 / 卡面 / 解锁三件事） |
| id | `runtime_zombie_N`（自动分配） | `runtime_plant_N`（自动分配） |
