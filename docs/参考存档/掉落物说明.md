# 掉落物说明

> **[面向 AI Agent]** ｜ **触发条件**：要改「掉钱 / 掉巧克力 / 掉种子包 / 掉礼包 / 掉阳光」这条线，或**新增一种掉落物**
> **读完你能**：知道该继承谁、在哪登记、生成口该调哪一个、落点与存在时长在哪改、老名字还有哪些、
> 以及结算线战利品的**那套表现**（箭头 / 闪光 / 爆裂）与结算之后的**领奖屏 / 关卡淡出**
> **强制级别**：**参考**（机制说明，不读不打回；硬约束在 [../项目规范.md](../项目规范.md) §1）
> **不读的风险**：无 —— 但容易把新逻辑写进某一个具体类里，于是又要抄第五遍
> **关联**：[禅境花园.md](禅境花园.md)（花园掉钱与蜗牛） ｜ [联机模组.md](联机模组.md)（掉落同步） ｜ [杂项存档.md](杂项存档.md)

## 1. 一条骨架 + 三个生成口

```
                       ┌─ DIM_Coin        （战斗掉钱：摇概率选银 / 金 / 钻）
生成口 ─ DIM_Base ─ ───┼─ DIM_Chocolate   （僵尸掉巧克力）
  （实例化 + 挂父节点   ├─ DIM_SeedPacket  （通关新植物种子包）
    + 落点 + 广播）     └─ DIM_GardenPlant （花园植物礼包）
                              │
                              ▼
                     DropItemBase（生到死的公共骨架）
                       钱 / 巧克力 / 种子包 / 礼包 / 阳光
                              │
                    SunSpawner（阳光专用生成口：天降 / 弹起 / 联机重放）
```

- **`DropItemBase`**（`src/items/drop/drop_item_base.gd`）：编号分配、点击接线、拾取光晕、
  抛物线弹出、超时淡出、自动拾取、拾取后的「飞向目标 → 淡出缩小 → 删除」。
  子类**不重写 `_ready()`**，改重写 `drop_ready()` / `pick()` 那几个钩子。
- **`DIM_Base`**（`src/managers/drop_item_manager/dim_base.gd`）：四个 `DIM_*` 子管理器共用，
  收掉了「父节点没配的报错 / 随机落点 / `DROP_ITEM_SPAWNED` 广播 / 掉落音效」。
  差异只剩三个重写点：`is_gate_enabled()`（受不受联机闸门）、`is_notify_spawned()`（要不要广播）、
  `get_spawn_sfx()`。
- **`SunSpawner`**（`src/items/drop/sun_spawner.gd`）：`pop_up()`（弹起再落下）/ `fall_from_sky()`（天降）/
  `spawn_at()`（**照给定的数据长**，联机主机替客户端长那一颗时用 —— 一个随机都不摇）/ 六个生成点共用，
  不再各抄一遍 tween。⚠️ 早先还有一个 `replay_fall()`（联机客户端照主机数据
  重放那一下下落）—— 2026-10-24 删除：阳光位置改成**逐帧抄主机**（快照接管），
  客户端不再自己演那一下，本体这一条入口也就没有调用方了。

## 2. 拾取的两条入口（别搞混）

| 入口 | 谁在调 | 过不过闸门 |
|---|---|---|
| `request_pick()` | 玩家点的那一下（按钮信号由基类自动连） | **过** `GlobalUtils.submit_player_action`（联机客户端只是发请求） |
| `pick()` | 已经定了的收走动作：联机主机重放、蜗牛捡钱、探针直接点 | **不过** |

`pick()` 是子类必写的业务实现（入账 / 弹提示 / 播特效）。已拾取字段统一叫 `is_opened`
（钱的老名字 `is_get`、阳光的老名字 `collected` 见 §5）。

## 3. 新增一种掉落物

1. `ItemRegistry`（`src/core/autoload/item_registry.gd`）加一个 `E_DropKind` 值 + `DROP_SCENE_MAP` 一行；
2. 新脚本 `extends DropItemBase`，写 `pick()`（要按钮就保证场景里挂 `Button` / `TextureButton`，
   要呼吸光晕就挂 `PickUpGlow` —— 基类按**节点名**自动接，不用自己连信号）；
3. 生产侧：随机掉落 → 加/复用一个 `DIM_Base` 子类，并在 `DropItemManager._dim_of_kind()` 挂一行
   （联机客户端照主机下发重建时按它找子管理器）；关卡脚本定时机的 → 直接调 `DropItemManager`。

`DropItemManager.E_DropKind` 是转发到 `ItemRegistry.E_DropKind` 的常量（老代码 / 模组还在用）。

## 4. 落点与存在时长

- **落点收敛**：`DropPositionUtil.clamp_drop_position(node, pos, margin)` —— 画布有偏移，
  屏幕左上角不对应世界原点，必须换算成世界矩形再夹。僵尸掉钱（`DropItemComponent`）与
  关卡掉落（`DropItemManager`）共用这一份。
- **存在时长**：`DropItemBase.auto_free_time`（默认 `DEFAULT_EXIST_TIME = 10` 秒），
  要在**入树之前**给（`_ready()` 当场就按它起定时器）—— 所以生产方用 `DIM_Base.create_drop()` +
  `add_drop()` 两步，别用 `instantiate_drop()` 一步版。
- **清理**：`DropItemManager.clear_all_drops()` 清四个掉落容器 + 阳光层，
  挂在 `MainGameManager.start_curr_round_game()`（多轮关卡切轮）上。失败 / 退出不用管：那两步切场景。

## 6. 联机边界（没变，只换了写法）

`mods_builtin/netplay/netplay_drop_sync.gd`：种类 / 编号 / 落点三个字段现在直接读 `DropItemBase`
（不再按 `is Coin` / `is ChocolateDrop` 分堆），收走用统一的 `pick()`。

## 7. 「战利品」那套表现（原版口径）

> 指的是**结算线上的战利品**（`is_level_complete_drop = true`）：通关掉出来的种子包 / 奖杯 / 道具。
> 普通金币、阳光、花园礼包**没有**这套表现（花园礼包只有光晕，原版 `COIN_PRESENT_PLANT` 也没有箭头）。

原版出处：`../PvZ-Portable-main/src/Lawn/Coin.cpp` 的 `IsLevelAward()` 那一类，粒子定义在
`pak/particles/*.xml`（原版粒子表原样搬过来了）。

| 表现 | 原版 | 本仓库落点 |
|---|---|---|
| **周期闪光** | `Coin::Draw` → `GetFlashingColor(mCoinAge, 75)`：灰度在 55~255 之间走三角波，周期 75 帧（1.25 秒） | `DropItemBase._start_level_award_flash()`（循环 tween 改 `modulate`） |
| **弹跳箭头** | 落地那一刻挂 `PARTICLE_AWARD_PICKUP_ARROW`（种子包用 `PARTICLE_SEED_PACKET`）：黄色下箭头，位置场 `0 → 10 → 0`，40 帧一个来回 | `src/fx/other_effect/loot_pickup_arrow.gd`，节点名 `PickUpArrow` |
| **星星爆裂** | `Coin::Collect` 里关卡奖励那一支播 `PARTICLE_STARBURST` | `src/fx/other_effect/loot_starburst.tscn`（`SceneRegistry.LOOT_STARBURST`） |
| **掉出来时屏幕闪一下** | `Challenge::SpawnLevelAward` → `PARTICLE_SCREEN_FLASH`（alpha .5 → 0，50 帧） | 事件 `ConstEventName.LEVEL_COMPLETE_LOOT_SPAWNED` → `CanvasLayerWhiteScreen.play_spawn_flash()` |
| **拾取后飞向屏幕中心并放大** | `Coin::UpdateCollected`：位置 350 帧 EASE_OUT 移到 (400-w/2, 200-h/2)，缩放 400 帧 1.01 → 2.0 | `CanvasLayerWhiteScreen.play_pickup()`（时长按本仓库节奏压缩，放大倍率照原版 2.0） |
| **永不过期** | `Coin::IsLevelAward()`：关卡奖励**不走** `mDisappearCounter` —— 掉落后不会自己消失，玩家不点就一直留在场上 | `DropItemBase.auto_free_time <= 0` = 永不过期；`DropItemManager.LOOT_NEVER_EXPIRE`（0.0）给结算线战利品 |

### 怎么接的

- **起效时机 = 落地那一刻**：`DropItemBase.notify_loot_landed()`。
  抛物线结束（`launch()`）与抛掷结束（`MgmRewardManager.throw_to`）都会调到它 ——
  原版也是 `mHitGround` 那一支才挂箭头，没落地就没箭头。
- **箭头位置**：`DropItemBase.get_level_award_arrow_offset()` = **贴图中心** + (宽/2, 高/2 - 60)（原版公式）；
  贴图尺寸由 `get_level_award_icon_size()` 给（默认礼物盒 80x80 → `(40, -20)`，
  `Present` 有自定义贴图时按贴图尺寸算）。种子包在 `SeedPacket` 里重写成 `(50, -50)`
  （原版种子包 50x70 → 贴图中心 +(25, -25)，本仓库种子包是 2 倍大）。
- **停效时机**：`DropItemBase.stop_level_award_effects()` —— 拾取 / 超时消失都要调。
  ⚠️ 闪光在改 `modulate`，不先停掉会跟淡出抢同一个属性（战利品会「闪着淡出」）。
- **星星爆裂挂在容器里，不挂在战利品身上**：战利品之后要放大飞向屏幕中心，挂身上会被一起放大。

### 探针

`test/scenarios/probe_loot_effects.gd` —— 进 1-4 掉道具类奖励，逐条断言：
落地前无箭头 → 落地后有箭头且在弹跳（幅度 > 2 像素）→ 亮度在闪（最暗 < 0.5）→ 点开有星星爆裂 → 箭头收起。

```bash
test/run_autopilot.ps1 -Scenario probe_loot_effects -Windowed
```

## 8. 结算之后：新植物领奖屏 + 关卡淡出

> 上一节讲的是「战利品在场上」的表现；这一节讲「点开之后」到「切场景」之间的两段。

### 8.1 新植物领奖屏（原版 AWARD_FORLEVEL 的新植物那一支）

原版出处：`../PvZ-Portable-main/src/Lawn/Widget/AwardScreen.cpp` 的 `DrawAwardSeed()` / `DrawBottom()`。

| 元素 | 原版坐标 / 值 | 本仓库落点 |
|---|---|---|
| 底图 | `IMAGE_AWARDSCREEN_BACK` = `pak/images/AwardScreen_Back.jpg`（800x600） | `award_screen.tscn` 的 `Background`（TextureRect） |
| 标题 | "[NEW_PLANT]" 画在 (400, 58)，金色 (213, 159, 43)，`FONT_DWARVENTODCRAFT24` | `Root/Title`（方正少儿 24，金色 0.835/0.624/0.169） |
| 种子包 | 放大 2 倍、中心在 (350, 129)（本仓库种子包本来就是原版 2 倍） | `Root/Packet`（Node2D @ 350,129）+ `CardBg` scale 2 |
| 植物名 | 画在 (400, 326)，白色 | `Root/PlantName`（y 308~340） |
| 植物说明 | `Rect(285, 360, 230, 90)`，深蓝 (40, 50, 90)，`FONT_BRIANNETOD16` | `Root/Description`（285,360)-(515,450)，SIMSUN 16 |
| 继续按钮 | `Resize(324, 500, 156, 42)` | `Root/ContinueButton`（322,500)-(478,542) |
| 整屏淡入 | `mFadeInCounter = 180` 帧白罩渐隐（3 秒） | `AwardScreen.FADE_IN_TIME = 180/60` 秒 |

**什么时候弹**：只有「拿到一株植物」才弹。
`MgmRewardManager.gain_loot()` 里查 `LootRegistry.get_plant_type(loot_name)`，
非空（种子包类战利品）就记进 `pending_award_plant` → `win_main_game()` 写完通关存档后弹这张屏。
道具类奖励（车钥匙 / 玉米卷 / 洒水壶 / 大图鉴 / 铁铲）**不弹**。

**怎么走**：领奖屏挂在主游戏上（`CanvasLayer` layer 120，压在白屏层 100 之上），
`MgmRewardManager.show_award_screen()` 轮询等玩家点「继续」→ 释放这张屏 → 再往下走
（跳商店 / 跳图鉴 / 回主菜单）。等不到就按 `AWARD_SCREEN_WAIT_TIME`（60 秒）兜底放行。

⚠️ **等「继续」的标志位必须是成员变量**（`is_award_continue_pressed`）：
GDScript 的 lambda 捕获局部变量是**按值**的，写局部变量外面看不到 —— 会永远等下去。

### 8.2 关卡淡出（原版 FadeOutLevel）

原版出处：`../PvZ-Portable-main/src/Lawn/Board.cpp:7094-7109` 的 `DrawFadeOut()`。

- **时长**：全屏填充 alpha 走满 **200 帧** → 本仓库 `CanvasLayerWhiteScreen.WHITE_TIME = 200/60` 秒。
- **颜色**：原版 `mLevel == 9 || 19 || 29 || 39 || 49` 那几关淡成**黑色**，其余白色 ——
  即冒险 1-9 / 2-9 / 3-9 / 4-9 / 5-9。本仓库 `BLACK_FADE_ADVENTURE_LEVELS = [9,19,29,39,49]`，
  由 `_get_fade_color()` 查当前冒险关卡号（`reward_manager.get_curr_adventure_level()`）决定。

  点「继续」→ 场景切走。带窗口跑会截图到 `user://autopilot_reports/shot_award_screen.png`。
