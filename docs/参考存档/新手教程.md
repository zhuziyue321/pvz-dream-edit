# 关卡教学演出（冒险模式 1-1 / 1-2 / 1-5）

原版 1-1 / 1-2 都是教程关：**第一波僵尸都在玩家种下第一株植物之后才出现**，提示文本按原版顺序逐条弹出。

- **1-1**：只有中间 1 行草皮但**仍是 5 行地图**（`map_front_1row`，其余 4 行是不可种植的无草皮土行）、
  开局 150 阳光、只有豌豆射手可用，教捡卡 → 种植 → 收阳光 → 再种一棵。
  **教学写在 `run_flow()` 里**（一句话一个 await），排在**允许操作之后、开战之前**：
  玩家先在一个没有僵尸的草坪上把三件事学会，流程走到「开战」才出第一波。
  已经通关过 1-1 的那次进入**不播教学**，改播「准备…安放…植物」红字（`ready_set_plant()`），
  顺序退化成普通关的 `预览 → 选卡 → 移回视角 → 允许操作 → 准备安放植物 → 开战`。
  教学敢指定「豌豆射手」的前提见该关卡脚本的文件头注释：首次打 1-1 的玩家只有这一张卡。
- **1-2**：只有中间 3 行草皮（`map_front_5row`）、拥有豌豆射手 + 向日葵，教种满三棵向日葵。
  （原版种下第一棵向日葵后就出僵尸；当前实现没有「不等开战先开第一波」的入口，
  教学整段跑完、走到 `start_battle()` 才出第一波。）
- **1-5**：**铲子教学关**（`card_mode = 2` 传送带 + `is_bowling_stripe` 保龄球关），
  教学整段跑在**关卡正式开局之前**。
  开局草坪上有 3 株豌豆射手（`run_flow()` 里 `await system_plant(...)` 种的，
  `plant_cell_pos` 为 1 开始的 (行,列)，按原版摆在 **(2,6) / (3,8) / (4,7)** ——
  三株都在红线右侧，铲掉之后那几列本来就种不了），
  教 **拿铲子 → 铲掉一株 → 铲光草坪**，原版顺序是：
  **戴夫开场白 → 玩家铲光草坪 → 戴夫介绍保龄球（说到「我们去玩保龄球！」的同时红线出现）→ 预览僵尸 → 开始关卡**。
  1-5 的教学**以戴夫惊喜对话收尾**，原版 1-5 没有「干得漂亮」这一句提示 —— 戴夫说完就直接进关卡。
  因为开场被教学占掉了，1-5 自己把 `first_wave_delay` 调到 `6.0`，传送带与第一波僵尸都由
  「开战」启动（传送带：`MainGameManager.main_game_start()`；第一波：`ZombieManager.start_game()`）。

> **2026-10-06 的改动**：原先有一套 `TutorialManager` + `ResourceTutorialData / ResourceTutorialStep`
> （步骤数据自驱跑 + 逐步模式两种跑法）已经**整体删除**。
> 现在「教学」没有任何专门系统：**它就是关卡流程里的一段**，用三个通用工具拼出来 ——
> 提示（`hint`）、箭头（`arrow_*`）、等玩家操作（`wait_*`）。
> 连带的改动：箭头目标枚举 `E_PointerTarget` 搬进 `PointerTargetResolver`；
> 传送带不再「由教程接管启动时机」，改由**开战**启动（见下文第 3 条）。

## 三个工具（任何关卡都能用，与「教程」无关）

| 工具 | 流程方法（`LevelScriptBase` 上） | 事件脚本 | 做什么 |
|------|--------|---------|-------|
| **提示** | `hint(文本)` / `hide_hint()` | `LevelTimelineEventHint` | 屏幕下方显示提示条；**传空串（或 `hide_hint()`）= 关掉提示条** |
| **箭头** | `arrow_card(植物)` / `arrow_lawn(植物)` / `arrow_sun()` / `arrow_shovel()` / `arrow_plant()` / `arrow(目标, 植物)` | `LevelTimelineEventArrow` | 箭头指到种子包 / 草地 / 阳光 / 铲子 / 草坪上的植物，**每帧跟着目标走** |
| 同上 | `hide_arrow()` | 同上（target = None） | 收起箭头 |
| **等玩家** | `wait_take_card(植物)` | `LevelTimelineEventWaitTakeCard` | 等玩家把这张卡捡到手上（手上已有就立刻过） |
| 同上 | `wait_take_shovel()` | `LevelTimelineEventWaitTakeShovel` | 等玩家把铲子拿在手上 |
| 同上 | `wait_plant(数量, 植物)` | `LevelTimelineEventWaitPlant` | 等玩家种下几株（按「草坪上这种植物多了几株」判定） |
| 同上 | `wait_plant_timeout(数量, 植物, 秒)` | 同上（`timeout` > 0） | **限时**等：时限内种下返回 `true`，到点没动手返回 `false` |
| 同上 | `wait_dig_plant(数量)` / `wait_dig_all_plants()` | `LevelTimelineEventWaitDigPlant` | 等玩家铲掉几株 / 铲光草坪 |
| 同上 | `wait_collect_sun()` | `LevelTimelineEventWaitCollectSun` | 等玩家点掉一颗阳光 |
| 同上 | `wait_sun_enough(数值)` | `LevelTimelineEventWaitSunEnough` | 等阳光攒够（进入时已经够就立刻过） |
| **配合演出** | `allow_operation()` | `LevelTimelineEventAllowOperation` | **放开玩家的手**（推进到 `MAIN_GAME` + 放出出战卡槽）；**不开战** |
| 同上 | `spawn_sun()` | `LevelTimelineEventSpawnSun` | 掉一颗阳光下来（不是天降阳光定时器） |

### 六条要知道的

1. **提示与箭头各自独立开关**：关掉提示条不会顺手收起箭头，反之亦然 —— 想一起收就各调一次
   （所以教学收尾是 `await hint("")` + `await hide_arrow()` 两句，不是一句）。
2. **两者共用同一个提示条实例**（`TutorialAdviceUI.ensure_level_hint`，按名字 `LevelHintUI`
   挂在 `CanvasLayerUI` 下），一次只会有一条提示条；它随主游戏一起销毁，关卡忘了「关掉」也不会留残影。
3. **箭头每帧重解析目标**：解析规则在 `PointerTargetResolver`
   （「阳光还没掉下来就先不显示、掉下来自动跟上」这类行为不用关卡操心）；
   主游戏被释放（玩家退回主菜单）时箭头自己收起，不会去访问已释放对象。
4. **提示条与箭头都不拦输入**（`mouse_filter = IGNORE`），点卡片 / 点草坪照旧。
5. **等玩家操作要玩家先能动手**：`allow_operation()` 把阶段推进到 `MAIN_GAME`
   （判据见 `Card._on_button_pressed` / `HandManager._on_main_game_progress_update`）；
   出怪 / 天降阳光 / 生成墓碑仍在 `main_game_start()`，由「开战」触发 —— 两者必须分开。
6. **玩家中途退回主菜单：协程照跑，但主游戏已经没了**。教学协程挂在「等玩家 XX」上时，
   一旦 `MainGameManager` 被释放，signal / timer 会把协程唤醒，接下来的流程方法
   传的就是个已释放对象（GDScript：`.. argument 1 (previously freed) is not a subclass of ..`）。
   闸门在 `LevelScriptBase._run_event()`：主游戏失效就直接返回，后面每个 await 快速跳过、协程自然收尾；
   各个等待事件自己也要用 `is_instance_valid()` 兜住 —— **`main_game != null` 对已释放对象是 `true`**，照样崩。

## 运行期四个模块

| 模块 | 职责 |
|------|------|
| `TutorialAdviceUI`（`src/ui/tutorial_advice_ui.gd` + `.tscn`） | **屏幕下方的提示条** + 指向箭头，挂在主游戏 `CanvasLayerUI`（层 50）下；关卡的「提示 / 箭头」工具与一次性提示都用它 |
| `TutorialPointer`（`src/ui/tutorial_pointer.gd`） | 箭头绘制：直接画五边形（不依赖美术素材），箭尖落在目标点、箭尾朝向提示条 |
| `PointerTargetResolver`（`src/ui/pointer_target_resolver.gd`） | 箭头目标解析（画布坐标）+ `E_PointerTarget` 枚举；「取卡片 / 找能种的格子」这套规则只有一份 |
| `LevelWaitCondition`（`src/levels/core/level_wait_condition.gd`） | 等待判据的查询（数草坪植物 / 手上拿的是什么 / 阳光多少），供各个 wait_* 事件共用 |

**提示条的形态（2026-10-03 起）**：一律是**贴屏幕底部的通栏提示条**
（左右各留 24、距底 20，高度按文本行数撑开、最小 64）。位置由 tscn 的 Bottom Wide 锚点决定，
**没有 `set_advice_position()` 这类外部定位接口**。改样式去改 tscn；改高度请先看下面第 1 条坑。

> **提示 UI 上踩过的三个坑**（改动这个 UI 前先看一眼，症状都很隐晦）：
>
> 1. **Label 没拿到布局宽度时宽度是 1px，不是 0**。Godot 会把 Control 的 size 钳到不小于
>    `minimum_size`，而 Label 的 minimum_size 是按可用宽度折行算的 —— 拿 1px 去算，
>    一句 12 字的提示能算出 **5008** 高的黑框。
>    所以宽度按面板算（`advice_panel.size.x - 左右 content_margin`），并且
>    `_ready()` 里先把宽度钉上、`Label.resized` 时再按实际行数重定一次高度。
> 2. **`TutorialAdviceUI._process()` 是「跟着目标走」专用的**（一次性提示跟着金币、箭头工具跟着目标），
>    两个通道都没有目标时才 `hide_pointer()` + `set_process(false)`。
>    **只调 `hide_pointer()` 而不清目标 / 不停 `_process`，下一帧又会把箭头按原目标点亮回来**
>    —— `hide_arrow()` 里三件事是一起做的。
>    顺带：`TutorialPointer._ready()` 里的 `visible = false` 曾晚于同一帧的 `point_to()` 执行
>    （节点 instantiate 后当帧就被指目标），同样会把箭头按没 —— 已改成看 `_has_target` 决定。
> 3. **锚点布局下别直接写 `size.y` / `position`**。提示条用 Bottom Wide 锚点（`anchor_top/bottom = 1.0`），
>    高度由 `offset_bottom - offset_top` 决定，写 `size.y` 会在下一次布局被 offsets 覆盖回去，
>    表现出来的症状是「多行长提示被裁掉」；改用 `offset_top = offset_bottom - 高度` 才是「贴底往上长」。
>    同理 `get_advice_box_center()`（箭头箭尾）不能拿 `position + size * 0.5` 算 ——
>    锚点模式下 `position` 落在锚点上，必须走 `get_global_transform_with_canvas()`。

改教学演出前必须知道的六件事：

1. **提示文本一律用原版 advice 字符串**，出处是 `data/strings/lawn_strings.txt` 的 `ADVICE_*` 条目
   （如 `ADVICE_CLICK_SEED_PACKET` = 点击种子包，把它捡起来！），不要另写文案。
2. **「超时才补提示」用 `wait_plant_timeout()`**：有些提示不该立刻说，得先给玩家自己试的机会。
   原版 1-1 说完「阳光够了」就是**直接等**，只有玩家 4 秒不动手才补那句「点击豌豆射手，再种一棵！」——
   写成 `if not await wait_plant_timeout(...): await hint(...)` 即可。
3. **完成条件走事件 / 信号 / 轮询**：捡卡听 `EventBus "hand_card_take"`、收阳光听 `EventBus "add_sun_value"`
   （这两个是瞬间动作，按帧轮询会漏）；「种了几株 / 铲了几株 / 阳光够不够 / 手上是不是铲子」按帧轮询，
   判据统一在 `LevelWaitCondition`。计数类判据一律**先记基准数再数差值**（`wait_plant` / `wait_dig_plant`），
   所以 1-5 那种「开局草坪上本来就有植物」的关卡照样能等；
   阳光数值只在轮询里读（`add_sun_value` 的回调顺序不保证卡槽已经加过数值）。
4. **指向草坪时指向「真能种下的格子」**：地图是数据驱动的（1-1 只有一行铺了草皮 `map_front_1row.tres`、
   1-2 / 1-3 只有中间三行 `map_front_5row.tres`），所以从草坪中心向外找第一个 `judge_is_can_plant()` 为真的格子。
   保龄球关（1-5 / 小游戏）：**红线右边一律不可种植**（`WallnutBowlingStripe` 把那些格子置成
   `IsNoPlantBowling`），靠种植条件过滤后箭头只会落在红线左边。
5. **取卡片一律走 `PointerTargetResolver.get_curr_card_list()`**：普通关取出战卡槽 `card_slot_battle`，
   **传送带关（1-5 / x-10）没有出战卡槽**，卡片在 `card_slot_conveyor_belt.curr_cards` 里；
   直接读 `card_slot_battle` 在传送带关拿到的是 null，箭头会消失。同理 `wait_sun_enough()` 只对
   普通卡槽关卡有意义（传送带关卡片免费、不掉阳光）。
6. **传送带与第一波僵尸的启动时机**：传送带**由开战启动**（`main_game_start()` 里
   `card_manager.start_conveyor_belt()`），所以 1-5 敢在教学里先 `allow_operation()` 放玩家的手 ——
   卡片不会提前从传送带上掉下来；第一波**只能由开战开**（`ZombieManager.start_game()`，
   整局一次），教学期间不出僵尸 —— 要提前出怪只能把 `start_battle()` 提前。

## 戴夫对话（关卡开场 / 教学中途）

戴夫有两个挂载点，文案一律取自 `data/strings/lawn_strings.txt` 的 `CRAZY_DAVE_*` 条目：

| 时机 | 落位 | 现有关卡 |
|------|------|---------|
| 关卡开场（选卡之前） | **关卡脚本 `run_flow()` 里现场构造并传参**：`await dave_dialog(_build_dave_dialog())`；老关卡才是字段 `ResourceLevelData.crazy_dave_dialog` | 1-5（2400~2406：自我介绍 + 让玩家用铲子清理草坪）；**2-1（201~207：进入夜晚场景的开场白）**；**3-1（501~505：进入泳池场景的开场白）**；**4-1（801~803：进入浓雾场景的开场白）**；**5-1（1201~1204：进入屋顶场景的开场白）**；**5-5（1301~1311：禅境花园收尾 + 警告飞贼僵尸）** —— 台词都内联在各关卡脚本的 `_build_dave_dialog()` 里 |
| 教学中途 | 同样是 `await dave_dialog(_build_xxx_dave_dialog())`，只是写在教学那一段流程里 | 1-5 铲光草坪后（2410~2415：保龄球惊喜，在 `_build_bowling_dave_dialog()` 里构造） |
| 多轮关卡第 2 / 3 批（摆下一批罐子之前） | **同上，按批各一个方法**：`await dave_dialog(_build_dave_dialog_2())` | **4-5 → 第 2 批（2700~2704：再给你一批花瓶）、第 3 批（2800~2802：最后一批）** |

- 播放统一走 `MainGameManager.play_crazy_dave_dialog()`：戴夫挂在 `CanvasLayerUI`，说完自动离场。
- 取值两条路：`dave_dialog(对话)` **传进来的优先**；没传才走
  `ResourceLevelData.get_crazy_dave_dialog_on_round(轮次)`（老 `.tres` 关卡：
  第 1 轮 `crazy_dave_dialog`，第 2 轮起 `crazy_dave_dialog_next_round[轮次 - 2]`，没有则不播）。
  每句话一个 `CrazyDaveDialogDetailResource`。
- 关卡脚本不给 `crazy_dave_dialog` 字段赋值、把对话写在 `run_flow()` 里时，**不需要任何声明**：
  「开场连播两段戴夫」靠关卡脚本自己避开 —— 有对话的关卡不写推销那一行（见下一条）。
- **某一句可以顺带触发一个事件**：`CrazyDaveDialogDetailResource.on_talk_event` 填事件名时，
  戴夫念到这一句的同一时刻 `EventBus.push_event(...)`（原版 1-5：`surprise_001`「我们去玩保龄球！」
  配 `on_talk_event = show_bowling_stripe`，保龄球红线订阅该事件后画出来，
  事件名常量 `WallnutBowlingStripe.SHOW_STRIPE_EVENT`）。
- 台词里的 `{PLAYER_NAME}` 由 `CrazyDave._resolve_text_placeholder()` 换成当前用户名
  （`Global.user_manager.curr_user_name`），取不到用户名时叫「我的邻居」。
- **跳过规则**（`MainGameManager.is_skip_level_dave_dialog()`）：只管关卡资源上的那段开场对话 ——
  `dave_dialog_only_first_playthrough` 为真时，本关已有通关记录就不再播
  （对齐原版「进入夜晚 / 泳池 / 浓雾 / 屋顶的开场白只在第一次进该场景说一次」）；该开关默认 false。
  **教学里的戴夫对话不归它管**：那是关卡流程自己写的，「只播一次」由关卡脚本自己判
  （1-5：`if mg.curr_game_round == 1 and not is_curr_level_success()` 包住开场那段）。
- **5-5 是两段口径拼在一起的一段对话**：原版前 3 句（1301~1303，禅境花园收尾）只在第一轮说，
  后 8 句（1304~1311，警告飞贼僵尸）每轮都说；而 `dave_dialog_only_first_playthrough` 是**整段级**开关，
  做不到「前半段跳过、后半段照播」。本仓库按「每轮都播」处理（开关保持默认 false），
  代价是重玩 5-5 时前 3 句会多说一遍 —— 要精确对齐原版得给 `CrazyDaveDialogDetailResource`
  加逐句的「只说一次」标记并在 `CrazyDave.start_dialog()` 里过滤，目前没做。
- **台词里的原版动画标签要剥掉**：`lawn_strings.txt` 的句尾常带 `{MOUTH_BIG_SMILE}` / `{SHAKE}` /
  `{SHOW_XXX}` 这类标签，本仓库的气泡是纯文本，这些标签一律**不写进 `text`**；
  只有带 `{SCREAM}` / `{SCREAM2}` 的疯言疯语句才额外把 `is_crazy` 设为 true
  （例：1-5 的 `opening_006`「开始挖吧！」）。
- **戴夫推销卡槽扩充由关卡脚本自己写**：2-2 ~ 3-4 这几关在 `run_flow()` 开头写一行
  `await dave_sell_card_slot()`（快捷工具，见 `LevelScriptBase`），有戴夫对话的关卡**不写**。
  推销最早在 2-2 触发（`ConstUnlockLevel.DAVE_SELL_ADVENTURE_LEVEL`），且**只在钱够当前档价时才真推销**。

### 给别的关卡加一段开场戴夫对话

1. 在关卡脚本里加一个 `func _build_dave_dialog() -> CrazyDaveDialogResource:`，
   按现有关卡的写法在里面 new 每一句（`CrazyDaveDialogDetailResource`，文本抄 `lawn_strings.txt`
   的对应 `CRAZY_DAVE_*` 条目，占位符 `{PLAYER_NAME}` 保持原样），最后 `assign` 成
   `CrazyDaveDialogResource` 并 `return`（不用再建 `dialog/*.tres`、`dialog_detail/*` 那些文件）。
2. `run_flow()` 里写 `await dave_dialog(_build_dave_dialog())`（放在「预览僵尸 / 选卡」之前）。
3. 要「已通关就不再播」就把 `dave_dialog_only_first_playthrough` 设为 true（这个开关仍在 `_init()` 里）；
   **本关在 2-2 ~ 3-4 之间且写了对话，就不要写 `await dave_sell_card_slot()`**（有对话关不推销）。
4. **打开游戏**进该关卡过一遍（对话只有打开游戏才看得见），见 [验证流程.md](../验证流程.md)。

## 给别的关卡加一段教学

在 `run_flow()` 里按要教的顺序把三个工具排下来即可（照抄 1-1 / 1-2 / 1-5 的骨架）：

1. 玩家要动手，第一个等待之前必须有 `await allow_operation()`（要教的东西排在开战之前时尤其如此）。
2. 一句 `hint(台词)` 配一个 `wait_*()`，箭头要指哪就 `arrow_*()`，换目标再调一次。
3. 收尾 `await hint("")` + `await hide_arrow()`（没有「教程收尾」事件会替你收）。
4. 要「已通关就不播」就用 `if not is_curr_level_success(): await _tutorial_flow()` 包起来。

### 最后一步：打开游戏验证

跑 `powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Windowed -Scenario probe_tutorial`
（1-1）、`-Scenario probe_tutorial_1_2`（1-2）或 `-Scenario probe_tutorial_1_5`（1-5）——
探针覆盖教学全流程 + 原版提示顺序 + 第一波僵尸的启动时机 + 已通关不再播。
**必须带 `-Windowed`**：提示条与箭头只有打开游戏才看得见，无头跑批证明不了行为对不对
（见 [验证流程.md](../验证流程.md)）。

探针不看步骤下标（没有下标了），推进判据是**提示文本**，提示顺序由探针订阅提示条的
`signal_advice_changed` 逐句记录；读文本 / 箭头可见性统一走
`TutorialAdviceUI.find_level_hint(Global.main_game)`（见 `test/scenarios/probe_tutorial.gd` 的 `_hint()`）。
⚠️ 别拿 `main_game_progress == MAIN_GAME` 当「开战」判据：教学里的 `allow_operation()` 也会推进到
`MAIN_GAME`；要等开战就看传送带 / 第一波（1-5 探针的 `_wait_battle_started()`）。

## 第一次掉落钱的一次性提示（冒险模式 2-1 起）

金钱在冒险模式 2-1 才解锁（`ConstUnlockLevel.MONEY_UNLOCK_ADVENTURE_LEVEL`）：判定是
「当前正在打的关卡序号 >= 2-1」（`get_max_success_adventure_level() + 1`），也就是**通关 1-10 后进入 2-1 就开始掉钱**，
不用等通关 2-1。**第一次掉出金币时**
草坪上弹一次「存钱来买更酷的道具吧！」（原版 `ADVICE_CLICKED_ON_COIN`），箭头指向掉出来的那枚金币，
5 秒后自动消失。这是**全局只弹一次**的一次性提示：

| 环节 | 位置 |
|------|------|
| 触发 | `DIM_Coin.create_coin()` 生成金币后推 `EventBus "first_coin_drop"`（携带那枚 `Coin`） |
| 显示 | `MainGameManager._on_first_coin_drop()`：实例化 `SceneRegistry.TUTORIAL_ADVICE` 挂到 `CanvasLayerUI`，调 `TutorialAdviceUI.show_advice_once()`（箭头每帧跟随金币，金币被捡走就收起箭头） |
| 只弹一次 | `GlobalGameState.is_first_coin_advice_shown`，弹完立刻 `SaveService.save_now()` 落存档，旧档读不到该字段按 `false` 处理 |

花园场景也有 `DIM_Coin`，但没有 `MainGameManager` 订阅该事件，所以**只在战斗关卡里弹**。
自动回归：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_first_coin_advice`
（输出 `[FIRSTCOIN] result=`），实机确认时用 `-Windowed` 看提示条与箭头。
