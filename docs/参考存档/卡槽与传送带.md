# 卡槽与传送带 —— 两个控制器

> **[面向 AI Agent]** ｜ **触发条件**：要改进卡方式（卡槽 / 传送带）、改传送带的出卡权重、查传送带里有什么卡，或者要让两者同时出现
> **读完你能**：知道卡槽和传送带各归哪个控制器管、换权重该调哪个接口、加一条权重规则该写在哪个文件
> **强制级别**：**参考**（机制说明，不做也不打回） ｜ **不读的风险**：可能直接在 `CardManager` 里加分支，把两种出卡方式又耦合回互斥的 `match`
> **关联**：[卡片与选卡流程.md](卡片与选卡流程.md) ｜ [特殊关卡.md](特殊关卡.md)（僵王战）｜ 硬约束 [../项目规范.md](../项目规范.md) §1-8

---

## 1. 一句话结构

```
CardManager（本体，只做转发）
    ├── CardSlotController     常规卡槽：选卡 / 出战卡槽 / 待选区
    └── ConveyorBeltController 传送带：出卡权重 / 出卡间隔 / 查询带上的卡
```

- 两个控制器都在 `init_manager()` 里建，**要哪个由关卡数据决定**（`create()` 内部按
  `has_norm_card_slot()` / `has_conveyor_belt()` 自己判断，不需要的模式直接不建）。
- 关卡数据上的 `card_mode` 决定有没有它们：
  `Norm` = 只有卡槽，`ConveyorBelt` = 只有传送带，**`Both` = 两个同时出现（卡槽在上、传送带在下）**。
- 外部（教程 / 结算）照旧读 `card_manager.card_slot_norm` / `card_slot_battle` /
  `card_slot_conveyor_belt` —— 这三个字段是控制器里实例的别名，只出不进。

代码落点：

| 文件 | 职责 |
| --- | --- |
| `src/ui/card/card_slot/ui_card_slot_controller.gd` | 卡槽控制器 |
| `src/ui/card/card_slot/ui_conveyor_belt_controller.gd` | 传送带控制器 |
| `src/ui/card/card_slot/ui_conveyor_weight_rule.gd` | 权重规则基类（每次出卡前被问一次） |
| `src/levels/core/zomboss/zomboss_conveyor_weight_rule.gd` | 僵王战的那条规则（5-10 / 迷你 20 共用） |

## 2. 卡槽控制器

默认口径不变：**出战卡由选卡决定**（`Norm` / `Both` 都走选卡；冒险模式的锁槽 / 预选卡见
[卡片与选卡流程.md](卡片与选卡流程.md)）。

```gdscript
mg.card_manager.card_slot_controller.get_cards()            ## 出战卡槽上的卡
mg.card_manager.card_slot_controller.has_card_slot()        ## 本关有没有卡槽
mg.card_manager.card_slot_controller.add_one_battle_card_placeholder()  ## 卡槽扩充补一格
```

选卡阶段出现 / 收起、主游戏阶段挪进 HUD 容器、多轮换一轮归位、阳光存档，也都在这个控制器上。

## 3. 传送带控制器

### 3.1 权重：底表 + 规则

- **底表** = 关卡数据里的 `conveyor_weights`（`Array[ResourceCardWeight]`），控制器只留副本，
  绝不改写关卡资源上的条目（那是共享资源，改了会污染关卡数据）。
- **运行期调整**靠「权重规则」：每次出卡前，控制器先把权重恢复成底表，再让每条规则各调一次，
  最后把结果推给传送带的随机池（`signal_before_create_card` → `refresh_weights()`）。
  所以规则看到的一定是「当前场上情况」，不用自己记住上一次改了什么。

```gdscript
## 关卡脚本里加一行就挂上了（见 adventure_05_10 / minigame_20_zomboss_revenge）
_mg.card_manager.add_conveyor_weight_rule(ZombossConveyorWeightRule.new())

## 规则内部：想改哪一项就调这两个
conveyor.set_plant_weight(plant_type, weight)        ## 直接指定权重（0 = 本次不参与抽取）
conveyor.set_plant_weight_scale(plant_type, scale)   ## 按倍率缩放（1 = 关卡初始值）
```

规则是 `RefCounted`，**一关专属的规则直接写在关卡脚本里**（硬约束 §1-8），
两关以上共用才上浮成单独的类（`ZombossConveyorWeightRule` 就是 5-10 与迷你 20 共用）。

### 3.2 查询传送带内的植物

```gdscript
mg.card_manager.conveyor_controller.get_cards()            ## 带上的卡（按槽位顺序）
mg.card_manager.conveyor_controller.get_card_plant_types() ## 带上的植物种类（去重）
mg.card_manager.conveyor_controller.count_card(plant_type) ## 带上某种植物的张数
## CardManager 上也有同义的两个口子：get_conveyor_card_plant_types() / count_conveyor_card()
```

### 3.3 出卡间隔与布局

- 间隔：`CardManager.set_conveyor_card_interval(秒)` / `set_conveyor_card_interval_scale(倍率)`（照旧）。
- **布局**：同时有卡槽和传送带时，传送带**不会**被挪进 `CardSlotContainer`
  （那个 `PanelContainer` 会把子控件铺满同一个矩形，两条卡槽会叠在一起），
  而是留在 `CardSlotRoot` 上，按 `set_appear_pos_y(卡槽高度)` 压到卡槽下面。

## 4. 僵王战的传送带权重

`ZombossConveyorWeightRule`（`src/levels/core/zomboss/`）：

| 场上情况 | 调整 |
| --- | --- |
| **空花盆 <= 5**（场上几乎没空盆可填了） | 花盆权重 × 0.5 |
| **传送带上花盆 >= 4** | 寒冰菇 / 火爆辣椒权重 × 2.0（这两张是打僵王的主力） |

「空花盆」= 格子上有花盆（`PlacePlantInCell.Down`）且花盆上没种东西。
5-10 / 迷你 20 开局预置 4 列花盆（20 个），所以这条规则是**打到后期草坪种满了才生效**。
阈值与倍率都是该脚本顶上的常量，调手感改那里。

## 5. 自定义种子包（关卡脚本的快捷工具）

出战卡槽上也能放**不是用来种植**的种子包（「花 1000 阳光把全场豌豆射手换成双重射手」这类）。
本体只提供一个通用口子，**点击做什么由关卡脚本自己写**（硬约束 §1-8）：

```gdscript
## 关卡脚本里（src/levels/core/level_script_base.gd）
var card := create_custom_seed_packet(card_reference, sun_cost, on_click, cool_time)
```

- `card_reference` 决定**卡面**：照抄 `AllCards` 里对应那张源卡（植物 / 僵尸 / 僵王都行；
  模仿者 P999 没有出战模板，会退回 `AllCards.imitater_card`）。
- `sun_cost` 是卡片上写的数字，**阳光不够时卡片自己置灰 + 蜂鸣，回调不会被调用**。
- `on_click` 收到本卡自己（`func(card: Card)`）。**扣阳光与冷却都不会自动发生**：
  想走出战卡槽那套就 `card.signal_card_use_end.emit(card)`，只想冷却就 `card.card_cool()`，
  一次性卡买完就 `card.set_card_disabled_forever()`（永久置灰，阳光变化也点不亮它）。

**三种「不能点」的状态，别用错**：

| 状态 | 怎么写 | 什么时候用 |
| --- | --- | --- |
| 阳光不够 | 不用写，`sun_cost` 自己判 | 钱不够（阳光一变自动重判） |
| **条件不满足**（现在没坑可填、现在没目标可换） | `card.set_card_blocked(true/false)` | 关卡脚本随时开关；与阳光**互不覆盖** |
| 一次性用完了 | `card.set_card_disabled_forever()` | 买过一次就再也点不动 |

`set_card_blocked()` 是给关卡脚本兜「条件」用的：`judge_card_ready()` 里单独判一道，
所以阳光变化把它冲不掉（现成的 `set_card_disable()` 会被阳光刷新重新点亮，别用它做这件事）。

链路：`Card.CardContext.Custom` → `Card._on_button_pressed()` 里直接转 `custom_click`，
**不进手持管理器**（不会变成「拿着植物去种」）；快捷键 1~10 与鼠标点击走同一条路。
现成用例：
- `src/levels/mode_minigame/minigame_05_beghouled.gd`（僵尸迷阵的五张卡：
  三档升级买完置灰 + 刷新盘面 + 填坑「没有坑时 `set_card_blocked` 置灰」）。
- `src/levels/mode_minigame/minigame_08_zombie_aquarium.gd`（僵尸水族馆的两张卡：
  100 阳光买一只潜水僵尸、1000 阳光买奖杯即通关；没有单独 UX 的那类小玩法可以直接把「按钮」做成卡）。

## 6. 验证

探针：`powershell -ExecutionPolicy Bypass -File test/run_autopilot.ps1 -Scenario probe_card_slot_conveyor`

- 1-3 改成 `Both`：两个控制器都在、卡槽在上（按全局矩形断言）、快捷键先数卡槽再数传送带、传送带查询接口；
- 5-10 僵王关：空花盆 20 > 5 时花盆权重不变 → 种满后（<= 5）花盆权重下降；带上花盆攒到 4 个 → 寒冰菇 / 辣椒权重上升。
