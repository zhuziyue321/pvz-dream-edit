## 1. 目录结构

### D-01 目录与文件命名

**适用范围**：全项目新增的文件与目录名。

**要求**

- **必须**全小写 snake_case，单词间下划线。
- **必须**不出现大写字母、空格、中文，例外仅限：
  - 约定俗成的文档名：`README.md`、`LICENSE`；
  - `docs/` 下的中文文档名；
  - `level_game_para/` 下的中文关卡名（该名字会显示给玩家）。

**正例**：`scripts/character/components/hp_component/component_hp.gd`

**反例**：`scripts/Character/Components/ComponentHP.gd`、`docs/新 规范.md`

**自动检查**：无（靠评审与 `test/verify.ps1` 的引用完整性间接兜底）。

### D-02 编号前缀

**适用范围**：同类成组资源（角色、子弹、关卡、主场景）。

**要求**：**必须**使用「三位编号 + 下划线 + 名称」；编号段内留出空位供扩展。

| 类型 | 命名模板 | 实例 |
|------|---------|------|
| 植物 | `plant_NNN_<name>` | `plant_001_pea_shooter_single`、`plant_999_imitater` |
| 僵尸 | `zombie_NNN_<name>` | `zombie_001_norm`、`zombie_999_boss` |
| 子弹 | `bullet_NNN_<name>` | `bullet_001_pea`、`bullet_1001_bowling` |
| 关卡 | `<模式>_<编号>_<名>` | `adventure_01_day`、`minigame_01_bowling`、`puzzle_pot_01`、`survival_flag_01_day` |
| 主场景 | `<NN>_<name>` | `01_start_menu`、`12_store`、`main_game_01_front` |

> 1000 段（`bullet_1001`、`plant_1001`）预留给小游戏 / 特殊模式资源，不要占用。

### D-03 顶层目录职责

| 目录 | 职责 |
|------|------|
| `addons/` | 第三方插件。**不修改、不参与本规范** |
| `animation/` | R2Ga_PVZ 转换出的动画资源，按 `角色类型/编号_名称/*.tres` |
| `assets/` | 图片、音频等美术素材（版权原因不在仓库中） |
| `data/` | Theme 主题资源、图鉴数据 `almanac_data.json` |
| `docs/` | 说明文档 |
| `level_game_para/` | 玩家可见的自定义关卡参数（`ResourceLevelData`） |
| `resources/` | 自定义资源 `.tres` 及其资源脚本 `.gd` |
| `scenes/` | 场景文件 |
| `scripts/` | 脚本文件 |
| `shaders/` `shader_material/` | 着色器与材质 |

### D-04 scripts/ 的组织方式

**要求**：**必须**按功能域分目录，并尽量与 `scenes/` 同名对应 —— 找脚本时按"它在哪个场景目录"就能推导出来。

| `scripts/` | 对应 `scenes/` | 说明 |
|-----------|---------------|------|
| `character/` | `character/` | 角色基类、植物、僵尸、**组件** |
| `bullet/` | `bullet/` | 子弹与运动组件 |
| `item/` | `item/` | 局内道具（脑子、梯子、冰道、植物格子…） |
| `main_game_bg/` | `main_game_bg/` | 主游戏背景（雾、泳池、雨、斜坡） |
| `garden/` `store/` `almanac/` `crazy_dave/` `start_menu/` `choose_level/` | 同名 | 各界面逻辑 |
| `ui/` | `ui/`、`card_slot/` | UI 与卡槽 |
| `manager/` | `manager/` | 主游戏各子管理器 |
| `autoload/` | `autoload/` | 全局单例（含 `util/logger.gd`） |
| `consts/` `util/` `camera/` `fx/` | — | 跨模块的常量、工具、相机、特效 |

> 新增功能域时**同时**在 `scripts/` 与 `scenes/` 建同名目录；只落一边会让"同名对应"这条失效。

### D-05 组件的落位

**适用范围**：所有 `*Component` 脚本。

**要求**

- **必须**放在 `scripts/character/components/<功能域>_component/` 下，一个组件一个目录：
  - 功能域单一、只有一份实现 → 直接 `scripts/character/components/component_xxx.gd`（如 `component_sleep.gd`）；
  - 有多份变体（基类 + 子类）→ 建目录 `<功能域>_component/`，文件 `component_<功能域>.gd` + `component_<功能域>_<变体>.gd`。
- **必须**让 `scenes/` 侧有对应位置：组件作为**子节点**挂在角色 / 管理器场景里。

**正例**（多变体）

```
scripts/character/components/attack_behavior_component/
├── component_attack_base.gd              # class_name AttackComponentBase
├── component_attack_bullet_base.gd       # class_name AttackComponentBulletBase
├── component_attack_bullet_split_pea.gd  # class_name AttackComponentBulletSplitPea
└── component_attack_zombie_norm.gd       # class_name AttackComponentZombieNorm
```

**反例**：把 `component_attack_bullet_split_pea.gd` 丢在 `scripts/character/plant/` 里 —— 组件与角色脚本混层，复用与查找都会退化。

### D-06 resources/ 的组织方式

**要求**：**必须**每种资源一个目录，**资源数据与其脚本同目录**，脚本统一放该目录的 `script/` 子目录。

```
resources/
├── ui_resource/            # 卡片背景 card_bg/、按钮样式 button_styles/
├── character_resource/
│   ├── plant_condition/    # 植物种植条件（必须放这里）
│   ├── body_change/plant/  # 掉血/掉头外观变化
│   └── script/             # 角色资源脚本
├── crazy_dave_resource/    # 戴夫对话资源 + script/
├── level_date_resource/    # 关卡资源 + script/（mode_adventure/minigame/puzzle/survival）
├── map_resource/           # 地图资源 + script/
└── save_game_resource/     # 存档资源 + script/
```

> 植物种植条件资源**必须**位于 `resources/character_resource/plant_condition/` —— 这是被代码路径依赖的硬约束。

## 2. 组件化开发规范

> 本项目的**主扩展手段是组件组合，不是继承**。
> 角色根节点只保留：基础属性、动画、body、以及与本体高度耦合无法拆分的特殊功能
> （土豆雷准备、大嘴花吞噬、魅惑），**其余一律做成组件**。

### K-01 组件的定义与边界

**适用范围**：任何准备写成组件的功能。

**要求**

- **必须**满足「可独立增删」：把组件节点从场景里删掉，角色应仍能运行（只是失去该能力），不得空引用崩溃。
- **必须**单一职责：一个组件只回答一个问题（移动 / 血量 / 检测 / 睡眠…）。出现"顺便也管一下 X"就应该拆成第二个组件。
- **必须**自持状态：组件自己的状态（`is_sleeping`、`curr_be_attack_status`…）由组件内部维护，**宿主不得直接改**。
- **应该**对宿主暴露「只读转发属性」。宿主给外部读的状态用 `get` 转发，不复制字段：

```gdscript
## plant_000_base.gd —— 宿主只做转发，状态本体在组件里
## 是否正在睡觉（由睡眠组件拥有）
var is_sleeping: bool:
	get:
		return is_instance_valid(sleep_component) and sleep_component.is_sleeping

## 是否在花园水族馆（由花园组件拥有）
var is_garden_aquarium: bool:
	get:
		return is_instance_valid(garden_component) and garden_component.is_garden_aquarium
```

**反例**

```gdscript
## ❌ 宿主自己存一份，和组件里的状态各自演化，两边迟早不一致
var is_sleeping := false
func _on_sleep_started() -> void:
	is_sleeping = true          # 组件里也有一份 is_sleeping
```

**为什么**：副本状态是这类项目最贵的 bug 来源 —— 症状是"看起来没睡但动不了"，排查成本极高。

### K-02 组件基类与命名

**适用范围**：所有组件脚本。

**要求**

| 项 | 规定 |
|----|------|
| 基类 | **必须**继承 `ComponentNormBase`（`scripts/character/components/component_norm_base.gd`），或继承其已有的抽象子类 |
| `class_name` | **必须**包含 `Component`，两种合法形式二选一；**必须** PascalCase |
| 文件名 | **必须** `component_<功能域>[_<变体>].gd` |
| 节点名 | **必须**与 `class_name` 同名（便于 `%` 唯一名引用与编辑器里辨识） |
| 抽象 | 不直接实例化的基类**必须**标 `@abstract` |

**`class_name` 的两种合法形式**

| 形式 | 何时用 | 实例 |
|------|--------|------|
| 后缀式 `<功能域>Component` | 该功能域只有一份实现，或变体用后缀区分 | `SleepComponent`、`HpComponentPlant`、`GardenComponentSprout` |
| 前缀式 `<功能域>Component<变体>` | 同族变体多、后缀容易被压扁成一长串 | `AttackComponentBulletSplitPea`、`BombComponentJalapeno`、`AnimComponentBobsled` |

> 同一功能域内部**必须**统一，不要 `AttackComponentBulletBase` 与 `BulletAttackComponent` 混用。

**正例**

```gdscript
# 后缀式：scripts/character/components/component_sleep.gd
extends ComponentNormBase
class_name SleepComponent

# 前缀式：scripts/character/components/attack_behavior_component/component_attack_zombie_norm.gd
class_name AttackComponentZombieNorm

# 抽象基类
# scripts/character/components/component_norm_base.gd
@abstract
extends Node2D
class_name ComponentNormBase
```

**组件目录里的非组件脚本**：`drop_body/`、`iron_node/` 这类辅助节点脚本不是组件，
不受上述命名约束（如 `ZombieDropBase`、`IronNode`、`JacksonStateMachine`），
但**必须**在 `test/standard_check.gd` 的 `CLASS_NAME_EXCEPTIONS` 里登记，否则检查会失败。

**`ComponentNormBase` 提供的统一能力**（不要重复实现）

- `is_enabling` / `is_enable_default`：启停总闸。
- `E_IsEnableFactor` 枚举：**必须**用它说明"为什么被禁用"（`Sleep`、`Scaredy`、`Death`、`HandItem`…）。
- `enable_component(factor)` / `disable_component(factor)` / `change_is_enabling(value, factor)`：多因子独立记账，任一因子为 false 即整体禁用。
- `owner_update_speed(speed_product)`：宿主改速度时统一回调，组件按需重写。

**反例**：组件自己写 `var is_active := true` 做启停 —— 绕过了多因子机制，睡眠解除后会错误地把"因死亡禁用"的组件一起打开。

### K-03 组件通信方式

**适用范围**：组件之间、组件与宿主之间。

**要求**：**必须**只用下面几种方式，**不得**发明新的（尤其禁止向下改宿主私有字段）。

| 方式 | 何时用 | 方向 |
|------|--------|------|
| **A. 组件内自洽** | 只影响自己的逻辑 | 组件内部 |
| **B. 内建 `owner` 反向引用宿主** | 组件需要读宿主属性 / 调宿主方法、访问兄弟节点 | 组件 → 宿主 |
| **C. 信号** | 事件通知（"我睡着了""我开始攻击了"） | 组件 → 宿主 / 其他组件 |
| **D. `@export` 引用 + 公开方法** | 配置与协同（"我影响这些组件"） | 宿主 → 组件 / 组件 → 组件 |
| **E. `EventBus`** | 跨模块、不关心谁在听的事件 | 任意 → 全局 |

**A. 组件内自洽**

```gdscript
# component_sleep.gd —— 睡眠状态、动画、判定全在组件里，宿主不参与
func start_sleep() -> void:
	is_sleeping = true
	visible = true
	anim_sleep.play("zzz")
	signal_is_sleep.emit()
```

**B. 反向引用宿主 —— 一律用内建 `owner`，不用 `get_parent()`**

```gdscript
# component_move.gd —— owner 是 Godot 内建的"场景根"，节点被 reparent 也不会断
@onready var owner_zombie: Zombie000Base = owner

# component_hp.gd
@onready var owner_character: Character000Base = owner

# component_detect.gd —— 用 owner 的类型分支决定检测层
if owner is Plant000Base:
	update_curr_collision_lay(1)
elif owner is Zombie000Base:
	update_curr_collision_lay(2)
```

> `get_parent()` **只允许**用于「真的要脱离宿主 / 挂到宿主父节点」的场景，
> 例如 `component_charred.gd` 的 `reparent(owner_character.get_parent())`。

**C. 信号 —— 组件发、宿主连**（连接位置见 [K-05](#k-05-组件信号连接)）

```gdscript
# component_sleep.gd（组件侧：只声明 + emit，不关心谁听）
signal signal_is_sleep
signal signal_not_is_sleep
```

**D. `@export` 引用 + 公开方法 —— 需要"被谁影响"时用导出数组，避免组件写死路径**

```gdscript
# component_sleep.gd：睡眠影响哪些组件由场景里配置，组件自己不认识它们
## 睡眠影响的节点,在植物本体中调用 judge_is_sleeping() 使对应节点 disable
@export var sleep_influence_components: Array[ComponentNormBase]
```

```gdscript
# plant_000_base.gd：宿主做"接线员"
for sleep_influence_component in sleep_component.sleep_influence_components:
	sleep_component.signal_is_sleep.connect(
		sleep_influence_component.disable_component.bind(ComponentNormBase.E_IsEnableFactor.Sleep))
	sleep_component.signal_not_is_sleep.connect(
		sleep_influence_component.enable_component.bind(ComponentNormBase.E_IsEnableFactor.Sleep))
```

**E. `EventBus` —— 唯一的全局事件通道**

```gdscript
# hand_manager.gd
EventBus.subscribe("main_game_progress_update", _on_main_game_progress_update)
# event_bus.gd 提供 subscribe / subscribe_once / unsubscribe / push_event（含优先级、once、filter、历史）
```

**要求**：**必须**只在"发布者不该知道订阅者"时用 `EventBus`；组件与宿主之间用信号就够了，
滥用全局事件会让依赖关系彻底不可追踪。

**反例**

```gdscript
# ❌ 组件沿场景树向上抓宿主并改它的字段：删掉/挪动组件立刻崩，也读不出依赖关系
get_parent().get_parent().is_sleeping = true

# ❌ 组件之间硬编码绝对路径：换个场景树结构就断
get_node("/root/MainGame/PlantCell/Plant/NormPlant/HpComponent").take_damage(20)
```

**替代写法**：需要"最左敌人"这类跨组件查询，**必须**由宿主或管理器的公开方法提供（如 `update_first_enemy()`），组件通过 `@export` / `@onready` 持有引用后调用。

### K-04 组件与宿主的职责划分

| 谁 | 负责 |
|----|------|
| **组件** | 自己的状态、自己的行为、自己的定时器与动画播放 |
| **宿主（角色 / 管理器）** | 组件引用的获取、**信号连接**、初始化顺序编排、对外只读转发、无法拆分的特殊逻辑 |
| **管理器** | 组件注册与事件派发（如 `HandManager`），**不实现**具体手持物行为 |

**要求**

- **必须**由宿主在 `_ready` 链路里连接信号（见 [K-05](#k-05-组件信号连接)）。
- **必须**让 `_ready()` 只做"按初始化类型分派"，不要在里面堆逻辑：

```gdscript
# plant_000_base.gd —— 只分派，不堆逻辑
func _ready() -> void:
	super()
	if plant_type == 0:
		push_error(name, "植物类型未赋值")

func ready_norm() -> void:
	super()
	garden_component.queue_free()          # 正常出战不需要花园组件
	be_attack_status_component.init_status()
	sleep_component.judge_is_sleeping()     # 是否睡觉由组件自己判断
```

- **必须**让子类重写 `ready_norm()` / `ready_show()` / `ready_garden()` / `ready_norm_signal_connect()`，**不得**重写 `_ready()`。
- **必须**在 `add_child()` 之前用 `init_*()` 给角色赋值（行、初始化类型等），因为 `_ready` 时已需要这些值。
- **必须**通过 `ZombieManager.create_norm_zombie()` 创建僵尸，不要自己 `instantiate + add_child`。

**正例**（子类扩展点，全项目 87 处同类写法）

```gdscript
# plant_002_sun_flower.gd
func ready_norm() -> void: ...
func ready_norm_signal_connect() -> void: ...
```

**反例**：在某个植物脚本里重写 `_ready()` 并 `super()` 后追加初始化 —— `_ready` 里的分派逻辑会被执行两次或漏执行，且父类后续改动会静默破坏子类。

### K-05 组件信号连接

**适用范围**：角色类信号（角色本体与组件、组件与组件）。

> 目标：**避免信号漫天飞**。任何"谁连了谁"都应能在角色脚本里一眼读完。

**要求**（按优先级从高到低判断，命中即按其执行）

| # | 场景 | 连接位置 |
|---|------|---------|
| 1 | 角色类**自身 Timer 节点**的 `timeout` | **可以**在编辑器中直接连 |
| 2 | 组件**自身 Timer** 的 `timeout` | **必须**连到该组件本体 |
| 3 | 父组件 ← 子组件（如攻击组件 ← 攻击检测组件） | **必须**由**父组件**连接 |
| 4 | 受角色速度影响的组件 | **必须**在角色根节点 `@export` 该组件，并在角色信号连接函数中连 |
| 5 | 组件对组件的**禁用**影响（睡眠、胆小…） | **必须**在**发起禁用**的组件里 `@export` 被影响的组件，由角色信号连接函数连 |
| 6 | 以上之外的所有自定义信号 | **必须**由角色本体在 `_ready()` 对应的 `ready_*_signal_connect()` 中连接 |

**正例**

```gdscript
# plant_000_base.gd::ready_norm_signal_connect()
## 发射子弹攻击组件影响植物眨眼
var attack_component: AttackComponentBulletBase = get_node_or_null(^"AttackComponent")
if attack_component:
	attack_component.signal_change_is_attack.connect(
		## 可以攻击时禁用眨眼
		func(value): blink_component.change_is_enabling(not value, ComponentNormBase.E_IsEnableFactor.Attack))
```

**反例**

```gdscript
# ❌ 组件自己在 _ready 里跨节点连别的组件：依赖关系藏进组件，宿主读不出来
func _ready() -> void:
	get_parent().get_node("BlinkComponent").disable_component(...)
```

**自动检查**：无（靠评审）。新增组件时请对照本表逐条确认。

### K-06 组件化角色组装

**适用范围**：新增 / 修改植物、僵尸。

**要求**

- **必须**让根节点只保留基础属性、动画、body、以及 [K-01](#k-01-组件的定义与边界) 允许的不可拆分功能。
- **必须**让每个新能力优先问一句「这是不是能做成组件」——能，就做组件。
- **必须**用统一名（`%UniqueName`）或 `get_node_or_null()` 获取组件引用：

```gdscript
# plant_000_base.gd
@onready var sleep_component: SleepComponent = %SleepComponent
## 可挂载梯子组件（只有可挂梯子的植物挂载，可能为空）
@onready var ladder_component: LadderComponent = get_node_or_null(^"LadderComponent")
```

> 可选组件（可能不存在）**必须**用 `get_node_or_null()` + `is_instance_valid()` 判空；
> 必需组件用 `%` 并在缺失时让编辑器尽早报错（`%` 找不到节点会直接报错，这是期望行为）。

- **必须**在新增组件后更新角色场景 `.tscn`，并把该组件登记进受影响角色的信号连接函数。
- **必须**让组件用内建 `owner` 拿宿主引用，宿主用 `%` / `get_node_or_null()` 拿组件引用（双向写法见 [K-03](#k-03-组件通信方式)）。

**反例**：为一个植物写 40 行特判塞进 `plant_000_base.gd` —— 基类会随植物数量线性膨胀，正确做法是做成组件或重写 `ready_norm()`。

### K-07 新增能力（技能 / 手持物）的三步扩展

**适用范围**：新增一类"当前有几种、以后会更多"的能力。手持物是本项目已落地的参考实现。

**要求**：**必须**满足「加能力不动管理器」—— 扩展点是枚举 + 组件脚本 + 场景节点，**不得**在管理器里加 `match` 分支。

| 步 | 动作 |
|----|------|
| 1 | 在能力类型枚举里加一个值（如 `E_HandComponentType`） |
| 2 | 写一个继承对应 `*ComponentBase` 的组件脚本，实现"我必须实现的那几个函数" |
| 3 | 在管理器节点下加一个挂该脚本的 `Node2D` 节点 |

> 管理器侧的**推荐范式**（`HandManager` 已落地）：遍历自己的子节点，按组件自声明的类型建表，
> 之后一律查表派发 —— 不写任何逐个能力的 `if` / `match`。
> 同一个管理器内部用 `get_children()` 做注册是允许的（见 [§8 红线](#8-红线清单) 第 3 条只禁止拿宿主）。

**正例**：`scripts/manager/hand_manager/component/hand_component_base.gd` 用注释把这三步直接写在类头，`HandManager` 只做注册 / 派发 / 切换三件事；新增锤子、手套无需改 `HandManager`。

**反例**

```gdscript
# ❌ 每加一个手持物就要改管理器：组件化没做干净
func use_hand() -> void:
	match curr_hand_type:
		"shovel": ...
		"hammer": ...   # 又来一个分支
```

**完整示例见** [手持物实现.md](手持物实现.md)。

### K-08 启停规范

**要求**

- **必须**用 `E_IsEnableFactor` 说明禁用原因，不要自造布尔开关。
- **必须**保证启停**幂等**：同一因子重复 enable/disable 不产生副作用。
- **必须**在 `disable_component` / `enable_component` 里同时收敛该组件负责的**界面显隐**（如手持物组件重写后调 `refresh_ui()`）。

```gdscript
# hand_component_base.gd —— 复用 ComponentNormBase 的启停机制，顺带刷新界面
func enable_component(is_enable_factor: E_IsEnableFactor) -> void:
	super(is_enable_factor)
	refresh_ui()
```

### K-09 生命周期与清理

**要求**

- **必须**让 `exit_*` / `end_*` 之类的退出函数**幂等**：可能未进入就被调用，也可能被连续调用两次。
- **必须**在组件被 `queue_free()` 或角色换代时断开自己建立的连接（或用 `bind` 后由信号源回收，避免悬空回调）。
- **应该**让临时状态在 `exit_*` 中复原，而不是依赖"下次进入时重置"。

```gdscript
# hand_component_base.gd
## 退出手持态
## 必须幂等：可能在没有 enter_hand 的情况下被调用，也可能被连续调用两次
func exit_hand() -> void: pass
```

> 反例场景：轮次切换 / 游戏结束时手持物残留 —— 根因就是退出路径不幂等或未被调用。
> 对应回归项见 [验证流程.md](验证流程.md) 人工清单的「手持物」一行。

### S-01 格式与注释

**要求**

- **必须**用 **Tab** 缩进（当前 357 个脚本中 339 个含 Tab 缩进、0 个用 4 空格缩进，保持一致）。
- **必须** UTF-8 **无 BOM**、换行 **LF**、文件末尾保留一个换行（`.editorconfig` + `.gitattributes` 已配置）。
- **必须**不留行尾空格；空行不留缩进。
- **必须**中文注释；成员文档注释用 `##`，普通注释用 `#`。
- **应该**用 `#region` / `#endregion` 分区（当前约 202 处），分区名写"这段在管什么"：

```gdscript
#region 组件状态访问
#endregion

#region 初始化相关
#endregion
```

- **应该**在角色脚本里把 `@onready` 组件引用放在 `extends` / `class_name` 之后的第一块（现有角色脚本一致如此），其余成员用 `#region` 分节组织：
  `#region 子节点` → `#region 基础属性` → `#region 组件状态访问` → 各功能小节。
- **可以**让 `enum` / `signal` 紧贴使用它的属性或 `@export_group`，不必强行凑成固定顺序 —— 本项目的强规则只有「`@onready` 置顶 + `#region` 分节」。
- **应该**给非平凡参数加注释：枚举成员、`@export` 配置项都要一句话说明用途。

### S-02 日志必须走 Log

**适用范围**：全部脚本。

**要求**：**必须**不使用裸 `print()` / `printerr()`，统一走自动加载单例 `Log`（`scripts/autoload/util/logger.gd`）。

```gdscript
Log.debug("生成罐子数量:", curr_pot_num)    ## 调试信息，发布版本默认不输出
Log.info("开始新的一轮")                     ## 常规信息
Log.warn("随机罐子数量超过剩余格子，已跳过")  ## 警告（含「错误/失败/异常/不存在」等关键词的场景）
Log.error("存档写入失败: " + path)           ## 错误，走 stderr
```

| 控制项 | 说明 |
|--------|------|
| 参数拼接 | 与 `print` 一致，**不加分隔符**，最多 4 个额外参数 |
| `Log.level` | 最低输出级别：编辑器内默认 `DEBUG`，导出发布版默认 `INFO`，静音设 `Level.OFF` |
| `Log.with_level_prefix` | 输出 `[DEBUG]`/`[INFO]` 等前缀 |
| `Log.with_timestamp` | 输出毫秒时间戳 |

**反例**

```gdscript
print("debug: ", x)      # ❌ 发布版无法关闭
printerr("failed")       # ❌ 绕过级别控制
```

**登记例外**（仅此两处，新增例外**必须**同时改检查器的豁免表）

| 文件 | 豁免范围 | 原因 |
|------|---------|------|
| `scripts/autoload/util/logger.gd` | 整个文件 | `_write()` 必须直连引擎原生 `print`/`printerr`，否则递归爆栈 |
| `scripts/autoload/debug_channel.gd` | 仅 `_line()` 函数 | 报告正文要原样落进 stdout 供粘贴，不能带级别前缀、不能被 `Log.level` 截断 |

> ⚠️ `logger.gd` 的 `_write()` 内部**必须**用引擎原生 `print`/`printerr`，
> 绝不能再调 `Log.*` —— 曾因此 `_write → debug() → _write` 无限递归爆栈，
> 而编辑器全量扫描 PROBLEMS=0、资源自检通过，静态检查完全抓不到。
> 这类"编译得过、一跑就炸"的问题只有运行期冒烟（验证第 4/5 步）能发现。

**自动检查**：`test/verify.ps1` 第 1c 步 `standard_check.gd` 的 `S-02 no-raw-print`（裸 print 直接判 FAIL）；
第 4/5 步 runtime smoke / autoload smoke（覆盖递归爆栈类故障）。

### S-03 UI 屏幕坐标避坑

**适用范围**：任何"点到某个 Control"或"判断鼠标压在哪个 Control 上"的代码。

**要求**：**必须**用屏幕坐标（含画布变换）—— 即 `get_global_transform_with_canvas()`；
**禁止**用 `global_position` / `get_global_rect()` 做命中或定位。

```gdscript
## 正确：控件在屏幕上真正能点到的中心
var screen_center := control.get_global_transform_with_canvas() * (control.size * 0.5)

## 错误：不含画布变换（相机），只有相机完全不动且原点为 (0,0) 时才碰巧对
var wrong := control.get_global_rect().get_center()
```

**原因**：鼠标命中测试与合成鼠标事件走的都是 `get_global_transform_with_canvas()`，
而 `global_position` / `get_global_rect()` 给的是**不含画布变换**的坐标。
本项目关卡有 `Camera2D`（`/root/MainGame/Camera2D`，位置 (120, 0)，**入场时还会移动**），
草坪实测两者相差 **150 像素** —— 用错就稳定点偏，且偏移**不是常数**，不能靠"量一次到处减掉"糊过去。

反向操作（判断鼠标在不在控件里）**必须**在**局部空间**比：

```gdscript
c.get_rect().has_point(c.get_local_mouse_position())   ## plant_cell.gd::is_mouse_in_ui() 就是这么写的，是对的
```

> 把 `get_global_rect()` 和屏幕坐标混着比才是错的。
> 完整根因、实测数据与排查手法见 [AI调试通道.md](AI调试通道.md) 第五、六节。

### S-06 字典读取一律用 get()

**适用范围**：读取「按枚举 / 槽位存可选对象」的字典，典型是 `PlantCell.plant_in_cell`（`Dictionary[PlacePlantInCell, Plant000Base]`）。

**要求**

- **必须**用 `Dictionary.get(key)` 读取，或走封装好的安全访问器（`PlantCell.get_plant(place)`）；
  **禁止**写 `dict[key]` 直接下标 —— 键缺失时会抛 `Out of bounds get index 'N'`，
  而且 `is_instance_valid(dict[key])` 这种"先判空"写法**拦不住**：异常发生在 `[]` 取值那一刻。
- **必须**给槽位型字典配一个安全访问器，新增读取一律走它，不要各自散落 `get()`。
- **可以**用 `dict[key] = value` 写入：写入不存在的键会新建键，不会越界。
- **可以**用 `for k in dict: dict[k]` 遍历：键来自字典自身，必然存在。

**正例**

```gdscript
# scripts/item/plant_cell.gd —— 唯一的读取入口
func get_plant(place: CharacterRegistry.PlacePlantInCell) -> Plant000Base:
	return plant_in_cell.get(place)

# 调用方：scripts/character/components/detect_component/component_detect.gd
var shell:Plant000Base = cell_plants.get(CharacterRegistry.PlacePlantInCell.Shell)
if is_instance_valid(shell):
	return shell
```

**反例**

```gdscript
# ❌ 槽位键可能是缺的；先判空也没用，异常在 [] 取值时就抛了
if is_instance_valid(plant.plant_cell.plant_in_cell[CharacterRegistry.PlacePlantInCell.Imitater]):
	return plant.plant_cell.plant_in_cell[CharacterRegistry.PlacePlantInCell.Imitater]
```

> 真实事故：`plant_in_cell` 默认只登记 `Norm/Shell/Down/Float` 四个槽位，`Imitater` 键被注释掉，
> 僵尸检测到「格子里只有花盆（`Down`）」时执行到 `Imitater` 分支 → `Out of bounds get index '4'`。
> 这个潜伏 bug 是在屋顶索敌修好、僵尸第一次真正检测到植物之后才暴露的。

**自动检查**：无（靠评审）。

## 5. 资源引用

### M-01 res:// 引用与改名

**适用范围**：脚本、场景、资源中的一切引用。

**要求**

- **必须**使用 `res://` 绝对路径。
- 移动 / 重命名资源时**必须**同步完成：
  1. 全局搜索旧路径字符串并全部替换（Godot 4 优先按 `uid://` 解析，路径错也能打开，**但导出会报错**）；
  2. 移动 `.gd` / `.gdshader` 时**连同同名 `.uid` 一起移动**（否则 Godot 重新分配 uid，场景引用失效）；
  3. **先关闭 Godot 编辑器**再批量重命名 —— 编辑器会把瞬时消失的 `.uid` 当孤儿文件删除（本项目曾一次性被删 17 个）。
- **必须**不手工编辑或提交伪造 `.uid` 内容。
- **必须**验证：全文搜 `res://`，确认引用文件真实存在。

**正例**：改名后用 `test/verify.ps1` 第 3 步（reference integrity）确认 `unresolvable=0`。

**反例**：只改文件名，靠编辑器"能打开"就以为没事 —— 导出时才发现 `ext_resource` 丢失。

**自动检查**：`test/verify.ps1` 第 3 步；第 2 步报告缺失 `.uid`；第 6 步报告孤儿 `.uid`。

### M-02 资源与脚本的配对

**要求**

- **必须**让自定义资源脚本与它的 `.tres` 数据同目录（脚本进该目录的 `script/`，见 [D-06](#d-06-resources-的组织方式)）。
- **必须**给资源类加 `Resource` 前缀（`ResourceLevelData`、`ResourcePlantCondition`、`ResourceSaveGame*`）。
- **应该**让「相同配置」共用同一份 `.tres`，而不是复制多份。

### M-03 注册表登记

**适用范围**：新增角色、子弹、道具、卡片等"按类型取场景"的对象。

**要求**：**必须**在对应注册表登记，**不得**在业务代码里散落 `preload` 映射。

| 注册表 | 位置 | 登记内容 |
|--------|------|---------|
| `CharacterRegistry.PlantType` + `CharacterRegistry.PlantInfo` | `scripts/autoload/global/character_registry.gd` | 枚举值 + 信息表（名称、冷却、阳光、场景、种植条件资源…），经 `get_plant_info()` 读取 |
| `CharacterRegistry.ZombieType` + `CharacterRegistry.ZombieInfo` | 同上 | 枚举值 + 信息表（名称、场景、行类型…），经 `get_zombie_info()` 读取 |
| `BulletRegistry.BulletType` + `BulletTypeMap` | `scripts/autoload/global/bullet_registry.gd` | 枚举值 + `preload` 场景 |
| `MainSceneRegistry.MainScenesMap` | `scripts/autoload/global/main_scene_registry.gd` | 主场景路径 |
| `AllCards` | `scenes/autoload/all_cards.tscn` | 卡片预制（运行时从它复制） |

> `ItemRegistry`（`scripts/autoload/global/item_registry.gd`）目前是空占位类，
> 道具注册尚未落地 —— 新增道具时若需要注册表，应先把它建起来，而不是另开一份散乱映射。

**正例**

```gdscript
# bullet_registry.gd
enum BulletType {
	Bullet001Pea = 1,        ## 豌豆
	Bullet1001Bowling = 1001, ## 保龄球
}
@export var BulletTypeMap: Dictionary[BulletType, PackedScene] = {
	BulletType.Bullet001Pea: preload("res://scenes/bullet/bullet_001_pea.tscn"),
}
```

**反例**：在植物脚本里 `if plant_type == 45: scene = preload(...)` —— 类型分派分散到各处，注册表失去意义。

**自动检查**：`test/verify.ps1` 第 1/2 步覆盖场景路径与资源加载；DebugChannel 报告会列出注册表条目数。

### V-01 交付前必跑验证

**要求**：改完代码**必须**跑一次完整验证流程：

```powershell

```

全部通过返回 `0`，有失败返回 `1`。`-SkipSlow` 只跑 1/2/3/6，**不能替代**完整流程。

| # | 步骤 | 抓什么 |
|---|------|--------|
| 1 | 编辑器全量扫描 | 脚本解析/编译错误、失效 `ext_resource` |
| 1b | 脚本编译自检 | 编辑器扫描**不编译**的字符串引用脚本（`load("res://x.gd")`） |
| **1c** | **规范静态检查** `test/standard_check.gd` | **规范红线**：裸 `print`、角色子类重写 `_ready()`、组件命名 |
| 2 | 资源自检 | 逐个 load `.tres/.tscn/.gdshader`，报告加载失败与缺失 `.uid` |
| 3 | 引用完整性 | 全文抓 `res://` 逐个 `Test-Path` |
| 4 | 运行期冒烟 | **真正执行** Logger / GlobalUtils / RandomPicker |
| 5 | autoload 冒烟 | 单例注册、日志可用、初始化顺序（隔离 user 目录） |
| 6 | 卫生检查 | `*.tmp`、`*__casetmp*`、孤儿 `.uid` |

> 违规明细是可读中文，方便直接定位。[WARN] 级检查**不**影响结果，
> 用于收集"可能误报、需要人看"的项（如组件里的 `get_parent()`）。

> ⚠️ 只跑「编辑器扫描 + 资源自检」**不够**：它们只能证明**能编译、引用完好**，抓不到运行期故障。

## 7. 扩展本规范

> 这一节是给**以后要改规范的人**的：规范本身也要可扩展。

### E-01 新增一条规范

**要求**

1. **必须**判断它属于哪一节：目录结构 `D-` / 组件化 `K-` / 命名 `C-` / 代码风格 `S-` / 资源引用 `M-` / 验证 `V-` / 规范自身 `E-`。
2. **必须**分配下一个空闲编号（**不复用**已删除编号，避免历史引用失效）。
3. **必须**复制下面的卡片模板，缺项写「无」而不是省略标题。
4. **必须**在 [§0.1 速查表](#01-我要做-x该看哪张卡) 加一行"我要做 X → 卡片编号"。
5. **应该**尽量给出**真实存在于本仓库**的正例路径与代码片段。

**卡片模板**（复制后填空）

```markdown
### <前缀>-<编号> <一句话标题>

**适用范围**：<什么时候需要看这条>

**要求**

- **必须**/ **应该**/ **可以** <可判定的要求，一条一句>

**正例**

    ```gdscript
    <能直接抄的代码，注明文件路径>
    ```

**反例**

    ```gdscript
    <错在哪、会坏成什么样>
    ```

**自动检查**：<具体步骤，或"无（靠评审）">
```

**为什么这么规定**

- 固定字段 → 读的人不用重新理解结构，写的人不用重新设计结构。
- 「正例必须真实」→ 卡片即模板，新增功能可以照抄，规范不会和代码漂移。

### E-02 把规范变成自动检查

**要求**：一条规范若能自动化，**应该**自动化，而不是留在文档里靠人记。

| 自动化档位 | 做法 | 适用 |
|-----------|------|------|
| 静态扫描 | 加进 `test/project_checker.gd` 或新增 `test/*.gd` | 命名、路径、禁用 API（如裸 `print`）、枚举登记齐全性 |
| 运行期冒烟 | 加进 `test/runtime_smoke.gd`、`test/autoload_smoke.tscn` | 日志、单例、工具类 |
| 行为回归 | 加一个 `test/scenarios/probe_*.gd`，用 `-Scenario` 跑 | 种植、手持物、泳池、锤子等玩法行为 |

**已落地**：`test/standard_check.gd`（verify 第 1c 步）就是按这个模式建的，
新增一条规范检查 = 在它的 `_build_checks()` 里加一个条目，**不需要改别处**。

| 现有检查 | 等级 | 覆盖规范 |
|---------|------|---------|
| `S-02 no-raw-print` | FAIL | [S-02](#s-02-日志必须走-log) |
| `K-04 no-_ready-override` | FAIL | [K-04](#k-04-组件与宿主的职责划分) |
| `K-02 component-class-name` | FAIL | [K-02](#k-02-组件基类与命名) |
| `K-03 get_parent-in-component` | WARN | [K-03](#k-03-组件通信方式) |

**接线步骤**

1. **必须**让 Godot 侧测试输出**一行纯 ASCII** 汇总标记：

   ```
   [XXX] passed=<n> failed=<n> result=PASS|FAIL
   ```

2. **必须**在 `test/verify.ps1` 里加对应步骤，解析该标记并 `Add-Result`。
3. **必须**保持 `verify.ps1` **全文 ASCII**，唯一例外是匹配 Godot **本地化报错**的正则
   （如 `$errPat` 里的 `错误|解析错误|分析错误` —— 引擎报错文本是中文，
   不写中文就匹配不到）。新增中文注释、中文文件名一律禁止：
   PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文正则会静默永不匹配。
4. **必须**在 [V-01](#v-01-交付前必跑验证) 的步骤表与本文档 [附录 B](#附录-b-规范--自动检查索引) 同步更新。
5. **应该**在 [验证流程.md](验证流程.md) 补一行"新增运行期测试的注意事项"。
6. **必须**把新检查的**豁免清单**（哪些文件/函数被允许违规）写在检查器顶部常量里，
   并在对应卡片里登记 —— 允许例外但不登记，等于把检查做成摆设。

**正例**：现有四个标记已被 `verify.ps1` 解析 —— `[SELFCHECK]`、`[RUNTIME-SMOKE]`、`[AUTOLOAD-SMOKE]`、`[STDCHECK]`。

**反例**：在 `verify.ps1` 里写中文正则 —— 静默永不匹配，表现为"步骤神秘失败"。

### E-03 规范与文档的边界

**要求**

- **必须**让本文档只写**约束**（怎么写）；机制、原理、历史踩坑放到对应专题文档，用链接互指。
- **禁止**在本文档重复专题文档的内容 —— 两处都写必然漂移，且读者不知道该信哪一份。
- **应该**在发现"同一个坑被踩第二次"时，把它升级成一张规范卡片（并尽量配自动检查）。
